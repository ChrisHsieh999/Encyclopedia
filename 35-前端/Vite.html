Vite

AI 生成 · 待核对前端工具链更新于 2026-10-21

本篇是 前端 入门路径里"把代码变成网站"的一篇。读完你应该能：用一条命令创建 Vite 项目；说清开发服务器、构建、预览三个命令各干什么；用 .env 文件区分环境；用 server.proxy 解决开发时的跨域；看懂构建产物里的哈希文件名。

一句话定义 ​

Vite（法语"快"，读作 /vit/）是一个前端构建工具：开发时启动一个即时响应的开发服务器，上线前把源码打包成浏览器能高效加载的静态文件（HTML、JS、CSS）。

先修知识 ​

  • Node.js与npm：会用 npm install、npm run，知道 package.json。
  • TypeScript：知道 .ts 要先转成 JS 才能在浏览器运行。
  • HTML基础、JavaScript基础。

它解决什么问题 ​

浏览器只认 HTML、CSS、JavaScript。但我们写项目时想用：

  • TypeScript、Vue 单文件组件（.vue）这类浏览器不认识的格式；
  • 把几十上百个模块文件按 import 拆开写；
  • 引入 npm 上的第三方库（浏览器没法直接读 node_modules）；
  • 改一行代码，页面立刻刷新看到效果。

Vite 的方案有两面：

  1. 开发时不打包。浏览器本身支持原生 ES Module（<script type="module">），Vite 开发服务器按需处理：浏览器要哪个文件，它就即时把该文件（TS 转 JS、.vue 转 JS）转换后返回。所以启动秒开，改文件后只更新受影响的模块（HMR，热更新）。
  2. 上线时打包。生成的文件数量少、体积小、文件名带内容哈希（可永久缓存）。

类比：开发服务器像"点菜现做"的小炒，构建像"批量预制 + 真空包装"的中央厨房。

核心概念 ​

1. 三个命令 ​

命令对应 npm 脚本做什么
vitenpm run dev启动开发服务器，默认端口 5173，热更新
vite buildnpm run build打包生产版本，输出到 dist/
vite previewnpm run preview起一个本地静态服务器预览 dist/，用来确认构建产物没问题（不是用来上线的）

2. 项目结构 ​

用官方脚手架 npm create vite@latest 创建（见下方"逐步例子"），一个项目大致如下：

vite-demo/
├── index.html        # 入口 HTML，放在项目根（不是 public 里）
├── package.json
├── tsconfig.json
├── vite.config.ts    # Vite 配置（可选）
├── .env              # 环境变量（可选）
├── public/           # 原样复制到 dist 的静态文件（如 favicon.svg）
└── src/
    └── main.ts       # 入口脚本

index.html 里有一行 <script type="module" src="/src/main.ts"></script>，这就是整个应用的起点。Vite 把 index.html 当作入口，顺着 import 一路收集依赖。

3. 配置文件 vite.config.ts ​

ts
import { defineConfig } from "vite";

export default defineConfig({
  server: {
    port: 5180,          // 开发服务器端口
    strictPort: true,    // 端口被占用就报错，而不是悄悄换端口
    proxy: {
      "/api": { target: "http://localhost:3202", changeOrigin: true },
    },
  },
});

不写配置文件也能跑，需要自定义（端口、代理、别名、插件、base）时才加。

4. 环境变量与模式 ​

同一份代码，开发时连测试接口，上线连正式接口，靠环境变量区分。

  • 在项目根放 .env 文件，每行 KEY=value。
  • 只有以 VITE_ 开头的变量才会暴露给前端代码，通过 import.meta.env.VITE_XXX 读取。官方文档特别提醒：它们会被打进最终的 JS 里，不要放密钥、数据库密码。
  • 模式（mode）：vite（开发）默认 development，vite build 默认 production；也可以 vite build --mode staging 自定义。
  • 文件加载规则：.env 总是加载；.env.[mode] 只在对应模式加载（例如 .env.production），且优先级更高；另有 .env.local 系列不提交 Git，放个人机器上的覆盖值。
  • 还有几个内置变量：import.meta.env.MODE、DEV、PROD、BASE_URL。

5. 开发代理 server.proxy ​

浏览器的同源策略会拦截跨域请求（详见 Axios与跨域）。开发时最省事的办法是：前端只请求自己（/api/...），由 Vite 开发服务器在服务端转发给真正的后端。因为浏览器看到的始终是同源，根本不触发跨域；服务器到服务器的转发不受同源策略限制。

注意：代理只在开发服务器（和 vite preview）里存在，dist/ 部署到别的服务器后没有它，需要用 Nginx 反向代理或后端开启 CORS 来替代，见 前端工程化与部署。

6. 构建产物 ​

vite build 做了什么：把 TS 转 JS、合并模块、tree-shaking（去掉没用到的代码）、压缩、给文件名加哈希（如 index-BQ_GPVah.js，内容变了哈希才变），把环境变量直接替换成字面值。

7. base：部署在子路径 ​

默认产物里的资源路径以 / 开头（/assets/...），适合部署在域名根（https://a.com/）。如果要放在 https://a.com/app/ 下，要在构建时指定 base 为 /app/。

逐步例子 ​

目标：创建一个小看板项目，读环境变量，请求后端，观察开发与生产两种模式的差别。

步骤 1：创建项目 ​

npm create vite@latest vite-demo --registry=https://registry.npmmirror.com -- --template vanilla-ts --no-interactive
  • vite-demo 是目录名；--template vanilla-ts 选"原生 JS + TypeScript"模板（还有 vue-ts 等，见 Vue）；--no-interactive 跳过交互提问。
  • 本机实测输出 create-vite v9.3.1，Done. Now run: cd vite-demo / npm install / npm run dev。
  • 生成的 package.json 脚本："dev": "vite"、"build": "tsc && vite build"、"preview": "vite preview"；依赖 typescript ~6.0.3、vite ^8.3.4。
cd vite-demo
npm install --registry=https://registry.npmmirror.com
npm run build

首次安装在本机花了约两分钟（网络波动），构建输出（实测）：

✓ 9 modules transformed.
dist/index.html                  0.45 kB │ gzip: 0.29 kB
dist/assets/vite-BF8QNONU.svg    8.70 kB │ gzip: 1.60 kB
dist/assets/hero-CLDdwZDr.png   13.05 kB
dist/assets/index-CsUDhMuy.css   4.10 kB │ gzip: 1.46 kB
dist/assets/index-wktXvZw9.js    4.49 kB │ gzip: 2.02 kB
✓ built in 156ms

注意几点：build 脚本先跑 tsc 做类型检查，通过才打包；JS、CSS 文件名里的 wktXvZw9 就是内容哈希；gzip 是服务器压缩传输后的大小。

步骤 2：精简成我们自己的看板 ​

删掉模板的示例素材（src/assets、src/counter.ts、src/style.css、public/icons.svg），把 src/main.ts 改成：

ts
const app = document.querySelector<HTMLDivElement>("#app")!;

app.innerHTML = `
  <h1>${import.meta.env.VITE_APP_TITLE}</h1>
  <p>mode = ${import.meta.env.MODE}</p>
  <p>API base = ${import.meta.env.VITE_API_BASE}</p>
  <p>secret = ${String(import.meta.env.DB_PASSWORD)}</p>
  <pre id="out">loading...</pre>
`;

const url = import.meta.env.VITE_API_BASE + "/hello";
fetch(url)
  .then((r) => r.json())
  .then((d) => (document.querySelector("#out")!.textContent = "API: " + JSON.stringify(d)))
  .catch((e) => (document.querySelector("#out")!.textContent = "API failed: " + e.message));

（! 是 TypeScript 的"非空断言"：我保证这个元素一定存在。）

步骤 3：写环境变量文件 ​

.env：

VITE_APP_TITLE=MiniMES 看板
VITE_API_BASE=/api
DB_PASSWORD=should-not-leak

.env.production：

VITE_API_BASE=http://localhost:3202/api

意图：开发时请求相对路径 /api（交给代理）；生产构建时直连后端完整地址。DB_PASSWORD 故意不带 VITE_ 前缀，用来验证它不会泄露。

步骤 4：配置代理并启动后端 ​

vite.config.ts 如上节所示（端口 5180、代理 /api 到 3202）。后端用 Node 起一个最小服务 api-simple.js（端口 3202，不带任何 CORS 头）：

js
import http from "node:http";
http.createServer((req, res) => {
  console.log(req.method, req.url, "Origin=" + (req.headers.origin ?? "-"));
  res.setHeader("Content-Type", "application/json; charset=utf-8");
  res.end(JSON.stringify({ msg: "hello from backend", url: req.url }));
}).listen(3202, () => console.log("api on 3202 (no CORS headers)"));

启动：node api-simple.js，另一个终端 npx vite。

步骤 5：验证开发模式 ​

先用 curl 看代理：

curl --noproxy "*" http://localhost:5180/api/hello
{"msg":"hello from backend","url":"/api/hello"}

请求的是 5180（Vite），内容却来自 3202（后端），证明代理生效。再看 Vite 如何即时转换 TS：curl --noproxy "*" http://localhost:5180/src/main.ts，返回的已经是去掉类型的 JavaScript，并且开头被插入了一行 import.meta.env = {"BASE_URL": "/", "DEV": true, "MODE": "development", ... "VITE_API_BASE": "/api", "VITE_APP_TITLE": "MiniMES 看板"}——注意里面没有 DB_PASSWORD。

用无头浏览器（headless Edge）真实加载页面并导出渲染后的 DOM：

msedge --headless=new --disable-gpu --virtual-time-budget=5000 --dump-dom http://localhost:5180/

实际得到的 body：

<h1>MiniMES 看板</h1>
<p>mode = development</p>
<p>API base = /api</p>
<p>secret = undefined</p>
<pre id="out">API: {"msg":"hello from backend","url":"/api/hello"}</pre>

后端日志显示：GET /api/hello Origin=-——没有 Origin 头，因为对浏览器来说这是同源请求。

步骤 6：构建并验证生产模式 ​

npm run build

产物只有三个文件：dist/index.html、dist/favicon.svg、dist/assets/index-PQupHgoH.js（1.09 kB）。检查：

  • grep "should-not-leak" dist/assets/*.js：无匹配，密码没进产物；
  • JS 里能找到 localhost:3202/api：说明 .env.production 的值被直接替换进了代码；
  • 产物里 secret = undefined 是字面量替换后的结果。

这里要特别理解：环境变量在构建时就写死了，部署后改 .env 是没用的，要改变就得重新构建。

用 npx vite preview --port 4180 --strictPort 预览产物，再用 headless Edge 加载 http://localhost:4180/：

<p>mode = production</p>
<p>API base = http://localhost:3202/api</p>
<pre id="out">API failed: Failed to fetch</pre>

页面本身正常，但请求失败了：生产构建直连 http://localhost:3202，是跨域请求，而后端没配 CORS。后端日志证明请求其实到达了：GET /api/hello Origin=http://localhost:4180，是浏览器拒绝把响应交给页面。这正是 Axios与跨域 的主题。

动手实验 ​

实验 1：不同模式用不同变量 ​

新增 .env.staging：

VITE_APP_TITLE=MiniMES 看板（预发布）
VITE_API_BASE=http://localhost:3202/api

运行 npx vite build --mode staging，然后 grep "预发布" dist/assets/*.js 能命中；页面 mode = staging（本机实测，后面 前端工程化与部署会拿它做部署演示）。

实验 2：子路径部署 ​

把 dist 放在 /app/ 下用 Python 静态服务器托管：

npx vite build --mode staging --base=/app/

查看 dist/index.html，脚本路径变成 src="/app/assets/index-BQ_GPVah.js"（不加 --base 时是 /assets/...）。复制到 site/app/，在 site/ 目录执行 python -m http.server 8080 --bind 127.0.0.1，访问 http://localhost:8080/app/ 页面正常。

如果忘了加 base却放在 /app/ 下，页面空白，服务器日志出现 GET /assets/index-BQ_GPVah.js HTTP/1.1" 404（本机实测）：浏览器去根目录找资源，找不到。

Git Bash 用户注意：--base=/app/ 会被自动改写成 C:/Program Files/Git/app/，需先 export MSYS_NO_PATHCONV=1（本机踩过的坑）。

实验 3：端口被占用 ​

本机的知识库网站（VitePress，其底层也是 Vite）已经占用了 5173。再启动一个 Vite 时，终端提示 Port 5173 is in use, trying another one... 并换到 5174。想要固定端口就设置 server.strictPort: true。

常见坑与排查 ​

  1. 读不到环境变量：变量名没有 VITE_ 前缀；或改了 .env 没有重启开发服务器。
  2. 以为 .env 能放密钥：VITE_ 变量会被打进 JS，任何访问者都能看到。密钥只放后端。
  3. 生产环境请求失败，开发正常：开发靠代理，生产没有代理；要么后端开 CORS，要么用 Nginx 反向代理。
  4. 刷新子页面 404：单页应用用了 history 路由时，服务器需要把所有路径回退到 index.html，见 前端工程化与部署。
  5. 部署到子路径后白屏：忘了设置 base。
  6. 直接双击 dist/index.html（file://）白屏：模块脚本在 file:// 下被浏览器拦截。本机用 headless Edge 实测 file:///.../dist/index.html，得到的是空的 <div id="app"></div>。要用静态服务器打开（vite preview 或 python -m http.server）。
  7. 构建报类型错误：build 脚本里有 tsc，类型不过就不打包。修类型错误，不要删掉 tsc。
  8. vite preview 当生产服务器用：它是预览工具，官方不建议当正式服务器；正式上线用 Nginx/IIS 等托管 dist/。
  9. 依赖安装卡住：用 npmmirror（见 Node.js与npm）。

业务视角与技术视角 ​

  • 业务视角：车间看板、扫码页往往有"测试线 / 正式线"两套后端。用环境变量区分接口地址，同一份代码能出两个版本，避免手改地址上线出错。
  • 技术视角：Vite 把"TS 转换 + 模块打包 + 热更新 + 代理"集成在一起；对 C# 开发者，可类比 Visual Studio 的"调试 / 发布"：npm run dev 像按 F5，npm run build 像"发布到文件夹"，dist/ 就是 publish/ 目录。

练习题与答案 ​

练习 1：.env 里有 VITE_A=1、B=2，前端读 import.meta.env.B 得到什么？

答案：undefined。没有 VITE_ 前缀的变量不会暴露（本篇实验中 DB_PASSWORD 即如此）。

练习 2：.env 里 VITE_API_BASE=/api，.env.production 里 VITE_API_BASE=http://x/api，执行 vite build 后得到哪个？

答案：http://x/api。.env.[mode] 优先于 .env，build 默认模式是 production（实测产物里是 localhost:3202/api）。

练习 3：开发时代理工作正常，npm run build 后部署到别的服务器却出现 Failed to fetch，为什么？

答案：代理只在 Vite 开发/预览服务器里；生产里变成了浏览器直接跨域请求，缺少 CORS 响应头被拦截。

练习 4：产物文件名 index-BQ_GPVah.js 的哈希有什么用？

答案：内容变化时文件名才变，因此浏览器和 CDN 可以对旧文件长期缓存，更新时因文件名不同自动拉新文件。

小结 ​

  • Vite = 开发时按需转换的服务器 + 上线时打包的构建器。
  • dev / build / preview 三条命令各司其职，preview 只是检查产物。
  • 只有 VITE_ 前缀的环境变量暴露给前端，且在构建时被替换成字面值，不要放密钥。
  • server.proxy 只存在于开发期，是解决开发跨域的常用手段。
  • 部署到子路径要设 base；不能用 file:// 打开产物。
