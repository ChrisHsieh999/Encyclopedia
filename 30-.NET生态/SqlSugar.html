SqlSugar

AI 生成 · 待核对dotNETORM数据库更新于 2026-10-21

本篇是 dotNET 数据访问部分的第 1 篇，也是你们公司 MES 系统用的 ORM。读完你应该能：说清 ORM 是什么、SqlSugar 的几个"链式入口"各管什么；用 CodeFirst 建表、用 Lambda 写查询/分页/连表/分组；做增删改、批量写入、事务、软删除；打印出实际执行的 SQL；分清 SqlSugarClient 和 SqlSugarScope 该在什么场合用哪个；并避开"中文列变成问号"这个最常见的坑。

一句话定义 ​

SqlSugar 是国产的 .NET ORM（对象关系映射）库：你用 C# 类描述表，用 Lambda 表达式写查询，它帮你生成并执行 SQL，把结果装回 C# 对象。

先修知识 ​

  • CSharp类与对象：属性、对象初始化器。
  • LINQ 与 CSharp委托事件与Lambda：e => e.Salary > 7000 这种写法。
  • SQL基础查询、SQL增删改、SQL连接JOIN：知道 SELECT / INSERT / UPDATE / DELETE / JOIN 各是什么。
  • 事务与ACID：知道事务"要么全成功、要么全回滚"。
  • NuGet：怎么给项目装包。
  • 建议先看一遍 MES 里的"迷你 MES"实验，本篇沿用它的项目写法。

它解决什么问题 ​

不用 ORM 时，访问数据库要手写 ADO.NET：建连接、拼 SQL 字符串、加参数、开读取器、一列一列取值。又长又容易拼错，字符串拼接还有 SQL 注入风险。

ORM 的思路是"类 = 表，对象 = 一行，属性 = 一列"：

数据库世界C# 世界
表 Employee类 Employee
一行数据一个 Employee 对象
列 Salary属性 Salary
WHERE Salary >= 7000.Where(e => e.Salary >= 7000)

好处：编译器帮你检查字段名（改了属性名，没改的地方编译就报错）；参数自动参数化，防注入；换数据库类型（SQL Server / Oracle / MySQL）时多数查询代码不用改。坏处：复杂 SQL 用 Lambda 写会别扭，这时 SqlSugar 允许你直接写原生 SQL（后面有一节）。

SqlSugar 的特点是 API 偏"链式"、上手快、对 SQL Server / Oracle / MySQL 等多种库都支持（官方文档说明支持的数据库很多，具体清单以 GitHub 仓库 为准），在国内企业里很常见。

核心概念（由浅入深） ​

1. 实体类：用特性描述表 ​

csharp
[SugarTable("Employee")]                       // 对应的表名；不写就用类名
public class Employee
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]   // 主键 + 自增
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(50)")]           // 含中文：必须 nvarchar
    public string Name { get; set; }
    public int DeptId { get; set; }
    [SugarColumn(ColumnDataType = "decimal(10,2)")]
    public decimal Salary { get; set; }
    public bool IsDeleted { get; set; }
    [SugarColumn(IsIgnore = true)]                           // 不对应任何列
    public string TempNote { get; set; }
}

常用的 [SugarColumn] 参数：

参数含义
IsPrimaryKey是主键
IsIdentity自增列（插入时不要给它赋值）
Length字符串长度。注意：只指定 Length 时，string 建成 varchar(长度)
ColumnDataType直接指定数据库列类型，如 "nvarchar(50)"、"decimal(18,4)"
IsNullable允许为 NULL
IsIgnore这个属性不是列（比如计算结果、临时备注）
ColumnName列名和属性名不一样时指定

2. 中文列必须 nvarchar（最常见的坑） ​

SqlSugar 自动建表时，C# 的 string 如果不指定类型，会建成 varchar。varchar 是非 Unicode 列，用的是数据库的代码页；LocalDB 默认的代码页是西欧的，中文存进去直接变成问号，而且原始数据永久丢失，不是显示问题。

本篇的实验故意建了一张错误的表 BadName（Name 没指定类型）做对比，实测结果：

=== 3 中文列坑：varchar 与 nvarchar ===
varchar 列读出: ??ABC  字节(十六进制): 3F3F414243
Employee 列类型: nvarchar
BadName 列类型 : varchar
Employee 里的中文: 张三

读出来是 ??ABC；用 CONVERT(varbinary, ...) 看真正存进去的字节是 3F3F414243，3F 就是问号。而写了 ColumnDataType = "nvarchar(50)" 的 Employee.Name 读出 张三，完全正常。

规则：凡是可能含中文的列都写 nvarchar；料号、编码这类纯英文数字的列可以用 varchar 省空间。 如果你们的系统是用 SqlSugar 自动建的表，值得抽查一下有没有中文列被建成了 varchar（见 MES 里同样的提醒）。

3. 连接配置 ConnectionConfig ​

csharp
var db = new SqlSugarClient(new ConnectionConfig
{
    ConnectionString = @"Server=(localdb)\MSSQLLocalDB;Database=Lab_SqlSugar;Trusted_Connection=True;TrustServerCertificate=True;",
    DbType = DbType.SqlServer,        // 数据库类型
    IsAutoCloseConnection = true,     // 每次操作完自动关连接（强烈建议开）
    InitKeyType = InitKeyType.Attribute,  // 以实体上的特性为准（主键/自增来自 [SugarColumn]）
});
  • IsAutoCloseConnection = true：用完自动关闭，不用手写 Close()；不开的话要自己管理连接，忘了就泄漏连接。
  • InitKeyType.Attribute：告诉 SqlSugar 主键、自增信息看实体特性。用特性的写法时必须设这个（另一个选项 SystemTable 是去数据库系统表里读，一般用于 DbFirst 场景）。
  • 连接字符串里的 TrustServerCertificate=True：新版 SQL Server 驱动默认要求加密连接，连本机 LocalDB 时加上这个才不会报证书错误。

4. 五个"链式入口" ​

SqlSugar 的 API 记住这 5 个入口就够了：

入口作用例
db.Queryable<T>()查db.Queryable<Employee>().Where(...).ToList()
db.Insertable(...)增db.Insertable(list).ExecuteCommand()
db.Updateable(...)改db.Updateable<Employee>().SetColumns(...).Where(...).ExecuteCommand()
db.Deleteable<T>()删db.Deleteable<Employee>().Where(...).ExecuteCommand()
db.Ado原生 SQL、事务db.Ado.SqlQuery<T>("select ...")

链条的最后一步才真正执行：查询是 ToList() / First() / Count() 等，增删改是 ExecuteCommand()（返回影响行数）。前面的 Where、OrderBy 只是在拼条件，不会访问数据库。

5. SqlSugarClient 与 SqlSugarScope ​

两者都叫"主 db"。区别在线程/上下文安全：

  • SqlSugarClient：每个实例内部持有一个连接状态，不是线程安全的，不能被多个线程/请求共享。官方"单例模式"文档的原话是："SqlSugarClient不能单例只能用 SqlSugarScope"。
  • SqlSugarScope：对 Client 的再封装。官方文档说它"在同一个上下文是同一个对象，不同上下文自动创建新对象"，因此可以放心做单例，同时解决了单例的死锁问题和非单例的线程安全问题，也能让事务跨方法使用。
  • 依赖注入注册时（官方 IOC 文档）：SqlSugarScope 用 AddSingleton，SqlSugarClient 用 AddScoped（每个请求一个实例），二选一，不要混用。
csharp
// 官方 IOC 文档的写法：Scope + 单例
builder.Services.AddSingleton<ISqlSugarClient>(s =>
{
    return new SqlSugarScope(new ConnectionConfig
    {
        ConnectionString = "……",
        DbType = DbType.SqlServer,
        IsAutoCloseConnection = true,
    }, db =>
    {
        // 这个回调里配置 AOP、过滤器等；每个新上下文创建 Client 时都会执行
        db.Aop.OnLogExecuting = (sql, pars) => Console.WriteLine(sql);
    });
});
// 业务类里通过构造函数注入 ISqlSugarClient 即可

⚠ 这段 DI 注册代码来自官方文档，没有在本机单独跑 Web 项目验证。SqlSugarScope 本身的行为（单例、多线程并发查询、Aop.OnError）已在下面的实验 13 实测。依赖注入的概念见 依赖注入。

官方文档里点名的错误单例写法：用属性/表达式体每次返回 new 的新对象；在泛型类里放静态字段（每个 T 一份实例）；在构造函数里 new。如果是自己写静态单例，把 public static SqlSugarScope Db = new(...) 放在非泛型类里。官方建议初始化后打印 Db.GetHashCode() 看是否始终相同来确认确实是单例。

拿不准就记一条：Web 项目里注册 SqlSugarScope 为单例；控制台小工具里一个 SqlSugarClient 够用。

逐步例子 ​

下面所有输出都来自本机的真实运行（LocalDB 里的临时库 Lab_SqlSugar，跑完自动 DROP）。完整代码在"动手实验"，这里按主题拆开讲。

例 1：CodeFirst 建库建表 ​

CodeFirst = "先写 C# 类，再让工具建表"：

csharp
db.DbMaintenance.CreateDatabase();                       // 库不存在就建
db.CodeFirst.InitTables(typeof(Dept), typeof(Employee), typeof(BadName));   // 表不存在就建
=== 1 建库建表 CodeFirst ===
表: BadName, Dept, Employee
Employee 列: Id(int), Name(nvarchar), DeptId(int), Salary(decimal), IsDeleted(bit)

注意 Employee 的 TempNote 属性因为 IsIgnore = true，没有生成列。对已存在的表，InitTables 会尝试按实体的变化调整表结构，能调到什么程度（加列、改类型、改长度）本篇没有逐项测试，以官方文档为准；总之生产库不要依赖它做表结构变更，正式变更用 SQL 脚本，并先在测试库验证。

反过来，DbFirst = "库里已有表，生成实体类"：

csharp
db.DbFirst.Where("Dept").CreateClassFile(dir, "SugarLab.Gen");   // 为 Dept 表生成 Dept.cs

实测生成了一个 Dept.cs：类是 public partial class Dept，每个属性带 Desc / Default / Nullable 注释，但不带 [SugarTable] / [SugarColumn] 特性（表名和类名相同时不需要）。生成后你需要自己补主键、自增、nvarchar 等特性。这对"接手一个已有的数据库"很有用。

例 2：插入与自增主键 ​

csharp
var deptId = db.Insertable(new Dept { Name = "SMT车间" }).ExecuteReturnIdentity();
=== 2 插入 ===
  [SQL] INSERT INTO [Dept]              ([Name])      VALUES            (@Name) ;SELECT SCOPE_IDENTITY();
  [参数] @Name=SMT车间
新部门 Id = 1
批量插入行数 = 5
  • ExecuteReturnIdentity() 返回新行的自增 Id（上面第一个部门 Id 是 1）。
  • 传入 List<Employee>，ExecuteCommand() 一次插入多行，返回影响行数 5。
  • 第 1 行 [SQL] 就是 AOP 打印出来的真实 SQL，见后面"打印 SQL"。

例 3：查询、动态条件、分页 ​

csharp
var rich = db.Queryable<Employee>()
    .Where(e => e.Salary >= 7000m && !e.IsDeleted)
    .OrderBy(e => e.Salary, OrderByType.Desc)
    .ToList();

// 条件是否生效取决于变量：WhereIF
var dyn = db.Queryable<Employee>()
    .WhereIF(!string.IsNullOrEmpty(nameFilter), e => e.Name.Contains(nameFilter))
    .WhereIF(dept.HasValue, e => e.DeptId == dept.Value)
    .ToList();

// 分页：第 2 页，每页 2 条，同时拿到总数
int total = 0;
var page2 = db.Queryable<Employee>().OrderBy(e => e.Id).ToPageList(2, 2, ref total);
=== 4 查询 ===
  [SQL] SELECT [Id],[Name],[DeptId],[Salary],[IsDeleted] FROM [Employee]  WHERE (( [Salary] >= @Salary0 ) AND NOT ( [IsDeleted]=1 ) )ORDER BY [Salary] DESC
  [参数] @Salary0=7000
工资>=7000: 孙七:9000.00, 赵六:8000.00, 王五:7000.00
名字含'三': 张三
Count=5  Any(Salary>9000)=False  Max=9000.00
动态条件(只按部门): 3 人
=== 5 分页 ===
  [SQL]  SELECT COUNT(1) FROM (SELECT [Id],[Name],[DeptId],[Salary],[IsDeleted] FROM [Employee] ) CountTable 
  [SQL] SELECT * FROM (SELECT [Id],[Name],[DeptId],[Salary],[IsDeleted],ROW_NUMBER() OVER(ORDER BY [Id] ASC) AS RowIndex  FROM [Employee] ) T WHERE RowIndex BETWEEN 3 AND 4
第2页(每页2条): 王五, 赵六  总数=5

要点：

  • 值 7000m 被自动变成参数 @Salary0，不是拼进 SQL 字符串，所以不用担心注入（见 SQL基础查询 里的参数化思想）。
  • WhereIF(条件, 表达式)：做"查询页面里有的筛选框填了才加条件"非常方便，比 if 拼一串更整洁。
  • ToPageList(pageIndex, pageSize, ref total)：页码从 1 开始；SqlSugar 先发一条 COUNT(1) 取总数，再发一条 ROW_NUMBER() OVER(ORDER BY ...) 取该页。分页必须有 OrderBy，否则每次翻页结果顺序不保证。
  • 其他常用终结方法：First()（没数据抛异常或返回 null，以版本行为为准，建议用 Any 先判断）、InSingle(id)（按主键取一行）、Count()、Any()、Max()。

csharp

BulkCopy 1000 行成功, 表内总数 = 1005

  • Fastest<T>().BulkCopy 走的是 SQL Server 的批量复制通道，速度比逐条 INSERT 快一个量级（量级差距是常识，本篇没有做压测，数字以你们的数据为准）。代价是：不触发 AOP 的单条 SQL 日志、对自增列和类型要求更严格。普通几百行的写入用 Insertable(list) 就够。
  • Storageable 把一批数据按"主键/指定列"分成"该新增的"和"该更新的"两堆：实验里 2 条数据，1 条 Id 已存在 → 更新，另 1 条 Id=99999 不存在 → 新增。（实验没有执行新增那一堆，因为 Id 是自增列，不能手工给值；实际使用时对"业务键"（如工单号）用 WhereColumns 最合适。）

=== 9 事务 UseTran ===

成功的事务: IsSuccess=True, 人数 -> 7
BeginTran/CommitTran 清理后人数 = 5

第一个事务里先插入一行再抛异常，结果 IsSuccess=False、错误信息是我们抛的"故意失败"，人数仍是 5 —— 插进去的那一行被回滚了。第二个事务两行都提交，人数变 7。注意 UseTran 默认会吞掉异常，只放进 r.ErrorMessage，你必须检查 IsSuccess，否则失败了程序还以为成功。事务的原理见 事务与ACID。

软删除 = 不真删，只把 IsDeleted 标成 true。每个查询都要记得加 !IsDeleted 很容易漏，所以用全局过滤器：

例 10：打印 SQL（AOP） ​

AOP 就是"在某个动作前后插入自己的代码"。SqlSugar 在 db.Aop 上提供事件：

csharp
db.Aop.OnLogExecuting = (sql, pars) =>      // 每条 SQL 执行之前
{
    var p = string.Join(", ", pars.Select(x => $"{x.ParameterName}={x.Value}"));
    Console.WriteLine("[SQL] " + sql);
    Console.WriteLine("[参数] " + p);
};
db.Aop.OnError = ex => Console.WriteLine("[出错] " + ex.Message);    // SQL 执行出错时

开发期强烈建议打开：你能看到 Lambda 到底被翻译成了什么 SQL，慢查询、重复查询一眼就能发现。正式环境把它接到日志系统（见 配置与日志），并注意别把含敏感数据的参数值写进日志。常用的还有 OnLogExecuted（执行之后，可取耗时）、DataExecuting（写入前统一加创建时间、创建人）等，详见官方 AOP 文档。

业务视角与技术视角 ​

  • 业务视角：MES 里的工单、BOM、过站记录、不良记录，最终都是数据库里的行。ORM 让开发者用"工单对象"而不是"SQL 字符串"思考，更容易和业务人员对齐字段含义；软删除过滤器对应业务上"单据作废但要可追溯"的要求（制造业不允许随便物理删除，见 工单管理）。
  • 技术视角：在分层架构里（见 软件架构分层），SqlSugar 属于数据访问层；上层通过仓储/服务调用，不直接到处写 db.Queryable。批量采集类大数据量（设备数据落库）用 BulkCopy；报表类复杂 SQL 用 SqlQueryable/SqlQuery；与 EF-Core、Dapper 的取舍见各自词条。

练习题与答案 ​

练习 1：下面的更新有什么问题？应该怎么改？

csharp
db.Updateable(new Employee { Id = 3, Salary = 9999m }).ExecuteCommand();

答案：没有指定要更新的列，Name（null）、DeptId（0）、IsDeleted（false）等都会被一起写回，等于把这行的其他字段清空。改为 .UpdateColumns(e => e.Salary)，或 db.Updateable<Employee>().SetColumns(e => e.Salary == 9999m).Where(e => e.Id == 3)。

练习 2：要查"质量部（DeptId=2）里工资最高的 2 个人"，写出 Lambda。

答案：db.Queryable<Employee>().Where(e => e.DeptId == 2).OrderBy(e => e.Salary, OrderByType.Desc).Take(2).ToList()。按本篇数据，结果是孙七（9000）和赵六（8000）。

练习 3：Web 项目里为什么不能把一个 SqlSugarClient 注册成单例？

答案：SqlSugarClient 实例内部有连接/事务状态，不是线程安全的；单例会被多个请求并发使用，出现连接被占用、事务串线等偶发错误。应注册 SqlSugarScope 为单例，或把 SqlSugarClient 注册成 Scoped（每请求一个）。

练习 4：为什么要把"全局软删除过滤器"放进 AddTableFilter，而不是每个查询手写 !IsDeleted？

答案：手写容易漏，漏一处就会让"已作废"的数据重新出现在界面或报表里；放进全局过滤器后每个查询自动生效，需要看全部数据时再显式 ClearFilter。

练习 5（动手）：运行实验，把第 9 节第二个事务里的第二个 Insertable 前面加一行 throw new Exception("半路失败");，预期输出里"人数"会怎样？

答案：两条插入都被回滚，IsSuccess=False，人数保持 5（因为第一条已执行的插入也被回滚）。

小结 ​

  • ORM = 类对应表；SqlSugar 的五个入口：Queryable / Insertable / Updateable / Deleteable / Ado。
  • 含中文的列一律 nvarchar，否则中文永久变成问号。
  • 更新要用 UpdateColumns / SetColumns，别整行覆盖；删除、更新必带 Where。
  • UseTran 不抛异常，要看 IsSuccess；打开 AOP 打印 SQL 是排查问题的第一步。
  • Web 里用 SqlSugarScope 单例，SqlSugarClient 只给单线程或 Scoped 场景。
