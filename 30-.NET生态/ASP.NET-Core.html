ASP.NET-Core

AI 生成 · 待核对dotNETWeb更新于 2026-10-21

本篇是 dotNET 入门路径的第 4 篇。读完你应该能：说清 ASP.NET Core 是什么、一个 Web 程序启动后在做什么；用"最小 API"写出带路径参数、查询参数、JSON 请求体的接口；看懂 Program.cs 和 launchSettings.json；知道什么时候该换成控制器（下一篇 WebAPI开发）。

一句话定义 ​

ASP.NET Core 是 .NET 上用来写 Web 应用的框架：它内置一个叫 Kestrel 的 Web 服务器，接收 HTTP 请求，经过一串处理环节（中间件与请求管道），交给你写的代码处理，再把结果作为 HTTP 响应返回。

先修知识 ​

  • HTTP：请求（方法、路径、头、正文）和响应（状态码、头、正文）。
  • REST-API设计：GET/POST 等方法的语义（可先略读）。
  • dotNET、dotNET运行时与SDK：会 dotnet new、dotnet run。
  • CSharp委托事件与Lambda：最小 API 大量使用 Lambda 表达式。

它解决什么问题 ​

工厂里的系统要互相说话：MES 客户端要查工单，设备采集程序要上报数据，看板要拉实时产量。它们之间最通用的"语言"就是 HTTP + JSON。自己用 Socket 写 HTTP 服务器要处理连接、解析报文、多线程、编码……(参见 Socket编程)。ASP.NET Core 把这些全做好，你只需写"收到某个地址的请求时，做什么、返回什么"。

核心概念 ​

请求怎么走 ​

  • Kestrel：跨平台的 Web 服务器，内置在你的程序里。你的程序本身就是一个 HTTP 服务器，不需要先装 IIS（需要时可以放在 IIS 后面，见 部署到IIS）。
  • 中间件管道：请求依次经过一串"关卡"，下一篇 中间件与请求管道 专讲。
  • 端点（Endpoint）：一个"地址 + 方法 -> 处理代码"的映射，例如"GET /sum 调用这个 Lambda"。

Program.cs：只有三步 ​

dotnet new web -n Hello 生成的完整 Program.cs：

csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello World!");

app.Run();
  1. WebApplication.CreateBuilder(args)：创建构建器。此时它已经默认帮你加载了配置（配置与日志）、日志、依赖注入容器（依赖注入）。你在 builder.Services 上登记服务。
  2. builder.Build()：造出 app。之后在 app 上配置管道和端点。
  3. app.Run()：启动 Kestrel 开始监听，这行会一直阻塞直到程序被停止。

两阶段的口诀：Build 之前登记服务，Build 之后配置管道。

最小 API（Minimal API） ​

用 app.MapGet / MapPost / MapPut / MapDelete 直接把地址绑到一个 Lambda 上。参数从哪来，框架按规则自动推断：

参数来源示例
名字出现在路由模板 {name} 里路径/hello/{name}
简单类型（int、string）不在路由里查询字符串/sum?a=3&b=4
复杂类型（类、record），POST/PUTJSON 请求体{"text":"hello"}
已登记在容器里的服务依赖注入见 依赖注入

返回值：返回字符串 -> 纯文本；返回对象 -> 自动序列化为 JSON（见 System.Text.Json）；返回 Results.Ok(...)、Results.NotFound() 等可精确控制状态码。

逐步例子与动手实验：一个小服务 ​

1. 创建项目 ​

powershell
dotnet new web -n Mini
cd Mini

2. 把 Program.cs 换成 ​

csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "MES 迷你服务已启动");

// 路径参数：/hello/Tom
app.MapGet("/hello/{name}", (string name) => $"你好，{name}");

// 查询字符串：/sum?a=3&b=4
app.MapGet("/sum", (int a, int b) => new { a, b, sum = a + b });

// 请求体 JSON → 对象
app.MapPost("/echo", (Echo body) => Results.Ok(new { received = body.Text, length = body.Text.Length }));

// 路由分组
var api = app.MapGroup("/api");
api.MapGet("/ping", () => Results.Ok(new { pong = true }));
api.MapGet("/status/{code:int}", (int code) => Results.StatusCode(code));

app.Run();

record Echo(string Text);

{code:int} 是路由约束：只有路径段是整数才匹配。MapGroup("/api") 给一组端点加共同前缀。

3. 运行 ​

powershell
dotnet run --urls http://localhost:5102

看到 Now listening on: http://localhost:5102。另开一个 PowerShell 窗口调用：

powershell
Invoke-RestMethod "http://localhost:5102/sum?a=3&b=4"

PowerShell 里 & 是特殊符号，URL 里有 & 时必须把整个地址用引号包起来。

4. 实测结果 ​

请求响应
GET /200，MES 迷你服务已启动
GET /hello/Tom200，你好，Tom
GET /sum?a=3&b=4200，{"a":3,"b":4,"sum":7}
GET /api/ping200，{"pong":true}
GET /api/status/418418 I'm a teapot（空正文）
GET /nothing404
GET /sum?a=3（少参数）400 Bad Request
POST /echo 正文 {"text":"hello"}200，{"received":"hello","length":5}
POST /echo 不带 Content-Type415 Unsupported Media Type

POST 用 PowerShell：

powershell
Invoke-RestMethod -Method Post -Uri http://localhost:5102/echo -ContentType 'application/json' -Body '{"text":"hello"}'

输出：

received length
-------- ------
hello         5

用 curl.exe（注意要写 .exe，否则 PowerShell 5.1 里 curl 是 Invoke-WebRequest 的别名）：

powershell
curl.exe -s -i "http://localhost:5102/sum?a=3&b=4"

5. 开发模式与生产模式的差别 ​

少传参数时，在 Development 环境返回的是带异常详情的文本，如：

Microsoft.AspNetCore.Http.BadHttpRequestException: Required parameter "int b" was not provided from query string.

而用 ASPNETCORE_ENVIRONMENT=Production 运行，同一请求只返回 400 空正文，不泄露内部信息。这就是"开发环境显示详细错误，生产环境不显示"的设计（环境概念详见 配置与日志）。

6. launchSettings.json：dotnet run 的默认设置 ​

项目里的 Properties\launchSettings.json：

json
{
  "profiles": {
    "http": {
      "commandName": "Project",
      "launchBrowser": true,
      "applicationUrl": "http://localhost:5063",
      "environmentVariables": { "ASPNETCORE_ENVIRONMENT": "Development" }
    }
  }
}
  • 端口是创建项目时随机生成的（每个项目不一样，这里是 5063）。
  • ASPNETCORE_ENVIRONMENT=Development 就是 dotnet run 默认处于开发环境的原因。
  • 只对开发时的 dotnet run/VS 有效；发布后的程序不读这个文件。用 --urls、环境变量 ASPNETCORE_URLS 或配置文件指定端口。本机实测发布后的 Mini.exe，用 ASPNETCORE_URLS=http://localhost:5106 启动，日志显示 Hosting environment: Production。

7. 发布并运行 ​

powershell
dotnet publish -c Release -o pub
$env:ASPNETCORE_URLS = "http://localhost:5106"
.\pub\Mini.exe

发布目录里有 Mini.exe、Mini.dll、appsettings.json、web.config 等（实测整个目录约 206 KB，不含运行时，所以目标机器要装 ASP.NET Core 运行时）。

最小 API 还是控制器？ ​

最小 API控制器（Controller）
写法app.MapGet(...) 直接绑 Lambda一个类，每个方法是一个动作，用特性标注路由
适合小服务、微服务、原型、简单接口接口多、需要分组/过滤器/统一校验的业务系统
校验需自己写或用库[ApiController] 自动校验模型
本库本篇WebAPI开发

两者可以同一个项目共存，底层相同（同一条管道）。一个经验：接口少、逻辑简单用最小 API；业务 API 超过十几个就用控制器，结构更清晰。

常见坑与排查 ​

  • Failed to bind to address ... address already in use：端口被占用。换一个端口，或结束占用的进程。
  • 本机有 HTTP_PROXY 环境变量时，命令行工具访问 localhost 返回 502/503：本机实测遇到。给 curl.exe 加 --noproxy "*"。Invoke-RestMethod 通常不受影响。
  • POST 返回 415：没带 Content-Type: application/json。
  • POST 少了字段返回 500：上面的 Echo(string Text)，请求体 {} 时 Text 是 null，执行 body.Text.Length 抛出空引用，返回 500（本机实测）。对外接口必须校验输入，见 WebAPI开发。
  • 中文路径：在 Git Bash 里用 curl 带中文路径会被转成 GBK 乱码，用 PowerShell 的 Invoke-RestMethod 并对中文做 [uri]::EscapeDataString(...)。
  • 改了代码没生效：dotnet run 不会自动重启。开发时可以用 dotnet watch，保存后自动重新编译重启。
  • 返回的 JSON 属性首字母变小写：WorkOrderNo 变成 workOrderNo，这是 Web 默认的 camelCase 命名，前端按小写取（见 System.Text.Json）。

业务视角与技术视角 ​

业务视角：Web API 是"系统之间的服务窗口"。MES 对 ERP、对 WMS、对设备采集，每个窗口的地址、入参、出参、错误码都要事先约定好，这就是接口文档（后面 Swagger与OpenAPI 自动生成）。

技术视角：

  • 每个请求在线程池里被并发处理，所以共享的状态（缓存、计数器）要注意线程安全（见 CSharp多线程与锁）。
  • 端点里做耗时的数据库/网络调用要用 async/await（见 CSharp异步编程），否则线程被占满，服务变慢。
  • 分层：端点只做"收参数、调服务、返结果"，业务逻辑放到服务类里（软件架构分层、依赖注入）。

练习题与答案 ​

  1. 写一个端点 GET /double/{n}，返回 n 的两倍（n 为整数）。 答：app.MapGet("/double/{n:int}", (int n) => n * 2);，访问 /double/21 返回 42。
  2. /sum?a=3 为什么返回 400？ 答：参数 b 是必填的 int，没提供，框架拒绝请求。改成 int? b 就变成可选（本机实测：(int a, int? b) => a + (b ?? 0) 访问 /sum2?a=3 返回 3）。
  3. 为什么发布后 launchSettings.json 里的端口不起作用？ 答：它是开发工具读的文件，不随程序发布；用 ASPNETCORE_URLS 或配置文件指定端口。
  4. Build() 之前和之后各做什么？ 答：之前登记服务（builder.Services），之后配置管道和端点（app.Use...、app.Map...）。

小结 ​

  • ASP.NET Core = Kestrel + 中间件管道 + 路由 + 你的端点；本身就是一个 HTTP 服务器。
  • Program.cs 三步：CreateBuilder、Build、Run。
  • 最小 API 用 MapGet/MapPost 绑 Lambda，参数来源自动推断；复杂业务用控制器。
  • 开发环境显示详细错误，生产环境不显示；launchSettings.json 只管开发。
