Dapper

AI 生成 · 待核对dotNETORM数据库更新于 2026-10-21

本篇是 dotNET 数据访问部分的第 3 篇。读完你应该能：说清 Dapper 与 SqlSugar、EF-Core 的本质区别；用 Dapper 做查询、参数化、批量、连表映射、事务；理解"列名对不上属性名"的几种解法；并知道什么时候该选它。

一句话定义 ​

Dapper 是一个很小的库：它在 IDbConnection 上加了几个扩展方法（Query、Execute 等），帮你把"手写的 SQL 语句 + 参数"执行后的结果自动映射成 C# 对象；SQL 本身仍由你亲手写。

先修知识 ​

  • SQL基础查询、SQL增删改、SQL连接JOIN：Dapper 里 SQL 是你写的，必须会。
  • CSharp类与对象、CSharp集合与泛型（泛型方法 Query<Employee> 的写法）。
  • SqlSugar：先读它，知道 ORM 做了哪些事，才能理解 Dapper "少做了什么"。
  • 了解 ADO.NET 的 SqlConnection 就够了：它是 .NET 连接 SQL Server 的底层对象。

它解决什么问题 ​

纯 ADO.NET 读一个查询要这样：建 SqlCommand、加参数、ExecuteReader()、while (reader.Read())、一列列 GetString(0)、GetInt32(1) ……非常啰嗦。完整 ORM（EF Core）又比较重，生成的 SQL 你不能完全掌控。

Dapper 的定位在中间：

ADO.NETDapperSqlSugar / EF Core
SQL 谁写你你框架生成（也可手写）
结果映射成对象手工自动自动
学习成本低但代码长很低较高
对 SQL 的控制完全完全部分
建表/迁移/变更跟踪无无有

适合：报表和复杂查询、对性能敏感的热点路径、已经有一大堆写好的 SQL/存储过程的老系统、需要精确控制每一条 SQL 的场合。

核心概念（由浅入深） ​

1. 扩展方法一览 ​

Dapper 就是 using Dapper; 之后 SqlConnection 上多出来的这些方法：

方法用途
Query<T>(sql, 参数)返回多行，映射成 IEnumerable<T>
QueryFirst<T> / QueryFirstOrDefault<T>取第一行（没有行时前者抛异常，后者返回默认值 null）
QuerySingle<T> / QuerySingleOrDefault<T>要求恰好一行（多于一行抛异常）
Execute(sql, 参数)增删改，返回影响行数
ExecuteScalar<T>返回第一行第一列（如 COUNT(*)）
QueryMultiple一次发多条 SELECT，依次读多个结果集
Query<A, B, TReturn>连表，把一行拆成两个对象再组合

2. 参数化：匿名对象 ​

csharp
db.Query<Employee>("SELECT * FROM Employee WHERE Salary >= @min", new { min = 7000 });

@min 是占位符，new { min = 7000 } 的属性名就是参数名。参数由数据库驱动传递，不是拼进字符串，因此不会被 SQL 注入。后面的实验把"字符串拼接"和"参数化"并排对比。

3. 连接的生命周期 ​

Dapper 不自己管理连接：SqlConnection 如果没打开，Dapper 会自动打开并在执行后关闭；已经手动 Open() 的则保持。ADO.NET 内部有连接池，所以"用时创建、用完 using 释放"的成本很低。多个语句要在同一个事务里时，才需要手动 Open()、BeginTransaction()。

4. 映射规则 ​

默认按"列名 = 属性名"（不区分大小写）映射。不一致时三种办法：SQL 里起别名 AS；全局设置 DefaultTypeMap.MatchNamesWithUnderscores = true（hire_date → HireDate）；自定义映射。

逐步例子 ​

输出全部来自本机真实运行（LocalDB 临时库 Lab_Dapper，程序结束时 DROP）。完整代码见"动手实验"。

例 1：建表、插入、批量插入 ​

csharp
db.Execute("CREATE TABLE Dept (Id int IDENTITY PRIMARY KEY, Name nvarchar(50) NOT NULL); CREATE TABLE Employee (...);");
var deptId = db.QuerySingle<int>("INSERT INTO Dept(Name) VALUES (@Name); SELECT CAST(SCOPE_IDENTITY() AS int);", new { Name = "SMT车间" });
var rows = db.Execute("INSERT INTO Employee(Name, DeptId, Salary, hire_date) VALUES (@Name, @DeptId, @Salary, @HireDate)", new[] { ... 5 个匿名对象 ... });
=== 1 建表与插入(Execute) ===
部门 Id: 1, 2
传入集合 -> 每个元素执行一次, 总影响行数 = 5
  • 取自增 Id：Dapper 没有 ExecuteReturnIdentity，自己在 SQL 后面加 SELECT CAST(SCOPE_IDENTITY() AS int)，用 QuerySingle<int> 接。（CAST 是因为 SCOPE_IDENTITY() 返回 decimal，不转成 int 会映射报错。）
  • 传入一个集合给 Execute：Dapper 对集合里每个元素各执行一次这条 SQL，返回的是总影响行数 5。注意这是"循环执行 5 次"，不是真正的批量插入；万行级别的大批量请用 SqlBulkCopy。
  • 含中文的列在建表时就写 nvarchar——Dapper 不会替你建表，类型完全由你的 CREATE TABLE 决定。

例 2：查询 ​

csharp
var rich = db.Query<Employee>("SELECT Id, Name, DeptId, Salary FROM Employee WHERE Salary >= @min ORDER BY Salary DESC", new { min = 7000 }).ToList();
db.QueryFirstOrDefault<Employee>("SELECT * FROM Employee WHERE Name = @n", new { n = "李四" });
db.ExecuteScalar<int>("SELECT COUNT(*) FROM Employee");
db.Query<string>("SELECT Name FROM Employee WHERE Id IN @ids ORDER BY Id", new { ids = new[] { 1, 3, 5 } });
=== 2 查询(Query<T>) ===
工资>=7000: 孙七:9000.00, 赵六:8000.00, 王五:7000.00
QueryFirstOrDefault: 李四
没有结果时: null
ExecuteScalar: 5
IN 列表(Dapper 自动展开): 张三, 王五, 孙七
  • 没找到行时 QueryFirstOrDefault 返回 null，输出里"没有结果时: null"。
  • IN @ids：传入数组，Dapper 自动展开成 IN (@ids1, @ids2, @ids3)。这是 Dapper 很讨喜的功能；手写 IN 列表最容易出注入和拼接错误。

例 3：列名和属性名不一致 ​

表里的列叫 hire_date，类里的属性叫 HireDate：

=== 3 列名与属性名不一致 ===
默认: HireDate = null (没映射上)
开启 MatchNamesWithUnderscores 后: HireDate = 2024-03-01
或者在 SQL 里起别名 AS HireDate: 2024-03-01

默认映射不上，HireDate 是 null（不报错，只是悄悄丢了值）。两种解决：在 SQL 里写 hire_date AS HireDate；或在程序启动时设置 DefaultTypeMap.MatchNamesWithUnderscores = true。

实验里还有个细节：Dapper 对每个类型的映射结果会缓存，所以开关必须在这个类型第一次查询之前设置。我的实验为此换了一个新类 Employee2 来演示"开启后"的效果；真实项目把这行放在 Main 的最开头。

例 4：连表映射（multi-mapping） ​

csharp
var joined = db.Query<Employee, Dept, Employee>(
    "SELECT e.Id, e.Name, e.DeptId, e.Salary, d.Id, d.Name FROM Employee e JOIN Dept d ON d.Id = e.DeptId ORDER BY e.Id",
    (e, d) => { e.Dept = d; return e; },
    splitOn: "Id").ToList();
=== 4 连表映射(multi-mapping) ===
  张三 | SMT车间 | 5000.00
  李四 | SMT车间 | 6000.00
  王五 | 质量部 | 7000.00
  赵六 | 质量部 | 8000.00
  孙七 | 质量部 | 9000.00

一行结果里有两张表的列。splitOn: "Id" 告诉 Dapper："从第二个叫 Id 的列开始，是第二个对象（Dept）的列"。然后你用 lambda 把两个对象拼起来（这里把 Dept 挂到 Employee.Dept 上）。这是 Dapper 初学者最容易错的地方：splitOn 必须写对，SELECT 里列的顺序也必须是"第一个对象的列在前、第二个对象的列在后"。

例 5：一次查多个结果集 ​

csharp
using var multi = db.QueryMultiple("SELECT COUNT(*) FROM Dept; SELECT TOP 2 Name FROM Employee ORDER BY Id;");
var cnt = multi.ReadSingle<int>();
var names = multi.Read<string>().ToList();
=== 5 一次查多个结果集(QueryMultiple) ===
部门数 = 2; 前两名员工 = 张三, 李四

按 SQL 里 SELECT 的顺序依次 Read，一次往返数据库取两个结果，适合"页面要同时显示列表和统计数字"。

例 6：事务 ​

csharp
db.Open();                                 // 手动打开，事务需要连接保持打开
using (var tx = db.BeginTransaction())
{
    db.Execute("INSERT INTO Employee(Name, DeptId, Salary) VALUES (N'事务A', 1, 1)", transaction: tx);
    tx.Rollback();                         // 回滚；换成 tx.Commit() 就是提交
}
=== 6 事务 ===
回滚后人数 = 5
提交后人数 = 6

两点：每个 Execute/Query 都要显式传 transaction: tx（忘了传的语句不在事务里，这是 Dapper 事务最常见的 bug）；SQL 字面量里的中文要写 N'事务A' 前缀才能保证按 Unicode 处理。

例 7：SQL 注入对比 ​

csharp
var evil = "x' OR '1'='1";
db.Query<string>("SELECT Name FROM Employee WHERE Name = '" + evil + "'");      // 字符串拼接：危险
db.Query<string>("SELECT Name FROM Employee WHERE Name = @n", new { n = evil }); // 参数化：安全
=== 7 SQL 注入对比 ===
字符串拼接: 查出 6 行(全表泄露!); 参数化: 查出 0 行

拼接的版本把恶意输入变成了 ... WHERE Name = 'x' OR '1'='1'，条件永远为真，查出了全部 6 行；参数化的版本把整个输入当成一个普通字符串去匹配，查出 0 行。任何来自用户/接口/文件的值都必须用参数传递。

例 8：varchar 与中文 ​

=== 8 varchar 与中文 ===
写入 varchar 列后读出: ??  (Dapper 不改变列类型, 建表时就要用 nvarchar)

已 DROP Lab_Dapper

我故意把表建成 varchar(20) 再写入"锡膏"，读出来是 ??。这说明：无论用 Dapper 还是 SqlSugar，列类型决定了能不能存中文，Dapper 只是个搬运工。

动手实验 ​

安全提醒：程序会在 LocalDB 里建库 Lab_Dapper、建表，最后 DROP。不要把连接字符串改成公司的库。

第 1 步：建项目、装包。

mkdir DapperLab

using var db = new SqlConnection(Conn);   // Dapper 会在需要时自动打开连接

H("1 建表与插入(Execute)");

var rows = db.Execute("INSERT INTO Employee(Name, DeptId, Salary, hire_date) VALUES (@Name, @DeptId, @Salary, @HireDate)", new[]
{
    new { Name = "张三", DeptId = deptId, Salary = 5000m, HireDate = (DateTime?)new DateTime(2024, 3, 1) },
    new { Name = "李四", DeptId = deptId, Salary = 6000m, HireDate = (DateTime?)null },
    new { Name = "王五", DeptId = d2,     Salary = 7000m, HireDate = (DateTime?)null },
    new { Name = "赵六", DeptId = d2,     Salary = 8000m, HireDate = (DateTime?)null },
    new { Name = "孙七", DeptId = d2,     Salary = 9000m, HireDate = (DateTime?)null },
});
Console.WriteLine("传入集合 -> 每个元素执行一次, 总影响行数 = " + rows);

H("2 查询(Query<T>)");
var rich = db.Query<Employee>("SELECT Id, Name, DeptId, Salary FROM Employee WHERE Salary >= @min ORDER BY Salary DESC", new { min = 7000 }).ToList();
Console.WriteLine("工资>=7000: " + string.Join(", ", rich.Select(e => $"{e.Name}:{e.Salary}")));
Console.WriteLine("QueryFirstOrDefault: " + db.QueryFirstOrDefault<Employee>("SELECT * FROM Employee WHERE Name = @n", new { n = "李四" })?.Name);
Console.WriteLine("没有结果时: " + (db.QueryFirstOrDefault<Employee>("SELECT * FROM Employee WHERE Name = @n", new { n = "不存在" }) is null ? "null" : "有值"));
Console.WriteLine("ExecuteScalar: " + db.ExecuteScalar<int>("SELECT COUNT(*) FROM Employee"));
var ids = new[] { 1, 3, 5 };
Console.WriteLine("IN 列表(Dapper 自动展开): " + string.Join(", ", db.Query<string>("SELECT Name FROM Employee WHERE Id IN @ids ORDER BY Id", new { ids })));

H("3 列名与属性名不一致");
var e1 = db.QueryFirst<Employee>("SELECT * FROM Employee WHERE Id = 1");
Console.WriteLine("默认: HireDate = " + (e1.HireDate?.ToString("yyyy-MM-dd") ?? "null (没映射上)"));
DefaultTypeMap.MatchNamesWithUnderscores = true;   // hire_date -> HireDate
var e2 = db.QueryFirst<Employee2>("SELECT * FROM Employee WHERE Id = 1");  // 换一个新类型: Dapper 按类型缓存映射
Console.WriteLine("开启 MatchNamesWithUnderscores 后: HireDate = " + (e2.HireDate?.ToString("yyyy-MM-dd") ?? "null"));
var e3 = db.QueryFirst<Employee>("SELECT Id, Name, hire_date AS HireDate FROM Employee WHERE Id = 1");
Console.WriteLine("或者在 SQL 里起别名 AS HireDate: " + e3.HireDate?.ToString("yyyy-MM-dd"));

H("4 连表映射(multi-mapping)");
var joined = db.Query<Employee, Dept, Employee>(
    "SELECT e.Id, e.Name, e.DeptId, e.Salary, d.Id, d.Name FROM Employee e JOIN Dept d ON d.Id = e.DeptId ORDER BY e.Id",
    (e, d) => { e.Dept = d; return e; },
    splitOn: "Id").ToList();
foreach (var e in joined) Console.WriteLine($"  {e.Name} | {e.Dept.Name} | {e.Salary}");

H("5 一次查多个结果集(QueryMultiple)");
using (var multi = db.QueryMultiple("SELECT COUNT(*) FROM Dept; SELECT TOP 2 Name FROM Employee ORDER BY Id;"))
{
    var cnt = multi.ReadSingle<int>();
    var names = multi.Read<string>().ToList();
    Console.WriteLine($"部门数 = {cnt}; 前两名员工 = {string.Join(", ", names)}");
}

H("6 事务");
db.Open();
using (var tx = db.BeginTransaction())
{
    db.Execute("INSERT INTO Employee(Name, DeptId, Salary) VALUES (N'事务A', 1, 1)", transaction: tx);
    tx.Rollback();
}
Console.WriteLine("回滚后人数 = " + db.ExecuteScalar<int>("SELECT COUNT(*) FROM Employee"));
using (var tx = db.BeginTransaction())
{
    db.Execute("INSERT INTO Employee(Name, DeptId, Salary) VALUES (N'事务B', 1, 1)", transaction: tx);
    tx.Commit();
}
Console.WriteLine("提交后人数 = " + db.ExecuteScalar<int>("SELECT COUNT(*) FROM Employee"));

H("7 SQL 注入对比");
var evil = "x' OR '1'='1";
var bad = db.Query<string>("SELECT Name FROM Employee WHERE Name = '" + evil + "'").Count();
var good = db.Query<string>("SELECT Name FROM Employee WHERE Name = @n", new { n = evil }).Count();
Console.WriteLine($"字符串拼接: 查出 {bad} 行(全表泄露!); 参数化: 查出 {good} 行");

H("8 varchar 与中文");
db.Execute("CREATE TABLE T_Var (Name varchar(20))");
db.Execute("INSERT INTO T_Var VALUES (@n)", new { n = "锡膏" });
Console.WriteLine("写入 varchar 列后读出: " + db.QuerySingle<string>("SELECT Name FROM T_Var") + "  (Dapper 不改变列类型, 建表时就要用 nvarchar)");

常见坑与排查 ​

现象原因处理
某属性始终是 null / 0，也不报错列名和属性名对不上AS 别名，或 MatchNamesWithUnderscores（要在该类型第一次查询前设置）
连表后第二个对象是 null 或错位splitOn 写错，或 SELECT 列顺序不对明确列顺序；splitOn 写第二个对象第一列的名字；多个对象用逗号分隔
事务没生效有语句没传 transaction: tx所有语句都传；或封装一个方法统一传
Query<int> 取自增 Id 报转换错误SCOPE_IDENTITY() 是 decimalCAST(SCOPE_IDENTITY() AS int)
IN 查询空数组实测 Dapper 2.1.89 返回 0 行不报错，但旧版本/其他驱动行为不一定相同调用前先判空，空集合直接返回空结果
中文变 ?表是 varchar建表时用 nvarchar
想要自动建表、迁移Dapper 不做这些用脚本、EF-Core 迁移或 SqlSugar CodeFirst
日期/枚举/可空类型映射异常类型不兼容属性类型与列类型对应（如可空列用 DateTime?）

业务视角与技术视角 ​

  • 业务视角：MES/WMS 的看板、报表常常是"跨好几张表聚合"的复杂 SQL（见 OEE、生产看板与实时报表），业务人员给的是"口径"，开发者最直接的做法就是把口径翻译成 SQL；这类场景用 Dapper 可以保证 SQL 与口径一一对应、便于 DBA 优化。
  • 技术视角：同一个项目里常见组合——增删改的常规业务用 ORM（SqlSugar），报表/统计/热点查询用 Dapper 或 SqlSugar 的原生 SQL。Dapper 和 EF/SqlSugar 同库时要注意事务边界：各自的连接对象不同，需要共享事务时必须传同一个 DbTransaction，否则它们不在同一个事务里。性能上 Dapper 的映射开销很小，官方仓库有对比基准，但具体数字和机器、数据量相关，本篇没有压测，请以你们的实测为准。

练习题与答案 ​

练习 1：QueryFirst 和 QuerySingle 的区别？

答案：QueryFirst 取第一行，没有行抛异常，多行也只取第一行；QuerySingle 要求恰好一行，没有或多于一行都抛异常。需要"唯一性断言"时用 QuerySingle。另有 …OrDefault 版本，没有行时返回默认值而不抛异常。

练习 2：下面的代码有什么问题？

csharp
var sql = "SELECT * FROM Employee WHERE Name = '" + name + "'";
var list = db.Query<Employee>(sql);

答案：字符串拼接，存在 SQL 注入。改为 db.Query<Employee>("SELECT * FROM Employee WHERE Name = @name", new { name })。

练习 3：db.Execute("INSERT INTO ... VALUES (@A)", listOf1000) 是一次批量插入吗？

答案：不是。Dapper 会对集合里每个元素执行一次，一千条就往返一千次（虽然可能在同一个连接上）。真正的大批量请用 SqlBulkCopy，或 SqlSugar 的 Fastest().BulkCopy。

练习 4：为什么 Dapper 的事务要显式给每条语句传 transaction？

答案：Dapper 只是 IDbConnection 的扩展方法，不持有"当前事务"状态；而 ADO.NET 要求命令必须明确关联事务。所以传不传完全取决于你。

练习 5（动手）：把实验里"例 4"的 splitOn: "Id" 改成一个不存在的列名，如 splitOn: "Nope"，运行会怎样？

答案（实测）：抛 ArgumentException: Multi-map error: splitOn column 'Nope' was not found - please ensure your splitOn parameter is set and in the correct order。

小结 ​

  • Dapper = SQL 你写 + 结果自动映射 + 参数化防注入，没有建表/迁移/变更跟踪。
  • 参数永远用 @名字 + 匿名对象；IN @ids 自动展开。
  • 列名对不上属性不会报错，会静默丢值；连表映射的 splitOn 和列顺序要写对。
  • 事务要手动传 transaction；批量大数据用 SqlBulkCopy。
  • 类型（varchar/nvarchar）由表结构决定，Dapper 不负责。
