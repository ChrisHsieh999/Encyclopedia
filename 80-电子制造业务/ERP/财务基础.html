财务基础

AI 生成 · 待核对制造业务ERP财务更新于 2026-10-21

⚠ 待核对：借贷记账规则、会计等式、试算平衡的定义已对照维基百科；增值税一般税率 13% 见上面 sources 的新闻稿（税率以税务机关现行规定为准）。**本篇使用的科目编码是教学用的简化编码，没有逐一对照《企业会计准则应用指南》附录的科目表；你们公司的科目体系、凭证规则、月结步骤请对照财务部门和你们 ERP 核实。**文中的 T-SQL 在本机 SQL Server LocalDB 上实际运行过，所有金额都用 Python 另算一遍核对过。

本篇是 ERP 系列第 6 篇，写给做信息化的人，不是会计教程。目标：看懂财务和生产系统之间传递的数据（凭证、科目、期间、成本），能设计凭证头行表，能写借贷平衡校验和试算平衡 SQL。

一句话定义 ​

财务模块用复式记账把企业每一笔经济业务记录成"有借必有贷、借贷必相等"的凭证，再汇总成总账、应收、应付和成本，月底结账后出报表。

先修知识 ​

  • ERP：知道 ERP 各模块的分工。
  • 库存与成本：知道库存数量、库存金额、单位成本。
  • SQL基础查询、SQL聚合与分组：会写 GROUP BY、SUM。
  • 事务与ACID：凭证头行要同时成功写入。

它解决什么问题 ​

工厂每天发生大量业务：收了一批电阻、车间领了料、做完一批板子入库、发货给客户、收到货款、付了供应商的钱。如果只在各系统里各记各的数量：

  • 老板问"这个月赚了多少钱"，没人答得出来：料、人工、制造费用最后有多少算进了成品成本？
  • 仓库说有 40000 元的原材料，财务账上写 39500，谁对？
  • 有人改了一笔上个月的数据，今年的报表就对不上了。

复式记账用一条硬规则（借贷必相等）+ 一套科目 + 一套期间锁定机制，让这些问题可检查、可追溯。ERP 的财务模块就是把这套规则固化成系统；生产系统（MES、WMS）不直接做账，而是把业务事件交给 ERP，由 ERP 生成凭证。

核心概念（由浅入深） ​

会计等式与科目 ​

最基础的等式：资产 = 负债 + 所有者权益（据维基百科，每笔记录的交易都使这个等式保持平衡）。

  • 资产：企业拥有的东西（银行存款、应收账款、原材料、库存商品）；
  • 负债：欠别人的（应付账款、应付职工薪酬、应交税费）；
  • 所有者权益：股东投入和积累（实收资本）。

企业日常还会用到：

  • 成本类：生产成本（正在做的产品上归集的料、工、费）；
  • 收入类：主营业务收入；
  • 费用类：主营业务成本、管理费用等。

会计科目就是给每一类东西起的名字和编码。凭证里每一行都要指向一个科目。本篇用的教学科目：

编码科目类别余额正常方向
1002银行存款资产借
1122应收账款资产借
1403原材料资产借
1405库存商品资产借
2202应付账款负债贷
2211应付职工薪酬负债贷
2221应交税费负债贷
4001实收资本权益贷
5001生产成本成本借
6001主营业务收入收入贷
6401主营业务成本费用借

借和贷：不是"收入支出" ​

"借（Debit）"和"贷（Credit）"只是记账的左边和右边，不是借钱贷款的意思。规则（据维基百科）：

科目类别增加记减少记
资产、成本、费用借贷
负债、权益、收入贷借

好记法：钱/货"进来或被占用"在左边（借），"来源"在右边（贷）。比如收到 10 万元货款：银行存款（资产）增加记借；这笔钱是客户欠的应收账款（资产）减少记贷。

核心约束：每张凭证借方合计 = 贷方合计。

凭证、总账、明细账 ​

  • 凭证（Voucher / Journal Entry）：一笔业务的记账记录，有一个头（日期、期间、来源、摘要）和多行分录（科目、借方金额、贷方金额）；
  • 总账（General Ledger，GL）：按科目汇总所有凭证，得到每个科目的借方发生额、贷方发生额、余额；
  • 明细账 / 辅助账：同一个科目下更细的账。应收账款按客户记，叫应收账款明细（AR）；应付账款按供应商记，叫应付账款明细（AP）；原材料按物料记，就是库存明细账。总账的数字应该等于明细账合计，两者对不上就要对账。

会计期间与月结 ​

账按期间（通常一个月）管理。月底做月结（结账）：

  1. 所有业务单据入账（采购收货、领料、完工、发货、收付款都已出凭证）；
  2. 库存关账：盘点，未收到发票的收货做暂估（先按订单价入账，来票后冲回重做）；
  3. 成本计算：把本月归集的料、工、费分配给完工产品和未完工的在制品；
  4. 结转损益：收入、成本、费用结转到"本年利润"；
  5. 对账：总账与库存明细、应收应付明细核对；
  6. 关闭本期间，不再允许往里记账；有错只能在下期做调整凭证。

成本会计（最小认识） ​

制造业的产品成本 = 直接材料 + 直接人工 + 制造费用（设备折旧、水电、车间管理人员等）。生产过程中这三项先归集到"生产成本"科目；产品完工入库时，把完工部分的成本从"生产成本"转到"库存商品"；还没做完的部分留在"生产成本"里，就是在制品（WIP, Work In Process）。

两种常见的成本核算方式（详细见 库存与成本）：实际成本（按实际发生的算）和标准成本（按预先定的标准价，月底把实际与标准的差异单独记账）。电子厂常见的是按工单归集成本，MES 的报工、物料消耗、工时就是成本的数据来源。

ERP 如何从业务单据自动生成凭证 ​

人不手工敲凭证，而是系统按规则自动生成。规则表大概长这样（业务单据类型 → 借贷科目 → 金额取自哪里）：

业务单据借贷金额依据
采购收货原材料、应交税费（进项税）应付账款不含税额、税额、价税合计
生产领料生产成本原材料领料成本
人工归集生产成本应付职工薪酬工时 × 费率
完工入库库存商品生产成本完工成本
销售发货应收账款主营业务收入、应交税费（销项税）不含税额、税额、价税合计
结转销售成本主营业务成本库存商品数量 × 单位成本
收款银行存款应收账款收款金额
付款应付账款银行存款付款金额

这就是后面实验里 GlRule 表做的事。几条工程原则：

  • 一张单据只生成一次凭证：用 (来源类型, 来源单号) 做唯一约束，重复生成会被数据库拦住；
  • 凭证要能追到源头单据：凭证头存 Source、SourceNo，对账和审计时从凭证一路点到原始单据；
  • 过账（Post）后不可改：改错用冲销凭证（把原凭证借贷互换再记一笔）加重做，不要直接改或删；
  • 关闭的期间不能再记账。

逐步例子：一个月的业务如何变成账 ​

起点：股东投入 500000 元。金额单位：元；增值税率按 13%（基于模型知识，请以现行规定为准）。

步业务借贷
1投入资本银行存款 500000实收资本 500000
2采购收货 100000 元，税 13%（13000）原材料 100000、应交税费 13000应付账款 113000
3生产领料 60000生产成本 60000原材料 60000
4人工 20000生产成本 20000应付职工薪酬 20000
5完工入库，成本 75000库存商品 75000生产成本 75000
6销售发货，不含税 90000，销项税 11700应收账款 101700主营业务收入 90000、应交税费 11700
7结转销售成本 50000主营业务成本 50000库存商品 50000
8客户回款 101700银行存款 101700应收账款 101700
9付供应商 113000应付账款 113000银行存款 113000

手算各科目余额（借方发生额 - 贷方发生额）：

  • 银行存款：500000 + 101700 - 113000 = 488700（借方）
  • 应收账款：101700 - 101700 = 0；应付账款：113000 - 113000 = 0
  • 原材料：100000 - 60000 = 40000；库存商品：75000 - 50000 = 25000
  • 生产成本：60000 + 20000 - 75000 = 5000，就是月底的在制品
  • 应交税费：借 13000（进项）- 贷 11700（销项）= 借方 1300，意思是多交了/可抵扣 1300（留抵）
  • 利润 = 收入 90000 - 成本 50000 = 40000

两个数字可以互相印证：完工 75000 元，如果完工 1500 块，单位成本 50 元/块；卖了 1000 块，成本 1000 × 50 = 50000，正好是步骤 7。借方总额 = 贷方总额 = 1134400（下面实验会跑出来，另用 Python 独立复算过）。

凭证表设计要点 ​

GlAccount     (AcctCode 主键, AcctName, AcctType, NormalSide)      科目
GlPeriod      (Period 主键, Status Open/Closed)                      会计期间
GlVoucher     (VoucherId, VoucherNo 唯一, VoucherDate, Period, Source, SourceNo, Status Draft/Posted, Memo)
GlVoucherLine (LineId, VoucherId, LineNum, AcctCode, Debit, Credit, Memo)

要点（都在实验的 SQL 里实现了）：

  1. 头行分表：一张凭证多行分录；
  2. 金额用 decimal(18,2)，不要 float；借方和贷方各一列，用 CHECK 约束"一行只能一边有金额、不能为负"；
  3. (Source, SourceNo) 唯一：同一业务单据只能生成一次；
  4. 状态机：Draft → Posted。过账前由存储过程检查：至少两行、借贷平衡、期间为 Open；
  5. 过账后锁定：触发器拒绝对 Posted 凭证的修改和删除；
  6. 冲销代替修改；
  7. 真实系统还有：凭证字号、制单人/审核人/过账人、币种与汇率、辅助核算维度（客户、供应商、物料、部门、项目）、附件张数，本篇省略。

LineNo 在 T-SQL 里是保留字，不能直接当列名，实验里改成了 LineNum。

给 IT 看的接口数据 ​

生产系统给财务的数据，最终都要落到"凭证需要什么"：

生产系统事件财务需要的数据
工单领料 / 退料工单号、物料、数量、实际批次成本（金额），日期（决定记哪个期间）
报工、完工入库工单号、完工数量、工时、入库日期
不良报废报废数量、原因、成本（计入哪个科目要财务定）
发货订单号、出货数量、客户
盘盈盘亏物料、差异数量、金额、审批人

IT 要注意：日期决定期间，晚到的单据会落到哪个期间要有明确规则；金额口径（含税/不含税、本币/外币）要与财务确认；同一事件只能传一次（接口重试要幂等，见 ERP与MES衔接）。

    LineNum    INT NOT NULL,
    AcctCode  VARCHAR(10) NOT NULL REFERENCES GlAccount(AcctCode),

                     PRIMARY KEY (DocType, Seq));

-- 已过账的凭证不允许改动（改错用冲销凭证）
CREATE TRIGGER TR_GlVoucher_Lock ON GlVoucher AFTER UPDATE, DELETE AS
BEGIN
    IF EXISTS (SELECT 1 FROM deleted WHERE Status = 'Posted')
        THROW 50010, N'已过账的凭证不能修改或删除，请做冲销凭证', 1;
END;
GO
CREATE TRIGGER TR_GlLine_Lock ON GlVoucherLine AFTER INSERT, UPDATE, DELETE AS
BEGIN
    IF EXISTS (SELECT 1 FROM GlVoucher v WHERE v.Status = 'Posted'
               AND v.VoucherId IN (SELECT VoucherId FROM inserted UNION SELECT VoucherId FROM deleted))
        THROW 50011, N'凭证已过账，不能增删改分录行', 1;
END;
GO
-- 过账：借贷平衡 + 至少两行 + 期间未关闭，才能把状态改为 Posted
CREATE PROCEDURE GlPost @VoucherNo VARCHAR(30) AS
BEGIN
    DECLARE @id INT, @st VARCHAR(8), @period CHAR(7), @n INT, @d DECIMAL(18,2), @c DECIMAL(18,2);
    SELECT @id = VoucherId, @st = Status, @period = Period FROM GlVoucher WHERE VoucherNo = @VoucherNo;
    IF @id IS NULL THROW 50001, N'凭证不存在', 1;
    IF @st <> 'Draft' THROW 50002, N'凭证不是草稿状态', 1;
    IF NOT EXISTS (SELECT 1 FROM GlPeriod WHERE Period = @period AND Status = 'Open') THROW 50003, N'会计期间已关闭', 1;
    SELECT @n = COUNT(*), @d = ISNULL(SUM(Debit), 0), @c = ISNULL(SUM(Credit), 0) FROM GlVoucherLine WHERE VoucherId = @id;
    IF @n < 2 THROW 50004, N'凭证至少要有两行分录', 1;
    IF @d <> @c THROW 50005, N'借贷不平衡，不能过账', 1;
    UPDATE GlVoucher SET Status = 'Posted' WHERE VoucherId = @id;
END;
GO

DECLARE @no VARCHAR(30);
DECLARE c CURSOR LOCAL FAST_FORWARD FOR SELECT VoucherNo FROM GlVoucher WHERE Status = 'Draft' ORDER BY VoucherId;
OPEN c; FETCH NEXT FROM c INTO @no;
WHILE @@FETCH_STATUS = 0
BEGIN
    BEGIN TRY
        EXEC GlPost @no;
        PRINT @no + N' -> 过账成功';
    END TRY
    BEGIN CATCH
        PRINT @no + N' -> 过账失败：' + ERROR_MESSAGE();
    END CATCH
    FETCH NEXT FROM c INTO @no;
END
CLOSE c; DEALLOCATE c;
GO
-- 检查 1：任何凭证（含草稿）借贷不平衡就列出来
SELECT v.VoucherNo, SUM(l.Debit) AS Debit, SUM(l.Credit) AS Credit, SUM(l.Debit) - SUM(l.Credit) AS Diff
FROM GlVoucher v JOIN GlVoucherLine l ON l.VoucherId = v.VoucherId
GROUP BY v.VoucherNo HAVING SUM(l.Debit) <> SUM(l.Credit);
-- 检查 2：试算平衡表（只算已过账凭证）
SELECT a.AcctCode, a.AcctName, SUM(l.Debit) AS DebitTotal, SUM(l.Credit) AS CreditTotal,
       CASE WHEN SUM(l.Debit) >= SUM(l.Credit) THEN SUM(l.Debit) - SUM(l.Credit) ELSE 0 END AS DebitBalance,
       CASE WHEN SUM(l.Credit) > SUM(l.Debit) THEN SUM(l.Credit) - SUM(l.Debit) ELSE 0 END AS CreditBalance
FROM GlAccount a JOIN GlVoucherLine l ON l.AcctCode = a.AcctCode JOIN GlVoucher v ON v.VoucherId = l.VoucherId AND v.Status = 'Posted'
GROUP BY a.AcctCode, a.AcctName ORDER BY a.AcctCode;
SELECT SUM(l.Debit) AS TotalDebit, SUM(l.Credit) AS TotalCredit
FROM GlVoucherLine l JOIN GlVoucher v ON v.VoucherId = l.VoucherId AND v.Status = 'Posted';
-- 利润 = 收入 - 成本费用
SELECT SUM(CASE WHEN a.AcctType = 'Revenue' THEN l.Credit - l.Debit ELSE 0 END) AS Revenue,
       SUM(CASE WHEN a.AcctType = 'Expense' THEN l.Debit - l.Credit ELSE 0 END) AS Expense
FROM GlVoucherLine l JOIN GlAccount a ON a.AcctCode = l.AcctCode JOIN GlVoucher v ON v.VoucherId = l.VoucherId AND v.Status = 'Posted';
GO

常见坑与排查 ​

现象原因与办法
总账与库存明细对不上常见：入库/领料时间跨期；暂估没冲回；单位成本口径不同；接口丢单。按物料、按日期逐个对，见 库存账与账实一致
同一单据出了两张凭证没有 (来源, 来源单号) 唯一约束，接口重试造成。数据库层加唯一约束
金额差几分钱用 float 或每行四舍五入，合计不等于单据金额。统一 decimal，明确舍入位置，余数挂到最后一行
借贷不平衡的凭证混进来过账前没有校验。过账过程里强制校验，并且每天跑检查查询
直接改了已过账的数据用触发器/权限锁住，改错走冲销
晚到的单据落进已关闭期间规则：按"当前开放的最早期间"记，或财务审批重开期间。别偷偷改日期
外币、含税/不含税混用接口字段必须写清币种和口径
负库存导致成本算不出来先发货后入库造成。库存账要禁止或预警负库存
税率写死在代码里税率会变，应做成配置，且按单据日期取有效税率

业务视角与技术视角 ​

业务视角：财务（总账会计、成本会计、应收应付会计、出纳）用凭证记账，月底结账出报表；采购、仓库、车间、销售在自己的系统里处理单据，由 ERP 转成凭证。KPI：月结天数（几号能结完）、账实相符率、对账差异笔数、应收账款周转天数。

技术视角：核心是凭证头行表、科目、期间；业务单据到凭证由规则表驱动；过账与锁定靠存储过程、约束、触发器；对账靠 SQL 汇总比对；接口要幂等。如果你们的 MES/WMS 是自研的，通常只传业务事实（谁、什么物料、多少、哪天），金额和科目由 ERP 财务模块决定；是否这样，请对照你们的实际架构。

练习题与答案 ​

  1. 收到客户货款 101700 元，该怎么记？ 答：借 银行存款 101700，贷 应收账款 101700。
  2. 车间领用 60000 元电阻，该怎么记？ 答：借 生产成本 60000，贷 原材料 60000。
  3. 采购 100000 元，增值税 13%，款未付，该怎么记？ 答：税额 100000 × 13% = 13000；借 原材料 100000、应交税费 13000，贷 应付账款 113000；借贷各 113000。
  4. 月底"生产成本"科目余额借方 5000，是什么意思？ 答：还没完工的在制品成本 5000：本月归集了 80000（料 60000 + 工 20000），完工转出 75000，余下 5000。
  5. 总账原材料 40000，库存明细合计 39500，应该怎么办？ 答：差 500，按物料、按单据对：看有没有未传的入库/领料、跨期、暂估未冲、单位成本口径不同，找出差异再调整，不能随便改总账数字。
  6. 为什么已过账的凭证不能直接改？ 答：改动会让以前出过的报表和审计轨迹失效。要改，做冲销凭证（借贷互换）再做正确的凭证，原凭证留痕。
  7. 借 1000、贷 900 的凭证，能不能过账？写一条 SQL 找出所有这样的凭证。 答：不能。SELECT v.VoucherNo FROM GlVoucher v JOIN GlVoucherLine l ON l.VoucherId = v.VoucherId GROUP BY v.VoucherNo HAVING SUM(l.Debit) <> SUM(l.Credit);（实验里已跑过）。
  8. 试算平衡表总借方等于总贷方，能保证账一定正确吗？ 答：不能。它只能说明借贷金额的合计相等（据维基百科是"部分检查"）：记错科目、整笔漏记、借贷同时记错同一金额，试算仍然平衡。

小结 ​

  • 复式记账：每笔业务借贷相等；资产/成本/费用借增，负债/权益/收入贷增。
  • ERP 按规则表把业务单据自动转成凭证；凭证头行分表，金额用 decimal。
  • 过账前校验平衡与期间；过账后锁定，改错用冲销；同一单据只出一次凭证。
  • 总账和明细账要对账；月结有固定步骤；产品成本 = 料 + 工 + 费，未完工的是在制品。
  • IT 关心的是接口数据：日期、金额口径、幂等。
