生产计划MRP

AI 生成 · 待核对制造业务ERP更新于 2026-10-21

⚠ 待核对：MRP 的定义和目标、EOQ 公式已对照维基百科；毛需求/净需求/低层码/批量策略的逻辑是教科书通用做法（基于模型知识），不同 ERP 产品在时间桶、安全库存算法、净改变/重新生成等细节上有差异，你们公司 ERP 的 MRP 参数请对照核实。文中的 Python 与 T-SQL 都在本机实际运行过，两种实现的结果逐行核对一致。

本篇是 ERP 系列第 5 篇。读完你应该能：说清 MRP 要哪些输入、产出什么；手算"毛需求 → 净需求 → 计划订单 → 提前期倒推 → 子件毛需求"一整套；理解为什么必须有低层码；会选批量策略；能用一份 Python 和一份 T-SQL 写出最小 MRP，并用手算结果核对它。

一句话定义 ​

MRP（Material Requirements Planning，物料需求计划）是根据要生产什么、什么时候要（主生产计划）、每个产品由什么构成（BOM）、手里已经有什么（库存和在途），倒推出每种物料什么时候、买/做多少的计算方法。据维基百科，它是用于管理制造过程的生产计划、排程和库存控制系统，目标是保证生产有料、交付有货，同时让库存尽量低。

先修知识 ​

  • BOM与物料清单：知道单耗、损耗率、多层 BOM、递归展开。
  • 库存与成本：知道现有库存、在途、安全库存这些词。
  • ERP：知道 ERP 里计划、采购、库存、财务几个模块各管什么。
  • 工单管理：MRP 产出的"生产计划订单"最终会变成工单。

它解决什么问题 ​

先看一个没有 MRP 的现场。销售说下个月交 330 块 A100 控制板。计划员打开 BOM，在 Excel 里乘一乘：要多少电阻、多少芯片……做到一半有人发现：

  • 芯片采购周期 4 周，今天下单已经赶不上第 3 周的交期；
  • 电阻 BOM 里有两处用到（板上 12 个，整机上还有 2 个外挂），Excel 里只算了一处，缺料；
  • 仓库其实有 2000 个电阻，计划员没扣库存，多买了一整卷；
  • 半成品板已经下过一单在途，也没扣。

MRP 做的事情就是把这些人脑容易漏的事自动、完整、按时间算清楚：

  1. 把成品需求沿 BOM 逐层"炸开"到每一种物料；
  2. 每层都扣掉库存和在途，只算真正缺的；
  3. 按提前期往前推，告诉你最晚什么时候必须下单；
  4. 按批量规则（一卷 5000、最小起订量）取整。

注意 MRP 是无限产能的：它只管"料"，不管产线、设备每周能不能做完。产能约束由 APS 等排程系统处理。

核心概念 ​

输入 ​

输入内容谁提供
主生产计划 MPS（Master Production Schedule）成品什么时候要多少（来自销售订单和预测）计划员，见 销售订单
BOM每个产品由哪些物料组成，单耗、损耗率工程/PLM，见 BOM与物料清单
库存现有可用库存（扣掉冻结、不良）仓库，见 库存与成本
在途 / 已下达未到货已下的采购单、已下达的工单：什么时候到多少采购、生产
提前期 LT（Lead Time）从下单到入库要多久，采购件看供应商，自制件看生产周期物料主数据
批量规则LFL / 固定批量 / 最小起订量 / EOQ物料主数据
安全库存为应对波动特意留的最低库存物料主数据
损耗率BOM 里的合理损耗，备料时要加上BOM

输出 ​

  • 计划订单（Planned Order）：MRP 算出来的"建议"，包含物料、数量、下达日期、到货日期。采购件的计划订单转成请购建议（再变成采购单，见 采购管理），自制件的计划订单转成生产计划订单（再变成工单）。
  • 异常消息：该提前的、该推迟的、该取消的订单；已经逾期、来不及的订单。

时间桶（Time Bucket） ​

MRP 把时间切成一格一格（按天或按周），本篇用周：W1、W2……W8。每个物料在每个时间桶里有一条记录，列如下：

列含义
毛需求 Gross这个时间桶里总共需要多少（来自上层计划订单或 MPS）
在途 Sched已经确定会在这个时间桶到货的数量
期末库存 POH（Projected On Hand）这周结束时预计还剩多少
净需求 Net扣掉库存和在途后还缺多少
计划到货为补足净需求，按批量规则取整后的计划订单数量

毛需求 → 净需求 → 计划订单 ​

核心三步，每个物料、每个时间桶都做：

可用 = 上周期末库存 + 本周在途 - 本周毛需求
净需求 = 如果 可用 < 安全库存，则 安全库存 - 可用，否则 0
计划到货 = 按批量规则把净需求取整（净需求为 0 则 0）
本周期末库存 = 可用 + 计划到货
下达周 = 到货周 - 提前期

最后一行叫提前期倒推（lead time offset）：想在 W3 有货，提前期 1 周，就要在 W2 下达。

多层 BOM 与低层码 ​

成品下达的计划订单，会按 BOM 变成下一层物料的毛需求（数量 × 单耗 × (1+损耗率)，向上取整），时间是下达周（不是到货周，因为开工要用料）。下一层物料算出自己的计划订单，再变成更下一层的毛需求……这样逐层展开。

问题来了：同一个物料可能出现在不同的层。比如本篇的电阻 R-10K-0402：

  • 在 A100 整机下直接用 2 个（第 1 层）；
  • 在半成品 PCBA-A100 下用 12 个（第 2 层）。

如果在算完第 1 层时就去算电阻，半成品的计划订单还没出来，电阻的需求就不完整。解决办法：低层码（Low-Level Code）——一个物料在所有 BOM 路径里出现的最深层数（成品为 0）。MRP 严格按低层码从小到大计算：只有当一个物料的所有"上层"都算完了，才轮到它。

本篇例子的低层码：

低层码物料
0A100（成品）
1PCBA-A100、ENCLOSURE、SCREW-M3
2PCB-A100、R-10K-0402、C-100N-0402、IC-MCU-32

R-10K-0402 同时在第 1 层和第 2 层出现，所以低层码是 2。

批量策略（Lot Sizing） ​

净需求算出来是 140，该下多少？

策略做法适用
LFL（Lot for Lot，逐批）缺多少下多少贵重件、定制件、周期短
固定批量缺的量向上取整到批量的整数倍。例：批量 100，缺 140 就下 200一卷 5000 的电阻、供应商有最小包装
最小起订量 MOQ缺的量不足 MOQ 时按 MOQ 下供应商限制
EOQ（经济订货量）按"下单成本"与"持有成本"的平衡点算批量需求稳定的通用件

EOQ 公式（据维基百科）：Q* = √(2DK / h)。D 是年需求量，K 是每次下单的固定成本（不含货款），h 是每单位每年的持有成本。举例：电阻年用量 D = 120000 个，每次下单成本 K = 150 元，每个每年持有成本 h = 0.01 元：

Q* = √(2 × 120000 × 150 / 0.01) = √3.6×10⁹ = 60000。

总成本 = 下单次数 × K + 平均库存 × h = D/Q × K + Q/2 × h，代入验证（Python 复算）：

批量 Q下单成本持有成本合计（元/年）
50003600253625
200009001001000
60000300300600
120000150600750

最低点正好在 60000，下单成本等于持有成本。EOQ 假设需求平稳；而 MRP 面对的是随时间变化的"块状"需求，所以 MRP 更常用 LFL 或固定批量，EOQ 一般用于通用低值件的参数设定。电子料还要考虑 MSD湿敏元件管理（买太多放过期）和料盘规格（一盘 5000）。

安全库存 ​

安全库存是"用来对付波动"的缓冲，不是正常消耗的库存。MRP 里的处理方式见上面的公式：可用低于安全库存就算缺。安全库存怎么定，常见做法是按需求波动和提前期算：安全库存 = Z × σ × √LT（Z 是服务水平对应的系数，σ 是每周需求的标准差，LT 是提前期周数）。例：想要约 95% 的服务水平（Z 约 1.65），每周需求波动 σ = 100，提前期 4 周：1.65 × 100 × √4 = 330。这是经验公式（基于模型知识），实际取值请和采购、计划一起定。

两个小细节：① 每张计划订单分别向上取整，所以 80+150+80=310 块整机的总需求是 164+306+164 = 634，而不是 310×2.04 = 632.4 → 633。这和"系统在哪一步取整"有关，是对账时常见的小差异。② 低层码的作用：假如电阻错误地在第 1 层就算（此时只有 A100 的 164/306/164），库存 2000 一路扣到 1366，都大于 500 安全库存，一张采购建议都不会出，等到半成品开工才发现缺 1112，这就是漏掉低层码的后果。

动手实验：最小 MRP（Python + T-SQL） ​

下面的 Python 和 T-SQL 各实现一遍同样的算法，数据就是上面的例子。两份实现算出的每一行（64 条时间桶记录、14 条计划订单）我都逐行比对过，完全一致。

实验 A：Python 版 ​

新建 mrp.py（只用标准库）：

python
"""最小 MRP：周为时间桶，逐层展开，按低层码从上往下算。只用标准库。"""
import math
from decimal import Decimal

WEEKS = 8  # W1..W8

# 物料主数据：提前期(周)、现有库存、安全库存、批量策略(LFL 或 ('FIX', 批量))
ITEMS = {
    "A100":          dict(lt=1, onhand=20,   safety=0,   lot="LFL"),
    "PCBA-A100":     dict(lt=1, onhand=40,   safety=10,  lot=("FIX", 100)),
    "PCB-A100":      dict(lt=3, onhand=50,   safety=0,   lot=("FIX", 200)),
    "ENCLOSURE":     dict(lt=2, onhand=200,  safety=0,   lot="LFL"),
    "SCREW-M3":      dict(lt=1, onhand=1000, safety=200, lot=("FIX", 1000)),
    "R-10K-0402":    dict(lt=2, onhand=2000, safety=500, lot=("FIX", 5000)),
    "C-100N-0402":   dict(lt=2, onhand=1000, safety=0,   lot=("FIX", 4000)),
    "IC-MCU-32":     dict(lt=4, onhand=30,   safety=0,   lot="LFL"),
}
# BOM：父, 子, 单耗, 损耗率
BOM = [
    ("A100", "PCBA-A100", 1, 0), ("A100", "ENCLOSURE", 1, 0),
    ("A100", "SCREW-M3", 4, 0), ("A100", "R-10K-0402", 2, 0.02),
    ("PCBA-A100", "PCB-A100", 1, 0), ("PCBA-A100", "R-10K-0402", 12, 0.02),
    ("PCBA-A100", "C-100N-0402", 8, 0.02), ("PCBA-A100", "IC-MCU-32", 1, 0),
]
MPS = {"A100": {3: 100, 5: 150, 7: 80}}          # 独立需求（主生产计划）
SCHED = {"PCBA-A100": {2: 60}}                   # 在途/已下达未到货


def low_level_codes():
    """低层码：物料在所有 BOM 路径中出现的最深层数（成品=0）。"""
    llc = {i: 0 for i in ITEMS}
    changed = True
    while changed:
        changed = False
        for p, c, _, _ in BOM:
            if llc[c] < llc[p] + 1:
                llc[c] = llc[p] + 1
                changed = True
    return llc


def lot_size(net, lot):
    if lot == "LFL":
        return net
    q = lot[1]
    return math.ceil(net / q) * q


def run():
    llc = low_level_codes()
    gross = {i: {w: 0 for w in range(1, WEEKS + 1)} for i in ITEMS}
    for i, d in MPS.items():
        for w, q in d.items():
            gross[i][w] += q
    result, orders = {}, []   # orders: (item, release_week, receipt_week, qty)
    for item in sorted(ITEMS, key=lambda i: (llc[i], i)):
        m = ITEMS[item]
        poh = m["onhand"]
        rows = []
        for w in range(1, WEEKS + 1):
            g = gross[item][w]
            sr = SCHED.get(item, {}).get(w, 0)
            avail = poh + sr - g
            net = max(0, m["safety"] - avail)
            por = lot_size(net, m["lot"]) if net > 0 else 0
            poh = avail + por
            rows.append(dict(w=w, gross=g, sr=sr, net=net, por=por, poh=poh))
            if por:
                rel = w - m["lt"]
                orders.append((item, rel, w, por))
                # 下达计划订单 => 子件毛需求出现在下达周（<1 周的算逾期，落在 W1）
                for p, c, qpa, loss in BOM:
                    if p == item:
                        need = math.ceil(por * Decimal(str(qpa)) * (1 + Decimal(str(loss))))  # 用 Decimal，避免 float 误差
                        gross[c][max(rel, 1)] += need
        result[item] = rows
    return llc, result, orders


if __name__ == "__main__":
    llc, result, orders = run()
    print("低层码:", {k: v for k, v in sorted(llc.items(), key=lambda kv: (kv[1], kv[0]))})
    for item, rows in result.items():
        print(f"\n{item} (LT={ITEMS[item]['lt']}, 安全库存={ITEMS[item]['safety']}, 批量={ITEMS[item]['lot']})")
        print("周   毛需求 在途 净需求 计划到货 期末库存")
        for r in rows:
            print(f"W{r['w']}  {r['gross']:6} {r['sr']:4} {r['net']:6} {r['por']:8} {r['poh']:8}")
    print("\n计划订单（下达周 -> 到货周）:")
    for item, rel, rec, q in sorted(orders, key=lambda o: (o[1], o[0])):
        flag = "  <-- 已逾期，要加急" if rel < 1 else ""
        print(f"{item:12} 下达 W{rel:<2} 到货 W{rec} 数量 {q}{flag}")
    # 手算结果的自检（见词条里的手算表）
    pcba = {r["w"]: r for r in result["PCBA-A100"]}
    assert (pcba[4]["net"], pcba[4]["por"], pcba[4]["poh"]) == (140, 200, 70)
    assert (pcba[6]["net"], pcba[6]["por"], pcba[6]["poh"]) == (20, 100, 90)
    rr = {r["w"]: r for r in result["R-10K-0402"]}
    assert [rr[w]["gross"] for w in (2, 3, 4, 5, 6)] == [164, 2448, 306, 1224, 164]
    assert (rr[3]["net"], rr[3]["por"]) == (1112, 5000)
    assert ("IC-MCU-32", -1, 3, 170) in orders
    print("\n手算自检全部通过")

实验 B：T-SQL 版 ​

新建 mrp.sql，在临时库 Lab_erp2 里运行（脚本开头会自己建库，用完要删库）：

sql
-- 最小 MRP（T-SQL）：周为时间桶；在临时库 Lab_erp2 里运行
IF DB_ID(N'Lab_erp2') IS NOT NULL BEGIN ALTER DATABASE Lab_erp2 SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE Lab_erp2; END
CREATE DATABASE Lab_erp2;
GO
USE Lab_erp2;
SET NOCOUNT ON;
GO
CREATE TABLE MrpItem (ItemCode VARCHAR(30) PRIMARY KEY, LeadWk INT, OnHand INT, Safety INT,
                      LotRule VARCHAR(3), LotQty INT);          -- LotRule: LFL 或 FIX
CREATE TABLE MrpBom  (Parent VARCHAR(30), Child VARCHAR(30), QtyPer DECIMAL(18,4), LossRate DECIMAL(9,4),
                      PRIMARY KEY (Parent, Child));
CREATE TABLE MrpDemand (ItemCode VARCHAR(30), Wk INT, Qty INT, Kind VARCHAR(3),  -- MPS 独立需求 / SR 在途
                        PRIMARY KEY (ItemCode, Wk, Kind));
CREATE TABLE MrpPlan (ItemCode VARCHAR(30), Wk INT, Gross INT, Sched INT, Net INT, PlanRecv INT, Poh INT,
                      PRIMARY KEY (ItemCode, Wk));
CREATE TABLE MrpOrder (ItemCode VARCHAR(30), RelWk INT, RecvWk INT, Qty INT);
GO
INSERT MrpItem VALUES

 ('ENCLOSURE',2,200,0,'LFL',0), ('SCREW-M3',1,1000,200,'FIX',1000), ('R-10K-0402',2,2000,500,'FIX',5000),
 ('C-100N-0402',2,1000,0,'FIX',4000), ('IC-MCU-32',4,30,0,'LFL',0);
INSERT MrpBom VALUES
 ('A100','PCBA-A100',1,0), ('A100','ENCLOSURE',1,0), ('A100','SCREW-M3',4,0), ('A100','R-10K-0402',2,0.02),
 ('PCBA-A100','PCB-A100',1,0), ('PCBA-A100','R-10K-0402',12,0.02),
 ('PCBA-A100','C-100N-0402',8,0.02), ('PCBA-A100','IC-MCU-32',1,0);
INSERT MrpDemand VALUES ('A100',3,100,'MPS'), ('A100',5,150,'MPS'), ('A100',7,80,'MPS'), ('PCBA-A100',2,60,'SR');
GO
-- 1. 低层码：每个物料在所有路径中出现的最深层（递归 CTE 取 MAX）
;WITH Path AS (
    SELECT ItemCode, 0 AS Lvl FROM MrpItem WHERE ItemCode NOT IN (SELECT Child FROM MrpBom)
    UNION ALL
    SELECT b.Child, p.Lvl + 1 FROM Path p JOIN MrpBom b ON b.Parent = p.ItemCode
)
SELECT ItemCode, MAX(Lvl) AS LowLevel INTO #Llc FROM Path GROUP BY ItemCode OPTION (MAXRECURSION 50);
-- 2. 预置 8 周空行，写入独立需求
INSERT MrpPlan (ItemCode, Wk, Gross, Sched, Net, PlanRecv, Poh)
SELECT i.ItemCode, w.n, 0, 0, 0, 0, 0 FROM MrpItem i CROSS JOIN (VALUES (1),(2),(3),(4),(5),(6),(7),(8)) w(n);
UPDATE p SET Gross = d.Qty FROM MrpPlan p JOIN MrpDemand d ON d.ItemCode = p.ItemCode AND d.Wk = p.Wk AND d.Kind = 'MPS';
UPDATE p SET Sched = d.Qty FROM MrpPlan p JOIN MrpDemand d ON d.ItemCode = p.ItemCode AND d.Wk = p.Wk AND d.Kind = 'SR';
GO
-- 3. 按低层码从小到大逐个物料计算
DECLARE @item VARCHAR(30), @lt INT, @poh INT, @safety INT, @rule VARCHAR(3), @lot INT;
DECLARE @wk INT, @gross INT, @sr INT, @avail INT, @net INT, @por INT;
DECLARE c CURSOR LOCAL FAST_FORWARD FOR
    SELECT i.ItemCode, i.LeadWk, i.OnHand, i.Safety, i.LotRule, i.LotQty
    FROM MrpItem i JOIN #Llc l ON l.ItemCode = i.ItemCode ORDER BY l.LowLevel, i.ItemCode;
OPEN c;
FETCH NEXT FROM c INTO @item, @lt, @poh, @safety, @rule, @lot;
WHILE @@FETCH_STATUS = 0
BEGIN
    SET @wk = 1;
    WHILE @wk <= 8
    BEGIN
        SELECT @gross = Gross, @sr = Sched FROM MrpPlan WHERE ItemCode = @item AND Wk = @wk;
        SET @avail = @poh + @sr - @gross;
        SET @net = CASE WHEN @avail < @safety THEN @safety - @avail ELSE 0 END;
        SET @por = CASE WHEN @net = 0 THEN 0
                        WHEN @rule = 'LFL' THEN @net
                        ELSE ((@net + @lot - 1) / @lot) * @lot END;      -- 向上取整到批量的整数倍
        SET @poh = @avail + @por;
        UPDATE MrpPlan SET Net = @net, PlanRecv = @por, Poh = @poh WHERE ItemCode = @item AND Wk = @wk;
        IF @por > 0
        BEGIN
            INSERT MrpOrder VALUES (@item, @wk - @lt, @wk, @por);
            -- 计划订单下达 -> 子件毛需求（单耗 × (1+损耗率) 向上取整；下达周 < 1 的算在 W1）
            UPDATE p SET Gross = p.Gross + CEILING(@por * b.QtyPer * (1 + b.LossRate))
            FROM MrpPlan p JOIN MrpBom b ON b.Child = p.ItemCode AND b.Parent = @item
            WHERE p.Wk = CASE WHEN @wk - @lt < 1 THEN 1 ELSE @wk - @lt END;
        END
        SET @wk += 1;
    END
    FETCH NEXT FROM c INTO @item, @lt, @poh, @safety, @rule, @lot;
END
CLOSE c; DEALLOCATE c;
GO

SELECT ItemCode, Wk, Gross, Sched, Net, PlanRecv, Poh FROM MrpPlan WHERE ItemCode = 'PCBA-A100' ORDER BY Wk;

第 3 步：自己改一改（结果均已用 Python 版实际运行） ​

  • 提前期不准：把 IC-MCU-32 的提前期从 4 周改成 2 周（lt=2）。逾期订单消失，变成 W1 下 170、W3 下 100。现实中的意义：供应商说"4 周交货"，实际 2 周就到，MRP 却一直按 4 周报"逾期"，计划员被迫长期人工干预。反过来，如果实际 6 周，MRP 会天天"安全"地漏单。
  • 库存不准：把芯片账面库存 30 改成 0（实际盘点发现根本没有）。W3 计划订单从 170 变成 200，少下 30 个就会缺料停线。
  • 批量策略：把电阻批量改成 LFL（缺多少买多少），计划订单变成 4 张：W1 下 1112、W2 下 306、W3 下 1224、W4 下 164，期末库存永远落在安全库存 500 上；固定批量 5000 则只有 W1 一张。LFL 库存低但下单次数多，固定批量相反。
  • 安全库存：把电阻安全库存改成 0，订单仍是 W1 下达的一张 5000（W3 净需求从 1112 降为 612，但固定批量依然取整到 5000），数量不变，只是库存底线降到 0，一旦消耗波动就没有缓冲了。

常见坑与排查 ​

现象原因与办法
MRP 建议"缺料"但仓库明明有库存账不准、库存在冻结/不良/待检状态没被算成可用，见 库存账与账实一致。MRP 只认账
满屏逾期订单提前期设置比实际长，或需求日期太近。先核对提前期，再看是不是 MPS 的订单排得不合理
子件需求算少/多BOM 不准（单耗、损耗率、版本不对），或者损耗在 BOM 和 MRP 参数里各算了一次，见 BOM与物料清单
同一物料在不同层，计划不完整没按低层码计算。自研 MRP 要特别注意；商用 ERP 一般会自动维护低层码，但新增 BOM 后要重算
电子料买多了过期批量太大或没考虑 MSD/保质期，见 MSD湿敏元件管理；通用件 MOQ 大时和采购谈拆包
替代料没有计入MRP 只按主料算，替代料库存用不上。要么做成"替代料组"一起算，要么人工处理，见 主数据与物料编码
MRP 结果和 APS 排程冲突MRP 无限产能。先 MRP 出料需求，再由 APS 按产能排程，两者要互相反馈
每次全算太慢、结果大幅跳变重新生成（Regenerative）与净改变（Net Change）两种运行方式的差异；大厂常每天夜里跑一次，白天只看结果
计划订单直接当成了采购单计划订单只是建议，采购/计划员确认后才转请购和采购单

业务视角与技术视角 ​

业务视角 ​

  • 谁用：计划员（跑 MRP、处理异常）、采购员（看请购建议）、车间主管（看生产计划订单）、仓库（备料）。
  • 流程：销售订单/预测 → MPS → 跑 MRP → 计划订单 → 采购件转请购/采购单 采购管理，自制件转工单 工单管理 → 工单下发时生成 SMT上料防错与站位表 的备料需求 → MES与WMS衔接 发料。
  • PCB/SMT 厂的特点：物料种类多（一块板几百个料号）、很多物料提前期长（芯片可能几十周）、有 MSD 湿敏和保质期（锡膏）约束、BOM 改版（ECN，见 变更管理ECN-ECR）频繁。
  • KPI：缺料率、齐套率（工单开工时料齐的比例）、库存周转、采购交期达成率、MRP 异常消息处理时效。

技术视角 ​

  • 表：物料主数据（提前期、安全库存、批量规则）、BOM、MPS（计划需求）、库存快照与在途（采购单行、工单）、计划订单表（物料、数量、下达日、到货日、状态：Planned 计划 → Firmed 确认 → Released 已转单；还要记录需求来源，即"这笔毛需求是被谁引起的"，称为 pegging，用于追溯）。
  • 算法：和实验一致：先算低层码，再按低层码顺序逐层逐桶计算。真实系统在数据量上是"几万物料 × 几十个时间桶 × 多层 BOM"，一般用批处理，夜间运行。
  • 数据类型：数量、单耗用 decimal，取整要明确在哪一步（每张订单还是汇总后），见上面 164/306/164 的例子。
  • 与 MES 的关系：MRP 在 ERP 里做"料"的计划，MES 管执行；MES 反馈的报工、物料消耗会更新 ERP 库存与在途，影响下一次 MRP，见 ERP与MES衔接。
  • 你们公司：自研的 MES/WMS 如果要做简化版齐套检查，可以直接用本篇 T-SQL 的思路（单工单展开 BOM、扣可用库存），但别拿它冒充完整 MRP。

练习题与答案 ​

  1. 某物料现有库存 40，安全库存 10，本周毛需求 80，在途 60，批量固定 100，期末库存是多少、要不要下计划订单？ 答：可用 = 40 + 60 - 80 = 20，不低于安全库存 10，不下单，期末库存 20（这就是 PCBA-A100 的 W2）。
  2. 同一物料下周毛需求 150，上周期末库存 20，其余同上。净需求和计划订单是多少？ 答：可用 = 20 - 150 = -130；净需求 = 10 - (-130) = 140；按固定批量 100 向上取整 = 200；期末库存 = -130 + 200 = 70。
  3. 一个物料 LT 为 3 周，计划到货 W5，应该哪一周下达？如果今天是 W2，会发生什么？ 答：W5 - 3 = W2 下达，刚好赶得上。如果今天已经是 W3，则下达周 W2 已过，属于逾期订单，要加急或改期。
  4. 计划 80 块整机，整机外挂电阻 2 个，损耗率 2%，需要多少电阻（这一张订单）？ 答：80 × 2 × 1.02 = 163.2，向上取整 164。
  5. 为什么要有低层码？不用会怎样？ 答：同一物料可能出现在 BOM 的不同层。必须等它所有上层都算完、毛需求汇齐了，才能计算它本身；否则会漏需求，该下的采购单没有出。
  6. 按 EOQ 公式，D = 120000，K = 150，h = 0.01，求 Q*，并验证 Q = 20000 时总成本更高。 答：Q* = √(2 × 120000 × 150 / 0.01) = 60000，总成本 600 元；Q = 20000 时 = 900 + 100 = 1000 元，更高。
  7. MRP 为什么叫"无限产能"？这会带来什么问题？ 答：MRP 只按料计算，不检查产线、设备每周能做多少。结果可能是某一周排了超出产能的生产计划订单，需要 APS 或计划员调整。
  8. 芯片提前期 4 周、W3 要货 200、现有库存 30，LFL。计划订单是多少、哪周下达？ 答：净需求 170，LFL 下 170；3 - 4 = -1，即 W-1 下达，已逾期。

小结 ​

  • MRP = 主生产计划 + BOM + 库存/在途 + 提前期 + 批量规则 → 计划订单（请购建议、生产计划订单）。
  • 核心公式：可用 = 上期末 + 在途 - 毛需求；可用低于安全库存则缺；净需求按批量取整成计划到货；下达周 = 到货周 - 提前期。
  • 多层 BOM 要按低层码从上往下算，子件毛需求取自父件的下达周。
  • 批量策略：LFL、固定批量、MOQ、EOQ 各有适用场景。
  • 现实里 MRP 的准确性取决于数据：BOM、库存账、提前期任何一项不准，结果都会失真。
