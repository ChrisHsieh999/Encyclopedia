检测任务与结果录入

AI 生成 · 待核对制造业务LIMS更新于 2026-10-21

⚠ 待核对：任务状态、复测与更正规则、OOS 调查的分阶段和结论名称（Invalid / Confirmed）、复核"不能是同一个人"，是实验室数据管理中的通用做法（OOS 一词来自制药行业的监管语境，电子厂常简化执行）。你们是自研 LIMS，具体流程、状态名和审批层级可能不同，请对照核实。 触发器和 THROW 的语法对照微软文档；所有 T-SQL、C# 代码和输出，都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 LIMS 系列第 4 篇，也是整个系列的核心。读完你应该能：说清检测任务从分派到复核的完整过程；实现"录入原始值、系统自动算均值极差、按限值自动判定"；理解 OOS 为什么要调查而不是随手重测；用触发器让结果表"只能追加"，亲手验证改数据会被拦住；用 C# 调用存储过程录入，并看到两个终端同时录入同一个点时只有一个成功。

一句话定义 ​

检测任务是"某个样品的某个检测项目，由某个人（用某台仪器）去测"这个工作单元；结果录入是把测出的原始数据存进系统，由系统按规格自动判定，并保证数据只增不改、改动留痕、超规格必查。

先修知识 ​

  • 样品管理：样品要先处于 Assigned 或 Testing 状态才能分派任务。
  • 检测方法与标准：知道检测项目、规格 LSL/USL、fn_ResolveSpec 怎么取限值。
  • 工单管理 里"把条件写进 WHERE"的技巧，本篇会反复用到。

它解决什么问题 ​

回到第一篇里的 Excel 实验室，看看结果环节最容易出的事：

  • 悄悄改数。镍厚度测出 6.3 微米，上限 6.0。检测员心想"肯定是探头歪了"，直接改成 5.9。没人知道，报告出去了，货也放行了。
  • 测到合格为止。重测一次 5.8，合格，把第一次的 6.3 删了。实验室行业叫 "testing into compliance"（测到合格为止），是数据造假的典型形式：保留好的、扔掉坏的。
  • 自己审自己。检测员录完数据，自己又点"复核通过"，等于没有复核。
  • 算错了。5 个点的平均值，用计算器按错一位。
  • 同时录入。两个人给同一个点各录了一遍，数据库里出现两个不同的值，报告取哪个？

本篇的设计目标：录入时系统自动判定，超规格自动开调查；结果表不允许改和删，更正只能追加并说明原因；调查结论为"实验室原因"才能复测；复核必须是另一个人。

核心概念 ​

任务的状态 ​

状态含义谁、怎么变
Pending任务已分派，还没开始主管分派
InProgress已录入至少一个结果检测员录入第一个值时自动变
Done检测员已提交：结果齐了，没有未处理的 OOS检测员提交
Reviewed另一位复核人确认复核人（不能是检测员本人）
Pending ─第一个结果→ InProgress ─提交→ Done ─复核→ Reviewed

重复值、均值与极差 ​

很多检测要在多个位置或多次重复取值：镀层厚度在板上测 5 个点，阻抗测 3 个测试条。每个值是一个 重复值（Replicate），用 ReplicateNo 编号。

  • 原始值（RawValue）：仪器读出的数，不做任何修约或加工，是证据。
  • 平均值：所有重复值之和除以个数。
  • 极差（Range）：最大值减最小值，用来看这几个点之间差异有多大，差异大说明镀层不均匀或测量不稳。

平均值和极差是算出来的，不要手工录入、也不要存成原始数据：它们从当前有效的原始值现算（用视图），原始值更正后它们自动跟着变。

自动判定与 Judgement ​

录入时系统用 fn_ResolveSpec 取当天的限值，把每个值与限值比较（含边界）：

Judgement含义
Pass在规格内
OOS超规格（Out Of Specification）：初判落在规格外，需要调查，暂不下结论
FailOOS 调查之后确认是真实不合格

注意区别：OOS 是"测出来超了"，Fail 是"调查后确认超了"。测出来超的原因可能是样品问题，也可能是实验室自己的问题（探头歪了、仪器没预热、数据抄错）。不调查就下结论，两个方向都不对：直接判不合格可能冤枉了供应商，随手重测可能放走了真正的不良。

更正、复测与"只追加" ​

结果表 TestResult 的铁律：不允许 UPDATE 和 DELETE。需要更正或复测时，追加一行，用 SupersedesId 指向被它取代的那一行，Reason 写原因。旧行永远在，只是不再是"当前有效结果"。

第 5 点:  [#5 6.3 OOS] ←取代── [#6 5.4 Pass, 原因: OOS 调查 Invalid 后复测]

"当前有效结果" = 没有被别的行取代的行，用一个视图 vw_CurrentResult 表达；平均值、极差都基于它。

OOS 调查 ​

一个超规格结果出现后：

  1. 系统自动开一个调查单（OosInvestigation，状态 Open），关联这条结果；
  2. 调查：先查实验室原因——仪器状态与校准、标准片核查、样品是否被污染或放错、操作步骤、计算和录入有没有错。找到明确的实验室原因 → 结论 Invalid（结果作废）；没找到、或复测确认同样超规格 → 结论 Confirmed（确认不合格）；
  3. 结论为 Invalid：允许复测。复测结果作为新行追加，取代原来那一行；
  4. 结论为 Confirmed：系统追加一行 Fail，该结果终结，不可再被取代，并通知 QMS 开不合格处理单（见 不合格品控制NCR）；
  5. 有未处理 OOS 的任务不能提交。

实验室对"能不能在调查前复测"有严格规定，核心精神是：不能不经调查就用复测结果替换超规格结果。本篇用"调查结论为 Invalid 才允许复测"来落实这个精神。

复核（四眼原则） ​

数据录入的人和确认数据的人不能是同一个人。复核人检查：原始数据是否齐全、仪器是否在校准期内、判定是否正确、有无未处理的 OOS、更正是否有原因。系统层面做一个硬规则：复核人 ≠ 检测员。

业务视角 ​

谁在什么环节做什么 ​

角色做什么
实验室主管分派任务（谁测哪个项目、用哪台仪器）；组织 OOS 调查；批准结论
检测员领样、按方法检测、录入原始值、提交
复核人复核数据与判定，签字
质量工程师接收 Confirmed 结论，发起不合格处理（NCR / 8D）

流程 ​

  1. 样品到位后主管分派任务：一个样品对应多个检测项目，每个项目一个任务；任务带上方法版本快照（见 检测方法与标准）；
  2. 检测员检测并逐点录入，系统实时判定；
  3. 超规格 → 自动开 OOS 调查 → 调查 → Invalid 则复测 / Confirmed 则追加 Fail；
  4. 所有重复值齐全、无未处理 OOS → 检测员提交；
  5. 另一位复核人复核；
  6. 全部任务复核完 → 样品进入 Tested，转入 报告与签发。

涉及的单据和记录 ​

检测任务单、原始数据记录（电子版即 TestResult）、OOS 调查单、复核记录。

KPI ​

任务按时完成率、一次通过率（无 OOS 的任务占比）、OOS 率（按检测项目、仪器、检测员分析，找系统性问题）、OOS 调查平均关闭时长、复核退回率。

表设计 ​

    SampleId     int          NOT NULL REFERENCES Sample(Id),
    ItemId       int          NOT NULL REFERENCES TestItem(Id),
    MethodId     int          NOT NULL REFERENCES TestMethod(Id),   -- 分派时快照的方法版本

CREATE TABLE TestResult (                         -- 只追加：不允许 UPDATE / DELETE
    Id           int IDENTITY PRIMARY KEY,
    TaskId       int           NOT NULL REFERENCES TestTask(Id),
    ReplicateNo  int           NOT NULL,
    RawValue     decimal(18,6) NULL,
    Judgement    varchar(8)    NOT NULL,          -- Pass / Fail / OOS
    EnteredBy    nvarchar(30)  NOT NULL,
    EnteredAt    datetime2(0)  NOT NULL,
    LslUsed      decimal(18,6) NULL,              -- 判定时用的限值快照
    UslUsed      decimal(18,6) NULL,
    SupersedesId int           NULL REFERENCES TestResult(Id),
    Reason       nvarchar(200) NULL,
    CONSTRAINT CK_TestResult_Judgement CHECK (Judgement IN ('Pass','Fail','OOS')),
    CONSTRAINT UQ_TestResult_Chain UNIQUE (TaskId, ReplicateNo, SupersedesId)
);

三个关键设计：

1. 触发器让结果表"只追加"

sql
CREATE TRIGGER TR_TestResult_AppendOnly ON TestResult INSTEAD OF UPDATE, DELETE AS
BEGIN
    THROW 50020, N'TestResult 只能追加：更正请插入一行并填 SupersedesId 与 Reason', 1;
END

INSTEAD OF 触发器会"取代"原来的 UPDATE 或 DELETE 语句，里面直接 THROW，语句就失败。不管谁从哪里连库，改和删都做不到（除非先禁用触发器，那需要高权限，并且应该被审计到）。

2. 唯一约束 UNIQUE (TaskId, ReplicateNo, SupersedesId)：数据库级防重复

SQL Server 的唯一约束把多个 NULL 当作"相同"。所以：同一任务同一个重复号只能有一行 SupersedesId 为空的"原始行"；同一行也只能被取代一次（不能有两行都说"我取代 #5"）。存储过程里的检查是第一道关，这个约束是最后一道保险，两个终端同时录入同一个点时，慢的那个会撞约束失败。

3. 视图：当前有效结果、平均值、极差

sql
CREATE OR ALTER VIEW vw_CurrentResult AS
SELECT r.* FROM TestResult r
WHERE NOT EXISTS (SELECT 1 FROM TestResult n WHERE n.SupersedesId = r.Id);

CREATE OR ALTER VIEW vw_TaskStats AS
SELECT TaskId, COUNT(*) AS N, AVG(RawValue) AS Mean, MIN(RawValue) AS MinV, MAX(RawValue) AS MaxV,
       MAX(RawValue) - MIN(RawValue) AS RangeV,
       SUM(CASE WHEN Judgement <> 'Pass' THEN 1 ELSE 0 END) AS NotPass
FROM vw_CurrentResult GROUP BY TaskId;

录入存储过程做了什么 ​

usp_EnterResult 的逻辑，按顺序：

  1. 任务必须存在、状态是 Pending 或 InProgress、录入人必须是被分派的检测员；
  2. 新录入（没填 SupersedesId）：该重复号不能已有当前有效结果；
  3. 更正或复测（填了 SupersedesId）：必须写原因；被取代的行必须是该任务该重复号的当前有效行；已确认 Fail 的不能被取代；OOS 的必须有"已关闭且 Invalid"的调查；
  4. 用 fn_ResolveSpec 取限值，比较得到 Pass 或 OOS；
  5. 一个事务里：插入结果、（OOS 则）插入调查单、任务状态 Pending → InProgress。

为什么要把规则写成存储过程？因为约束和触发器能拦住"明显违规的写入"，但"这个更正合不合法"这类业务规则需要一段逻辑。把它们放在数据库里，不管 C# 程序、导入脚本还是仪器接口，走的都是同一条路，没有绕过的后门。

C# 端不需要重复这些规则，只需要调用存储过程、处理被拒绝的情况：

}
catch (Exception e) { /* e.Message 就是数据库 THROW 的中文原因，直接提示给用户 */ }

注意参数里写 @Now = @now：存储过程第 5 个位置参数是 @SupersedesId，漏写参数名会把时间塞进去（我实验里就踩过，报"datetime 不能隐式转换成 int"）。调用存储过程时，可选参数一律写名字。

sql
USE Lab_LIMS;
GO
-- 视图：当前有效结果 = 没有被后来的行取代的结果
CREATE OR ALTER VIEW vw_CurrentResult AS
SELECT r.* FROM TestResult r
WHERE NOT EXISTS (SELECT 1 FROM TestResult n WHERE n.SupersedesId = r.Id);
GO
-- 视图：每个任务的平均值、极差（只算当前有效结果）
CREATE OR ALTER VIEW vw_TaskStats AS
SELECT TaskId, COUNT(*) AS N, AVG(RawValue) AS Mean, MIN(RawValue) AS MinV, MAX(RawValue) AS MaxV,
       MAX(RawValue) - MIN(RawValue) AS RangeV,
       SUM(CASE WHEN Judgement <> 'Pass' THEN 1 ELSE 0 END) AS NotPass
FROM vw_CurrentResult GROUP BY TaskId;
GO
-- 分派检测任务：样品必须已分配或在测；方法版本在此刻快照
CREATE OR ALTER PROCEDURE usp_AssignTask
    @SampleNo nvarchar(30), @ItemCode nvarchar(30), @Analyst nvarchar(30), @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    INSERT TestTask (SampleId, ItemId, MethodId, Analyst, Status, AssignedAt)
    SELECT s.Id, i.Id, i.MethodId, @Analyst, 'Pending', @Now
    FROM Sample s CROSS JOIN TestItem i
    WHERE s.SampleNo = @SampleNo AND i.ItemCode = @ItemCode AND s.Status IN ('Assigned', 'Testing');
    IF @@ROWCOUNT = 0 THROW 50003, N'样品不存在、状态不对（需 Assigned/Testing），或检测项目不存在', 1;
END
GO
-- 录入一个结果：取规格 -> 自动判定 -> 只追加；超规格自动开 OOS 调查
CREATE OR ALTER PROCEDURE usp_EnterResult
    @TaskId int, @ReplicateNo int, @Value decimal(18,6), @EnteredBy nvarchar(30),
    @SupersedesId int = NULL, @Reason nvarchar(200) = NULL, @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    DECLARE @status varchar(12), @analyst nvarchar(30), @itemId int, @product nvarchar(40);
    SELECT @status = t.Status, @analyst = t.Analyst, @itemId = t.ItemId, @product = s.ItemCode
    FROM TestTask t JOIN Sample s ON s.Id = t.SampleId WHERE t.Id = @TaskId;
    IF @status IS NULL THROW 50010, N'任务不存在', 1;
    IF @status NOT IN ('Pending', 'InProgress') THROW 50011, N'任务已提交或已复核，不能再录入', 1;
    IF @EnteredBy <> @analyst THROW 50012, N'只有被分派的检测员能录入', 1;
    IF @SupersedesId IS NULL
    BEGIN
        IF EXISTS (SELECT 1 FROM vw_CurrentResult WHERE TaskId = @TaskId AND ReplicateNo = @ReplicateNo)
            THROW 50013, N'该重复号已有结果；更正或复测请填 SupersedesId 和原因', 1;
    END
    ELSE
    BEGIN
        IF @Reason IS NULL THROW 50015, N'更正或复测必须写原因', 1;
        DECLARE @oldJ varchar(8);
        SELECT @oldJ = Judgement FROM vw_CurrentResult WHERE Id = @SupersedesId AND TaskId = @TaskId AND ReplicateNo = @ReplicateNo;
        IF @oldJ IS NULL THROW 50016, N'被取代的行不存在、不属于该任务/重复号，或已被取代', 1;
        IF @oldJ = 'Fail' THROW 50017, N'已确认不合格的结果不能被取代', 1;
        IF @oldJ = 'OOS' AND NOT EXISTS (SELECT 1 FROM OosInvestigation WHERE ResultId = @SupersedesId AND Status = 'Closed' AND Conclusion = 'Invalid')
            THROW 50014, N'超规格结果必须先完成 OOS 调查并判定无效，才能复测', 1;
    END
    DECLARE @lsl decimal(18,6), @usl decimal(18,6);
    SELECT @lsl = Lsl, @usl = Usl FROM fn_ResolveSpec(@product, @itemId, CAST(@Now AS date));
    DECLARE @j varchar(8) = CASE WHEN (@lsl IS NOT NULL AND @Value < @lsl) OR (@usl IS NOT NULL AND @Value > @usl) THEN 'OOS' ELSE 'Pass' END;
    BEGIN TRAN;
    INSERT TestResult (TaskId, ReplicateNo, RawValue, Judgement, EnteredBy, EnteredAt, LslUsed, UslUsed, SupersedesId, Reason)
    VALUES (@TaskId, @ReplicateNo, @Value, @j, @EnteredBy, @Now, @lsl, @usl, @SupersedesId, @Reason);
    DECLARE @rid int = SCOPE_IDENTITY();
    IF @j = 'OOS' INSERT OosInvestigation (ResultId, Status, OpenedAt) VALUES (@rid, 'Open', @Now);
    UPDATE TestTask SET Status = 'InProgress' WHERE Id = @TaskId AND Status = 'Pending';
    COMMIT;
END
GO
-- 关闭 OOS 调查：Invalid = 实验室原因、允许复测；Confirmed = 确认不合格，追加一行 Fail
CREATE OR ALTER PROCEDURE usp_CloseOos
    @OosId int, @Conclusion varchar(10), @RootCause nvarchar(200), @By nvarchar(30), @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    IF @Conclusion NOT IN ('Invalid', 'Confirmed') THROW 50018, N'结论只能是 Invalid 或 Confirmed', 1;
    BEGIN TRAN;
    UPDATE OosInvestigation SET Status = 'Closed', Conclusion = @Conclusion, RootCause = @RootCause, ClosedAt = @Now, ClosedBy = @By
    WHERE Id = @OosId AND Status = 'Open';
    IF @@ROWCOUNT = 0 BEGIN ROLLBACK; THROW 50019, N'调查不存在或已关闭', 1; END
    IF @Conclusion = 'Confirmed'
        INSERT TestResult (TaskId, ReplicateNo, RawValue, Judgement, EnteredBy, EnteredAt, LslUsed, UslUsed, SupersedesId, Reason)
        SELECT r.TaskId, r.ReplicateNo, r.RawValue, 'Fail', @By, @Now, r.LslUsed, r.UslUsed, r.Id, N'OOS 调查确认：' + @RootCause
        FROM OosInvestigation o JOIN TestResult r ON r.Id = o.ResultId WHERE o.Id = @OosId;
    COMMIT;
END
GO
-- 提交：结果齐了、没有未处理的 OOS，才能 InProgress -> Done
CREATE OR ALTER PROCEDURE usp_SubmitTask @TaskId int, @By nvarchar(30)
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE t SET Status = 'Done'
    FROM TestTask t JOIN TestItem i ON i.Id = t.ItemId
    WHERE t.Id = @TaskId AND t.Status = 'InProgress' AND t.Analyst = @By
      AND (SELECT COUNT(*) FROM vw_CurrentResult WHERE TaskId = t.Id) >= i.Replicates
      AND NOT EXISTS (SELECT 1 FROM vw_CurrentResult WHERE TaskId = t.Id AND Judgement = 'OOS');
    IF @@ROWCOUNT = 0 THROW 50030, N'不能提交：状态不对、不是本人、结果不齐，或还有未处理的 OOS', 1;
END
GO
-- 复核：必须是另一个人，Done -> Reviewed
CREATE OR ALTER PROCEDURE usp_ReviewTask @TaskId int, @Reviewer nvarchar(30), @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE TestTask SET Status = 'Reviewed', ReviewedBy = @Reviewer, ReviewedAt = ISNULL(@Now, SYSDATETIME())
    WHERE Id = @TaskId AND Status = 'Done' AND Analyst <> @Reviewer;
    IF @@ROWCOUNT = 0 THROW 50031, N'不能复核：任务未提交，或复核人与检测员是同一个人', 1;
END
GO

namespace LimsLab;

// 实验：C# 调用存储过程录入结果，看自动判定、边界值，以及两个终端同时录入同一个点
public static class LabResult
{
    static readonly DateTime Now = new(2026, 10, 24, 9, 0, 0);

    // 录入一个结果，返回 "成功" 或数据库给出的拒绝原因
    static string Enter(int taskId, int rep, decimal value, string by)
    {
        using var db = Db.Create();                        // 每个终端自己的连接
        try
        {
            db.Ado.ExecuteCommand("EXEC usp_EnterResult @t, @r, @v, @by, @Now = @now", new SugarParameter[] {
                new("@t", taskId), new("@r", rep), new("@v", value), new("@by", by), new("@now", Now) });
            return "成功";
        }
        catch (Exception e) { return "被拒绝：" + e.Message.Split('\n')[0]; }
    }

    public static void Run(SqlSugarClient db)
    {
        // 准备：新登记一个样品，分配，派一个化金厚度任务
        db.Ado.ExecuteCommand("EXEC usp_RegisterSample N'IQC', N'IQC-LAB', N'PCB-A100', N'L2610-LAB', N'收样员', N'收样台', @now", new SugarParameter("@now", Now));
        var sampleNo = db.Ado.GetString("SELECT TOP 1 SampleNo FROM Sample WHERE SampleNo LIKE 'SMP-20261024-%' ORDER BY Id DESC");
        db.Ado.ExecuteCommand("EXEC usp_MoveSample @no, 'Assigned', N'收样员', N'理化室A架', NULL, @now", new SugarParameter[] { new("@no", sampleNo), new("@now", Now) });
        db.Ado.ExecuteCommand("EXEC usp_AssignTask @no, N'AU_THK', N'张工', @now", new SugarParameter[] { new("@no", sampleNo), new("@now", Now) });
        var taskId = db.Ado.GetInt("SELECT MAX(t.Id) FROM TestTask t JOIN Sample s ON s.Id = t.SampleId WHERE s.SampleNo = @no", new SugarParameter("@no", sampleNo));

        Console.WriteLine("规格：化金厚度 0.05 ~ 0.10 µm（含边界）");
        foreach (var (rep, v) in new[] { (1, 0.049m), (2, 0.05m), (3, 0.10m), (4, 0.101m) })
        {
            Console.WriteLine($"  点 {rep} 录入 {v} -> {Enter(taskId, rep, v, "张工")}");
        }
        Console.WriteLine("别人冒名录入：" + Enter(taskId, 5, 0.07m, "李四"));

        var res = new string[2];
        Parallel.For(0, 2, i => res[i] = Enter(taskId, 5, 0.07m, "张工"));
        Console.WriteLine($"两个终端同时录入第 5 点：成功 {res.Count(r => r == "成功")} 个，被拒绝 {res.Count(r => r != "成功")} 个");

        Console.WriteLine("入库的结果与自动判定：");
        foreach (var r in db.Queryable<TestResult>().Where(r => r.TaskId == taskId).OrderBy(r => r.Id).ToList())
            Console.WriteLine($"  点 {r.ReplicateNo}  {r.RawValue:0.000}  {r.Judgement}");
        var open = db.Ado.GetInt("SELECT COUNT(*) FROM OosInvestigation o JOIN TestResult r ON r.Id = o.ResultId WHERE r.TaskId = @t AND o.Status = 'Open'", new SugarParameter("@t", taskId));
        Console.WriteLine($"自动开出的 OOS 调查：{open} 个");
    }
}

常见坑与排查 ​

坑事实与办法
结果表允许 UPDATE数据可以悄悄改。用 INSTEAD OF 触发器拦住，更正追加新行
OOS 后直接允许重测变成"测到合格为止"。重测必须以调查结论 Invalid 为前提
只在存储过程里检查"重复号是否已有结果"并发时两个终端都通过检查。再加唯一约束作为最后保险
判定时现查规格规格改版后历史结果被重新解释。录入时把限值存进 LslUsed/UslUsed
平均值、极差手工录入或存成原始数据原始值更正后就对不上。用视图从当前有效值现算
把 float 用在 RawValue边界值（0.05）可能存成 0.0499999 误判。用 decimal
复核人可以是检测员本人复核失去意义。存储过程里硬规则：复核人不等于检测员
调用存储过程时位置参数错位可选参数一律写名字（@Now = @now）
存储过程里先检查、后在事务外插入检查和插入之间有空档。写入放事务里，并配唯一约束
通过禁用触发器"修数据"需要高权限且应有审计。实验室数据的修正走更正流程，不要走后门
OOS 的结论不通知 QMSConfirmed 要触发不合格处理（NCR / 8D），否则实验室发现了问题却没人跟进

练习题与答案 ​

  1. OOS 和 Fail 的区别是什么？ 答：OOS 是初判超规格，需要调查，暂不下结论；Fail 是调查后确认是真实不合格。
  2. 为什么复测要以"调查结论为 Invalid"为前提？ 答：防止"测到合格为止"。只有找到明确的实验室原因（探头偏、录入错等）才能让原结果作废并复测；找不到原因就不能用复测值替换超规格值。
  3. UNIQUE (TaskId, ReplicateNo, SupersedesId) 为什么能同时防止"同一点录入两次"和"同一行被取代两次"？ 答：SQL Server 唯一约束把 NULL 当相同。两个原始行（SupersedesId 都为 NULL）同任务同重复号 → 重复，被拒；两行都取代同一个 Id → 也重复，被拒。
  4. 修改题：规则改为"每个点都要合格，且均值也要在规格内"。应该改哪里？ 答：逐点判定不变；提交时（usp_SubmitTask）增加对均值的判断——用 vw_TaskStats 的 Mean 与 fn_ResolveSpec 取到的限值比较，均值超规格则拒绝提交或自动开 OOS 调查。
  5. 写一个查询：找出所有"还有未关闭 OOS 调查"的任务编号及检测员。 答：
    sql
    SELECT DISTINCT t.Id AS TaskId, t.Analyst
FROM OosInvestigation o
JOIN TestResult r ON r.Id = o.ResultId
JOIN TestTask t ON t.Id = r.TaskId
WHERE o.Status = 'Open';
  6. 为什么实验里 usp_CloseOos 的 Confirmed 分支要追加一行 Fail，而不是直接把原来那行 OOS 改成 Fail？ 答：结果表不允许 UPDATE。追加一行并用 SupersedesId 指回去，既完成了"终态为 Fail"，又保留了"曾经是 OOS"的历史。

小结 ​

  • 任务状态：Pending → InProgress → Done → Reviewed；复核人必须不是检测员。
  • 录入时自动取限值判定（含边界），超规格判 OOS 并自动开调查单；平均值和极差用视图从当前有效值现算。
  • 结果表只追加：触发器禁止改删，更正或复测追加一行，用 SupersedesId 指向旧行并写原因；唯一约束防重复。
  • OOS 调查：Invalid 才允许复测，Confirmed 追加 Fail 并通知 QMS；有未处理 OOS 的任务不能提交。
  • 限值与方法版本做快照，历史结论不随规格改版而变。
