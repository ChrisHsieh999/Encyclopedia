仪器管理与校准

AI 生成 · 待核对制造业务LIMS仪器更新于 2026-10-21

⚠ 待核对：校准、期间核查、校准失败后的影响分析是实验室管理的通用做法；ISO/IEC 17025:2017 适用于检测和校准实验室这一点已对照 IEC 网店页面，条款原文和具体要求我没有逐条核对（标准是付费文本）。校准周期、提前提醒天数、核查容差、校准失败后的回溯范围等，你们公司和客户另有规定，且你们是自研 LIMS，请对照核实。仪器自动采集部分用 CSV 文件模拟仪器导出，没有连接真实仪器，真实仪器的文件格式或通信协议因厂商而异。所有 T-SQL 和 Python 代码、输出，都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 LIMS 系列第 5 篇。读完你应该能：说清仪器台账、校准、期间核查、使用记录各是什么；设计"校准过期不得出数据"的锁定机制，并理解为什么锁定不能依赖一个每天跑一次的状态刷新任务；处理校准不合格后的影响分析；理解仪器自动采集的基本思路，用 Python 把仪器导出的 CSV 变成录入数据并过滤坏行。

一句话定义 ​

仪器管理是 LIMS 里管理实验室所有测量设备的功能：建台账、定校准计划、记录校准结果、校准过期或不合格就锁定不得出数据，并记录每台仪器用在了哪些检测上。

先修知识 ​

  • 检测任务与结果录入：知道任务、usp_EnterResult 和结果只追加。本篇会给这个存储过程加上校准锁定。
  • 检测方法与标准：知道检测方法和仪器的关系：方法规定用哪类仪器。
  • 校准与量具管理：QMS 侧对量具的管理，和本篇的实验室仪器管理思路相通。

它解决什么问题 ​

  • 过期仪器出数据。XRF 测厚仪的校准证书 10 月 10 日到期，没人记得。到 10 月 21 日，检测员照常用它测了几十块板。客户审核发现，这段时间的数据全部"溯源性不足"，报告可能要重做，甚至要召回已放行的批次。
  • 仪器坏了没人知道。仪器漂移了，测的数偏了 0.1 微米，每天照用，数据系统性偏高。校准周期是一年，中间没有任何检查。
  • 校准不合格了，不知道影响了谁。这次送校发现仪器读数偏差超限。那么上次校准合格以来，这台仪器出过的所有数据都可疑，但没有使用记录，根本不知道是哪些样品、哪些报告。
  • 台账靠 Excel 和便利贴。到期提醒靠人记，哪台在用、哪台报废了，各说各的。

仪器管理要做到：该校准的提前提醒；过期、不合格的仪器系统直接拒绝出数据；每次使用都有记录，出了问题能倒查影响范围。

核心概念 ​

术语解释
仪器台账所有测量设备的清单：编号、名称、型号、位置、校准周期、到期日、状态
校准（Calibration）用更高精度的标准去核对仪器，确定它的读数偏差是否在允许范围内。结果是一份校准证书，有日期、结论、下次到期日
校准周期 / 到期日校准有有效期，到期必须重新校准；周期由仪器特性、使用频率、历史稳定性决定
溯源性（Traceability）校准用的标准本身可以一级一级追溯到国家或国际标准；证书是溯源链的凭证。ISO/IEC 17025 是检测和校准实验室能力的通用要求，溯源性是其中重要的一部分
期间核查（Intermediate Check）两次校准之间，用一个已知值的标准件（比如标称 2.50 微米的镀层标准片）自己测一下，看读数偏差是否在容差内，及时发现漂移
校准状态本系列用三个：Active（可用）、Overdue（过期或被锁定，不得出数据）、Retired（已报废）
使用记录每次用哪台仪器测了哪个任务、谁、什么时候。校准出问题时倒查用
影响分析校准或核查不合格后，找出"上次合格以来这台仪器出过的所有结果"，评估是否需要复测、是否要通知客户

校准锁定：核心是"在录入那一步拦" ​

很多系统只在仪器列表里把过期的标红。标红谁都能无视。真正的锁定是：录入结果的那一步，系统检查仪器是否在有效期内，不在就拒绝。

这里有一个很容易犯的错误：用一个状态字段 + 每天跑一次的任务来控制——任务把过期仪器的状态改成 Overdue，录入时只检查状态字段。问题是：

  • 到期日 10 月 10 日，10 月 11 日凌晨的任务如果没跑（服务挂了、数据库维护），状态仍是 Active，仪器照样能出数据；
  • 就算任务按时跑，从午夜 0 点到任务运行之间也有空窗。

所以正确做法是录入时直接用到期日和"现在"比较，状态字段只管"被人工锁定/报废"和给界面显示用。两个条件都满足才允许出数据：

状态 = Active  且  到期日 >= 录入日期

到期日当天仍有效，第二天起失效（本系列的约定，请与你们实验室的规定一致）。

业务视角 ​

谁做什么 ​

角色做什么
仪器管理员 / 计量员新仪器验收建档；制定校准计划；安排送校或厂内校准；录入证书；做期间核查
检测员使用前确认仪器状态；使用时系统自动记录；发现异常上报
实验室主管审批校准计划，处理校准失败后的影响分析
质量部门抽查校准有效性，客户审核时提供证据

流程 ​

  1. 新购验收：开箱检查，首次校准合格后建档，设定周期和到期日；
  2. 校准计划：系统每月（或每天）生成"未来 30 天（示例）内到期"的清单，提醒送校；提前量根据送校耗时定；
  3. 校准：送外部计量机构或厂内用标准器校准，得到证书；
  4. 录入证书：记录校准日期、下次到期日、证书号、结论；合格则更新到期日并保持可用；不合格则立即锁定；
  5. 期间核查：按计划（如每天开机后或每周）用标准件核查，偏差超容差就锁定并通知；
  6. 使用：每次出数据自动写使用记录；
  7. 报废：状态改 Retired，保留历史记录，不再允许任何使用。

涉及的单据和记录 ​

仪器台账、校准计划、校准证书（CalibrationRecord）、期间核查记录（InstrumentCheck）、使用记录（InstrumentUsage）、报废单。

常见规则 ​

  • 过期、不合格、报废的仪器不得出数据；
  • 校准不合格必须做影响分析；
  • 只读 / 外部校准件的证书要保留，客户审核会看；
  • 仪器搬迁、维修后要重新核查甚至重新校准才能恢复使用。

KPI ​

校准按期完成率、超期仪器数（应为 0）、期间核查通过率、校准锁定拦截次数（说明有人想用过期仪器，要查原因）、仪器利用率。

技术视角 ​

表设计 ​

Instrument 和 CalibrationRecord 在 LIMS 的基础库里已经建好，本篇新增使用记录和核查记录两张表：

sql
CREATE TABLE Instrument (
    Id           int IDENTITY PRIMARY KEY,
    InstrumentNo nvarchar(30) NOT NULL CONSTRAINT UQ_Instrument UNIQUE,
    Name         nvarchar(60) NOT NULL,
    CalDueDate   date         NOT NULL,           -- 校准到期日
    Status       varchar(10)  NOT NULL DEFAULT 'Active',
    CONSTRAINT CK_Instrument_Status CHECK (Status IN ('Active','Overdue','Retired'))
);
-- CalibrationRecord：每次校准一行，只追加（InstrumentId, CalDate, NextDue, CertNo, Result, CalBy）
-- InstrumentUsage：每次出数据一行（InstrumentId, TaskId, UsedBy, UsedAt）
-- InstrumentCheck：每次期间核查一行（InstrumentId, CheckedAt, RefValue, Measured, Tol, Passed, CheckedBy）
表作用是否只追加
Instrument台账，当前到期日和状态否（当前状态）
CalibrationRecord校准历史，每次一行是（历史）
InstrumentCheck期间核查历史是
InstrumentUsage使用历史是

校准锁定怎么写 ​

在 检测任务与结果录入 的 usp_EnterResult 里，取到任务之后、做其它检查之前加入这一段：

sql
IF @inst IS NOT NULL AND NOT EXISTS (
    SELECT 1 FROM Instrument WHERE Id = @inst AND Status = 'Active' AND CalDueDate >= CAST(@Now AS date))
    THROW 50040, N'仪器不在校准有效期内（过期、被锁定或已报废），不能出数据', 1;

同一事务里，成功写入结果后再写一条使用记录：

sql
IF @inst IS NOT NULL INSERT InstrumentUsage (InstrumentId, TaskId, UsedBy, UsedAt) VALUES (@inst, @TaskId, @EnteredBy, @Now);

要点：

  1. 以日期比较为准，不依赖状态刷新任务；usp_MarkOverdue 只是给界面和清单用；
  2. 用 @Now（录入时刻）而不是"任务分派时刻"：仪器可能在任务分派后才过期；
  3. 任务没有指定仪器怎么办：本实验里 InstrumentId 为空就不检查（比如纯手工的滴定）。真实系统应该让"需要仪器的方法"强制指定仪器，否则就留了后门——这是你们设计时要决定的；
  4. 解锁只能通过合格的校准记录：usp_RecordCalibration 校准合格才把状态改回 Active 并更新到期日；不合格就置为 Overdue；
  5. 期间核查不合格同样置 Overdue，不合格后要靠重新校准解锁。

台账提醒与影响分析 ​

即将到期清单（只用日期比较，随时可跑）：

sql
SELECT InstrumentNo, Name, CalDueDate FROM Instrument
WHERE Status <> 'Retired' AND CalDueDate <= DATEADD(DAY, 30, CAST(SYSDATETIME() AS date));

影响分析：找出某台仪器在可疑期间出过的所有数据（见实验第 8 部分）。

仪器自动采集的思路 ​

手工抄写仪器读数既慢又容易错。常见的自动采集方式（本机无法验证具体仪器，以下仅为概念）：

方式说明
文件导出仪器软件把结果导出为 CSV / TXT / XML 放到共享目录，LIMS 的导入程序定时读取，最常见也最容易落地
串口 / 网口通信仪器通过串口或 TCP 把读数发出来，需要按厂商协议解析，见 串口通信、工业通信
仪器软件的数据库直接读取仪器软件的本地数据库，需注意不能影响仪器软件运行
工业协议部分设备支持 OPC UA 等，见 OPC-UA

无论哪种，导入程序都要做好这几件事：校验数据（空值、单位、范围）、坏行隔离不入库并报告、写入时走同一条受控通路（即 usp_EnterResult，这样校准锁定、判定、只追加照样生效）、保留原始文件。下面的实验用 Python 演示前三点。

样品 SMP-20261021-003，分派两个任务给张工：化镍厚度用 XRF-01（到期日 2027-03-15），阻抗用 TDR-01（到期日 2026-10-10，已过期）。

 (N'ROSE-01', N'离子污染测试仪',   '2026-12-01', 'Active'),
 (N'XRF-OLD', N'旧款测厚仪',       '2025-01-01', 'Retired');
GO
-- 记录一次校准：合格则更新到期日并解锁；不合格则锁定
CREATE OR ALTER PROCEDURE usp_RecordCalibration
    @InstrumentNo nvarchar(30), @CalDate date, @NextDue date, @CertNo nvarchar(40), @Result varchar(10), @CalBy nvarchar(60)
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @id int = (SELECT Id FROM Instrument WHERE InstrumentNo = @InstrumentNo AND Status <> 'Retired');
    IF @id IS NULL THROW 50041, N'仪器不存在或已报废', 1;
    BEGIN TRAN;
    INSERT CalibrationRecord (InstrumentId, CalDate, NextDue, CertNo, Result, CalBy) VALUES (@id, @CalDate, @NextDue, @CertNo, @Result, @CalBy);
    IF @Result = 'Pass' UPDATE Instrument SET CalDueDate = @NextDue, Status = 'Active' WHERE Id = @id;
    ELSE                UPDATE Instrument SET Status = 'Overdue' WHERE Id = @id;      -- 校准不合格：立刻锁定
    COMMIT;
END
GO
-- 日常任务：把已过期的在用仪器标成 Overdue（给界面显示用；真正的拦截不依赖它）
CREATE OR ALTER PROCEDURE usp_MarkOverdue @AsOf date
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE Instrument SET Status = 'Overdue' WHERE Status = 'Active' AND CalDueDate < @AsOf;
    PRINT CAST(@@ROWCOUNT AS nvarchar(10)) + N' 台仪器被标为 Overdue';
END
GO
-- 期间核查：用已知值的标准件测一次，偏差超容差就锁定
CREATE OR ALTER PROCEDURE usp_RecordCheck
    @InstrumentNo nvarchar(30), @RefValue decimal(18,6), @Measured decimal(18,6), @Tol decimal(18,6), @By nvarchar(30), @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    DECLARE @id int = (SELECT Id FROM Instrument WHERE InstrumentNo = @InstrumentNo AND Status <> 'Retired');
    IF @id IS NULL THROW 50041, N'仪器不存在或已报废', 1;
    DECLARE @ok bit = CASE WHEN ABS(@Measured - @RefValue) <= @Tol THEN 1 ELSE 0 END;
    INSERT InstrumentCheck (InstrumentId, CheckedAt, RefValue, Measured, Tol, Passed, CheckedBy) VALUES (@id, @Now, @RefValue, @Measured, @Tol, @ok, @By);
    IF @ok = 0 UPDATE Instrument SET Status = 'Overdue' WHERE Id = @id;
END
GO
-- 分派任务时可以指定仪器（新增最后一个参数，旧调用方式不受影响）
CREATE OR ALTER PROCEDURE usp_AssignTask
    @SampleNo nvarchar(30), @ItemCode nvarchar(30), @Analyst nvarchar(30), @Now datetime2(0) = NULL, @InstrumentNo nvarchar(30) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    DECLARE @inst int = (SELECT Id FROM Instrument WHERE InstrumentNo = @InstrumentNo);
    IF @InstrumentNo IS NOT NULL AND @inst IS NULL THROW 50042, N'仪器编号不存在', 1;
    INSERT TestTask (SampleId, ItemId, MethodId, InstrumentId, Analyst, Status, AssignedAt)
    SELECT s.Id, i.Id, i.MethodId, @inst, @Analyst, 'Pending', @Now
    FROM Sample s CROSS JOIN TestItem i
    WHERE s.SampleNo = @SampleNo AND i.ItemCode = @ItemCode AND s.Status IN ('Assigned', 'Testing');
    IF @@ROWCOUNT = 0 THROW 50003, N'样品不存在、状态不对（需 Assigned/Testing），或检测项目不存在', 1;
END
GO
-- 录入结果：在 03 篇的基础上加了"仪器必须在校准有效期内"，并写使用记录
CREATE OR ALTER PROCEDURE usp_EnterResult
    @TaskId int, @ReplicateNo int, @Value decimal(18,6), @EnteredBy nvarchar(30),
    @SupersedesId int = NULL, @Reason nvarchar(200) = NULL, @Now datetime2(0) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET @Now = ISNULL(@Now, SYSDATETIME());
    DECLARE @status varchar(12), @analyst nvarchar(30), @itemId int, @product nvarchar(40), @inst int;
    SELECT @status = t.Status, @analyst = t.Analyst, @itemId = t.ItemId, @product = s.ItemCode, @inst = t.InstrumentId
    FROM TestTask t JOIN Sample s ON s.Id = t.SampleId WHERE t.Id = @TaskId;
    IF @status IS NULL THROW 50010, N'任务不存在', 1;
    IF @status NOT IN ('Pending', 'InProgress') THROW 50011, N'任务已提交或已复核，不能再录入', 1;
    IF @EnteredBy <> @analyst THROW 50012, N'只有被分派的检测员能录入', 1;
    -- ★ 校准锁定：状态必须是 Active，并且按"录入时刻"的日期算，到期日当天仍有效、第二天起失效
    IF @inst IS NOT NULL AND NOT EXISTS (
        SELECT 1 FROM Instrument WHERE Id = @inst AND Status = 'Active' AND CalDueDate >= CAST(@Now AS date))
        THROW 50040, N'仪器不在校准有效期内（过期、被锁定或已报废），不能出数据', 1;
    IF @SupersedesId IS NULL
    BEGIN
        IF EXISTS (SELECT 1 FROM vw_CurrentResult WHERE TaskId = @TaskId AND ReplicateNo = @ReplicateNo)
            THROW 50013, N'该重复号已有结果；更正或复测请填 SupersedesId 和原因', 1;
    END
    ELSE
    BEGIN
        IF @Reason IS NULL THROW 50015, N'更正或复测必须写原因', 1;
        DECLARE @oldJ varchar(8);
        SELECT @oldJ = Judgement FROM vw_CurrentResult WHERE Id = @SupersedesId AND TaskId = @TaskId AND ReplicateNo = @ReplicateNo;
        IF @oldJ IS NULL THROW 50016, N'被取代的行不存在、不属于该任务/重复号，或已被取代', 1;
        IF @oldJ = 'Fail' THROW 50017, N'已确认不合格的结果不能被取代', 1;
        IF @oldJ = 'OOS' AND NOT EXISTS (SELECT 1 FROM OosInvestigation WHERE ResultId = @SupersedesId AND Status = 'Closed' AND Conclusion = 'Invalid')
            THROW 50014, N'超规格结果必须先完成 OOS 调查并判定无效，才能复测', 1;
    END
    DECLARE @lsl decimal(18,6), @usl decimal(18,6);
    SELECT @lsl = Lsl, @usl = Usl FROM fn_ResolveSpec(@product, @itemId, CAST(@Now AS date));
    DECLARE @j varchar(8) = CASE WHEN (@lsl IS NOT NULL AND @Value < @lsl) OR (@usl IS NOT NULL AND @Value > @usl) THEN 'OOS' ELSE 'Pass' END;
    BEGIN TRAN;
    INSERT TestResult (TaskId, ReplicateNo, RawValue, Judgement, EnteredBy, EnteredAt, LslUsed, UslUsed, SupersedesId, Reason)
    VALUES (@TaskId, @ReplicateNo, @Value, @j, @EnteredBy, @Now, @lsl, @usl, @SupersedesId, @Reason);
    DECLARE @rid int = SCOPE_IDENTITY();
    IF @j = 'OOS' INSERT OosInvestigation (ResultId, Status, OpenedAt) VALUES (@rid, 'Open', @Now);
    IF @inst IS NOT NULL INSERT InstrumentUsage (InstrumentId, TaskId, UsedBy, UsedAt) VALUES (@inst, @TaskId, @EnteredBy, @Now);
    UPDATE TestTask SET Status = 'InProgress' WHERE Id = @TaskId AND Status = 'Pending';
    COMMIT;
END
GO

第 4 步，读懂输出：

  • 第 2 部分最关键：TDR-01 的到期日是 10 月 10 日，但 Status 还是 Active（日常任务没跑），录入照样被拒绝。锁定靠日期比较，不靠状态刷新；
  • 第 3 部分：日常任务把它标成 Overdue；第 4 部分：校准合格后恢复，录入成功；
  • 第 5 部分：到期日当天 23:50 成功，第二天 00:10 被拒绝；
  • 第 6 部分：核查偏差 0.02（在容差 0.05 内）合格，偏差 0.11 不合格，XRF-01 立刻锁定，后面的录入被拒绝；

python
"""把 XRF 导出的 CSV 变成录入 SQL。坏行不入库，只在最后列出来给人看。
用法：python xrf_import.py 输入.csv 输出.sql"""
import csv, sys
from decimal import Decimal, InvalidOperation

ANALYST = "张工"
EXPECT_UNIT = {"NI_THK": "um", "AU_THK": "um"}      # 仪器单位必须和检测项目一致

good, bad = [], []
with open(sys.argv[1], encoding="utf-8", newline="") as f:
    for n, row in enumerate(csv.DictReader(f), start=2):          # 第 1 行是表头，数据从第 2 行算
        try:
            value = Decimal(row["value"])
            if row["unit"] != EXPECT_UNIT[row["item"]]:
                raise ValueError(f"单位 {row['unit']} 与项目要求 {EXPECT_UNIT[row['item']]} 不符")
            good.append((row["sample"], row["item"], int(row["point"]), value, row["time"]))
        except InvalidOperation:
            bad.append((n, row, "数值无法解析"))
        except (ValueError, KeyError) as e:
            bad.append((n, row, str(e)))

lines = []
emit = lines.append
emit("USE Lab_LIMS; SET NOCOUNT ON;")
emit("DECLARE @t int;")
for sample, item, point, value, time in good:
    emit(f"SET @t = (SELECT t.Id FROM TestTask t JOIN Sample s ON s.Id=t.SampleId JOIN TestItem i ON i.Id=t.ItemId "
         f"WHERE s.SampleNo=N'{sample}' AND i.ItemCode=N'{item}');")
    emit(f"EXEC usp_EnterResult @t, {point}, {value}, N'{ANALYST}', @Now = '{time}';")
emit(f"PRINT N'导入 {len(good)} 行，拒收 {len(bad)} 行';")
for n, row, why in bad:
    emit(f"PRINT N'拒收：CSV 第 {n} 行（{row['item']} 点{row['point']}）：{why}';")

with open(sys.argv[2], "w", encoding="utf-8", newline="\n") as f:
    f.write("\n".join(lines) + "\n")
print(f"已生成 {sys.argv[2]}：导入 {len(good)} 行，拒收 {len(bad)} 行")

练习题与答案 ​

  1. 为什么校准锁定不能只依赖"每天凌晨把过期仪器标成 Overdue 的任务"？ 答：任务可能没跑或有时间空窗，期间过期仪器的状态仍是 Active，可以出数据。录入时直接用到期日与当前日期比较，没有空窗。
  2. 到期日是 2026-10-21。10-21 23:59 可以出数据吗？10-22 00:00 呢？ 答：10-21 23:59 可以（CalDueDate >= 录入日期，到期日当天有效）；10-22 00:00 不可以。这是本系列的约定，需与你们实验室规定一致。
  3. 校准不合格和期间核查不合格，仪器分别应该怎么处理？为什么都要锁定？ 答：都置为不可用（Overdue）。因为这说明仪器读数已经不可信，继续出数据只会产生错误结论。解锁只能通过重新校准合格。
  4. 写一个查询：列出未来 30 天内到期、且没有报废的仪器。 答：见正文"台账提醒与影响分析"的 SQL；条件是 Status <> 'Retired' 且 CalDueDate <= 今天 + 30 天。如果还想列出已过期的，不加下限即可。
  5. 导入程序直接 INSERT INTO TestResult 比调用 usp_EnterResult 快，为什么不应该这样做？ 答：直接写表绕过了校准锁定、自动判定、OOS 调查、使用记录、权限检查等全部规则，实验室数据的可信度就靠导入程序"自觉"。所有来源的数据走同一条受控通路，规则才不会有后门。
  6. 为什么要保留仪器导出的原始文件？ 答：原始文件是数据来源的证据。数据库里的值如果被质疑，可以与原始文件核对；同时在导入程序有缺陷时可以重新导入。

小结 ​

  • 仪器管理包含台账、校准、期间核查、使用记录；校准有有效期，核查用已知值的标准件。
  • 校准锁定要在录入那一步由系统强制：状态为 Active 且到期日不早于录入日期；以日期比较为准，不依赖状态刷新任务。
  • 校准或核查不合格立即锁定；用使用记录倒查"可疑期间出过哪些数据"，做影响分析。
  • 解锁只能通过合格的校准记录；报废用状态而不是删除。
  • 仪器自动采集要校验数据、隔离坏行、走同一条受控录入通路、保留原始文件。
