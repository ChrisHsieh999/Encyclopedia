首件检验与换线

AI 生成 · 待核对制造业务MESSMT首件换线防错更新于 2026-10-21

⚠ 待核对：首件检验的触发条件（开线、换线、换料、换班、设备维修后、工艺变更）、换线清单、"未通过首件锁线"的规则是电子厂（尤其 SMT）常见的通用做法，每家公司的首件制度（谁检、检什么、首件要不要留样、末件要不要做、换班是否都要首件）差别很大，你们的自研 MES 一定有自己的规则，请对照你们的系统和质量体系文件。"首件检验"在航空领域有 SAE AS9102 这个专门标准（要求在制造源、工艺、检验方法、地点、工装或材料等变化可能影响装配/外形/功能时重新做首件），已联网确认大意，电子制造业通常是参照这个思路做自己的制度，不要把 AS9102 的要求直接套到你们的产品上。代码与输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 11 篇，对应 过站与工序流转 进站检查清单的第 7 项"首件已通过"。读完你应该能：说清首件检验（FAI）为什么存在、什么时候要做；列出换线（Changeover）的标准步骤；设计首件单 FirstArticle 和它的状态；让"首件没过，线体不能生产"在系统里真正生效；理解 Fail 之后怎么返调、怎么重检；并亲手跑通整个流程。

一句话定义 ​

首件检验（FAI，First Article Inspection）是在开线、换线、换料等"可能改变生产结果"的时刻之后，先做出一块（或一小批）样板，由检验员确认它完全正确，确认合格之前不允许批量生产。换线（Changeover）是产线从做 A 产品切换到做 B 产品（或换一批料、换一个程序）的整个切换过程，首件是换线的"出口检查"。

先修知识 ​

  • SMT与电子组装流程：知道印刷、贴片、回流、AOI 的顺序。
  • SMT上料防错与站位表：换线时要重新上料并扫码比对。
  • 治具与钢网管理：换线时要换钢网。
  • 工艺参数与炉温曲线管理：换线时要换设备程序/炉温曲线。
  • 过站与工序流转：知道进站检查清单，首件是其中的第 7 项。

它解决什么问题 ​

SMT 线最怕"批量性错误"：一个设置错了，后面每一块板都跟着错。

现场故事：早班换线，把 A100 的产线切换成 A200。物料员换了料，钢网也换了，但贴片机程序忘了调（还是 A100 的程序）。没人检查，机器全速贴了 300 块板才被后道 AOI 发现：全部元件贴错位置。这 300 块板报废的成本，远远超过检查第一块板所需的几分钟。

类似的批量性错误还有：

  • 上错一盘料（电容装成了电阻），后面每块板都错；
  • 钢网装反或装错，每块板锡膏印偏；
  • 炉温曲线调错，每块板焊接不良；
  • 维修了设备后参数飘了；
  • 换班后新班组的设置和上个班不一样。

首件检验的思路很简单：既然错误是成批的，就在批量开始前，用第一块板把错误挡住。检验的成本是一块板，挡住的是一整批。

核心概念 ​

首件检验 FAI ​

首件检验不是"检查第一块板"这么简单，它有三个要素：

  • 时机：什么情况下要做（触发条件，见下）；
  • 内容：检什么（元件型号/极性/位置、焊接质量、外观、必要时的功能测试，对照样板、BOM 和图纸）；
  • 门禁：没通过就不能量产。这条是核心，不是检验完记录一下就算，而是系统要真的拦住。

电子厂里还有几个相关概念，别混淆：

概念做什么与首件的区别
首件开线/换线后第一块量产前的"准入"检查
巡检（PQC/IPQC）生产中按频率抽检持续监控
末件一批/一个班/换线前的最后一块确认整批过程没漂移，也常留作下次的比对样板
终检（OQC）出货前抽检出货的"出口"检查

触发条件 ​

下面是常见的触发首件的场景，本篇实验把它们作为 TriggerType：

TriggerType触发场景说明
Startup开线（班前开机、长时间停线后重启）设备预热、首次生产的确认
Changeover换线（换产品/换工单）最严格，一次改变多项
MaterialChange生产中换了料（尤其是更换料号或不同批次、替代料）防止换错或换成不合格批次
ShiftChange换班新班组接手后的确认（是否强制取决于工厂制度）
Repair设备维修/保养后维修可能改变精度和参数
ProcessChange工艺变更（程序、参数、炉温曲线修改，ECN 生效）关联 工艺参数与炉温曲线管理
Retry上一次首件 Fail，调机后的复检返调回路

与 AS9102 的思路相比，电子制造业常用的触发清单更"贴近设备动作"：凡是人换了一个东西、改了一个设置，都可能需要首件。具体哪些必须做、哪些可以豁免，是质量体系的决定，不是 MES 的决定；MES 的任务是把决定固化成不可绕过的规则。

换线：不止是换料 ​

换线是一串有顺序的动作，漏掉任何一项都可能出批量错误。一份常见的换线清单（Changeover Checklist）：

#步骤做什么与系统的关系
1清线（Line Clearance）把上一个产品的板子、物料、标签、钢网、治具从线上清理干净，防止混料混板线长确认；ClearLine
2换料按新产品站位表上料，每盘扫码比对SMT上料防错与站位表；Material
3换程序/Recipe印刷机、贴片机、回流炉、AOI 切换到新产品程序和炉温曲线工艺参数与炉温曲线管理；Program
4换钢网/治具领用新产品的钢网、治具，归还旧的治具与钢网管理；Stencil
5首件确认生产首件，检验员判定FirstArticle
6放行首件 Pass 后，线体允许量产进站检查放行

注意：清线、换料、换程序、换钢网这 4 项是"准备项"，必须先做完才能申请首件判定；首件才是"验收"。实验里把这四项作为 ChecklistDone，没做完就不能判 Pass。不同触发原因要求的准备项不同：换班可能一项都不要，换料只要确认 Material。

首件单与线体状态 ​

FirstArticle（首件单）是一张单据，有状态：

text
Pending（待检）──检验员判定──→ Pass（合格，线体放行）
                              └→ Fail（不合格，线体继续锁定）

线体能不能生产，不另建"线体状态"字段，直接看这条线最新的一张首件单：

最新首件单线体
不存在不能生产（没有证明过）
Pending锁定，等待检验
Fail锁定，必须调机后开新单复检
Pass 且工单 = 板所属工单放行
Pass 但工单不是这块板的工单不能生产（线体当前的首件是另一张工单的）

这个设计的好处是状态只有一个来源：不会出现"首件单是 Fail、线体状态却是放行"这种两处不一致。

Fail 之后怎么办？ 不是修改这张单，而是：调机/返调 → 开一张新的首件单（Retry）→ 重新检验。旧的 Fail 单保留，履历里能看到"这次换班第一次就没过"。这和 过站与工序流转 里"Fail 的记录保留，Pass 另追加"是同一个原则。

业务视角 ​

谁在什么环节做什么：

角色动作
线长/技术员执行换线：清线、换料、换程序、换钢网；确认准备项；生产首件并送检
首件检验员（IPQC/QC）对首件做检验（对照 BOM、样板、位号图，必要时测试），判定 Pass/Fail，Fail 时写原因
物料员按站位表上料
工艺工程师Fail 时分析原因、调整参数；批准工艺变更
生产/品质主管看首件通过率、换线耗时；处理异常

流程：

  1. 触发（系统自动或线长申请）→ 系统开一张 Pending 首件单，线体立刻锁定；
  2. 换线人员完成各准备项，系统逐项记录；
  3. 生产首件（SMT 通常是 1 拼板），检验员检验；
  4. 判定：
    • Pass：线体放行，操作员可以开始进站；
    • Fail：线体继续锁定，工艺工程师返调；返调后重新开 Retry 单，重检；
  5. 生产结束或换线前，按需要做末件检验并留样。

常见规则：

  • 首件检验员不应该是做设置的同一个人（"自检"与"互检"分离），防止自己检查自己；
  • 同一条线同一时刻只能有一张待检的首件单（防止两张单互相冲突）；
  • 首件通过后，线体上的关键设置不得再改：改了就是新的触发（比如换料就是 MaterialChange）；
  • 首件板通常不直接出货，要标识，处理方式（留样/返工后出货）由制度决定。

KPI：

  • 首件一次通过率（Pass 数 ÷ 首件单数）；
  • 换线时长（从触发到首件 Pass）；
  • 首件 Fail 原因分布（料、程序、钢网、设备）；
  • 因首件问题造成的批量不良次数（应当趋近 0）。

技术视角 ​

表设计 ​

本篇定义实体 FirstArticle（规划中的字段见 MES核心数据模型，以本篇为准）：

字段含义
LineCode哪条线
WoNo开线/换线后要生产的工单
ProductCode产品
TriggerType触发原因（上面的 7 种）
StatusPending / Pass / Fail
ChecklistDone已完成的准备项，逗号分隔（简化；真实系统常拆成明细表：每个准备项一行，含谁、何时）
SampleSn首件样板的板码
Inspector检验员
RemarkFail 的原因
CreatedAt / ResultAt触发时间 / 判定时间

实体代码见后面的实验。几个设计点：

1. 同一条线只能有一张 Pending：用筛选唯一索引，和 SMT上料防错与站位表 的"一个站位一盘在线"同一个手法：

sql
CREATE UNIQUE INDEX UX_FirstArticle_Pending ON FirstArticle(LineCode) WHERE Status = 'Pending';

这样即使两个终端同时申请首件，也只有一个能开成功。

2. 判定用条件 UPDATE：

sql
UPDATE FirstArticle SET Status = @result, Inspector = @who, Remark = @remark, ResultAt = GETDATE()
WHERE Id = @id AND Status = N'Pending';

返回 1 行才算成功；0 行说明这张单已经被别人判定过了（两个检验员同时点）。Pass 之前还要在代码里检查准备项是否齐全。

3. 门禁查询：进站检查里的"首件已通过"就是看这条线最新的首件单：

sql
SELECT TOP 1 WoNo, TriggerType, Status FROM FirstArticle WHERE LineCode = 'SMT-L1' ORDER BY Id DESC;

用 (LineCode, Id DESC) 的索引，这个查询很快。门禁必须在服务端进站检查里执行（前端检查会被设备接口绕过）。

4. 把"首件"和"过站"联动：在 过站与工序流转 的进站检查里加第 7 项：线体最新首件单不是 Pass，或工单不是这块板的工单，拒绝并说明原因。

这个坑我踩到了 ​

我在写实验时，重复运行实验遇到一个错误：The index 'UX_FirstArticle_Pending' is dependent on column 'Status'. ALTER TABLE ALTER COLUMN Status failed。原因是：SqlSugar 的 InitTables 在第二次运行时会尝试对已有的列做 ALTER COLUMN，而被筛选索引依赖的列不允许这样改。解决办法（实验里已经这样写）：重跑前先删掉这个索引、InitTables 之后再重新建。生产环境里不要靠 InitTables 演进表结构，用迁移脚本。

逐步例子：一次换班加一次换线 ​

线体 SMT-L1，两张工单：WO-FAI-001（产品 PCBA-A100）和 WO-FAI-002（产品 PCBA-A200）。三块板：FAI-0001、FAI-0002（属于 001），FAI-0101（属于 002）。

// 首件检验单（单据）：线体每次需要"重新证明自己能做对"时开一张，Pending -> Pass / Fail。

[SugarTable("FirstArticle")]

{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(20)")]
    public string LineCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(30)")]

    [SugarColumn(ColumnDataType = "nvarchar(50)")]

    [SugarColumn(ColumnDataType = "nvarchar(20)")]

    [SugarColumn(ColumnDataType = "nvarchar(200)", IsNullable = true)]

第 2 步：新建 LabFai.cs：

csharp
using SqlSugar;

namespace MiniMes;

// 首件与换线实验：触发首件 -> 未放行不得进站 -> Pass 放行 -> Fail 返调后重检
public static class LabFai
{
    const string Line = "SMT-L1";

    // 每种触发原因，Pass 之前必须先完成哪些准备项
    static readonly Dictionary<string, string[]> Required = new()
    {
        ["Startup"] = new[] { "Material", "Program" },
        ["Changeover"] = new[] { "ClearLine", "Material", "Program", "Stencil" },
        ["MaterialChange"] = new[] { "Material" },
        ["ShiftChange"] = new string[0],
        ["Repair"] = new[] { "Program" },
        ["ProcessChange"] = new[] { "Program" },
        ["Retry"] = new[] { "Adjust" },
    };

    // 开一张首件单（Pending）。同一条线同时只能有一张 Pending，由数据库的筛选唯一索引保证
    static (string Msg, int Id) Open(SqlSugarClient db, string wo, string trigger)
    {
        var w = db.Queryable<WorkOrder>().InSingle(wo);
        if (w == null || w.Status != "Running") return ("拒绝：工单不是 Running", 0);
        try
        {
            int id = db.Insertable(new FirstArticle { LineCode = Line, WoNo = wo, ProductCode = w.ProductCode, TriggerType = trigger, Status = "Pending", CreatedAt = DateTime.Now })
                .ExecuteReturnIdentity();
            return ($"已开首件单（{trigger}，待检），线体 {Line} 锁定", id);
        }
        catch (Exception e) when (e.Message.Contains("UX_FirstArticle_Pending"))
        {
            return ("拒绝：这条线已经有一张待检的首件单", 0);
        }
    }

    static void Tick(SqlSugarClient db, int id, params string[] items)
    {
        var fa = db.Queryable<FirstArticle>().InSingle(id);
        var all = string.Join(",", (fa.ChecklistDone ?? "").Split(',', StringSplitOptions.RemoveEmptyEntries).Union(items));
        db.Updateable<FirstArticle>().SetColumns(f => new FirstArticle { ChecklistDone = all }).Where(f => f.Id == id && f.Status == "Pending").ExecuteCommand();
    }

    // 判定：Pass 之前准备项必须齐；条件 UPDATE 保证一张单只能出一次结果
    static string Submit(SqlSugarClient db, int id, string result, string remark = null)
    {
        var fa = db.Queryable<FirstArticle>().InSingle(id);
        if (fa.Status != "Pending") return $"拒绝：这张首件单已经有结果了（{fa.Status}）";
        if (result == "Pass")
        {
            var done = (fa.ChecklistDone ?? "").Split(',', StringSplitOptions.RemoveEmptyEntries);
            var missing = Required[fa.TriggerType].Except(done).ToList();
            if (missing.Count > 0) return $"拒绝：准备项没做完，缺 {string.Join("、", missing)}";
        }
        int n = db.Updateable<FirstArticle>()
            .SetColumns(f => new FirstArticle { Status = result, Inspector = "QC01", Remark = remark, ResultAt = DateTime.Now })
            .Where(f => f.Id == id && f.Status == "Pending").ExecuteCommand();
        return n == 1 ? $"首件 {result}" + (result == "Pass" ? "，线体放行" : "，线体继续锁定") : "拒绝：被别人抢先判定了";
    }

    // 进站检查清单里的"首件已通过"：看这条线最新的一张首件单
    static string Gate(SqlSugarClient db, string sn)
    {
        var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
        var fa = db.Queryable<FirstArticle>().Where(f => f.LineCode == Line).OrderBy(f => f.Id, OrderByType.Desc).First();
        if (fa == null) return "拒绝（线体还没有首件单）";
        if (fa.WoNo != u.WoId) return $"拒绝（线体当前首件单属于 {fa.WoNo}，这块板属于 {u.WoId}）";
        if (fa.Status != "Pass") return $"拒绝（首件{(fa.Status == "Pending" ? "还没判定" : "判了不合格")}：{fa.TriggerType}）";
        return "进站通过";
    }

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        // InitTables 重跑时会尝试 ALTER 列，被筛选索引依赖的列会报错：所以先删索引，建表后再建
        db.Ado.ExecuteCommand("IF OBJECT_ID('FirstArticle') IS NOT NULL DROP INDEX IF EXISTS UX_FirstArticle_Pending ON FirstArticle;");
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(FirstArticle));
        db.Ado.ExecuteCommand(@"
IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'UX_FirstArticle_Pending')
    CREATE UNIQUE INDEX UX_FirstArticle_Pending ON FirstArticle(LineCode) WHERE Status = 'Pending';");
        db.Deleteable<FirstArticle>().Where(f => f.LineCode == Line).ExecuteCommand();
        db.Deleteable<Unit>().Where(u => u.SerialNo.StartsWith("FAI-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo.StartsWith("WO-FAI-")).ExecuteCommand();
        db.Insertable(new List<WorkOrder>
        {
            new() { WoNo = "WO-FAI-001", ProductCode = "PCBA-A100", PlanQty = 100, Status = "Running", CreatedAt = DateTime.Now },
            new() { WoNo = "WO-FAI-002", ProductCode = "PCBA-A200", PlanQty = 50, Status = "Running", CreatedAt = DateTime.Now },
        }).ExecuteCommand();
        foreach (var (sn, wo, p) in new[] { ("FAI-0001", "WO-FAI-001", "PCBA-A100"), ("FAI-0002", "WO-FAI-001", "PCBA-A100"), ("FAI-0101", "WO-FAI-002", "PCBA-A200") })
            db.Insertable(new Unit { SerialNo = sn, WoId = wo, ProductCode = p, Status = "InProcess", CreatedAt = DateTime.Now }).ExecuteCommand();

        Console.WriteLine("1. 开线：线体 SMT-L1 要开始生产 WO-FAI-001");
        var (m, a) = Open(db, "WO-FAI-001", "Startup");
        Console.WriteLine($"   {m}");
        Console.WriteLine($"   FAI-0001 想进站 -> {Gate(db, "FAI-0001")}");
        Console.WriteLine($"   这时又触发了一次换班 -> {Open(db, "WO-FAI-001", "ShiftChange").Msg}");

        Console.WriteLine("2. 首件判定：");
        Tick(db, a, "Material");
        Console.WriteLine($"   只做完换料确认就想判 Pass -> {Submit(db, a, "Pass")}");
        Tick(db, a, "Program");
        Console.WriteLine($"   补做程序确认后判 Pass -> {Submit(db, a, "Pass")}");
        Console.WriteLine($"   FAI-0001 想进站 -> {Gate(db, "FAI-0001")}");
        Console.WriteLine($"   同一张单再判一次 -> {Submit(db, a, "Pass")}");

        Console.WriteLine("3. 生产中换了一盘料（MaterialChange）：");
        (m, a) = Open(db, "WO-FAI-001", "MaterialChange");
        Console.WriteLine($"   {m}");
        Console.WriteLine($"   FAI-0002 想进站 -> {Gate(db, "FAI-0002")}");
        Tick(db, a, "Material");
        Console.WriteLine($"   {Submit(db, a, "Pass")}；FAI-0002 想进站 -> {Gate(db, "FAI-0002")}");

        Console.WriteLine("4. 换班首件不合格，返调后重检：");
        (m, a) = Open(db, "WO-FAI-001", "ShiftChange");
        Console.WriteLine($"   判 Fail（印刷偏移）-> {Submit(db, a, "Fail", "印刷偏移 0.12mm")}");
        Console.WriteLine($"   FAI-0001 想进站 -> {Gate(db, "FAI-0001")}");
        (m, a) = Open(db, "WO-FAI-001", "Retry");
        Console.WriteLine($"   调机后重开首件单（Retry）：{m}");
        Console.WriteLine($"   没记录调机动作就判 Pass -> {Submit(db, a, "Pass")}");
        Tick(db, a, "Adjust");
        Console.WriteLine($"   记录调机后判 Pass -> {Submit(db, a, "Pass")}；FAI-0001 想进站 -> {Gate(db, "FAI-0001")}");

        Console.WriteLine("5. 换线：SMT-L1 从 WO-FAI-001（PCBA-A100）换到 WO-FAI-002（PCBA-A200）");
        (m, a) = Open(db, "WO-FAI-002", "Changeover");
        Console.WriteLine($"   {m}");
        Console.WriteLine($"   FAI-0101 想进站 -> {Gate(db, "FAI-0101")}");
        Tick(db, a, "ClearLine", "Material", "Program");
        Console.WriteLine($"   清线、换料、换程序做完，钢网还没换就判 Pass -> {Submit(db, a, "Pass")}");
        Tick(db, a, "Stencil");
        Console.WriteLine($"   换好钢网后判 Pass -> {Submit(db, a, "Pass")}");
        Console.WriteLine($"   FAI-0101 想进站 -> {Gate(db, "FAI-0101")}");
        Console.WriteLine($"   旧工单的 FAI-0002 想进站 -> {Gate(db, "FAI-0002")}");

        Console.WriteLine("6. SMT-L1 的首件单履历：");
        foreach (var f in db.Queryable<FirstArticle>().Where(f => f.LineCode == Line).OrderBy(f => f.Id).ToList())
            Console.WriteLine($"   {f.WoNo} {f.TriggerType,-14} {f.Status,-4} {f.Remark}");
    }
}

常见坑与排查 ​

误区 / 坑事实与办法
首件只是一条记录，不拦生产必须接进站检查，未 Pass 就拒绝，系统真的拦住
线体状态和首件单状态两处存放会不一致。线体能否生产由最新首件单推出，只存一份
Fail 后把原单改成 Pass历史被改写。Fail 保留，调机后开新单
换线只换料清线、换程序、换钢网同样会出批量错误。用清单逐项确认
准备项没做完也能判 Pass判 Pass 前检查准备项齐全
同一条线同时多张待检单互相覆盖、冲突。筛选唯一索引保证只有一张 Pending
两个检验员同时判定条件 UPDATE ... AND Status = 'Pending'，只有一个成功
工单不匹配也放行换线后旧工单的板能进站。门禁要比对工单
首件检验员就是做设置的人自己检查自己。制度上分离，系统里校验账号
InitTables 遇到筛选索引报错重跑前先删索引，建表后再建；生产用迁移脚本
换班是否做首件靠口头在配置里写清楚哪些触发必须首件，系统强制

练习题与答案 ​

  1. 首件检验和巡检的区别？ 答：首件是开线/换线等变化之后、量产之前的准入检查，没过不能量产；巡检是生产过程中按频率抽检，持续监控。
  2. 为什么线体能否生产，要看"最新一张首件单"，而不是在线体上另存一个状态字段？ 答：状态只有一个来源，不会出现首件单 Fail 但线体状态放行的不一致；查询、审计也更简单。
  3. 为什么首件 Fail 后不能把原单改成 Pass，而要开新单？ 答：保留历史才能统计首件通过率、分析 Fail 原因；改写会让"这次换班第一次就没过"这件事消失。
  4. 实验中 UX_FirstArticle_Pending 防止了什么？ 答：防止同一条线同时存在两张待检首件单（比如两个终端同时申请）。即使绕过程序直接插入，数据库也会拒绝。
  5. 线体当前首件单是 WO-FAI-002 的 Pass，WO-FAI-001 的板想进站，为什么要拒绝？ 答：首件证明的是"线体现在按 002 的设置能做对"，001 的板用的钢网、程序、料都不是当前设置，混进来就是批量错误。
  6. 怎样要求"检验员不能是做设置的人"？ 答：首件单记录"准备项完成人"，判定时比对当前登录账号：如果检验员就是准备项的完成人之一，拒绝。同时在制度上授权不同角色。
  7. 换线清单为什么要有"清线"？ 答：防止上一个产品的板、料、标签、钢网混进下一个产品。混料混板是电子厂最难追的错误之一。
  8. 为什么 Pass 之前要检查准备项？ 答：首件板可能是用旧设置做出来的"碰巧好"。准备项做完意味着设置已经更新，首件才能代表后面的量产。
  9. 首件和 过站与工序流转 的进站检查是什么关系？ 答：首件是进站检查清单的第 7 项：线体最新首件单不是 Pass 或工单不匹配就拒绝进站。

小结 ​

  • 首件检验是在可能引起批量性错误的时刻（开线、换线、换料、换班、维修后、工艺变更）之后，量产之前的一次准入检查，没过不能量产。
  • 换线是一串动作：清线、换料、换程序、换钢网，最后首件确认并放行；准备项没做完不能判 Pass。
  • FirstArticle 是单据：Pending → Pass/Fail；线体能否生产看最新首件单，且工单必须匹配；Fail 不改原单，调机后开 Retry 新单。
  • 同一线一张待检单靠筛选唯一索引，判定靠条件 UPDATE；门禁必须放在服务端进站检查里。
  • 规则（触发清单、准备项）由质量体系决定，MES 负责把它固化成不可绕过的检查。
