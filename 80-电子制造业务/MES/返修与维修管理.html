返修与维修管理

AI 生成 · 待核对制造业务MES质量返修更新于 2026-10-21

⚠ 待核对：返修次数上限（本篇实验设为 2 次）、返修后回到哪一站、哪些不良允许返修哪些直接报废，是每个工厂和每个客户自己规定的，本篇的数字只是演示，请对照你们的工艺文件、客户要求和系统。"返工（Rework）"与"维修（Repair）"的含义，我只查到 IPC-7711/7721 的目录和培训机构的解释文章，没有读到 IPC 标准原文，所以定义以标准原文为准。代码和输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 16 篇，接着 不良品拦截与锁定：板子被锁了之后，怎么修、修完回哪里、修几次、修不好怎么办，以及怎么保证修过的板追溯链不断。读完你应该能：说清返工与维修的区别；设计 RepairRecord；写出"开始返修、记维修动作、回流重测、超次数报废"的代码；解释为什么换料后不能改旧的追溯记录，只能追加。

一句话定义 ​

返修是把被锁定的不良板修好并重新送回流程的整个过程：维修员处理缺陷（补焊、换件、清洗等），品质复检，板子回到指定的工序重新过站；修不好或修太多次就报废。全过程要记录，板的追溯信息必须保持连续。

先修知识 ​

  • 不良品拦截与锁定：DefectRecord（不良记录）、HoldRecord（锁定单）、Unit 的 Hold 状态，本篇的实验直接调用上一篇 LabHold 里的方法。
  • 过站与工序流转：CurrentStepNo 的含义，以及"Fail 的那一站不算完成，放行后下一道自然还是它"。
  • 物料追溯与批次关联：UnitMaterial，换料后要往里追加。
  • SMT与电子组装流程：知道回流焊、AOI、手工补焊这些工序。

它解决什么问题 ​

现场的三个故事：

  1. 修了没人知道：一块板 AOI 判虚焊，维修员补焊后直接放回线上。系统里只有一条 Fail 和一条后来的 Pass，客户退货时没人能说清"补焊的是哪个点、用的什么烙铁温度、有没有换件"。
  2. 换了料，追溯断了：U1（MCU）烧坏换了新的，新芯片是另一个批次。系统里这块板的 MCU 批次还是出厂时的旧批次。后来旧批次被召回，这块板被误判为受影响；新批次出问题时，这块板又漏掉了。
  3. 一块板反复修：同一块板被修了五次，焊盘已经起翘铜皮，修好的板可靠性存疑，却照样出货。没有"返修次数上限"，没人拦。

返修管理就是用系统回答：谁、修了哪个位号、因为什么、做了什么、换了哪批料；修了几次；修完回了哪一站；超了怎么办。

核心概念 ​

返工与维修的区别 ​

在 IPC 的体系里（IPC-7711/7721 是电子组件返工、改装与维修的标准，目录见延伸阅读），这几个词是有区分的。据我查到的解释（来自标准的相关解读，非原文）：

术语含义例子结果
返工（Rework）用原来规定的工艺，把不合格品重新加工到完全符合要求SPI 判锡膏桥连：清洗后重新印刷；元件偏位：热风重新焊完全符合规格
维修（Repair）把有缺陷的东西恢复到可用，但不一定完全回到原设计状态焊盘脱落后飞线、断线用跳线连接能用，可能有外观偏差或使用限制
改装（Modification）主动修改合格品以满足新的要求，要有授权和文件ECN 要求加一颗电容符合新规格，见 变更管理ECN-ECR

工厂里口头常常混用"返修"，但区分有意义：返工是回到标准流程，一般可以放行到正常客户；维修可能需要客户特采、标记，甚至降级。MES 的数据模型要能区分它们：本篇用同一张表 RepairRecord 记所有动作，靠 Action（补焊 / 更换 / 清洗 / 回流到某站）区分；真实系统常常再加一个"处置类型"字段。

返修站与返修流程 ​

返修站（Rework Station）是专门的工位：有烙铁、热风枪、BGA 返修台、显微镜、ESD 防护。不良板不在原工位修，原因：不干扰产线节拍；有资质的人、专用设备；便于记录。

回流位置：修完回到哪一站 ​

修完不是随便放回线上，要回到能验证修复结果的那一站重新过站。两种常见情况：

情况回流位置CurrentStepNo
手工补焊、换件（返修站做的）回到发现不良的那一站（比如 AOI）重测不用动：Fail 的站不算完成，下一道自然还是它
返工：要重做一段标准工艺（SPI 判桥连，清洗后重新印刷）回到更早的站（PRINT）往回拨到那一站的前一个序号

第二种是回退，会让 CurrentStepNo 变小，打破了"序号只增不减"的常规，所以要格外小心：必须是品质复检之后，在锁定状态（Hold）下用条件 UPDATE 拨回，并且要留痕。本篇的做法是追加一条 RepairRecord（动作写成"回流到 PRINT(10) 重新过站"）。

返修次数限制 ​

每次返修都对板有损伤：反复加热让焊盘起翘、基材分层、元件受热劣化。所以很多工厂规定同一块板最多返修 N 次（也可能按位置限制，如同一个位号最多换 2 次），超了直接报废。N 取多少由工艺文件和客户要求定，本篇实验设成 2 次。

次数怎么数：一条 DefectRecord 对应一次返修循环（一次检验发现的不良 → 修 → 复检）。一次循环里可以有多个维修动作（多条 RepairRecord）。所以"已返修次数"= 这块板上 Status = 'Repaired' 的 DefectRecord 数量。

报废 ​

报废的原因：超过返修次数上限；缺陷无法修复（基板烧焦、焊盘脱落无法飞线）；客户规定此类缺陷不可返修。报废是终态：Unit.Status = 'Scrapped'，不良记录 Scrapped，未解除的锁定单要关闭（否则会留下永远未解除的锁定单，污染"当前锁定列表"）。实验里用 ReleasedBy = 'SCRAP' 标记这类关闭，真实系统应有独立的处置字段。报废后的物料处理、成本核算见 不合格品控制NCR、质量成本与KPI。

返修后的追溯保持 ​

维修会改变这块板"实际有什么":

维修动作对追溯的影响怎么记
补焊、清洗板上的料没变只记 RepairRecord
更换元件该位号的批次变了RepairRecord + 追加一行 UnitMaterial（StationCode = 'REPAIR-01'，SlotNo = 'REPAIR'，同一位号，新批次）
回流参数需要重新记录再次过炉会产生新的炉温记录

关键原则：追加，不改旧行。这样：

  • 反向追溯这块板：同一个位号取最新的一行（Id 最大），就是现在板上的料；
  • 正向追溯旧批次：仍然能找到这块板，可以通过"同位号有更晚的一行"判断它已经被更换，不会漏掉；是否真的需要隔离取决于被拆下的旧料是否带来了其它风险；
  • 正向追溯新批次：也能找到这块板。

位号是范围（R1-R12）的料，换了其中一个电阻就很难精确记录，这时 RefDes 应该记单个位号，并配合展开；实验里换的是 U1，位号是单个的。

实体 RepairRecord ​

RepairRecord 是只追加的维修动作流水：哪块板、对应哪条不良、位号、原因、做了什么、换了什么料、谁、何时。ReplacedMaterial 和 ReplacedLot 记的是换上去的新料；被拆下的旧料可以从同位号更早的 UnitMaterial 推出。

业务视角 ​

角色在返修里做什么
维修员在返修站处理被锁定的不良板，按规范操作，记录位号、原因、动作、换的料
品质复检；决定放行、回流位置、报废；批准超过次数的特殊放行
线长/生产看返修板数量和积压；返修板不得混入正常流
工艺工程师看维修记录里的原因分布，改善源头工艺（见 8D与CAPA）
物料员维修领用的物料也要扫码，维修换料要有批次

典型流程：不良被锁 → 送返修站（不良记录从 Open 到 Repairing）→ 维修员记录动作 → 修完后品质复检（不良变 Repaired）→ 解锁 → 板回到指定站重新过站 → 重测 Pass 后继续或完工；超限则报废。

KPI：返修率（进返修站的板占比）、一次修复率、各不良代码/位号的返修占比、返修平均时长、报废率、返修后二次不良率（修好之后又在后续工序判 Fail 的比例，说明修得不彻底）。

技术视角 ​

表设计 ​

sql
CREATE TABLE RepairRecord (
    Id               int IDENTITY(1,1) NOT NULL CONSTRAINT PK_RepairRecord PRIMARY KEY,
    SerialNo         nvarchar(40)  NOT NULL,
    DefectId         int           NOT NULL,   -- 对应哪条 DefectRecord
    RefDes           nvarchar(20)  NULL,       -- 位号；整板动作（清洗、回流）可为空
    Cause            nvarchar(100) NOT NULL,
    Action           nvarchar(100) NOT NULL,
    ReplacedMaterial nvarchar(50)  NULL,       -- 换上去的新料
    ReplacedLot      nvarchar(40)  NULL,
    RepairedBy       nvarchar(30)  NOT NULL,
    RepairedAt       datetime      NOT NULL CONSTRAINT DF_Repair_At DEFAULT GETDATE()
);
CREATE INDEX IX_RepairRecord_Sn     ON RepairRecord(SerialNo);
CREATE INDEX IX_RepairRecord_Defect ON RepairRecord(DefectId);

设计点：

  1. 板码、物料批次的类型和 Unit、UnitMaterial 统一；
  2. 不良与维修一对多：DefectId 外键（实验里没有建外键约束，保持和前面几篇一致，真实系统建议加）；
  3. 只追加：和 TrackRecord 一样，用权限或触发器限制修改（见 过站与工序流转）；
  4. RefDes 允许为空：清洗、回流这类整板动作没有位号。

状态机与条件更新 ​

DefectRecord 的状态流转：Open → Repairing → Repaired，或 Open → Scrapped。每一步都是条件 UPDATE：

sql
UPDATE DefectRecord SET Status = N'Repairing' WHERE Id = @id AND Status = N'Open';   -- 受影响行数必须是 1

两个维修员同时点"开始返修"同一条不良，只有一个能得到 1 行。

一个事务：开始返修的两种结果 ​

次数 = SELECT COUNT(*) FROM DefectRecord WHERE SerialNo = @sn AND Status = N'Repaired'
IF 次数 >= 上限:  -- 报废
    BEGIN TRAN
      UPDATE DefectRecord SET Status = N'Scrapped' WHERE Id = @id AND Status = N'Open'
      UPDATE Unit SET Status = N'Scrapped' WHERE SerialNo = @sn AND Status = N'Hold'
      UPDATE HoldRecord SET ReleasedBy = N'SCRAP', ReleasedAt = GETDATE() WHERE ... AND ReleasedAt IS NULL
    COMMIT
ELSE:             -- 开始返修
    UPDATE DefectRecord SET Status = N'Repairing' WHERE Id = @id AND Status = N'Open'

记维修动作 + 换料追溯 ​

一个事务里：插入 RepairRecord；如果换了料，同时插入一行 UnitMaterial。两个都成功或都失败，否则会出现"记录说换了但追溯里没有"的矛盾。

回流时往回拨序号 ​

sql
UPDATE Unit SET CurrentStepNo = @target WHERE SerialNo = @sn AND Status = N'Hold';   -- 只在锁定状态下拨

其中 @target 是回流站的前一个序号（0 表示从头开始）。随后品质复检解锁，板回到 InProcess，下一道自然就是回流站。拨回的操作要留痕。

追溯查询：换料后现在是什么料 ​

sql
-- 同一位号取最新的一行，就是板上现在的料
SELECT * FROM (
    SELECT m.*, ROW_NUMBER() OVER (PARTITION BY m.RefDes ORDER BY m.Id DESC) AS rn
    FROM UnitMaterial m WHERE m.SerialNo = @sn
) x WHERE rn = 1;

-- 正向追溯旧批次时，标出"已被更换"
SELECT m.SerialNo,
       CASE WHEN EXISTS (SELECT 1 FROM UnitMaterial n WHERE n.SerialNo = m.SerialNo AND n.RefDes = m.RefDes AND n.Id > m.Id)
            THEN N'已被更换' ELSE N'在板上' END AS State
FROM UnitMaterial m WHERE m.LotNo = @lot;

逐步例子：三块板的三种结局 ​

RP-0001（维修，换件）：已走到序号 40（回流），AOI 判 Fail（U1 虚焊，SOLDER_OPEN）。自动锁定。维修员 RW01 开始第 1 次返修；检查发现芯片过热损坏，更换 U1，换上 IC-MCU-32 的批次 LOT-U-555；品质复检，不良变 Repaired，解锁；回流位置是 AOI，不用往回拨（序号还是 40），AOI 重测 Pass。履历里 AOI 有 Fail 和 Pass 两条。追溯：UnitMaterial 里 U1 有两行：贴片时的 LOT-RP-U1，维修的 LOT-U-555。查 LOT-RP-U1 正向追溯，这块板在列表里，标"已被更换"；查 LOT-U-555，标"在板上"。

RP-0002（返工，回退）：序号 10，SPI 判 Fail（锡膏桥连 PASTE_BRIDGE）。这种问题不该"补焊"，而是清洗后重印：维修员做超声清洗；品质复检；回流位置是 PRINT，所以序号从 10 拨回 0；追加一条记录"回流到 PRINT(10) 重新过站"。随后 PRINT、SPI、MOUNT、REFLOW、AOI 依次 Pass 完工。履历：20 SPI Fail / 10 PRINT Pass / 20 SPI Pass / ...。

RP-0003（超限，报废）：AOI 反复判 Fail。第 1 次：开始第 1 次返修，修好，放行；再 Fail：开始第 2 次返修；第三次 Fail：已返修 2 次，达上限，判报废。不良记录依次 Repaired / Repaired / Scrapped，板 Scrapped，没有未解除的锁定单，再想进站被拒绝（"板状态是 Scrapped"）。

动手实验：维修换料、返工回退、超次数报废 ​

第 2 步：新建 LabRepair.cs（它调用 LabHold 里的 Advance、TryEnter、ReleaseUnit、NewBoard、Steps）：

csharp
using SqlSugar;

namespace MiniMes;

// 返修与维修实验：不良板 -> 开始返修 -> 记维修动作 -> 回到指定站重测 -> 超次数报废；换料后追溯保持
// 过站、锁定、解锁的函数直接用上一篇 LabHold 里的（Advance、HoldUnit、ReleaseUnit 等）
public static class LabRepair
{
    const int MaxRepair = 2;        // 同一块板最多返修 2 次，第 3 次不良直接报废

    public class ReplaceRow { public string SerialNo { get; set; } public string State { get; set; } }

    // 开始返修：Open -> Repairing（条件 UPDATE）。已返修次数达到上限则改为报废，并关掉锁定单
    static string StartRepair(SqlSugarClient db, int defectId, string by)
    {
        var d = db.Queryable<DefectRecord>().InSingle(defectId);
        string sn = d.SerialNo;
        int done = db.Queryable<DefectRecord>().Count(x => x.SerialNo == sn && x.Status == "Repaired");
        if (done >= MaxRepair)
        {
            var now = DateTime.Now;
            db.Ado.BeginTran();
            try
            {
                int a = db.Updateable<DefectRecord>().SetColumns(x => new DefectRecord { Status = "Scrapped" }).Where(x => x.Id == defectId && x.Status == "Open").ExecuteCommand();
                int b = db.Updateable<Unit>().SetColumns(x => new Unit { Status = "Scrapped" }).Where(x => x.SerialNo == sn && x.Status == "Hold").ExecuteCommand();
                db.Updateable<HoldRecord>().SetColumns(x => new HoldRecord { ReleasedBy = "SCRAP", ReleasedAt = now })
                    .Where(x => x.TargetType == "Unit" && x.TargetKey == sn && x.ReleasedAt == null).ExecuteCommand();
                if (a != 1 || b != 1) { db.Ado.RollbackTran(); return "失败（状态已变）"; }
                db.Ado.CommitTran();
            }
            catch { db.Ado.RollbackTran(); throw; }
            return $"已返修 {done} 次，达到上限 {MaxRepair}，判报废";
        }
        int n = db.Updateable<DefectRecord>().SetColumns(x => new DefectRecord { Status = "Repairing" }).Where(x => x.Id == defectId && x.Status == "Open").ExecuteCommand();
        return n == 1 ? $"开始第 {done + 1} 次返修" : "失败（这条不良不是 Open）";
    }

    // 记一个维修动作；换了料就同时给这块板追加一行 UnitMaterial（旧的那行不删，追溯链不断）
    static void AddRepair(SqlSugarClient db, int defectId, string refDes, string cause, string action, string newMaterial, string newLot, string by)
    {
        var d = db.Queryable<DefectRecord>().InSingle(defectId);
        if (d.Status != "Repairing") throw new InvalidOperationException("这条不良不在返修中");
        db.Ado.BeginTran();
        try
        {
            db.Insertable(new RepairRecord
            {
                SerialNo = d.SerialNo, DefectId = defectId, RefDes = refDes, Cause = cause, Action = action,
                ReplacedMaterial = newMaterial, ReplacedLot = newLot, RepairedBy = by, RepairedAt = DateTime.Now,
            }).ExecuteCommand();
            if (newLot != null)
                db.Insertable(new UnitMaterial { SerialNo = d.SerialNo, StepNo = d.StepNo, StationCode = "REPAIR-01", SlotNo = "REPAIR", RefDes = refDes, MaterialCode = newMaterial, LotNo = newLot }).ExecuteCommand();
            db.Ado.CommitTran();
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    // 修完：不良 Repairing -> Repaired；指定回流到哪一站；品质复检后解锁
    // returnStepCode 比不良发现的那一站更靠前时，要把板的 CurrentStepNo 往回拨，并追加一条 RepairRecord 留痕
    static string FinishRepair(SqlSugarClient db, int defectId, string returnStepCode, string by)
    {
        var d = db.Queryable<DefectRecord>().InSingle(defectId);
        string sn = d.SerialNo;
        int n = db.Updateable<DefectRecord>().SetColumns(x => new DefectRecord { Status = "Repaired" }).Where(x => x.Id == defectId && x.Status == "Repairing").ExecuteCommand();
        if (n != 1) return "失败（这条不良不在返修中）";
        var steps = LabHold.Steps(db);
        var back = steps.First(s => s.StepCode == returnStepCode);
        int target = steps.Where(s => s.StepNo < back.StepNo).Select(s => s.StepNo).DefaultIfEmpty(0).Max();
        var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
        if (target < u.CurrentStepNo)
        {
            db.Updateable<Unit>().SetColumns(x => new Unit { CurrentStepNo = target }).Where(x => x.SerialNo == sn && x.Status == "Hold").ExecuteCommand();
            db.Insertable(new RepairRecord { SerialNo = sn, DefectId = defectId, Cause = "返工", Action = $"回流到 {returnStepCode}({back.StepNo}) 重新过站", RepairedBy = by, RepairedAt = DateTime.Now }).ExecuteCommand();
        }
        var r = LabHold.ReleaseUnit(db, sn, "QA01");
        return r.Ok ? $"修复完成，回流到 {returnStepCode} 重测" : $"失败（{r.Msg}）";
    }

    static string History(SqlSugarClient db, string sn) =>
        string.Join(" / ", db.Queryable<TrackRecord>().Where(r => r.SerialNo == sn).OrderBy(r => r.Id).ToList().Select(r => $"{r.StepNo} {r.StepCode} {r.Result}"));

    static int Defect(SqlSugarClient db, string sn, int index) => db.Queryable<DefectRecord>().Where(d => d.SerialNo == sn).OrderBy(d => d.Id).ToList()[index].Id;

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(UnitMaterial), typeof(DefectRecord), typeof(HoldRecord), typeof(RepairRecord));
        db.Deleteable<RepairRecord>().Where(r => r.SerialNo.StartsWith("RP-")).ExecuteCommand();
        db.Deleteable<HoldRecord>().Where(h => h.TargetKey.StartsWith("RP-")).ExecuteCommand();
        db.Ado.ExecuteCommand(@"
IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'UX_HoldRecord_Open')
    CREATE UNIQUE INDEX UX_HoldRecord_Open ON HoldRecord(TargetType, TargetKey) WHERE ReleasedAt IS NULL;");
        db.Deleteable<DefectRecord>().Where(d => d.SerialNo.StartsWith("RP-")).ExecuteCommand();
        db.Deleteable<UnitMaterial>().Where(m => m.SerialNo.StartsWith("RP-")).ExecuteCommand();
        db.Deleteable<TrackRecord>().Where(r => r.SerialNo.StartsWith("RP-")).ExecuteCommand();
        db.Deleteable<Unit>().Where(u => u.SerialNo.StartsWith("RP-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo.StartsWith("WO-RP-")).ExecuteCommand();
        db.Insertable(new WorkOrder { WoNo = "WO-RP-001", ProductCode = Seed.Product, PlanQty = 100, Status = "Running", CreatedAt = DateTime.Now }).ExecuteCommand();

        // 造三块板：RP-0001 已贴片回流（MCU 用的 LOT-RP-U1），RP-0002 刚印刷完，RP-0003 已回流
        LabHold.NewBoard(db, "RP-0001", "WO-RP-001", 40, "InProcess");
        LabHold.NewBoard(db, "RP-0002", "WO-RP-001", 10, "InProcess");
        LabHold.NewBoard(db, "RP-0003", "WO-RP-001", 40, "InProcess");
        db.Insertable(new UnitMaterial { SerialNo = "RP-0001", StepNo = 30, StationCode = "SMT-01", SlotNo = "S03", RefDes = "U1", MaterialCode = "IC-MCU-32", LotNo = "LOT-RP-U1" }).ExecuteCommand();

        // 1. 维修：RP-0001 在 AOI 判 Fail，MCU 引脚虚焊且芯片损坏，更换后回 AOI 重测
        Console.WriteLine("1. 维修（Repair）：RP-0001 在 AOI 判 Fail，U1 引脚虚焊");
        Console.WriteLine($"   {LabHold.Advance(db, "RP-0001", "AOI", "Fail", "SOLDER_OPEN")}");
        int d1 = Defect(db, "RP-0001", 0);
        Console.WriteLine($"   {StartRepair(db, d1, "RW01")}");
        AddRepair(db, d1, "U1", "引脚虚焊，芯片过热损坏", "更换芯片", "IC-MCU-32", "LOT-U-555", "RW01");
        Console.WriteLine($"   {FinishRepair(db, d1, "AOI", "RW01")}；板状态 {db.Queryable<Unit>().First(x => x.SerialNo == "RP-0001").Status}，当前工序 {db.Queryable<Unit>().First(x => x.SerialNo == "RP-0001").CurrentStepNo}（不用往回拨，下一道就是 AOI）");
        Console.WriteLine($"   AOI 重测 -> {LabHold.Advance(db, "RP-0001", "AOI")}");
        Console.WriteLine($"   履历：{History(db, "RP-0001")}");
        var repairs = db.Queryable<RepairRecord>().Where(r => r.SerialNo == "RP-0001").ToList();
        Console.WriteLine($"   维修记录 {repairs.Count} 条：位号 {repairs[0].RefDes}，{repairs[0].Action}，新料 {repairs[0].ReplacedMaterial}/{repairs[0].ReplacedLot}，维修人 {repairs[0].RepairedBy}");

        // 2. 追溯保持：旧批次的追溯链还在，且标出"已被更换"
        Console.WriteLine("2. 换料后的追溯：");
        foreach (var m in db.Queryable<UnitMaterial>().Where(m => m.SerialNo == "RP-0001").OrderBy(m => m.Id).ToList())
            Console.WriteLine($"   {m.StationCode,-9} {m.RefDes} {m.MaterialCode} {m.LotNo}");
        foreach (var lot in new[] { "LOT-RP-U1", "LOT-U-555" })
        {
            var rows = db.Ado.SqlQuery<ReplaceRow>(@"
SELECT m.SerialNo,
       CASE WHEN EXISTS (SELECT 1 FROM UnitMaterial n WHERE n.SerialNo = m.SerialNo AND n.RefDes = m.RefDes AND n.Id > m.Id)
            THEN N'已被更换' ELSE N'在板上' END AS State
FROM UnitMaterial m WHERE m.LotNo = @lot AND m.SerialNo LIKE 'RP-%'", new { lot });
            Console.WriteLine($"   正向追溯 {lot} -> {string.Join(", ", rows.Select(r => $"{r.SerialNo}（{r.State}）"))}");
        }

        // 3. 返工（Rework）：RP-0002 在 SPI 判 Fail（锡膏桥连），清洗后回到 PRINT 重做
        Console.WriteLine("3. 返工（Rework）：RP-0002 在 SPI 判 Fail（PASTE_BRIDGE），清洗后回到 PRINT");
        Console.WriteLine($"   {LabHold.Advance(db, "RP-0002", "SPI", "Fail", "PASTE_BRIDGE")}");
        int d2 = Defect(db, "RP-0002", 0);
        StartRepair(db, d2, "RW01");
        AddRepair(db, d2, null, "锡膏桥连", "超声清洗", null, null, "RW01");
        Console.WriteLine($"   {FinishRepair(db, d2, "PRINT", "RW01")}；当前工序被拨回 {db.Queryable<Unit>().First(x => x.SerialNo == "RP-0002").CurrentStepNo}");
        foreach (var code in new[] { "PRINT", "SPI", "MOUNT", "REFLOW", "AOI" }) LabHold.Advance(db, "RP-0002", code);
        Console.WriteLine($"   履历：{History(db, "RP-0002")}");
        Console.WriteLine($"   板状态 {db.Queryable<Unit>().First(x => x.SerialNo == "RP-0002").Status}；维修记录：{string.Join(" / ", db.Queryable<RepairRecord>().Where(r => r.SerialNo == "RP-0002").OrderBy(r => r.Id).ToList().Select(r => r.Action))}");

        // 4. 返修次数上限：RP-0003 在 AOI 反复判 Fail，第 3 次直接报废
        Console.WriteLine($"4. 返修次数上限（{MaxRepair} 次）：RP-0003 在 AOI 连续判 Fail");
        for (int i = 0; i < 3; i++)
        {
            LabHold.Advance(db, "RP-0003", "AOI", "Fail", "SOLDER_OPEN");
            int d = Defect(db, "RP-0003", i);
            string msg = StartRepair(db, d, "RW01");
            Console.WriteLine($"   第 {i + 1} 次不良 -> {msg}");
            if (db.Queryable<DefectRecord>().InSingle(d).Status == "Repairing")
            {
                AddRepair(db, d, "U1", "虚焊", "补焊", null, null, "RW01");
                FinishRepair(db, d, "AOI", "RW01");
            }
        }
        var u3 = db.Queryable<Unit>().First(x => x.SerialNo == "RP-0003");
        Console.WriteLine($"   板状态 {u3.Status}；不良记录状态：{string.Join(" / ", db.Queryable<DefectRecord>().Where(d => d.SerialNo == "RP-0003").OrderBy(d => d.Id).ToList().Select(d => d.Status))}");
        Console.WriteLine($"   报废后想进 AOI -> {LabHold.TryEnter(db, "RP-0003", "AOI")}；未解除的锁定单 {db.Queryable<HoldRecord>().Count(h => h.TargetKey == "RP-0003" && h.ReleasedAt == null)} 张");
    }
}

动手改（下面两条我都实际改过、运行过）：

常见坑与排查 ​

误区 / 坑事实与办法
维修后直接放回线上，没有复检维修员自己判自己，风险大。解锁要品质复检，并留痕
换件后不更新追溯旧批次召回会误判、新批次召回会漏掉。追加 UnitMaterial
修改旧的 UnitMaterial历史被改，旧批次的追溯链断了。只追加
回流位置总是"回到发现的站"对返工（清洗重印）是错的。回流位置由维修动作决定，必要时往回拨
往回拨序号没有留痕履历里看不出为什么序号倒退。追加一条记录
没有返修次数上限一块板反复修，可靠性存疑。设上限并强制
报废后锁定单没关当前锁定列表里永远有它。关闭并标明报废
返修的板和正常板混放靠系统的 Hold 状态强制，不靠现场摆放
位号是范围 R1-R12，换了一个电阻不知怎么记记单个位号；或接受只到"这个料号"的粒度
返工和维修不分影响放行规则与客户特采，数据模型里要能区分处置类型

练习题与答案 ​

  1. 返工（Rework）和维修（Repair）的区别？ 答：返工用原规定的工艺把不合格品重新加工到完全符合要求；维修把缺陷恢复到可用，但不一定完全回到原设计状态，可能有外观偏差或限制（据标准解读，以 IPC 原文为准）。
  2. 为什么 SPI 判桥连要回流到 PRINT，AOI 判虚焊补焊后只回 AOI？ 答：桥连的原因在锡膏印刷，清洗后必须重印；虚焊是局部焊点问题，补焊后重新检验即可。回流位置要能验证修复结果。
  3. 回流到更早的站时，CurrentStepNo 怎么改？为什么要在 Hold 状态下改？ 答：设为回流站的前一个序号（0 表示从头）。在 Hold 下改，是因为这时板不会被正常过站推进，也防止与其它终端的并发冲突；条件 UPDATE ... AND Status = 'Hold' 保证这一点。
  4. 实验里返修次数是怎么数的？一次检验发现两个位号都不良，算几次？ 答：数 Status = 'Repaired' 的 DefectRecord。一次检验发现的多个位号合并成一条不良记录，下面可以有多条维修动作，算一次返修。
  5. 换了 U1 之后，为什么不改旧的 UnitMaterial 行？ 答：旧行是贴片时的事实，改了追溯链就断了；追加新行后，同位号最新的一行是现状，旧批次仍能追溯到这块板，并标注已更换。
  6. 板达到返修上限报废时，为什么要关闭它的锁定单？ 答：不关的话，"当前锁定中"列表里永远有一张已报废板的单，干扰统计。用独立的标记（如 ReleasedBy = 'SCRAP'）区分正常解锁。
  7. 两个维修员同时点同一条不良的"开始返修"，会怎样？ 答：条件 UPDATE ... WHERE Status = 'Open' 只有一个得到 1 行，另一个得到 0 行，提示"这条不良不是 Open"。
  8. 怎么查一块板现在 U1 用的是哪个批次？ 答：同一位号取 Id 最大的一行（ROW_NUMBER() OVER (PARTITION BY RefDes ORDER BY Id DESC) 取第 1 行）。
  9. 返修率很高，应该关注哪些指标？ 答：各不良代码和位号的返修占比、一次修复率、返修后二次不良率；帕累托找最大的几项，往源头工艺改善。
  10. 为什么返修站要单独设置，而不是在 AOI 旁边直接修？ 答：不影响产线节拍；需要有资质的人员和专用设备；便于记录和管控，避免不良品混流。

小结 ​

  • 返工（回到标准工艺重做）和维修（恢复可用）有区别；返修是"锁定 → 维修 → 复检解锁 → 回流重测"的闭环，或次数超限后报废。
  • RepairRecord 记每个维修动作；一条 DefectRecord 对应一次返修循环，已返修次数 = Repaired 的不良数。
  • 回流位置取决于能验证修复的那一站，返工要把 CurrentStepNo 往回拨，并留痕。
  • 换料后追加 UnitMaterial，不改旧行：旧批次仍能追溯到这块板且标"已更换"，新批次也能追到。
  • 报废是终态，要关闭锁定单；所有状态变化都是条件 UPDATE，事务内完成。
