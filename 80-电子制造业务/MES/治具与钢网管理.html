治具与钢网管理

AI 生成 · 待核对制造业务MESSMT钢网治具防错更新于 2026-10-21

⚠ 待核对：钢网、治具、探针的管理项（厚度、开孔、张力、清洗周期、寿命）和"领用-计数-清洗-归还-报废"的流程是电子厂通用做法。具体的厚度、张力、寿命次数、清洗间隔都由钢网厂商规格、工艺规范和你们公司标准决定，本篇实验里的 500 次、每 200 次清洗只是为了几步就能演示完的示例数字，不是行业标准值；IPC-7525（钢网设计指南，现行版本是 IPC-7525C，2021 年 11 月）只确认了名称和用途，没有逐条核对其数值要求。你们自研系统用一张表还是多张表管工装、计数在印刷机上还是 MES 里累加，请对照你们的系统。代码与输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 10 篇，对应 过站与工序流转 进站检查清单的第 8 项"治具、钢网在寿命内"。读完你应该能：说清钢网、治具、载具、测试探针各是什么、为什么要管寿命；设计工装台账 Tooling 与使用流水 ToolingUsage；画出工装的状态机；写出"计数 + 超寿命拦截 + 清洗周期"一条 UPDATE 搞定的 SQL；理解为什么两条线同时领用同一个钢网只能有一个成功；并亲手跑通整个流程。

一句话定义 ​

工装（Tooling）是生产中反复使用、会磨损的辅助器具：钢网、治具、载具、测试探针等。工装管理就是给每个工装一个编号，记录它"谁在用、用了多少次、什么时候该清洗、什么时候必须停用"，超过寿命就在系统里拦下，不让它继续生产。

先修知识 ​

  • SMT与电子组装流程：知道锡膏印刷用钢网、贴片后过回流焊。
  • 过站与工序流转：知道进站检查清单、条件 UPDATE。
  • SMT上料防错与站位表：本篇用同一套"扫码 → 比对 → 记录"的思路，只是对象从物料换成工装。
  • 会读简单的 UPDATE ... WHERE。

它解决什么问题 ​

先看没有工装管理的车间：

  • 钢网用到变形：钢网每印一次，刮刀就刮一次，开孔边缘会磨损，框上的张力会下降。用得太久，锡膏量不稳、印偏，表现为少锡、连锡、桥接，却没人想到是钢网的问题。因为没有人记得这张钢网印了多少次。
  • 钢网不清洗：开孔里残留的锡膏变干、堵孔，后面印出来的板子锡量越来越少。擦网靠人"感觉该擦了"。
  • 同一张钢网被两条线同时领走：仓库账上只有一张，两条线的人都说"我领了"，其中一条线最后发现钢网在别人手里，白白等了半小时。
  • 测试治具探针磨损：ICT/FCT 测试的探针（Pogo pin）接触次数有限，用到寿命后接触电阻变大，开始误判不良。良品被判成不良、返修线爆满，查了半天才发现是探针。
  • 治具找不到、不知道谁借走：夹具、过炉载具（Pallet）散落各处，库存数对不上。
  • 该报废的没人报废：寿命早就到了，只是还能用，一直拖着。

工装管理把这些变成：有编号、有台账、有状态、有计数、到点拦截。

核心概念 ​

常见工装 ​

工装作用要管什么
钢网 Stencil锡膏印刷时盖在 PCB 上，开孔处漏下锡膏。一款产品、一个面一张厚度、开孔、张力、使用次数/寿命、清洗周期、储存位置、报废
治具/夹具 Fixture固定板子，用于印刷、贴片、插件、焊接、测试使用次数、保养周期、归属产品
载具 Pallet过回流焊/波峰焊时托住板子（尤其是薄板、柔性板）使用次数、变形检查、过炉次数（受热老化）
测试探针 ProbeICT/FCT 针床上的探针，接触板子上的测试点接触次数/寿命，到寿命要换针

钢网的几个参数（只做认识，数值以厂商和公司规范为准）：

  • 厚度：决定锡膏量。不同元件对锡量要求不同，所以钢网厚度要兼顾最小的元件（如细间距 IC）和最大的元件，有时会用局部加厚/减薄的阶梯钢网（Step Stencil）。
  • 开孔（Aperture）：开孔的形状和尺寸，通常相对焊盘做一些缩放。开孔的面积比（开孔面积与孔壁面积的比）影响锡膏能不能顺利脱模，经验上有一个常被引用的下限，这个数值我没有联网核实，标待核对。IPC-7525 就是专门讲钢网设计和制造的指南。
  • 张力：钢网绷在网框上，需要一定张力才能保持平整。张力随使用逐步下降，需要定期测量。
  • 材质与处理：常见不锈钢激光切割，孔壁可电抛光、可加涂层以利脱模。

这些参数是钢网的属性（主数据），进台账时登记；本篇实验关注的是使用过程（次数、状态），不再细抠工艺参数。

状态机 ​

工装的状态：

状态含义能不能用于生产
InStock 在库放在钢网架/治具架上，可领用否（要先领用）
InUse 使用中被某条线领用，正在生产是
Cleaning 待清洗用到清洗周期，必须清洗后才能继续否
Maintenance 待评估/维修到寿命上限，需要评估：报废，还是换针/大修后重新使用否
Scrapped 报废终态否

几点说明：InStock 的工装如果发现问题（外观损坏）也可以直接报废；到寿命后工装自动下线（线体字段清空），不是等人手动归还，避免"明知到寿命还继续用"。

计数：用一次加一次 ​

使用次数是工装管理的核心数据。要点：

  • 按"一次使用"计，不是按板数。钢网一次印刷印一个拼板（Panel，见 条码与板码规则）：一个拼板有 4 块小板，印一次钢网计 1 次，不是 4 次。探针按"一次接触测试"计，一个拼板如果一次测完整块，也只算 1 次。
  • 自动累加，不要靠人工抄。常见做法有两种：
    1. 在过站里累加：印刷站出站时，除了推进板子，再给当前线体领用的钢网 UseCount + 1（和 过站与工序流转 的出站事务放在一起，见"技术视角"）；
    2. 接设备计数：印刷机、测试机自己有计数器，通过 SMT设备接口 定期上报，MES 累加。设备计数更准，但要处理断线补报。
  • 必须原子：计数要和"检查寿命"在同一条 SQL 里，否则两个终端同时计数，可能都通过检查而超过上限。

清洗周期 ​

钢网需要两种清洗：

  • 印刷机自动擦网（每印若干片擦一次底面），属于工艺参数，由印刷机程序控制；
  • 下线清洗（超声或专用设备，把开孔里的残锡彻底洗掉），按使用次数或时间间隔进行。

MES 管的是第二种：台账里记 CleanEvery（每用多少次必须清洗）和 CountAtClean（上次清洗时的计数）。当 UseCount − CountAtClean 达到 CleanEvery，工装自动变 Cleaning，必须清洗后才能继续。清洗时顺便记录清洗时间 LastCleanedAt。

超寿命拦截 ​

每个工装有 MaxUseCount。计数时：

  • 如果这次计数会让总数超过上限（现在 400，想一次加 150）→ 拒绝；
  • 如果计数后恰好等于上限 → 允许，同时状态自动变 Maintenance、线体清空，下次不能再计数、不能再被领用。

这样"到寿命"这件事由数据库在同一条 UPDATE 里完成，不会有人在最后一次之后"再偷偷用一次"。

业务视角 ​

谁在什么环节做什么：

角色动作
工艺/SMT 工程师提出制作钢网（随新产品导入）；定义寿命、清洗周期；评估到寿命的工装是报废还是继续
钢网/治具管理员入库登记、编号；发放、回收；清洗；储存管理；报废处理
印刷机操作员换线时领用钢网并扫码；生产中系统自动计数；被提示清洗时送洗
测试工程师管理测试治具和探针，到寿命换针
线长处理超寿命、待清洗的拦截

钢网的一生：

  1. 制作：工程师下单，钢网到货，入库登记（编号、厚度、开孔、张力、寿命、归属产品）。
  2. 领用：换线时，在印刷机上扫钢网上的码，系统检查"在库、没到寿命、不需要清洗"，通过后变 InUse、记录线体。
  3. 生产：每印一次计数；到清洗周期自动提示。
  4. 清洗：送洗，清洗后记录。
  5. 归还：生产结束，清洗（很多厂规定每次下线都洗）后放回钢网架，变 InStock。
  6. 到寿命：自动下线，评估后报废；报废的钢网要物理销毁或做标记，防止被误用。

储存：钢网要放在专用架上，按编号定位（库位）；锡膏残留、湿度、碰撞都会影响寿命。台账里可以加库位字段；本篇不展开。

保养：治具、载具按使用次数或时间定期保养（检查变形、磨损、螺丝）；保养到期同样可以让状态变 Maintenance。保养计划和设备保养有共通之处，见 设备管理与设备状态、设备保养与TPM。

KPI：

  • 钢网平均使用寿命（实际印了多少次才报废）；
  • 超寿命拦截次数（应当越来越少，说明提前预警有效）；
  • 清洗合规率（到周期有没有按时清洗）；
  • 工装找不到/账实不符次数；
  • 因钢网/治具问题导致的不良（少锡、连锡、测试误判）占比。

技术视角 ​

表设计 ​

两个实体由本篇定义：

实体类别说明
Tooling主数据 + 当前状态一个工装一行：编号（唯一）、类型、状态、计数、寿命、清洗信息、被谁领用
ToolingUsage记录（只追加）每次领用、计数、清洗、归还、换针、报废各一行

回顾 MES 的原则："当前状态"用单据式的行（会变）；"发生过什么"用流水（只追加）。Tooling.UseCount 是为了查询快，ToolingUsage 的 Delta 合计是真相的来源，两者可以对账，实验最后一步就是对账。

Tooling 的字段（完整实体代码见后面的实验）：

字段含义
ToolCode工装编号，贴在钢网框/治具上的那个码，唯一索引
ToolTypeStencil / Fixture / Pallet / Probe
ProductCode专用于哪个产品（钢网通常专用，可空）
Status五个状态之一
UseCount / MaxUseCount累计使用次数 / 寿命上限
CleanEvery / CountAtClean每用多少次清洗（0 = 不需要）/ 上次清洗时的计数
LastCleanedAt上次清洗时间
CurrentLine被哪条线领用着，在库时为空

ToolingUsage 的字段：ToolCode、Action（Issue / Count / Clean / Return / Repair / Scrap）、LineCode、Delta、CountAfter、OperatorCode、At。

建议再加一个 CHECK 约束，让状态只能是五个值之一（实验里用 T-SQL 加了）：

sql
ALTER TABLE Tooling ADD CONSTRAINT CK_Tooling_Status
  CHECK (Status IN (N'InStock', N'InUse', N'Cleaning', N'Maintenance', N'Scrapped'));

每个动作是一条带条件的 UPDATE ​

这和 工单管理 的报工、过站与工序流转 的出站是同一个手法：把"检查"写进 WHERE，用受影响行数判断成败。

领用：只有"在库、没到寿命、不需要清洗"的才能领，谁先到谁拿到：

sql
UPDATE Tooling SET Status = N'InUse', CurrentLine = @line
WHERE ToolCode = @c AND Status = N'InStock' AND UseCount < MaxUseCount
  AND (CleanEvery = 0 OR UseCount - CountAtClean < CleanEvery);

两条线同时执行这条语句，数据库让它们排队：先执行的把 Status 改成 InUse，后执行的发现 Status 已经不是 InStock，更新 0 行。这就是"并发两线领同一钢网只有一个成功"的原理。

计数（含到寿命、到清洗周期的自动状态切换）：

sql
UPDATE Tooling SET UseCount = UseCount + @n,
    Status = CASE WHEN UseCount + @n >= MaxUseCount THEN N'Maintenance'
                  WHEN CleanEvery > 0 AND UseCount + @n - CountAtClean >= CleanEvery THEN N'Cleaning'
                  ELSE Status END,
    CurrentLine = CASE WHEN UseCount + @n >= MaxUseCount THEN NULL ELSE CurrentLine END
WHERE ToolCode = @c AND Status = N'InUse' AND CurrentLine = @line
  AND UseCount + @n <= MaxUseCount
  AND (CleanEvery = 0 OR UseCount + @n - CountAtClean <= CleanEvery);

读法：SET 子句里用的是更新前的 UseCount（SQL 里同一条 UPDATE 的右边表达式都用修改前的值），所以 UseCount + @n 就是"计数之后的值"。WHERE 条件保证状态是使用中、是这条线领用的、不超寿命、不超清洗周期。到寿命优先于到清洗周期（两者同时到时直接进待评估）。

清洗、归还、换针、报废同理，每条 UPDATE 的 WHERE 里写"当前必须是什么状态"：

动作允许的起始状态结果
清洗 CleanCleaningInUse，CountAtClean = UseCount，记 LastCleanedAt
归还 ReturnInUse 且是本线领用InStock，线体清空
换针/大修 RepairMaintenanceInStock，UseCount = 0，CountAtClean = 0
报废 ScrapMaintenance、InStockScrapped

每次成功动作追加一条使用流水 ​

动作成功（受影响 1 行）后，在同一个事务里追加一条 ToolingUsage。拒绝的动作不写流水（真实系统里可以另写拒绝日志）。Delta 的约定：计数为正，换针为负（把清零也记成一笔），其他动作为 0，这样任何时刻 SUM(Delta) 都应等于 UseCount，对账很简单。

与过站联动：在出站事务里加一步 ​

印刷站出站时，除了原来的三步，加上第四步（顺序固定放在最后，只对印刷工序执行）：

text
BEGIN TRAN
  1. UPDATE Unit        -- 推进位置
  2. INSERT TrackRecord -- 追加过站记录
  3. UPDATE WorkOrder   -- 仅末站 Pass
  4. UPDATE Tooling     -- 仅印刷站：当前线体领用的钢网 UseCount + 1（上面的"计数"语句）
COMMIT

第 4 步得到 0 行说明钢网状态不允许（超寿命、待清洗），整笔回滚，板子不进入下一站，并提示操作员原因。更好的做法是进站时就检查（只读检查"钢网在寿命内且不需要清洗"），出站时再计数，避免操作员印完才发现不行。这就是进站检查清单第 8 项。

热点行问题：高节拍下同一张钢网的行会被频繁更新；如果觉得是瓶颈，可以按拼板计数（本来就是按拼板），或让设备批量上报增量（一次 +50），不要每次都单条更新。

逐步例子：一张钢网的一生 ​

台账：STN-A100-T，钢网，寿命 500 次，每 200 次清洗。线体 SMT-L1 使用。

步骤动作UseCount状态说明
1SMT-L1 领用0InUse成功
2SMT-L2 想领用0InUse拒绝：已被 SMT-L1 领用
3印 150 次150InUse距离清洗还差 50
4再印 50 次200Cleaning到清洗周期，自动改状态
5想再印 1 次200Cleaning拒绝：必须先清洗
6清洗200InUseCountAtClean = 200
7印 150 次350InUse距上次清洗 150
8想一口气印 100 次350InUse拒绝：距上次清洗会到 250，超过 200
9印 50 次400Cleaning又到周期
10清洗400InUseCountAtClean = 400
11想印 150 次400InUse拒绝：400 + 150 > 500
12印 100 次500Maintenance到寿命，自动下线，线体清空
13想再印 1 次500Maintenance拒绝：状态不对
14评估后报废500Scrapped终态

这张钢网共产生 9 条使用流水：领用 1 + 计数 5 + 清洗 2 + 报废 1 = 9 条（被拒绝的动作不写流水）；5 次计数的 Delta 合计 150 + 50 + 150 + 50 + 100 = 500，等于最终的 UseCount。

csharp
using SqlSugar;

namespace MiniMes;

// 治具与钢网实验：每个动作都是"一条带条件的 UPDATE"，返回 1 行才算成功，成功后同一事务追加一条使用流水
public static class LabTooling
{
    static Tooling Get(SqlSugarClient db, string code) => db.Queryable<Tooling>().First(t => t.ToolCode == code);

    // 执行一条 UPDATE；1 行成功就追加流水，0 行就读出当前状态，给出人能看懂的拒绝原因
    static string Act(SqlSugarClient db, string code, string action, string line, int n, string sql)
    {
        db.Ado.BeginTran();
        try
        {
            var ps = new[] { new SugarParameter("@c", code), new SugarParameter("@line", line ?? (object)DBNull.Value), new SugarParameter("@n", n) };
            if (db.Ado.ExecuteCommand(sql, ps) != 1) { db.Ado.RollbackTran(); return "被拒绝（" + Why(Get(db, code), action, line, n) + "）"; }
            var t = Get(db, code);
            db.Insertable(new ToolingUsage
            {
                ToolCode = code, Action = action, LineCode = line, CountAfter = t.UseCount, OperatorCode = "OP001", At = DateTime.Now,
                Delta = action == "Count" ? n : action == "Repair" ? -n : 0,
            }).ExecuteCommand();
            db.Ado.CommitTran();
            return $"成功（UseCount {t.UseCount}，状态 {t.Status}）";
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    static string Why(Tooling t, string action, string line, int n)
    {
        if (t == null) return "工装不存在";
        if (action == "Issue" && t.Status != "InStock") return $"状态是 {t.Status}" + (t.CurrentLine == null ? "，不在库" : "，已被 " + t.CurrentLine + " 领用");
        if (action == "Issue") return "寿命已用完或已到清洗周期";
        if (action == "Count" && t.Status != "InUse") return $"状态是 {t.Status}，不能计数" + (t.Status == "Cleaning" ? "，必须先清洗" : "");
        if (action == "Count" && t.CurrentLine != line) return $"不是 {line} 领用的";
        if (action == "Count" && t.UseCount + n > t.MaxUseCount) return $"会超过寿命上限 {t.MaxUseCount}（现在 {t.UseCount}）";
        if (action == "Count") return $"距上次清洗将超过 {t.CleanEvery} 次";
        if (action == "Return") return t.Status == "InUse" ? $"不是 {line} 领用的" : $"状态是 {t.Status}，不能归还";
        return $"当前状态 {t.Status} 不允许这个动作";
    }

    static string Issue(SqlSugarClient db, string code, string line) => Act(db, code, "Issue", line, 0, @"
UPDATE Tooling SET Status = N'InUse', CurrentLine = @line
WHERE ToolCode = @c AND Status = N'InStock' AND UseCount < MaxUseCount
  AND (CleanEvery = 0 OR UseCount - CountAtClean < CleanEvery)");

    // 计数：一条 UPDATE 同时完成 检查（状态/线体/寿命/清洗周期）+ 累加 + 到线后自动改状态
    static string Count(SqlSugarClient db, string code, string line, int n) => Act(db, code, "Count", line, n, @"
UPDATE Tooling SET UseCount = UseCount + @n,
    Status = CASE WHEN UseCount + @n >= MaxUseCount THEN N'Maintenance'
                  WHEN CleanEvery > 0 AND UseCount + @n - CountAtClean >= CleanEvery THEN N'Cleaning'
                  ELSE Status END,
    CurrentLine = CASE WHEN UseCount + @n >= MaxUseCount THEN NULL ELSE CurrentLine END
WHERE ToolCode = @c AND Status = N'InUse' AND CurrentLine = @line
  AND UseCount + @n <= MaxUseCount
  AND (CleanEvery = 0 OR UseCount + @n - CountAtClean <= CleanEvery)");

    static string Clean(SqlSugarClient db, string code) => Act(db, code, "Clean", null, 0, @"
UPDATE Tooling SET Status = N'InUse', CountAtClean = UseCount, LastCleanedAt = GETDATE()
WHERE ToolCode = @c AND Status = N'Cleaning'");

    static string Return(SqlSugarClient db, string code, string line) => Act(db, code, "Return", line, 0, @"
UPDATE Tooling SET Status = N'InStock', CurrentLine = NULL
WHERE ToolCode = @c AND Status = N'InUse' AND CurrentLine = @line");

    // 换针/大修后寿命清零（流水的 Delta 记成负数，让流水合计仍然等于 UseCount）
    static string Repair(SqlSugarClient db, string code) => Act(db, code, "Repair", null, Get(db, code).UseCount, @"
UPDATE Tooling SET Status = N'InStock', UseCount = 0, CountAtClean = 0
WHERE ToolCode = @c AND Status = N'Maintenance'");

    static string Scrap(SqlSugarClient db, string code) => Act(db, code, "Scrap", null, 0, @"
UPDATE Tooling SET Status = N'Scrapped', CurrentLine = NULL
WHERE ToolCode = @c AND Status IN (N'Maintenance', N'InStock')");

    public static void Run(SqlSugarClient db)
    {
        db.CodeFirst.InitTables(typeof(Tooling), typeof(ToolingUsage));
        db.Ado.ExecuteCommand(@"
IF NOT EXISTS (SELECT 1 FROM sys.check_constraints WHERE name = 'CK_Tooling_Status')
    ALTER TABLE Tooling ADD CONSTRAINT CK_Tooling_Status CHECK (Status IN (N'InStock', N'InUse', N'Cleaning', N'Maintenance', N'Scrapped'));");
        db.Deleteable<ToolingUsage>().ExecuteCommand();
        db.Deleteable<Tooling>().ExecuteCommand();
        db.Insertable(new List<Tooling>
        {
            new() { ToolCode = "STN-A100-T", ToolType = "Stencil", ProductCode = Seed.Product, Status = "InStock", MaxUseCount = 500, CleanEvery = 200 },
            new() { ToolCode = "STN-A100-B", ToolType = "Stencil", ProductCode = Seed.Product, Status = "InStock", MaxUseCount = 500, CleanEvery = 200 },
            new() { ToolCode = "FIX-A100-01", ToolType = "Fixture", ProductCode = Seed.Product, Status = "InStock", MaxUseCount = 2000, CleanEvery = 0 },
            new() { ToolCode = "PRB-ICT-01", ToolType = "Probe", Status = "InStock", MaxUseCount = 30, CleanEvery = 0 },
        }).ExecuteCommand();
        Console.WriteLine("台账：STN-A100-T / STN-A100-B 钢网（寿命 500 次，每 200 次清洗），FIX-A100-01 治具（寿命 2000），PRB-ICT-01 探针（寿命 30）");

        Console.WriteLine("1. 领用：");
        Console.WriteLine($"   SMT-L1 领用 STN-A100-T -> {Issue(db, "STN-A100-T", "SMT-L1")}");
        Console.WriteLine($"   SMT-L2 也想领用 STN-A100-T -> {Issue(db, "STN-A100-T", "SMT-L2")}");

        var barrier = new Barrier(2);
        var res = new string[2];
        var ths = new[] { "SMT-L1", "SMT-L2" }.Select((line, i) => new Thread(() =>
        {
            var d = Db.Create();
            barrier.SignalAndWait();
            res[i] = Issue(d, "STN-A100-B", line);
        })).ToList();
        ths.ForEach(t => t.Start()); ths.ForEach(t => t.Join());
        var b = Get(db, "STN-A100-B");
        Console.WriteLine($"2. 并发：两条线同时领用 STN-A100-B -> 成功 {res.Count(r => r.StartsWith("成功"))} 条，被拒绝 {res.Count(r => r.StartsWith("被拒绝"))} 条；领用流水 {db.Queryable<ToolingUsage>().Count(u => u.ToolCode == "STN-A100-B" && u.Action == "Issue")} 条，状态 {b.Status}");

        Console.WriteLine("3. 计数与清洗（STN-A100-T 在 SMT-L1）：");
        Console.WriteLine($"   印刷 150 次 -> {Count(db, "STN-A100-T", "SMT-L1", 150)}");
        Console.WriteLine($"   再印 50 次（累计 200，到清洗周期）-> {Count(db, "STN-A100-T", "SMT-L1", 50)}");
        Console.WriteLine($"   想再印 1 次 -> {Count(db, "STN-A100-T", "SMT-L1", 1)}");
        Console.WriteLine($"   清洗 -> {Clean(db, "STN-A100-T")}");
        Console.WriteLine($"   印刷 150 次 -> {Count(db, "STN-A100-T", "SMT-L1", 150)}");
        Console.WriteLine($"   想一口气印 100 次（距上次清洗会到 250）-> {Count(db, "STN-A100-T", "SMT-L1", 100)}");
        Console.WriteLine($"   印刷 50 次（累计 400，又到清洗周期）-> {Count(db, "STN-A100-T", "SMT-L1", 50)}");
        Console.WriteLine($"   清洗 -> {Clean(db, "STN-A100-T")}");

        Console.WriteLine("4. 超寿命拦截：");
        Console.WriteLine($"   想印 150 次（400 + 150 > 500）-> {Count(db, "STN-A100-T", "SMT-L1", 150)}");
        Console.WriteLine($"   印刷 100 次（累计 500，到寿命）-> {Count(db, "STN-A100-T", "SMT-L1", 100)}");
        Console.WriteLine($"   到寿命后领用线体：{Get(db, "STN-A100-T").CurrentLine ?? "（空，已自动下线）"}；再印 1 次 -> {Count(db, "STN-A100-T", "SMT-L1", 1)}");
        Console.WriteLine($"   SMT-L2 想领用 -> {Issue(db, "STN-A100-T", "SMT-L2")}");
        Console.WriteLine($"   评估后报废 -> {Scrap(db, "STN-A100-T")}");

        Console.WriteLine("5. 治具领用、计数、归还（FIX-A100-01）：");
        Console.WriteLine($"   SMT-L2 领用 -> {Issue(db, "FIX-A100-01", "SMT-L2")}");
        Console.WriteLine($"   SMT-L2 使用 300 次 -> {Count(db, "FIX-A100-01", "SMT-L2", 300)}");
        Console.WriteLine($"   SMT-L1 想归还别人领的治具 -> {Return(db, "FIX-A100-01", "SMT-L1")}");
        Console.WriteLine($"   SMT-L2 归还 -> {Return(db, "FIX-A100-01", "SMT-L2")}");

        Console.WriteLine("6. 测试探针（PRB-ICT-01，寿命 30）：");
        Console.WriteLine($"   ICT-1 领用 -> {Issue(db, "PRB-ICT-01", "ICT-1")}");
        Console.WriteLine($"   测试 30 次 -> {Count(db, "PRB-ICT-01", "ICT-1", 30)}");
        Console.WriteLine($"   换针 -> {Repair(db, "PRB-ICT-01")}");

        Console.WriteLine("7. 对账：流水里 Delta 的合计应该等于台账的 UseCount");
        foreach (var t in db.Queryable<Tooling>().OrderBy(t => t.ToolCode).ToList())
        {
            int sum = db.Queryable<ToolingUsage>().Where(u => u.ToolCode == t.ToolCode).Sum(u => u.Delta);
            int rows = db.Queryable<ToolingUsage>().Count(u => u.ToolCode == t.ToolCode);
            Console.WriteLine($"   {t.ToolCode,-12} 状态 {t.Status,-11} UseCount {t.UseCount,3}  流水 {rows,2} 条，合计 {sum,3} -> {(sum == t.UseCount ? "一致" : "不一致!")}");
        }
    }

   STN-A100-B   状态 InUse       UseCount   0  流水  1 条，合计   0 -> 一致
   STN-A100-T   状态 Scrapped    UseCount 500  流水  9 条，合计 500 -> 一致

第 5 步，读懂输出：

  • 场景 1–2：第二条线领不到已被领用的钢网，提示里直接说明被谁领用；
  • 场景 2（并发）：用 Barrier 让两个独立连接同时领用同一张钢网，结果总是成功 1 个、被拒绝 1 个，领用流水只有 1 条；
  • 场景 3：计数到 200 自动进入 Cleaning，不清洗就不能再计数；清洗后计数重新开始算周期；一次性计数会让距离上次清洗超过 200 也会被拒绝；
  • 场景 4：超寿命前一次被拒绝，刚好到 500 时成功并自动下线（线体变空），之后无法计数、无法领用；
  • 场景 5：治具领用、计数、归还；别的线体不能归还别人领用的治具；
  • 场景 6：探针到寿命后进入 Maintenance，换针后 UseCount 清零回到 InStock；
  • 场景 7：对账，4 个工装的流水 Delta 合计都等于 UseCount。

常见坑与排查 ​

误区 / 坑事实与办法
按板数计数钢网/探针按"使用一次"计，一个拼板印一次/测一次就算 1 次
先查寿命再更新并发时两个终端同时通过。把寿命条件写进 UPDATE 的 WHERE

只记计数，不记流水对不上账时无从追查。每次动作追加一条流水，Delta 合计对账

报废的钢网没做标记被误领用。状态改 Scrapped 并物理处理
领用线体没记录不知道谁拿走了。CurrentLine 必填，归还必须是本线

数字照搬实验寿命、清洗周期以钢网厂商和公司规范为准

练习题与答案 ​

  1. 为什么两条线同时领用同一张钢网，只有一个能成功？ 答：领用是一条 UPDATE ... WHERE Status = N'InStock'。数据库让两条语句排队，先执行的改成 InUse，后执行的看到状态已变，更新 0 行。
  2. 钢网印一个有 4 块小板的拼板，使用次数加几？ 答：加 1。钢网每印一次计一次，与拼板里有几块小板无关。
  3. 钢网当前 UseCount = 480，寿命 500，清洗周期 200，上次清洗时是 400。想一次计数 30 次，会怎样？ 答：拒绝。480 + 30 = 510 超过寿命 500。（距上次清洗 80 + 30 = 110，没超过周期，但寿命先超了。）
  4. 同样的钢网，计数 20 次呢？ 答：成功。480 + 20 = 500，等于寿命上限，状态自动变 Maintenance、线体清空；之后不能再计数。
  5. 为什么 Repair 换针后，流水里要记 Delta = -30（负数）？ 答：换针把 UseCount 清零，台账变了 30，流水也要有对应的一笔，才能保证 SUM(Delta) 始终等于 UseCount，对账才成立。
  6. 钢网在 Cleaning 状态下，能被另一条线领用吗？ 答：不能。领用要求状态是 InStock；Cleaning 的钢网还挂在原线体上，必须先清洗回到 InUse、再归还。
  7. 如何增加"用到寿命 90% 时预警"？ 答：预警是只读查询，不改状态：SELECT ... WHERE Status IN (N'InStock', N'InUse') AND UseCount * 10 >= MaxUseCount * 9，在换线备料和看板上显示，提醒提前制作新钢网。
  8. 为什么 ToolingUsage 不记被拒绝的动作？这样有什么缺点？ 答：实验只关心成功的动作，流水与 UseCount 对账。缺点是看不到谁多次尝试被拦。真实系统可另写拦截日志，用于分析习惯性违规。

小结 ​

  • 工装（钢网、治具、载具、探针）会磨损，要有编号、台账、状态和使用次数，到寿命就拦截。
  • 状态五个：InStock、InUse、Cleaning、Maintenance、Scrapped；到清洗周期、到寿命由计数自动触发状态切换。
  • 每个动作是一条带条件的 UPDATE，靠受影响行数判断；领用的并发、计数的超寿命都由数据库一条语句内完成。
  • 成功的动作在同一事务里追加一条流水，Delta 合计 = UseCount，用于对账；计数按"使用一次"，不是按板数。
  • 与过站联动：进站检查工装在寿命内，印刷站出站时计数；数值（寿命、周期）以厂商和公司规范为准。
