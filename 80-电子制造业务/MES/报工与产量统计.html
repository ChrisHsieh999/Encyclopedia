报工与产量统计

AI 生成 · 待核对制造业务MES报工产量良率统计更新于 2026-10-21

⚠ 待核对：报工方式、良率/直通率的口径、班次划分、完工入库的触发时机是电子厂的通用做法；FPY（直通率）和良率在不同公司有不同口径（有的把返修后通过算合格，有的不算；有的按板、有的按拼板、有的按工序），班次时间、跨零点归属、是否允许超报也各家不同，你们的自研系统一定有自己的口径，请对照你们的报表定义。FPY/RTY 的基本定义已联网对照多个来源，来源之间对"返工算不算一次通过"也有分歧（见正文）。代码、SQL 和输出是我在本机 SQL Server LocalDB 上实际运行得到的；"手动报工表 ReportRecord"的 T-SQL 在本机临时表上运行验证过，但没有写进实验项目。

本篇是 MES 系列第 12 篇，回应 过站与工序流转 里留下的问题（"完成数由 TrackRecord 汇总得出"）和 工单管理 里的"防超报"。读完你应该能：说清报工是什么、自动报工和手动报工各适合什么场景；区分合格/不良/报废；说出良率、最终良率、直通率 FPY 的区别并手算；写出按线体、班次、小时统计产出的 SQL（GROUP BY 和窗口函数）；处理夜班跨零点；让工单完成数和过站统计保持一致；并亲手跑通一个 35 块板的统计实验。

一句话定义 ​

报工是向系统报告"某工单在某工序完成了多少、其中合格多少、不良多少、报废多少"。产量统计是把这些数字按工单、班次、线体、小时等维度汇总，回答"做了多少、做得好不好"。

先修知识 ​

  • 工单管理：知道工单的计划数、完成数、防超报的条件 UPDATE。
  • 过站与工序流转：知道 TrackRecord（过站记录）和 Unit（板）。
  • 会写 SQL 的 GROUP BY；窗口函数（ROW_NUMBER、SUM ... OVER）本篇会边用边讲。

它解决什么问题 ​

先看没有统一报工口径的工厂：

  • "今天做了多少"没有标准答案：计划说 300，线长说 280，仓库入库 270，ERP 里报了 290。每个人都有道理，因为大家数的东西不一样：有的数印刷出站，有的数 AOI 出站，有的数入库。
  • 手工报工靠记忆：下班前凭印象填一个数。多报了冲击库存和成本，少报了漏发工资。
  • 超报：一张工单计划 500，不知不觉报了 520，多出的 20 块的物料从哪来、算谁的？
  • 跨零点的夜班算不清：夜班 20:00 到次日 08:00，按"自然日"汇总，同一个班次被拆成两天，两天都不对。
  • 良率好看但不真实：返修后再通过算合格，所以"良率 99%"，其实一次通过的只有 80%，返修线一直爆满。
  • 工单完成数和实际对不上：工单显示完成 18，过站记录里数出来 19。

本篇的目标：数字有定义，有来源，能核对。

核心概念 ​

自动报工 vs 手动报工 ​

自动报工（过站驱动）手动报工
怎么来末站（或指定工序）出站 Pass，系统自动 FinishedQty + 1操作员/班组长在界面上录入数量
优点准确、实时、没有人为误差；和追溯完全一致适用于没有扫码的工序
缺点需要每块板都过站（扫码或设备上报）容易错报、漏报、虚报，需要审核
适用SMT 线、有扫码/设备接口的工序手工包装、整箱计数、补报、更正
记录TrackRecord 本身就是记录需要独立的"报工记录"，每次一行

原则：能自动就不要手动。在 过站与工序流转 里，末站出站 Pass 时同一事务内 FinishedQty + 1，这就是自动报工。手动报工是补充，用于自动覆盖不到的地方，并且必须留痕、可审、可更正。

合格、不良、报废 ​

数含义来源
合格数通过检验、可以流入下一工序/入库的数量末站出站 Pass 的板
不良数判了不合格（Fail），正在返修或待处理出站 Fail，Unit 为 Hold
报废数无法修复，作废Unit 为 Scrapped

一块板的账：投入 = 合格 + 在制（含 Hold 待处理）+ 报废。统计时要明确"不良"是指"出现过 Fail 记录"（含已修好的），还是"当前仍是 Hold"。前者用于质量分析，后者用于在制品管理，不要混用。

几个"率"，一定要分清 ​

用同一批数据解释。假设一个班次某条线投入 8 块板，其中：6 块一次全 Pass，2 块在 AOI 先 Fail、返修后第二次 Pass，没有报废。

指标算法结果含义
按记录的站良率（AOI 站）AOI 站 Pass 记录数 ÷ AOI 站总记录数8 ÷ 10 = 80.0%站点每次检测的通过比例；返修重检会多出记录，不是按板的比例
最终良率最终合格的板 ÷ 投入的板8 ÷ 8 = 100.0%只看结果，返修后合格也算合格，反映报废多少
直通率 FPY一次就全部 Pass（没有任何 Fail）的板 ÷ 投入的板6 ÷ 8 = 75.0%反映过程质量，包括返修成本

这三个数就是后面实验里 L2 白班的真实数据。结论：最终良率 100% 看起来很美，但 FPY 只有 75%，意味着四分之一的板子走了返修，成本和产能都在被吃掉。

FPY 的口径分歧：多个资料把 FPY 定义为"第一次就通过、没有返工/返修/报废的比例"，也有资料把"返工后通过"算进去（那更接近 FTY）。本篇采用严格口径：板只要出现过一次 Fail 就不算一次通过。你们公司的口径请对照。

RTY（滚动直通率） 是把每个工序的一次通过率连乘：例如三道工序一次通过率分别是 96%、98%、95%，RTY = 0.96 × 0.98 × 0.95 ≈ 89.4%（我用计算器验算过）。它反映多工序累积的损失：每站看起来都不错，连起来就不好看。本篇的 FPY 是"整条路线任何一站都没有 Fail"的板占比，在每块板都走完整路线的前提下，等于各站一次通过率连乘的结果。

产量的统计口径 ​

同样叫"产量"，必须说清楚四件事：

  1. 数什么：数板还是拼板？SMT 一次贴一个拼板（4 块小板），数拼板是 1，数小板是 4。统一用单板（Unit），拼板出站时按子板展开（见 条码与板码规则）。
  2. 在哪个工序数：完工数看末站出站 Pass；工序产出看该工序出站 Pass。
  3. 用哪个时间：按出站时间 OutAt（板完成这一站的时刻）。不要用入站时间或记录写入时间。
  4. 一块板返修多次算几次：产出按板去重（一块板只会有一条末站 Pass），不是按记录数；但站良率是按记录数。

四个常见的汇总维度：

维度回答的问题依据
按工单这张工单做完了多少，达成率工单号 WoId
按线体每条线产出、良率工站→线体的对应
按班次白班/夜班各做多少，哪班良率低出站时间 → 班次
按小时产能有没有波动，什么时候停线出站时间截断到小时

班次划分：跨零点是最大的坑 ​

假设两班倒：白班 08:00–20:00，夜班 20:00–次日 08:00。夜班跨过零点，00:00 之后的产出，应该算在"夜班开始的那天"，因为那是同一个班次、同一批人。

如果直接 GROUP BY CAST(OutAt AS date)（按自然日），同一个夜班会被切成两天：

text
夜班 10-20 20:00 开始 → 10-21 08:00 结束
  自然日 10-20：20:00–24:00 的产出
  自然日 10-21：00:00–08:00 的产出   ← 被算到了第二天

一个简单可靠的办法：把时间往前拨 8 小时（班次起点）再取日期。DATEADD(HOUR, -8, OutAt) 之后：08:00–次日 07:59:59 都落在同一个日期，白班和夜班自然分开，夜班过零点的部分自动归到前一天。班次名则看小时：8 ≤ 小时 < 20 是白班，其余是夜班。

三班倒（如 08–16、16–24、00–08）的"班次日"约定又不同（00–08 班通常算当天），这时更稳妥的做法是建一张班次表，每行写班次名、起止时间、是否跨零点，用关联而不是写死 -8。本篇实验用两班倒演示。

另一个相关的坑：时区与服务器时间。设备、终端、服务器时间不一致，会让板子落在错误的班次。统一用服务器时间写 OutAt；设备上报的时间要么校准，要么只当参考。

业务视角 ​

谁在什么环节做什么：

角色动作
操作员过站（自动报工）；手工工序手动报工
线长/班组长核对本班产量、不良；审核手动报工；处理差异
生产计划看工单达成率，调整排产
仓库工单完工后收到入库通知，接收成品（见 WMS与MES交互）
品质看良率、FPY，分析不良趋势
财务/成本用完工数和报废数核算成本，对账 ERP

完工入库的触发：当一张工单的完工数达到计划数（或被人工"完工"），工单进入 Completed，同时通知仓库成品入库，并通过接口把报工结果回写 ERP（见 MES与ERP及设备的接口设计）。触发方式常见两种：按工单整张完工入库，或按批次/箱分批入库（先做完的先入）。两种都应满足：入库数 ≤ 完工数、入库后不可再改完工数、每次入库留痕。接口失败要能重试且幂等（用"待发送消息"表，见 MES核心数据模型 里的规划）。

KPI公式

最终良率最终合格板数 ÷ 投入板数
直通率 FPY一次通过板数 ÷ 投入板数
报废率报废板数 ÷ 投入板数
小时产能 UPH某小时末站 Pass 数
返修率出现过 Fail 但最终合格的板 ÷ 投入板数

技术视角 ​

数据来源：只看 TrackRecord ​

在迷你 MES 里，所有产量数字都能从 TrackRecord 推出来，不需要额外的"产量表"：

  • 每块板的最终状态：看它最后一条记录——如果最后一条是末站 AOI 且 Pass，就是合格；
  • 每块板是否一次通过：它的所有记录里有没有 Fail；
  • 板属于哪条线：看它最后一条记录的工站（StationCode），通过"工站→线体"的对应得到。迷你模型里工站编码约定为 线体-工序（如 L2-AOI），实验里用一个内联的对应表代替；真实系统应该有 Station 表（见 MES核心数据模型 里规划的 Line / Station）。

核心 SQL：窗口函数 + GROUP BY ​

查询分两步：先用窗口函数为每块板挑出最后一条记录并算出它有几次 Fail，再按线体和班次 GROUP BY。

text
r：每条记录带两个窗口函数结果
    ROW_NUMBER() OVER (PARTITION BY SerialNo ORDER BY OutAt DESC, Id DESC)   -- 倒数第几条，=1 就是最后一条
    SUM(CASE WHEN Result='Fail' THEN 1 ELSE 0 END) OVER (PARTITION BY SerialNo)  -- 这块板一共 Fail 几次
u：只保留 rn = 1（每块板一行），判断是否完工(Done)，并关联得到线体
最后：GROUP BY 线体 + 班次日 + 班次 → 板数、完工数、一次过数

ROW_NUMBER 给每个分区（这里一块板就是一个分区）内的行编号；SUM(...) OVER (PARTITION BY ...) 是窗口聚合：它不会像 GROUP BY 那样把行合并，而是给每一行附上分区内的合计。两者配合，就能"保留最后一行，同时知道整块板的 Fail 次数"。完整的 SQL 在实验代码的 ShiftSql 里，下面的实验会运行它。

按小时的累计产出（也是窗口函数）：

sql
SELECT CONVERT(varchar(13), DATEADD(HOUR, DATEDIFF(HOUR, 0, OutAt), 0), 120) + ':00' AS H, COUNT(*) AS N,
       SUM(COUNT(*)) OVER (ORDER BY DATEDIFF(HOUR, 0, OutAt)) AS Cum
FROM TrackRecord WHERE SerialNo LIKE 'OUT-%' AND StationCode = 'L2-AOI' AND Result = 'Pass'
  AND OutAt >= '2026-10-20 08:00' AND OutAt < '2026-10-20 20:00'
GROUP BY DATEDIFF(HOUR, 0, OutAt) ORDER BY DATEDIFF(HOUR, 0, OutAt);

DATEDIFF(HOUR, 0, OutAt) 是"从 1900-01-01 到现在过了多少小时"，用它分组等于按整点分组；SUM(COUNT(*)) OVER (ORDER BY ...) 是在分组结果上再做累计和（运行总数）。

与工单完成数保持一致 ​

WorkOrder.FinishedQty 是累加出来的，TrackRecord 是源头。两者应当随时能对账：

sql
SELECT w.WoNo, w.FinishedQty,
       (SELECT COUNT(DISTINCT t.SerialNo) FROM TrackRecord t
         WHERE t.WoId = w.WoNo AND t.StepCode = 'AOI' AND t.Result = 'Pass') AS Real
FROM WorkOrder w;

注意 COUNT(DISTINCT SerialNo)：一块板即使重复出现过多条 AOI Pass（异常数据），也只算一次。差异出现时，以过站记录为准，修正累加值并查明原因（常见：人为改库、手动补报、事务没覆盖到某条路径）。

高并发下 WorkOrder 是热点行（见 过站与工序流转），有的系统把完成数改成由汇总得出、定时刷新；那样"对账"就变成"汇总表和源头比对"，做法相同。

防超报 ​

不管自动还是手动，写完成数的唯一入口都应该是 工单管理 里那条条件 UPDATE：

sql
UPDATE WorkOrder SET FinishedQty = FinishedQty + @qty
WHERE WoNo = @wo AND Status = 'Running' AND FinishedQty + @qty <= PlanQty;

要允许超产 10%，把上限改为 PlanQty * 1.1，并做成可配置规则。

手动报工的表设计（设计建议） ​

手动报工必须有独立的记录，每次一行，不改不删，更正用冲销：

sql
CREATE TABLE ReportRecord (
  Id          int IDENTITY(1,1) NOT NULL PRIMARY KEY,
  WoNo        nvarchar(30) NOT NULL,
  StepNo      int NOT NULL,
  Kind        nvarchar(10) NOT NULL DEFAULT N'Normal',   -- Normal 正常 / Reversal 冲销
  GoodQty     int NOT NULL,
  DefectQty   int NOT NULL DEFAULT 0,
  ScrapQty    int NOT NULL DEFAULT 0,
  Reason      nvarchar(100) NULL,
  ReportedBy  nvarchar(30) NOT NULL,
  ReportedAt  datetime NOT NULL DEFAULT GETDATE(),
  CorrectsId  int NULL,                                   -- 冲销的是哪一条
  CONSTRAINT CK_Rep_Qty CHECK ((Kind = N'Normal' AND GoodQty >= 0 AND DefectQty >= 0 AND ScrapQty >= 0)
                            OR (Kind = N'Reversal' AND GoodQty <= 0 AND DefectQty <= 0 AND ScrapQty <= 0 AND CorrectsId IS NOT NULL)));

我在本机用临时表跑过：正常报工 100/3/2，再用冲销行 −10 更正后，SUM 得到 90/3/2；把一条负数当成 Normal 报工，被 CHECK 约束拒绝。这个表在本篇实验里没有使用（实验只用自动报工的数据），不同公司的手动报工字段会有差异，请对照你们的系统。

逐步例子：35 块板，两条线，两个班次 ​

实验造了 6 批板，每批的特征和手算结果如下（每块板 5 站：PRINT、SPI、MOUNT、REFLOW、AOI；时间是该板 AOI 出站时刻，批内每 10 分钟一块）：

批线体首块板 AOI 时间构成板数完工一次过
G1L110-20 09:008 块一次过、1 块 SPI 先 Fail 后修好、1 块 AOI Fail 后报废1098
G2L110-20 23:306 块一次过（其中 3 块在零点之后完成）666
G3L110-21 02:002 块一次过、1 块 AOI 先 Fail 后修好332
G4L210-20 10:006 块一次过、2 块 AOI 先 Fail 后修好886
G5L210-20 21:004 块一次过、1 块 SPI Fail 后报废（没走到 AOI）544
G6L210-21 07:503 块一次过（07:50 属夜班，08:00 和 08:10 属白班）333

合并成"线体 × 班次日 × 班次"后，手算：

  • L1 白班 10-20 = G1：10 板，完工 9，一次过 8。最终良率 9÷10 = 90.0%，FPY 8÷10 = 80.0%。
  • L1 夜班 10-20 = G2 + G3（都是 10-20 20:00 开始的夜班）：9 板，完工 9，一次过 6 + 2 = 8。最终良率 100.0%，FPY 8÷9 = 88.9%。
  • L2 白班 10-20 = G4：8 板，完工 8，一次过 6。最终良率 100.0%，FPY 75.0%。
  • L2 夜班 10-20 = G5 + G6 的第一块（07:50）：5 + 1 = 6 板，完工 4 + 1 = 5，一次过 4 + 1 = 5。最终良率 5÷6 = 83.3%，FPY 83.3%。
  • L2 白班 10-21 = G6 的后两块（08:00、08:10）：2 板，完工 2，一次过 2。100.0%、100.0%。

合计：35 块板（10 + 9 + 8 + 6 + 2），完工 33（9 + 9 + 8 + 5 + 2），一次过 29（8 + 8 + 6 + 5 + 2）。过站记录共 176 条：G1 = 8×5 + 6 + 5 = 51，G2 = 30，G3 = 2×5 + 6 = 16，G4 = 6×5 + 2×6 = 42，G5 = 4×5 + 2 = 22，G6 = 15，合计 51 + 30 + 16 + 42 + 22 + 15 = 176。

G2 是专门测"夜班跨零点"的：6 块板在 23:30、23:40、23:50、00:00、00:10、00:20 完成。按自然日会被切成 3 + 3，按班次日全部算 10-20 夜班。G6 是专门测边界的：08:00 整属于白班。

第 1 步：新建 LabOutput.cs（本实验不需要新实体，只往 TrackRecord 里造数据）：

csharp
using SqlSugar;

namespace MiniMes;

// 产量统计实验：造一批 TrackRecord，按"线体 x 班次"统计产出、最终良率、直通率 FPY，并和手算核对
public static class LabOutput
{
    // 一组板：线体、第一块板的完工时刻、间隔 10 分钟一块；clean 一次过，spiFix SPI 先 Fail 后修好，
    // aoiFix AOI 先 Fail 后修好，aoiScrap AOI 判 Fail 后报废，spiScrap SPI 判 Fail 后报废
    record G(string Line, string Wo, DateTime First, int Clean, int SpiFix, int AoiFix, int AoiScrap, int SpiScrap);

    static readonly G[] Groups =
    {
        new("L1", "WO-OUT-001", new DateTime(2026, 10, 20, 9, 0, 0), 8, 1, 0, 1, 0),
        new("L1", "WO-OUT-001", new DateTime(2026, 10, 20, 23, 30, 0), 6, 0, 0, 0, 0),
        new("L1", "WO-OUT-001", new DateTime(2026, 10, 21, 2, 0, 0), 2, 0, 1, 0, 0),
        new("L2", "WO-OUT-002", new DateTime(2026, 10, 20, 10, 0, 0), 6, 0, 2, 0, 0),
        new("L2", "WO-OUT-002", new DateTime(2026, 10, 20, 21, 0, 0), 4, 0, 0, 0, 1),
        new("L2", "WO-OUT-002", new DateTime(2026, 10, 21, 7, 50, 0), 3, 0, 0, 0, 0),
    };

    static readonly (int No, string Code)[] Steps = { (10, "PRINT"), (20, "SPI"), (30, "MOUNT"), (40, "REFLOW"), (50, "AOI") };

    static TrackRecord Rec(string sn, string wo, string line, (int No, string Code) s, string result, DateTime outAt) => new()
    {
        SerialNo = sn, WoId = wo, StepNo = s.No, StepCode = s.Code, Result = result, StationCode = $"{line}-{s.Code}",
        OperatorCode = "OP001", InAt = outAt.AddMinutes(-3), OutAt = outAt,
    };

    static List<TrackRecord> Build(out Dictionary<string, (string Line, DateTime Last, bool Done, bool FirstPass)> truth)
    {
        var rows = new List<TrackRecord>();
        truth = new();
        int seq = 0;
        foreach (var g in Groups)
        {
            var kinds = Enumerable.Repeat("clean", g.Clean).Concat(Enumerable.Repeat("spiFix", g.SpiFix)).Concat(Enumerable.Repeat("aoiFix", g.AoiFix))
                .Concat(Enumerable.Repeat("aoiScrap", g.AoiScrap)).Concat(Enumerable.Repeat("spiScrap", g.SpiScrap)).ToList();
            for (int i = 0; i < kinds.Count; i++)
            {
                string sn = $"OUT-{++seq:0000}", k = kinds[i];
                var t = g.First.AddMinutes(10 * i);                       // 这块板在 AOI 站出站的时刻
                var at = Steps.Select((s, j) => t.AddMinutes(-10 * (4 - j))).ToArray();   // 每站间隔 10 分钟，AOI 是最后一站
                if (k == "spiScrap")
                {
                    rows.Add(Rec(sn, g.Wo, g.Line, Steps[0], "Pass", at[0]));
                    rows.Add(Rec(sn, g.Wo, g.Line, Steps[1], "Fail", at[1]));
                    truth[sn] = (g.Line, at[1], false, false);
                    continue;
                }
                for (int j = 0; j < 4; j++)
                {
                    if (j == 1 && k == "spiFix") rows.Add(Rec(sn, g.Wo, g.Line, Steps[1], "Fail", at[1].AddMinutes(-5)));
                    rows.Add(Rec(sn, g.Wo, g.Line, Steps[j], "Pass", at[j]));
                }
                if (k == "aoiFix") rows.Add(Rec(sn, g.Wo, g.Line, Steps[4], "Fail", t.AddMinutes(-5)));
                rows.Add(Rec(sn, g.Wo, g.Line, Steps[4], k == "aoiScrap" ? "Fail" : "Pass", t));
                truth[sn] = (g.Line, t, k != "aoiScrap", k == "clean");
            }
        }
        return rows;
    }

    // 班次：白班 08:00-20:00，夜班 20:00-次日 08:00。把时间往前拨 8 小时再取日期，夜班过零点的部分自动归到前一天
    const string ShiftSql = @"
WITH r AS (
    SELECT t.SerialNo, t.StepCode, t.Result, t.StationCode, t.OutAt,
           ROW_NUMBER() OVER (PARTITION BY t.SerialNo ORDER BY t.OutAt DESC, t.Id DESC) AS rn,
           SUM(CASE WHEN t.Result = 'Fail' THEN 1 ELSE 0 END) OVER (PARTITION BY t.SerialNo) AS Fails
    FROM TrackRecord t WHERE t.SerialNo LIKE 'OUT-%'),
u AS (   -- 每块板只留最后一条记录：它决定这块板最终的结果、归属的时间和线体
    SELECT r.SerialNo, st.LineCode, r.OutAt, r.Fails,
           CASE WHEN r.StepCode = 'AOI' AND r.Result = 'Pass' THEN 1 ELSE 0 END AS Done
    FROM r JOIN (VALUES ('L1-PRINT','L1'),('L1-SPI','L1'),('L1-MOUNT','L1'),('L1-REFLOW','L1'),('L1-AOI','L1'),
                        ('L2-PRINT','L2'),('L2-SPI','L2'),('L2-MOUNT','L2'),('L2-REFLOW','L2'),('L2-AOI','L2')) st(StationCode, LineCode)
         ON st.StationCode = r.StationCode
    WHERE r.rn = 1)
SELECT LineCode,
       CONVERT(varchar(10), CAST(DATEADD(HOUR, -8, OutAt) AS date), 120) AS ShiftDate,
       CASE WHEN DATEPART(HOUR, OutAt) BETWEEN 8 AND 19 THEN 'Day' ELSE 'Night' END AS Shift,
       COUNT(*) AS Units, SUM(Done) AS Good,
       SUM(CASE WHEN Done = 1 AND Fails = 0 THEN 1 ELSE 0 END) AS FirstPass
FROM u GROUP BY LineCode, CAST(DATEADD(HOUR, -8, OutAt) AS date), CASE WHEN DATEPART(HOUR, OutAt) BETWEEN 8 AND 19 THEN 'Day' ELSE 'Night' END
ORDER BY LineCode, ShiftDate, Shift";

    class Row { public string LineCode { get; set; } public string ShiftDate { get; set; } public string Shift { get; set; } public int Units { get; set; } public int Good { get; set; } public int FirstPass { get; set; } }

    class HourRow { public string H { get; set; } public int N { get; set; } public int Cum { get; set; } }
    class WoRow { public string WoNo { get; set; } public int FinishedQty { get; set; } public int Real { get; set; } }

    static string Pct(int a, int b) => b == 0 ? "-" : $"{Math.Round(100m * a / b, 1, MidpointRounding.AwayFromZero):0.0}%";

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(TrackRecord));
        db.Deleteable<TrackRecord>().Where(t => t.SerialNo.StartsWith("OUT-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo.StartsWith("WO-OUT-")).ExecuteCommand();
        var rows = Build(out var truth);
        db.Insertable(rows).ExecuteCommand();
        Console.WriteLine($"1. 造数据：{truth.Count} 块板，{rows.Count} 条过站记录（2 条线、6 批、跨零点夜班）");

        var list = db.Ado.SqlQuery<Row>(ShiftSql);
        Console.WriteLine("2. 按 线体 x 班次 统计（班次日 = 夜班过零点的部分算前一天）：");
        Console.WriteLine("   线体 班次日      班次  板数 完工 一次过  最终良率  FPY");
        foreach (var r in list)
            Console.WriteLine($"   {r.LineCode}   {r.ShiftDate} {r.Shift,-5} {r.Units,4} {r.Good,4} {r.FirstPass,5}  {Pct(r.Good, r.Units),7}  {Pct(r.FirstPass, r.Units),6}");
        Console.WriteLine($"   合计 {list.Sum(r => r.Units)} 块板，完工 {list.Sum(r => r.Good)}，一次过 {list.Sum(r => r.FirstPass)}");

        // 手算：不查数据库，直接用造数据时的"真相"在内存里按同样口径数一遍
        var expect = truth.Values.GroupBy(v => (v.Line, Date: v.Last.AddHours(-8).Date, Day: v.Last.Hour >= 8 && v.Last.Hour < 20))
            .Select(g => (g.Key.Line, Date: g.Key.Date.ToString("yyyy-MM-dd"), Shift: g.Key.Day ? "Day" : "Night", Units: g.Count(), Good: g.Count(x => x.Done), Fp: g.Count(x => x.FirstPass)))
            .OrderBy(x => x.Line).ThenBy(x => x.Date).ThenBy(x => x.Shift).ToList();
        bool same = expect.Count == list.Count && expect.Zip(list, (e, r) => e.Line == r.LineCode && e.Date == r.ShiftDate && e.Shift == r.Shift && e.Units == r.Units && e.Good == r.Good && e.Fp == r.FirstPass).All(x => x);
        Console.WriteLine($"3. 与内存里的手算结果逐行比对（{expect.Count} 行）-> {(same ? "一致" : "不一致!")}");

        var naive = db.Ado.SqlQuery<Row>(@"
SELECT '' AS LineCode, CONVERT(varchar(10), CAST(OutAt AS date), 120) AS ShiftDate, '' AS Shift, COUNT(*) AS Units, 0 AS Good, 0 AS FirstPass
FROM TrackRecord WHERE SerialNo LIKE 'OUT-%' AND StepCode = 'AOI' AND Result = 'Pass' AND StationCode = 'L1-AOI' AND OutAt >= '2026-10-20 20:00' AND OutAt < '2026-10-21 08:00'
GROUP BY CAST(OutAt AS date) ORDER BY ShiftDate");
        Console.WriteLine("4. 坑：按自然日分组会把 L1 的 10-20 夜班拆成两天：" + string.Join("，", naive.Select(n => $"{n.ShiftDate} 有 {n.Units} 块")) + "；按班次日是 " + list.First(r => r.LineCode == "L1" && r.Shift == "Night").Good + " 块");

        var l2 = list.First(r => r.LineCode == "L2" && r.ShiftDate == "2026-10-20" && r.Shift == "Day");
        int aoiPass = db.Queryable<TrackRecord>().Count(t => t.SerialNo.StartsWith("OUT-") && t.StationCode == "L2-AOI" && t.Result == "Pass" && t.OutAt >= new DateTime(2026, 10, 20, 8, 0, 0) && t.OutAt < new DateTime(2026, 10, 20, 20, 0, 0));
        int aoiAll = db.Queryable<TrackRecord>().Count(t => t.SerialNo.StartsWith("OUT-") && t.StationCode == "L2-AOI" && t.OutAt >= new DateTime(2026, 10, 20, 8, 0, 0) && t.OutAt < new DateTime(2026, 10, 20, 20, 0, 0));
        Console.WriteLine($"5. 三种\"良率\"（L2 10-20 白班）：AOI 站按记录 {aoiPass}/{aoiAll} = {Pct(aoiPass, aoiAll)}；最终良率 {l2.Good}/{l2.Units} = {Pct(l2.Good, l2.Units)}；FPY {l2.FirstPass}/{l2.Units} = {Pct(l2.FirstPass, l2.Units)}");

        Console.WriteLine("6. L2 白班按小时的完工数与累计（窗口函数 SUM OVER）：");
        var hours = db.Ado.SqlQuery<HourRow>(@"
SELECT CONVERT(varchar(13), DATEADD(HOUR, DATEDIFF(HOUR, 0, OutAt), 0), 120) + ':00' AS H, COUNT(*) AS N,
       SUM(COUNT(*)) OVER (ORDER BY DATEDIFF(HOUR, 0, OutAt)) AS Cum
FROM TrackRecord WHERE SerialNo LIKE 'OUT-%' AND StationCode = 'L2-AOI' AND Result = 'Pass' AND OutAt >= '2026-10-20 08:00' AND OutAt < '2026-10-20 20:00'
GROUP BY DATEDIFF(HOUR, 0, OutAt) ORDER BY DATEDIFF(HOUR, 0, OutAt)");
        foreach (var h in hours) Console.WriteLine($"   {h.H}  本小时 {h.N}  累计 {h.Cum}");

        Console.WriteLine("7. 与工单完成数对账（工单完成数应等于 AOI 末站 Pass 的板数）：");
        foreach (var (wo, plan) in new[] { ("WO-OUT-001", 20), ("WO-OUT-002", 20) })
        {
            int done = db.Queryable<TrackRecord>().Where(t => t.WoId == wo && t.StepCode == "AOI" && t.Result == "Pass").Select(t => t.SerialNo).Distinct().Count();
            db.Insertable(new WorkOrder { WoNo = wo, ProductCode = Seed.Product, PlanQty = plan, FinishedQty = done, Status = "Running", CreatedAt = DateTime.Now }).ExecuteCommand();
        }
        db.Updateable<WorkOrder>().SetColumns(w => w.FinishedQty == w.FinishedQty + 1).Where(w => w.WoNo == "WO-OUT-002").ExecuteCommand();   // 模拟一次多报
        foreach (var d in db.Ado.SqlQuery<WoRow>(@"
SELECT w.WoNo, w.FinishedQty, (SELECT COUNT(DISTINCT t.SerialNo) FROM TrackRecord t WHERE t.WoId = w.WoNo AND t.StepCode = 'AOI' AND t.Result = 'Pass') AS Real
FROM WorkOrder w WHERE w.WoNo LIKE 'WO-OUT-%' ORDER BY w.WoNo"))
            Console.WriteLine($"   {d.WoNo}  工单完成数 {d.FinishedQty}，过站统计 {d.Real} -> {(d.FinishedQty == d.Real ? "一致" : $"差 {d.FinishedQty - d.Real}，需要查")}");

        Console.WriteLine("8. 防超报（WO-OUT-001 计划 20，已完成 18）：");
        foreach (var q in new[] { 2, 1 })
        {
            int n = db.Updateable<WorkOrder>().SetColumns(w => w.FinishedQty == w.FinishedQty + q)
                .Where(w => w.WoNo == "WO-OUT-001" && w.Status == "Running" && w.FinishedQty + q <= w.PlanQty).ExecuteCommand();
            Console.WriteLine($"   补报 {q} 块 -> {(n == 1 ? "成功" : "被拒绝（会超过计划数）")}，现在 {db.Queryable<WorkOrder>().InSingle("WO-OUT-001").FinishedQty}/20");
        }
    }
}

  • 场景 4：自然日分组的坑——L1 夜班被拆成"10-20 有 3 块、10-21 有 6 块"，实际应是一个班次 9 块（场景 2 中 L1 夜班完工 9）；
  • 场景 5：同一批数据（L2 白班）的三种"良率"：站良率 80.0%、最终良率 100.0%、FPY 75.0%；
  • 场景 6：按小时统计，10 点 6 块、11 点 2 块，累计 8（与 L2 白班完工 8 吻合）；
  • 场景 7：工单对账。故意把 WO-OUT-002 的完成数多加 1，对账发现"差 1，需要查"；
  • 场景 8：防超报。计划 20、已完成 18，补报 2 块成功，再补 1 块被拒绝。

  • 把 aoiScrap 那块报废板去掉（AoiScrap 改 0）：L1 白班的最终良率从 90.0% 变成多少？FPY 呢？（参考练习题 4。）

练习题与答案 ​

  1. 自动报工和手动报工分别适合什么场景？ 答：自动报工适合有扫码或设备接口的工序（SMT 线），准确、实时、可追溯；手动报工适合没有扫码的工序（手工包装、整箱计数）和补报、更正，必须留痕、可审核。
  2. L2 白班 10-20：8 块板，6 块一次过，2 块 AOI 先 Fail 后修好，没有报废。最终良率和 FPY 各是多少？ 答：最终良率 8÷8 = 100.0%；FPY 6÷8 = 75.0%。
  3. 夜班 20:00–次日 08:00，一块板在 10-21 03:15 完工，它的班次日是哪天、哪个班？ 答：10-20 夜班。03:15 − 8 小时 = 10-20 19:15，取日期是 10-20；小时 3 不在 8 到 19 之间，属夜班。
  4. 把 L1 白班那块 AOI 报废的板去掉（只剩 9 块：8 块一次过 + 1 块 SPI 修好），最终良率和 FPY 是多少？ 答：板数 9，完工 9，最终良率 100.0%；一次过 8，FPY 8÷9 = 88.9%。
  5. 三道工序一次通过率分别是 90%、95%、98%，RTY 是多少？ 答：0.90 × 0.95 × 0.98 = 0.8379，约 83.8%。
  6. 为什么按记录数算的 AOI 站良率（80.0%）比 FPY（75.0%）高？ 答：站良率的分母把返修重检的记录也算进去（8 块板产生了 10 条 AOI 记录，其中 8 条 Pass），重检通过的 Pass 把比例拉高；FPY 按板算，只要出现过一次 Fail 就不算一次通过。
  7. 发现 WorkOrder.FinishedQty 比过站统计多 1，应该怎么办？ 答：以 TrackRecord 为准。先查原因（人为改库、手动补报、事务没覆盖到的路径），再用有权限、可审计的方式把完成数更正，留下更正记录。
  8. 为什么手动报工的更正要用"冲销"而不是直接改原来的数字？ 答：保持记录只追加，历史可信。冲销是追加一条相反方向的记录，合计自然得到正确数，同时保留了"曾经多报、后来更正"的事实。

小结 ​

  • 报工分自动（过站驱动，首选）和手动（补充，必须留痕）；合格、不良、报废要分开记。
  • 良率有三种：站良率（按记录）、最终良率（按板看结果）、FPY（按板看一次通过）；口径要在报表里写清楚，FPY 不把返修后通过算一次通过。
  • 产量口径四件事：数单板、看末站 Pass、用出站时间、产出按板去重。
  • 班次日用"时间往前拨到班次起点再取日期"处理夜班跨零点；三班倒用班次表。
  • 统计 SQL：窗口函数挑出每块板的最后一条记录并算 Fail 次数，再 GROUP BY 线体、班次日、班次。
  • 工单完成数要能和 TrackRecord 对账；写完成数的入口只有一个，防超报写在条件 UPDATE 里。
