产品追溯

AI 生成 · 待核对制造业务MES追溯质量更新于 2026-10-21

⚠ 待核对：一块板的履历由哪些表组成、追溯数据保留多少年、客诉到根因的处理流程，都是电子厂常见的通用做法，你们自研系统的表、保留期限和客户合同要求可能不同，请对照你们的系统与合同；ISO 9001 对"标识和可追溯性"有要求，具体条款请查标准原文，本篇没有逐条引用。本篇的时间线 SQL、完整性检查 SQL、读页数据都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 14 篇，是前面所有记录的"收口"：过站与工序流转、工艺参数与炉温曲线管理、物料追溯与批次关联 分别记了一部分，本篇把它们拼成一块板的完整履历，并讲怎么发现"履历里缺东西"。读完你应该能：列出一块板的履历由哪些记录组成；用一条 SQL 拼出时间线；设计按板码查询的索引并理解为什么快；写出缺记录检测；说清客诉到根因的追溯路径。

一句话定义 ​

产品追溯是给定一个板码，系统能还原这块板从投产到出货（甚至到返修）的完整履历：谁、在哪台设备、什么时候、用什么工艺参数和什么批次的料，做了什么，结果如何。

先修知识 ​

  • 过站与工序流转：Unit、TrackRecord 是履历的主干。
  • 物料追溯与批次关联：UnitMaterial，板用了哪批料。
  • 工艺参数与炉温曲线管理：ReflowRecord，板过炉时的实测曲线结果。
  • 后两篇的记录：不良与锁定见 不良品拦截与锁定，维修见 返修与维修管理，本篇只"读"它们。

它解决什么问题 ​

三个场景，每个都是真实会发生的：

  1. 客户投诉：客户退回一块板，说"偶发死机"。没有履历，你只能把板拆开看，看出个虚焊也不知道是哪天哪台炉子的问题。有履历：这块板 10 月 20 日 10:09 过 2 号炉，峰值 243 ℃，MCU 批次 LOT-U-777，AOI 曾判过一次虚焊，补焊后放行。线索一串，下一步该查什么就清楚了。
  2. 审核与合规：客户（尤其是汽车、医疗、通信设备）审核时，随机抽一个板码，要求你当场展示全过程。拿不出来，就是体系缺陷。IPC-1782 把追溯按风险分级，等级越高要记得越细，要求由你和客户约定。
  3. 自己找问题：直通率突然掉了，要看掉的那批板有什么共同点：同一台设备？同一个班？同一批料？这些问题全部靠履历回答。

没有"完整"二字，追溯就是半截的。最危险的情况不是某条记录写错了，而是应该有的记录根本不存在，客户抽查那一块刚好是缺记录的板。所以本篇有一半内容是讲"怎么发现缺记录"。

核心概念 ​

一块板的履历由什么组成 ​

履历内容来源表回答的问题记录的方式
身份：工单、产品、板码Unit这是谁的、哪个产品一行，会变
工艺路线工单绑定的 Route应该走哪些站主数据
过站TrackRecord每站何时、什么设备、谁、结果流水，只追加
工艺参数ReflowRecord、各设备参数记录过炉时的实测曲线流水
物料批次UnitMaterial用了哪些批次的料流水（快照）
检验TrackRecord 的检验站、专用检验表AOI / ICT / FCT 测了什么流水
不良DefectRecord哪一站发现什么不良流水 + 状态
锁定HoldRecord谁锁了、为什么、谁解的单据
返修RepairRecord修了哪个位号、换了什么流水
出货出货记录（见 WMS与MES交互）发给了谁流水

规律：每个事件在自己的表里按板码记，追溯时才把它们拼起来。这叫"事件源"思路：不把所有东西塞进一张宽表，而是保留每个事件，需要时拼。好处是每种记录各管各的、可以各自归档；代价是拼的时候要写 UNION ALL。

时间线：用 UNION ALL 拼 ​

各表的列不一样，但追溯只关心三样东西：什么时候、什么类别、说了什么。把每张表统一成这三列再 UNION ALL，按时间排序，就是时间线。这是追溯查询的核心套路：

sql
SELECT 时间, 类别, 说明 FROM (
    SELECT t.OutAt AS 时间, N'过站' AS 类别, CONCAT(...) AS 说明 FROM TrackRecord t WHERE t.SerialNo = @sn
    UNION ALL
    SELECT ... FROM UnitMaterial ...
    UNION ALL
    SELECT ... FROM DefectRecord ...
) x ORDER BY 时间

完整的 SQL 在后面的实验里，涉及 7 张表。

追溯的两个维度 ​

  • 纵向（一块板）：它自己的完整时间线。
  • 横向（一群板）：和它"共享某个因素"的其它板：同一批料、同一台炉、同一个班次。纵向发现线索，横向圈定范围。横向的做法在 物料追溯与批次关联 里已经做了，本篇的实验里把两者接起来。

追溯完整性 ​

"完整"的定义是按照规则应该有的记录都有。常见的缺口：

缺口怎么发生的怎么检出
缺过站记录接口丢消息、手工改过 Unit 位置却没写记录板推进到序号 N，但路线里某一道没有 Pass 记录
缺物料快照出站和快照不在一个事务；快照代码异常被吞掉贴片已出站，却没有 UnitMaterial
重复记录设备重发，没有幂等保护同一工序出现多条 Pass
孤立记录板被删除或改了板码，记录还在记录表里的板码在 Unit 里找不到
时间倒错两台设备时钟没对后一站的出站时间早于前一站

检测的原则：把规则写成 SQL，定期跑，结果进监控，而不是等客户来抽查。

业务视角 ​

角色在追溯里做什么
品质工程师查客诉板的履历，找根因，圈范围，出追溯报告
客服 / 销售接客诉，要板码；有履历就能先给客户一个初步判断
审核员 / 客户稽核随机抽板码，要求展示履历
工艺 / 设备工程师横向找共同因素：哪台设备、哪个参数
IT / 系统管理员保证记录齐全、可查、保留足够年限

客诉到根因的路径（完整案例见 客诉到根因追溯的全过程，客诉本身的处理见 客诉与RMA）：

  1. 收板，记录板码和故障现象；
  2. 纵向：查这块板的完整履历，看有无异常（返修过？某站参数边缘？）；
  3. 对照异常线索，横向：同一批料、同一天同一台炉的其它板，有无同类问题；
  4. 圈定范围，决定遏制（锁定库存与在制，通知已出货客户），见 不良品拦截与锁定；
  5. 根因分析与纠正预防，见 8D与CAPA；
  6. 追溯报告归档。

KPI：追溯查询耗时（分钟级）、追溯完整率（抽样检查有完整履历的板占比）、客诉根因定位时间。

技术视角 ​

按板码查询的性能 ​

履历查询几乎全是"按板码查"，所以每张记录表都要有以板码开头的索引。我在本机造了 100 万行过站记录（20 万块板 × 5 站）做对比，查一块板的 5 条记录：

情况逻辑读（读了多少个 8KB 页）
没有索引，全表扫描16050
有 (SerialNo, StepNo) 索引3

差了 5000 多倍；数据越多，差距越大。"逻辑读"是 SET STATISTICS IO ON 输出的指标，可以当成"这条查询读了多少页"。

两个细节：

  • 板码列类型统一为 nvarchar(40)。我实测过：用 'xxx'（varchar 常量）去查 nvarchar 列仍然是 3 次逻辑读，因为这个方向是把常量转换成列的类型，不影响索引；反过来（列是 varchar、参数是 nvarchar）会把整列转换，导致索引失效，这个坑在 MES核心数据模型 里有实测。所以统一类型是习惯，不是侥幸。
  • 时间线不要 SELECT *：只取展示需要的列，每个子查询的 WHERE 都按板码，才能每个都走索引。

数据量、分区与归档 ​

过站记录、物料快照、炉温记录都是只追加的大表。方案（分区的语法和限制见 MES核心数据模型）：

  1. 按月分区：用时间列（OutAt）做分区键。热数据在近几个月分区里，查询快，维护也快（索引重建、统计信息更新只针对热分区）。
  2. 归档：超过热数据期限的分区，切换（SWITCH）到归档表或归档库，压缩存放。归档后仍要能查，所以：追溯查询要有"热库+归档库"都查的路径，或者按板码的出生日期（板码里的日期段，见 条码与板码规则）先判断去哪个库。
  3. 保留期限：由行业和合同决定（几年到十几年不等），不要自己拍脑袋定，先问品质和法务。
  4. 分区后的索引：如果按时间分区，而查询只按板码，板码索引要么是"对齐的"（每个分区一份，查一块板可能要探多个分区），要么板码里带日期以便先剪枝。这是分区带来的新问题，要实测。

完整性检查 SQL ​

三条规则，写成 SQL（实验里一起运行）：

  • 规则 a：板已推进到序号 N，路线里序号 ≤ N 的每一道，必须有一条 Pass 记录（NOT EXISTS）；
  • 规则 b：有贴片 Pass 的板，必须有物料快照；
  • 规则 c：同一工序不能有两条以上 Pass（GROUP BY ... HAVING COUNT(*) > 1；注意"先 Fail 后 Pass"是正常的，所以只数 Pass）。

规则 a 里的"路线"为了简化，用的是产品当前生效的那一版；严格地说要用工单绑定的版本（见 过站与工序流转）。

追溯数据的"只追加" ​

追溯可信的前提是记录不被改。除了程序里不写 UPDATE/DELETE，数据库层也要限制（触发器或权限，见 过站与工序流转）。记录需要更正时追加一条"更正"，保持历史完整。

逐步例子：TR-0001 的一生 ​

工单 WO-TR-001，板码 TR-0001，10 月 20 日上午：

时间事件
10:00:40印刷出站 Pass
10:01:20SPI 出站 Pass
10:03:10贴片出站 Pass，同时生成物料快照 3 行（电阻 LOT-TR-R1、电容 LOT-TR-C1、MCU LOT-U-777）
10:09:00回流焊出站 Pass，炉温记录：曲线 SAC305-A100，峰值 243 ℃，TAL 62 s
10:10:30AOI 出站 Fail：U1 虚焊（SOLDER_OPEN），自动锁定
10:30:00维修员 RW01 补焊 U1
10:35:00品质 QA01 解锁
10:40:30AOI 重测 Pass，完工

共 14 条事件（过站 6 条、物料 3 条、炉温 1 条、不良 1 条、锁定 1 条、解锁 1 条、维修 1 条）。实验会用一条 SQL 把它们拼出来。

接着客户投诉这块板：它的 U1 用的是 MCU 批次 LOT-U-777；横向一查，LOT-U-777 还被 TR-0005 用过（在制）。品质据此决定锁定 TR-0005 并检查库存。

动手实验：拼出完整时间线，检出缺失记录 ​

前提：做完 过站与工序流转、物料追溯与批次关联 的实验（需要 Unit.cs、UnitMaterial.cs、LabMatTrace.cs——本篇调用它的 Forward）。本篇还要用到后两篇定义的实体类：DefectRecord、HoldRecord（文件 DefectHold.cs，在 不良品拦截与锁定）和 RepairRecord（文件 RepairRecord.cs，在 返修与维修管理）。按顺序学的话，先把这两个文件的代码复制进项目（只要实体类，不需要先做它们的实验）；本篇只往这些表里插几行演示数据。

第 1 步：新建 LabTrace.cs：

csharp
using SqlSugar;

namespace MiniMes;

// 产品追溯实验：用一条 SQL 把一块板的完整履历拼成时间线，再用几条 SQL 检出缺失的记录
// 本实验用到后面两篇定义的 DefectRecord、HoldRecord（不良品拦截与锁定）和 RepairRecord（返修与维修管理）的实体类，
// 只往里插几行演示数据，不需要先跑那两篇的实验
public static class LabTrace
{
    public class TimelineRow { public DateTime EventAt { get; set; } public string Kind { get; set; } public string Detail { get; set; } }
    public class GapRow { public string SerialNo { get; set; } public string What { get; set; } }

    static readonly DateTime T0 = new(2026, 10, 20, 10, 0, 0);
    static DateTime At(int min, int sec = 0) => T0.AddMinutes(min).AddSeconds(sec);
    static readonly Dictionary<string, string> Stations = new() { ["PRINT"] = "PRN-01", ["SPI"] = "SPI-01", ["MOUNT"] = "SMT-01", ["REFLOW"] = "RFL-01", ["AOI"] = "AOI-01" };

    // 一块板的完整履历：多张表 UNION ALL 成同样的三列（时间、类别、说明），再按时间排序
    const string TimelineSql = @"
SELECT EventAt, Kind, Detail FROM (
    SELECT t.OutAt AS EventAt, N'过站' AS Kind, CONCAT(t.StepNo, N' ', t.StepCode, N' ', t.Result, N'  ', t.StationCode, N' ', t.OperatorCode) AS Detail, 1 AS Ord
    FROM TrackRecord t WHERE t.SerialNo = @sn
    UNION ALL
    SELECT t.OutAt, N'物料', CONCAT(m.SlotNo, N' ', m.MaterialCode, N' ', m.LotNo, N' ', m.RefDes), 2
    FROM UnitMaterial m JOIN TrackRecord t ON t.SerialNo = m.SerialNo AND t.StepNo = m.StepNo AND t.Result = N'Pass' WHERE m.SerialNo = @sn
    UNION ALL
    SELECT r.RecordedAt, N'炉温', CONCAT(r.ProfileName, N' 峰值', r.PeakTemp, N' TAL', r.Tal, N's ', r.Result), 2
    FROM ReflowRecord r WHERE r.Sn = @sn
    UNION ALL
    SELECT d.FoundAt, N'不良', CONCAT(d.DefectCode, N' ', d.StationCode, N' ', d.Status), 3
    FROM DefectRecord d WHERE d.SerialNo = @sn
    UNION ALL
    SELECT h.HeldAt, N'锁定', CONCAT(h.Reason, N' by ', h.HeldBy), 4
    FROM HoldRecord h WHERE h.TargetType = N'Unit' AND h.TargetKey = @sn
    UNION ALL
    SELECT h.ReleasedAt, N'解锁', CONCAT(N'by ', h.ReleasedBy), 4
    FROM HoldRecord h WHERE h.TargetType = N'Unit' AND h.TargetKey = @sn AND h.ReleasedAt IS NOT NULL
    UNION ALL
    SELECT p.RepairedAt, N'维修', CONCAT(p.RefDes, N' ', p.Cause, N' -> ', p.Action, N' by ', p.RepairedBy), 5
    FROM RepairRecord p WHERE p.SerialNo = @sn
) x ORDER BY EventAt, Ord, Detail";

    // 完整性检查（缺记录检测）
    const string GapSql = @"
-- a. 板已推进到序号 N，但路线里 N 及以前的某一道没有 Pass 的过站记录
SELECT u.SerialNo, CONCAT(N'缺少工序 ', s.StepNo, N' ', s.StepCode, N' 的 Pass 记录') AS What
FROM Unit u
JOIN Route r ON r.ProductCode = u.ProductCode AND r.Status = 'Active'
JOIN RouteStep s ON s.RouteId = r.RouteId AND s.StepNo <= u.CurrentStepNo
WHERE u.SerialNo LIKE 'TR-%'
  AND NOT EXISTS (SELECT 1 FROM TrackRecord t WHERE t.SerialNo = u.SerialNo AND t.StepNo = s.StepNo AND t.Result = N'Pass')
UNION ALL
-- b. 贴片已出站，却没有物料快照
SELECT t.SerialNo, N'贴片已出站但没有物料快照'
FROM TrackRecord t
WHERE t.SerialNo LIKE 'TR-%' AND t.StepCode = N'MOUNT' AND t.Result = N'Pass'
  AND NOT EXISTS (SELECT 1 FROM UnitMaterial m WHERE m.SerialNo = t.SerialNo AND m.StepNo = t.StepNo)
UNION ALL
-- c. 同一道工序有不止一条 Pass（Fail 后再 Pass 是正常的，Pass 两次不正常）
SELECT t.SerialNo, CONCAT(N'工序 ', t.StepNo, N' 有 ', COUNT(*), N' 条 Pass 记录')
FROM TrackRecord t WHERE t.SerialNo LIKE 'TR-%' AND t.Result = N'Pass'
GROUP BY t.SerialNo, t.StepNo HAVING COUNT(*) > 1
ORDER BY SerialNo, What";

    static void Track(SqlSugarClient db, string sn, int stepNo, string code, string result, DateTime outAt, int sec = 30) =>
        db.Insertable(new TrackRecord
        {
            SerialNo = sn, WoId = "WO-TR-001", StepNo = stepNo, StepCode = code, Result = result, StationCode = Stations[code],
            OperatorCode = "OP001", InAt = outAt.AddSeconds(-sec), OutAt = outAt,
        }).ExecuteCommand();

    static void Board(SqlSugarClient db, string sn, int step, string status) =>
        db.Insertable(new Unit { SerialNo = sn, WoId = "WO-TR-001", ProductCode = Seed.Product, CurrentStepNo = step, Status = status, CreatedAt = T0 }).ExecuteCommand();

    static void Mount(SqlSugarClient db, string sn, string mcuLot)
    {
        db.Insertable(new List<UnitMaterial>
        {
            new() { SerialNo = sn, StepNo = 30, StationCode = "SMT-01", SlotNo = "S01", RefDes = "R1-R12", MaterialCode = "R-10K-0402", LotNo = "LOT-TR-R1" },
            new() { SerialNo = sn, StepNo = 30, StationCode = "SMT-01", SlotNo = "S02", RefDes = "C1-C8", MaterialCode = "C-100N-0402", LotNo = "LOT-TR-C1" },
            new() { SerialNo = sn, StepNo = 30, StationCode = "SMT-01", SlotNo = "S03", RefDes = "U1", MaterialCode = "IC-MCU-32", LotNo = mcuLot },
        }).ExecuteCommand();
    }

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(UnitMaterial), typeof(LotLink), typeof(ReflowRecord), typeof(DefectRecord), typeof(HoldRecord), typeof(RepairRecord));
        db.Deleteable<RepairRecord>().Where(r => r.SerialNo.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<HoldRecord>().Where(h => h.TargetKey.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<DefectRecord>().Where(d => d.SerialNo.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<ReflowRecord>().Where(r => r.Sn.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<UnitMaterial>().Where(m => m.SerialNo.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<TrackRecord>().Where(r => r.SerialNo.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<Unit>().Where(u => u.SerialNo.StartsWith("TR-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo == "WO-TR-001").ExecuteCommand();
        db.Insertable(new WorkOrder { WoNo = "WO-TR-001", ProductCode = Seed.Product, PlanQty = 100, Status = "Running", CreatedAt = T0 }).ExecuteCommand();

        // TR-0001：完整的一生，AOI 判过一次 Fail，被锁、被修、被放行，再重测通过
        Board(db, "TR-0001", 50, "Completed");
        Track(db, "TR-0001", 10, "PRINT", "Pass", At(0, 40)); Track(db, "TR-0001", 20, "SPI", "Pass", At(1, 20));
        Track(db, "TR-0001", 30, "MOUNT", "Pass", At(3, 10), 70); Track(db, "TR-0001", 40, "REFLOW", "Pass", At(9, 0), 240);
        Track(db, "TR-0001", 50, "AOI", "Fail", At(10, 30)); Track(db, "TR-0001", 50, "AOI", "Pass", At(40, 30));
        Mount(db, "TR-0001", "LOT-U-777");
        db.Insertable(new ReflowRecord { Sn = "TR-0001", ProfileName = "SAC305-A100", MaxRamp = 1.8m, PeakTemp = 243m, Tal = 62, Result = "OK", RecordedAt = At(9, 0) }).ExecuteCommand();
        int defectId = db.Insertable(new DefectRecord { SerialNo = "TR-0001", StepNo = 50, StationCode = "AOI-01", DefectCode = "SOLDER_OPEN", FoundAt = At(10, 30), Status = "Repaired" }).ExecuteReturnIdentity();
        db.Insertable(new HoldRecord { TargetType = "Unit", TargetKey = "TR-0001", Reason = "AOI 判 Fail：SOLDER_OPEN", HeldBy = "SYSTEM", HeldAt = At(10, 30), ReleasedBy = "QA01", ReleasedAt = At(35) }).ExecuteCommand();
        db.Insertable(new RepairRecord { SerialNo = "TR-0001", DefectId = defectId, RefDes = "U1", Cause = "引脚虚焊", Action = "补焊", RepairedBy = "RW01", RepairedAt = At(30) }).ExecuteCommand();

        // TR-0002：已经到了序号 50，但贴片(30)的过站记录丢了
        Board(db, "TR-0002", 50, "Completed");
        Track(db, "TR-0002", 10, "PRINT", "Pass", At(20, 40)); Track(db, "TR-0002", 20, "SPI", "Pass", At(21, 20));
        Track(db, "TR-0002", 40, "REFLOW", "Pass", At(30)); Track(db, "TR-0002", 50, "AOI", "Pass", At(31));
        // TR-0003：过站记录齐全，但贴片的物料快照没生成
        Board(db, "TR-0003", 50, "Completed");
        for (int i = 0; i < 5; i++) Track(db, "TR-0003", (i + 1) * 10, new[] { "PRINT", "SPI", "MOUNT", "REFLOW", "AOI" }[i], "Pass", At(40 + i));
        // TR-0004：SPI(20) 出站被记录了两次 Pass（设备重发）
        Board(db, "TR-0004", 20, "InProcess");
        Track(db, "TR-0004", 10, "PRINT", "Pass", At(50)); Track(db, "TR-0004", 20, "SPI", "Pass", At(51)); Track(db, "TR-0004", 20, "SPI", "Pass", At(51, 2));
        // TR-0005：正常在制，和 TR-0001 用了同一批 MCU（LOT-U-777）
        Board(db, "TR-0005", 30, "InProcess");
        Track(db, "TR-0005", 10, "PRINT", "Pass", At(60)); Track(db, "TR-0005", 20, "SPI", "Pass", At(61)); Track(db, "TR-0005", 30, "MOUNT", "Pass", At(62));
        Mount(db, "TR-0005", "LOT-U-777");

        // 1. 一块板的完整时间线
        var line = db.Ado.SqlQuery<TimelineRow>(TimelineSql, new { sn = "TR-0001" });
        Console.WriteLine($"1. TR-0001 的完整履历（共 {line.Count} 条事件，一条 SQL）：");
        foreach (var e in line) Console.WriteLine($"   {e.EventAt:HH:mm:ss} {e.Kind} {e.Detail}");

        // 2. 完整性检查
        var gaps = db.Ado.SqlQuery<GapRow>(GapSql);
        Console.WriteLine($"2. 完整性检查（TR- 开头的 5 块板）：发现 {gaps.Count} 处问题");
        foreach (var g in gaps) Console.WriteLine($"   {g.SerialNo} {g.What}");
        var clean = new[] { "TR-0001", "TR-0005" }.Where(sn => gaps.All(g => g.SerialNo != sn));
        Console.WriteLine($"   没有问题的板：{string.Join("、", clean)}");

        // 3. 客诉路径：客户退回 TR-0001，查 U1 的批次，再看同批次还有哪些板
        var mcu = db.Queryable<UnitMaterial>().First(m => m.SerialNo == "TR-0001" && m.RefDes == "U1");
        Console.WriteLine($"3. 客诉路径：客户退回 TR-0001 -> U1 用的是 {mcu.MaterialCode} 批次 {mcu.LotNo}");
        var same = LabMatTrace.Forward(db, mcu.LotNo);
        Console.WriteLine($"   同批次影响的板：{string.Join("、", same.Select(r => $"{r.SerialNo}({r.Status})"))}");
    }
}

读懂输出：

  • 场景 1：14 条事件和上面手写的表一致。同一时间点的事件按固定顺序排（过站 → 物料/炉温 → 不良 → 锁定/解锁 → 维修），ORDER BY EventAt, Ord, Detail 让输出稳定。注意"锁定"和"不良"都在 10:10:30，是因为 AOI 判 Fail 的那一刻同时发生。
  • 场景 2：5 块板里查出 3 处问题，每个都是我故意造的：TR-0002 缺贴片的 Pass 记录（规则 a）；TR-0003 贴片出站了但没有快照（规则 b）；TR-0004 的 SPI 有 2 条 Pass（规则 c）。TR-0001（有 Fail 又有 Pass，是正常的返修历史）和 TR-0005 没有被误报。

常见坑与排查 ​

误区 / 坑事实与办法
追溯查询很慢，一块板要几十秒记录表没有以板码开头的索引；用 SET STATISTICS IO ON 看逻辑读
把履历塞进一张宽表每种事件字段不同，宽表一堆空列还难归档。分表记录，查询时 UNION ALL
时间线顺序乱多设备时钟不一致。用 NTP 校时；同一时间点用固定的类别顺序打破平局
只做了正常路径的记录Fail、锁定、解锁、维修也要记，否则履历"太干净"，审核不可信
缺记录要等客户来抽查才发现把完整性规则写成定时任务，缺口进告警
归档后查不到归档不是删除。追溯入口要能同时查热数据和归档
查客诉板只看它自己还要横向：同批料、同炉、同班次，才能圈定范围
追溯数据保留期自己定看合同和行业要求，问品质和法务

练习题与答案 ​

  1. 一块板的履历至少包含哪几类信息？ 答：身份、过站、工艺参数、物料批次、检验、不良、锁定、返修（以及出货）。
  2. 为什么时间线查询用 UNION ALL 而不是 UNION？ 答：UNION 会去重，需要额外排序比较，还可能把两条真的一样的事件合并。履历要保留每一条事件，用 UNION ALL。
  3. 100 万行过站记录，按板码查，没有索引读了 16050 页，有索引只读 3 页。为什么索引能这么快？ 答：索引按板码有序，直接定位到那几行，不用逐页扫描；读页数只和这块板的行数有关，和总行数几乎无关。
  4. 完整性规则 a 为什么只数 Result = 'Pass' 的记录？ 答：一块板可以先 Fail 后返修再 Pass，那一道有两条记录是正常的；规则要检查的是"每道至少有一次合格出站"。规则 c 也只数 Pass，因为同一道有两次 Pass 才是重复。
  5. TR-0002 缺了贴片的过站记录，板却到了 AOI，可能是怎么发生的？ 答：贴片机上报的消息丢了，或有人手工改了 Unit.CurrentStepNo，没有写过站记录。要追查丢的原因，并补一条"更正"记录（不要偷偷插一条假的）。
  6. 客诉板的履历一切正常，怎么办？ 答：纵向没有线索时，横向看同批次、同日期、同设备的其它板有没有类似问题；也可能是设计或使用问题，转交研发。
  7. 为什么说"最危险的不是记录写错，而是记录不存在"？ 答：写错的记录至少能被发现和追查，不存在的记录没有任何痕迹，直到客户抽查才暴露。
  8. 按月分区后，只知道板码要查它的履历，会遇到什么问题？ 答：不知道板在哪个分区，可能要探测多个分区。解决：板码里带日期以便先判断分区，或接受对热分区都探一次的代价，实测后决定。
  9. 为什么追溯记录不能随意 UPDATE？ 答：被改过的记录无法证明可信。更正要追加新记录，保留旧记录和更正痕迹。
  10. 完整性检查应该多久跑一次？ 答：至少每班或每天一次，发现缺口越早越容易补；缺口数量要进监控看板，见 生产看板与实时报表。

小结 ​

  • 产品追溯 = 把一块板在各张记录表里的事件，按板码拼成时间线；核心套路是统一成三列的 UNION ALL + 按时间排序。
  • 纵向（一块板）找线索，横向（共享因素的一群板）圈范围；客诉到根因要两者结合。
  • 所有记录表都要有以板码开头的索引，实测 100 万行上差 5000 多倍；大表按月分区、归档，保留期看合同。
  • "完整"要靠检查来保证：缺过站、缺快照、重复，写成 SQL 定期跑。
  • 追溯数据只追加；更正追加不修改。
