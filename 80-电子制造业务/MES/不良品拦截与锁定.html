不良品拦截与锁定

AI 生成 · 待核对制造业务MES质量防错更新于 2026-10-21

⚠ 待核对：不良发现后"自动锁定"还是"人工判定后锁定"、谁有权解锁、批次锁定是否联动库存冻结、状态名称，都是电子厂常见的通用做法，你们自研 MES 的流程、角色权限、状态名都可能不同，请对照你们的系统。缺陷代码字典不在本篇，参见 缺陷代码与不良分类，MES 里先存代码字符串。代码和输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 15 篇。过站与工序流转 里 Fail 的板会变成 Hold，但那里只改了一个状态，没有记"为什么锁、谁锁、谁解"。本篇补上：不良记录、锁定单、批次级锁定、解锁权限与留痕、并发安全。读完你应该能：说清从发现不良到处置的全流程；设计 DefectRecord 和 HoldRecord；写出"锁板、进站被拦、按物料批次批量锁板、解锁留痕"的代码；解释为什么锁定要靠条件 UPDATE 和数据库唯一索引。

一句话定义 ​

不良品拦截与锁定是：发现不良（或怀疑不良）后，系统立即把那块板（或那一批料、那张工单）标成"锁定"，在进站检查里拒绝它继续流转，直到有权限的人评审处置并解锁，整个过程留下记录。

先修知识 ​

  • 过站与工序流转：Unit 的四个状态（InProcess、Hold、Completed、Scrapped）、条件 UPDATE、进站检查清单。
  • 物料追溯与批次关联：UnitMaterial、LotLink，批次级锁定靠它找出受影响的板。本篇实验调用它的 Forward。
  • 缺陷代码与不良分类：不良代码的字典与分类（MES 里先存代码字符串）。
  • 不合格品控制NCR：质量体系里对不合格品的处置流程，本篇是它在 MES 里的"执行端"。

它解决什么问题 ​

看一个没有锁定机制的车间：

  • AOI 判某块板"桥连"Fail，操作员把它拿下来放在旁边的筐里。半小时后换班，新来的操作员看到筐里一堆板，以为是待测的好板，又放回了传送带。系统里这块板的状态只是"AOI Fail"，下一站没有任何东西拦它。
  • 品质发现一批电阻（LOT-HD-100）有问题，在系统里冻结了库存，却不知道已经有 5 块板用了这批料：3 块在线上，1 块已入库，1 块在返修。线上的 3 块继续往下走，到了客户手里才发现。
  • 有人把一块不良板"解锁"放行了，三个月后客户投诉同一块板，没有人记得是谁放的、凭什么放的。

三个问题对应三件事：拦得住（系统强制，不靠人记性）、圈得准（批次问题能找出所有受影响的板）、留得下（谁在什么时候出于什么原因锁、解，全有记录）。

核心概念 ​

流程：从发现到处置 ​

不良发现的来源 ​

来源谁判特点
AOI（自动光学检查）设备量大、速度快，有误判，需要人复判
SPI（锡膏检测）设备在贴片之前，越早拦住损失越小
ICT（在线测试）/ FCT（功能测试）设备/测试架电气问题，通常要定位到位号
目检人灵活，但容易漏，要记录是谁判的
后续工序发现的人/设备比如装配时发现焊点问题，要回溯到责任工序

这些来源最后都落成一条 DefectRecord：哪块板、在第几道工序、哪个工站、什么不良代码、什么时候发现。

两个实体 ​

  • DefectRecord：不良记录。一次检验发现的一个不良一行。它是记录类，但 Status 会随处理推进：Open（刚发现）→ Repairing（返修中）→ Repaired（修好了）或 Scrapped（报废了）。
  • HoldRecord：锁定单。对一块板（Unit）、一个料批次（Lot）或一张工单（WorkOrder）的一次锁定，记录原因、谁锁、什么时候锁、谁解、什么时候解。ReleasedAt 为空表示还在锁定中。解锁只补填 Released*，不删除不修改其它列，历史就在那里。

两者分工：不良记录回答"发现了什么问题"，锁定单回答"为此采取了什么行动、谁负责"。一块板一次 Fail 通常产生一条不良记录和一张锁定单，但批次锁定一张批次单会连带多张板的锁定单。

板级与批次级锁定 ​

层级触发动作
板级一块板 Fail，或品质怀疑某块板这块板 Unit.Status = Hold + 一张 Unit 锁定单
批次级发现某物料批次有问题找出所有用过该批次（含拆出的子批次）的板：在制的锁定；已完工在库的冻结库存；已发货的通知；批次本身开一张 Lot 锁定单，同时通知仓库冻结库存（库存状态见 库存管理与批次序列号）
工单级工艺文件错了、整张工单要停工单暂停，见 工单管理

批次级是难点：它依赖前一篇的正向追溯。找出来的板按状态分类：

板的状态怎么处理
在制（InProcess）条件 UPDATE 锁定，开板级锁定单
已在锁定（Hold）不重复锁，只做标记
已完工（Completed）板已经不在产线上，MES 锁不住：要通知仓库冻结成品库存、拦截未发出的货
已报废（Scrapped）不用处理
已出货超出 MES 的范围，转入客户通知与召回流程（见 客诉与RMA）

与 NCR 的关系 ​

锁定是 MES 的"现场动作"，NCR（Non-Conformance Report，不合格品报告）是质量体系的"文件流程"：评审、处置（返工、让步接收、报废）、责任归属、纠正措施（见 不合格品控制NCR、8D与CAPA）。联动方式：批次级锁定或严重不良自动触发 NCR；NCR 评审结论反过来驱动 MES 解锁、返修或报废。MES 里的 HoldRecord 可以带 NCR 单号（本篇的最小模型没有放，需要时加一列）。

业务视角 ​

角色在锁定里做什么
操作员发现不良时按键判 Fail，板被自动锁定；被拦下时按提示送去评审
线长看锁定板的数量与分布；批次问题时配合隔离
品质工程师评审锁定的板，决定返修、复判、报废；有权解锁；发起批次锁定
维修员处理被锁定的不良板（见 返修与维修管理）
仓库接批次锁定通知，冻结库存

规则：

  1. 锁定可以由任何人、任何系统（AOI 自动判、操作员、品质）发起，宁可错锁，不要漏锁；
  2. 解锁必须有权限，通常只有品质（板级可以到主管）；批次级只有品质；
  3. 还有未处理完的不良记录，不能解锁；
  4. 解锁要有原因（至少有解锁人和时间），重大的还要 NCR 单号；
  5. 同一对象同一时刻只允许一张未解除的锁定单。

KPI：锁定板数与时长（越长越占用现场）、各不良代码的占比（帕累托）、误判率（复判放行比例）、批次锁定响应时间（从发现到所有在制被锁的分钟数）。

技术视角 ​

表设计 ​

sql
CREATE TABLE DefectRecord (
    Id          int IDENTITY(1,1) NOT NULL CONSTRAINT PK_DefectRecord PRIMARY KEY,
    SerialNo    nvarchar(40) NOT NULL,
    StepNo      int          NOT NULL,
    StationCode nvarchar(30) NOT NULL,
    DefectCode  nvarchar(20) NOT NULL,
    FoundAt     datetime     NOT NULL CONSTRAINT DF_Defect_Found DEFAULT GETDATE(),
    Status      nvarchar(20) NOT NULL CONSTRAINT DF_Defect_Status DEFAULT N'Open',
    CONSTRAINT CK_Defect_Status CHECK (Status IN (N'Open', N'Repairing', N'Repaired', N'Scrapped'))
);
CREATE INDEX IX_DefectRecord_Sn ON DefectRecord(SerialNo);
-- 待处理队列：只给还没处理完的行建索引
CREATE INDEX IX_DefectRecord_Pending ON DefectRecord(Status, FoundAt) WHERE Status IN (N'Open', N'Repairing');

CREATE TABLE HoldRecord (
    Id          int IDENTITY(1,1) NOT NULL CONSTRAINT PK_HoldRecord PRIMARY KEY,
    TargetType  nvarchar(10)  NOT NULL CONSTRAINT CK_Hold_Type CHECK (TargetType IN (N'Unit', N'Lot', N'WorkOrder')),
    TargetKey   nvarchar(50)  NOT NULL,
    Reason      nvarchar(200) NOT NULL,
    HeldBy      nvarchar(30)  NOT NULL,
    HeldAt      datetime      NOT NULL CONSTRAINT DF_Hold_HeldAt DEFAULT GETDATE(),
    ReleasedBy  nvarchar(30)  NULL,
    ReleasedAt  datetime      NULL,
    -- 要么都空（还在锁定），要么都有（已解锁）
    CONSTRAINT CK_Hold_Release CHECK ((ReleasedBy IS NULL AND ReleasedAt IS NULL) OR (ReleasedBy IS NOT NULL AND ReleasedAt IS NOT NULL))
);
CREATE INDEX IX_HoldRecord_Target ON HoldRecord(TargetType, TargetKey);
-- 同一个对象同一时刻最多一张未解除的锁定单
CREATE UNIQUE INDEX UX_HoldRecord_Open ON HoldRecord(TargetType, TargetKey) WHERE ReleasedAt IS NULL;

用 sqlcmd 执行这段脚本要加 -I（QUOTED_IDENTIFIER ON），否则创建筛选索引会报错 1934：筛选索引要求会话的这个选项为 ON（据微软文档）。SqlSugar 通过 SqlClient 连接时默认就是 ON，所以实验里用 ExecuteCommand 建这个索引没问题。

几个设计点：

  1. CHECK 约束守住枚举和成对关系：Status 只能是四个值；ReleasedBy 和 ReleasedAt 必须同时为空或同时有值（我试过只填 ReleasedBy 会被拒绝，错误 547）。
  2. 筛选唯一索引 UX_HoldRecord_Open：对 ReleasedAt IS NULL 的行，(TargetType, TargetKey) 唯一，也就是"同一对象同一时刻最多一张未解除的锁定单"；解除过的历史单不受限制。我试过连续插入两张未解除的单，第二张报错 2601（重复键）。这样即使有人绕过程序直接写库，也不会出现重复锁定。
  3. 待处理队列用筛选索引：DefectRecord 里 Open、Repairing 的行只占极少数，筛选索引小而快，品质每天看"待处理不良清单"就靠它。
  4. Unit.Status 与 HoldRecord 的一致性：Unit.Status = 'Hold' 的板应该有且只有一张未解除的 Unit 锁定单。这个一致性靠事务（两个写入同成功同失败）保证，并可以用检查 SQL 定期核对。

锁板：条件 UPDATE + 开锁定单 ​

sql
BEGIN TRAN
  UPDATE Unit SET Status = N'Hold' WHERE SerialNo = @sn AND Status = N'InProcess';  -- 受影响行数必须是 1
  INSERT HoldRecord (TargetType, TargetKey, Reason, HeldBy) VALUES (N'Unit', @sn, @reason, @by);
COMMIT

受影响行数是 0 说明板已经不是在制（已锁、已完工、已报废，或者不存在），不要再开单。两个终端同时锁同一块板时，只有一个条件 UPDATE 得到 1 行；即使有一方漏掉了条件，唯一索引还会拦第二张单。

出站 Fail：一个事务做四件事 ​

过站篇的 Fail 路径要升级成：条件 UPDATE 锁板、追加 TrackRecord（Fail）、追加 DefectRecord（Open）、追加 HoldRecord，同一个事务。只做前两件的话，板锁了却没有不良记录，评审时没人知道为什么。

进站检查里的锁定提示 ​

进站检查发现 Status = 'Hold' 时，把锁定原因读出来告诉操作员，而不是只说"已锁定"。原因来自该板未解除的锁定单（TargetType = 'Unit' AND TargetKey = @sn AND ReleasedAt IS NULL）。操作员知道是"AOI 桥连"还是"批次异常"，才知道该送去维修还是等品质通知。

锁定的即时生效 ​

锁板之后，其它终端正在进行的出站应当失败。这靠出站的条件 UPDATE 里的 Status = 'InProcess'：板被锁成 Hold，条件不满足，得到 0 行，出站被拒绝。实验场景 7 演示：终端 A 进站检查通过，品质此时锁板，A 出站被拒绝，过站记录没有增加。不需要给板加行锁，也不需要通知其它终端。

批次级锁定 ​

  1. 调用正向追溯（含 LotLink 子批次）找出所有用过该批次的板；
  2. 开一张 Lot 锁定单；
  3. 逐块板：在制的 → 条件 UPDATE + 开板级锁定单（Reason 以 LOT:批次号 开头，用来在解锁批次时认出"因为这个批次才被锁"的板）；其余状态只统计；
  4. 同一个事务；
  5. 把已完工的板、库存的批次通知仓库（见 WMS与MES交互）。

注意：批次锁定之后，新上线的板也要拦：每次贴片出站生成快照时，如果快照里有被锁定的批次，要把这块板直接锁住。更好的是上料环节就拒绝上被锁批次的料（见 SMT上料防错与站位表）。本篇没有实现这一步，实验的"批次解锁"用 Reason 前缀识别也只是教学简化：真实系统应该在板级锁定单上加一列 ParentHoldId 指向批次单。

权限与留痕 ​

  • 角色：操作员可以锁，不能解；品质/主管可以解板；只有品质能解批次。实验里用一个写死的字典模拟，真实系统用用户与角色表。
  • 留痕：HoldRecord 保留所有历史，HeldBy/ReleasedBy/时间都在。再重要的操作（批次解锁）可以加 NCR 单号和电子签名，这属于权限与审计模块，不在本篇范围。
  • 不要提供"删除锁定单"的功能，删掉就是销毁证据。

逐步例子：一块板的锁定与一个批次的锁定 ​

板级： 板 HD-0007 在 AOI 出站判 Fail（桥连 SOLDER_BRIDGE）。系统在一个事务里：Unit 变 Hold、追加过站记录（Fail）、追加不良记录（Open）、开一张锁定单（原因"AOI 判 Fail：SOLDER_BRIDGE"，锁定人 SYSTEM）。操作员想让它再进 AOI，被拒绝，提示里带着原因。有人（QA01）又想手工锁，因为已经是 Hold，被拒绝，锁定单仍是 1 张。操作员 OP001 想解锁，无权限；QA01 想解锁，被拦，因为不良记录还是 Open；返修完成、不良变 Repaired 后，QA01 解锁成功，锁定单上留下 ReleasedBy = QA01。

批次级： 批次 LOT-HD-100 的电阻来料焊端氧化。系统找出用过它的 5 块板：

板状态处理
HD-0001在制锁定
HD-0002在制锁定
HD-0003已完工无法锁，通知仓库冻结成品和出货
HD-0004已报废不处理
HD-0006已锁定（自己的不良）不重复锁

新锁 2 块，加 1 张批次锁定单。等品质复判认为问题可控，解锁批次时，只解开因这个批次被锁的 2 块板，HD-0006 因为自己的不良还没处理，仍保持锁定。

第 2 步：新建 LabHold.cs。这个文件的 Advance、HoldUnit、ReleaseUnit 等方法是 public static，下一篇 返修与维修管理 的实验会直接调用：

csharp
using SqlSugar;

namespace MiniMes;

// 不良拦截与锁定实验：记录不良 -> 锁板 -> 进站被拦 -> 批次级批量锁定 -> 解锁留痕 -> 并发
public static class LabHold
{
    // 谁能干什么：真实系统查用户和角色表，这里写死几个
    static readonly Dictionary<string, string> Roles = new() { ["OP001"] = "Operator", ["QA01"] = "QA", ["QA02"] = "QA", ["SUP01"] = "Supervisor" };
    static bool CanRelease(string user, string targetType) =>
        targetType == "Lot" ? Roles.GetValueOrDefault(user) == "QA" : Roles.GetValueOrDefault(user) is "QA" or "Supervisor";

    static readonly Dictionary<string, string> Stations = new()
    {
        ["PRINT"] = "PRN-01", ["SPI"] = "SPI-01", ["MOUNT"] = "SMT-01", ["REFLOW"] = "RFL-01", ["AOI"] = "AOI-01",
    };

    public static List<RouteStep> Steps(SqlSugarClient db)
    {
        var route = db.Queryable<Route>().First(r => r.ProductCode == Seed.Product && r.Status == "Active");
        return db.Queryable<RouteStep>().Where(s => s.RouteId == route.RouteId).OrderBy(s => s.StepNo).ToList();
    }

    public static void NewBoard(SqlSugarClient db, string sn, string wo, int stepNo, string status) =>
        db.Insertable(new Unit { SerialNo = sn, WoId = wo, ProductCode = Seed.Product, CurrentStepNo = stepNo, Status = status, CreatedAt = DateTime.Now }).ExecuteCommand();

    // 进站检查（在过站篇的基础上，多一条：板被锁定时，把锁定原因告诉操作员）
    public static string TryEnter(SqlSugarClient db, string sn, string stepCode)
    {
        var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
        if (u == null) return "拒绝（板码不存在）";
        if (u.Status == "Hold")
        {
            var h = db.Queryable<HoldRecord>().First(x => x.TargetType == "Unit" && x.TargetKey == sn && x.ReleasedAt == null);
            return $"拒绝（已锁定：{h?.Reason ?? "没有锁定单，请查 Unit 状态"}）";
        }
        if (u.Status != "InProcess") return $"拒绝（板状态是 {u.Status}）";
        var next = Steps(db).FirstOrDefault(s => s.StepNo > u.CurrentStepNo);
        if (next == null) return "拒绝（所有工序已完成）";
        return next.StepCode == stepCode ? "允许进站" : $"拒绝（下一道应该是 {next.StepCode}）";
    }

    // 出站 Pass：条件 UPDATE + 追加过站记录，一个事务。返回 false 表示板已被锁定或被别的终端处理
    public static bool ExitPass(SqlSugarClient db, string sn, int prev, RouteStep step, bool isLast)
    {
        string newStatus = isLast ? "Completed" : "InProcess";
        int stepNo = step.StepNo;
        db.Ado.BeginTran();
        try
        {
            int n = db.Updateable<Unit>().SetColumns(x => new Unit { CurrentStepNo = stepNo, Status = newStatus })
                .Where(x => x.SerialNo == sn && x.CurrentStepNo == prev && x.Status == "InProcess").ExecuteCommand();
            if (n != 1) { db.Ado.RollbackTran(); return false; }
            var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
            db.Insertable(new TrackRecord
            {
                SerialNo = sn, WoId = u.WoId, StepNo = stepNo, StepCode = step.StepCode, Result = "Pass",
                StationCode = Stations[step.StepCode], OperatorCode = "OP001", InAt = DateTime.Now.AddSeconds(-30), OutAt = DateTime.Now,
            }).ExecuteCommand();
            db.Ado.CommitTran();
            return true;
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    // 出站 Fail：一个事务里做四件事：条件 UPDATE 锁板、追加过站记录、记不良、开锁定单
    public static void ExitFail(SqlSugarClient db, string sn, string stepCode, string defectCode)
    {
        var steps = Steps(db);
        var step = steps.First(s => s.StepCode == stepCode);
        var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
        int prev = u.CurrentStepNo;
        db.Ado.BeginTran();
        try
        {
            int n = db.Updateable<Unit>().SetColumns(x => new Unit { Status = "Hold" })
                .Where(x => x.SerialNo == sn && x.CurrentStepNo == prev && x.Status == "InProcess").ExecuteCommand();
            if (n != 1) { db.Ado.RollbackTran(); throw new InvalidOperationException("别的终端已经处理了这块板"); }
            var now = DateTime.Now;
            db.Insertable(new TrackRecord
            {
                SerialNo = sn, WoId = u.WoId, StepNo = step.StepNo, StepCode = stepCode, Result = "Fail",
                StationCode = Stations[stepCode], OperatorCode = "OP001", InAt = now.AddSeconds(-30), OutAt = now,
            }).ExecuteCommand();
            db.Insertable(new DefectRecord { SerialNo = sn, StepNo = step.StepNo, StationCode = Stations[stepCode], DefectCode = defectCode, FoundAt = now, Status = "Open" }).ExecuteCommand();
            db.Insertable(new HoldRecord { TargetType = "Unit", TargetKey = sn, Reason = $"{stepCode} 判 Fail：{defectCode}", HeldBy = "SYSTEM", HeldAt = now }).ExecuteCommand();
            db.Ado.CommitTran();
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    // 一次完整过站（进站检查 + 出站）
    public static string Advance(SqlSugarClient db, string sn, string stepCode, string result = "Pass", string defectCode = null)
    {
        var msg = TryEnter(db, sn, stepCode);
        if (msg != "允许进站") return msg;
        if (result == "Fail") { ExitFail(db, sn, stepCode, defectCode); return $"进站通过 -> 出站 Fail（{defectCode}），已锁板"; }
        var steps = Steps(db);
        var u = db.Queryable<Unit>().First(x => x.SerialNo == sn);
        var step = steps.First(s => s.StepNo > u.CurrentStepNo);
        return ExitPass(db, sn, u.CurrentStepNo, step, step.StepNo == steps.Max(s => s.StepNo)) ? "进站通过 -> 出站 Pass" : "拒绝（板已被锁定或被别的终端处理）";
    }

    // 锁一块板：条件 UPDATE（只有在制的板才能锁）+ 开锁定单，一个事务。已有未解除的锁定单会被唯一索引拒绝
    public static (bool Ok, string Msg) HoldUnit(SqlSugarClient db, string sn, string reason, string by)
    {
        if (!Roles.ContainsKey(by)) return (false, "未知用户");
        db.Ado.BeginTran();
        try
        {
            int n = db.Updateable<Unit>().SetColumns(x => new Unit { Status = "Hold" })
                .Where(x => x.SerialNo == sn && x.Status == "InProcess").ExecuteCommand();
            if (n != 1) { db.Ado.RollbackTran(); return (false, "板不存在或不是在制状态（可能已被锁定）"); }
            db.Insertable(new HoldRecord { TargetType = "Unit", TargetKey = sn, Reason = reason, HeldBy = by, HeldAt = DateTime.Now }).ExecuteCommand();
            db.Ado.CommitTran();
            return (true, "已锁定");
        }
        catch (Exception e) when (e.Message.Contains("UX_HoldRecord_Open"))
        {
            db.Ado.RollbackTran();
            return (false, "已有未解除的锁定单");
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    // 解锁一块板：要有权限；还有未处理完的不良记录不能解；关锁定单 + 板恢复在制，一个事务
    public static (bool Ok, string Msg) ReleaseUnit(SqlSugarClient db, string sn, string by)
    {
        if (!CanRelease(by, "Unit")) return (false, "无权限（只有品质或主管能解锁）");
        if (db.Queryable<DefectRecord>().Any(d => d.SerialNo == sn && (d.Status == "Open" || d.Status == "Repairing")))
            return (false, "还有未关闭的不良记录");
        var now = DateTime.Now;
        db.Ado.BeginTran();
        try
        {
            int h = db.Updateable<HoldRecord>().SetColumns(x => new HoldRecord { ReleasedBy = by, ReleasedAt = now })
                .Where(x => x.TargetType == "Unit" && x.TargetKey == sn && x.ReleasedAt == null).ExecuteCommand();
            int u = db.Updateable<Unit>().SetColumns(x => new Unit { Status = "InProcess" })
                .Where(x => x.SerialNo == sn && x.Status == "Hold").ExecuteCommand();
            if (h != 1 || u != 1) { db.Ado.RollbackTran(); return (false, "没有可解除的锁定"); }
            db.Ado.CommitTran();
            return (true, "已解锁");
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    // 批次级锁定：批次（含拆出的子批次）用到的所有板，在制的全锁；同时开一张批次锁定单（库存冻结由 WMS 接这张单）
    public static string HoldLot(SqlSugarClient db, string lot, string reason, string by)
    {
        var affected = LabMatTrace.Forward(db, lot);
        var units = db.Queryable<Unit>().Where(u => SqlFunc.ContainsArray(affected.Select(a => a.SerialNo).ToArray(), u.SerialNo)).OrderBy(u => u.SerialNo).ToList();
        var held = new List<string>(); var already = new List<string>(); var done = new List<string>(); var scrapped = new List<string>();
        db.Ado.BeginTran();
        try
        {
            db.Insertable(new HoldRecord { TargetType = "Lot", TargetKey = lot, Reason = reason, HeldBy = by, HeldAt = DateTime.Now }).ExecuteCommand();
            foreach (var u in units)
            {
                string sn = u.SerialNo;
                if (u.Status == "Completed") done.Add(sn);
                else if (u.Status == "Scrapped") scrapped.Add(sn);
                else if (u.Status == "Hold") already.Add(sn);
                else
                {
                    int n = db.Updateable<Unit>().SetColumns(x => new Unit { Status = "Hold" }).Where(x => x.SerialNo == sn && x.Status == "InProcess").ExecuteCommand();
                    if (n != 1) { already.Add(sn); continue; }
                    db.Insertable(new HoldRecord { TargetType = "Unit", TargetKey = sn, Reason = $"LOT:{lot} {reason}", HeldBy = by, HeldAt = DateTime.Now }).ExecuteCommand();
                    held.Add(sn);
                }
            }
            db.Ado.CommitTran();
        }
        catch { db.Ado.RollbackTran(); throw; }
        string L(List<string> l) => l.Count == 0 ? "无" : string.Join("、", l);
        return $"影响 {units.Count} 块板；新锁定 {held.Count} 块（{L(held)}）；本来就在锁定 {already.Count} 块（{L(already)}）；已完工 {done.Count} 块（{L(done)}，要另行拦截库存和出货）；已报废 {scrapped.Count} 块（{L(scrapped)}）";
    }

    // 批次解锁：只有品质能解；关批次单，并解开"因为这个批次才被锁"的那些板（靠 Reason 前缀 LOT:批次号 识别）
    public static (bool Ok, string Msg) ReleaseLot(SqlSugarClient db, string lot, string by)
    {
        if (!CanRelease(by, "Lot")) return (false, "无权限（批次解锁只有品质能做）");
        var now = DateTime.Now;
        string prefix = $"LOT:{lot} ";
        int units = 0;
        db.Ado.BeginTran();
        try
        {
            int n = db.Updateable<HoldRecord>().SetColumns(x => new HoldRecord { ReleasedBy = by, ReleasedAt = now })
                .Where(x => x.TargetType == "Lot" && x.TargetKey == lot && x.ReleasedAt == null).ExecuteCommand();
            if (n != 1) { db.Ado.RollbackTran(); return (false, "没有未解除的批次锁定单"); }
            var holds = db.Queryable<HoldRecord>().Where(x => x.TargetType == "Unit" && x.ReleasedAt == null && x.Reason.StartsWith(prefix)).ToList();
            foreach (var h in holds)
            {
                string sn = h.TargetKey;
                db.Updateable<HoldRecord>().SetColumns(x => new HoldRecord { ReleasedBy = by, ReleasedAt = now }).Where(x => x.Id == h.Id).ExecuteCommand();
                units += db.Updateable<Unit>().SetColumns(x => new Unit { Status = "InProcess" }).Where(x => x.SerialNo == sn && x.Status == "Hold").ExecuteCommand();
            }
            db.Ado.CommitTran();
            return (true, $"批次单已解除，同时解开 {units} 块板");
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    static string Status(SqlSugarClient db, string sn) => db.Queryable<Unit>().First(x => x.SerialNo == sn).Status;
    static int OpenHolds(SqlSugarClient db, string key) => db.Queryable<HoldRecord>().Count(h => h.TargetKey == key && h.ReleasedAt == null);
    static int AllHolds(SqlSugarClient db, string key) => db.Queryable<HoldRecord>().Count(h => h.TargetKey == key);

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(UnitMaterial), typeof(LotLink), typeof(DefectRecord), typeof(HoldRecord));
        db.Deleteable<HoldRecord>().Where(h => h.TargetKey.StartsWith("HD-") || h.TargetKey.StartsWith("LOT-HD-")).ExecuteCommand();
        // 数据库层面的保险：同一个对象同一时刻最多只能有一张未解除的锁定单
        db.Ado.ExecuteCommand(@"
IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'UX_HoldRecord_Open')
    CREATE UNIQUE INDEX UX_HoldRecord_Open ON HoldRecord(TargetType, TargetKey) WHERE ReleasedAt IS NULL;");
        db.Deleteable<DefectRecord>().Where(d => d.SerialNo.StartsWith("HD-")).ExecuteCommand();
        db.Deleteable<UnitMaterial>().Where(m => m.SerialNo.StartsWith("HD-")).ExecuteCommand();
        db.Deleteable<TrackRecord>().Where(r => r.SerialNo.StartsWith("HD-")).ExecuteCommand();
        db.Deleteable<Unit>().Where(u => u.SerialNo.StartsWith("HD-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo.StartsWith("WO-HD-")).ExecuteCommand();
        db.Insertable(new WorkOrder { WoNo = "WO-HD-001", ProductCode = Seed.Product, PlanQty = 100, Status = "Running", CreatedAt = DateTime.Now }).ExecuteCommand();

        // 造板：0001-0004、0006 都用了 LOT-HD-100 的电阻；0005 用的是 LOT-HD-200
        foreach (var (sn, step, st, lot) in new[]
        {
            ("HD-0001", 30, "InProcess", "LOT-HD-100"), ("HD-0002", 40, "InProcess", "LOT-HD-100"), ("HD-0003", 50, "Completed", "LOT-HD-100"),
            ("HD-0004", 30, "Scrapped", "LOT-HD-100"), ("HD-0005", 30, "InProcess", "LOT-HD-200"), ("HD-0006", 40, "Hold", "LOT-HD-100"),
        })
        {
            NewBoard(db, sn, "WO-HD-001", step, st);
            db.Insertable(new UnitMaterial { SerialNo = sn, StepNo = 30, StationCode = "SMT-01", SlotNo = "S01", RefDes = "R1-R12", MaterialCode = "R-10K-0402", LotNo = lot }).ExecuteCommand();
        }
        db.Insertable(new HoldRecord { TargetType = "Unit", TargetKey = "HD-0006", Reason = "AOI 判 Fail：SOLDER_OPEN", HeldBy = "SYSTEM", HeldAt = DateTime.Now }).ExecuteCommand();
        db.Insertable(new DefectRecord { SerialNo = "HD-0006", StepNo = 50, StationCode = "AOI-01", DefectCode = "SOLDER_OPEN", FoundAt = DateTime.Now, Status = "Open" }).ExecuteCommand();
        foreach (var sn in new[] { "HD-0007", "HD-0008", "HD-0009" }) NewBoard(db, sn, "WO-HD-001", sn == "HD-0008" ? 10 : sn == "HD-0007" ? 40 : 30, "InProcess");

        // 1. 不良发现 -> 自动锁板 -> 进站被拦
        Console.WriteLine("1. 不良发现 -> 锁板：HD-0007 在 AOI 出站判 Fail（SOLDER_BRIDGE 桥连）");
        Console.WriteLine($"   {Advance(db, "HD-0007", "AOI", "Fail", "SOLDER_BRIDGE")}");
        var d7 = db.Queryable<DefectRecord>().First(d => d.SerialNo == "HD-0007");
        Console.WriteLine($"   板状态 {Status(db, "HD-0007")}；不良记录 {d7.DefectCode}（{d7.Status}）；未解除的锁定单 {OpenHolds(db, "HD-0007")} 张");
        Console.WriteLine($"   想再进 AOI -> {TryEnter(db, "HD-0007", "AOI")}");

        // 2. 重复锁定
        var r2 = HoldUnit(db, "HD-0007", "品质复查", "QA01");
        Console.WriteLine($"2. 重复锁定：QA01 再申请锁 HD-0007 -> {(r2.Ok ? "成功" : "拒绝")}（{r2.Msg}）；锁定单共 {AllHolds(db, "HD-0007")} 张");

        // 3. 解锁权限与留痕
        Console.WriteLine("3. 解锁：");
        var a = ReleaseUnit(db, "HD-0007", "OP001"); Console.WriteLine($"   OP001 解锁 -> {(a.Ok ? "成功" : "拒绝")}（{a.Msg}）");
        var b = ReleaseUnit(db, "HD-0007", "QA01"); Console.WriteLine($"   QA01 解锁（不良还是 Open）-> {(b.Ok ? "成功" : "拒绝")}（{b.Msg}）");
        db.Updateable<DefectRecord>().SetColumns(d => new DefectRecord { Status = "Repaired" }).Where(d => d.SerialNo == "HD-0007").ExecuteCommand();
        var c = ReleaseUnit(db, "HD-0007", "QA01"); Console.WriteLine($"   不良处理完后 QA01 解锁 -> {(c.Ok ? "成功" : "拒绝")}（{c.Msg}）；板状态 {Status(db, "HD-0007")}");
        var h7 = db.Queryable<HoldRecord>().First(h => h.TargetKey == "HD-0007");
        Console.WriteLine($"   锁定单留痕：HeldBy {h7.HeldBy}，ReleasedBy {h7.ReleasedBy}，共 {AllHolds(db, "HD-0007")} 张（已解除 {AllHolds(db, "HD-0007") - OpenHolds(db, "HD-0007")} 张）");

        // 4. 批次级锁定
        Console.WriteLine("4. 批次级锁定：QA01 发现 LOT-HD-100 的电阻来料有问题");
        Console.WriteLine($"   {HoldLot(db, "LOT-HD-100", "来料焊端氧化", "QA01")}");
        Console.WriteLine($"   批次锁定单 {OpenHolds(db, "LOT-HD-100")} 张；HD-0001 想进 REFLOW -> {TryEnter(db, "HD-0001", "REFLOW")}");
        Console.WriteLine($"   HD-0005（用的是 LOT-HD-200）想进 REFLOW -> {TryEnter(db, "HD-0005", "REFLOW")}");

        // 5. 批次解锁
        var e = ReleaseLot(db, "LOT-HD-100", "OP001"); Console.WriteLine($"5. 批次解锁：OP001 -> {(e.Ok ? "成功" : "拒绝")}（{e.Msg}）");
        var f = ReleaseLot(db, "LOT-HD-100", "QA02"); Console.WriteLine($"   QA02 -> {(f.Ok ? "成功" : "拒绝")}（{f.Msg}）");
        Console.WriteLine($"   HD-0001 {Status(db, "HD-0001")}，HD-0002 {Status(db, "HD-0002")}；HD-0006 {Status(db, "HD-0006")}（它自己的不良还没处理）");

        // 6. 并发：两个终端同时锁同一块板
        var barrier = new Barrier(2);
        var res = new bool[2];
        var threads = Enumerable.Range(0, 2).Select(i => new Thread(() =>
        {
            var d = Db.Create();
            barrier.SignalAndWait();
            res[i] = HoldUnit(d, "HD-0008", "两个人同时发现问题", i == 0 ? "QA01" : "QA02").Ok;
        })).ToList();
        threads.ForEach(t => t.Start()); threads.ForEach(t => t.Join());
        Console.WriteLine($"6. 并发：两个终端同时锁 HD-0008 -> 成功 {res.Count(x => x)} 个，被拒绝 {res.Count(x => !x)} 个；锁定单 {AllHolds(db, "HD-0008")} 张");

        // 7. 进站检查通过之后、出站之前被锁：出站必须失败
        var steps = Steps(db);
        var u9 = db.Queryable<Unit>().First(x => x.SerialNo == "HD-0009");
        Console.WriteLine($"7. 进站后被锁：HD-0009 在终端 A 通过进站检查 -> {TryEnter(db, "HD-0009", "REFLOW")}");
        Console.WriteLine($"   此时 QA01 锁板 -> {HoldUnit(db, "HD-0009", "怀疑锡膏过期", "QA01").Msg}");
        bool ok9 = ExitPass(db, "HD-0009", u9.CurrentStepNo, steps.First(s => s.StepCode == "REFLOW"), false);
        Console.WriteLine($"   终端 A 出站 -> {(ok9 ? "成功" : "拒绝（板已被锁定）")}；HD-0009 过站记录 {db.Queryable<TrackRecord>().Count(r => r.SerialNo == "HD-0009")} 条，当前工序 {db.Queryable<Unit>().First(x => x.SerialNo == "HD-0009").CurrentStepNo}");
    }
}

常见坑与排查 ​

误区 / 坑事实与办法
只改 Unit.Status，不开锁定单没人知道为什么锁、谁锁的。状态和锁定单同一个事务
进站只说"已锁定"操作员不知道怎么办。把原因读出来
靠操作员记得"这筐是不良的"人会忘。系统强制拦截
解锁没有权限和留痕谁都能放行，出了事无法追责。角色权限 + 保留历史
批次锁定只冻结库存在制品和已完工的成品还在流动。要走正向追溯
批次锁定后新上线的板不拦上料环节拒绝被锁批次，或快照时自动锁板
同一对象重复锁定解锁时会漏一张。筛选唯一索引兜底
删除或修改历史锁定单销毁证据。只追加，解锁只补 Released*
ReleasedBy、ReleasedAt 只填一个留痕不全。CHECK 约束要求成对
误判的板也要走完整返修AOI 误判很常见，设"复判放行"路径，但要记录谁复判
用 Reason 前缀识别批次关联教学简化，真实系统用 ParentHoldId 外键

练习题与答案 ​

  1. 为什么锁定单只追加，解锁时"补填"而不是"删除"？ 答：删除就没有历史了，无法回答"谁、什么时候、因为什么锁/解"。补填 ReleasedBy/At 既表示结束，又保留证据。
  2. UX_HoldRecord_Open 是什么索引？它保证什么？ 答：(TargetType, TargetKey) 上带 WHERE ReleasedAt IS NULL 的筛选唯一索引；保证同一对象同一时刻最多一张未解除的锁定单，历史单不受限制。
  3. 终端 A 进站检查通过，随后品质锁板，A 再出站会怎样？为什么不用给板加锁？ 答：出站的条件 UPDATE 要求 Status = 'InProcess'，板已是 Hold，得到 0 行，出站被拒绝。数据库在写入瞬间核对条件，不需要提前加锁。
  4. 批次级锁定时，已完工的板为什么不能直接锁？ 答：它已经不在产线上，MES 的过站拦截管不到；要通知仓库冻结成品库存、拦截出货，必要时联系客户。
  5. 解锁批次时，为什么 HD-0006 不被解开？ 答：它被锁是因为自己的不良，而不是这个批次；它的锁定单原因不带 LOT: 前缀，批次解锁不动它，且它的不良记录还是 Open。
  6. 谁应该有权限解锁？列出板级和批次级的区别。 答：板级：品质，可到主管；批次级：只有品质。批次级影响面更大，所以限制更严。
  7. 为什么要有"还有未关闭的不良记录就不能解锁"的规则？ 答：防止不良没处理就放行。放行前必须不良已修复或判定为可接受，状态要先改。
  8. 锁定时为什么说"宁可错锁，不要漏锁"？解锁为什么相反要严？ 答：错锁的代价是多一次评审和一点时间；漏锁的代价是不良品流到客户手里。放行是承担风险的动作，所以要有权限和留痕。
  9. Unit.Status = 'Hold' 与 HoldRecord 不一致时（板是 Hold 但没有未解除的单），怎么发现？ 答：写检查 SQL：Unit 中 Hold 的板左连接未解除的 Unit 锁定单，找不到的就是不一致；定期跑并告警。
  10. 批次锁定之后又有新板上了这批料，怎么办？ 答：贴片出站生成快照时，发现批次有未解除的锁定单，直接把这块板锁住；更好的是上料时就拒绝被锁批次。

小结 ​

  • 不良品拦截 = 记录不良（DefectRecord）+ 锁板（Unit=Hold + HoldRecord）+ 进站拒绝并说明原因 + 评审处置 + 有权限的解锁，全程留痕。
  • 锁板和 Fail 出站都要在一个事务里；并发和"进站后被锁"靠条件 UPDATE；重复锁定靠筛选唯一索引兜底。
  • 批次级锁定依靠正向追溯找出所有板，按状态分类处理；已完工和已出货的板 MES 锁不住，要联动仓库与客户。
  • 解锁要有权限、检查未结不良、保留历史；锁定单只追加，不删除。
  • 本篇的锁定是 MES 的现场动作，与 NCR 的文件流程联动，见 不合格品控制NCR。
