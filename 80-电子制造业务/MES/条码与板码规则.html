条码与板码规则

AI 生成 · 待核对制造业务MES追溯条码更新于 2026-10-21

⚠ 待核对：Data Matrix 的容量和尺寸、Luhn mod N 校验算法、GS1 应用标识符（AI）的长度规则、DigiKey 标签上的数据标识符，都已对照网上公开资料（见 sources）；SQL Server 的数据类型优先级和 SEQUENCE 行为已对照微软文档。ISO/IEC 15434 的外壳细节和 ANSI MH10.8.2 的完整标识符表是收费标准，我没有读到原文，代码里只实现了 DigiKey 公开说明里出现的几个标识符，其余请以你们实际收到的标签为准。板码的格式（长度、前缀、是否含日期）、拼板怎么打码、扫码枪怎么配置，各家工厂差别很大，文中的 16 位格式是为了讲解而设计的示例，请对照你们的系统和客户要求。代码和输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 6 篇，也是"生产执行"的第一篇。读完你应该能：分清工单码、物料码、批次码、拼板码、板码各是什么；自己设计一套带校验位的板码规则；讲清一个拼板上 4 块小板的板码怎么派生、怎么对应；写出并发下不重号的取号代码；读懂供应商料盘标签上那串看起来乱码的二维码。

一句话定义 ​

板码（SN，Serial Number，序列号）是贴在或刻在每一块板子上的唯一编号，通常印成条码或二维码；它是 MES 追溯一块板"一生"的钥匙。同一家工厂里，板码一旦发出就永远不能重复。

先修知识 ​

  • MES：搭好了"迷你 MES"项目，知道三类表（主数据、单据、记录）。
  • 条码与二维码：知道一维码（如 Code 128）和二维码（如 QR、Data Matrix）的区别，以及扫码枪的基本用法。
  • 工单管理、工艺路线与工序：知道工单和工序序号，本篇的板码会挂在工单下，下一篇 过站与工序流转 里板码要在路线上流转。
  • SMT与电子组装流程：知道板子在 SMT 线上要经过印刷、贴片、回流焊，以及为什么常常是"一大块拼板"一起走。

它解决什么问题 ​

想象下面几个场景，都出自电子厂的日常：

  1. 同码两板：两台打码机各自从 1 开始数，早班和夜班各打出一个 00123。回流焊之后有一块板炉温不合格，系统里查 00123，查出来的是另一块板的记录，好板被拦下，坏板放了过去。
  2. 手输错一位：返修台上的工人用键盘输入板码，把 ...0123 敲成 ...0132。系统里恰好也有这个号码，于是把别人的维修记录记到了这块板上。
  3. 拼板里谁是谁：一块拼板上有 4 块小板，分板之后，ICT 测试台扫到一块小板的码，系统却不知道它在 SMT 线上用的是哪盘料、过的是哪个炉温曲线，因为那些记录都挂在"整块拼板"上。
  4. 料盘标签看不懂：来料标签上的二维码扫出来是 [)>␞06␝1PRC0402FR-0710KL␝Q5000...，仓库只会人眼看旁边印的字，不能自动入库，也就没法防错和追溯。

所以条码要解决的是身份问题：每块板、每个拼板、每盘料、每个批次，都要有一个机器能快速读取、不会重复、录错能发现的编号。没有它，后面所有的防错、记录、追溯都无从谈起。

核心概念：几种"码"别搞混 ​

电子厂里至少有五六种码，用途完全不同，混着用是新手最常见的错误：

码它标识什么例子谁产生唯一范围
工单码一张生产指令WO-LAB-001ERP 下发或 MES 创建全厂唯一，见 工单管理
物料码（料号）一种物料，不是某一件R-10K-0402（10K 电阻）工程师在物料主数据里建全厂唯一；同种料永远同一个号
物料条码（料盘 ID）一盘具体的料供应商标签 + 本厂贴的内部标签来料时扫描、收货时贴每盘一个，用完作废
批次码（LOT）一批同一次生产的东西供应商批次 L2610150042、本厂的锡膏批次供应商或本厂同一物料内唯一即可
拼板码（Panel SN）一整块拼板PA1002610210001OMES 或 PCB 供应商全厂唯一
板码（SN）一块具体的单板A10026102100004QMES全厂唯一，永远不重

要点：

  • 料号是"种类"，物料条码是"个体"。 一万颗 10K 电阻都叫 R-10K-0402，但装在 20 盘里就有 20 个料盘 ID，每盘有自己的批次、数量、开封时间。追溯时问的是"这块板用了哪一盘"，所以必须扫到盘这一级，见 物料追溯与批次关联。
  • 批次码是"一批"，不是"一个"。 同一批次里的东西很多，批次码本身不能区分其中的个体，只能把它们归成一堆。出了质量问题，常用批次一次性圈出范围。
  • 拼板码和板码是上下级。 拼板（panel，也叫 array）是为了让贴片机、回流焊一次处理多块小板而拼出来的大板；SMT 阶段按拼板走，分板（depanel）之后按单板走。
  • 板码和工单是多对一。 一张工单产生很多块板，每块板记住自己属于哪张工单（Unit.WoId，见下一篇）。

板码里该放什么信息：含义码与流水码 ​

一类做法是含义码：把产品、日期、线别等信息编进板码里，例如本篇示例的 A100 + 261021 + 00001 + 校验位。好处是人眼看一眼就知道大概哪天、哪个产品，丢了标签也能靠号码猜范围；坏处是信息一旦编进去就改不了（产品改名、换线怎么办），而且容易让人去"解析"板码而不是查数据库。

另一类是纯流水码：只有一个递增数字（外加校验位），所有信息都在数据库里。更简单、更稳，但看不出什么。

折中的常见做法是：板码里只放"永远不会变"且用来保证唯一的东西（产品系列简码、年月日、流水号），其余一切（工单、线别、班次）都不进板码，靠数据库关联。程序判断业务逻辑时只查数据库，不去切板码字符串。

编码规则怎么设计 ​

下面这些是设计一套板码规则时要逐条回答的问题。

1. 格式与长度 ​

本篇示例（16 位）：

段长度例子说明
产品简码4A100取自产品料号 PCBA-A100 去掉前缀
日期6261021yyMMdd
流水号500001每个产品每天从 1 开始，一天最多 99999 块
校验位1W前面 15 位算出来的校验字符

拼板码用同样的思路，前面加一个 P，流水号只用 4 位（一天的拼板数比单板少）：P + A100 + 261021 + 0001 + 校验位 = 16 位。

长度怎么定？够用就好，别太长。 越长越难手输、二维码越大、越难在小板上刻下。常见做法是 12 到 20 位。流水号的位数要按"一天最多做多少块"留余量，写满了要有预案（比如改用字母进位），不能溢出后回到 00001。

2. 字符集 ​

示例用的是 0-9 加 A-Z，共 36 个字符，不含符号。符号（-、/、空格）有的扫码枪会处理成别的字符，有的数据库、文件名不允许。有些工厂还会去掉容易混淆的字母（例如大写 I 与 1、O 与 0），车辆识别码 VIN 就不使用 I、O、Q；缺点是字符变少、同样长度能表示的数量变少。本例为了让校验算法的演示更简单，保留了全部 36 个字符。

3. 校验位：手输错一位也能发现 ​

校验位是根据前面所有字符算出来的最后一个字符。系统每次收到板码，先自己算一遍校验位对不对，不对就直接拒绝，不用查库。这样能拦住大部分手输错误和扫码误读。

本篇用的是 Luhn mod N 算法（把信用卡号用的 Luhn 算法推广到 N 个字符，这里 N = 36）。据维基百科：它能发现所有"单个字符被替换"的错误，和大部分"相邻两个字符写反"的错误（例外是把第一个和最后一个有效字符对调这类特殊情况）；N 必须是偶数。算法步骤：

  1. 把每个字符映射成 0 到 35 的数（0-9 是 0 到 9，A-Z 是 10 到 35）。
  2. 从最右边开始，每隔一位乘以 2（最右边一位乘 2，然后 1、2、1、2……）。
  3. 每个乘积写成"36 进制"再把各位数相加；因为乘积最大是 70，也就是商加余数：商 = 乘积 / 36，余数 = 乘积 % 36，两者相加。
  4. 全部加起来得到总和 S。校验位的值是 (36 - S % 36) % 36，再映射回字符。
  5. 验证时把校验位也带上，从最右边开始（校验位乘 1，然后 2、1、2……）算总和，能被 36 整除就合格。

4. 防重 ​

"不重号"要靠三层保证：

  1. 取号时原子地拿到唯一的流水号（见后面"并发安全"）；
  2. 落库时板码列上有唯一索引，万一程序有 bug，数据库也会拒绝重号；
  3. 打码时同一个板码只打一次，补打要走专门的"补打"流程并留记录，不能随便重新生成。

5. 载体：条码还是二维码、贴还是刻 ​

  • 一维码（如 Code 128）：简单，几乎所有扫码枪都能读，但容量小、占地大，适合贴在纸质标签上。
  • 二维码（QR、Data Matrix）：容量大、占地小、自带纠错，板上能放进一个很小的方块。据维基百科，Data Matrix（ECC 200）方形符号从 10×10 到 144×144，最多能存 2335 个字母数字字符；美国电子工业联盟（EIA）建议用它来标识小型电子元件。电路板上常见的做法是用激光在板子上刻一个 Data Matrix，因为标签会被高温回流焊烤坏、烤掉，刻的码就不会。
  • 刻码位置要避开元件和焊盘、对比度要足够、码周围要留空白（静区），并且要用扫码枪实际验证能不能读。具体参数请以你们的激光打码设备和工艺文件为准（本篇没有核对相关国际标准）。

拼板与子板的关系 ​

先看一张图：

一个拼板上有 4 块小板，板码怎么给？有两种常见做法：

做法例子优点缺点
A. 独立板码 + 对应表拼板 PA1002610210001O，4 块板 A10026102100004Q……...007K，对应关系存在 PanelBoard 表板码格式统一，分板后和单板码没区别；拼板数量变化（2 拼、6 拼）不影响规则要多维护一张对应表；对应关系写错了所有追溯都乱
B. 拼板码加后缀拼板 PA1002610210001O，子板 PA1002610210001O-1 到 -4号码本身就带着上下级关系，不用对应表也能推子板码比拼板码长，格式不统一；符号 - 要处理；拼板码一变子板码全变

本篇实验用 A 做法。关键细节：

  • 一次性预留 4 个连续的流水号（LastNo = LastNo + 4），这样一个拼板的 4 块小板码是连续的，打码时按位置 1、2、3、4 依次打，对应关系天然有序。
  • 拼板码、4 个板码、对应表的写入放在一个事务里：要么全成功，要么全不留痕，不会出现"拼板登记了但小板没登记"。
  • PanelBoard 上对 SerialNo 建唯一索引（一个板码只能在一个拼板的一个位置），再对 (PanelSn, Position) 建唯一索引（同一个拼板的同一个位置只能有一块板）。
  • SMT 阶段（印刷、SPI、贴片、回流）扫拼板码，系统按对应表把动作"展开"到 4 块小板上，各写一条过站记录；分板之后每块板扫自己的 SN。如果来料就是带板码的拼板，打码就发生在 PCB 来料或首站，之后只需要"把对应关系登记进系统"。
  • 拼板里偶尔有来料就已经标记为坏的小板（叉板），贴片时会跳过。真实系统里 PanelBoard 通常还要加一列"是否有效/是否跳过"，本篇的迷你模型没有加。

SN 生成的并发安全 ​

多个打码终端、多条线同时要号。最容易写出来的是这样一段"看起来没问题"的代码：

1. 查出今天已发到几号：SELECT MAX(流水号) ...
2. 新号 = 已发号 + 1
3. 插入这个新号

问题和 工单管理 里讲的一样：第 1 步和第 3 步之间有空档。两个终端同时查到 "已发到 0 号"，都算出新号是 1，都去插入——重号。如果板码列有唯一索引，第二个会失败（数据库拦住了），但如果没有，重号就悄悄进了系统。

正确的做法是让数据库在一条语句里同时完成"加号"和"返回新值"：

sql
UPDATE SnSequence SET LastNo = LastNo + @n
OUTPUT inserted.LastNo
WHERE SeqKey = @k;

这里 SnSequence 每个"产品+日期"一行，LastNo 是已发出的最大流水号。UPDATE 要给这一行加锁，所以两个并发的取号会排队：先到的把 LastNo 加到 1 并拿走，后到的看到 1，加到 2 拿走。OUTPUT inserted.LastNo 返回的是更新后的值，所以不需要再查一遍。一次要 4 个就 @n = 4，拿到的是 LastNo - 3 到 LastNo 这 4 个连续号。

其他常见方案对比：

方案说明适用与局限
号段表 UPDATE ... OUTPUT（本篇）每个"产品+日期"一行，一条语句取号简单可靠，可预留一批；同一个 key 取号会串行，每秒几千个也够用
IDENTITY 自增列数据库自动给最简单，但不能按"每天从 1 开始"重置，号码里的流水就是个全局数字
SEQUENCE 对象NEXT VALUE FOR 取号，可用 sp_sequence_get_range 一次取多个据微软文档，序列号在事务之外生成，事务回滚了号也已经用掉，所以会有空号；"每天重置"要定时 ALTER SEQUENCE ... RESTART，麻烦
程序内存里计数lock + 静态变量多个程序实例、程序重启就会重号，不要用
GUID全局唯一太长，没法印成小码，也没法手输

空号可以接受，重号不可以。 取号和使用不在同一个事务里时，取到的号可能因为后面失败而没用掉（比如打码机故障），号段里就留下了空洞。这是正常的，追溯不会因为"号码跳了"出错；所以不要为了"连续"去牺牲并发。

三层防线 ​

  1. 取号用原子语句（上面的 UPDATE ... OUTPUT）。
  2. 板码列上有唯一索引，最后一道保险。
  3. 板码在业务上只来自 MES 一个入口，不允许其他系统（或人）自己造码。

解析物料条码 ​

供应商的料盘标签上，常见三种格式：

1. 电子元件行业二维码（数据标识符 + GS 分隔） ​

据 DigiKey 公开的说明，其标签的二维码内容以 [)> 加 06 开头（这是 ISO/IEC 15434 的"格式 06"外壳），后面是一串字段，每个字段以一个"数据标识符"（DI）开头，字段之间用一个不可见的控制字符 GS（Group Separator，ASCII 29，十六进制 1D）分隔。几个常见的数据标识符（来自 DigiKey 页面说明）：

DI含义DI含义
P客户料号1T批次码（Lot）
1P供应商（制造商）料号9D日期码
30P分销商料号4L原产国（两位国家代码）
K采购订单号Q数量
1K销售订单号10K发票号

注意：同一个标识符的写法在各家供应商之间可能略有不同（例如日期码是不是"年周"格式、数量有没有前导零），实际以收到的标签为准；标识符还要按长的先匹配，否则 10K 会被当成 1 加 0K，1P 会被当成 P 加 1……

2. GS1 元素串 ​

零售和医药常用 GS1 体系：每个字段以"应用标识符"（AI）开头。据公开的 AI 列表：(01) 是全球贸易项目代码 GTIN，固定 14 位；(17) 是有效期，固定 6 位 YYMMDD；(10) 是批次，(21) 是序列号，两者长度可变（1 到 20 位），所以后面必须跟一个 GS（FNC1）分隔符，除非它是最后一个字段。解析时：固定长度的字段直接按长度切；变长字段读到 GS 或字符串结束为止。GTIN 最后一位是校验位：前 13 位从左起交替乘 3 和 1，求和，校验位 = (10 - 和 % 10) % 10。

3. 厂商自定义 ​

很多工厂自己印标签：R-10K-0402|L2610150042|5000（料号、批次、数量用竖线隔开），或者干脆是一个内部料盘 ID。这类格式只有自己知道，一定要有格式校验（段数对不对、数量是不是正整数），错了就拒绝入库。

解析的通用套路 ​

  1. 先认格式：以 [)> 开头是 15434；以 01 加 14 位数字开头多半是 GS1；含 | 是自家标签；认不出就拒绝，别猜。
  2. 按规则切字段：该用 GS 分隔就用 GS，该按固定长度就按长度。
  3. 逐字段校验：数量是正整数、日期合法、GTIN 校验位对。
  4. 转换成本厂的统一模型：不管来源格式，最后都变成 (料号, 批次, 数量, 日期码)，后面的入库、上料防错 SMT上料防错与站位表、追溯 物料追溯与批次关联 只认这个统一模型。
  5. 再配合 WMS 打的内部标签，见 物料标签与条码。

扫码枪的坑：GS 是不可见的控制字符，有的扫码枪默认把它吞掉或转成别的字符，解析就全乱了。上线前要用真实标签、真实扫码枪验证，并在扫码枪的设置里确认控制字符的输出方式。

技术视角：表与 SqlSugar ​

表设计 ​

sql
SnSequence ( SeqKey nvarchar(40) 主键, LastNo int )                       -- 号段表：每个"类型-产品-日期"一行
Panel      ( PanelSn nvarchar(40) 主键, WoNo, ProductCode, BoardCount, CreatedAt )
PanelBoard ( Id 自增主键, PanelSn, Position, SerialNo,
             唯一索引 (SerialNo)，唯一索引 (PanelSn, Position) )

三条设计要点：

  1. 板码在所有表里用同一种类型。本系列统一用 nvarchar(40)（Unit.SerialNo、TrackRecord.SerialNo、PanelBoard.SerialNo 都是）。据微软文档，两种类型比较时，优先级低的会被转换成优先级高的，nvarchar 高于 varchar；如果一边是 varchar 列一边是 nvarchar，连表或比较时 varchar 那一侧要被转换。我在本机实测过：10 万行的 varchar 主键，用 nvarchar 参数按主键查一行，逻辑读是 1526，类型一致时只要 3（详见 MES核心数据模型）。前面的 MES 里炉温记录表的板码列 Sn 是 varchar(50)，列名和类型都与后面的表不一致——这是迷你模型里一个可以反面教学的细节，真实系统里要从一开始就统一。
  2. 号段 key 要带上"类型-产品-日期"，S-A100-261021 和 P-A100-261021 是两个独立的号段，板码和拼板码互不干扰。
  3. 每天重置靠"换一行"实现：明天的 key 里日期变了，自然是新的一行，从 0 开始；不用定时任务去清零。

从拼板展开到单板 ​

首站扫到拼板码后，要为 4 块小板建立"在制品"记录（Unit 表在下一篇 过站与工序流转 里定义）：

sql
INSERT INTO Unit(SerialNo, WoId, ProductCode, CurrentStepNo, Status, CreatedAt)
SELECT pb.SerialNo, p.WoNo, p.ProductCode, 0, N'InProcess', GETDATE()
FROM PanelBoard pb JOIN Panel p ON p.PanelSn = pb.PanelSn
WHERE pb.PanelSn = N'PA1002610210001O';

我在本机用实验里的数据实际执行过：这条语句插入了 4 行，WoId 都是 WO-LAB-001，Status 都是 InProcess。

反查 ​

任何一块板码，都要能在一条查询里找到它的拼板和位置：SELECT PanelSn, Position FROM PanelBoard WHERE SerialNo = @sn，这靠 SerialNo 上的唯一索引保证速度和唯一性。

逐步例子：手算一个校验位 ​

例 1：算短板码 A100 的校验位。 字符对应的数：A = 10，1 = 1，0 = 0，0 = 0。从最右边开始，乘数依次是 2、1、2、1：

字符数乘数乘积商 + 余数贡献
0（最右）0200 + 00
00100 + 00
11220 + 22
A101100 + 1010

总和 S = 12，校验位的值 (36 - 12 % 36) % 36 = 24，第 24 个字符是 O（A 是 10，O 是 10 + 14 = 24）。所以完整码是 A100O。

验证：带上校验位重新算，从最右边起乘数是 1、2、1、2、1：O = 24 × 1 = 24；0 × 2 = 0；0 × 1 = 0；1 × 2 = 2；A = 10 × 1 = 10。总和 24 + 0 + 0 + 2 + 10 = 36，36 % 36 = 0，合格。

例 2：乘积超过 35 时。 算 Z1 的校验位：1 × 2 = 2；Z = 35，乘数 1，35。总和 37，值 (36 - 37 % 36) % 36 = 35，字符 Z，所以是 Z1Z。需要进位的情形，例如某个字符 Z（35）乘 2 得 70，70 / 36 = 1，70 % 36 = 34，贡献 1 + 34 = 35。

我用另一份独立的 Python 实现复算过这两个例子，以及实验里的 A10026102100001 的校验位 W、A10026102100002 的 U、拼板码主体 PA1002610210001 的 O，结果一致。

例 3：第一块板的完整过程。 产品 PCBA-A100，日期 2026-10-21，当天第一次取号：号段表里没有 S-A100-261021，UPDATE 返回空，程序插入一行 LastNo = 0，重试 UPDATE，LastNo 变成 1，拿到 1。主体是 A100 + 261021 + 00001 = A10026102100001（15 位），算校验位得 W，所以板码是 A10026102100001W，共 16 位。

// 条码实验：板码生成 + 校验位 + 拼板派生 + 并发不重号 + 解析物料条码
public static class LabBarcode
{
    const string Alpha = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ";   // 36 个字符，没有符号，扫码枪最不容易出错
    const char GS = '\u001d', RS = '\u001e', EOT = '\u0004';
    static readonly DateTime Day = new(2026, 10, 21);              // 固定日期，实验结果每次一样

    // ---------- 校验位：Luhn mod 36 ----------
    static int LuhnSum(string s, int factor)
    {
        int sum = 0;
        for (int i = s.Length - 1; i >= 0; i--)
        {
            int add = factor * Alpha.IndexOf(s[i]);
            factor = factor == 2 ? 1 : 2;
            sum += add / 36 + add % 36;
        }
        return sum;
    }
    static char CheckChar(string body) => Alpha[(36 - LuhnSum(body, 2) % 36) % 36];
    static bool IsValid(string sn) => sn.All(c => Alpha.Contains(c)) && LuhnSum(sn, 1) % 36 == 0;

    // 板码 = 产品简码(4) + 日期(6) + 流水号(5) + 校验位(1) = 16 位；拼板码前面多一个 P，流水号 4 位
    static string ShortOf(string product) => product.Replace("PCBA-", "");
    static string Make(string kind, string product, DateTime d, int seq) =>
        kind == "P" ? Seal($"P{ShortOf(product)}{d:yyMMdd}{seq:D4}") : Seal($"{ShortOf(product)}{d:yyMMdd}{seq:D5}");
    static string Seal(string body) => body + CheckChar(body);

    // ---------- 取号：一条 UPDATE 同时"加号"和"返回新值"，数据库保证同一行同一时刻只有一个人在改 ----------
    static int Reserve(SqlSugarClient db, string key, int count)
    {
        while (true)
        {
            var r = db.Ado.GetScalar("UPDATE SnSequence SET LastNo = LastNo + @n OUTPUT inserted.LastNo WHERE SeqKey = @k",
                new SugarParameter("@n", count), new SugarParameter("@k", key));
            if (r != null) return Convert.ToInt32(r);
            try { db.Insertable(new SnSequence { SeqKey = key, LastNo = 0 }).ExecuteCommand(); }
            catch { /* 别人刚好先建了这一行，重试 UPDATE 即可 */ }
        }
    }
    static List<string> NewSns(SqlSugarClient db, string kind, string product, DateTime d, int count)
    {
        int last = Reserve(db, $"{kind}-{ShortOf(product)}-{d:yyMMdd}", count);
        return Enumerable.Range(last - count + 1, count).Select(n => Make(kind, product, d, n)).ToList();
    }

    // ---------- 解析物料条码 ----------
    // 1) 电子元件 2D 码（ISO/IEC 15434 的外壳 + 数据标识符 DI），字段之间用 GS 分隔
    static readonly string[] Dis = { "30P", "10K", "1P", "1K", "1T", "9D", "4L", "P", "K", "Q" };   // 长的放前面，先匹配
    static readonly Dictionary<string, string> DiName = new()
    {
        ["P"] = "客户料号", ["1P"] = "供应商料号", ["30P"] = "分销商料号", ["K"] = "采购订单", ["1K"] = "销售订单",
        ["10K"] = "发票号", ["9D"] = "日期码", ["1T"] = "批次码", ["4L"] = "原产国", ["Q"] = "数量",
    };
    static List<(string Di, string Value)> ParseIso15434(string raw)
    {
        if (!raw.StartsWith("[)>")) throw new FormatException("不是 [)> 开头");
        var parts = raw.Split(GS).Skip(1).Select(p => p.TrimEnd(RS, EOT)).Where(p => p.Length > 0);
        return parts.Select(p =>
        {
            var di = Dis.FirstOrDefault(d => p.StartsWith(d)) ?? throw new FormatException($"不认识的字段：{p}");
            return (di, p.Substring(di.Length));
        }).ToList();
    }
    static string Show(string s) => s.Replace(GS.ToString(), "<GS>").Replace(RS.ToString(), "<RS>").Replace(EOT.ToString(), "<EOT>");

    // 2) GS1 元素串：(01) GTIN 固定 14 位，(17) 日期固定 6 位，(10) 批次、(21) 序列号可变长（最长 20），变长的后面要跟 GS
    static bool GtinOk(string g) =>
        g.Length == 14 && g.All(char.IsDigit) &&
        (10 - g.Take(13).Select((c, i) => (c - '0') * (i % 2 == 0 ? 3 : 1)).Sum() % 10) % 10 == g[13] - '0';
    static Dictionary<string, string> ParseGs1(string raw)
    {
        var r = new Dictionary<string, string>();
        int p = 0;
        while (p < raw.Length)
        {
            string ai = raw.Substring(p, 2); p += 2;
            int len = ai switch { "01" => 14, "17" => 6, "10" or "21" => -1, _ => throw new FormatException($"本实验不认识 AI {ai}") };
            if (len < 0) { int e = raw.IndexOf(GS, p); if (e < 0) e = raw.Length; len = e - p; }
            r[ai] = raw.Substring(p, len); p += len;
            if (p < raw.Length && raw[p] == GS) p++;
        }
        return r;
    }

    // 3) 工厂自己的标签：料号|批次|数量
    static (string Pn, string Lot, int Qty) ParseHouse(string raw)
    {
        var f = raw.Split('|');
        if (f.Length != 3 || !int.TryParse(f[2], out int q) || q <= 0) throw new FormatException("格式应为 料号|批次|数量，数量必须是正整数");
        return (f[0], f[1], q);
    }

    public static void Run(SqlSugarClient db)
    {
        db.CodeFirst.InitTables(typeof(SnSequence), typeof(Panel), typeof(PanelBoard), typeof(SnTrial));
        db.Deleteable<PanelBoard>().ExecuteCommand();
        db.Deleteable<Panel>().ExecuteCommand();
        db.Deleteable<SnTrial>().ExecuteCommand();
        db.Deleteable<SnSequence>().ExecuteCommand();
        const string Product = "PCBA-A100";

        // 1. 生成 + 校验
        Console.WriteLine("1. 生成板码（产品 PCBA-A100，日期 2026-10-21，每天每个产品从 1 开始）");
        var sns = NewSns(db, "S", Product, Day, 3);
        foreach (var s in sns) Console.WriteLine($"   {s}  长度 {s.Length}  校验 {(IsValid(s) ? "通过" : "失败")}");
        var good = sns[0];
        var typo = good.Substring(0, 12) + (good[12] == '9' ? '8' : '9') + good.Substring(13);
        Console.WriteLine($"   手抄错一位 {typo} -> 校验 {(IsValid(typo) ? "通过" : "失败")}");
        var swap = good.Substring(0, 13) + good[14] + good[13] + good.Substring(15);
        Console.WriteLine($"   相邻两位写反 {swap} -> 校验 {(IsValid(swap) ? "通过" : "失败")}");

        // 2. 校验位到底能拦住多少错误：对一个板码穷举
        int sub = 0, subOk = 0, tr = 0, trOk = 0;
        for (int i = 0; i < good.Length; i++)
            foreach (var c in Alpha.Where(c => c != good[i]))
            {

练习题与答案 ​

  1. 料号、物料条码（料盘 ID）、批次码三者的区别？ 答：料号标识一"种"物料（所有 10K 电阻同一个料号）；物料条码标识"一盘"具体的料（每盘不同）；批次码标识"一批"同时生产的料（同批的很多盘共用）。追溯要精确到盘，批次用来一次圈出一批范围。
  2. 为什么板码里最好不放"工单号"？ 答：工单号会变（拆单、改单、返工重投），而板码印上去就改不了。板码里只放永不变化的信息，其余通过数据库关联；程序也不要靠切板码字符串来获取工单。
  3. 本篇示例的板码，一天最多能给一个产品发多少个？写满之后怎么办？ 答：流水号 5 位，最多 99999 个。实际要按一天最大产量留余量；写满后应改为字母进位（扩大字符集），或增加位数，绝不能回到 00001。
  4. 手算：板码主体 B2（B = 11，2 = 2）的 Luhn mod 36 校验位是什么？ 答：从右起乘数 2、1：2 × 2 = 4；B = 11 × 1 = 11；和 15；校验位值 (36 - 15) % 36 = 21，第 21 个字符是 L（A 是 10，L 是 10 + 11 = 21）。完整码 B2L。验证：L = 21 × 1 = 21；2 × 2 = 4；B = 11 × 1 = 11；总和 36，被 36 整除。
  5. 为什么并发取号时，"先查最大号再 +1"会重号，而 UPDATE ... OUTPUT 不会？ 答：前者的"查"和"写"是两个步骤，中间有空档，多个线程可能读到同一个值；后者在一条语句里修改并返回，UPDATE 对这一行加锁，并发的取号只能排队，各自拿到不同的值。
  6. 取到的号后来没用掉（打码机故障），号段里留下空洞，这是问题吗？ 答：不是。追溯不依赖号码连续，只要不重复就行；为了连续去延长事务、限制并发反而有害。如果某些客户要求"连续"，要在业务层记录作废号。
  7. 一个拼板 4 块小板，为什么要在一个事务里写拼板和对应表？ 答：保证"要么都成功，要么都不留"。否则可能出现拼板登记了但小板没登记，之后拿着拼板码展开不出小板，或小板登记了却找不到所属拼板。
  8. 如果板码里不含日期，只用纯流水号，号段表的 key 要怎么设计？ 答：不用日期，key 只含类型和产品，如 S-A100，LastNo 一直累加，不再每天重置。流水号的位数要按总产量估算，位数要更长。
  9. 解析电子元件二维码时，为什么标识符要"从长到短"匹配？ 答：有些标识符是另一个的前缀或字符重叠，例如 1P 和 P、10K 和 1K。先匹配短的会把 1P 当成 P，值前面多出一个 1，解析错位。
  10. 把板码 A10026102100001W 的最后两位 1W 对调成 W1，校验位还能发现吗？ 答：能。这是相邻两个不同字符的对调，实验第 2 部分穷举的 11 种相邻对调全部被发现。Luhn mod N 只有"首尾字符对调"这类特殊情形才可能漏掉，而这里不是首尾。

小结 ​

  • 板码是每块板唯一的身份；板码、拼板码、料号、物料条码、批次码、工单码各管一件事，不要混用。
  • 编码规则要回答格式、长度、字符集、校验位、防重、载体六个问题；板码里只放永不变化的信息，业务逻辑查数据库，别切字符串。
  • 校验位（Luhn mod 36）能在查库之前拦住手输错和误读：单字符错误全部发现，相邻对调绝大多数发现。
  • 拼板和子板：独立板码加对应表，一次预留连续号，拼板与对应表在一个事务里写入，板码上建唯一索引。
  • 取号要原子：UPDATE ... OUTPUT 一条语句取号，唯一索引做最后保险；允许空号，不允许重号。
  • 物料条码有三类格式（数据标识符加 GS 分隔、GS1 元素串、厂商自定义），解析 = 认格式、切字段、校验、转成统一模型。
