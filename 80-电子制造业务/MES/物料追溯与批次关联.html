物料追溯与批次关联

AI 生成 · 待核对制造业务MES追溯物料更新于 2026-10-21

⚠ 待核对：站位快照在哪个时刻抄、拼板怎么展开、批次谱系放在 MES 还是 WMS、快照表的归档周期，都是通用做法与设计取舍，你们自研 MES 的做法可能不同（有的靠贴片机上报的实际贴装数据），请对照你们的系统。本篇依赖实体 SlotLoad，它由 SMT上料防错与站位表 定义，本篇不重复定义；实验里 SlotLoad 用了该篇约定的字段（线体、站位、料号、批次、装上和卸下时间）。IPC-1782（电子制造追溯标准）只引用其存在与适用范围，具体要求以标准原文为准。代码、输出和"行数、空间、读页数"的数字，都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 13 篇。上料防错只管"现在装的料对不对"，本篇管"做完以后，还能查到这块板用的是哪批料"。读完你应该能：说清为什么要把料批次"抄"到板子名下；比较三种关联方式；设计 UnitMaterial 表并写出生成快照的代码；做正向追溯（某批料影响了哪些板）和反向追溯（某块板用了哪些料）；处理批次拆分合并；估算快照表的数据量并设计归档。

一句话定义 ​

物料追溯就是让"板"和"料批次"之间有一条能查的线：给定一块板，能说出它每个位号用的是哪个料盘（批次）；给定一个料批次，能列出所有用过它的板、工单。

先修知识 ​

  • SMT上料防错与站位表：知道料站位（Slot）、料盘（Lot）、SlotLoad（谁在什么时间把哪盘料装到哪个站位）。
  • 过站与工序流转：本篇的快照在贴片出站时生成，要用 Unit、TrackRecord。
  • 库存管理与批次序列号：批次（Lot）是什么、为什么物料要按批次管。
  • BOM与物料清单：位号（RefDes）从 BOM 来。

它解决什么问题 ​

先看一个典型的现场故事：

某天晚上，供应商通知：你们 10 月收到的一批 10K 电阻（批次 LOT-R-001）焊端镀层有问题，焊接后可能虚焊，请全部召回。仓库先去查库存：还剩 300 盘，好办，冻结。但已经上线用掉的呢？ 如果系统里只有"上料记录"（某时某站位装了这盘料）和"过站记录"（某块板某时出站），没人把两者连起来，你只能靠人去翻：这盘料 08:00 装上、09:00 卸下，这期间这条线上过贴片的板……而这条线同时还在做别的工单，中途还换过班、停过线。结果通常是两种：宁多勿漏，把整个班次的板全部隔离，损失巨大；或者漏掉，带病的板发给了客户。

物料追溯要把这件事变成一条 SQL：LOT-R-001 → 影响了哪些板 → 在哪些工单 → 现在在哪（在制 / 已完工 / 已出货）。它是质量事故时"圈定范围"的唯一依据，范围圈得准，损失才小。

核心概念 ​

为什么不直接查上料记录 ​

SlotLoad 记的是"站位上装了什么"，过站记录记的是"板什么时候出站"。理论上把两张表按时间对一下就能知道一块板用了哪盘料，这叫按时间窗口重建。它有三个问题：

  1. 慢且依赖时间精度：每次追溯都要对时间，两张表的时钟如果差几秒，边界上的板就会错。
  2. 换料边界上有歧义：一块板在贴片机里待 30 秒，换盘恰好发生在这 30 秒里，两盘料它都可能用过。
  3. 历史会被改：站位表的记录如果被更正、被归档，三个月后重建的结果就和当时不同。

所以主流做法是出站时把当时的情况抄一份挂到板子名下，这就是站位快照。快照是一份"当时的事实"，之后上料记录再怎么变，它都不变。

三种关联方式 ​

方式做法优点缺点
站位快照（出站时抄）贴片出站时，把这条线所有"此刻装着"的站位抄成 UnitMaterial 行查询快、结果固定、好审计表大；换料边界上的那块板抄的是出站时刻的料
按时间窗口重建不存，查询时用板的进出站窗口去匹配 SlotLoad不占空间，实现简单慢、边界上会多算（宁多勿漏）、依赖时钟
设备直接上报（最准）贴片机按每个元件的贴装记录上报"从哪个供料器吸的"位号级精确，没有歧义依赖设备接口和型号，数据量最大，见 MES与ERP及设备的接口设计

多数工厂的路线是：先做站位快照（够用、便宜），对车规等高要求产品再叠加设备贴装数据。IPC-1782（电子制造与供应链追溯标准）把追溯按风险分成几个等级，等级越高记得越细，具体到什么程度由你和客户约定，要求以标准原文为准。

拼板与位号 ​

  • 拼板：SMT 一次处理的是一整张拼板（panel），里面有好几块小板。贴片出站是对拼板扫一次，所以快照要对拼板上的每块子板各抄一份（对应关系见 条码与板码规则）。本篇实验为简单，一块板一个板码。
  • 位号：RefDes 来自 BOM。同一个料号可能在板上有很多位号（R1-R12），实验里直接存范围；真实系统要追溯到某个电阻时，需要展开成单个位号，或靠设备数据。

正向与反向 ​

方向问题例子
反向追溯这块板用了哪些料？客户退回一块板，要查它的 MCU 是哪批的
正向追溯这批料用在了哪些板、工单上？供应商通知某批电阻有问题，要圈范围

反向追溯是"按板码找几行"，正向追溯是"按批次找所有板，再看它们的状态"，后者才是真正的难点，因为要扫很多行，还要处理批次的拆分合并。

批次拆分与合并 ​

料在仓库和车间里会被拆开：一个供应商大盘 LOT-C-900 有 10000 只电容，仓库按 5000 一盘拆成两个料盘 LOT-C-002、LOT-C-003，上线用的是子批次。供应商通知"LOT-C-900 有问题"时，如果追溯只认上线用的子批次，你就查不到。所以要有批次谱系（lot genealogy）：父子关系表 LotLink，追溯时沿着关系把子批次一起带上。合并同理：几个尾料并成一盘，新批次有多个父批次，往下追时它继承所有父批次的风险。

谱系关系通常在仓库拆盘、并盘时产生（见 库存管理与批次序列号、物料标签与条码），MES 追溯时只读不写。

业务视角 ​

角色在追溯里做什么
上料员每次换料盘都扫码，保证 SlotLoad 准确，这是整个追溯链的源头
品质工程师来料异常、客诉时发起追溯，圈定范围，决定隔离（见 不良品拦截与锁定）
采购 / 供应商质量拿追溯结果向供应商索赔，见 供应商质量管理
生产主管看受影响的在制品在哪个工序，安排拦截

典型流程：发现问题批次 → 反查批次的所有子批次 → 圈出用过它们的板 → 按状态分类（在制 / 完工未发货 / 已出货）→ 在制的锁定、库存的冻结、已出货的通知客户 → 追溯报告留存。KPI：追溯查询耗时（目标是分钟级）、追溯完整率（有贴片记录的板中有快照的比例）、一次圈定的范围是否被后来证明"漏了"或"多了"。

技术视角 ​

表设计 ​

两张记录类表，都是只追加：

sql
CREATE TABLE UnitMaterial (
    Id           int IDENTITY(1,1) NOT NULL CONSTRAINT PK_UnitMaterial PRIMARY KEY,
    SerialNo     nvarchar(40)  NOT NULL,
    StepNo       int           NOT NULL,
    StationCode  nvarchar(30)  NOT NULL,
    SlotNo       nvarchar(10)  NOT NULL,
    RefDes       nvarchar(200) NOT NULL,
    MaterialCode nvarchar(50)  NOT NULL,
    LotNo        nvarchar(40)  NOT NULL
);
-- 反向追溯：按板码查
CREATE INDEX IX_UnitMaterial_Sn  ON UnitMaterial(SerialNo, StepNo);
-- 正向追溯：按批次查，带上板码就不用回表
CREATE INDEX IX_UnitMaterial_Lot ON UnitMaterial(LotNo, SerialNo);
-- 防重复：同一块板同一站同一站位同一位号只能有一行
CREATE UNIQUE INDEX UX_UnitMaterial_Slot ON UnitMaterial(SerialNo, StepNo, SlotNo, RefDes);

CREATE TABLE LotLink (
    Id           int IDENTITY(1,1) NOT NULL CONSTRAINT PK_LotLink PRIMARY KEY,
    ParentLotNo  nvarchar(40) NOT NULL,
    ChildLotNo   nvarchar(40) NOT NULL,
    Relation     nvarchar(10) NOT NULL CONSTRAINT CK_LotLink_Rel CHECK (Relation IN (N'Split', N'Merge')),
    Qty          decimal(18,3) NOT NULL,
    CreatedAt    datetime NOT NULL CONSTRAINT DF_LotLink_Created DEFAULT GETDATE()
);
CREATE INDEX IX_LotLink_Parent ON LotLink(ParentLotNo);
CREATE INDEX IX_LotLink_Child  ON LotLink(ChildLotNo);

几个设计点：

  1. 板码列类型统一为 nvarchar(40)，和 Unit、TrackRecord 一致，连表不会触发隐式类型转换（见 MES核心数据模型）。
  2. 两个查询方向各建一个索引：(SerialNo, StepNo) 管反向，(LotNo, SerialNo) 管正向。正向索引把 SerialNo 放进键里，查批次只需读索引不必回表。
  3. 唯一索引防重复：出站事件可能被设备重发，重复生成快照不应翻倍。唯一索引加 SQL 里的"已存在就跳过"双保险。
  4. 记 StepNo 不记工序码（和过站篇一致）：双面板贴片出现两次，靠序号区分是 A 面还是 B 面。
  5. 不存时间：快照的时间就是对应的 TrackRecord.OutAt，用 (SerialNo, StepNo) 连得到，不冗余。
  6. 本表没有 Qty（用量）。如果需要核算每批料实际消耗，用量由贴装数据或 BOM 单耗推算，不在这里记。

生成快照的规则 ​

在贴片出站（Pass）的事务里，对这条线上每个"出站那一刻还装着"的站位抄一行：

装上时间 <= 出站时间  AND  (卸下时间 IS NULL OR 卸下时间 > 出站时间)

注意区间是左闭右开：恰好在 09:00:00 换盘时，旧盘的卸下时间等于新盘的装上时间，一个站位在任一时刻只命中一行。

正向追溯与 CTE ​

正向追溯要沿谱系向下找所有子批次，用递归 CTE（Common Table Expression，公共表表达式，微软文档里叫 WITH common_table_expression）：

sql
WITH Lots(LotNo) AS (
    SELECT CAST(@lot AS nvarchar(40))                       -- 起点：问题批次
    UNION ALL
    SELECT l.ChildLotNo FROM LotLink l JOIN Lots p ON l.ParentLotNo = p.LotNo   -- 往下找子批次
)
SELECT DISTINCT u.WoId, m.SerialNo, u.Status
FROM UnitMaterial m JOIN Unit u ON u.SerialNo = m.SerialNo
WHERE m.LotNo IN (SELECT LotNo FROM Lots);

锚点里的 CAST(@lot AS nvarchar(40)) 不能省：递归 CTE 要求锚点和递归部分的列类型一致，参数默认是 nvarchar(4000)，不转换会报类型不匹配。如果谱系里出现环（数据错误），递归会一直转，SQL Server 默认在 100 层递归时报错停下（可用 OPTION (MAXRECURSION n) 调整）。

数据量与归档 ​

快照表是 MES 里长得最快的表之一：每块板 × 每个站位一行。我在本机造了 20000 块板 × 60 个站位 = 120 万行的数据实测：

项目实测
数据本身（聚集索引）145,456 KB（约 142 MiB，平均每行约 124 字节）
加上两个查询索引后合计282,840 KB（约 276 MiB，平均每行约 241 字节）
按板码查一块板（(SerialNo, StepNo) 索引）3 次逻辑读
按批次查 2000 块板（(LotNo, SerialNo) 索引）19 次逻辑读

按这个比例估算一条线一天做 8000 块板、60 个站位、一年 250 天：8000 × 60 × 250 = 1.2 亿行，合计约 27 GiB（估算值，按上表每行约 241 字节外推，真实的料号、批次、位号长度不同会有出入）。

降本的几种思路：

  1. 按月分区 + 归档：快照表只追加、按时间自然有序，是分区的理想对象，方法见 MES核心数据模型。近 3~6 个月放热数据，更早的搬到归档库；追溯合规要求保留多久（几年到十几年，取决于行业和合同）就保留多久，归档库可以用压缩。
  2. 快照去重（设计思路，我没有实测）：同一条线在两次换料之间，所有板抄的站位组合是一模一样的。可以单独建一张"站位组合"表（每次换料产生一个新组合），板只记一个组合编号。每天换料假设 100 次，那就是 100 × 60 = 6000 行组合 + 每板一行，而不是 48 万行。代价是查询要多连一张表，实现也更复杂。
  3. 别抄不需要追溯的料：如辅料、结构件等按 BOM 标记"需要追溯"的才抄。

并发与一致性 ​

  • 快照与出站应放在同一个事务（或可靠的事件队列）里：板出站了却没有快照，追溯就缺一块，后面的"完整性检查"（见 产品追溯）会把这类板找出来。
  • 快照读 SlotLoad 时不要锁住它：上料员正在换料，不能因为抄快照而阻塞。读已提交即可，边界上的一两块板的差异本来就是前面说的歧义窗口。

csharp
using SqlSugar;

namespace MiniMes;

// 物料追溯快照：一块板在某一站"用了哪个站位上的哪个批次的料"。只追加，不修改
[SugarTable("UnitMaterial")]
[SugarIndex("IX_UnitMaterial_Sn", nameof(UnitMaterial.SerialNo), OrderByType.Asc, nameof(UnitMaterial.StepNo), OrderByType.Asc)]
[SugarIndex("IX_UnitMaterial_Lot", nameof(UnitMaterial.LotNo), OrderByType.Asc, nameof(UnitMaterial.SerialNo), OrderByType.Asc)]
[SugarIndex("UX_UnitMaterial_Slot", nameof(UnitMaterial.SerialNo), OrderByType.Asc, nameof(UnitMaterial.StepNo), OrderByType.Asc,
    nameof(UnitMaterial.SlotNo), OrderByType.Asc, nameof(UnitMaterial.RefDes), OrderByType.Asc, true)]   // 同一块板同一站同一站位同一位号只能有一行：重复生成快照不会翻倍
public class UnitMaterial
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(40)")]
    public string SerialNo { get; set; }       // 板码，和 Unit.SerialNo 同类型
    public int StepNo { get; set; }            // 工序序号（记序号，不记工序码）
    [SugarColumn(ColumnDataType = "nvarchar(30)")]
    public string StationCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(10)")]
    public string SlotNo { get; set; }         // 站位号；人工维修换料时写 REPAIR
    [SugarColumn(ColumnDataType = "nvarchar(200)")]
    public string RefDes { get; set; }         // 位号（来自 BOM，可能是 R1-R12 这样的范围）
    [SugarColumn(ColumnDataType = "nvarchar(50)")]
    public string MaterialCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(40)")]
    public string LotNo { get; set; }
}

// 批次谱系：一个批次拆成几个（Split），或几个并成一个（Merge）。父子关系只追加
[SugarTable("LotLink")]
[SugarIndex("IX_LotLink_Parent", nameof(LotLink.ParentLotNo), OrderByType.Asc)]
[SugarIndex("IX_LotLink_Child", nameof(LotLink.ChildLotNo), OrderByType.Asc)]
public class LotLink
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(40)")]
    public string ParentLotNo { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(40)")]
    public string ChildLotNo { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(10)")]
    public string Relation { get; set; }       // Split 拆分 / Merge 合并
    [SugarColumn(ColumnDataType = "decimal(18,3)")]
    public decimal Qty { get; set; }
    public DateTime CreatedAt { get; set; }
}

第 2 步：新建 LabMatTrace.cs：

csharp
using SqlSugar;

namespace MiniMes;

// 物料追溯实验：造上料记录和过站数据 -> 出站时生成站位快照 -> 正向、反向追溯 -> 和手算核对
public static class LabMatTrace
{
    public class FwdRow { public string WoId { get; set; } public string SerialNo { get; set; } public string Status { get; set; } }

    static readonly DateTime T0 = new(2026, 10, 20, 8, 0, 0);
    static DateTime At(int min, int sec = 0) => T0.AddMinutes(min).AddSeconds(sec);

    // 工站属于哪条线：真实系统查 Station 主数据，这里写死一个
    static readonly Dictionary<string, string> LineOf = new() { ["SMT-01"] = "MT-L1" };

    // 出站时调用：把"此刻这条线上各站位装的料"抄一份挂到这块板上。返回新增行数；重复调用返回 0
    public static int Snapshot(SqlSugarClient db, string sn, int stepNo)
    {
        var tr = db.Queryable<TrackRecord>().First(r => r.SerialNo == sn && r.StepNo == stepNo && r.Result == "Pass");
        var product = db.Queryable<Unit>().First(u => u.SerialNo == sn).ProductCode;
        var bom = db.Queryable<Bom>().First(b => b.ProductCode == product && b.Status == "Active");
        var refDes = db.Queryable<BomItem>().Where(i => i.BomId == bom.BomId).ToList()
            .ToDictionary(i => i.MaterialCode, i => i.RefDes ?? "");
        string line = LineOf[tr.StationCode];
        // 出站那一刻"装着"的料：装上时间 <= 出站时间，且还没卸下（或卸下时间在出站之后）
        var loads = db.Queryable<SlotLoad>().Where(s => s.LineCode == line).ToList()
            .Where(s => s.LoadedAt <= tr.OutAt && (s.UnloadedAt == null || s.UnloadedAt > tr.OutAt)).ToList();
        int n = 0;
        foreach (var s in loads)
        {
            string slot = s.SlotNo.ToString();
            if (db.Queryable<UnitMaterial>().Any(m => m.SerialNo == sn && m.StepNo == stepNo && m.SlotNo == slot)) continue;
            db.Insertable(new UnitMaterial
            {
                SerialNo = sn, StepNo = stepNo, StationCode = tr.StationCode, SlotNo = slot,
                RefDes = refDes.GetValueOrDefault(s.MaterialCode, ""), MaterialCode = s.MaterialCode, LotNo = s.LotNo,
            }).ExecuteCommand();
            n++;
        }
        return n;
    }

    // 正向追溯：某个批次（含它拆出来的所有子批次）影响了哪些板
    public static List<FwdRow> Forward(SqlSugarClient db, string lot) => db.Ado.SqlQuery<FwdRow>(@"
WITH Lots(LotNo) AS (
    SELECT CAST(@lot AS nvarchar(40))
    UNION ALL
    SELECT l.ChildLotNo FROM LotLink l JOIN Lots p ON l.ParentLotNo = p.LotNo
)
SELECT DISTINCT u.WoId, m.SerialNo, u.Status
FROM UnitMaterial m JOIN Unit u ON u.SerialNo = m.SerialNo
WHERE m.LotNo IN (SELECT LotNo FROM Lots)
ORDER BY m.SerialNo", new { lot });

    public static string Show(List<FwdRow> rows) =>
        $"{string.Join(", ", rows.Select(r => r.SerialNo))}（{rows.Count} 块；" +
        $"{string.Join(" ", rows.GroupBy(r => r.WoId).OrderBy(g => g.Key).Select(g => $"{g.Key}:{g.Count()}"))}）";

    static void NewBoard(SqlSugarClient db, string sn, string wo, DateTime inAt, DateTime outAt)
    {
        db.Insertable(new Unit { SerialNo = sn, WoId = wo, ProductCode = Seed.Product, CurrentStepNo = 30, Status = "InProcess", CreatedAt = inAt }).ExecuteCommand();
        db.Insertable(new TrackRecord
        {
            SerialNo = sn, WoId = wo, StepNo = 30, StepCode = "MOUNT", Result = "Pass", StationCode = "SMT-01",
            OperatorCode = "OP001", InAt = inAt, OutAt = outAt,
        }).ExecuteCommand();
    }

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(SlotLoad), typeof(UnitMaterial), typeof(LotLink));
        db.Deleteable<UnitMaterial>().Where(m => m.SerialNo.StartsWith("MT-")).ExecuteCommand();
        db.Deleteable<TrackRecord>().Where(r => r.SerialNo.StartsWith("MT-")).ExecuteCommand();
        db.Deleteable<Unit>().Where(u => u.SerialNo.StartsWith("MT-")).ExecuteCommand();
        db.Deleteable<WorkOrder>().Where(w => w.WoNo.StartsWith("WO-MT-")).ExecuteCommand();
        db.Deleteable<SlotLoad>().Where(s => s.LineCode == "MT-L1").ExecuteCommand();
        db.Deleteable<LotLink>().Where(l => l.ParentLotNo.StartsWith("LOT-C-9")).ExecuteCommand();
        foreach (var no in new[] { "WO-MT-001", "WO-MT-002" })
            db.Insertable(new WorkOrder { WoNo = no, ProductCode = Seed.Product, PlanQty = 100, Status = "Running", CreatedAt = At(0) }).ExecuteCommand();

        // 1. 上料记录：S01 的电阻料盘 09:00 换，S02 的电容料盘 09:15 换，S03 的 MCU 全程不换
        db.Insertable(new List<SlotLoad>
        {
            new() { LineCode = "MT-L1", SlotNo = "S01", MaterialCode = "R-10K-0402", LotNo = "LOT-R-001", Qty = 5000, LoadedAt = At(0), UnloadedAt = At(60), Operator = "OP101" },
            new() { LineCode = "MT-L1", SlotNo = "S01", MaterialCode = "R-10K-0402", LotNo = "LOT-R-002", Qty = 5000, LoadedAt = At(60), Operator = "OP101" },
            new() { LineCode = "MT-L1", SlotNo = "S02", MaterialCode = "C-100N-0402", LotNo = "LOT-C-001", Qty = 5000, LoadedAt = At(0), UnloadedAt = At(75), Operator = "OP101" },
            new() { LineCode = "MT-L1", SlotNo = "S02", MaterialCode = "C-100N-0402", LotNo = "LOT-C-002", Qty = 5000, LoadedAt = At(75), Operator = "OP102" },
            new() { LineCode = "MT-L1", SlotNo = "S03", MaterialCode = "IC-MCU-32", LotNo = "LOT-U-001", Qty = 1000, LoadedAt = At(0), Operator = "OP101" },
        }).ExecuteCommand();
        Console.WriteLine("1. 线体 MT-L1 的上料记录：5 条（S01 在 09:00 换了料盘，S02 在 09:15 换了料盘）");

        // 2. 6 块板的贴片过站（出站时刻见词条里的表），出站时生成快照
        var boards = new (string Sn, string Wo, int InMin, int InSec, int OutMin, int OutSec)[]
        {
            ("MT-0001", "WO-MT-001", 30, 0, 30, 30), ("MT-0002", "WO-MT-001", 50, 0, 50, 30),
            ("MT-0003", "WO-MT-001", 59, 45, 60, 15), ("MT-0004", "WO-MT-001", 70, 0, 70, 30),
            ("MT-0005", "WO-MT-002", 80, 0, 80, 30), ("MT-0006", "WO-MT-002", 90, 0, 90, 30),
        };
        int total = 0;
        foreach (var b in boards)
        {
            NewBoard(db, b.Sn, b.Wo, At(b.InMin, b.InSec), At(b.OutMin, b.OutSec));
            total += Snapshot(db, b.Sn, 30);
        }
        Console.WriteLine($"2. 6 块板贴片出站后生成快照：共写入 {total} 行 UnitMaterial");
        Console.WriteLine($"   再对 MT-0001 生成一次快照 -> 新增 {Snapshot(db, "MT-0001", 30)} 行（重复调用不翻倍）");

        // 3. 反向追溯：MT-0003 用了哪些料
        Console.WriteLine("3. 反向追溯 MT-0003（09:00:15 出站，正好在 S01 换盘之后）：");
        foreach (var m in db.Queryable<UnitMaterial>().Where(m => m.SerialNo == "MT-0003").OrderBy(m => m.SlotNo).ToList())
            Console.WriteLine($"   {m.SlotNo} {m.MaterialCode,-12} {m.LotNo}  位号 {m.RefDes}");

        // 4. 正向追溯
        Console.WriteLine($"4. 正向追溯 LOT-R-001 -> {Show(Forward(db, "LOT-R-001"))}");
        Console.WriteLine($"   正向追溯 LOT-R-002 -> {Show(Forward(db, "LOT-R-002"))}");
        Console.WriteLine($"   正向追溯 LOT-C-001 -> {Show(Forward(db, "LOT-C-001"))}");
        Console.WriteLine($"   正向追溯 LOT-U-001 -> {Show(Forward(db, "LOT-U-001"))}");

        // 5. 和手算结果核对（手算表见词条）
        var expected = new Dictionary<string, string[]>
        {
            ["LOT-R-001"] = new[] { "MT-0001", "MT-0002" },
            ["LOT-R-002"] = new[] { "MT-0003", "MT-0004", "MT-0005", "MT-0006" },
            ["LOT-C-001"] = new[] { "MT-0001", "MT-0002", "MT-0003", "MT-0004" },
            ["LOT-C-002"] = new[] { "MT-0005", "MT-0006" },
            ["LOT-U-001"] = new[] { "MT-0001", "MT-0002", "MT-0003", "MT-0004", "MT-0005", "MT-0006" },
        };
        int okCount = expected.Count(e => Forward(db, e.Key).Select(r => r.SerialNo).SequenceEqual(e.Value));
        Console.WriteLine($"5. 手算核对：{expected.Count} 个批次，查询结果与手算一致 {okCount} 个");

        // 6. 不用快照，直接按时间窗口去上料记录里"重建"：MT-0003 的进出站窗口跨过换盘时刻，会被多算进来
        var win = db.Ado.SqlQuery<string>(@"
SELECT DISTINCT t.SerialNo
FROM TrackRecord t JOIN SlotLoad s ON s.LineCode = 'MT-L1' AND s.LotNo = @lot
 AND s.LoadedAt <= t.OutAt AND (s.UnloadedAt IS NULL OR s.UnloadedAt > t.InAt)
WHERE t.StepCode = 'MOUNT' AND t.StationCode = 'SMT-01' AND t.SerialNo LIKE 'MT-%'
ORDER BY t.SerialNo", new { lot = "LOT-R-001" });
        Console.WriteLine($"6. 按时间窗口重建 LOT-R-001 -> {string.Join(", ", win)}（{win.Count} 块，比快照多出跨换盘时刻的 MT-0003）");

        // 7. 批次拆分：供应商大盘 LOT-C-900 拆出 LOT-C-002 和 LOT-C-003，追溯大盘要把子批次一起带上
        db.Insertable(new List<LotLink>
        {
            new() { ParentLotNo = "LOT-C-900", ChildLotNo = "LOT-C-002", Relation = "Split", Qty = 5000, CreatedAt = At(0) },
            new() { ParentLotNo = "LOT-C-900", ChildLotNo = "LOT-C-003", Relation = "Split", Qty = 5000, CreatedAt = At(0) },
        }).ExecuteCommand();
        Console.WriteLine($"7. 拆批后正向追溯 LOT-C-900（拆出 LOT-C-002、LOT-C-003）-> {Show(Forward(db, "LOT-C-900"))}");
    }
}

读懂输出：

  • 场景 2：6 块板共 18 行，和手算一致；再对 MT-0001 生成一次，新增 0 行（"已存在就跳过"加唯一索引）。

  • 场景 4、5：4 个批次的正向追溯各自和手算表一致，脚本里另有 LOT-C-002 共 5 个批次用手算数据逐个比对，"一致 5 个"。
  • 场景 6：不用快照、直接按时间窗口重建 LOT-R-001，结果多了 MT-0003。这就是前面说的歧义：它的窗口跨过了换盘线，窗口法"宁多勿漏"。快照法给的是出站时刻的料，在这块板上也不一定百分之百精确（它的前半个窗口也许用的是旧盘），所以边界上的板应该被当作"可疑板"一并隔离，或者用设备贴装数据确认。
  • 场景 7：LOT-C-900 拆成 LOT-C-002、LOT-C-003 后，追溯大盘能找到用过子批次的 MT-0005、MT-0006。

动手改（我都实际改过运行过）：

  • 在 LotLink 里再插入一行 LOT-C-002 → LOT-C-900（造一个环：大盘拆出子盘，子盘又"拆出"大盘），再跑场景 7：SQL Server 报错 530，意思是递归超过了默认的 100 层。（做完记得把这行删掉。）
  • 删掉 Snapshot 里 Any(...) 那一行检查，再跑：场景 2 里第一次仍是 18 行，但"重复生成"那一步会因为唯一索引 UX_UnitMaterial_Slot 报"Cannot insert duplicate key row"。程序里的检查是礼貌，数据库里的唯一索引才是底线。

常见坑与排查 ​

误区 / 坑事实与办法
只存上料记录，追溯时再对时间慢、边界有歧义、历史可能被改。出站时抄快照
快照和出站不在同一个事务出现"板出站了没快照"，追溯缺口。同事务，或用完整性检查兜底
区间写成闭区间换盘瞬间一个站位命中两行。装上 <= t < 卸下
正向追溯只查当前批次，不认谱系供应商大批次有问题时查不到子批次。沿 LotLink 递归
递归 CTE 锚点类型不一致报类型不匹配。CAST(@lot AS nvarchar(40))
位号存范围，想追溯到某个电阻范围只能到"这个料号在这块板上"。要位号级就展开或用设备数据
板码列 varchar / nvarchar 混用连表时隐式转换，索引失效，见 MES核心数据模型
快照表不分区不归档一年上亿行，查询和维护越来越慢。按月分区
维修换了料却没更新追溯板上的料已经不是快照记的了，见 返修与维修管理

练习题与答案 ​

  1. 为什么不直接用上料记录和过站记录按时间对着查，非要抄一份快照？ 答：时间匹配慢、依赖时钟精度、换料边界有歧义，且上料记录日后可能被更正或归档，结果会变。快照是当时事实的固化。
  2. 站位 S01 在 09:00:00 从 LOT-R-001 换成 LOT-R-002，一块 09:00:00 出站的板，快照该抄哪个？ 答：LOT-R-002。区间是左闭右开：LoadedAt <= 出站时间 < UnloadedAt，旧盘 09:00:00 不再命中。
  3. 实验里 MT-0003 的正向追溯结果为什么按快照法不在 LOT-R-001 里，按窗口法却在？ 答：它 09:00:15 出站，快照取出站时刻，此时 S01 是新盘。它的进站在 08:59:45，窗口跨过换盘，窗口法两盘都算。
  4. 供应商通知大盘 LOT-C-900 有问题，而上线用的是拆出的 LOT-C-002，怎么追？ 答：沿 LotLink 递归找到所有子批次，再查用过这些子批次的板。
  5. 一条线一天 8000 块板、60 个站位，快照一年大约多少行？如果每行 241 字节（含索引）大约多大？ 答：8000 × 60 × 250 = 1.2 亿 行；1.2 亿 × 241 字节 ≈ 28.9 × 10^9 字节 ≈ 27 GiB。
  6. 为什么 UnitMaterial 要记 StepNo 而不是工序码？ 答：双面板贴片工序出现两次，工序码相同，只有序号能分清 A 面还是 B 面。
  7. 正向追溯的索引为什么建成 (LotNo, SerialNo) 而不是只有 (LotNo)？ 答：查批次要拿到板码，板码在索引键里就不用回表，读页更少。
  8. 板出站的事务提交了，但快照生成失败了，会怎样？怎么发现？ 答：这块板追溯缺一块。用完整性检查（"贴片已出站却没有快照"），见 产品追溯。
  9. 一块板维修时更换了 U1，原来的快照该改还是追加？ 答：追加，不改旧行。这样旧批次的追溯链还在，且能通过更晚的一行得知它"已被更换"，见 返修与维修管理。
  10. 什么时候必须引入设备贴装数据，而不是只靠站位快照？ 答：要追溯到"具体哪个位号用了哪盘料"，或客户合同要求最高等级追溯时；站位快照只能到"这块板的这个料号可能来自哪几盘"。

小结 ​

  • 追溯 = 板与料批次之间一条能查的线；出站时抄站位快照（UnitMaterial）是最常用的做法，比事后按时间对齐更快、更稳。
  • 区间用左闭右开；换料边界上的板有歧义，应作为可疑板处理，要更精确用设备贴装数据。
  • 反向追溯按板码查，正向追溯按批次查，要沿 LotLink 递归带上子批次；两个方向各建一个索引。
  • 快照表很大（实测 120 万行约 276 MiB，一年约 27 GiB 的量级），按月分区、归档，或做快照去重。
  • 快照与出站要同事务，缺口用完整性检查兜底。
