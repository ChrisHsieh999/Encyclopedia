SMT上料防错与站位表

AI 生成 · 待核对制造业务MESSMT防错上料更新于 2026-10-21

⚠ 待核对：站位表、上料比对、接料、剩余数量预警的流程是 SMT 车间的通用做法，你们自研 MES 是在 MES 里扫码比对，还是由贴片机自带的料站校验（很多厂商的贴片机/上料系统自带）完成，料盘条码长什么样，替代料怎么批准，预警阈值是多少，都可能不同，请对照你们的系统。代码和输出是我在本机 SQL Server LocalDB 上实际运行得到的；"料盘条码"用的是 P=料号|1T=批次|Q=数量 的简化格式（风格参照 物料标签与条码），不是任何厂商的真实格式。

本篇是 MES 系列第 9 篇，在 过站与工序流转 的进站检查清单里对应第 6 项"物料已上对"。读完你应该能：说清站位表（Feeder Map）是什么、长什么样；说出上料时扫码比对的每一步；区分错料、替代料、重复上料、站位被占用各自怎么处理；设计上料记录（SlotLoad）并保证"一个站位同一时刻只有一盘在线"；估算料盘剩余数量并做预警；理解换料和接料的区别；并用 C# + SqlSugar 把这些跑一遍。

一句话定义 ​

站位表（Feeder Map，也叫料站表、Feeder List）是一张"这个产品在这条线上，每个站位应该装哪种料"的对照表；上料防错就是每装一盘料，先扫料盘条码，让系统对着站位表核对"这盘料是不是这个站位该装的"，对不上就当场拦住。

先修知识 ​

  • SMT与电子组装流程：知道贴片机是什么、料盘（Reel）和供料器（Feeder）怎么配合。
  • BOM与物料清单：知道位号（RefDes）、单耗和替代料。
  • 过站与工序流转：知道进站检查清单和"条件 UPDATE"，本篇要用 TrackRecord 估算用量。
  • 物料标签与条码：知道料盘标签上有料号、批次、数量。

它解决什么问题 ​

贴片机的每个站位（Slot，也叫料站）装一盘料：1 号机第 1 个站位装 10K 电阻，第 2 个站位装 100nF 电容……一台机器常有几十个站位，一条线有好几台。贴片机只认站位号："去 1-01 站位吸料，贴到 R1 的位置"。它不知道这个站位上实际装的是不是 10K 电阻。

没有防错时的现场：

  • 错料：操作员把 100nF 电容盘装进了电阻的站位。两种料封装可能一模一样（都是 0402），机器照贴不误。整批板子的 R1–R12 位置全是电容，到 AOI 或 ICT 才发现，已经贴了几百上千块。
  • 漏换料：换产品时，站位表变了，但有一两个站位的料盘没换，混着新旧产品的料。
  • 重复上料：同一盘料被装在两个站位，或者一个站位压着两盘，后果是物料消耗、追溯对不上。
  • 用完没人知道：料盘中途用完，机器报"缺料"停机，等换料的几分钟里整条线空转。
  • 追溯断档：客户投诉某批板子电容有问题，但没有任何记录说明那几块板上的电容来自哪盘料。

上料防错把这些变成：装料前核对（防错）、装料后记录（追溯）、装料中估算余量（预警）。

核心概念 ​

站位表 FeederMap ​

站位表是主数据。一行回答："产品 P，在线体 L 的站位 S，应该装料 M"。字段：

字段含义例
ProductCode哪个产品PCBA-A100
LineCode哪条线SMT-L1
SlotNo站位号，带机台前缀M1-01（1 号机第 1 站位）
MaterialCode应装的料号R-10K-0402
AltMaterialCode允许的替代料（可空）C-100N-0402-B
RefDes这个站位负责的位号R1-R12

这张表是怎么来的？一般由工艺工程师用贴片机编程软件导出的"料站表"，对着 BOM与物料清单 整理出来：BOM 说"要什么料"，站位表说"这些料放在机器的哪个位置"。两者要互相校验：站位表里同一个料号的位号个数，应该等于 BOM 里的单耗；BOM 里每个需要贴片的料都应该出现在站位表里。

(ProductCode, LineCode, SlotNo) 必须唯一，实验里用唯一索引保证。

多机台、双轨：一条线通常有多台贴片机，所以站位号要带机台前缀（M1-01、M2-01）。双轨贴片机有前后两个轨道，可以同时贴两块板，站位号常再带轨道/前后标记（如 M1-F01、M1-R01）：同一种料如果前后轨道都要用，就在两个站位各装一盘，站位表里是两行。不同产品的站位表不同，同一条线换产品时整张表要换——这正是下一篇 首件检验与换线 里"换料"的由来。

料盘条码到物料 ​

操作员扫的是料盘上的标签。料盘标签（来料标签或仓库打印的内部标签，见 物料标签与条码）里至少有三样信息：料号、批次（或料盘 ID）、数量。本篇实验用一个简化格式：

text
P=R-10K-0402|1T=LOT-R001|Q=5000

P 是料号，1T 是批次，Q 是数量（P、1T、Q 这些前缀的做法参照电子元件行业常用的数据标识符，真实标签的解析规则见 物料标签与条码）。解析不出这三项，直接拦截。

上料比对流程 ​

每扫一盘料，系统按顺序做下面的检查，任一步不通过就拒绝，并说明原因：

text
扫料盘条码
  1. 能解析出 料号 / 批次 / 数量？          否 -> 拦截：条码无法解析
  2. 这个站位在站位表里？                  否 -> 拦截：站位不在站位表
  3. 料号 = 站位表主料号？
       是 -> 物料正确
       否 -> 料号 = 替代料？ 是 -> 替代料放行（要留记录）
                            否 -> 拦截：错料
  4. 这个批次已经在线上别处了？            是 -> 拦截：重复上料
  5. 这个站位已经有一盘在线？              是 -> 拦截：先下料，或走接料
  6. 先进先出：有更早入库、还没用完的批次？  是 -> 提醒（或拦截，看厂规）
  7. 写上料记录 SlotLoad，站位变成"在线"

几个要点：

替代料：BOM 里常有"主料 + 替代料"（见 BOM与物料清单），例如同规格不同品牌的电容。站位表的 AltMaterialCode 就是"这个站位允许装的替代料"。替代料放行必须留记录：SlotLoad.MaterialCode 存的是实际装上的料号，不是站位表的主料号，追溯时才能知道这几块板用的是替代料。不同品牌的替代料有时需要品质批准，批准结果应该进到主数据里（谁、什么时候批准），不要让操作员现场决定。

先进先出（FIFO，见 先进先出与先到先用）：同一个料号的多个批次，应该先用入库早的。这里的陷阱是尾料：一盘没用完下线的料退回仓库后，要标上"尾料"，下次优先领用，否则它会一直躺在仓库里，直到过了保质期或湿敏时限（见 MSD湿敏元件管理）。实验里把"有更早批次"做成提醒，真实系统通常按物料类型决定提醒还是拦截。

一个站位同一时刻只能有一盘在线：靠程序判断不够，实验里用 SQL Server 的筛选唯一索引在数据库层面保证（见"技术视角"）。

上料、下料、接料、换料 ​

动作含义记录怎么写
上料站位上原来没有料，装一盘新增一行 SlotLoad，UnloadedAt 为空
下料把站位上的料盘取下来（用完、换产品、换料）给这行补写 UnloadedAt；估算剩余数量，尾料退库
换料下料 + 上料（先停机或站位空着）两个动作，各留一条记录
接料不停机：旧盘快用完时，把新盘的料带接在旧盘料带尾部，让机器连续吸料一个事务：旧盘补 UnloadedAt，新盘新增一行；新盘一样要过比对

接料是 SMT 车间的日常，它的风险比普通上料更高：机器没停，装错的料会立刻被贴到板子上。所以接料必须扫码比对，且新旧盘要在同一个事务里切换，记录里不能出现"旧盘已下线、新盘还没上"的空档，更不能出现"两盘同时在线"。

剩余数量估算 ​

料盘上有多少料，机器不一定告诉 MES。一个够用的估算办法是：

text
已用数量 = 上料之后贴过的板数 × 这个站位每块板的用量
剩余数量 = 上料时的数量 - 已用数量
还能贴的板数 = 剩余数量 ÷ 每块板用量（向下取整）

"每块板的用量"等于这个站位负责的位号个数：R1-R12 是 12 个，U1 是 1 个。"贴过的板数"可以来自 过站与工序流转 的 TrackRecord（贴片站出站 Pass 的数量），也可以由贴片机上报的计数得到（见 SMT设备接口）。当"还能贴的板数"低于某个阈值（例如 20 块，大约十来分钟的量）就预警，提醒备料、接料。

这只是估算：抛料（机器吸料后没贴上就扔掉）、首件调试、换料头尾的损耗，都会让实际消耗大于理论值。所以要给估算留余量，并且在下料时核对（称重或点数）。贴片机自己记录的吸料/抛料计数比 MES 估算更准，如果能接到（见 SMT设备接口）就优先用。

业务视角 ​

谁在什么环节做什么：

角色动作
工艺工程师维护站位表：新产品导入时编制，工程变更时更新；批准替代料
仓库/备料员按工单和站位表备料（领出整盘），尾料回库时标注
上料员（物料员）换线时按站位表上料；生产中接料；每次都扫码
线长处理拦截；看预警；决定尾料怎么处理
品质抽查上料记录；出了问题按上料记录追溯

换线备料的典型流程（和 首件检验与换线 衔接）：

  1. 计划确定下一张工单后，备料员按站位表把所有料盘领出，按站位顺序摆在料车上，这叫备料或"预上料"；
  2. 上一单结束，旧料盘全部下料，估算剩余并退库；
  3. 上料员按站位表逐站上料，每盘都扫码，被拦截的料盘放到一边等线长处理；
  4. 全部站位上料完成并核对通过，才能申请首件；
  5. 生产中，系统按预警提示接料。

常见规则：

  • 站位表未完成比对（有站位没装、有站位装错）→ 不允许开线（在进站检查里体现）。
  • 湿敏元件（MSD）开封后有时限，上料记录要能回答"这盘料开封多久了"。
  • 一个料盘的数量不能凭空增加：下料时的剩余加上已用，应小于等于上料时的数量。

KPI：

  • 错料拦截次数（以及漏拦的次数，应当是 0）；
  • 上料一次通过率（扫码即通过的比例）；
  • 换线上料耗时；
  • 缺料停机次数/时长（预警的效果）；
  • 抛料率（需要机台数据）。

技术视角 ​

表设计 ​

两个实体由本篇定义（后面的 物料追溯与批次关联、产品追溯 等词条会引用 SlotLoad，字段名请不要改）：

实体类别作用
FeederMap主数据站位表：产品-线体-站位-主料号-替代料-位号
SlotLoad记录（流水型）上料记录：每装一盘一行；下料时只补写 UnloadedAt

SlotLoad 严格说不是"纯只追加"：下料要补写 UnloadedAt。可以接受的前提是只允许补写这一列，且只能从空写成有值一次；更严格的设计是把上料和下料拆成两条事件记录，由查询推出"在线"。本篇用前者，因为简单、查"当前在线什么"很快。

筛选唯一索引保证一个站位同一时刻最多一盘在线（和 MES 里"同一产品最多一个生效 BOM"同一个手法）：

sql
CREATE UNIQUE INDEX UX_SlotLoad_Active ON SlotLoad(LineCode, SlotNo) WHERE UnloadedAt IS NULL;

据微软文档，筛选索引只对满足条件的行建索引，且可以带 UNIQUE。这里的意思是：只看没下线的行，同一个 (LineCode, SlotNo) 只能出现一次。已下线的历史行不受限制。有了它，即使两个终端同时上料、或者有人绕过程序直接 INSERT，数据库都会拒绝第二盘。

关键查询 ​

  1. 现在线上有什么：
sql
SELECT SlotNo, MaterialCode, LotNo, CASE WHEN UnloadedAt IS NULL THEN 'Online' ELSE 'Offline' END AS St
FROM SlotLoad WHERE LineCode = 'SMT-L1' ORDER BY Id;
  1. 反向追溯：某盘料用在了哪些板上（上料时段内，该站位所在工序出站 Pass 的板）：
sql
SELECT s.LotNo, s.SlotNo, COUNT(t.Id) AS Boards
FROM SlotLoad s JOIN TrackRecord t
  ON t.StepCode = 'MOUNT' AND t.Result = 'Pass' AND t.WoId = 'WO-FDR-001'
 AND t.OutAt >= s.LoadedAt AND (s.UnloadedAt IS NULL OR t.OutAt < s.UnloadedAt)
WHERE s.LotNo = 'LOT-R001'
GROUP BY s.LotNo, s.SlotNo;

这个查询靠时间区间把"料盘在站位上的时段"和"板子出站的时间"对上。它能成立的前提是上料记录和过站记录的时间可信（服务器时间统一），且板子是按这个线体的这些站位贴的。真实系统里线体、机台应该直接写进 TrackRecord（或贴片机上报的贴装明细），不要只靠时间推。这正是 物料追溯与批次关联 要深入的内容。

并发与一致性 ​

  • 接料必须在一个事务里：旧盘补 UnloadedAt 和新盘 INSERT 要么都成功要么都失败。
  • 拒绝要带原因：错料、重复、站位被占用的提示不同，操作员才知道下一步怎么做。
  • 所有比对在服务端做：前端比对可以被设备接口、其他程序绕过。
  • 拦截事件也要记录：本篇实验没有把被拦截的扫码写进库（SlotLoad 只记成功上料）。真实系统应该有单独的"拦截日志"，用来统计错料次数、发现习惯性出错的人或站位。
  • 站位表要版本化：产品换了 BOM 版本，站位表也要跟着变，已经生产的批次要能查到当时用的是哪一版。

逐步例子：一次换线上料 ​

产品 PCBA-A100，线体 SMT-L1，站位表 3 行（实验里的数据）：

站位主料号替代料位号每板用量
M1-01R-10K-0402—R1-R1212
M1-02C-100N-0402C-100N-0402-BC1-C88
M2-01IC-MCU-32—U11

操作过程与系统反应：

  1. 扫 P=R-10K-0402|1T=LOT-R001|Q=5000 到 M1-01：料号等于主料号 → 放行，写一行 SlotLoad。
  2. 把一盘电阻（LOT-R002）装到 M1-02：M1-02 应为 C-100N-0402，扫到 R-10K-0402，既不是主料也不是替代料 → 拦截（错料），库里没有新记录。
  3. 把 C-100N-0402-B（LOT-C900）装到 M1-02：等于替代料 → 替代料放行，SlotLoad.MaterialCode 存的是 C-100N-0402-B。
  4. 再扫一次 LOT-R001 到 M1-01 → 拦截（重复上料）；把 LOT-R002 直接压到有料的 M1-01 → 拦截（站位已有料盘）。
  5. 工单跑了 400 块板。M1-01 的 LOT-R001：已用 400 × 12 = 4800，剩余 5000 − 4800 = 200，能贴 ⌊200 ÷ 12⌋ = 16 块板，低于 20 → 预警。M1-02 的 LOT-C900：已用 400 × 8 = 3200，剩余 6800，能贴 850 块。
  6. 换料：先下 M1-01 的 LOT-R001（估算剩余 200，尾料退库），再装 LOT-R002：放行，但提醒"有更早批次 LOT-R001 还没用完"。
  7. 接料：M1-02 想接一盘单片机 → 拦截（错料），LOT-C900 仍在线；接 LOT-C901（C-100N-0402）→ 一个事务里 LOT-C900 下线、LOT-C901 上线。

csharp
using SqlSugar;

namespace MiniMes;

// 站位表（主数据）：某个产品在某条线的某个站位，应该装什么料。
// (ProductCode, LineCode, SlotNo) 唯一：同一个站位只能有一条规则
[SugarTable("FeederMap")]
[SugarIndex("UX_FeederMap_Slot", nameof(FeederMap.ProductCode), OrderByType.Asc, nameof(FeederMap.LineCode), OrderByType.Asc, nameof(FeederMap.SlotNo), OrderByType.Asc, true)]
public class FeederMap
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(50)")]
    public string ProductCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(20)")]
    public string LineCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(10)")]
    public string SlotNo { get; set; }             // 站位号，带机台前缀，如 M1-01 = 1 号机第 1 个站位
    [SugarColumn(ColumnDataType = "nvarchar(50)")]
    public string MaterialCode { get; set; }       // 这个站位应该装的料号
    [SugarColumn(ColumnDataType = "nvarchar(50)", IsNullable = true)]
    public string AltMaterialCode { get; set; }    // 允许的替代料（可空）
    [SugarColumn(ColumnDataType = "nvarchar(200)", IsNullable = true)]
    public string RefDes { get; set; }             // 这个站位负责的位号，对应 BomItem.RefDes
}

// 上料记录（流水型）：每装一盘料一行；下料时只补写 UnloadedAt，其余列不改。
// 同一个 (LineCode, SlotNo) 同一时刻最多一盘在线（UnloadedAt 为空），由筛选唯一索引保证
[SugarTable("SlotLoad")]
[SugarIndex("IX_SlotLoad_Lot", nameof(SlotLoad.LotNo), OrderByType.Asc)]
public class SlotLoad
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)]
    public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(20)")]
    public string LineCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(10)")]
    public string SlotNo { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(50)")]
    public string MaterialCode { get; set; }       // 实际装上的料号（用了替代料时，和站位表的主料号不同）
    [SugarColumn(ColumnDataType = "nvarchar(50)")]
    public string LotNo { get; set; }              // 料盘/批次号
    [SugarColumn(ColumnDataType = "decimal(18,3)")]
    public decimal Qty { get; set; }               // 上料时这盘料的数量
    public DateTime LoadedAt { get; set; }
    [SugarColumn(IsNullable = true)]
    public DateTime? UnloadedAt { get; set; }      // 空 = 还在线上
    [SugarColumn(ColumnDataType = "nvarchar(30)")]
    public string Operator { get; set; }
}

第 2 步：新建 LabFeeder.cs：

csharp
using SqlSugar;

namespace MiniMes;

// 上料防错实验：站位表比对（错料/替代料）、重复上料、下料、接料、剩余数量估算
public static class LabFeeder
{
    const string Line = "SMT-L1";
    const string Wo = "WO-FDR-001";

    // 仓库里的可用料批（真实系统来自库存/物料批表 MaterialLot，这里写死当作"库存"）：料号、批次、入库日
    static readonly (string Mat, string Lot, DateTime Recv)[] Stock =
    {
        ("R-10K-0402", "LOT-R001", new DateTime(2026, 9, 1)),
        ("R-10K-0402", "LOT-R002", new DateTime(2026, 10, 1)),
        ("IC-MCU-32", "LOT-U001", new DateTime(2026, 9, 10)),
        ("IC-MCU-32", "LOT-U002", new DateTime(2026, 10, 2)),
        ("C-100N-0402-B", "LOT-C900", new DateTime(2026, 9, 15)),
        ("C-100N-0402", "LOT-C901", new DateTime(2026, 10, 5)),
    };

    // 料盘条码（简化版 DI 格式）：P=料号|1T=批次|Q=数量
    static (bool Ok, string Mat, string Lot, decimal Qty) Parse(string code)
    {
        var d = code.Split('|').Select(p => p.Split('=', 2)).Where(p => p.Length == 2).ToDictionary(p => p[0], p => p[1]);
        return d.TryGetValue("P", out var m) && d.TryGetValue("1T", out var l) && d.TryGetValue("Q", out var q) && decimal.TryParse(q, out var n)
            ? (true, m, l, n) : (false, null, null, 0);
    }

    // 上料 / 接料（splice = true 时，允许站位上已有一盘，并在同一事务里把旧的下掉）
    static string Load(SqlSugarClient db, string slot, string barcode, bool splice = false)
    {
        var (ok, mat, lot, qty) = Parse(barcode);
        if (!ok) return "拦截：条码无法解析";
        var map = db.Queryable<FeederMap>().First(m => m.ProductCode == Seed.Product && m.LineCode == Line && m.SlotNo == slot);
        if (map == null) return $"拦截：站位 {slot} 不在站位表里";
        string tip;
        if (mat == map.MaterialCode) tip = "物料正确";
        else if (mat == map.AltMaterialCode) tip = $"替代料放行（站位表允许 {mat} 代替 {map.MaterialCode}）";
        else return $"拦截：错料，站位 {slot} 应为 {map.MaterialCode}，扫到 {mat}";

        var active = db.Queryable<SlotLoad>().Where(s => s.LineCode == Line && s.UnloadedAt == null).ToList();
        var dup = active.FirstOrDefault(s => s.LotNo == lot);
        if (dup != null) return $"拦截：料盘 {lot} 已经在站位 {dup.SlotNo} 上";
        var cur = active.FirstOrDefault(s => s.SlotNo == slot);
        if (cur != null && !splice) return $"拦截：站位 {slot} 已有料盘 {cur.LotNo}，请先下料或走接料";

        // 先进先出：同料号、入库更早、又不在线上的批次，提醒先用（这里只提醒不拦截）
        var recv = Stock.First(s => s.Lot == lot).Recv;
        var onLine = active.Select(s => s.LotNo).ToHashSet();
        var older = Stock.Where(s => s.Mat == mat && s.Recv < recv && !onLine.Contains(s.Lot)).Select(s => s.Lot).ToList();
        if (older.Count > 0) tip += $"；提醒：有更早的批次 {string.Join("、", older)} 还没用完，建议先用";

        db.Ado.BeginTran();
        try
        {
            if (cur != null)
                db.Updateable<SlotLoad>().SetColumns(s => new SlotLoad { UnloadedAt = DateTime.Now }).Where(s => s.Id == cur.Id).ExecuteCommand();
            db.Insertable(new SlotLoad { LineCode = Line, SlotNo = slot, MaterialCode = mat, LotNo = lot, Qty = qty, LoadedAt = DateTime.Now, Operator = "OP001" }).ExecuteCommand();
            db.Ado.CommitTran();
        }
        catch { db.Ado.RollbackTran(); throw; }
        return (cur != null ? $"接料成功，{cur.LotNo} 下线，" : "上料成功，") + tip;
    }

    // 位号个数 = 每块板在这个站位要贴几个：R1-R12 是 12 个，U1 是 1 个，R1-R3,R7 是 4 个
    static int CountRefDes(string refDes) => refDes.Split(',').Sum(t =>
    {
        var m = System.Text.RegularExpressions.Regex.Match(t.Trim(), @"^[A-Za-z]+(\d+)-[A-Za-z]*(\d+)$");
        return m.Success ? int.Parse(m.Groups[2].Value) - int.Parse(m.Groups[1].Value) + 1 : 1;
    });

    // 剩余数量估算：初始数量 - 上线后已贴板数 × 每板用量（站位表位号个数）
    static (decimal Used, decimal Left, int Boards) Remain(SqlSugarClient db, SlotLoad s)
    {
        var map = db.Queryable<FeederMap>().First(m => m.ProductCode == Seed.Product && m.LineCode == s.LineCode && m.SlotNo == s.SlotNo);
        int per = CountRefDes(map.RefDes);
        int mounted = db.Queryable<TrackRecord>().Count(t => t.WoId == Wo && t.StepCode == "MOUNT" && t.Result == "Pass" && t.OutAt >= s.LoadedAt);
        decimal used = mounted * per, left = s.Qty - used;
        return (used, left, (int)Math.Floor(left / per));
    }

    static string Unload(SqlSugarClient db, string slot)
    {
        var cur = db.Queryable<SlotLoad>().First(s => s.LineCode == Line && s.SlotNo == slot && s.UnloadedAt == null);
        if (cur == null) return "站位上没有料盘";
        var r = Remain(db, cur);
        db.Updateable<SlotLoad>().SetColumns(s => new SlotLoad { UnloadedAt = DateTime.Now }).Where(s => s.Id == cur.Id).ExecuteCommand();
        return $"下料成功，{cur.LotNo} 估算剩余 {r.Left:0.###}，应退回仓库（尾料）";
    }

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        db.CodeFirst.InitTables(typeof(Unit), typeof(TrackRecord), typeof(FeederMap), typeof(SlotLoad));
        db.Ado.ExecuteCommand(@"
IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'UX_SlotLoad_Active')
    CREATE UNIQUE INDEX UX_SlotLoad_Active ON SlotLoad(LineCode, SlotNo) WHERE UnloadedAt IS NULL;");
        db.Deleteable<SlotLoad>().Where(s => s.LineCode == Line).ExecuteCommand();
        db.Deleteable<FeederMap>().Where(m => m.LineCode == Line).ExecuteCommand();
        db.Deleteable<TrackRecord>().Where(t => t.WoId == Wo).ExecuteCommand();

        db.Insertable(new List<FeederMap>
        {
            new() { ProductCode = Seed.Product, LineCode = Line, SlotNo = "M1-01", MaterialCode = "R-10K-0402", RefDes = "R1-R12" },
            new() { ProductCode = Seed.Product, LineCode = Line, SlotNo = "M1-02", MaterialCode = "C-100N-0402", AltMaterialCode = "C-100N-0402-B", RefDes = "C1-C8" },
            new() { ProductCode = Seed.Product, LineCode = Line, SlotNo = "M2-01", MaterialCode = "IC-MCU-32", RefDes = "U1" },
        }).ExecuteCommand();

        Console.WriteLine("站位表（产品 PCBA-A100，线体 SMT-L1）：M1-01=R-10K-0402，M1-02=C-100N-0402（可用 C-100N-0402-B 代替），M2-01=IC-MCU-32");
        Console.WriteLine("1. 上料正确：");
        Console.WriteLine($"   M1-01 扫 LOT-R001 -> {Load(db, "M1-01", "P=R-10K-0402|1T=LOT-R001|Q=5000")}");
        Console.WriteLine($"   M2-01 扫 LOT-U001 -> {Load(db, "M2-01", "P=IC-MCU-32|1T=LOT-U001|Q=1000")}");
        Console.WriteLine($"2. 错料拦截：M1-02 扫电阻盘 LOT-R002 -> {Load(db, "M1-02", "P=R-10K-0402|1T=LOT-R002|Q=5000")}");
        Console.WriteLine($"3. 替代料放行：M1-02 扫 LOT-C900（C-100N-0402-B）-> {Load(db, "M1-02", "P=C-100N-0402-B|1T=LOT-C900|Q=10000")}");
        Console.WriteLine("4. 重复上料：");
        Console.WriteLine($"   LOT-R001 再扫一次到 M1-01 -> {Load(db, "M1-01", "P=R-10K-0402|1T=LOT-R001|Q=5000")}");
        Console.WriteLine($"   LOT-R002 想直接装到有料的 M1-01 -> {Load(db, "M1-01", "P=R-10K-0402|1T=LOT-R002|Q=5000")}");
        try
        {
            db.Insertable(new SlotLoad { LineCode = Line, SlotNo = "M2-01", MaterialCode = "IC-MCU-32", LotNo = "LOT-U002", Qty = 1000, LoadedAt = DateTime.Now, Operator = "OP001" }).ExecuteCommand();
            Console.WriteLine("   绕过程序直接 INSERT 第二盘 -> 竟然成功了（索引没生效！）");
        }
        catch (Exception e) { Console.WriteLine($"   绕过程序直接 INSERT 第二盘 -> 数据库拒绝（UX_SlotLoad_Active 命中：{e.Message.Contains("UX_SlotLoad_Active")}）"); }

        // 5. 剩余估算：工单 WO-FDR-001 在上料之后贴了 400 块板（MOUNT 站 Pass 400 条）
        db.Insertable(Enumerable.Range(1, 400).Select(i => new TrackRecord
        {
            SerialNo = $"FDR-{i:0000}", WoId = Wo, StepNo = 30, StepCode = "MOUNT", Result = "Pass",
            StationCode = "SMT-01", OperatorCode = "OP001", InAt = DateTime.Now, OutAt = DateTime.Now,
        }).ToList()).ExecuteCommand();
        Console.WriteLine("5. 剩余数量估算（上料后工单 WO-FDR-001 已贴 400 块板；预警线：可再贴不足 20 块）：");
        foreach (var s in db.Queryable<SlotLoad>().Where(x => x.LineCode == Line && x.UnloadedAt == null).OrderBy(x => x.SlotNo).ToList())
        {
            var r = Remain(db, s);
            Console.WriteLine($"   {s.SlotNo} {s.LotNo} 初始 {s.Qty:0.###}，已用 {r.Used:0.###}，剩余 {r.Left:0.###}（约 {r.Boards} 块板）-> {(r.Boards < 20 ? "预警：准备接料" : "正常")}");
        }

        Console.WriteLine("6. 换料：");
        Console.WriteLine($"   M1-01 下料 -> {Unload(db, "M1-01")}");
        Console.WriteLine($"   M1-01 装 LOT-R002 -> {Load(db, "M1-01", "P=R-10K-0402|1T=LOT-R002|Q=5000")}");
        Console.WriteLine("7. 接料（不停机换盘，新盘必须也过比对）：");
        Console.WriteLine($"   M1-02 接一盘单片机 LOT-U002 -> {Load(db, "M1-02", "P=IC-MCU-32|1T=LOT-U002|Q=1000", splice: true)}");
        Console.WriteLine($"   M1-02 仍在线：{db.Queryable<SlotLoad>().First(s => s.SlotNo == "M1-02" && s.UnloadedAt == null).LotNo}");
        Console.WriteLine($"   M1-02 接 LOT-C901（C-100N-0402）-> {Load(db, "M1-02", "P=C-100N-0402|1T=LOT-C901|Q=10000", splice: true)}");

        Console.WriteLine("8. 当前在线料盘：");
        foreach (var s in db.Queryable<SlotLoad>().Where(x => x.LineCode == Line && x.UnloadedAt == null).OrderBy(x => x.SlotNo).ToList())
            Console.WriteLine($"   {s.SlotNo} {s.MaterialCode} {s.LotNo}");
        int total = db.Queryable<SlotLoad>().Count(s => s.LineCode == Line);
        int online = db.Queryable<SlotLoad>().Count(s => s.LineCode == Line && s.UnloadedAt == null);
        Console.WriteLine($"   上料记录共 {total} 条，其中在线 {online} 条，已下线 {total - online} 条");
    }
}

   M2-01 LOT-U001 初始 1000，已用 400，剩余 600（约 600 块板）-> 正常

   M1-01 下料 -> 下料成功，LOT-R001 估算剩余 200，应退回仓库（尾料）
   M1-01 装 LOT-R002 -> 上料成功，物料正确；提醒：有更早的批次 LOT-R001 还没用完，建议先用
7. 接料（不停机换盘，新盘必须也过比对）：
   M1-02 接一盘单片机 LOT-U002 -> 拦截：错料，站位 M1-02 应为 C-100N-0402，扫到 IC-MCU-32
   M1-02 仍在线：LOT-C900
   M1-02 接 LOT-C901（C-100N-0402）-> 接料成功，LOT-C900 下线，物料正确
8. 当前在线料盘：
   M1-01 R-10K-0402 LOT-R002
   M1-02 C-100N-0402 LOT-C901
   M2-01 IC-MCU-32 LOT-U001
   上料记录共 5 条，其中在线 3 条，已下线 2 条

第 5 步，读懂输出：

  • 场景 1–3 是比对的三种结果：主料放行、错料拦截、替代料放行；
  • 场景 4 有三道防线：同一盘料不能重复扫（程序判断），一个站位不能压两盘（程序判断），最后直接绕过程序 INSERT 第二盘，被筛选唯一索引拒绝——最后一道防线在数据库；
  • 场景 5 用 TrackRecord 里的 400 条贴片 Pass 记录估算余量，只有 16 块板余量的电阻盘被预警；
  • 场景 6 展示 FIFO 提醒：LOT-R001（9 月入库）退回仓库后，装 LOT-R002（10 月入库）会被提醒先用旧的尾料；
  • 场景 7 展示接料：错料的新盘被拦截时旧盘依然在线；正确的新盘一步完成切换；
  • 场景 8 的最终状态：5 行上料记录，3 行在线、2 行已下线。

第 6 步，动手改：

  • 把 LabFeeder 里的 db.Ado.ExecuteCommand(...) 建索引那段删掉，并且手工在库里删掉 UX_SlotLoad_Active（DROP INDEX UX_SlotLoad_Active ON SlotLoad）再运行：场景 4 最后一行会变成"竟然成功了"，同一站位在线两盘。这就是只靠程序判断的风险；
  • 在 Stock 里加一个更早批次的电容，看看接料时的 FIFO 提醒怎么变；
  • 想一想：如果要把"FIFO 提醒"改成"拦截"，应该改哪一行？拦截后现场急用怎么办？（参考练习题 6。）

常见坑与排查 ​

误区 / 坑事实与办法
只比对料号，不记批次追溯需要"哪一盘"。SlotLoad 一定要记批次/料盘 ID
替代料放行后记成主料号追溯时看不出用了替代料。记实际装上的料号
只靠程序保证一个站位一盘并发或绕过接口会出现两盘。用筛选唯一索引
接料不扫码接料时机器没停，装错的料立刻上板。接料也要比对
接料分两步（先下后上）中间失败会留下空档或两盘并存。放进一个事务
站位表和 BOM 不一致位号个数 ≠ 单耗，或 BOM 有料站位表里没有。生效前做校验
换产品没换站位表新旧产品的料混在线上。换线时整张站位表重新比对
剩余数量当精确值抛料、首件损耗会让实际更少。预警留余量，下料时核对
尾料没标记尾料躺仓库过期。退库时标注，领料时优先
只有成功上料有记录被拦截的扫码也有价值，单独记拦截日志
站位号没有机台前缀多机台、双轨会重号。站位号带机台和轨道

练习题与答案 ​

  1. 站位表和 BOM 的分工是什么？ 答：BOM 说产品"需要什么料、各多少"；站位表说这些料在某条线的贴片机上"放在哪个站位"。两者要互相校验，例如站位表里同一料号的位号个数应等于 BOM 单耗。
  2. 为什么替代料放行后，SlotLoad.MaterialCode 要存实际装上的料号？ 答：追溯时要知道这几块板用的是哪种料。若存站位表的主料号，替代料的使用就被掩盖了。
  3. 一盘 Q=8000 的电容，每块板用 8 个，上线后贴了 600 块板，剩余多少、还能贴多少块？ 答：已用 600 × 8 = 4800，剩余 8000 − 4800 = 3200，还能贴 3200 ÷ 8 = 400 块。
  4. 为什么要用筛选唯一索引 WHERE UnloadedAt IS NULL，而不是给 (LineCode, SlotNo) 加普通唯一索引？ 答：普通唯一索引会让同一个站位永远只能有一条记录，换料就插不进去了。筛选索引只约束"没下线"的行，历史行不受限制。
  5. 接料和"先下料再上料"有什么区别？为什么接料要放在事务里？ 答：接料是不停机的，旧盘用完前新盘就接上；它要求旧盘下线与新盘上线原子地发生，否则会出现空档或两盘并存。普通换料是停下来做的两个独立动作。
  6. 把 FIFO 的"提醒"改成"拦截"有什么风险？ 答：现场可能因为旧批次的料盘正好不够、或旧批次受限（待检、湿敏超时）而急需用新批次，硬拦截会停线。常见做法是拦截，同时提供带权限和原因记录的"跳过 FIFO"例外。
  7. 某天发现一批板子的电容有问题，如何用上料记录找到受影响的板？ 答：先按料号/批次在 SlotLoad 找到所有上料行（站位、LoadedAt、UnloadedAt），再用时间区间到 TrackRecord（或贴装明细）找到这个时段该线体贴片出站的板。这是 物料追溯与批次关联 的内容。
  8. 估算的剩余数量为什么可能比实际多？ 答：抛料、首件调试、料带头尾损耗都会消耗理论之外的料，所以实际剩余更少。预警要留余量。

小结 ​

  • 站位表是"产品-线体-站位-料号-替代料-位号"的主数据，由工艺维护，要和 BOM 互相校验。
  • 上料比对按顺序检查：条码可解析、站位在表里、料号对（或替代料）、批次不重复、站位未占用、FIFO，全部通过才写 SlotLoad。
  • 错料拦截、替代料放行（记实际料号）、重复上料、站位占用各自有明确的提示。
  • 一个站位同一时刻一盘，靠筛选唯一索引在数据库保证；接料用事务一步切换，新盘一样要比对。
  • 剩余数量 = 上料数量 − 已贴板数 × 每板用量，是估算，要留余量，贴片机计数更准。
  • 上料记录是物料追溯的起点，实体 SlotLoad 和 FeederMap 由本篇定义。
