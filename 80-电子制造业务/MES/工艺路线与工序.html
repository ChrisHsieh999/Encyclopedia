工艺路线与工序

AI 生成 · 待核对制造业务MES更新于 2026-10-21

⚠ 待核对：工艺路线、工序的概念和电子厂常见做法（工序序号间隔、必经与可选、返工回路、双面板）是通用做法，没有逐条联网核实；你们自研 MES 的路线模型、工序命名、是否支持分支和并行可能不同，请对照核实。代码和输出是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 MES 系列第 4 篇。读完你应该能：说清工艺路线和工序是什么、为什么要有"序号"和"工序码"两个东西；理解路线为什么要有版本；写出"这块板下一步能进哪个工序"的判断逻辑；处理双面板这种工序重复出现的情况；知道设计路线时哪些地方容易出错。

一句话定义 ​

工艺路线（Routing）是一个产品从投料到完工要经过的工序顺序，以及每道工序的要求。工序是路线里的一道加工或检验。

先修知识 ​

  • MES：搭好了"迷你 MES"项目。
  • 工单管理：知道工单下发时会绑定工艺路线的版本。
  • SMT与电子组装流程：知道电子厂里一块板要经过哪些工站。

它解决什么问题 ​

工艺路线回答三个问题：

  1. 这个产品要经过哪些工序？ 否则操作员可能漏掉一站，比如漏了回流焊就把板子送去测试；
  2. 按什么顺序？ 贴片必须在印刷之后、回流焊之前，顺序错了板子就报废；
  3. 每道工序有什么要求？ 用什么设备、什么参数、要不要检验，见 工艺参数与炉温曲线管理。

有了路线，系统才能在板子过站时判断"你现在进这个工序对不对"，把漏站、跳站、重复在源头拦住，见 过站与工序流转。

核心概念 ​

路线里有什么 ​

以 A100 控制板为例，单面板的 SMT 路线是：

序号工序码工序名称
10PRINT锡膏印刷
20SPI锡膏检测
30MOUNT贴片
40REFLOW回流焊
50AOI光学检查

两个关键字段：

  • 工序序号（StepNo）：决定先后顺序，数字越小越早；
  • 工序码（StepCode）：这道工序"是什么"，同样的工序在不同产品里、甚至同一个产品里会出现多次。

为什么序号是 10、20、30，而不是 1、2、3？ 为了以后好插入。如果将来要在贴片和回流之间加一道"炉前检查"，可以给它编号 35，不用把后面的序号全部改掉（改了的话，历史上记录的"已完成第几道"就对不上了）。

序号和工序码为什么要分开 ​

只用工序码判断顺序会出问题：双面板要在 A 面和 B 面各做一遍印刷、SPI、贴片、回流焊，同一个工序码 REFLOW 在路线里出现了两次：

序号工序码名称
10PRINTA面印刷
20SPIA面检测
30MOUNTA面贴片
40REFLOWA面回流
50PRINTB面印刷
60SPIB面检测
70MOUNTB面贴片
80REFLOWB面回流
90AOI光学检查

如果系统只记"这块板过了 REFLOW"，就分不清是 A 面还是 B 面。所以记录"已完成到哪一站"时，要记序号，而不是工序码。设备或工站上通常配置的是"我是什么工序码"，系统结合这块板"已完成的序号"，就能判断它下一步应该是哪一个。

工序的几种类型 ​

类型说明例子
加工改变板子状态的工序印刷、贴片、回流
检验判定好坏，不改变板子SPI、AOI
测试电气或功能测试ICT、FCT
维修不良板的修复返修站

检验和测试工序有判定结果（合格、不合格），不合格的板不能继续往下走，要走返修路线。

返工回路 ​

不良板返修后要回到流程中。常见两种做法：

  • 返修后回到出错的那一站重做（比如 AOI 发现缺件，修复后回到 AOI 复检）；
  • 返修站完成后，回到路线中某个固定的位置。

这意味着板子的"状态"不是单向往前，而是可以回退。实现时要能表达"这块板被判不良，转入返修，修好后回到序号 xx"。具体见 返修与维修管理。

路线要有版本 ​

和 BOM 一样，工艺会改进（加一道检查、调整顺序），所以路线也要有版本：Draft、Active、Obsolete，同一产品同一时间只有一个生效版本，旧版本不删除。工单下发时绑定当时生效的路线版本，之后不受改版影响，规则见 BOM与物料清单 的版本部分。

技术视角：路线的表和进站判断 ​

表设计 ​

Route     (RouteId 主键, ProductCode 产品, Version 版本, Status 状态)
RouteStep (Id 主键, RouteId 所属路线, StepNo 序号, StepCode 工序码, StepName 工序名称)

设计建议：

  • 同一条路线里 StepNo 不能重复，建议加唯一索引 (RouteId, StepNo)；
  • 和 BOM 一样，对 Route 建"同一产品最多一个生效版本"的筛选唯一索引（实验里的 Db.Init 已建）；
  • 工序码不要加唯一约束，因为双面板里同一工序码会出现多次。

真实系统的路线表通常还有更多字段：是否必须经过、是否为检验工序、标准节拍、允许的设备或工位、对应的工艺参数配方等。这些可以逐步加。

进站判断的逻辑 ​

判断"这块板能不能进某个工序"，输入有三个：路线的所有工序、这块板已完成的最后一道工序序号、想进入的工序码。逻辑：

  1. 找到路线里序号大于"已完成序号"的第一道工序，它就是板子应该进的下一道；
  2. 如果没有下一道，说明所有工序都完成了；
  3. 如果想进入的工序码等于下一道的工序码，允许；
  4. 否则拒绝，并给出原因：工序不在路线里、跳站（想进入的工序在后面）、重复（想进入的工序已完成过）。

注意第 4 步判断"跳站"还是"重复"时，不能只找"第一个同名工序"，要看有没有序号更大的同名工序。否则双面板里 已完成 30，想进 PRINT 会被误判成"重复进已完成的工序"，因为路线里第一个 PRINT 的序号是 10（已完成过），而实际上后面还有 B 面的 PRINT（序号 50），正确的提示应该是"跳站，下一道应该是回流焊"。这是我在做这个实验时发现并修正的一个细节。

并发的提醒 ​

两台设备同时扫描同一块板、或同一块板被重复扫描进同一站，会出现重复记录。路线判断只解决"顺序对不对"，防重复要靠过站记录表的唯一约束或"条件写进 UPDATE"的写法，见 过站与工序流转 和 工单管理 里的技巧。

动手实验：读取路线并判断进站 ​

前提：已经按 MES 建好项目并运行了 dotnet run -- init。

第 1 步：新建 LabRoute.cs：

csharp
using SqlSugar;

namespace MiniMes;

// 工艺路线实验：读取生效的路线，并判断"一块板下一步允许进哪个工序"
public static class LabRoute
{
    // lastDone：已完成的最后一道工序的序号（0 表示还没开始）；target：想进的工序码
    // 注意：同一个工序码可能在路线里出现多次（双面板要印刷两次），所以靠"序号"判断先后，不能只看工序码
    static (bool Ok, string Why) CanEnter(List<RouteStep> steps, int lastDone, string target)
    {
        var next = steps.OrderBy(s => s.StepNo).FirstOrDefault(s => s.StepNo > lastDone);
        if (next == null) return (false, "所有工序都已完成");
        if (next.StepCode == target) return (true, "按顺序");
        var same = steps.Where(s => s.StepCode == target).ToList();
        if (same.Count == 0) return (false, "这个工序不在路线里");
        return same.Any(s => s.StepNo > lastDone)
            ? (false, $"跳站，下一道应该是 {next.StepCode}")
            : (false, "重复进已完成的工序");
    }

    static void Demo(string title, List<RouteStep> steps, (int Done, string Target)[] cases)
    {
        Console.WriteLine(title);
        foreach (var s in steps.OrderBy(s => s.StepNo)) Console.WriteLine($"   {s.StepNo,3}  {s.StepCode,-7} {s.StepName}");
        Console.WriteLine("进站判断：");
        foreach (var (done, target) in cases)
        {
            var (ok, why) = CanEnter(steps, done, target);
            Console.WriteLine($"   已完成 {done,2}，想进 {target,-7} -> {(ok ? "允许" : "拒绝")}（{why}）");
        }
    }

    public static void Run(SqlSugarClient db)
    {
        Seed.Basics(db);
        var route = db.Queryable<Route>().First(r => r.ProductCode == Seed.Product && r.Status == "Active");
        var steps = db.Queryable<RouteStep>().Where(s => s.RouteId == route.RouteId).OrderBy(s => s.StepNo).ToList();

        Demo($"1. 产品 {Seed.Product} 生效的工艺路线 {route.Version}（单面板，来自数据库）：", steps, new (int, string)[]
        {
            (0, "PRINT"), (10, "SPI"), (10, "MOUNT"), (20, "SPI"), (50, "PRINT"), (20, "SOLDER"),
        });

        // 双面板：印刷、SPI、贴片、回流焊各出现两次，仅在内存里构造，不写数据库
        var twoSided = new List<(int No, string Code, string Name)>
        {
            (10, "PRINT", "A面印刷"), (20, "SPI", "A面检测"), (30, "MOUNT", "A面贴片"), (40, "REFLOW", "A面回流"),
            (50, "PRINT", "B面印刷"), (60, "SPI", "B面检测"), (70, "MOUNT", "B面贴片"), (80, "REFLOW", "B面回流"),
            (90, "AOI", "光学检查"),
        }.Select(x => new RouteStep { StepNo = x.No, StepCode = x.Code, StepName = x.Name }).ToList();

        Console.WriteLine();
        Demo("2. 双面板路线（工序码重复出现，仅在内存里构造）：", twoSided, new (int, string)[]
        {
            (40, "PRINT"), (30, "PRINT"), (0, "REFLOW"), (80, "AOI"), (90, "AOI"),
        });
    }
}

  • 单面板第 3 行：已完成 10（印刷），想直接进 MOUNT（贴片），但下一道应该是 SPI，所以拒绝并提示"跳站"；
  • 单面板第 4 行：已完成 20（SPI），又想进 SPI，序号 20 已经完成过，路线里也没有更靠后的 SPI，判断为"重复"；
  • 双面板第 1 行：A 面回流（序号 40）做完后，想进 PRINT，下一道正好是 B 面印刷（序号 50），允许。同一个工序码 PRINT，因为"已完成序号"不同，得到不同的结论，这就是"靠序号判断"的意义；
  • 双面板第 2 行：只做完 A 面贴片（30），想进 PRINT，下一道应该是回流，但路线后面确实有 PRINT（序号 50），所以是"跳站"，而不是"重复"。

第 5 步，自己改一改：

  • 在 cases 里再加几个情况（比如 (60, "MOUNT")、(60, "SPI")），先猜结果再运行验证；
  • 把单面板路线的第一个判断 (0, "PRINT") 改成 (0, "SPI")，看提示是什么；
  • 思考：真实系统里，"想进的工序码"从哪来？（通常是工站或设备上配置的"我是什么工序"，或扫码终端选择的工序。）如果同一台设备既做 A 面又做 B 面，系统怎么知道这次是哪一面？（答案见练习题。）

常见坑与误区 ​

误区 / 坑事实与办法
只用工序码记录板子完成到哪双面板或重复工序时分不清。记序号
序号用 1、2、3 连续编号以后插入工序要改后面所有序号，历史记录就对不上。用 10、20、30 留空隙
序号重复先后顺序就乱了。对 (RouteId, StepNo) 建唯一索引
直接修改生效中的路线已经在线的板子会被"打乱"。要改就建新版本，旧版本作废
返修后无法回到流程路线要设计返修的出口和回到的位置，否则返修板成了"孤儿"
把"检验"当作无条件通过检验有判定，不合格的板要拦截，不能继续往下走
路线判断只写在前端界面里别的入口（设备自动上传、接口）会绕过。要在服务端、数据库层判断
一个路线对应所有产品不同产品的工序可能不同，路线应该按产品（和版本）来配置

练习题与答案 ​

  1. 为什么工序序号常用 10、20、30，而不是 1、2、3？ 答：为了留出插入空间。将来要在中间加一道工序，比如 35，不用修改后面的序号。如果序号变了，历史上记录的"已完成到第几道"就对不上了。
  2. 单面板路线里，一块板已完成序号 20（SPI），想进序号 40 的回流焊，系统应该怎么判断？ 答：拒绝，原因是"跳站"：下一道应该是序号 30 的贴片。
  3. 双面板路线中，板子已完成 A 面回流（序号 40），再次扫描 PRINT 工序应该允许吗？ 答：允许。下一道序号 50 正好是 B 面印刷，工序码匹配。
  4. 为什么判断"跳站"还是"重复"时，不能只找第一个同名工序？ 答：双面板里同一个工序码出现多次。如果只看第一个，已完成 30 想进 PRINT 会被误判为"重复"，而实际上后面还有 B 面的 PRINT，应该提示"跳站"。要看是否存在序号更大的同名工序。
  5. 同一台印刷机既印 A 面又印 B 面，系统怎么知道这次是哪一面？ 答：不需要设备告诉它是哪一面。设备只告诉系统"我是 PRINT 工序"，系统用这块板"已完成的序号"推出下一道，再看下一道是 A 面印刷（序号 10）还是 B 面印刷（序号 50）。
  6. 为什么对 (RouteId, StepNo) 要建唯一索引，而对 StepCode 不建？ 答：同一路线里序号必须唯一，否则顺序不明；而工序码在双面板路线里本来就会重复出现，建唯一约束会让双面板路线无法保存。

小结 ​

  • 工艺路线是产品要经过的工序顺序，工序是路线里的一道加工或检验。
  • 序号决定先后（10、20、30 留空隙），工序码表示"是什么"，两者要分开；记录板子进度时记序号。
  • 路线和 BOM 一样要有版本：同一产品一个生效版本，旧版本作废不删，工单下发时绑定。
  • 进站判断：找序号大于已完成序号的第一道工序，工序码匹配就允许；不匹配时区分"不在路线"、"跳站"、"重复"。
  • 双面板、返工回路是路线设计中最容易出问题的地方。
