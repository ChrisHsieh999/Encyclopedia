设备联网方案

AI 生成 · 待核对制造业务设备自动化网络更新于 2026-10-21

⚠ 待核对：本篇是联网方案的通用设计思路。IEC 62443 的"区域与管道"、Modbus 网关的两种工作方式，我是对照公开的技术博客和厂商资料写的，IEC 62443 标准全文是收费文件，我没有读到原文；交换机、网关的具体型号、VLAN 与防火墙规则、IP 规划，必须和你们的网络管理员、设备厂商一起按现场实际确定。文中的 IP 地址、点数、带宽都是示例数字。实验是在本机回环地址上运行的概念演示（不是可直接上生产的网关），代码和输出是我在本机实际运行得到的，不连接真实设备。

本篇是 EAP 系列第 4 篇。读完你应该能：画出一条 SMT 线的设备网络拓扑；说清设备端、上位机、边缘网关三种采集位置的取舍；区分串口服务器的"透传"和"协议转换"；知道设备网络为什么要隔离、怎么隔离；给没有任何接口的老设备想出办法；按步骤实施并用清单验收。

一句话定义 ​

设备联网方案是把车间里的设备接入网络并让 EAP 能稳定、安全地和它们通信的整体设计：包括网络怎么布、数据在哪里采、协议怎么转、怎么隔离防护、新旧设备怎么混合，以及怎么一步步实施和验收。

先修知识 ​

  • 以太网与交换机：知道网口、网线、交换机、VLAN 是什么。简单说：交换机把同一个网络里的设备连起来，VLAN 把一台交换机虚拟地切成几个互相隔离的小网络。
  • 工业以太网：知道工业场合对以太网设备（宽温、抗干扰、环网冗余）有特殊要求。
  • Modbus-TCP、RS-232与RS-485：知道串口和以太网两种连接方式的区别。
  • 设备数据采集：知道采集器怎么工作。

它解决什么问题 ​

一个典型的"野蛮生长"的车间网络：

  • 设备的 IP 是各个厂商工程师现场随手设的，有的是 192.168.0.100，有的是 192.168.1.10，有两台撞了同一个地址；
  • 设备网络和办公室网络是同一个网段，有人用自己的电脑插上网线拷程序，U 盘在设备电脑和办公电脑之间来回传；
  • 回流焊炉的 PLC 支持 Modbus TCP，但整个公司的网络谁都能连它的 502 端口，包括中了病毒的电脑；
  • 十年前的老炉子只有一个串口，没人知道怎么接；
  • 一次交换机故障，整条线的数据全断，没人知道。

联网方案要解决的就是：连得上、连得稳、连得安全、连得起（老设备）、连完能验收。

核心概念 ​

设备网络拓扑 ​

一个常见的分层结构（按 ISA-95 的层次来想，设备层与管理层分开）：

要点：

  1. 设备网独立：不和办公网混在一个网段，中间用防火墙或三层交换机隔开，只开放必要的通信（例如只允许 EAP 服务器访问设备网的指定端口）。
  2. 线边交换机：每条线放一台，线内设备就近接入，上联到车间核心交换机。选工业交换机还是普通交换机，看环境（温度、粉尘、振动）和可靠性要求。
  3. 拓扑形式：星型最简单、故障只影响一台设备；环网可以在一根线断开时自动切换，用于要求高可靠的场合（见 工业以太网）。
  4. 地址规划：每条线一个网段，设备用固定 IP（不要用 DHCP 自动分配，否则重启后 IP 变了，采集器就连不上）。做一张 IP 台账，登记设备、IP、MAC、位置、负责人。

采集位置：设备端、上位机、边缘网关 ​

位置做法优点缺点适用
设备端设备自己把数据推出来（OPC UA 订阅、MQTT 发布、CFX 发布）数据实时、不用轮询、减轻网络和设备负担设备要支持，且要信任它的实现新设备
上位机采集车间 EAP 服务器直接轮询各设备集中管理、部署简单设备多时服务器压力大；服务器和设备之间网络不稳时断数据；一处故障影响全部设备少、网络好
边缘网关线边放一台工控机/网关，负责本线设备的采集、缓存、协议转换，再上传到服务器网络断了可本地缓存；设备协议留在设备网，上层只见统一接口；故障影响范围小多一层设备要维护设备多、协议杂、网络不够稳的车间（最常见）

现实中经常是混合：新贴片机用 CFX 直接发布到消息代理，老炉子通过边缘网关读 Modbus，AOI 用文件监听。设计时让上层只依赖统一的数据模型（位号、事件），底层怎么采是网关的事。

工业网关与串口服务器 ​

很多老设备只有串口（RS-232/RS-485，见 串口通信）。要把它接进以太网，有两类设备：

方式做什么主站（上位机）看到什么
串口服务器（透传）把串口数据原样封装进 TCP 包转发，两端像直连一样上位机仍说串口协议（如 Modbus RTU over TCP），要自己处理校验、间隔等
协议转换网关一边是串口（如 Modbus RTU），一边是以太网（Modbus TCP）：收到 TCP 请求，转成 RTU 帧发到串口，再把回应转回上位机像和普通 Modbus TCP 设备通信。串口设备的地址填进 MBAP 头的单元标识（见 Modbus-TCP）

厂商常把两种都叫"透明转换"，所以买之前看清手册的工作模式，别只看名字。还有一点：串口那一侧同一时刻只能处理一个请求，多个上位机同时访问同一个网关，请求会在网关里排队，轮询周期要相应放宽。

更广义的协议转换，是网关把设备的"寄存器地址 + 原始整数"翻译成"位号名 + 工程值 + 单位"，再通过 HTTP、MQTT、OPC UA 等对上层提供。MQTT 是轻量的发布/订阅协议，物联网和 IIoT 中常用：设备（或网关）把数据发布到某个主题，谁订阅谁收到。本篇的实验演示这个思路。

网络隔离与安全 ​

Modbus-TCP 一篇已经指出：Modbus 协议本身没有认证、没有加密，任何能连到 502 端口的人都能读写。OPC UA、CFX 的 AMQP 可以配置安全机制，但很多现场仍在用明文。所以保护要靠网络层面。详见 工业网络安全，这里给出基本原则：

原则具体做法
分区据对 IEC 62443 的公开介绍，该系列标准用"区域（zone）"和"管道（conduit）"的概念：把安全要求相同的资产分成区域，区域之间的通信路径（管道）用防火墙等手段控制。落到车间就是：办公区、MES 服务区、设备网分开；各条线的设备网也最好分开
最小开放防火墙只允许 EAP/网关访问设备网里的必要 IP 和端口，其余一律拒绝；设备网不允许主动访问外网
读写分离采集账号只读；写（控制）通过独立、受审计的通道
不暴露绝不把 502 等工业端口映射到公网；远程维护用 VPN，并有审批和日志
移动介质管控U 盘是工业病毒的常见入口；统一扫描、专用 U 盘、禁用不必要的 USB 口
补丁与备份设备电脑的系统补丁难打（怕影响设备），至少做到网络隔离；设备程序、PLC 程序定期备份
审计谁在什么时间对哪台设备做了写操作，必须有日志

"改动设备要谨慎"：给设备装采集软件、改设备电脑配置之前，先问清厂商，避免失去保修或影响生产。

新旧设备混合：老设备没有接口怎么办 ​

按"代价由低到高"：

办法做什么能得到什么局限
读设备已有的输出日志文件、本地数据库、打印口产量、结果事后、格式杂
读 PLC 点位设备里有 PLC 就读它的寄存器（Modbus、S7 等，见 PLC）状态、计数、温度要对着程序/点表，要得到许可
三色灯采集设备的三色灯（红/黄/绿）信号接 IO 模块运行/待机/报警（粗粒度）没有报警原因和产量
光电/接近传感器计数在传送带上装传感器，数过板的数量产量只知道数量，不知道哪块板
电流/电量检测电流互感器或智能电表接在设备电源上开机/空载/加工（靠功率区分）间接判断，要标定阈值
加温湿度等传感器独立安装，数据走 RS-485/Modbus环境量与设备内部状态无关
换设备/升级加装联网模块或改造控制器完整数据成本高，要厂商配合

经验：先用最便宜的办法拿到最关键的数据（运行状态 + 产量），其他需要时再升级。IO 采集要有隔离：不要把现场的高电压直接接进采集模块，一定要用厂商建议的信号和模块，由电气工程师做。

实施步骤 ​

  1. 调研盘点：设备清单（品牌、型号、接口、软件、位置）、现有网络、需求（采什么、控什么）。
  2. 方案设计：拓扑、IP 规划、网关选型、采集位置、安全分区、位号表草稿。
  3. 小范围试点：选 1 条线、2~3 台设备，跑通采集、存储、展示全流程。
  4. 安装部署：布线、装交换机/网关、配置、调试。注意施工要在停线窗口，不影响生产。
  5. 联调与验证：采集的数据与设备屏幕对照，断线重连测试，长时间稳定性测试。
  6. 验收与培训：按清单验收；培训维护人员；提交文档。
  7. 推广与运维：监控采集在线率、数据完整率，有人负责。

验收清单 ​

项检查点
网络IP 无冲突；设备网与办公网已隔离；防火墙规则已记录；交换机/网关有备份配置
连通所有设备采集在线；拔网线再插回，采集自动恢复
数据抽样对照设备屏幕：值、单位、比例都对；状态变化时间准确到约定精度
完整性连续运行 72 小时无断点（或有断点标记），数据量符合预期
断线续传模拟数据库/网络中断，恢复后无丢失、无重复
时间设备、服务器、网关时钟已同步，误差在约定范围内
安全采集账号只读；无多余开放端口；写操作有权限与日志
性能采集延迟、CPU/网络占用在约定范围内
文档IP 台账、位号表、接口说明、网络图、应急处置流程齐全
回退采集故障不影响设备生产；有明确的回退方案

逐步例子：一条 SMT 线的联网规划 ​

假设一条线有 8 台设备：上板机、印刷机、SPI、贴片机×2、回流焊炉、炉后 AOI、下板机。

IP 规划：设备网用 192.168.10.0/24。可以用 Python 验证这个网段有多少地址：

python
import ipaddress
n = ipaddress.ip_network("192.168.10.0/24")
print(n.num_addresses, n.num_addresses - 2, n.netmask, n.broadcast_address)

带宽估算：8 台设备、每台 20 个位号、每秒 1 次、每条数据按 100 字节（含协议开销，假设值）估算：8 × 20 × 100 = 16000 字节/秒，约 128 kbit/s，只占 100 Mbit/s 网口的约 0.13%。一次读 20 个寄存器的 Modbus TCP 请求 12 字节、回应 49 字节（7 字节报文头 + 2 字节功能码和字节数 + 40 字节数据），共 61 字节。可见设备数据采集本身对网络几乎没有压力，真正要小心的是 SPI/AOI 的图像文件传输，和广播风暴、环路这类网络故障。

动手实验：简易 Modbus TCP 到 HTTP/MQTT 网关（本机回环） ​

目标：理解协议转换网关的核心：读 Modbus 寄存器 → 按"位号映射表"换算成带单位的工程值 → 通过 HTTP 对上层提供（只读），并推送给一个接收器；同时演示 MQTT 的"主题 + 载荷"格式。所有东西都在本机一个文件里，用 127.0.0.1，不连接真实设备。

说明：这是概念演示。网关里的"设备"是脚本模拟的；MQTT 部分只打印主题和载荷，没有真正的 MQTT broker，也不会发出任何网络包。真正的 MQTT 要用 broker（如 Mosquitto）和客户端库，本机未验证，细节见 MQTT。

新建 gateway_demo.py（只用 Python 标准库，无需安装任何包）：

python
"""Modbus TCP -> HTTP 网关概念演示（全部在本机回环地址，一个文件跑完）：
模拟设备(5022) <- 网关轮询 -> 网关对外提供只读 HTTP(8088) + 向"云端接收器"(8089) 推送；MQTT 只演示主题和载荷格式。"""
import json
import socket
import struct
import threading
import time
import urllib.error
import urllib.request
from http.server import BaseHTTPRequestHandler, HTTPServer

DEV_PORT, API_PORT, SINK_PORT = 5022, 8088, 8089
# 本机若设了系统代理，访问 127.0.0.1 也会被转给代理而得到 503；设备/网关内网通信要显式不走代理
urllib.request.install_opener(urllib.request.build_opener(urllib.request.ProxyHandler({})))
REGS = [2531, 1, 12345]   # 模拟设备：温度×10、状态码、累计产量

# 位号映射表：网关的核心配置——寄存器地址、比例、单位、状态码含义都在这里，而不是写死在代码里
TAGS = [
    {"name": "temp", "reg": 0, "scale": 0.1, "unit": "degC"},
    {"name": "status", "reg": 1, "map": {0: "STOP", 1: "RUN", 2: "ALARM"}},
    {"name": "count", "reg": 2, "scale": 1, "unit": "pcs"},
]


def recv_exact(c, n):
    buf = b""
    while len(buf) < n:
        chunk = c.recv(n - len(buf))
        if not chunk:
            raise ConnectionError
        buf += chunk
    return buf


def device_sim():
    """极简 Modbus TCP 从站：只支持功能码 03，写请求一律回异常码 1（非法功能）。"""
    srv = socket.create_server(("127.0.0.1", DEV_PORT))
    while True:
        conn, _ = srv.accept()
        with conn:
            try:
                while True:
                    tid, _p, length, unit = struct.unpack(">HHHB", recv_exact(conn, 7))
                    pdu = recv_exact(conn, length - 1)
                    if pdu[0] == 3:
                        addr, qty = struct.unpack(">HH", pdu[1:5])
                        body = bytes([3, qty * 2]) + b"".join(struct.pack(">H", v) for v in REGS[addr:addr + qty])
                    else:
                        body = bytes([pdu[0] | 0x80, 1])
                    conn.sendall(struct.pack(">HHHB", tid, 0, len(body) + 1, unit) + body)
            except ConnectionError:
                pass


def read_regs(sock, tid, addr, qty):
    pdu = struct.pack(">BHH", 3, addr, qty)
    sock.sendall(struct.pack(">HHHB", tid, 0, len(pdu) + 1, 1) + pdu)
    _t, _p, length, _u = struct.unpack(">HHHB", recv_exact(sock, 7))
    body = recv_exact(sock, length - 1)
    return list(struct.unpack(f">{body[1] // 2}H", body[2:]))


def convert(raw_regs):
    """协议转换的核心：原始寄存器 -> 带单位的工程值。"""
    out = {}
    for t in TAGS:
        raw = raw_regs[t["reg"]]
        out[t["name"]] = t["map"].get(raw, "UNKNOWN") if "map" in t else {"value": round(raw * t["scale"], 3), "unit": t["unit"]}
    return out


cache = {}                     # 网关缓存：HTTP 客户端读缓存，不会每次都去打设备
pushed = []                    # "云端接收器"收到的消息


class ApiHandler(BaseHTTPRequestHandler):
    def log_message(self, *a):   # 关掉默认的访问日志，保持输出干净
        pass

    def do_GET(self):
        if self.path == "/api/tags":
            self._send(200, {"device": "REFLOW-01", "tags": cache})
        else:
            self._send(404, {"error": "not found"})

    def do_POST(self):           # 网关只读：任何写请求一律拒绝
        self._send(405, {"error": "read-only gateway"})

    def _send(self, code, obj):
        data = json.dumps(obj, sort_keys=True).encode()
        self.send_response(code)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)


class SinkHandler(BaseHTTPRequestHandler):
    def log_message(self, *a):
        pass

    def do_POST(self):
        pushed.append(json.loads(self.rfile.read(int(self.headers["Content-Length"]))))
        self.send_response(204)
        self.end_headers()


def serve(port, handler):
    srv = HTTPServer(("127.0.0.1", port), handler)   # 只绑定回环地址：局域网里别的机器连不上
    threading.Thread(target=srv.serve_forever, daemon=True).start()


def main():
    threading.Thread(target=device_sim, daemon=True).start()
    serve(API_PORT, ApiHandler)
    serve(SINK_PORT, SinkHandler)
    time.sleep(0.3)

    # 网关的采集循环：轮询一次 -> 转换 -> 更新缓存 -> 推送
    with socket.create_connection(("127.0.0.1", DEV_PORT), timeout=2) as sock:
        cache.update(convert(read_regs(sock, 1, 0, 3)))
        req = urllib.request.Request(f"http://127.0.0.1:{SINK_PORT}/ingest", method="POST",
                                     data=json.dumps({"device": "REFLOW-01", "tags": cache}, sort_keys=True).encode(),
                                     headers={"Content-Type": "application/json"})
        print("推送到云端接收器，状态码:", urllib.request.urlopen(req).status)
        # 验证网关不会把写请求透传给设备（演示设备侧对写功能码的回应）
        pdu = struct.pack(">BHH", 6, 0, 9999)
        sock.sendall(struct.pack(">HHHB", 2, 0, len(pdu) + 1, 1) + pdu)
        _t, _p, length, _u = struct.unpack(">HHHB", recv_exact(sock, 7))
        print("直接对设备发写功能码 06，回应:", recv_exact(sock, length - 1).hex(" "), "(0x86 = 06 + 80，异常码 01)")

    # 客户端：像任何 Web 应用一样用 HTTP 取数据，不需要懂 Modbus
    with urllib.request.urlopen(f"http://127.0.0.1:{API_PORT}/api/tags") as r:
        print("GET /api/tags ->", r.status, r.read().decode())
    try:
        urllib.request.urlopen(urllib.request.Request(f"http://127.0.0.1:{API_PORT}/api/tags", data=b"{}", method="POST"))
    except urllib.error.HTTPError as e:
        print("POST /api/tags ->", e.code, e.read().decode())
    print("云端接收器收到", len(pushed), "条:", json.dumps(pushed[0], sort_keys=True))

    # MQTT 只演示"主题 + 载荷"的约定，没有真正的 broker，不会发出任何网络包
    for name, val in cache.items():
        v = val["value"] if isinstance(val, dict) else val
        print(f"[MQTT 概念] topic=factory/smt1/reflow01/{name} payload={v}")


if __name__ == "__main__":
    main()

运行 python gateway_demo.py，预期输出（本机实际运行，连续运行 3 次，输出完全一致）：

推送到云端接收器，状态码: 204
直接对设备发写功能码 06，回应: 86 01 (0x86 = 06 + 80，异常码 01)
GET /api/tags -> 200 {"device": "REFLOW-01", "tags": {"count": {"unit": "pcs", "value": 12345}, "status": "RUN", "temp": {"unit": "degC", "value": 253.1}}}
POST /api/tags -> 405 {"error": "read-only gateway"}
云端接收器收到 1 条: {"device": "REFLOW-01", "tags": {"count": {"unit": "pcs", "value": 12345}, "status": "RUN", "temp": {"unit": "degC", "value": 253.1}}}
[MQTT 概念] topic=factory/smt1/reflow01/temp payload=253.1
[MQTT 概念] topic=factory/smt1/reflow01/status payload=RUN
[MQTT 概念] topic=factory/smt1/reflow01/count payload=12345

看懂输出：

  1. 模拟设备里的寄存器是 [2531, 1, 12345]。网关按位号映射表换算：温度 2531 × 0.1 = 253.1 degC；状态码 1 翻译成 RUN；计数 12345 个。映射表（TAGS）是网关的核心，改它就能适配另一台设备，不用改代码逻辑。
  2. GET /api/tags 返回的是 JSON。任何 Web 应用、脚本，不需要懂 Modbus 就能取数。这就是"协议转换"：设备的协议被隐藏在网关后面。
  3. POST /api/tags 返回 405：网关没有提供写入路径，这是读写分离的体现。（上面直接对设备发功能码 06 的那行，是模拟设备自己拒绝写入，回应 86 01：0x86 = 0x06 + 0x80，异常码 1 是"非法功能"。它演示的是异常响应的格式，不是网关替设备做了拦截。）
  4. 推送到"云端接收器"返回 204（成功，无内容）；MQTT 部分按 factory/smt1/reflow01/temp 这种层级主题发布，一个位号一个主题，订阅者可以只订阅自己关心的。
  5. 服务只绑定 127.0.0.1：局域网里的其他机器连不上，这是最小开放原则的一个具体表现。

一个我踩到的坑：本机如果配置了系统代理（比如科学上网工具、公司代理），Python 的 urllib 访问 127.0.0.1 时也会走代理，得到 HTTP Error 503。脚本里用 ProxyHandler({}) 显式不走代理就解决了。内网设备通信同样要注意绕过代理。

自己改一改：

  1. 在 TAGS 里加一个位号，例如把 count 的 scale 改成 0.5，看输出变化；
  2. 把 REGS 的第 2 个值改成 2，看 status 变成什么；改成 9，看 UNKNOWN；
  3. 思考：这个网关一次连接只读一次，真实网关还需要加什么？（答：周期轮询、断线重连与退避、超时、日志、数据质量标记、缓存、多设备并发、认证与 HTTPS、异常告警，见 设备数据采集。）

练习题与答案 ​

  1. 为什么设备要用固定 IP 而不是 DHCP？ 答：采集器靠 IP 找设备，DHCP 可能在设备重启后分配不同的地址，采集就断了；固定 IP 也便于台账管理和防火墙规则。
  2. 串口服务器的"透传"和"协议转换"区别是什么？ 答：透传把串口数据原样装进 TCP，上位机仍说串口协议；协议转换网关把 Modbus TCP 请求转成 Modbus RTU 帧，上位机像访问普通 Modbus TCP 设备，串口设备的地址填在单元标识里。
  3. 为什么说设备数据采集本身对网络压力很小？请用数字说明。 答：8 台设备、每台 20 位号、每秒一次、每条 100 字节，一共 16000 字节/秒，约 128 kbit/s，只占 100 Mbit/s 的约 0.13%。
  4. 边缘网关相比"EAP 服务器直接采集所有设备"有什么好处？ 答：网络断了可以本地缓存；协议差异留在设备网，上层只见统一数据模型；故障影响范围小；减轻服务器压力。
  5. 一台没有任何接口的老设备，最便宜的办法能采到什么？ 答：用三色灯信号接 IO 模块得到运行/待机/报警状态，用光电传感器数产量。只能得到粗粒度的信息。
  6. 设备网和办公网为什么要隔离？列出两个具体措施。 答：Modbus 等协议没有认证和加密，任何能连上的人都能读写设备。措施如：独立网段/VLAN 加防火墙只放行必要通信；采集账号只读；禁止把工业端口暴露到外网；U 盘管控。
  7. 实验里网关为什么拒绝 POST？ 答：为了读写分离：采集通道只读，写（控制）要走受权限与审计控制的独立通道，避免误操作或被攻击时直接改设备。

小结 ​

  • 设备网要独立、分层、固定 IP、有台账。
  • 采集位置有设备端、上位机、边缘网关三种，现实中多为混合，边缘网关最灵活。
  • 串口老设备用串口服务器或协议转换网关接入；注意两种工作模式的区别和串口侧排队。
  • Modbus 等协议没有保护，要靠分区、最小开放、读写分离、移动介质管控、审计。
  • 无接口的老设备：先用三色灯、光电传感器、电量检测拿到最关键的状态和产量。
  • 按"调研、设计、试点、部署、联调、验收、运维"实施，用清单验收。
