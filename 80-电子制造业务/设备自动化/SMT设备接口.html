SMT设备接口

AI 生成 · 待核对制造业务设备自动化SMT更新于 2026-10-21

⚠ 待核对：SMT 设备的接口因厂商、型号、软件版本差别极大。本篇只总结公开可查的行业标准（IPC-CFX、IPC-Hermes、IPC-SMEMA-9851）和通用的"文件/数据库/厂商接口/IO"思路；不针对任何品牌型号，也不声称某品牌支持什么。"各类设备通常能提供什么""数据样例"是通用经验和虚构样例（字段名、格式都是我自拟的），真实的字段、格式、接口一定要拿设备手册和厂商技术支持确认。CFX/Hermes 的细节来自 IPC 和 Hermes 官网，标准全文是收费文件，我没有读到全文，具体消息清单请以标准和厂商文档为准。实验代码和输出是我在本机实际运行得到的，使用的是自拟的小文件，不连接真实设备。

本篇是 EAP 系列第 3 篇。读完你应该能：说出印刷机、SPI、贴片机、回流焊炉、AOI 通常能提供什么数据、用什么方式拿；理解板码读取、Recipe 下载、防错联动三件事怎么做；面对一台没接过的设备，知道按什么步骤调查和接入；并亲手写一个解析贴片机日志和 AOI 结果文件、按拼板关联到板码 SN 的程序。

一句话定义 ​

SMT 设备接口是 SMT 线上各类设备（印刷机、SPI、贴片机、回流焊炉、AOI 等）向外提供数据、接收指令的方式的总称，可能是行业标准接口（CFX、Hermes），可能是厂商私有接口，也可能只是"设备把结果写成一个文件"。

先修知识 ​

  • EAP：知道 EAP 的五项职责。
  • 设备数据采集：知道采集的通道有哪几种（寄存器、文件、数据库、CFX 等）。
  • SMT与电子组装流程：知道各工站做什么。
  • 条码与板码规则：知道拼板码和板码的关系。
  • JSON-XML-YAML：能看懂 XML 的标签和属性。

它解决什么问题 ​

SMT 线上设备常常来自不同厂商、不同年代：一台新贴片机支持 CFX，旁边的印刷机只会把检测结果存成 CSV，再旁边的回流炉是十年前的老炉子，只有一个 PLC。MES 要的是"这块板在每个工站的结果、用的程序、有没有不良"，设备却各说各的话。

做 SMT 设备对接的人，面对每台设备都要回答同样的几个问题：

  1. 这台设备能给我什么数据？实时的还是事后的？
  2. 数据怎么给？接口、文件、数据库，还是只能加传感器？
  3. 数据里有没有板码？没有的话怎么和板对上？
  4. 我能不能让它做事（切程序、锁机）？谁来保证安全？

核心概念 ​

接口的四大类 ​

类别说明典型场景
行业标准接口IPC-CFX、IPC-Hermes、SMEMA较新的设备；多厂商混线
厂商开放接口厂商提供的 API、SDK、通信协议文档厂商愿意提供且你们有技术能力对接
文件/数据库设备把日志、结果写成文件或存进本地数据库最常见的"保底"方案
硬件信号/加传感器IO 点、PLC 点位、外加传感器老设备，什么接口都没有

下面分别说前两类里的标准。

IPC-CFX：设备"发布事件" ​

据 IPC 官网，**IPC-2591 Connected Factory Exchange（CFX）**是组装行业设备与上位系统之间双向信息交换的开放标准，覆盖自动、半自动和手工的 PCBA 组装过程。官网列出的最新版本是 1.7（2023 年 8 月），首版 1.0 发布于 2019 年 3 月；标准分四部分：结构概览、操作建模、主题与动态结构、消息。

通俗地说：支持 CFX 的设备把"事件"（比如开始生产一块板、完成了、换了程序、发生了故障）作为消息发布出去，谁关心谁订阅。据 IPC 的 AMQP 指南，CFX 的消息代理必须是 AMQP 1.0，指南推荐 RabbitMQ。IPC 还提供 CFX 的 SDK（官网链接到 NuGet 包和 GitHub 源码）。详见 IPC-CFX。

注意：支持 CFX 不等于支持所有消息。各厂商实现的消息子集不同，接入前要问清设备会发布哪些消息、字段是否齐全。

IPC-Hermes：设备之间"交接板子" ​

据 Hermes 官网，The Hermes Standard（IPC-HERMES-9852）是 SMT 线上机器对机器通信的开放标准，管理不同厂商设备之间的板子流转，基于 TCP/IP 和 XML，让每块板不需要在每台设备重新扫码就能被追踪。它是旧标准 IPC-SMEMA-9851 的继任者：SMEMA 是 90 年代末的接口，据维基百科和 IPC 的资料，它规定了传送带之间的机械和电气接口（本质上是几根线上的"我有板"、"我准备好接板"信号），不传送板码等数据；Hermes 在此基础上增加了板标识、传送速度等数据。Hermes 1.0 发布于 2017 年 4 月。详见 IPC-Hermes。

两者分工，据 IPC 的介绍：CFX 管设备事件数据，Hermes 管板子交接，可以配合使用。

各类设备通常能提供什么 ​

下面是通用情况，不是对任何品牌的保证：

设备通常能提供的数据常见的拿数据方式常见的难点
印刷机状态、生产计数、印刷参数（刮刀压力/速度、脱模速度）、钢网清洁次数、当前程序名厂商接口、日志文件、CFX钢网编号、锡膏批号往往不在设备里，要靠 MES 补录
SPI每块板（常精确到每个焊盘）的锡膏体积/面积/高度、判定、板码结果 CSV/XML、数据库数据量大（每板几千焊盘），通常只取汇总和不良明细
贴片机状态、产量、抛料（取料/识别失败）、报警、当前程序、站位上的物料信息、每块板的贴装记录CFX、厂商接口、日志文件日志格式复杂；站位物料对应关系的取得方式各不相同（见 SMT上料防错与站位表）
回流焊炉各温区温度、链速、状态、报警；有的有炉内氧含量PLC 寄存器、厂商软件的文件/数据库、OPC炉子本身通常不知道过的是哪块板，要靠"进炉时间 + 链速"推算，或在入口扫码
AOI每块板的判定、缺陷位置和类型、复判结果、板码、程序名结果文件、数据库、厂商接口缺陷类型编码各厂不同，要建映射（见 缺陷代码与不良分类）
上下板机、缓存机、输送线板的到达/离开、计数、堵板报警Hermes、SMEMA 信号、PLC信号多为开关量，没有板码

各类设备的数据样例（虚构，仅示意） ​

印刷机的一行日志（CSV）：

2026-10-21 08:00:41,PRN-01,A100_TOP_V3,PA1002610210001,SQ=8.5kg,SPD=40mm/s,SEPARATION=1.0mm,OK

SPI 的一块板汇总（CSV）：

2026-10-21 08:00:58,SPI-01,PA1002610210001,pads=3860,vol_avg=102.4%,area_avg=98.7%,ng_pads=3,result=PASS

贴片机的事件（文本）：

2026-10-21 08:02:14 CM-01 PICK_ERROR feeder=F12 part=R-10K-0402 retry=1

回流炉的状态（PLC 寄存器，经换算后）：

{"time":"2026-10-21 08:05:00","zone3_temp":182.5,"conveyor_speed_cm_min":90.0,"status":"RUN"}

AOI 的结果（XML）见本篇后面的动手实验。

这些样例的共同点：时间、设备编号、板码（或拼板码）、结果是最关键的四要素。拿到任何设备的数据，第一件事就是找这四样。

板码读取 ​

SMT 阶段通常按拼板走（见 条码与板码规则）：上板时由读码器或设备自带相机扫拼板码，之后每台设备要么重新扫，要么由上游传递。

方式说明优缺点
每台设备自己扫码设备配读码器，日志里带板码独立，不依赖上下游；成本高，读码失败要处理
上游通过 Hermes 传板码板码随板子在设备间传递少扫码；要设备都支持
EAP 按时序推算记录板进出各设备的时间，推测板码不要钱，但出错（掉板、插板）就错乱，尽量别依赖
设备日志只有流水号，MES 补关联设备给自己的内部序号，EAP 查对照需要稳定的对应规则

读码失败（实验里的 NOREAD）是常态：要有明确的处理规则——是拦停还是人工补录，不能悄悄把它记成别的板。

设备程序切换（Recipe 下载） ​

换产品时，每台设备要切换到对应产品的程序（印刷程序、贴片程序、AOI 检测程序、炉温曲线）。人工选容易选错。联网后的流程是：

  1. MES 里工单切换到产品 A100 的新批次（见 首件检验与换线）；
  2. EAP 查"产品 A100 在这台设备上应使用哪个程序名/版本"（来自 MES 的配方管理，见 工艺参数与炉温曲线管理）；
  3. EAP 通过设备接口下发/切换程序（或者让操作员选，EAP 只做核对）；
  4. EAP 回读设备当前程序名和版本，与要求核对，一致才放行，不一致报警；
  5. 把"谁、何时、哪台设备、从哪个程序切换到哪个程序"记下来。

很多设备只支持"读"当前程序名，不支持远程"写"。这时退一步：不自动下发，但 EAP 采集当前程序名，和 MES 要求的对比，不一致就报警或锁定。这个"核对"比"下发"更容易实现，也能挡住绝大多数选错程序的事故，是起步阶段的首选。

防错联动：设备等 MES 放行 ​

典型场景：贴片机在换料后，要等 MES 校验物料和站位无误才允许生产；炉温曲线没通过验证，回流炉不允许放板。

联动的几种实现层次：

层次做法说明
提示MES 弹窗告诉操作员"校验失败"最简单，靠人遵守
软锁定EAP 向设备发"锁机"指令（设备接口支持时）设备会停止生产或拒绝开始
硬联锁MES/EAP 通过 PLC 点位或 IO 给设备一个"允许生产"信号，没有这个信号设备不动最可靠，要改设备或加线，要设备厂配合

设计时必须想清楚失效策略：如果 EAP 或网络挂了，设备是继续生产（fail-open）还是全部停机（fail-closed）？前者保生产但可能漏防错，后者保质量但一次网络抖动就停线。这是一个业务决策，不是纯技术问题，要和生产、质量一起定，并通过 不良品拦截与锁定 之类的机制兜底。

通用接入策略 ​

面对一台没接过的设备，按下面步骤做：

  1. 问：设备手册、厂商技术支持。有没有标准接口（CFX/OPC UA/SECS-GEM）？有没有私有 API？日志在哪里、格式是什么？把答复写成文档。
  2. 看：先用只读方式观察。看日志目录、看数据库表、抓一下网络包，别急着写。
  3. 选：按优先级选通道：标准接口 > 厂商开放接口 > 文件/数据库 > 硬件信号。
  4. 取样：拿 1~2 天的真实数据样本（先在测试环境），确认四要素（时间、设备、板码、结果）齐不齐。
  5. 只读先行：先只做采集，稳定运行一段时间后，再谈控制（下发、锁机）。
  6. 验证：对比设备屏幕上的数字和你采到的数字，对比设备自己的产量和你统计的产量。
  7. 留退路：采集挂了，设备要能照常生产（除非业务明确要求联锁）。
  8. 文档化：每台设备一份"接口说明"：通道、地址/路径、格式、字段含义、已知问题。

import_logs.py（导入程序。它每次先重建表，--keep 参数表示保留已有表、只做导入，用来演示"重复导入"）：

python
"""解析贴片机日志（CSV）和 AOI 结果（XML），入库并通过拼板码关联到板码 SN。"""
import csv
import hashlib
import sys
import xml.etree.ElementTree as ET
from datetime import datetime
from pathlib import Path

import pyodbc

CONN_STR = (r"DRIVER={ODBC Driver 17 for SQL Server};SERVER=(localdb)\MSSQLLocalDB;"
            r"DATABASE=Lab_eap;Trusted_Connection=yes;")
FMT = "%Y-%m-%d %H:%M:%S"   # 假设设备日志时间是本地时间；真实项目要问清时区

DDL = """
IF OBJECT_ID('AoiDefect') IS NOT NULL DROP TABLE AoiDefect;
IF OBJECT_ID('AoiBoard') IS NOT NULL DROP TABLE AoiBoard;
IF OBJECT_ID('AoiPanel') IS NOT NULL DROP TABLE AoiPanel;
IF OBJECT_ID('MachineEvent') IS NOT NULL DROP TABLE MachineEvent;
IF OBJECT_ID('PanelBoard') IS NOT NULL DROP TABLE PanelBoard;
IF OBJECT_ID('ImportedFile') IS NOT NULL DROP TABLE ImportedFile;
CREATE TABLE ImportedFile(FileName NVARCHAR(200) NOT NULL, Sha256 CHAR(64) NOT NULL,
    ImportedRows INT NOT NULL, CONSTRAINT PK_ImportedFile PRIMARY KEY (FileName, Sha256));
CREATE TABLE PanelBoard(PanelSn NVARCHAR(30) NOT NULL, Position INT NOT NULL, SerialNo NVARCHAR(30) NOT NULL,
    CONSTRAINT PK_PanelBoard PRIMARY KEY (PanelSn, Position), CONSTRAINT UQ_PanelBoard_Sn UNIQUE (SerialNo));
CREATE TABLE MachineEvent(Id INT IDENTITY PRIMARY KEY, EventTime DATETIME2(0) NOT NULL, Machine NVARCHAR(20) NOT NULL,
    EventType NVARCHAR(30) NOT NULL, Program NVARCHAR(60) NULL, PanelSn NVARCHAR(30) NULL, SnOk BIT NOT NULL,
    Feeder NVARCHAR(10) NULL, PartNo NVARCHAR(40) NULL, Detail NVARCHAR(200) NULL,
    LineHash CHAR(64) NOT NULL, CONSTRAINT UQ_MachineEvent_Line UNIQUE (LineHash));
CREATE TABLE AoiPanel(PanelSn NVARCHAR(30) NOT NULL, InspectTime DATETIME2(0) NOT NULL, Machine NVARCHAR(20) NOT NULL,
    Program NVARCHAR(60) NULL, Result NVARCHAR(10) NOT NULL, CONSTRAINT PK_AoiPanel PRIMARY KEY (PanelSn, InspectTime));
CREATE TABLE AoiBoard(PanelSn NVARCHAR(30) NOT NULL, InspectTime DATETIME2(0) NOT NULL, Position INT NOT NULL,
    Result NVARCHAR(10) NOT NULL, CONSTRAINT PK_AoiBoard PRIMARY KEY (PanelSn, InspectTime, Position));
CREATE TABLE AoiDefect(Id INT IDENTITY PRIMARY KEY, PanelSn NVARCHAR(30) NOT NULL, InspectTime DATETIME2(0) NOT NULL,
    Position INT NOT NULL, RefDes NVARCHAR(20) NOT NULL, DefectCode NVARCHAR(20) NOT NULL, Judge NVARCHAR(5) NOT NULL,
    X DECIMAL(9,2) NULL, Y DECIMAL(9,2) NULL);
"""


def sha256(data: bytes) -> str:
    return hashlib.sha256(data).hexdigest()


def already_imported(db, name, digest):
    return db.execute("SELECT 1 FROM ImportedFile WHERE FileName=? AND Sha256=?", name, digest).fetchone() is not None


def import_placer(db, path: Path):
    raw = path.read_bytes()
    if already_imported(db, path.name, sha256(raw)):
        print(f"{path.name}：内容没变，跳过")
        return
    ok = bad = dup = 0
    for line in raw.decode("utf-8").splitlines()[1:]:       # 跳过表头
        row = next(csv.reader([line]))
        t, machine, event, program, panel, feeder, part, detail = row
        sn_ok = panel not in ("", "NOREAD") if event.startswith("BOARD") else True
        if event == "BOARD_IN" and not sn_ok:
            bad += 1
        try:
            n = db.execute("""INSERT INTO MachineEvent(EventTime,Machine,EventType,Program,PanelSn,SnOk,Feeder,PartNo,Detail,LineHash)
                SELECT ?,?,?,?,?,?,?,?,?,? WHERE NOT EXISTS (SELECT 1 FROM MachineEvent WHERE LineHash=?)""",
                           datetime.strptime(t, FMT), machine, event, program or None, panel or None, int(sn_ok),
                           feeder or None, part or None, detail or None, sha256(line.encode()), sha256(line.encode())).rowcount
        except ValueError as e:                             # 坏行不能拖垮整个文件：记下来继续
            print(f"  坏行跳过：{line!r}（{e}）")
            continue
        ok += n
        dup += 1 - n
    db.execute("INSERT INTO ImportedFile VALUES (?,?,?)", path.name, sha256(raw), ok)
    db.commit()
    print(f"{path.name}：新增 {ok} 行，重复 {dup} 行，板码读不到的板 {bad} 块")


def import_aoi(db, path: Path):
    raw = path.read_bytes()
    if already_imported(db, path.name, sha256(raw)):
        print(f"{path.name}：内容没变，跳过")
        return
    root = ET.fromstring(raw)
    panel = root.get("panel")
    if not panel or panel == "NOREAD":
        print(f"{path.name}：拼板码缺失，进待处理区，不入库")
        return
    t = datetime.strptime(root.get("time"), FMT)
    db.execute("INSERT INTO AoiPanel VALUES (?,?,?,?,?)", panel, t, root.get("machine"), root.get("program"), root.get("result"))
    nb = nd = 0
    for b in root.findall("Board"):
        pos = int(b.get("array"))
        db.execute("INSERT INTO AoiBoard VALUES (?,?,?,?)", panel, t, pos, b.get("result"))
        nb += 1
        for d in b.findall("Defect"):
            db.execute("INSERT INTO AoiDefect(PanelSn,InspectTime,Position,RefDes,DefectCode,Judge,X,Y) VALUES (?,?,?,?,?,?,?,?)",
                       panel, t, pos, d.get("refdes"), d.get("code"), d.get("judge"), float(d.get("x")), float(d.get("y")))
            nd += 1
    db.execute("INSERT INTO ImportedFile VALUES (?,?,?)", path.name, sha256(raw), nb)
    db.commit()
    print(f"{path.name}：拼板 {panel}，小板 {nb} 块，缺陷记录 {nd} 条")


def main(folder: Path, reset: bool):
    db = pyodbc.connect(CONN_STR)
    if reset:
        db.execute(DDL)
        for i in range(8):   # 拼板与板码对应（真实系统来自 MES 的拼板绑定）
            db.execute("INSERT INTO PanelBoard VALUES (?,?,?)", f"PA100261021000{i // 4 + 1}", i % 4 + 1, f"SN-A100-{i + 1:04d}")
        db.commit()
    import_placer(db, folder / "placer.csv")
    for f in sorted(folder.glob("aoi_*.xml")):
        import_aoi(db, f)


if __name__ == "__main__":
    main(Path(__file__).parent, "--keep" not in sys.argv)

查询：把下面的 SQL 存成 q1.sql，运行 sqlcmd -S "(localdb)\MSSQLLocalDB" -E -C -f 65001 -d Lab_eap -W -i q1.sql：

sql
SET NOCOUNT ON;
-- 1. 贴片机每块拼板的节拍
SELECT i.PanelSn, DATEDIFF(SECOND, i.EventTime, o.EventTime) AS CycleSec, o.Detail
FROM MachineEvent i JOIN MachineEvent o ON o.PanelSn = i.PanelSn AND o.EventType='BOARD_OUT' AND o.Machine=i.Machine
WHERE i.EventType='BOARD_IN' AND i.SnOk=1 ORDER BY i.PanelSn;
-- 2. 追溯：按板码 SN 查 AOI 与贴片信息
SELECT pb.SerialNo, pb.PanelSn, pb.Position, b.Result AS AoiResult,
       ISNULL(STRING_AGG(d.RefDes+':'+d.DefectCode+'('+d.Judge+')', ', ') WITHIN GROUP (ORDER BY d.Id), '-') AS Defects,
       (SELECT COUNT(*) FROM MachineEvent e WHERE e.PanelSn=pb.PanelSn AND e.EventType='PICK_ERROR') AS PickErrOnPanel
FROM PanelBoard pb
JOIN AoiBoard b ON b.PanelSn=pb.PanelSn AND b.Position=pb.Position
LEFT JOIN AoiDefect d ON d.PanelSn=b.PanelSn AND d.InspectTime=b.InspectTime AND d.Position=b.Position
GROUP BY pb.SerialNo, pb.PanelSn, pb.Position, b.Result ORDER BY pb.SerialNo;
-- 3. 板码读不到
SELECT COUNT(*) AS NoReadBoards FROM MachineEvent WHERE EventType='BOARD_IN' AND SnOk=0;

常见坑与排查 ​

现象最可能的原因
设备日志里没有板码设备没配读码器或没读到；用 Hermes 传递，或补装读码器；或用 MES 记录的进出站时间对照（风险较高）
日志文件读到一半是残行设备正在写。只处理以换行结尾的完整行，或等文件大小稳定
同一文件被重复导入，数据翻倍没有"已处理文件"记录或行级唯一约束
中文/特殊字符乱码文件编码不是 UTF-8（可能是 GBK）。解析时明确指定，并和厂商确认
设备软件升级后解析突然失败日志格式变了。解析器要有版本检测，遇到未知格式报警而不是静默丢弃
AOI 缺陷代码对不上 MES 的缺陷代码需要建映射表，见 缺陷代码与不良分类
设备时间比服务器快了几分钟做时间同步；日志同时存设备时间和收到时间
下发程序后设备没切换设备不支持远程切换或需要先停机；一律下发后回读核对
联锁一旦网络抖动就频繁停线失效策略没设计好；加断线容忍时间、本地缓存放行状态
想直接读设备本机数据库，被厂商说会影响保修先问清楚；用只读账号、复制备份库读，别在生产库上跑重查询

练习题与答案 ​

  1. 什么是 SMEMA，为什么说 Hermes 是它的继任者？ 答：SMEMA（IPC-SMEMA-9851）是传送带之间交接板子的机械和电气接口，主要是几根线上的"有板/准备好"信号，不传数据。Hermes（IPC-HERMES-9852）基于 TCP/IP 和 XML，除了交接信号，还能传板标识、传送速度等数据。
  2. CFX 和 Hermes 分别解决什么问题？ 答：CFX 让设备把事件数据（生产、故障、换程序等）以消息的方式发布给上位系统；Hermes 管设备之间板子交接并传递板的信息。
  3. 实验里 NOREAD 的拼板为什么不能直接丢掉或归到相邻的板上？ 答：丢掉会让这块板没有记录，追溯断链；归到别的板会污染别人的追溯数据。正确做法是明确标记为异常，等人工处理。
  4. Recipe 下载与 Recipe 核对有什么区别？为什么起步阶段建议先做核对？ 答：下载是 EAP 主动把程序写给设备，需要设备支持远程写；核对是只读设备当前程序名并与要求比较。很多设备不支持远程写，核对更容易实现，也能挡住绝大多数选错程序的事故。
  5. 防错联动里的"失效策略"是什么？举两种选择。 答：EAP/网络出故障时设备如何表现。fail-open：继续生产，保产能但可能漏防错；fail-closed：全部停机，保质量但会停线。要由业务决定。
  6. 文件内容没变就跳过导入，靠的是什么？如果文件被设备每分钟追加一行，这个办法还够用吗？ 答：靠文件名加内容摘要。追加写的文件摘要每次都变，会被重新解析；所以还需要行级去重（行摘要唯一约束），文件很大时还应记录读取位置只读新增部分。
  7. 实验里 SN-A100-0003 的 AOI 结果是 PASS，却有一条缺陷记录，为什么要保留？ 答：那条缺陷被复判为 OK（误报或可接受），保留它能统计 AOI 的误报率、优化检测程序，也能在追溯时解释"当时报过什么"。

小结 ​

  • SMT 设备接口分四类：行业标准（CFX、Hermes、SMEMA）、厂商开放接口、文件/数据库、硬件信号。
  • 各设备都要找出四要素：时间、设备、板码（拼板码）、结果。
  • 设备记录挂在拼板码上，通过拼板与板码的对应表展开到每块小板，才能由 SN 追溯。
  • Recipe：先做"采集核对"，再考虑"下发"；防错联动要设计失效策略。
  • 接入顺序：问、看、选、取样、只读先行、验证、留退路、文档化。
  • 厂商差异大，一切以设备手册和厂商技术支持为准。
