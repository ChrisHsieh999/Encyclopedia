IQC来料检验

AI 生成 · 待核对制造业务QMSIQC更新于 2026-10-21

⚠ 待核对：IQC 的流程、状态名称、处置类型（允收/拒收/特采/挑选）和表结构是行业通用做法，你们自研 QMS 的叫法、审批流、和 WMS 的衔接方式一定不同，请对照核实。文中检验标准书的规格值（如 0603 电容长度 1.60 ± 0.15 mm、容值 100 nF ± 10%）是教学示例，不是某个厂家数据手册的值。RoHS 限值已对照维基百科（0.1% / Cd 0.01%），但具体适用范围和豁免条款请以法规原文为准。SQL 与 SqlSugar 代码、输出都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 QMS 系列第 3 篇。读完你应该能：说清来料检验的完整流程和四种处置；写出一份检验标准书；设计 InspectionLot、InspectionItem、InspectionResult 三张核心表（后面 IPQC过程检验、FQC与OQC、不合格品控制NCR 都复用它们）；用"条件写进 WHERE"实现开始、判定、特采的状态流转；并亲手跑通一次"抽样 → 录入 → 判定 → 特采 → 结果只追加"。

一句话定义 ​

IQC（Incoming Quality Control，来料检验）是物料从供应商到货后、入库使用之前，按检验标准书抽样检验、判定能不能用的那道关卡；它把"待检"的物料变成"合格可发料"、"不合格退货"或"特采使用"。

先修知识 ​

  • 质量管理基础：知道三检（来料、过程、成品）和"检测不等于预防"。
  • 抽样检验AQL：知道怎么由批量和 AQL 查出样本量和 Ac/Re。本篇会直接引用。
  • 收货与上架：知道到货后物料会先放进待检库存，检验合格才能转为可用库存。

它解决什么问题 ​

先看一个现场故事。某周二，仓库收到一批 0603 贴片电容 5000 颗，供应商换了新的包装卷盘。仓管直接扫码入库，周三上午就发料上线。下午 SMT 线的 AOI 开始大量报"立碑"和"少锡"，一小时报废 40 块板。事后查：这批电容端头氧化，可焊性不合格，锡膏爬不上去。

没有 IQC 会怎样：

  • 坏料直接上线，成本是"整块板 + 停线 + 追溯 + 客户风险"，比在仓库里发现贵几十倍到几百倍；
  • 出了问题，没有"来料时的检验记录"，无法向供应商索赔（"当初你们也没检出来"）；
  • 同一个供应商反复出问题，没有数据能支撑调整采购份额或启动供应商审核（见 供应商质量管理）。

有 IQC 则：到货先锁在待检库存里（WMS 不允许发料），检验员按标准书抽样、记录结果、给出判定；合格才放行，不合格走 不合格品控制NCR。记录留下来，就是供应商评价的数据来源。

核心概念 ​

IQC 在整条链里的位置 ​

四种处置：

处置英文（本库的 Result 取值）含义后续
允收Accept抽样结果满足 Ac库存由"待检"转"合格"，可发料
拒收Reject抽样结果达到 Re开不合格品单（见 不合格品控制NCR），退供应商（RTV，Return To Vendor），通知采购
特采Concession本该拒收，但因交期紧、缺陷轻微等原因，经授权人审批让步使用必须留审批记录；通常要求产线加强监控、该批可追溯；计入供应商质量指标，不能当合格算
挑选Sort全检，挑出不良品，良品使用挑选的工时和成本通常由供应商承担；挑选后的良品是否还要再抽检，由标准书规定

检验标准书（SIP） ​

检验员不是凭经验判，而是按检验标准书（也叫检验规范、SIP，Standard Inspection Procedure）执行。它是主数据，按物料（或物料类别）+ 版本维护，核心内容：

项目说明本文例子（0603 电容 100 nF）
检验项目看什么、测什么外观、长度、电容值
检验方法/工具目视、卡尺、LCR 表、放大镜倍数LCR 表、20 倍放大镜
规格与上下限规格值和公差（Lsl 下限，Usl 上限）长度 1.45–1.75 mm；容值 90–110 nF
缺陷等级Critical / Major / Minor外观为 Minor，其余 Major
AQL每个缺陷等级的 AQL（见 抽样检验AQL）外观 2.5，长度、容值 1.0
引用标准外观判据来源，组装件看 IPC-A-610（见 FQC与OQC），元件外观常引用供应商规格书—

电子来料的常见检验项目：

类别内容说明
外观与包装标识破损、变形、氧化、引脚共面性、丝印、标签、数量、批次/日期码、是否真空包装湿敏元件还要核对 MSL 等级和湿度卡，见 MSD湿敏元件管理
尺寸长宽高、引脚间距、PCB 板厚卡尺、投影仪
电气性能阻值、容值、电压、通断LCR 表、万用表；通常抽测
可焊性元件端头或引脚能否被焊锡润湿常用方法有"浸渍观察"（dip and look，定性）和润湿称量法（wetting balance，定量）；试验前通常先做加速老化模拟库存时间。来源：维基百科 Solderability
RoHS / 有害物质铅、镉、汞、六价铬等是否超限欧盟 RoHS 对铅、汞、六价铬及若干溴系阻燃剂和邻苯类限值是 0.1%（1000 ppm），镉是 0.01%（100 ppm）（按均质材料）。这类检测一般不逐批做，而是定期送检或核对供应商 RoHS 报告，由 LIMS 管理，见 LIMS

对于 Critical 缺陷（如 RoHS 超标），常见做法不是抽样，而是逐批核对供应商报告 + 定期第三方复检。

抽样与"批" ​

检验批（InspectionLot）是一次检验的最小单位。一批通常是"同一个供应商、同一料号、同一生产批次/日期码、同一次到货"，不能把不同日期码混成一批（否则好批会掩盖坏批）。批量 N 就是这批的数量，样本量 n 由 N 和 AQL 查表得到，见 抽样检验AQL。

免检、跳批与供应商认证 ​

对长期表现优秀的供应商和物料，可以减少检验：放宽检验（见转移规则）、跳批检验（隔几批检一次）或免检（凭供应商出货报告 COC 放行并定期复检）。这需要有数据支撑（连续 N 批合格、PPM 达标）和审批，不是"熟人关系"。

业务视角 ​

角色与步骤

角色做什么
仓管（WMS）到货收货，按供应商送货单录入数量、批次；物料入"待检"库位，库存状态=待检，不可发料
系统收货后自动创建检验批（Pending），按标准书带出检验项目，按批量和 AQL 算出样本量
IQC 检验员领取检验批，随机抽样，逐项录入结果（计量型录实测值，计数型录 OK/NG 和缺陷代码，缺陷代码见 缺陷代码与不良分类），完成后提交判定
IQC 组长/QE判定（系统按 Ac/Re 给出建议），对拒收批决定退货、挑选或申请特采
采购对拒收批与供应商交涉；批准特采要评估交期与风险
生产/工程特采物料上线时加强监控（如首件加严、AOI 重点关注该批）

涉及的单据/记录：送货单、检验批（IQC 报告）、检验结果明细、不合格品通知（NCR）、特采申请单、退货单。

典型规则

  • 待检库存不允许被领料、拣货（WMS 必须强制）；
  • 判定后状态不可随意改；改判（如拒收后特采）要留审批和理由；
  • 同一供应商同一物料的检验结果要累计，用于转移规则和供应商评分；
  • 紧急放行（来不及检就先用）是高风险动作：必须留痕、标记批次、保证可追溯，万一不合格能找回并隔离已用料的板。

KPI：批合格率（一次判定 Accept 的批 ÷ 总批数）、批退率、特采率、检验及时率（到货到判定的小时数）、供应商来料 PPM。见 质量成本与KPI。

技术视角 ​

三张核心表 ​

表类型要点
InspectionLot单据一次检验一行。InspType 区分 IQC/IPQC/FQC/OQC；Status 管流程，Result 管结论
InspectionItem单据明细从检验标准书复制到本批，之后标准书改版不影响已建的批
InspectionResult记录每个样本、每个项目一行，只追加（用触发器强制）

状态机：

Pending（待检）─开始→ Inspecting（检验中）─判定→ Judged（已判定）─关闭→ Closed（已关闭）

Result（结论）：Accept、Reject、Concession（特采）、Sort（挑选）。Status 与 Result 分开：Judged 之后结论可以从 Reject 变成 Concession 或 Sort，但这一变化必须走审批，状态仍是 Judged。

完整 T-SQL（建库与建表，这是本库约定的共享表定义，后续词条直接引用）：

sql
IF DB_ID(N'Lab_QMS') IS NOT NULL BEGIN ALTER DATABASE Lab_QMS SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE Lab_QMS; END
GO
CREATE DATABASE Lab_QMS;
GO
USE Lab_QMS;
GO
-- ① 检验批：一次检验的"任务单"，从待检到关闭
CREATE TABLE InspectionLot (
    Id           INT IDENTITY(1,1) PRIMARY KEY,
    LotNo        VARCHAR(40)    NOT NULL UNIQUE,              -- 检验批号，如 IQC-20261021-001
    InspType     VARCHAR(10)    NOT NULL CHECK (InspType IN ('IQC','IPQC','FQC','OQC')),
    ItemCode     VARCHAR(50)    NOT NULL,                     -- 被检物料/产品料号
    SupplierCode VARCHAR(30)    NULL,                         -- IQC 才有
    LotQty       DECIMAL(18,3)  NOT NULL,                     -- 批量
    SampleQty    INT            NOT NULL DEFAULT 0,           -- 抽样数（由抽样方案算出）
    Status       VARCHAR(12)    NOT NULL DEFAULT 'Pending'
                 CHECK (Status IN ('Pending','Inspecting','Judged','Closed')),
    Result       VARCHAR(12)    NULL
                 CHECK (Result IN ('Accept','Reject','Concession','Sort')),
    CreatedAt    DATETIME2(0)   NOT NULL DEFAULT SYSDATETIME(),
    JudgedAt     DATETIME2(0)   NULL
);
-- ② 检验项目：从检验标准书"复制"到本批，之后不随标准书改版而变
CREATE TABLE InspectionItem (
    Id       INT IDENTITY(1,1) PRIMARY KEY,
    LotId    INT           NOT NULL REFERENCES InspectionLot(Id),
    ItemName NVARCHAR(50)  NOT NULL,
    Spec     NVARCHAR(100) NULL,
    Lsl      DECIMAL(18,4) NULL,                              -- 下限，计数型项目为空
    Usl      DECIMAL(18,4) NULL,                              -- 上限
    Unit     NVARCHAR(10)  NULL
);
-- ③ 检验结果：每个样本、每个项目一行，只追加
CREATE TABLE InspectionResult (
    Id            BIGINT IDENTITY(1,1) PRIMARY KEY,
    LotId         INT           NOT NULL REFERENCES InspectionLot(Id),
    ItemId        INT           NOT NULL REFERENCES InspectionItem(Id),
    SampleNo      INT           NOT NULL,
    MeasuredValue DECIMAL(18,4) NULL,                         -- 计量型填实测值，计数型为空
    Judgement     VARCHAR(2)    NOT NULL CHECK (Judgement IN ('OK','NG')),
    DefectCode    VARCHAR(30)   NULL,
    CONSTRAINT UQ_InspectionResult UNIQUE (ItemId, SampleNo)
);
GO
CREATE TRIGGER TR_InspectionResult_AppendOnly ON InspectionResult
INSTEAD OF UPDATE, DELETE AS
BEGIN
    THROW 50001, N'检验结果只追加：不能修改或删除', 1;
END
GO
-- 检验标准书（主数据）与抽样方案表
CREATE TABLE InspectionSpec (
    Id          INT IDENTITY(1,1) PRIMARY KEY,
    ItemCode    VARCHAR(50)   NOT NULL,
    ItemName    NVARCHAR(50)  NOT NULL,
    DefectClass VARCHAR(10)   NOT NULL CHECK (DefectClass IN ('Critical','Major','Minor')),
    Spec        NVARCHAR(100) NULL,
    Lsl         DECIMAL(18,4) NULL,

几个设计取舍 ​

要点做法与理由
项目要"复制"到批上标准书下个月改版（比如容值公差从 ±10% 改 ±5%），已经检完的批不应受影响；复制后每批自带当时的 Lsl/Usl
结果只追加检验记录是质量证据，不能被悄悄改。用 INSTEAD OF UPDATE, DELETE 触发器拦截；确需更正，应追加一条"更正记录"或整批作废重检（本文不展开更正表）
(ItemId, SampleNo) 唯一同一样本同一项目只能有一条结果，重复提交会被数据库拒绝
判定必须"样本录满"判定 SQL 里检查结果行数 = 样本数 × 项目数，防止没检完就判定
判定条件写进 WHERE只有 Status = 'Inspecting' 才能判定；同一批再点一次"判定"更新 0 行，不会重复。与 工单管理 里防超报是同一个技巧
与 WMS 的衔接判定后给 WMS 发事件：批号、料号、供应商、数量、结论。WMS 据此把待检库存转成合格/不合格/特采；也可以由 WMS 查询检验批状态后决定能否发料。无论哪种，"待检不可发"必须由 WMS 一侧强制。参见 收货与上架、WMS与MES交互
用 decimal 存数量来料有的按个，有的按米、克、千克，用 decimal(18,3)

逐步例子 ​

例：2026-10-21 到货 C-0603-100N（0603 电容 100 nF）1000 颗，供应商 SUP-A，建检验批 IQC-20261021-001。

  1. 批量 1000，水平 II → 字母 J；标准书里外观 AQL 2.5，长度、容值 AQL 1.0；J 方案：AQL 2.5 → 80 个、Ac/Re = 5/6；AQL 1.0 → 80 个、Ac/Re = 2/3。两种样本量都是 80，抽 80 个（若样本量不同，取较大者，见 抽样检验AQL）；
  2. 检验员抽 80 颗，逐项检验：外观 3 颗不良（第 17、53、71 号，缺陷代码 APP-02）；长度第 40 号是 1.80 mm、第 66 号是 1.42 mm，都超出 1.45–1.75，2 颗不良；电容值第 9 号 86.5 nF、第 33 号 112 nF、第 61 号 88 nF，超出 90–110，3 颗不良；
  3. 判定：外观 3 ≤ 5，接收；长度 2 ≤ 2，接收；电容值 3 ≥ Re 3，拒收。任一项目拒收则整批拒收，结论 Reject；
  4. 采购评估：生产急用，电容值偏差轻微，申请特采；审批通过后，结论改成 Concession，产线对该批加强监控；
  5. 有人想把电容值第 9 号的 NG 改成 OK 让它"合格"，触发器拒绝：检验结果只追加。

03_lab.sql：建批 → 复制检验项目 → 开始 → 录入 240 行结果 → 汇总 → 判定 → 特采 → 尝试改结果。点开复制：

03_lab.sql（点击展开）
sql
USE Lab_QMS;
SET NOCOUNT ON;
-- 1 建检验批：批量 1000，按检验水平 II 查字母，再取各项目 AQL 对应方案里最大的样本量
INSERT INTO InspectionLot(LotNo, InspType, ItemCode, SupplierCode, LotQty)
VALUES ('IQC-20261021-001', 'IQC', 'C-0603-100N', 'SUP-A', 1000);
DECLARE @lot INT = SCOPE_IDENTITY();

UPDATE l SET SampleQty = x.n
FROM InspectionLot l
CROSS APPLY (SELECT MAX(p.SampleSize) AS n
             FROM InspectionSpec s
             JOIN AqlCode c ON l.LotQty BETWEEN c.LotMin AND c.LotMax
             JOIN AqlPlan p ON p.Letter = c.Letter AND p.Aql = s.Aql
             WHERE s.ItemCode = l.ItemCode) x
WHERE l.Id = @lot;

-- 2 把检验标准书复制成本批的检验项目
INSERT INTO InspectionItem(LotId, ItemName, Spec, Lsl, Usl, Unit)
SELECT @lot, ItemName, Spec, Lsl, Usl, Unit FROM InspectionSpec WHERE ItemCode = 'C-0603-100N' ORDER BY Id;

-- 3 开始检验：状态条件写进 WHERE，重复点"开始"不会出错
DECLARE @r1 INT, @r2 INT;
UPDATE InspectionLot SET Status = 'Inspecting' WHERE Id = @lot AND Status = 'Pending';  SET @r1 = @@ROWCOUNT;
UPDATE InspectionLot SET Status = 'Inspecting' WHERE Id = @lot AND Status = 'Pending';  SET @r2 = @@ROWCOUNT;
PRINT N'开始检验：第一次影响 ' + CAST(@r1 AS NVARCHAR(5)) + N' 行，第二次影响 ' + CAST(@r2 AS NVARCHAR(5)) + N' 行';

-- 4 录入结果：外观 NG 在第 17/53/71 号；长度第 40 号=1.80、第 66 号=1.42；电容值第 9/33/61 号偏出规格
DECLARE @appear INT = (SELECT Id FROM InspectionItem WHERE LotId = @lot AND ItemName = N'外观');
DECLARE @len    INT = (SELECT Id FROM InspectionItem WHERE LotId = @lot AND ItemName = N'长度');
DECLARE @cap    INT = (SELECT Id FROM InspectionItem WHERE LotId = @lot AND ItemName = N'电容值');
DECLARE @n INT = (SELECT SampleQty FROM InspectionLot WHERE Id = @lot);

;WITH t AS (SELECT TOP (@n) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b)
INSERT INTO InspectionResult(LotId, ItemId, SampleNo, MeasuredValue, Judgement, DefectCode)
SELECT @lot, @appear, i, NULL, CASE WHEN i IN (17,53,71) THEN 'NG' ELSE 'OK' END,
       CASE WHEN i IN (17,53,71) THEN 'APP-02' END FROM t;

;WITH t AS (SELECT TOP (@n) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b),
v AS (SELECT i, CAST(CASE i WHEN 40 THEN 1.80 WHEN 66 THEN 1.42
                            ELSE 1.60 + (((i * 7) % 11) - 5) * 0.01 END AS DECIMAL(18,4)) AS x FROM t)
INSERT INTO InspectionResult(LotId, ItemId, SampleNo, MeasuredValue, Judgement, DefectCode)
SELECT @lot, @len, i, x, CASE WHEN x BETWEEN 1.45 AND 1.75 THEN 'OK' ELSE 'NG' END,
       CASE WHEN x NOT BETWEEN 1.45 AND 1.75 THEN 'DIM-01' END FROM v;

;WITH t AS (SELECT TOP (@n) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b),
v AS (SELECT i, CAST(CASE i WHEN 9 THEN 86.5 WHEN 33 THEN 112 WHEN 61 THEN 88
                            ELSE 100 + (((i * 13) % 17) - 8) * 1.0 END AS DECIMAL(18,4)) AS x FROM t)
INSERT INTO InspectionResult(LotId, ItemId, SampleNo, MeasuredValue, Judgement, DefectCode)
SELECT @lot, @cap, i, x, CASE WHEN x BETWEEN 90 AND 110 THEN 'OK' ELSE 'NG' END,
       CASE WHEN x NOT BETWEEN 90 AND 110 THEN 'ELE-01' END FROM v;

PRINT N'--- 批信息 ---';
SELECT LotNo, InspType, LotQty, SampleQty, Status FROM InspectionLot WHERE Id = @lot;

PRINT N'--- 每个项目：样本数、NG 数、方案、结论 ---';
SELECT i.ItemName AS 项目, s.Aql AS AQL, COUNT(*) AS 样本数,
       SUM(CASE WHEN r.Judgement = 'NG' THEN 1 ELSE 0 END) AS NG数,
       p.Ac, p.Re,
       CASE WHEN SUM(CASE WHEN r.Judgement = 'NG' THEN 1 ELSE 0 END) <= p.Ac THEN N'接收' ELSE N'拒收' END AS 项目结论
FROM InspectionItem i
JOIN InspectionLot l  ON l.Id = i.LotId
JOIN InspectionSpec s ON s.ItemCode = l.ItemCode AND s.ItemName = i.ItemName
JOIN AqlCode c        ON l.LotQty BETWEEN c.LotMin AND c.LotMax
JOIN AqlPlan p        ON p.Letter = c.Letter AND p.Aql = s.Aql
JOIN InspectionResult r ON r.ItemId = i.Id
WHERE i.LotId = @lot
GROUP BY i.Id, i.ItemName, s.Aql, p.Ac, p.Re
ORDER BY i.Id;

-- 5 判定：样本录满才能判；任一项目 NG 数 > Ac 则整批拒收。仍用"条件写进 WHERE"
DECLARE @j1 INT, @j2 INT;
DECLARE @judge NVARCHAR(MAX) = N'
UPDATE l SET Status = ''Judged'', JudgedAt = SYSDATETIME(),
       Result = CASE WHEN EXISTS (
            SELECT 1 FROM InspectionItem i
            JOIN InspectionSpec s ON s.ItemCode = l.ItemCode AND s.ItemName = i.ItemName
            JOIN AqlCode c ON l.LotQty BETWEEN c.LotMin AND c.LotMax
            JOIN AqlPlan p ON p.Letter = c.Letter AND p.Aql = s.Aql
            WHERE i.LotId = l.Id
              AND (SELECT COUNT(*) FROM InspectionResult r WHERE r.ItemId = i.Id AND r.Judgement = ''NG'') > p.Ac)
          THEN ''Reject'' ELSE ''Accept'' END
FROM InspectionLot l
WHERE l.Id = @lot AND l.Status = ''Inspecting''
  AND (SELECT COUNT(*) FROM InspectionResult r WHERE r.LotId = l.Id)
      = l.SampleQty * (SELECT COUNT(*) FROM InspectionItem i WHERE i.LotId = l.Id);';
EXEC sp_executesql @judge, N'@lot INT', @lot = @lot;  SET @j1 = @@ROWCOUNT;
EXEC sp_executesql @judge, N'@lot INT', @lot = @lot;  SET @j2 = @@ROWCOUNT;
PRINT N'判定：第一次影响 ' + CAST(@j1 AS NVARCHAR(5)) + N' 行，第二次影响 ' + CAST(@j2 AS NVARCHAR(5)) + N' 行';
SELECT LotNo, Status, Result FROM InspectionLot WHERE Id = @lot;

-- 6 拒收后经评审"特采"：只有 Judged 且 Reject 的批才能改成 Concession
UPDATE InspectionLot SET Result = 'Concession' WHERE Id = @lot AND Status = 'Judged' AND Result = 'Reject';
PRINT N'特采后：';
SELECT LotNo, Status, Result FROM InspectionLot WHERE Id = @lot;

-- 7 尝试改结果：触发器拦截
BEGIN TRY
    UPDATE InspectionResult SET Judgement = 'OK' WHERE ItemId = @cap AND SampleNo = 9;
END TRY
BEGIN CATCH
    PRINT N'改结果被拒绝：' + ERROR_MESSAGE();
END CATCH

csharp
﻿using QmsLab;
using SqlSugar;

// 连接 LocalDB 里的练习库 Lab_QMS（先用 SQL 脚本建好表）
var db = new SqlSugarClient(new ConnectionConfig
{
    ConnectionString = @"Server=(localdb)\MSSQLLocalDB;Database=Lab_QMS;Trusted_Connection=True;TrustServerCertificate=True;",
    DbType = DbType.SqlServer,
    IsAutoCloseConnection = true,
    InitKeyType = InitKeyType.Attribute,
});
if (args.Contains("sql")) db.Aop.OnLogExecuting = (sql, _) => { if (sql.TrimStart().StartsWith("UPDATE")) Console.WriteLine("SQL> " + sql.Replace("\r\n", " ").Replace("\n", " ")); };

const string LotNo = "IQC-20261021-002";

// 0 清理上次实验留下的数据。结果表有"只追加"触发器，实验清理时临时关掉它（真实系统不要这么做）
db.Ado.ExecuteCommand("DISABLE TRIGGER TR_InspectionResult_AppendOnly ON InspectionResult");
var old = db.Queryable<InspectionLot>().Where(l => l.LotNo == LotNo).Select(l => l.Id).ToList();
db.Deleteable<InspectionResult>().Where(r => old.Contains(r.LotId)).ExecuteCommand();
db.Deleteable<InspectionItem>().Where(i => old.Contains(i.LotId)).ExecuteCommand();
db.Deleteable<InspectionLot>().Where(l => old.Contains(l.Id)).ExecuteCommand();
db.Ado.ExecuteCommand("ENABLE TRIGGER TR_InspectionResult_AppendOnly ON InspectionResult");

// 1 建检验批：批量 500，水平 II 查字母，AQL 1.0 查方案
decimal lotQty = 500, aql = 1.0m;
var letter = db.Queryable<AqlCode>().First(c => c.LotMin <= lotQty && lotQty <= c.LotMax).Letter;
var plan = db.Queryable<AqlPlan>().First(p => p.Letter == letter && p.Aql == aql);
var lot = new InspectionLot { LotNo = LotNo, InspType = "IQC", ItemCode = "R-0603-10K", SupplierCode = "SUP-B",
                              LotQty = lotQty, SampleQty = plan.SampleSize, Status = "Pending" };
lot.Id = db.Insertable(lot).ExecuteReturnIdentity();
Console.WriteLine($"1. 批 {LotNo}：批量 {lotQty:0}，代码字母 {letter}，AQL {aql}，抽 {plan.SampleSize} 个，Ac/Re = {plan.Ac}/{plan.Re}");

// 2 检验项目
var appear = new InspectionItem { LotId = lot.Id, ItemName = "外观", Spec = "无破损、丝印清晰" };
var resist = new InspectionItem { LotId = lot.Id, ItemName = "阻值", Spec = "10 kΩ ± 1%", Lsl = 9900, Usl = 10100, Unit = "Ω" };
appear.Id = db.Insertable(appear).ExecuteReturnIdentity();
resist.Id = db.Insertable(resist).ExecuteReturnIdentity();

// 3 开始检验（状态条件写进 WHERE）
bool Move(string from, string to) => db.Updateable<InspectionLot>()
    .SetColumns(l => new InspectionLot { Status = to })
    .Where(l => l.Id == lot.Id && l.Status == from).ExecuteCommand() == 1;
Console.WriteLine($"2. 开始检验 Pending->Inspecting：{(Move("Pending", "Inspecting") ? "成功" : "被拒绝")}；再点一次：{(Move("Pending", "Inspecting") ? "成功" : "被拒绝")}");

// 4 录入结果：外观第 7 号 NG；阻值第 22 号实测 10150 Ω 超上限
var rows = new List<InspectionResult>();
for (int no = 1; no <= plan.SampleSize; no++)
{
    rows.Add(new InspectionResult { LotId = lot.Id, ItemId = appear.Id, SampleNo = no,
        Judgement = no == 7 ? "NG" : "OK", DefectCode = no == 7 ? "APP-01" : null });
    decimal v = no == 22 ? 10150 : 10000 + (no % 5 - 2) * 20;       // 正常样本在 9960~10040 之间
    bool ok = v >= resist.Lsl && v <= resist.Usl;
    rows.Add(new InspectionResult { LotId = lot.Id, ItemId = resist.Id, SampleNo = no, MeasuredValue = v,
        Judgement = ok ? "OK" : "NG", DefectCode = ok ? null : "ELE-02" });
}
db.Insertable(rows).ExecuteCommand();
Console.WriteLine($"3. 录入结果 {rows.Count} 行（{plan.SampleSize} 个样本 x 2 个项目）");

// 5 汇总每个项目的 NG 数
var ng = db.Queryable<InspectionResult>().Where(r => r.LotId == lot.Id && r.Judgement == "NG")
    .GroupBy(r => r.ItemId).Select(r => new { r.ItemId, Cnt = SqlFunc.AggregateCount(r.Id) }).ToList();
foreach (var it in new[] { appear, resist })
    Console.WriteLine($"   {it.ItemName}：NG {ng.FirstOrDefault(x => x.ItemId == it.Id)?.Cnt ?? 0} 个（Ac={plan.Ac}）");
int worst = ng.Count == 0 ? 0 : ng.Max(x => x.Cnt);

// 6 判定：样本录满才能判，只有 Inspecting 状态能判；第二次判定不生效
bool Judge()
{
    var result = worst <= plan.Ac ? "Accept" : "Reject";
    var expected = plan.SampleSize * 2;
    return db.Updateable<InspectionLot>()
        .SetColumns(l => new InspectionLot { Status = "Judged", Result = result, JudgedAt = DateTime.Now })
        .Where(l => l.Id == lot.Id && l.Status == "Inspecting"
                    && SqlFunc.Subqueryable<InspectionResult>().Where(r => r.LotId == lot.Id).Count() == expected)
        .ExecuteCommand() == 1;
}
Console.WriteLine($"4. 判定：{(Judge() ? "成功" : "被拒绝")}；再判一次：{(Judge() ? "成功" : "被拒绝")}");
var final = db.Queryable<InspectionLot>().InSingle(lot.Id);
Console.WriteLine($"最终：{final.LotNo} 状态 {final.Status}，结果 {final.Result}");

常见坑与排查 ​

坑事实与办法
待检库存被发料检验批状态只是"提示"，真正的锁必须在 WMS 库存状态上；上线前用测试用例验证"待检不可拣货"
一批混了多个日期码抽样前拆批；系统收货时按日期码/批次号生成检验批
检验标准书改版，旧批被"改规格"项目复制到批上，改版只影响之后的批
样本录入一半就判定判定条件要求结果行数等于样本数 × 项目数
重复提交判定用状态条件做幂等，返回受影响行数提示用户
特采被当成合格统计批合格率只算 Accept；特采单独统计，且要追踪特采批后续在线表现
检验员改结果结果表只追加，更正走更正记录并审批
缺陷代码乱写缺陷代码用统一字典，见 缺陷代码与不良分类，否则无法做帕累托
计量型项目只记 OK/NG，不记实测值计量型项目务必存 MeasuredValue，才能做 CPK 等统计，见 过程能力CPK
抽样不随机只抽最上层的一箱会漏掉其他箱的问题，按箱、卷盘分层随机抽

练习题与答案 ​

  1. 一批 12000 颗电阻，水平 II，AQL 0.65，样本量和 Ac/Re 是多少？ 答：12000 落在 10001–35000 → 字母 M，样本量 315，Ac/Re = 5/6（用 aql.py 验证过）。
  2. 为什么要把检验项目"复制"到检验批，而不是只存一个标准书的外键？ 答：标准书会改版。只存外键的话，改版后旧批显示的是新规格，重新判定会得到不同结论，也无法还原当时按什么标准判的。复制后每批自带当时的规格。
  3. 一批判了 Reject，之后审批通过特采。为什么只改 Result 而不改 Status？ 答：Status 描述流程走到哪一步（已判定），Result 描述结论。特采是对结论的修订，不是流程倒退。把两者分开，才能准确回答"这批当初判了什么、后来怎么处置"。
  4. 实验里"判定"为什么要检查"结果行数 = 样本数 × 项目数"？ 答：防止检验员没检完就触发判定。没检的样本没有记录，NG 数会被低估，可能把坏批判成接收。
  5. 供应商要求"把拒收批改成特采，下次我保证改善"。你怎么处理？ 答：特采不是人情。要走审批（采购、QE、使用部门），记录风险、有效期、后续监控措施；该批计入供应商拒收率，并要求供应商出整改报告（见 8D与CAPA）。
  6. 外观 NG 3 个，Ac 5；长度 NG 2，Ac 2。为什么整批没有因为长度"到了 Ac"就拒收？ 答：Ac 是"最多可接受数"，NG 等于 Ac 仍接收，大于等于 Re（= Ac + 1）才拒收。

小结 ​

  • IQC 在物料入库使用前把关：待检锁定 → 抽样 → 检验 → 判定 → 允收/拒收/特采/挑选。
  • 检验标准书是主数据，复制到检验批；结果表只追加；判定条件写进 WHERE，保证幂等。
  • 本库约定的三张表 InspectionLot、InspectionItem、InspectionResult 是 IPQC/FQC/OQC 共用的核心。
  • 特采是让步接收，必须审批留痕，不能算合格；"待检不可发料"要由 WMS 强制。
  • 抽样数据来自 抽样检验AQL，不良处置交给 不合格品控制NCR。
