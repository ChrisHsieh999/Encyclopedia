抽样检验AQL

AI 生成 · 待核对制造业务QMS抽样更新于 2026-10-21

⚠ 待核对：①本篇的查表数据取自 IS 2500 (Part 1):2000（印度国家标准，与 ISO 2859-1:1999 等同采用，全文公开在 law.resource.org）扫描件里的 Table 1、2-A、2-B。扫描件是倒置的图片，我逐格读图后编码，再和 asiaqualityfocus 的摘录表、若干公开资料里的单点数值交叉核对，并用标准 Table 6-A 里的一个格子（J 方案 6.52%）核对了接收概率公式，全部一致；但没有逐格核对整张表。②联网搜索显示 ISO 2859-1 已有 2026 年新版（BSI、AFNOR 目录可见），本篇是 1999 版，新版的表值和转移规则是否有变化未核对；ANSI/ASQ Z1.4 的最新确认版是 2003 (R2018)。③放宽检验（Table 2-C）未编码，只讲规则。④正式使用请以你们合同或公司指定的标准原文为准；公司 QMS 的抽样规则请对照你们系统核实。

本篇是 QMS 系列第 6 篇，也是 IQC来料检验、IPQC过程检验、FQC与OQC 共用的"抽多少、几个坏就退"的规则手册。读完你应该能：说清 AQL 到底是什么（以及最常见的误解）；用"批量 → 代码字母 → 样本量 → Ac/Re"四步查出抽样方案；理解正常、加严、放宽三种严格度怎样转移；看懂 OC 曲线和 α、β 两种风险；并亲手运行一个 Python 查表函数，复算本文所有例子。

一句话定义 ​

抽样检验是"从一批产品里随机抽一小部分来检，根据样本里发现的不良个数，决定整批接收还是拒收"的方法；AQL（Acceptance Quality Limit，接收质量限）是买卖双方约定的"这条供货线上长期平均不良率最多能差到多少还算可以接受"，ISO 2859-1 / ANSI Z1.4 这套表就是按 AQL 来索引抽样方案的。

先修知识 ​

  • 质量管理基础：知道"检验"在质量体系里的位置，以及"检测不等于预防"。
  • IQC来料检验：知道一批来料为什么要检、检完有哪几种处置。
  • 会算概率里的"二项分布"最好，不会也行，本文用代码替你算。

它解决什么问题 ​

一批 12000 颗 0603 电阻，一颗一颗量？按每颗 3 秒算，要 10 个小时，而且很多检验是破坏性的（比如可焊性试验、拉力试验，测完就报废了）。可是什么都不检，坏料直接上线，一块板上有 300 多个焊点，一颗坏件就是一块报废板。

抽样检验折中了这两头：只检一部分，用统计学保证"坏得多的批大概率被拦下，好的批大概率被放行"。但新手常见的麻烦是：

  • 凭感觉抽："这批抽 10 个吧"。抽少了，坏批漏过去；抽多了，浪费人力。没人能解释为什么是 10。
  • 供应商问："你们凭什么退我的货？"检验员答不上来。有了统一的标准方案，答案是"按双方约定的 ISO 2859-1，AQL 1.0，样本 80，不良超过 2 个就拒收"。
  • 同一个物料，有的检验员判 1 个不良过、有的判不过，因为没有统一的 Ac/Re。

这套表就是把这些经验固化成一本"查表手册"。

核心概念 ​

先认几个符号 ​

符号含义例子
N（批量）这一批一共多少个1000 颗电容
n（样本量）抽出来检多少个80
d样本里发现的不合格品个数2
Ac（Acceptance number，接收数）d 小于等于它就接收2
Re（Rejection number，拒收数）d 大于等于它就拒收；单次抽样里 Re = Ac + 13
AQL约定的接收质量限，单位是"每百个里的不合格品数"（或每百个里的缺陷数）1.0

计数抽样（by attributes）的意思是：每个被检个体只判"合格/不合格"（或数缺陷个数），不记实测值。ISO 2859-1 就是这一类。如果要记实测值（比如长度是 1.62 mm）并用均值和标准差判定，那是计量抽样（如 ISO 3951 系列），本文不展开。

AQL 是什么，不是什么 ​

ISO 2859-1 的定义很绕口：AQL 是"连续一系列批提交验收时，最差还能容忍的过程平均"。人话版本：

  • 它说的是过程平均（长期很多批的平均不良率），不是某一批的不良率。
  • 它是对供应商的一个信号："只要你的长期平均不良率好于 AQL，你的批绝大多数会被接收；差于 AQL，你会越来越频繁地被拒收，最后被加严甚至暂停供货。"
  • 标准自己也特别注明：定了 AQL 不等于说"这个质量水平是理想的"。

最常见的误解："AQL 1.0 就是允许 1% 不良"。不对。AQL 1.0 的方案对"恰好 1% 不良的批"仍有接近 5% 的概率拒收（见后面的 OC 曲线实验），而且样本里抽到几个不良才拒收，是由样本量决定的，不是由 1% 直接决定的。更不能理解为"我们送你的货里 1% 的坏品，你不能投诉"。

缺陷分类与常用 AQL ​

同一件产品的不同缺陷严重程度不同，所以通常分级，每级用不同的 AQL：

缺陷等级含义常见做法（行业惯例，不是标准规定）
Critical（致命）危及人身安全或违反法规（如 RoHS 超标、起火风险）AQL 0，往往直接全检或要求供应商提供检测报告
Major（主要）影响功能、可靠性或客户使用（如电容值超差、焊盘氧化不可焊）AQL 0.65 或 1.0
Minor（次要）不影响功能，只是外观（轻微划痕、丝印略淡）AQL 2.5 或 4.0

具体取多少，是买卖双方（或公司质量部）约定的事。ISO 2859-1 明确说，AQL 的选择和缺陷分类由"责任方"决定。

三步查表 ​

  1. 批量 + 检验水平 → 代码字母；
  2. 代码字母 + AQL → 在"主表"（Table 2-A，正常检验单次抽样）里读出样本量 n 和 Ac/Re；
  3. 从批里随机抽 n 个，检完数不良：d ≤ Ac 接收；d ≥ Re 拒收。

主表里有一些格子画的是箭头而不是数字，意思是"这个字母在这个 AQL 下没有合适的方案，请顺着箭头用别的字母的方案，并且用那个字母对应的样本量"。箭头向下：用箭头下面第一个有数字的方案；箭头向上：用上面第一个有数字的方案。如果查出来的样本量大于或等于批量，就全检。

正常、加严、放宽：三种严格度 ​

"AQL 方案"不是只查一次，而是一个系统：根据最近几批的结果，自动在三档严格度间切换，用来奖励好供应商、惩罚差供应商。这就是前面说的"AQL 是对供应商的信号"的实现方式。

严格度做法
正常检验开始时默认用。查 Table 2-A
加严检验样本量不变，但 Ac/Re 更小（更容易拒收）。查 Table 2-B
放宽检验样本量更小（约正常的 40%）。查 Table 2-C（本文不编码）

转移规则（ISO 2859-1:1999 第 9 章，单次抽样）：

  • 正常 → 加严：连续 5 批（或不到 5 批）里，有 2 批一次提交就被拒收（"原检验"，不算返工重交的批）。
  • 加严 → 正常：连续 5 批一次提交都被接收。
  • 正常 → 放宽：同时满足三条：转移分达到 30；生产稳定；责任方同意用放宽。转移分的算法：开始为 0，每批原检验后更新——Ac 大于等于 2 的方案，如果该批在"AQL 收紧一档"时也能接收则加 3 分，否则清零；Ac 为 0 或 1 的方案，批接收加 2 分，拒收清零。
  • 放宽 → 正常：任何一批被拒收、或生产不稳定、或责任方认为需要。
  • 暂停检验：加严检验下累计拒收批达到 5 批，就停止验收，直到供应商采取改进措施并经责任方同意。
  • 转移规则对每一类缺陷独立应用。

OC 曲线与两种风险 ​

给定方案（n, Ac），批的实际不良率 p 不同，被接收的概率 Pa 也不同。把 p 作横轴、Pa 作纵轴画出来，就是OC 曲线（Operating Characteristic curve，操作特性曲线）。它总是一条从左上到右下的 S 形线：p 小，Pa 接近 100%；p 大，Pa 接近 0。

  • 生产方风险 α（Producer's risk）：一个质量恰好等于 AQL 的"好批"被错误拒收的概率，α = 1 − Pa(AQL)。
  • 消费方风险 β（Consumer's risk）：一个质量很差的"坏批"被错误接收的概率。ISO 2859-1 里把"接收概率为 10% 时对应的不良率"称为消费方风险质量 CRQ（也叫极限质量 LQ 的一种表述），也就是"这么差的批，你有 10% 的概率放过去"。

抽样永远有这两种风险，只能通过加大样本量把它们压低，不可能消除。

Pa 的计算：若批量很大，每个样本是否不良近似互相独立，用二项分布：

Pa = Σ(d = 0..Ac)  C(n, d) · p^d · (1 − p)^(n−d)

批量不大时，精确的做法是超几何分布（不放回抽样）。标准里的表用的是二项分布（Table 6 的注释写明了），本文代码两种都给。

逐步例子 ​

例 1：普通查表。 一批 1000 颗电容，水平 II，AQL 1.0。

  1. 1000 落在 501–1200，水平 II → 字母 J；
  2. J 的样本量 80；主表 J 行、AQL 1.0 列是 "2 / 3"，即 Ac = 2、Re = 3；
  3. 抽 80 颗，检出不良 ≤ 2 个接收，≥ 3 个拒收。

例 2：碰到箭头。 一批 500 颗电阻，水平 II，AQL 0.65。

  1. 500 落在 281–500，水平 II → 字母 H（本来样本量 50）；
  2. 主表 H 行、AQL 0.65 列是箭头，向下，用下面第一个有数字的方案，来到 J 行：n = 80，Ac/Re = 1/2；
  3. 所以要抽 80 个而不是 50 个。

例 3：小批量全检。 一批 8 块金手指板，AQL 0.65。查出来的方案是 n = 20，大于批量 8，所以全检，Ac = 0（一个不良就拒收）。

例 4：怎么理解接收概率。 J 方案 (n=80, Ac=2) 下，一批实际不良率 3% 的货：期望抽到 80 × 3% = 2.4 个不良，接收的概率是 56.8%（代码算出）。也就是说"3% 不良的批"有四成多的概率被拒收；而不良率只有 1% 的批，被拒收的概率约 4.7%。

动手实验：Python 实现抽样方案查表并复算 ​

前提：Python 3.8+（我用 3.12）。建一个文件夹，放下面几个文件。

第 1 步：新建 aql.py。它包含代码字母、样本量、主表的"对角线规律"、箭头解析、接收概率 Pa 和转移规则状态机。

主表（Table 2-A）看起来是一大堆数字，但规律很强：每个字母行有一个第一个 "0/1" 的 AQL 列；它右边第 1、2 格是箭头；从第 3 格开始 Ac/Re 依次是 1/2、2/3、3/4、5/6、7/8、10/11、14/15、21/22（只有 A–E 行继续到 30/31、44/45）；加严表整体右移一列，数列是 1/2、2/3、3/4、5/6、8/9、12/13、18/19（A–E 行继续到 27/28、41/42）。代码用"规律 + 箭头方向"生成每个格子，这种编码方式比手抄 400 多个格子更不容易抄错，但也意味着必须有校验，见第 2 步。

python
"""ISO 2859-1 / ANSI Z1.4 单次抽样方案查表（正常检验 Table 2-A、加严检验 Table 2-B）。
数据来源：IS 2500 (Part 1):2000（与 ISO 2859-1:1999 等同）的 Table 1、2-A、2-B，按表上的"对角线规律 + 箭头"编码。
"""
import math

CODE_LOT_MAX = [8, 15, 25, 50, 90, 150, 280, 500, 1200, 3200, 10000, 35000, 150000, 500000]  # Table 1 各档批量上限；之后是最后一档
LETTERS = "ABCDEFGHJKLMNPQRS"
LEVELS = {  # Table 1：一般检验水平 I/II/III，15 档批量对应的代码字母
    "I":   "AABCCDEFGHJKLMN",
    "II":  "ABCDEFGHJKLMNPQ",
    "III": "BCDEFGHJKLMNPQR",
}
SIZE = dict(A=2, B=3, C=5, D=8, E=13, F=20, G=32, H=50, J=80, K=125, L=200, M=315,
            N=500, P=800, Q=1250, R=2000, S=3150)
AQLS = [0.010, 0.015, 0.025, 0.040, 0.065, 0.10, 0.15, 0.25, 0.40, 0.65, 1.0, 1.5, 2.5,
        4.0, 6.5, 10, 15, 25, 40, 65, 100, 150, 250, 400, 650, 1000]
# 每个字母第一个 "0 1" 所在的 AQL 列号（下标），读自 Table 2-A；加严检验整体右移一列
C0_NORMAL = dict(A=14, B=13, C=12, D=11, E=10, F=9, G=8, H=7, J=6, K=5, L=4, M=3, N=2, P=1, Q=0, R=-1)
NORMAL_SEQ = [(1, 2), (2, 3), (3, 4), (5, 6), (7, 8), (10, 11), (14, 15), (21, 22), (30, 31), (44, 45)]
TIGHT_SEQ = [(1, 2), (2, 3), (3, 4), (5, 6), (8, 9), (12, 13), (18, 19), (27, 28), (41, 42)]


def code_letter(lot, level="II"):
    i = sum(lot > m for m in CODE_LOT_MAX)
    return LEVELS[level][i]


def _cell(sev, letter, col):
    """返回数字格 (Ac, Re)；是箭头格返回 None。"""
    big = letter in "ABCDE"
    if sev == "normal":
        c0, seq, nmax = C0_NORMAL[letter], NORMAL_SEQ, (10 if big else 8)
    else:
        c0 = C0_NORMAL.get(letter, -2) + 1
        seq, nmax = TIGHT_SEQ, (9 if big else 7)
    if col == c0:
        return (0, 1)
    k = col - c0 - 3
    if 0 <= k < nmax:
        return seq[k]
    return None


def _arrow_dir(sev, letter, col):
    c0 = (C0_NORMAL[letter] if sev == "normal" else C0_NORMAL.get(letter, -2) + 1)
    return "down" if col < c0 or col == c0 + 2 else "up"   # 其余（c0+1 与右侧）都向上


def plan(lot, aql, level="II", sev="normal"):
    """返回 dict(letter, n, ac, re, full)；sev 为 normal 或 tightened（Table 2-A / 2-B）。"""
    sev = "normal" if sev == "normal" else "tight"
    col = AQLS.index(aql)
    last = "R" if sev == "normal" else "S"
    letters = LETTERS[:LETTERS.index(last) + 1]
    i = letters.index(code_letter(lot, level))
    while True:
        cell = _cell(sev, letters[i], col)
        if cell:
            break
        d = _arrow_dir(sev, letters[i], col)
        if d == "down" and i == len(letters) - 1: d = "up"
        if d == "up" and i == 0: d = "down"
        i += 1 if d == "down" else -1
    n = SIZE[letters[i]]
    return dict(letter=letters[i], n=n, ac=cell[0], re=cell[1], full=n >= lot)


def pa(n, ac, p, lot=None):
    """接收概率：给批量用超几何分布（精确），不给用二项分布（近似）。p 为批不良率（小数）。"""
    if lot is None:
        return sum(math.comb(n, d) * p**d * (1 - p)**(n - d) for d in range(ac + 1))
    D = round(lot * p)
    return sum(math.comb(D, d) * math.comb(lot - D, n - d) for d in range(ac + 1)) / math.comb(lot, n)


class Switch:
    """正常/加严/放宽转移规则（ISO 2859-1:1999 第 9 章，单次抽样）。"""
    def __init__(self):
        self.sev, self.score, self.hist, self.tight_ok, self.tight_rej = "normal", 0, [], 0, 0

    def after(self, accepted, ac, accepted_if_tighter_aql=None):
        """记录一批的结果，返回处理后的严格度。ac=本批所用方案的接收数。"""
        if self.sev == "normal":
            self.hist = (self.hist + [accepted])[-5:]
            if self.hist.count(False) >= 2:
                self.sev, self.hist, self.tight_ok, self.tight_rej = "tightened", [], 0, 0
                return self.sev
            if ac >= 2:
                self.score = self.score + 3 if accepted_if_tighter_aql else 0
            else:
                self.score = self.score + 2 if accepted else 0
            if self.score >= 30:   # 还需生产稳定且负责方同意，这里只提示
                self.sev = "reduced?"
        elif self.sev == "tightened":
            if accepted:
                self.tight_ok += 1; self.tight_rej = 0
                if self.tight_ok == 5:
                    self.sev, self.hist, self.score = "normal", [], 0
            else:
                self.tight_ok = 0; self.tight_rej += 1
                if self.tight_rej == 5:   # 简化：按"连续"计；原文是累计不接收批数达到 5
                    self.sev = "discontinue"
        return self.sev

第12批 [tightened] n=80 Ac/Re=1/2 不良0 -> 接收  转移分= 0  之后: normal
第13批 [normal   ] n=80 Ac/Re=2/3 不良1 -> 接收  转移分= 3  之后: normal
第14批 [normal   ] n=80 Ac/Re=2/3 不良1 -> 接收  转移分= 6  之后: normal
第15批 [normal   ] n=80 Ac/Re=2/3 不良0 -> 接收  转移分= 9  之后: normal

读输出，注意这几个关键点：

  • 第 1–3 批连续接收，且 Ac = 2，每批都"收紧一档（AQL 0.65，Ac = 1）也能接收"，所以转移分每批 +3，累计到 9；
  • 第 4 批不良 2 个，正常方案接收，但 AQL 0.65 的方案（Ac = 1）会拒收，转移分清零；
  • 第 5 批、第 7 批各被拒收一次，"连续 5 批里 2 批被拒"（第 3–7 批里有第 5、7 批），第 7 批之后转入加严，Ac/Re 变成 1/2；
  • 加严下连续接收 5 批（第 8–12 批），回到正常；
  • 代码里放宽只是提示（reduced?）：放宽需要"生产稳定"和"责任方同意"两个人为条件，代码无法判断；
  • 暂停检验的"累计 5 批"我简化成"连续"，生产实现时应该按标准原文的"累计"。

第 6 步，动手改：

  • 把 lab_lookup.py 里的 (1000, 1.0) 改成 (1000, 0.4)，对照 K、L 的箭头路径，预测结果后再运行；
  • 在 lab_oc.py 里把方案改成 plan(1000, 1.0, level="III")（水平 III，抽得更多），看 α 和 CRQ 怎么变（样本量变大，CRQ 变小，也就是消费方更安全）；
  • 用 Switch 模拟一个"一直很差"的供应商：每批不良数都等于 Ac + 1，看几批后转入加严、再几批后到暂停。

业务视角与技术视角 ​

业务视角 ​

  • 谁决定 AQL：质量工程师（QE）与客户/采购共同约定，写进《检验标准书》（见 IQC来料检验）。车规、医疗等客户可能指定更严的 AQL，甚至要求"零缺陷"（Ac = 0）。
  • 谁执行：IQC/IPQC/FQC/OQC 检验员，按系统里自动算出的样本量抽样。
  • KPI：批合格率、批退率、转移状态分布（有多少供应商在加严）、检验工时。见 质量成本与KPI。
  • 和供应商的关系：转移规则让"好供应商少检、差供应商多检"变成自动的，不靠人情。参见 供应商质量管理。
  • 特别提醒：抽样合格的批，并不等于里面没有不良品。批里的不良品仍然是不良品，发现了要隔离处理（见 不合格品控制NCR）。

技术视角 ​

系统里需要这几类数据：

数据类型说明
代码字母表 AqlCode主数据批量区间 → 字母（按检验水平，可加一列水平）。IQC 实验里有
抽样方案表 AqlPlan主数据字母 + AQL → 样本量、Ac、Re，按严格度（正常/加严）分开存。IQC 实验里有正常检验的一小部分
检验标准书主数据每个物料每个检验项目的 AQL、缺陷等级
严格度状态记录每个 供应商 + 物料 + 缺陷等级 当前处在正常/加严/放宽，转移分，最近 5 批结果
检验批 InspectionLot记录查表得到的 SampleQty 写进去（见 IQC来料检验）

设计要点：

  • 查表数据要入库而不是写死在代码里：标准改版（比如换新版）只需要换数据。表里的值必须有出处和版本。
  • 样本量要冻结：检验批创建时就把 SampleQty、Ac、Re 写到批上；之后即使有人改了方案表，这一批仍按创建时的方案判。
  • 转移状态更新要在批判定的同一个事务里完成，并用"条件写进 WHERE"保证同一批不会被重复计入（参见 工单管理 里的同一个技巧）。
  • 样本要真随机：系统可以对一批里的箱号、卷盘号、SN 随机抽取（用伪随机数并记录种子），不要让检验员"顺手拿"。

⚠ 以上"表结构"是通用设计，请对照你们自研 QMS 的实际做法核实。

常见坑与排查 ​

坑事实与办法
把 AQL 当成"允许的不良率"AQL 是长期过程平均的约定，不是单批的合格线。见上文
忽略箭头，直接用本字母的样本量箭头要求用另一个字母的方案及其样本量；H 行 0.65 例子就是这样
样本不是随机抽的（只抽最上面一箱）破坏了所有概率计算的前提。多箱混批要按箱分层，每箱按比例抽
一个批里混了不同生产日期/批次抽样的"批"应该是同质的，混批会让好批掩盖坏批。按生产批/日期码拆批
样本量大于批量还照抽样本量大于等于批量要全检
同一个物料的几种缺陷等级各抽各的抽样数不同时，ISO 允许取最大样本量用于所有等级，再各用各的 Ac/Re
只拒收才记录，接收的不记转移规则要看接收的批（转移分、连续 5 批接收），必须每批都记
返工后重交的批也计入转移转移规则只算"原检验"，返工重交不算
觉得 Ac = 0 最安全Ac = 0 对应的样本量往往不大，OC 曲线反而不陡；想真正压低风险，是增大样本量，而不是单纯把 Ac 改成 0
抽样合格后把批里发现的不良也放走已发现的不良品必须隔离处理，不因批接收而放行

练习题与答案 ​

以下答案都用本文的 aql.py 算过。

  1. 一批 3000 颗芯片，水平 II，AQL 1.5，正常检验的方案是什么？加严检验呢？ 答：3000 落在 1201–3200，水平 II → K，样本量 125。正常：Ac/Re = 5/6；加严：3/4。
  2. 一批 200 个，水平 I，AQL 2.5，怎么抽？ 答：水平 I、批量 151–280 → 字母 E（13 个）；主表 E 行 AQL 2.5 是箭头，向下用 F 行，样本量 20、Ac/Re = 1/2。
  3. 方案 K（n=125，Ac=3）下，批不良率 3% 时接收概率是多少？ 答：二项分布，约 0.4814（不良率 1% 时是 0.9626）。
  4. 一批 60 个，水平 II，AQL 1.0，怎么抽？ 答：批量 51–90，水平 II → E（13 个），E 行 AQL 1.0 有数字 0/1。抽 13 个，不良一个就拒收。
  5. 为什么"连续 5 批接收就回到正常"，而"2 批拒收就转加严"？ 答：这是有意的不对称：惩罚快、恢复慢。拒收说明质量可能变差，要尽快加大保护；恢复则要多一点证据才放心。
  6. 供应商抱怨"我们的 AQL 是 1.0，你们抽到 3 个不良（样本 80）就退货，不合理，1% 才 0.8 个"。你怎么回应？ 答：AQL 不是"允许不良率"，方案是 Ac = 2、Re = 3，是 80 个里最多接收 2 个；样本里抽到 3 个，说明这一批的真实不良率很可能显著高于 AQL（实验里 3% 不良率的批仍有约 57% 概率被放行，说明这个方案已经对供应商相当宽松）。同时说明转移规则：他们如果持续好，就会被放宽检验。
  7. 两位检验员抽了同一批的 80 个，一个判 1 个不良、一个判 3 个，结论完全不同。怎么办？ 答：这是检验标准一致性问题，不是抽样问题：要有《检验标准书》与限度样本（boundary sample），判不准的缺陷要双人复判，并纳入检验员培训。

小结 ​

  • 抽样检验用"小样本 + 统计规则"在检验成本和风险之间折中；AQL 是过程平均的约定，不是允许不良率。
  • 四步：批量 + 检验水平 → 代码字母 → 查主表（注意箭头）→ 样本量与 Ac/Re；样本量大于等于批量就全检。
  • 严格度有正常、加严、放宽三档，由最近几批的结果自动转移：好供应商少检，差供应商多检。
  • OC 曲线描述接收概率随不良率的变化；α（生产方风险）与 β（消费方风险）永远存在，只能靠样本量压低。
  • 表数据要入库、有版本、有出处；实现后一定要和独立来源核对。
