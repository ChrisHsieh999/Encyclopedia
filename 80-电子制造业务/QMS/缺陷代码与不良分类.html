缺陷代码与不良分类

AI 生成 · 待核对制造业务QMS缺陷主数据更新于 2026-10-21

⚠ 待核对：①IPC-A-610 是收费标准，我没有读到原文。"三个产品等级 + Acceptable / Process Indicator / Defect"取自 Wevolver 和 ANSI 博客的介绍；它们说 J 版（2024）已取消 Target（目标）这一类，更早的版本才有 Target，我只找到这一个主要来源，请对照你们手里的 IPC-A-610 版本核实。②各缺陷的成因和"在哪个工位检出"是行业通用经验，不是标准条文；缺陷代码的编号规则、严重度划分、"其他"占比阈值都是示例设计，你们的自研 QMS/MES 一定有自己的代码表，请对照核实。③SQL、Python、C# 代码和输出都是我在本机 SQL Server LocalDB（临时库 Lab_qms3）上实际运行得到的，数据是虚构的。

本篇是 QMS 系列的一篇。读完你应该能：说出电子厂常见的十几种缺陷是怎么来的、一般在哪一站被发现；设计一张缺陷代码主数据表，并说清它和 MES 不良记录的关系；知道为什么"其他"不能占 40%；亲手用 Python 和 SQL 做出柏拉图（Pareto）的累计占比。

一句话定义 ​

缺陷代码（Defect Code）是给每一种"不良现象"起的统一编号和名字（比如 PR-001 = 虚焊），存在一张主数据表里；检验员、测试设备、维修员记录不良时都从这张表里选，而不是手写文字。有了统一代码，才能统计、画柏拉图（Pareto Chart，按数量从高到低排列的柱状图加累计占比折线），才知道该先解决哪个问题。

先修知识 ​

  • SMT与电子组装流程：知道 SPI、AOI、ICT、FCT 各在流程的哪一站，回流焊长什么样。
  • 质量管理基础：知道"不良""不合格品"这些词的区别（内容还在写时，可先按字面理解）。
  • 会读简单的 SQL（SELECT、GROUP BY、JOIN）。窗口函数在实验里现讲。

它解决什么问题 ​

先讲一个现场故事。某工厂的 AOI 工位，操作员发现不良后在系统里手工输入原因：同一种问题，有人写"虚焊"，有人写"假焊"，有人写"焊接不良"，有人写"连锡"又写成"短路"。月底质量经理要出报表："本月最多的不良是什么？"——IT 导出来一看，几百种写法，Excel 里手工合并了两天，结论还被各线批评"你们归类不对"。

没有统一缺陷代码，会发生这些事：

  1. 统计不出来：同一种缺陷被拆成很多名字，数量被稀释，排不出重点。
  2. 追溯不了：想查"所有立碑的板"，只能模糊搜文字，漏很多。
  3. 改进无从下手：8D与CAPA 要先说清"是什么问题"，口径不一致就吵不清楚。
  4. 设备和系统对不上：AOI 设备报的缺陷名称（常是英文或设备自己的编码）和 MES 里手工选的不是一套，要建映射表，没人维护就错位。
  5. "其他"成了垃圾桶：选项不够用时大家都选"其他"，而"其他"占了 40% 的柏拉图，等于什么都没说。

缺陷代码主数据就是用来解决这些问题的：一个现象一个代码，全厂只有一张表，所有记录都引用它。

核心概念 ​

现象、原因、措施：三件事别混 ​

层次回答什么例子谁来填
缺陷现象（Symptom）看到了什么连锡、少锡、缺件检验员 / 设备（AOI、ICT）
缺陷原因（Cause）为什么会这样钢网堵孔、吸嘴磨损、炉温偏低维修员 / 工程师（分析后）
处理措施（Action）做了什么补焊、更换元件、清洗钢网维修员 / 工程师

本篇的缺陷代码指的是第一层：现象。检验员和 AOI 看到的只能是现象，他们不知道也不该猜原因；原因是维修分析后才确定的（见 返修与维修管理），可以用另一张"原因代码表"。把三者混在一张表里是常见错误，会让一个代码既像现象又像原因，统计时前后不一致。

分类层级：外观 / 电性 / 功能 / 物料 / 工艺 ​

代码表里常给每个缺陷挂一个大类（Category），方便汇总。一种常见的分法（只是示例）：

大类含义举例
外观看得见、一般不影响电气性能的表面问题污染、划伤、丝印模糊
电性测量出来电气参数不对开路、短路、阻值超差
功能整板通电后功能不工作无法开机、通信失败、烧录失败
物料来料本身的问题板翘曲、元件引脚氧化、元件参数不良
工艺制造过程造成的焊接 / 贴装问题虚焊、连锡、少锡、偏移、立碑、缺件、错件、极性反

几点注意：

  • 分类要互斥（一个缺陷只属于一类）。像"缺件"，既可算工艺（贴片机漏贴）又可算物料（料盘缺），就要在规则里写死归哪类，别让两个人归两边。
  • 分类不是越细越好。层级太深，检验员在手机或平板上选不过来。两层够用：大类 + 具体缺陷。
  • 缺陷粒度要"可行动"：能让不同的人看到同一个现象选同一个代码，也能让工程师据此采取不同的措施。"焊接不良"太粗（虚焊、连锡、少锡的对策完全不同）；"左边第三个焊点少 0.1 mg 锡膏"太细。

严重度：Critical / Major / Minor ​

每个缺陷代码带一个严重度（Severity），常用三档（通用做法，各公司定义不同）：

严重度含义举例
Critical（致命）可能危及人身安全、违反法规，或让产品完全不能用极性反导致电池过热、电源短路
Major（严重）影响功能、可靠性或客户使用虚焊、连锡、缺件
Minor（轻微）不影响功能和可靠性的外观或轻微偏差轻微划伤、助焊剂残留、小的偏移

它和 抽样检验AQL 里的"致命 / 严重 / 轻微缺陷"的 AQL 值是对应的：不同严重度用不同的 AQL 值抽检，所以代码表里记录严重度，抽样和判定系统才能自动取用。

IPC-A-610：电子组装的"验收长什么样" ​

行业里判断一个焊点、一个元件贴得算不算合格，最常用的参考是 IPC-A-610（Acceptability of Electronic Assemblies，电子组装件的可接受性，IPC 协会发布）。据 Wevolver 和 ANSI 博客的介绍：

三个产品等级（Class）：

等级名称典型产品
Class 1通用类电子产品低价大批量的消费类产品，功能为主
Class 2专用服务类电子产品工业控制、网络设备、汽车模块、家电；没指定等级时，通常按 Class 2
Class 3高性能 / 高可靠性电子产品航空航天、医疗、军工，不允许失效

等级越高越严格：同一个状态，在 Class 1 可接受，在 Class 3 可能就是缺陷。

验收状况分类（Condition）：

状况含义（据 Wevolver）
Target（目标）接近理想的状态。资料称 J 版（2024）已取消 这一类，旧版才有
Acceptable（可接受）满足验收准则，能保证可靠，不用处理
Process Indicator（制程警示）与理想状态有轻微偏离，不影响形状、装配和功能，可以接受，但要记录和监控——它可能提示制程在漂移
Defect（缺陷）不满足验收要求，需要返修、修理或报废

对做系统的人，最有用的是中间这个"制程警示"：它不是不良，不要让板子被拦截，但值得统计。比如 AOI 发现焊料量略少但仍在可接受范围，就记成 Process Indicator，在趋势图里看它是不是越来越多——越来越多，说明钢网或印刷参数正在变坏，等它变成 Defect 就晚了。因此在设计缺陷代码表时，可以给"制程警示"单独一个标记，或者设一个 Severity/Disposition 区分"不处理只统计"的类别。

注意：IPC-A-610 是验收标准（怎么看合格），不是工艺标准（怎么焊）。后者是 J-STD-001 等的范畴。本库不复制标准条文，具体图例和尺寸要求以你们手里的正版标准为准。

常见缺陷清单：成因与检出工位 ​

下表是 PCBA（贴好件的板）上最常见的十几种缺陷。"成因"是行业通用经验（不是标准条文），"检出工位"指通常在哪一站发现——注意发现不等于产生：连锡是在印刷工位产生的，可能在 SPI 就被拦住，也可能到 ICT 才被测出来。

缺陷是什么常见成因通常检出工位
虚焊焊点外观像焊上了，实际没有形成可靠的连接，时通时断焊盘或引脚氧化、润湿不良；炉温不足、TAL 太短；锡膏少；元件引脚不共面AOI 能发现一部分；ICT / FCT（间歇性）；BGA 要靠 X-ray；最容易漏到客户手里
连锡 / 桥接焊料把相邻的焊盘或引脚连在一起，造成短路锡膏过多或塌陷；钢网开孔偏大或底部脏；贴装压力过大；元件偏移SPI（印刷桥连）、AOI、ICT（短路）
少锡焊料不足，焊点太小钢网堵孔或太脏；刮刀压力或速度不当；脱模速度；钢网变形SPI（体积 / 面积 / 高度）、AOI
偏移元件或锡膏偏离焊盘中心贴片坐标偏、吸嘴磨损；锡膏印偏；板定位不准SPI（印刷偏移）、AOI（元件偏移）
立碑（Tombstoning）小元件一端焊上，另一端翘起，像墓碑两端焊盘受热不均；两端锡膏量不等；焊盘设计不对称；贴偏AOI
缺件该有元件的位置没有元件吸嘴堵或磨损导致抛料；飞达缺料；元件在过炉前被碰掉AOI（炉前 / 炉后）、ICT
错件贴了不是 BOM 要求的元件上料错站位；物料混料；BOM 或站位表错AOI（部分，靠丝印）、ICT（参数不符）、FCT；源头防错见 SMT上料防错与站位表
极性反有方向的元件（二极管、电解电容、IC）方向装反料带方向与贴片程序角度不一致；程序角度错AOI（极性检查）、ICT、FCT
冷焊焊点灰暗、粗糙、不光亮，强度差回流温度不足；焊接中被扰动（板子在凝固前被振动）目检、AOI（部分）、FCT
锡珠焊点附近的小锡球预热升温过快；锡膏吸湿；钢网开孔设计不当；贴装压力过大AOI、目检
翘曲板或元件受热后变形，不平PCB 材质或 Tg 偏低、吸湿；拼板设计；过炉时支撑不足IQC（来料测翘曲）、SPI（高度异常）、AOI；BGA 开焊靠 X-ray
污染助焊剂残留、指纹、异物操作不戴手套；设备漏油；清洗不彻底目检、AOI
划伤板面或线路被刮伤搬运、传送带、治具摩擦目检

其中立碑的原因有公开资料可查：Indium 公司的技术博客 Tombstoning: The Death of a PCBA 指出它和两端焊盘的润湿力不平衡有关（先熔化一端的表面张力把元件拉起）。其他成因是工厂里的通用经验。

这些缺陷的前后关系请回看 SMT与电子组装流程 的流程图：越早的工位越便宜。SPI 拦下的少锡板，擦掉锡膏重印就行；到了 FCT 才发现，要维修；到了客户手里，要走退货（见 质量成本与KPI）。这也是为什么在缺陷代码表里要记录"哪些工位可能检出它"。

缺陷代码主数据表：DefectCode ​

核心设计是一张表（本库约定的列名，其他 QMS / MES 篇的实验也引用它）：

列类型说明
Codevarchar(20)，唯一缺陷代码，例 PR-001。要唯一，其他表引用它
Namenvarchar(50)中文名，例"虚焊"
Categorynvarchar(10)大类：外观 / 电性 / 功能 / 物料 / 工艺
Severityvarchar(10)Critical / Major / Minor
StationScopenvarchar(100)哪些工位可以选它，例 SPI,AOI（逗号分隔）
Activebit是否启用。停用而不是删除

编码规则示例：<类别缩写>-<三位序号>，如 PR-001（Process 工艺）、AP-001（Appearance 外观）、MT-001（Material 物料）、EL-001（Electrical 电性）、FN-001（Function 功能）、OT-000（Other 其他）。注意：

  • 代码一旦发布就不再改含义，也不复用已停用的编号。否则历史数据里的 PR-007 突然变了意思，三年前的柏拉图全错。
  • 名称可以改（把"虚焊"改成"虚焊/假焊"），因为记录里存的是代码，改名后历史记录显示新名字，统计不受影响。
  • 一个代码对应一个现象。若想再细分，新增子码（比如把 PR-001 虚焊 细分出 BGA 虚焊），并把旧码停用或保留为"未细分"，别悄悄改旧码的含义。
  • StationScope 的作用是缩小选项：SPI 工位的下拉里只出现印刷类缺陷，不会出现"功能失效"，检验员选择压力小得多，选错也少。

与 MES 不良记录的关系 ​

MES 里每发现一个缺陷，写一条不良记录（DefectRecord），它只存缺陷代码，不存名称：

列说明
Sn板码（见 条码与板码规则）
LineCode、StationCode在哪条线、哪个工位发现的（发现工位，不是产生工位）
DefectCode缺陷代码，外键指向 DefectCode.Code
RefDes位号，例 U5、C12（见下方"一个缺陷要记几条"）
Qty数量，通常为 1

三个设计要点：

  1. 外键保证代码合法：不能录入代码表里没有的代码（实验里可以看到被数据库拒绝）。
  2. 只存代码，名字用 JOIN 得到：改名、翻译成英文，都不用动几百万行记录。
  3. 一块板多个缺陷，要记多条：同一块板有 3 个位号的元件偏移，记 3 条（位号不同），而不是一条数量 3。这样才能回答"U5 这个位号最常出什么问题"，进而追到某个站位的飞达或某块钢网。

不良记录之后还会接到 不良品拦截与锁定（不良板被拦住不能流下去）和 返修与维修管理（维修员填原因和措施）。完整流程见 不良品从发现到关闭的全过程。

代码治理：别让"其他"占 40% ​

"其他"（Other）是必要的安全阀：现场总会遇到代码表里没有的现象。但它很容易失控：

  • 检验员图省事，什么都选"其他"。
  • 下拉里的选项太多或名字不好懂，找不到就选"其他"。
  • 没人回头看"其他"里到底是什么，代码表就从不更新。

结果是柏拉图里"其他"占了 40%，统计失去意义。治理方法（通用做法，阈值是示例）：

做法说明
选"其他"必须填备注系统强制，备注不能空，也不能是"其他""不知道"
监控"其他"占比按线体、班组每天统计 其他 / 总数，超过阈值（如 5%）报警；见实验里的查询
定期清理备注每周把"其他"的备注拉出来看，出现次数多的现象升级成新代码
按工位缩小选项用 StationScope，让选项刚好够用
代码表有负责人新增、停用要走申请和审批（也属于 内部审核与体系文件 要管的受控记录）
设备代码映射AOI 报的缺陷类型要映射到统一代码；映射不到的不要默认丢到"其他"，要报警让人处理
不要为了好看合并把相近的现象合成一个代码会损失信息；是否合并看"对策是不是一样"

另一个常见问题是代码膨胀：越加越多，500 个代码没人记得住。给每个代码设 Active，定期把近半年一次都没用过的停用。

柏拉图（Pareto）分析 ​

柏拉图基于一个经验规律（常说"80/20"）：少数几个原因造成了大部分问题。做法：

  1. 按缺陷类别统计数量；
  2. 按数量从大到小排序；
  3. 计算每类占总数的占比，和从左到右累加的累计占比；
  4. 画成柱状图（数量）加折线（累计占比），在 80% 处画一条参考线；
  5. 累计到约 80% 的那几类就是"关键少数"，优先解决。

"其他"的排序规则：无论它数量多少，都固定放最后，不参与排序。否则一个大"其他"排在第一位，没有任何指导意义。

下图是本篇实验的数据（SMT-01 线，420 条不良）画出来的。累计占比越过 80% 的是第 7 个"锡珠"（81.2%），也就是前 7 类（虚焊、连锡、少锡、偏移、立碑、缺件、锡珠）是关键少数。

逐步例子：AOI 一天的不良怎么变成一张柏拉图 ​

假设 SMT-01 线一天（或一个班）AOI、SPI、ICT、FCT 等工位共录了 420 条不良。统计后的数量：

缺陷数量缺陷数量
虚焊118污染12
连锡74冷焊11
少锡52划伤9
偏移41错件8
立碑23开路7
缺件19极性反6
锡珠14翘曲5
其他14功能失效4
短路3合计420

手算前三名：

  • 虚焊 118 / 420 = 28.095…% ≈ 28.1%，累计 28.1%
  • 连锡 74 / 420 = 17.619…% ≈ 17.6%，累计 118 + 74 = 192，192 / 420 = 45.714…% ≈ 45.7%
  • 少锡 52 / 420 = 12.380…% ≈ 12.4%，累计 192 + 52 = 244，244 / 420 = 58.095…% ≈ 58.1%

第 7 名锡珠：累计 118 + 74 + 52 + 41 + 23 + 19 + 14 = 341，341 / 420 = 81.190…% ≈ 81.2%，越过 80%。

最后一名"其他"：14 / 420 = 3.3%，累计到 420 / 420 = 100.0%。它虽然也是 14，却被放在最后，而不是排在锡珠（也是 14）旁边。

读图结论：虚焊 + 连锡 + 少锡就占 58.1%。其中连锡和少锡都是印刷（钢网、锡膏）问题，说明优先查 SPI 之前的印刷工序（钢网清洁、刮刀压力、脱模参数）比到处找原因更划算。这就是柏拉图的用处：把"我们有 17 种问题"变成"先解决前三种"。

第 2 步：用 SQL 做柏拉图 ​

这里用了窗口函数（Window Function）：SUM(...) OVER (...) 在不合并行的情况下做汇总。SUM(Cnt) OVER () 是全部合计；SUM(Cnt) OVER (ORDER BY Rk ROWS UNBOUNDED PRECEDING) 是从第一行累加到当前行，也就是累计。排序里用 CASE WHEN Code = 'OT-000' THEN 1 ELSE 0 END 保证"其他"固定最后：

sql
;WITH c AS (
    SELECT d.Code, d.Name, SUM(r.Qty) AS Cnt
    FROM DefectRecord r JOIN DefectCode d ON d.Code = r.DefectCode
    WHERE r.LineCode = 'SMT-01'
    GROUP BY d.Code, d.Name),
o AS (
    SELECT *, ROW_NUMBER() OVER (ORDER BY CASE WHEN Code = 'OT-000' THEN 1 ELSE 0 END, Cnt DESC, Code) AS Rk,
           SUM(Cnt) OVER () AS Total
    FROM c)
SELECT Rk, Code, Name, Cnt,
       CAST(100.0 * Cnt / Total AS DECIMAL(5,1)) AS Pct,
       CAST(100.0 * SUM(Cnt) OVER (ORDER BY Rk ROWS UNBOUNDED PRECEDING) / Total AS DECIMAL(5,1)) AS CumPct
FROM o ORDER BY Rk;

第 3 步：用 Python 复算累计占比 ​

把下面的代码保存为 pareto.py，运行 python -X utf8 pareto.py（中文输出需要 UTF-8）：

python
"""柏拉图（Pareto）计算：按数量降序，"其他"固定放最后，输出占比和累计占比。"""
counts = {
    "虚焊": 118, "连锡": 74, "少锡": 52, "偏移": 41, "立碑": 23, "缺件": 19,
    "错件": 8, "极性反": 6, "冷焊": 11, "锡珠": 14, "污染": 12, "划伤": 9,
    "翘曲": 5, "开路": 7, "短路": 3, "功能失效": 4, "其他": 14,
}
OTHER = "其他"

items = sorted((kv for kv in counts.items() if kv[0] != OTHER), key=lambda kv: -kv[1])
if OTHER in counts:
    items.append((OTHER, counts[OTHER]))          # "其他"不参与排序，永远放最后

total = sum(counts.values())
cum = 0
print(f"{'排名':<4}{'名称':<8}{'数量':>5}{'占比%':>8}{'累计%':>8}")
vital = []                                         # 累计占比首次达到 80% 之前（含跨过那一项）的"关键少数"
for rank, (name, n) in enumerate(items, 1):
    before = cum
    cum += n
    print(f"{rank:<4}{name:<8}{n:>5}{100*n/total:>8.1f}{100*cum/total:>8.1f}")
    if before / total < 0.8 and name != OTHER:
        vital.append(name)
print(f"合计 {total}；关键少数（累计占比跨过 80% 为止）：{'、'.join(vital)}")
assert total == 420 and cum == total

    new() { Code = "PR-007", Name = "错件", Category = "工艺", Severity = "Critical", StationScope = "AOI,ICT,FCT" },
    new() { Code = "OT-000", Name = "其他", Category = "工艺", Severity = "Minor",    StationScope = "ALL" },
}).ExecuteCommand();
Console.WriteLine("读回主数据：" + string.Join("、", db.Queryable<DefectCode>().OrderBy(d => d.Id).Select(d => d.Name).ToList()));

// 3) 不良记录：虚焊 6、连锡 3、错件 1、其他 2
var rows = new List<DefectRecord>();
void Add(string code, int n) { for (int i = 0; i < n; i++) rows.Add(new DefectRecord { Sn = $"SN{rows.Count + 1:D5}", LineCode = "SMT-01", StationCode = "AOI", DefectCode = code }); }
Add("PR-001", 6); Add("PR-002", 3); Add("PR-007", 1); Add("OT-000", 2);
db.Insertable(rows).ExecuteCommand();

// 4) 重复 Code 被唯一索引拦住
try { db.Insertable(new DefectCode { Code = "PR-001", Name = "虚焊2", Category = "工艺", Severity = "Major", StationScope = "AOI" }).ExecuteCommand(); }
catch (Exception ex) { Console.WriteLine("重复 Code 被拒绝：" + ex.Message.Split('\n')[0].Substring(0, 40)); }

// 5) Pareto：SQL 分组 + C# 算累计（"其他"固定最后）
var counts = db.Queryable<DefectRecord, DefectCode>((r, d) => r.DefectCode == d.Code)
    .Where((r, d) => r.LineCode == "SMT-01")
    .GroupBy((r, d) => new { d.Code, d.Name })
    .Select((r, d) => new { d.Code, d.Name, Cnt = SqlFunc.AggregateSum(r.Qty) })
    .ToList();
var ordered = counts.Where(c => c.Code != "OT-000").OrderByDescending(c => c.Cnt)
    .Concat(counts.Where(c => c.Code == "OT-000")).ToList();
int total = ordered.Sum(c => c.Cnt), cum = 0;
foreach (var c in ordered)
{
    cum += c.Cnt;
    Console.WriteLine($"{c.Code} {c.Name} {c.Cnt} {100.0 * c.Cnt / total:F1}% 累计 {100.0 * cum / total:F1}%");
}

业务视角与技术视角 ​

业务视角——谁在用：

角色怎么用缺陷代码
AOI / 目检 / 测试员发现不良时从下拉里选代码，必要时填位号
维修员看到代码后维修，再填原因和措施（返修与维修管理）
质量工程师看柏拉图决定先攻哪几个缺陷，发 8D（8D与CAPA）；维护代码表
生产主管看各线、各班的缺陷分布，找培训和管理问题
客户 / 审核员看缺陷统计和趋势是否有改进（见 质量成本与KPI）

技术视角——要点：

  • 主数据表 DefectCode，记录表 DefectRecord 通过 Code 引用，记录里不存名称；
  • 主数据的变更（新增、停用、改严重度）本身要留痕、要审批；
  • 设备（AOI、ICT）上传的缺陷类型要建映射到统一代码，映射不到的要报警，别默认进"其他"；
  • 柏拉图是查询，不是存起来的数据。每次现算，数据量大时按日汇总到一张统计表；
  • 严重度会被抽样（抽样检验AQL）和拦截（不良品拦截与锁定）规则引用，改它之前要想清楚影响面。

练习题与答案 ​

  1. 为什么 DefectRecord 里存 DefectCode 而不存缺陷名称？ 答：名称可能改、可能翻译，存名称会让新旧记录对不上；存代码，改名只改主数据表一行，历史统计不受影响。外键还能保证代码合法。
  2. 同一块板上 U5、U7、C12 三个位置都偏移了，应该记几条不良记录？ 答：3 条（每个位号一条，Qty = 1）。这样才能统计"哪个位号最爱出问题"，进而追到站位和飞达。
  3. 用手算验证：某线共 420 条不良，其中虚焊 118、连锡 74，两者累计占比是多少？ 答：(118 + 74) / 420 = 192 / 420 = 45.7%。
  4. 为什么柏拉图要把"其他"固定放最后？ 答：它是多种不同现象的合计，不代表某一个原因。若按数量排序，一个很大的"其他"会排第一，却无法指导任何行动。
  5. IPC-A-610 里的"制程警示"（Process Indicator）算不算不良？该怎么处理？ 答：不算不良，它是可接受的状态，但提示制程可能在漂移。不拦截板子，但要记录和统计，看趋势，趋势恶化就去调整工艺。
  6. 一个 AOI 报告了设备自定义的缺陷名 Insufficient Solder，系统里没有对应的映射。应该怎么办？ 答：不要默认记成"其他"。应该报警，让质量工程师确认它对应哪个已有代码（这里是 PR-003 少锡），补上映射；若确实是新现象，才新增代码。
  7. （实验）SMT-02 线的"其他"占比 46.7%，你下一步做什么？ 答：先看这 14 条"其他"的备注，把重复多的现象升级成新代码；同时去现场看检验员是不是因为下拉里没有合适的选项，才选"其他"。

小结 ​

  • 缺陷代码主数据让"同一个现象一个名字"，是统计、追溯、改进的基础；它描述的是现象，原因和措施另表。
  • DefectCode 的列：Code（唯一）、Name（nvarchar）、Category（外观 / 电性 / 功能 / 物料 / 工艺）、Severity（Critical / Major / Minor）、StationScope、Active。
  • MES 的不良记录只存代码，外键引用；一个位号一条；停用不删除；含义永不改。
  • IPC-A-610 分三个产品等级，状况分 Acceptable / Process Indicator / Defect（J 版取消 Target，待核对）。
  • 柏拉图 = 排序 + 占比 + 累计占比，"其他"固定放最后；"其他"占比要监控，选"其他"要强制备注。
  • 常见缺陷的成因和检出工位（虚焊、连锡、少锡、偏移、立碑、缺件、错件、极性反、冷焊、锡珠、翘曲、污染、划伤）是工艺改进的入口。
