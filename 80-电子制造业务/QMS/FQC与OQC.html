FQC与OQC

AI 生成 · 待核对制造业务QMSFQCOQC更新于 2026-10-21

⚠ 待核对：①IPC-A-610 的当前版本（Revision J，2024 年 3 月发布）、Class 1/2/3 的含义，来自 ANSI 博客、NextPCB 和 Wevolver 等第三方页面，我没有读到 IPC 官方页面（ipc.org 无法抓取）；各来源对"Target（目标）状态在哪一版取消"的说法互相矛盾，本文不引用，请以 IPC 官方文件为准。②COC（Certificate of Conformance）、COA（Certificate of Analysis）的内容和格式因客户而异，本文是通用写法。③FQC 与 OQC 的分工、放行条件和 COC 编号规则是通用做法，请对照你们的系统。SQL 与输出都是我在本机 SQL Server LocalDB 上实际运行得到的。

本篇是 QMS 系列第 5 篇。读完你应该能：区分 FQC 与 OQC；决定全检还是抽检；理解 IPC-A-610 在外观检验里的作用；设计"引用 MES 测试记录"的 FQC 流程；实现"检验批合格才允许出货放行并生成 COC 编号"，并亲手跑通整个过程。

一句话定义 ​

FQC（Final Quality Control，成品检验，也叫终检）是成品入库前对完成的产品做的最后一次全面检验；OQC（Outgoing Quality Control，出货检验）是发货前按订单对待发货产品做的抽查，两者都通过，才能放行并开具合格证（COC）。

先修知识 ​

  • IQC来料检验：本篇复用 InspectionLot、InspectionItem、InspectionResult 三张共享表和"条件写进 WHERE"的状态流转。
  • 抽样检验AQL：成品抽检仍按 AQL 方案查样本量。
  • IPQC过程检验：知道过程检验和成品检验的分工。
  • 过站与工序流转：知道一块板有 SN，要经过多个测试工位，每次测试都有记录。

它解决什么问题 ​

PCBA（印刷电路板组装件）出厂前，已经过了 SPI、AOI、ICT、FCT 等一连串在线检测，为什么还要 FQC/OQC？

  • 在线检测各管一段：AOI 看焊点外观，ICT 测通断，FCT 测功能，但没有谁对"这块板作为一个成品是否完整"负责：板上有没有漏贴的结构件？标签对不对？包装数量对不对？
  • 漏网之鱼：某批 1250 块板里，有 3 块 FCT 一直没修好，却被仓管当成"已完工"混进了出货箱。没有"出货前再核一次测试记录"的关卡，这 3 块就到客户手里了。
  • 客户要证据：汽车、医疗客户常常要求每批出货随附检验报告和合格证（COC），证明"这一批符合订单要求"。
  • 最后一道经济关卡：出货后发现的问题，成本是退货、索赔、丢订单，比出厂前发现贵得多（见 质量管理基础里的质量成本）。

核心概念 ​

FQC 与 OQC 有什么区别 ​

对比FQC 成品检验OQC 出货检验
时点完工后、入成品库前发货前（按订单备货后）
对象一个生产批/工单的完成品一张出货单（可能由多个工单、多个批组成）
目的确认生产出来的东西合格确认发给这个客户的东西合格且和订单一致
内容外观、尺寸、功能测试结果核查、标识外观抽查、包装、标签、数量、随货文件、COC
很多厂的实际做法两者合并成一道检验FQC 负责检验，OQC 只做放行核对

不同公司叫法和分工不同，有的厂只有 FQC，有的只有 OQC，请对照你们的体系。本文用同一个检验批，InspType 取 FQC 或 OQC，再加一道"出货放行"。

全检还是抽检 ​

情形做法理由
一般产品抽检，按 抽样检验AQL：批量查字母，主要缺陷（Major）AQL 如 0.65，次要缺陷（Minor）AQL 如 2.5经济，且在过程受控时风险可接受
高可靠产品（IPC Class 3：医疗生命支持、航空、军工等）常要求全检（外观和测试）失效后果严重
新产品首批、客户投诉后加严或全检，一段时间后再放宽过程还不稳定
功能测试（FCT）通常是100% 在线测试，FQC 只引用结果，不重测测试已经全检过，重复测试浪费，还可能损伤板
样本大于批量全检AQL 规则：样本量大于等于批量就全检

外观标准：IPC-A-610 ​

电子组装件的外观判据，行业通行的是 IPC-A-610（Acceptability of Electronic Assemblies，电子组装件的可接受性）。要点（来源：ANSI 博客、NextPCB、Wevolver 等第三方页面，待核对）：

  • 当前版本是 Revision J，2024 年 3 月发布；没有 Revision I（跳过字母 I，避免和数字 1 混淆）。
  • 按产品用途分三个等级：
    • Class 1（通用类）：消费类电子，如玩具、一般小家电，对外观要求最宽松；
    • Class 2（专用服务类）：要求持续工作和较长寿命，但不要求不间断服务，如电脑、家用电器、一般工业设备。多数商业和工业电子默认用 Class 2；
    • Class 3（高性能/苛刻环境类）：不允许停机和失效，如医疗生命支持、航空航天、军工，要求最严。
  • 同一种外观现象（如焊料爬升高度、元件偏出焊盘的比例、通孔填充率），Class 越高要求越严。客户在订单里指定 Class，检验时按那个 Class 判。
  • 它和 J-STD-001（焊接的电子电气组件要求）配套：J-STD-001 规定"该怎么做"，IPC-A-610 规定"做出来的样子合不合格"。

版权提醒：IPC-A-610 是付费标准，不要把标准里的图和条文复制进系统或词条；检验标准书里写"按 IPC-A-610 Class 2"，并把你们实际用到的限度样本（实物或照片）作为内部补充。

功能测试结果的"引用"原则 ​

FQC 阶段最重要的原则是：不重复录入，只引用 MES 的测试记录。一块板可能测多次（第一次 FAIL，返修后重测 PASS），所以要看的是最近一次的结果：

  • 最近一次 PASS → 可以进入 FQC 批；
  • 最近一次 FAIL（还没修好）→ 不能进入 FQC 批，应该留在返修或待处理区。

另外，一次通过率 FPY（First Pass Yield，第一次测试就通过的比例）是过程质量指标，要从"第一次测试"算，不是最后一次；两个指标要区分。

放行条件与 COC / COA ​

出货放行不是"检验员点个按钮"，而是一组条件同时满足，常见有：

  1. 对应的 FQC/OQC 检验批已判定且结论为 Accept（或经审批的特采）；
  2. 该批没有未关闭的质量异常（如 IPQC过程检验 里的 Stop 级异常）、没有 Hold；
  3. 出货数量等于检验批里"合格板"数量；
  4. 满足客户特殊要求（如特定标签、随货报告）；
  5. 追溯信息完整：SN、批次、工单、关键物料可查。

放行时生成：

文件全称含义
COCCertificate of Conformance（合格证、符合性证明）供应商声明"本批产品符合订单/规格要求"，可附检验报告和引用的标准（如 IPC-A-610 Class 2）
COACertificate of Analysis（分析证书）附带具体检测数值（如化学成分、实测值）的证明，常见于材料、化工类；电子成品较少，但物料供应商会给你 COA
出货检验报告—检验批的汇总：批量、样本量、各项目 NG 数、结论、检验员、日期

COC 要有唯一编号，并且和出货单、检验批、板的 SN 清单对得上。

业务视角 ​

角色做什么
FQC 检验员领取 FQC 批，抽样检验外观、标识、包装；核对 FCT 记录；录入结果；判定
OQC/出货质检按出货单核对数量、标签、随货文件；做出货抽查；放行
仓库合格品入成品库、按订单备货；放行后才能出库
销售/客服向客户提供 COC 与检验报告
QE处理拒收批（返工、挑选、特采评审）和客户特殊要求

记录：FQC/OQC 检验批、检验结果、测试记录引用、COC、出货单。KPI：FQC 批合格率、出货批合格率、一次通过率、出货后客户退货率（客户 PPM）、放行及时率。见 质量成本与KPI。

技术视角 ​

复用共享三表，InspType 取 FQC/OQC。新增 3 张表（实验里建的）：

表类型说明
TestRecordMES 的测试记录（实验里是简化版）每次测试一行：SN、工单、工位、PASS/FAIL、时间。FQC 只读它，不写它
FqcLotBoard记录FQC 批包含哪些板（SN），用于追溯和出货清单
OqcRelease记录放行记录和 COC 编号；LotId 唯一，一个批只能放行一次

关键 SQL：

  • 取每块板最近一次测试结果：ROW_NUMBER() OVER (PARTITION BY Sn ORDER BY TestedAt DESC, Id DESC)，取 rn = 1；
  • 一次通过率：同样的窗口函数，按 TestedAt 升序取第一次；
  • 放行：INSERT ... SELECT ... WHERE Status = 'Judged' AND Result = 'Accept' AND NOT EXISTS (已放行)，条件写进 WHERE，重复放行得到 0 行；
  • COC 编号：实验里用"已有行数 + 1"生成，简单但在并发下可能重复，真实系统应使用 SEQUENCE 或专用编号表，再靠 UNIQUE 约束兜底。

和别的系统：测试记录来自 MES（见 过站与工序流转）；放行结果通知 WMS 允许出库、通知 ERP 做发货（见 WMS与MES交互）；拒收批进入 不合格品控制NCR。

逐步例子 ​

例：工单 WO-FQC-1 生产 1250 块 PCBA（SN0001–SN1250）。

  1. 功能测试：第 97 的倍数的板（12 块）第一次 FAIL，返修后重测 PASS；SN0333、SN0777、SN1111 三块第一次 FAIL，重测仍 FAIL；其余 1235 块第一次就 PASS；
  2. 统计：总 1250 块；一次通过 1235 块，FPY = 1235 ÷ 1250 = 98.8%；最终 PASS 1247 块，未修好 3 块；
  3. 建 FQC 批：只收最近一次为 PASS 的 1247 块，批量 1247；
  4. 抽样：1247 落在 1201–3200，水平 II → 字母 K，样本量 125；主要缺陷 AQL 0.65 → Ac/Re = 2/3；次要缺陷 AQL 2.5 → 7/8；抽 125 块；
  5. 检验：外观按 IPC-A-610 Class 2：主要缺陷 1 块（第 58 号，SMT-02），次要缺陷 5 块（第 5、21、40、77、101 号，SMT-09）；
  6. 判定：主要 1 ≤ 2，次要 5 ≤ 7，Accept；
  7. 放行：生成 COC-20261021-0001，出货数量 1247；再放行一次被拦住。

IF OBJECT_ID('FqcLotBoard') IS NOT NULL DROP TABLE FqcLotBoard;
IF OBJECT_ID('TestRecord') IS NOT NULL DROP TABLE TestRecord;
DELETE r FROM InspectionResult r JOIN InspectionLot l ON l.Id = r.LotId WHERE l.InspType IN ('FQC','OQC');
DELETE i FROM InspectionItem i JOIN InspectionLot l ON l.Id = i.LotId WHERE l.InspType IN ('FQC','OQC');
DELETE FROM InspectionLot WHERE InspType IN ('FQC','OQC');
ALTER TABLE InspectionResult ENABLE TRIGGER TR_InspectionResult_AppendOnly;

CREATE TABLE TestRecord (                        -- MES 里的功能测试（FCT）记录：一块板可以测多次
    Id       INT IDENTITY(1,1) PRIMARY KEY,
    Sn       VARCHAR(30) NOT NULL,
    WoNo     VARCHAR(30) NOT NULL,
    Station  VARCHAR(10) NOT NULL,
    Result   VARCHAR(4)  NOT NULL CHECK (Result IN ('PASS','FAIL')),
    TestedAt DATETIME2(0) NOT NULL
);
CREATE TABLE FqcLotBoard (                       -- FQC 批里包含哪些板（追溯用）
    LotId INT NOT NULL REFERENCES InspectionLot(Id),
    Sn    VARCHAR(30) NOT NULL,
    PRIMARY KEY (LotId, Sn)
);
CREATE TABLE OqcRelease (                        -- 出货放行 + 合格证（COC）编号
    Id         INT IDENTITY(1,1) PRIMARY KEY,
    LotId      INT NOT NULL UNIQUE REFERENCES InspectionLot(Id),   -- 一个批只能放行一次
    CocNo      VARCHAR(30) NOT NULL UNIQUE,
    CustomerCode VARCHAR(20) NOT NULL,
    ShipQty    INT NOT NULL,
    ReleasedAt DATETIME2(0) NOT NULL
);

-- 1 造数据：WO-FQC-1 做了 1250 块板。第一次 FCT：第 97 的倍数的板 FAIL（共 12 块），返修后重测 PASS；
--   第 333、777、1111 号板第一次 FAIL，重测仍 FAIL（还没修好）
;WITH t AS (SELECT TOP (1250) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b)
INSERT INTO TestRecord(Sn, WoNo, Station, Result, TestedAt)
SELECT 'SN' + RIGHT('0000' + CAST(i AS VARCHAR(4)), 4), 'WO-FQC-1', 'FCT',
       CASE WHEN i % 97 = 0 OR i IN (333,777,1111) THEN 'FAIL' ELSE 'PASS' END, DATEADD(MINUTE, i, '2026-10-21 08:00') FROM t;
;WITH t AS (SELECT TOP (1250) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b)
INSERT INTO TestRecord(Sn, WoNo, Station, Result, TestedAt)
SELECT 'SN' + RIGHT('0000' + CAST(i AS VARCHAR(4)), 4), 'WO-FQC-1', 'FCT',
       CASE WHEN i IN (333,777,1111) THEN 'FAIL' ELSE 'PASS' END, DATEADD(MINUTE, i + 600, '2026-10-21 08:00') FROM t
WHERE i % 97 = 0 OR i IN (333,777,1111);

-- 2 统计：一次通过率，以及"最近一次 FCT 不是 PASS"的板（不能进 FQC 批）
PRINT N'--- 1. FCT 统计 ---';
;WITH latest AS (SELECT Sn, Result, ROW_NUMBER() OVER (PARTITION BY Sn ORDER BY TestedAt DESC, Id DESC) AS rn FROM TestRecord),
first_ AS (SELECT Sn, Result, ROW_NUMBER() OVER (PARTITION BY Sn ORDER BY TestedAt, Id) AS rn FROM TestRecord)
SELECT (SELECT COUNT(DISTINCT Sn) FROM TestRecord)                                 AS 总板数,
       (SELECT COUNT(*) FROM first_ WHERE rn = 1 AND Result = 'PASS')              AS 一次通过,
       CAST(100.0 * (SELECT COUNT(*) FROM first_ WHERE rn = 1 AND Result = 'PASS')
            / (SELECT COUNT(DISTINCT Sn) FROM TestRecord) AS DECIMAL(5,1))         AS 一次通过率,
       (SELECT COUNT(*) FROM latest WHERE rn = 1 AND Result = 'PASS')              AS 最终PASS,
       (SELECT COUNT(*) FROM latest WHERE rn = 1 AND Result <> 'PASS')             AS 未修好;

-- 3 建 FQC 批：只收"最近一次 FCT 为 PASS"的板
INSERT INTO InspectionLot(LotNo, InspType, ItemCode, LotQty, Status)
VALUES ('FQC-20261021-001', 'FQC', 'PCBA-A100', 0, 'Pending');
DECLARE @lot INT = SCOPE_IDENTITY();
;WITH latest AS (SELECT Sn, Result, ROW_NUMBER() OVER (PARTITION BY Sn ORDER BY TestedAt DESC, Id DESC) AS rn FROM TestRecord WHERE WoNo = 'WO-FQC-1')
INSERT INTO FqcLotBoard(LotId, Sn) SELECT @lot, Sn FROM latest WHERE rn = 1 AND Result = 'PASS';
UPDATE InspectionLot SET LotQty = (SELECT COUNT(*) FROM FqcLotBoard WHERE LotId = @lot) WHERE Id = @lot;

-- 4 抽样：批量查字母（水平 II），主要缺陷 AQL 0.65、次要缺陷 AQL 2.5，样本量取较大者
DECLARE @n INT, @acMaj INT, @acMin INT, @letter CHAR(1);
SELECT @letter = c.Letter FROM InspectionLot l JOIN AqlCode c ON l.LotQty BETWEEN c.LotMin AND c.LotMax WHERE l.Id = @lot;
SELECT @acMaj = Ac, @n = SampleSize FROM AqlPlan WHERE Letter = @letter AND Aql = 0.65;
SELECT @acMin = Ac FROM AqlPlan WHERE Letter = @letter AND Aql = 2.5;
UPDATE InspectionLot SET SampleQty = @n, Status = 'Inspecting' WHERE Id = @lot;
PRINT N'--- 2. FQC 批 ---';
SELECT LotNo, LotQty AS 批量, @letter AS 代码字母, SampleQty AS 抽样数, @acMaj AS 主要Ac, @acMin AS 次要Ac, Status FROM InspectionLot WHERE Id = @lot;

-- 5 抽样检外观（IPC-A-610 Class 2 判据）：主要缺陷 1 个，次要缺陷 5 个
INSERT INTO InspectionItem(LotId, ItemName, Spec) VALUES (@lot, N'外观-主要缺陷', N'IPC-A-610 Class 2：无连锡、无缺件、无立碑');
DECLARE @maj INT = SCOPE_IDENTITY();
INSERT INTO InspectionItem(LotId, ItemName, Spec) VALUES (@lot, N'外观-次要缺陷', N'IPC-A-610 Class 2：锡点光泽、助焊剂残留等');
DECLARE @min INT = SCOPE_IDENTITY();
;WITH t AS (SELECT TOP (@n) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS i FROM sys.all_objects a CROSS JOIN sys.all_objects b)
INSERT INTO InspectionResult(LotId, ItemId, SampleNo, Judgement, DefectCode)
SELECT @lot, @maj, i, CASE WHEN i = 58 THEN 'NG' ELSE 'OK' END, CASE WHEN i = 58 THEN 'SMT-02' END FROM t
UNION ALL
SELECT @lot, @min, i, CASE WHEN i IN (5,21,40,77,101) THEN 'NG' ELSE 'OK' END, CASE WHEN i IN (5,21,40,77,101) THEN 'SMT-09' END FROM t;

PRINT N'--- 3. 判定 ---';
SELECT i.ItemName AS 项目, SUM(CASE WHEN r.Judgement = 'NG' THEN 1 ELSE 0 END) AS NG数,
       CASE i.Id WHEN @maj THEN @acMaj ELSE @acMin END AS Ac,
       CASE WHEN SUM(CASE WHEN r.Judgement = 'NG' THEN 1 ELSE 0 END) <= CASE i.Id WHEN @maj THEN @acMaj ELSE @acMin END THEN N'接收' ELSE N'拒收' END AS 结论
FROM InspectionItem i JOIN InspectionResult r ON r.ItemId = i.Id WHERE i.LotId = @lot GROUP BY i.Id, i.ItemName ORDER BY i.Id;

UPDATE InspectionLot SET Status = 'Judged', JudgedAt = '2026-10-21 16:00',
       Result = CASE WHEN EXISTS (SELECT 1 FROM InspectionItem i
                                  WHERE i.LotId = @lot
                                    AND (SELECT COUNT(*) FROM InspectionResult r WHERE r.ItemId = i.Id AND r.Judgement = 'NG')
                                        > CASE i.Id WHEN @maj THEN @acMaj ELSE @acMin END)
                     THEN 'Reject' ELSE 'Accept' END
WHERE Id = @lot AND Status = 'Inspecting';

-- 6 出货放行：只有"已判定且 Accept 的 FQC 批"能放行，并生成 COC 编号；同一批第二次放行被拦住
DECLARE @rel NVARCHAR(MAX) = N'
INSERT INTO OqcRelease(LotId, CocNo, CustomerCode, ShipQty, ReleasedAt)
SELECT l.Id, ''COC-20261021-'' + RIGHT(''0000'' + CAST((SELECT COUNT(*) + 1 FROM OqcRelease) AS VARCHAR(4)), 4), ''CUST-X'', l.LotQty, ''2026-10-21 17:00''
FROM InspectionLot l
WHERE l.Id = @lot AND l.Status = ''Judged'' AND l.Result = ''Accept''
  AND NOT EXISTS (SELECT 1 FROM OqcRelease o WHERE o.LotId = l.Id);';
DECLARE @x1 INT, @x2 INT;
EXEC sp_executesql @rel, N'@lot INT', @lot = @lot;  SET @x1 = @@ROWCOUNT;
EXEC sp_executesql @rel, N'@lot INT', @lot = @lot;  SET @x2 = @@ROWCOUNT;
PRINT N'--- 4. 放行：第一次插入 ' + CAST(@x1 AS NVARCHAR(5)) + N' 行，第二次插入 ' + CAST(@x2 AS NVARCHAR(5)) + N' 行 ---';
SELECT l.LotNo, l.Status, l.Result, o.CocNo, o.ShipQty FROM InspectionLot l LEFT JOIN OqcRelease o ON o.LotId = l.Id WHERE l.Id = @lot;

常见坑与排查 ​

坑事实与办法
FQC 批里混入"最近一次为 FAIL"的板建批时只收最近一次 PASS 的板；放行前再校验一次
把"最终通过率"当 FPYFPY 要用第一次测试；用最终结果会掩盖返修率
FQC 重复录入测试结果只引用 MES 的测试记录，不重复录入，避免两套数据对不上
一个批放行两次，COC 重复OqcRelease.LotId 唯一 + 放行 SQL 的 NOT EXISTS
并发时 COC 编号重复用 SEQUENCE 或编号表，CocNo 加唯一约束
抽样检合格就放行有缺陷的个体抽到的不良品要隔离处理，不因批接收而放行
拒收批直接"改成特采"放行特采要审批和留痕，见 IQC来料检验 中的特采处理
出货数量与检验批数量不一致放行时核对数量：出货数 = 检验批合格数
客户 Class 要求没落到标准书订单里的 IPC Class 要写进检验标准书，由系统带出
把 IPC-A-610 的图片复制进系统标准有版权，写引用关系与自己的限度样本

练习题与答案 ​

  1. FQC 和 OQC 的主要区别是什么？ 答：FQC 面向生产批，确认生产出的成品合格；OQC 面向出货单，确认发给客户的东西合格且与订单一致。很多厂合并成一道检验。
  2. 为什么 FQC 只"引用"FCT 结果，不重新测试？ 答：FCT 已经 100% 在线测试过；重测浪费且可能损伤板，也会产生两套对不上的数据。FQC 要做的是核对：最近一次是不是 PASS。
  3. 一块板第一次 FCT 失败，返修后重测通过。算 FPY 时算通过还是失败？ 答：失败。FPY 看第一次测试；返修后通过的板计入"最终通过"，但不计入一次通过。
  4. 若 FQC 批量是 1200 块，水平 II，主要缺陷 AQL 0.65，样本量和 Ac/Re 是多少？ 答：1200 落在 501–1200 → 字母 J；J 行 AQL 0.65 是箭头 → 用 J 行 1/2，样本量 80，Ac/Re = 1/2（用 aql.py 验证：批量 1200 → J，AQL 0.65 → n=80，Ac/Re = 1/2）。
  5. 实验的放行 SQL 为什么要同时判断 Status = 'Judged' 和 Result = 'Accept'？ 答：只有"已判定且接收"才能放行。仅判断结论可能放行还在检验中的批；仅判断状态可能放行被拒收的批。
  6. IPC-A-610 Class 2 和 Class 3 在检验上有什么实际影响？ 答：Class 越高，同一缺陷的接受限度越严，检验员判 NG 的情况更多；Class 3 的产品往往还要求全检。具体限度以标准为准。

小结 ​

  • FQC 管完成品，OQC 管出货单；两者都过才放行并出 COC。
  • 全检还是抽检由产品等级和客户要求决定；抽检按 抽样检验AQL；功能测试结果只引用 MES 记录。
  • 外观按 IPC-A-610 的 Class 判；标准有版权，只引用不复制。
  • 放行是一组条件的 AND：检验批 Accept、无异常 Hold、数量一致、客户要求满足；放行和 COC 编号要幂等、唯一。
  • 一次通过率看第一次测试，不是最终结果。
