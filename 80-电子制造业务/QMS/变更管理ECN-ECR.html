变更管理ECN-ECR

AI 生成 · 待核对制造业务QMS更新于 2026-10-21

⚠ 待核对：ISO 9001:2015 第 8.5.6 条（变更控制）的大意来自 IAQG 发布的指南文档的转述；IATF 16949 第 8.5.6.1 条（变更要评估影响）只从二手资料确认了"变更的影响要评估，变更来源包括组织、客户和供应商"，两者都没有核对标准原文。"ECR / ECN / ECO"三个词在不同公司含义不同，本篇采用的是常见分法，你们公司的叫法、会签部门、分级规则请对照你们的系统和程序文件核实。SQL 实验都在本机 SQL Server LocalDB 临时库 Lab_qms2 上实际运行过，Python 复算过物料数字。

本篇是 QMS 系列的一篇。读完你应该能：分清 ECR、ECN、ECO；说出一次变更从申请到关闭的流程和会签部门；理解 4M 变更为什么也要管；会用"切换点"（SN / 日期 / 批次）控制新旧版本的生效，并算出变更对 BOM、在制品和库存的影响。

一句话定义 ​

ECR（Engineering Change Request，工程变更申请）是"我想改某个东西"的申请单，要经过各部门评审；ECN（Engineering Change Notice，工程变更通知）是 ECR 批准后发布的"从哪一块板、哪一天、哪一批开始，按新的来"的执行通知。管好变更，就是保证"改了的东西全公司同时知道，且新旧版本不会混用"。

先修知识 ​

  • BOM与物料清单：变更最常改的就是 BOM，要知道 BOM 版本（Rev）和"工单绑定 BOM 版本"。
  • PLM 与 工程变更流程：设计端的变更流程在 PLM 里；本篇讲的是质量与制造端如何控制变更的影响。
  • 工单管理：已经下发的工单怎么处理新版本。
  • 不合格品控制NCR、8D与CAPA：很多变更是 CAPA 的措施落地；变更没管好又会造成新的 NCR。

它解决什么问题 ​

工程师为了解决物料停产，把 A100 的 C12、C13 电容从 16V 改成 25V。他在邮件里通知了采购和工艺，没通知仓库，也没改 BOM。结果：仓库继续发 16V 的料；产线上料防错按旧 BOM 通过；新到的 25V 料没有人认。三天后，客户审核时发现，同一批出货的板子，有的用 16V 有的用 25V，而出货文件上写的是 16V。

没有受控的变更会带来：

  • 新旧混用：板子的实际物料和 BOM、追溯记录对不上，客诉时无法定位；
  • 该通知的人没通知：仓库、产线、采购、客户各自按旧信息行动；
  • 没人评估风险：改一颗电容，会不会影响可靠性？要不要重新做试验？客户要不要批准？
  • 旧库存变呆滞：新料到了，旧料没人管，积压成本；
  • 改了不验证：改完没有首件，问题批量流出。

ISO 9001 第 8.5.6 条要求组织对生产和服务提供的变更进行评审和控制，以确保持续符合要求（IAQG 指南转述）；汽车行业 IATF 16949 第 8.5.6.1 条进一步要求评估变更的影响，不论变更来自组织自己、客户还是供应商。

核心概念 ​

ECR、ECN、ECO ​

名称常见含义时点
ECR 工程变更申请提出变更的需求、原因、范围，经各部门评审变更之前
ECN 工程变更通知ECR 批准后发布，写明新版本、切换点、旧库存如何处理，通知所有相关部门执行批准之后
ECO 工程变更单 / 订单有的公司把 ECR + ECN 合成一张单；有的公司指代 ERP / PLM 里的执行单视公司而定

本篇用最常见的两段式：ECR 管"该不该改"，ECN 管"怎么改、从哪切"。

变更的类型：4M 与设计变更 ​

类型英文电子厂举例为什么要管
人Man关键工位（如 X-ray 判读、返修）人员换岗；新员工独立上岗技能影响质量，需要资格认定
机Machine换贴片机、新增回流炉、设备大修、程序修改设备条件变了，工艺能力要重新验证
料Material更换供应商、替代料、物料规格变更电气性能、可靠性、焊接性可能受影响
法Method修改回流焊炉温曲线、擦网频率、作业指导书、检验标准方法变了，结果可能变
环（可选）Environment车间搬迁、温湿度控制变化影响静电、受潮、印刷
设计Design改 PCB、改电路、改 BOM最常见的 ECN 来源，影响最大

为什么"人机料法"也要走变更？ 因为它们和设计一样，会改变产品质量。汽车行业常叫"4M 变更"，客户通常要求：这四类变更发生时，要事先通知并获得批准，批准后要做首件、试生产验证。

变更的分级（通用做法） ​

不是所有变更都要最高规格评审。常见分三级（具体划分请按你们的程序文件和客户要求）：

级别例子评审
小变更文字错误、丝印微调、不影响功能的图纸注释工程 + 品质
一般变更同规格替代料、工艺参数微调工程、品质、生产、采购会签
重大变更改变功能 / 可靠性相关的设计、关键物料、产地、关键工艺会签 + 管理层，通常还需要客户书面批准，可能要重新做可靠性试验或重新提交样品

切换点（Effectivity）：从哪块开始用新版本 ​

ECN 的灵魂是切换点——它决定新旧版本的分界。常见四种：

类型说法适用优点缺点
按序列号 SN序号大于等于 A100-0299 的用 Rev B单板可追溯的产品精确到每一块，混用风险最小要求 SN 在生产早期就生成，且上料防错能按 SN 取 BOM
按日期工单下发日大于等于 10-25 的用 Rev B简单场景容易理解同一天内的在制品容易混；换班时间点要明确
按批次 / 工单从 WO-1021-03 起用 Rev B以工单为单位生产与工单绑定版本的做法一致工单内不能混用，已下发的工单要决定是否改
用完为止 Run-out旧库存用完再切新的变更成本高、旧料多、风险小的变更不产生呆滞混用期长，要两版本并存管理，追溯复杂

旧库存怎么处理（ECN 里必须写）：

  • RunOut 用完为止（只在旧版本仍有订单需求时才合理）；
  • Scrap 报废；
  • Return 退给供应商；
  • Rework 返工（把在制品上的旧料换掉）。

变更对 BOM、路线、在制品的影响 ​

对象变更时要问
BOM新建一个 Rev，不要改旧 Rev；旧 Rev 保留，已出货的产品还要靠它追溯
工艺路线 / 程序贴片程序、炉温曲线、测试程序是否要同步改；见 工艺路线与工序、工艺参数与炉温曲线管理
钢网、治具是否需要重做
在制品切换点前已经开始的、切换点后但已经贴了旧料的，怎么处理
库存新料够不够、旧料还剩多少
已下发的工单是改工单绑定的版本，还是让这张工单按旧版走完
作业指导书、检验标准同步改版并培训
客户要不要通知、是否需要批准

业务视角 ​

流程 ​

  1. ECR 提出：工程师（或品质、生产、采购）写明变更内容、原因、影响范围、风险评估。
  2. 会签评审：工程、品质、生产、采购四方（常见）逐一确认。任何一方否决，ECR 就被否决；只有全部同意才通过。重大变更还要管理层和客户批准。
  3. ECN 发布：批准后发布，写明新版 Rev、切换点、旧库存处理方式、受影响文件清单。
  4. 实施：BOM 建新版；采购下新料订单；程序、文件、钢网、治具到位；仓库设置新旧料标识；产线培训。
  5. 验证：切换点后的首件检验（见 首件检验与换线）；必要时试生产，小批量验证后再放量。
  6. 关闭：旧库存已处理完、文件已更新、验证通过，ECN 关闭。

时间线示意：下图是 ECN-26-031 的在制品快照。切换点 A100-0299：SN 小于它的继续用 Rev A；大于等于它的用 Rev B。但是在 ECN 实际生效时，SN 0299、0300、0301 已经贴了旧电容，它们是变更的"漏网"在制品，要决定返工、让步还是报废。

单据与会签 ​

  • ECR 单：编号、标题、类别（人机料法 / 设计）、原因、申请人、状态；
  • 会签记录：每个部门同意 / 否决 / 待定；
  • ECN 单：关联 ECR、产品、旧版、新版、切换点类型与值、旧库存处理、是否通过首件、旧库存是否处理完；
  • 文件清单：BOM、程序、SOP、检验标准等的新版本号。

KPI ​

指标含义
ECR 平均评审周期从提交到批准 / 否决
ECN 实施周期发布到关闭
变更后 30 天不良率变更是否引入新问题；对比变更前
变更造成的呆滞 / 报废金额评审时就应估算
无 ECN 的变更数内审的重点：发现"悄悄改了"的情况

技术视角 ​

表设计 ​

表作用
Ecr变更申请：EcrNo 唯一、Category（Man / Machine / Material / Method / Design）、Status（Draft / Reviewing / Approved / Rejected）
EcrReview会签明细：(EcrNo, Dept) 主键，Decision（Pending / Approve / Reject）。四个部门各一行
Ecn变更通知：EcnNo 唯一、EcrNo、ProductCode、FromRev、ToRev、EffectType（SN / Date / Lot）、EffectValue、OldStockAction、FirstArticlePass、OldStockHandled、Status（Issued / Implementing / Verified / Closed）
BomHeader、BomLine简化的 BOM：每个 Rev 一组行，(ProductCode, Rev, RefDes) 为主键

⚠ 请对照你们的系统：MES 的 BOM 表（见 BOM与物料清单）是否支持"一个产品同时存在两个生效版本"。那里为了保证简单，设计了"同一产品只能有一个生效 BOM"的唯一索引。按 SN 切换时，同一时刻 Rev A（给小序号）和 Rev B（给大序号）都有效，这个索引会和 SN 切换冲突。常见解法：BOM 版本不靠"状态 = Active"来选，而是靠 ECN 的生效规则（本篇实验）或者有效区间（生效起止 SN / 日期）来选；工单下发时才确定绑定哪个版本。

会签：全部同意才通过，一条 UPDATE 搞定 ​

sql
UPDATE e SET Status = CASE WHEN EXISTS (SELECT 1 FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Reject')
                           THEN 'Rejected' ELSE 'Approved' END
FROM dbo.Ecr e
WHERE e.EcrNo = @EcrNo AND e.Status = 'Reviewing'
  AND ( EXISTS (SELECT 1 FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Reject')
        OR (SELECT COUNT(*) FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Approve') = 4 );

有人否决 → 立即 Rejected；四个部门全部同意 → Approved；否则条件不满足，更新 0 行，保持评审中。和 工单管理 一样，判断和修改在一条语句里，不会出现"检查时三个同意、更新时有人改成否决"的竞态。

版本解析：这块板该用哪个 Rev ​

sql
CREATE FUNCTION dbo.fn_RevOfSn (@Product NVARCHAR(30), @Sn NVARCHAR(30)) RETURNS NVARCHAR(5) AS BEGIN
    RETURN COALESCE(
        (SELECT TOP 1 ToRev FROM dbo.Ecn
         WHERE ProductCode = @Product AND EffectType = 'SN' AND Status IN ('Implementing','Verified','Closed') AND @Sn >= EffectValue
         ORDER BY EffectValue DESC),
        (SELECT BaseRev FROM dbo.BomHeader WHERE ProductCode = @Product));
END;

规则：只看已进入实施的 ECN（Issued 状态不算，因为新版 BOM 可能还没建好）；有多条 ECN 时，取切换点最大的那条；没有 ECN 命中就用基础版本。注意 SN 是字符串比较，前提是 SN 格式固定宽度、前缀相同（如 A100-0299），否则 A100-999 会大于 A100-1000。这就是 条码与板码规则 里强调"定长、补零"的原因之一。

状态机和前置条件 ​

Issued → Implementing → Verified → Closed，每一步的条件写进 WHERE：

流转前置条件
Issued → Implementing新版 BOM（ToRev）已经建好
Implementing → Verified首件通过（FirstArticlePass = 1）
Verified → Closed旧库存已处理（OldStockHandled = 1）

与其他系统的衔接 ​

  • PLM → ERP → MES：设计变更在 PLM 里产生，经 ERP 同步到 MES（见 BOM在PLM与ERP间的流转）。QMS 的 ECN 常是"跟踪执行和验证"的一层；⚠ 你们公司的 ECN 在 PLM 还是 QMS 里发起，请核实。
  • SMT 上料防错：切换点附近，防错系统要能根据板的 SN → Rev → BOM → 允许的物料来校验，旧料上到新板、新料上到旧板都要拦截（见 SMT上料防错与站位表）。
  • WMS：新旧料用不同料号或明确标识；旧料按 OldStockAction 处理（见 退料与呆滞料）。
  • 追溯：每块板记录它实际用的 BOM Rev 和物料批次（见 产品追溯），客诉时才查得清。

逐步例子：ECR-26-018 ​

背景：A100 的 C12、C13（0805，10uF）16V 型号原厂停产，要改 25V 同封装。

  1. 申请：张伟提交 ECR-26-018（类别 Material），系统生成四个部门的会签行。同时李娜提了 ECR-26-019（想把回流焊峰值温度从 245 提到 255℃以改善虚焊，类别 Method，没有试验数据）。
  2. 会签：ECR-26-018 工程、品质、生产同意，采购还没签 → 不能通过；采购同意 → Approved。ECR-26-019 品质否决（没数据支持，可能损伤元件）→ Rejected。
  3. 发布 ECN：为 ECR-26-019 发 ECN 被拒（ECR 未批准）。为 ECR-26-018 发 ECN-26-031：Rev A → Rev B，切换点 SN = A100-0299，旧库存 RunOut。
  4. 实施：新版 BOM（Rev B，C12,C13 用 CAP-10U-0805-25V）还没建好时尝试 Implementing 被拒；建好后成功。
  5. 在制品和物料影响（见实验）：
    • 已贴旧料、但序号在切换点之后的板：0299、0300、0301，共 3 块，需要处置；
    • 旧料：库存 40 颗，只有 0298 还要用（2 颗）；用完剩 40 - 2 = 38 颗，RunOut 没有可用的地方，应改为退货或报废——这就是评审时必须估算呆滞的原因；
    • 新料：新板 5 块 × 2 = 10 颗，返工 3 块 × 2 = 6 颗，共需 16 颗；库存只有 8 颗，缺口 8 颗，要让采购加急。
  6. 验证与关闭：首件通过 → Verified；旧库存处理完 → Closed。

CREATE TABLE dbo.BomHeader (ProductCode NVARCHAR(30) PRIMARY KEY, BaseRev NVARCHAR(5) NOT NULL);   -- 没有任何 ECN 生效时用的版本
CREATE TABLE dbo.BomLine (ProductCode NVARCHAR(30) NOT NULL, Rev NVARCHAR(5) NOT NULL, RefDes NVARCHAR(30) NOT NULL,
    ItemCode NVARCHAR(40) NOT NULL, Qty INT NOT NULL, PRIMARY KEY (ProductCode, Rev, RefDes));
CREATE TABLE dbo.Ecr (                          -- ECR：变更申请
    Id INT IDENTITY PRIMARY KEY, EcrNo NVARCHAR(30) NOT NULL UNIQUE, Title NVARCHAR(100) NOT NULL,
    Category NVARCHAR(10) NOT NULL CHECK (Category IN ('Man','Machine','Material','Method','Design')),   -- 4M + 设计
    Reason NVARCHAR(200) NULL, Requester NVARCHAR(30) NOT NULL,

    EcrNo NVARCHAR(30) NOT NULL, Dept NVARCHAR(10) NOT NULL,

    PRIMARY KEY (EcrNo, Dept));
CREATE TABLE dbo.Ecn (                          -- ECN：变更通知（批准后发布，规定怎么切、从哪切）
    Id INT IDENTITY PRIMARY KEY, EcnNo NVARCHAR(30) NOT NULL UNIQUE, EcrNo NVARCHAR(30) NOT NULL,
    ProductCode NVARCHAR(30) NOT NULL, FromRev NVARCHAR(5) NOT NULL, ToRev NVARCHAR(5) NOT NULL,
    EffectType NVARCHAR(5) NOT NULL CHECK (EffectType IN ('SN','Date','Lot')),   -- 切换点类型
    EffectValue NVARCHAR(30) NOT NULL,                                          -- 切换点的值：SN / 日期 / 批号

    Station NVARCHAR(10) NOT NULL CHECK (Station IN ('Printing','Mounting','Reflow','AOI','FCT','Done')));

GO
-- ECR 提交：Draft -> Reviewing，同时为四个部门各生成一条待会签记录
CREATE PROC dbo.usp_EcrSubmit @EcrNo NVARCHAR(30), @Msg NVARCHAR(100) OUTPUT AS BEGIN
    SET NOCOUNT ON; BEGIN TRAN;
    UPDATE dbo.Ecr SET Status = 'Reviewing' WHERE EcrNo = @EcrNo AND Status = 'Draft';
    IF @@ROWCOUNT = 1 BEGIN
        INSERT dbo.EcrReview (EcrNo, Dept) SELECT @EcrNo, d FROM (VALUES ('ENG'),('QA'),('PROD'),('PUR')) t(d);
        COMMIT; SET @Msg = N'成功';
    END ELSE BEGIN ROLLBACK; SET @Msg = N'拒绝：只有 Draft 状态能提交'; END
END;
GO
-- ECR 定案：有人 Reject 就 Rejected；四个部门全部 Approve 才 Approved；其余情况保持 Reviewing
CREATE PROC dbo.usp_EcrFinalize @EcrNo NVARCHAR(30), @Msg NVARCHAR(100) OUTPUT AS BEGIN
    SET NOCOUNT ON;
    UPDATE e SET Status = CASE WHEN EXISTS (SELECT 1 FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Reject')
                               THEN 'Rejected' ELSE 'Approved' END
    FROM dbo.Ecr e
    WHERE e.EcrNo = @EcrNo AND e.Status = 'Reviewing'
      AND ( EXISTS (SELECT 1 FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Reject')
            OR (SELECT COUNT(*) FROM dbo.EcrReview r WHERE r.EcrNo = e.EcrNo AND r.Decision = 'Approve') = 4 );
    SET @Msg = CASE WHEN @@ROWCOUNT = 1 THEN N'已定案：' + (SELECT Status FROM dbo.Ecr WHERE EcrNo = @EcrNo)
                    ELSE N'未定案：还有部门没会签完（或状态不对）' END;
END;
GO
-- 发布 ECN：只有 Approved 的 ECR 才能发布
CREATE PROC dbo.usp_EcnIssue @EcnNo NVARCHAR(30), @EcrNo NVARCHAR(30), @Product NVARCHAR(30), @From NVARCHAR(5), @To NVARCHAR(5),
    @EffType NVARCHAR(5), @EffVal NVARCHAR(30), @OldStock NVARCHAR(10), @Msg NVARCHAR(100) OUTPUT AS BEGIN
    SET NOCOUNT ON;
    INSERT dbo.Ecn (EcnNo, EcrNo, ProductCode, FromRev, ToRev, EffectType, EffectValue, OldStockAction)
    SELECT @EcnNo, @EcrNo, @Product, @From, @To, @EffType, @EffVal, @OldStock
    WHERE EXISTS (SELECT 1 FROM dbo.Ecr WHERE EcrNo = @EcrNo AND Status = 'Approved');
    SET @Msg = CASE WHEN @@ROWCOUNT = 1 THEN N'成功' ELSE N'拒绝：ECR 未批准' END;
END;
GO
-- ECN 流转：Issued -> Implementing（新版 BOM 已就绪）-> Verified（首件通过）-> Closed（旧库存已处理）
CREATE PROC dbo.usp_EcnMove @EcnNo NVARCHAR(30), @To NVARCHAR(15), @Msg NVARCHAR(100) OUTPUT AS BEGIN
    SET NOCOUNT ON;
    UPDATE e SET Status = @To
    FROM dbo.Ecn e
    JOIN (VALUES ('Issued','Implementing'), ('Implementing','Verified'), ('Verified','Closed')) t(f, t2) ON t.f = e.Status AND t.t2 = @To
    WHERE e.EcnNo = @EcnNo
      AND (@To <> 'Implementing' OR EXISTS (SELECT 1 FROM dbo.BomLine b WHERE b.ProductCode = e.ProductCode AND b.Rev = e.ToRev))
      AND (@To <> 'Verified' OR e.FirstArticlePass = 1)
      AND (@To <> 'Closed'   OR e.OldStockHandled = 1);
    SET @Msg = CASE WHEN @@ROWCOUNT = 1 THEN N'成功' ELSE N'拒绝：流转不合法，或前置条件（新版 BOM / 首件 / 旧库存处理）没满足' END;
END;
GO
-- 一块板该用哪个版本的 BOM：看 Implementing 及之后的、SN 类型的 ECN，SN 大于等于切换点就用新版
CREATE FUNCTION dbo.fn_RevOfSn (@Product NVARCHAR(30), @Sn NVARCHAR(30)) RETURNS NVARCHAR(5) AS BEGIN
    RETURN COALESCE(
        (SELECT TOP 1 ToRev FROM dbo.Ecn
         WHERE ProductCode = @Product AND EffectType = 'SN' AND Status IN ('Implementing','Verified','Closed') AND @Sn >= EffectValue
         ORDER BY EffectValue DESC),
        (SELECT BaseRev FROM dbo.BomHeader WHERE ProductCode = @Product));
END;
GO

练习题与答案 ​

  1. ECR 和 ECN 的区别是什么？ 答：ECR 是变更申请，管"该不该改"，要经过会签评审；ECN 是 ECR 批准后发布的执行通知，管"怎么改、从哪块板（日期、批次）开始改、旧库存怎么办"。
  2. 为什么要在 ECR 阶段让采购、品质、生产、工程都会签？ 答：变更的影响横跨多个部门：采购要换料和处理库存，品质要评估风险和验证，生产要调整工艺和培训，工程负责设计。任何一方不知情，都可能造成新旧混用或不能实施。
  3. 实验里 A100-0298 的 SN 比切换点小，为什么它还需要旧料？ 答：它的 SN 小于 A100-0299，按规则用 Rev A；而且它还在印刷、还没贴件，所以还需要 2 颗旧电容。
  4. 为什么 A100-0299、0300、0301 是"漏网"的板？ 答：它们的 SN 在切换点之后，应当使用 Rev B（25V），但在 ECN 进入实施前已经贴上了 16V 电容。需要返工换件、让步接收（需评估并获批）或报废。
  5. 旧料 40 颗只用掉 2 颗，RunOut（用完为止）还合理吗？应怎么办？ 答：不合理，剩下 38 颗无处可用，会变呆滞。应该改成退货（如果供应商接受）或报废，并把金额算进变更成本，见 退料与呆滞料。
  6. Lot 类型的 ECN，fn_RevOfSn 要怎么改？ 答：要换成按"批号 / 工单号"判断：函数参数改成工单号，比较的是工单号大于等于切换工单（工单号须有可比较的顺序），或在 Ecn 里存"从哪个工单起"，在工单下发时一次性绑定 Rev，之后不再按单板判断。
  7. 为什么说"工单下发时绑定 BOM 版本"和"按 SN 切换"会有矛盾？怎么协调？ 答：绑定版本意味着整张工单用同一个 Rev，而按 SN 切换可能在一张工单中间换版本。协调办法：ECN 生效时对跨切换点的工单拆单或关闭重发；或者让工单不绑定固定 Rev，而是每块板按 SN 动态取版本。前者简单，后者灵活但实现复杂。

小结 ​

  • ECR 管"该不该改"，ECN 管"怎么改、从哪切"；人机料法和设计的变更都要受控。
  • 切换点必须可比较（SN / 日期 / 批次）；ECN 要写清旧库存的处理方式。
  • 变更的影响要评估到：BOM、程序、文件、在制品、库存、已下发工单、客户。
  • 会签"全员同意才通过，一人否决即否决"，用一条带条件的 UPDATE 实现；ECN 的前置条件（新版 BOM、首件、旧库存处理）写进状态机。
  • 技术难点：同一产品同时有两个生效版本，要靠 ECN 规则或有效区间来选，而不是"唯一生效"索引。
