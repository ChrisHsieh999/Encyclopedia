内部审核与体系文件

AI 生成 · 待核对制造业务QMS体系文件控制更新于 2026-10-21

⚠ 待核对：①ISO 9001 是收费标准，我没有读到原文。第 7.5（成文信息）、9.2（内部审核）、9.3（管理评审）这几个条款号和要点，来自几个第三方整理页对 ISO 9001:2015 的介绍（网址见 sources）。"2015 版不再强制要求质量手册和形成文件的程序"以及"认证周期是三年（初次审核 + 每年监督审核 + 三年再认证）"来自我的模型知识，未联网逐条核实，请对照你们的认证机构和正版标准确认。②四级文件的命名（QP/WI 编号）、状态名、审批流程是通用做法，你们公司的文控制度和自研系统可能不同，请对照核实。③SQL 与 C# 代码和输出是我在本机 SQL Server LocalDB（临时库 Lab_qms3）上实际运行得到的。

本篇是 QMS 系列的一篇。读完你应该能：说清四级文件体系每一级放什么；设计一套"版本 + 状态机"的受控文件表，并用数据库保证同一个文件只有一个有效版；知道内审、不符合项、管理评审、外部认证审核是怎么串起来的。

一句话定义 ​

体系文件是把"我们这家厂怎么保证质量"写成的一套文件（手册、程序、作业指导书、记录表单）；文件控制（文控，Document Control）保证现场用的永远是有效的最新版，旧版被收回或作废；内部审核（内审）是厂里自己定期检查"做的和写的是否一致"，找出的偏差叫不符合项；管理评审是高层定期回顾整个体系是否有效。

先修知识 ​

  • 质量管理基础：知道质量体系（QMS）是什么、ISO 9001 大致要求什么。
  • QMS：知道本库 QMS 系列的整体结构。
  • 会读简单的 SQL；实验里会用到事务和过滤唯一索引，会现场讲解。

它解决什么问题 ​

一个常见的现场故事。SMT 线上贴着一份回流焊炉温测试的作业指导书，上面写"炉温测试频率：每班一次"。但一个月前工艺部改了规定：每 4 小时一次，新版 SOP 已经在文件夹里发布了——线上贴的还是旧版。结果一整个月内，这条线的炉温测试都是每班一次，客户来审核时翻出记录对照新规，直接开出不符合项。

没有文件控制会发生：

  1. 现场用了作废版：旧版没收回，新旧版同时存在，谁都不知道哪个对。
  2. 改了没人知道：新版发布了但没通知到岗位，没人培训，没人签收。
  3. 改动没有来历：这一版为什么改、谁批的、改了哪几处，说不清。
  4. 审核时拿不出证据：客户或认证机构问"这个流程在哪里规定的"，翻不出来。
  5. 多个有效版：系统里同一个文件两个版本都显示"有效"，每个人打开的都不一样。

内审则解决另一类问题：写的和做的对不上，却没人发现——文件很漂亮，现场根本没人按它做。外审（客户或认证机构来）才发现就晚了。内审是厂里给自己做的"体检"。

核心概念 ​

四级文件体系 ​

很多工厂把体系文件分成四层，越往下越具体（通用做法，叫法略有不同）：

级别名称回答什么例子
一级质量手册（Quality Manual）我们公司的质量方针、体系范围、整体架构《质量手册》：质量方针、组织架构、各程序的清单
二级程序文件（Procedure）某项管理活动由谁、按什么流程、做什么QP-07-001 不合格品控制程序、QP-05-002 文件控制程序、内审程序
三级作业指导书（SOP / Work Instruction，WI）在某个岗位上，一步一步具体怎么操作WI-SMT-005 回流焊炉温测试作业指导书、钢网清洗 SOP
四级记录 / 表单（Record / Form）做完以后留下的证据，以及用来填写的空白表炉温测试记录表、首件检验记录、IQC 检验报告、校准记录

一条经验规则：上级文件管"做什么、谁负责"，下级文件管"怎么做"；程序文件引用作业指导书，作业指导书要求填写某个记录表单。一次内审，常常是沿着这条线从上往下查："程序里规定了 X → 现场的 SOP 有没有写 → 记录表单有没有填"。

ISO 9001:2015 把"文件"和"记录"统一称为成文信息（Documented Information）。据第三方对标准条款 4.4.2 的介绍，其中区分了"保持"（maintain，指文件，要保持更新）和"保留"（retain，指记录，要留作证据）。2015 版不再强制要求有质量手册，但很多工厂（尤其客户要求较高、或者要做 IATF 16949 的汽车行业）仍保留四级结构，因为它清楚、好培训。这些说法请按你们的认证机构和正版标准核实。

文件 vs 记录，是文控里最重要的区分：

文件（手册、程序、SOP、空白表单）记录（填好的表单、报告）
性质规定"该怎么做"证明"已经做了"
会不会改会，有版本，要换新版不能改，写好后只能追加更正（并留痕）
控制重点版本、发布、回收、作废保存期限、可检索、防篡改
例子WI-SMT-005 的 A1 版2026-10-21 的炉温测试记录

文件受控：版本、发布、回收、失效 ​

受控的意思是：文件有唯一编号、有版本、有批准、有分发范围、有收回机制。

环节做什么
编号文件号唯一且有规律，如 QP-07-001（程序文件，第 7 条款，第 1 份）、WI-SMT-005（SMT 的第 5 份 SOP）
版本每次修订换一个版本号（A0、A1、A2 或 1.0、1.1）；修订要写变更说明（改了什么、为什么改）
审批起草 → 审核（相关部门会签）→ 批准。不是起草人自己批
发布批准后设生效日期；通知到相关岗位并培训、签收。生效前旧版继续有效
分发记录发给了谁（部门 / 岗位）几份。电子版则控制在系统里可查阅
回收新版生效，旧版纸质件要收回销毁（或盖"作废"章）；确需保留的旧版另加"作废保存"标识
失效文件不再需要时（流程取消、产品停产）作废，并保留历史供追溯
外来文件客户图纸、国标、供应商的规格书也要受控（登记、识别版本、有变更时更新）

现场判断标准只有一个：任何人站在任何岗位，拿到的都必须是当前有效版。所以越来越多的工厂把 SOP 放进系统，工位屏幕上直接打开系统里的有效版，而不是贴纸质件——这样"回收"就变成了"系统里只显示有效版"。

文件状态机 ​

文件版本在生命周期里，会经过这些状态。一个版本任一时刻只有一个状态，只能沿着允许的方向走：

规则：

  • 只有 Approved 的版本才能变成 Effective；不允许草稿直接生效（跳过审批）。
  • 一个文件号同一时刻最多一个 Effective。新版生效的同一个动作里，旧版自动变 Obsolete。
  • Obsolete 的版本保留，不删，供追溯（"2026 年 3 月当时用的是哪一版"）。
  • 想改一个已生效的文件，不是改它，而是新建一个新版本，走完流程再替换。

内部审核（内审） ​

内审是组织自己对自己的体系做的审核。据第三方对 ISO 9001:2015 条款 9.2 的介绍：要在策划好的时间间隔做；要覆盖标准的全部要求；也有来源建议按"过程"而不是按条款逐条去审。

阶段做什么
① 年度审核计划一年里每个部门 / 过程在什么时候被审一次；风险高、问题多的多审几次
② 审核方案与检查表针对被审部门，列出要查什么：依据（标准条款、程序文件）、要看的记录、要问的问题
③ 首次会议审核组告知范围、方法、时间安排
④ 现场审核收集客观证据：看文件、查记录、问人（面谈）、看现场操作。发现偏差时记录证据
⑤ 末次会议宣布审核发现，被审核方确认
⑥ 审核报告汇总发现、结论、改进机会，发给管理层
⑦ 整改与跟踪被审部门对不符合项分析原因，采取纠正和纠正措施；审核员验证有效后关闭

两条重要原则（通用做法）：

  • 独立性：审核员不审自己的工作，避免"自己批改自己的作业"；
  • 基于证据：每个发现都必须写出"看到了什么、在哪里看到的"，不能凭印象。

不符合项（Nonconformity，NC） ​

审核中发现"没满足要求"，就是一个不符合项。常见分级（各公司定义不同）：

类别含义例子
严重不符合（Major）体系整体失效，或某要求完全没有执行，或会导致交付不合格品整条线没有首件检验的记录；校准超期的量具仍在测量放行产品
一般不符合（Minor）个别偶发的、不影响体系整体有效的偏差一份 SOP 现场版本比有效版落后一版
观察项 / 改进机会（OFI）不算不符合，但有风险或可以做得更好记录表的格式不统一

一条好的不符合项描述有三个要素：要求（依据）、事实（看到什么）、证据（编号、位置）。

例：依据：QP-05-002 文件控制程序 要求现场使用的文件必须是有效版。事实：SMT-01 线回流焊工位使用的 WI-SMT-005 为 A0 版，系统中有效版为 A1。证据：2026-10-18 现场检查，工位文件夹中 A0 版纸质件，无作废标识。

注意区分两个"不合格"：本篇的不符合项说的是体系层面（做的和要求不一致）；产品不合格叫不合格品，走 不合格品控制NCR。整改要深挖原因的，走 8D与CAPA。

管理评审 ​

管理评审（Management Review）是最高管理者定期回顾质量体系是否持续适宜、充分、有效。据第三方对 ISO 9001 条款 9.3 的介绍，高层在策划的时间间隔评审，并保留评审结果的成文信息；资料称它与内审、校准一样是外部审核中容易被开出问题的地方。

内容
输入上次评审的跟踪情况、内外部变化、客户满意度与反馈、质量目标达成情况（直通率、PPM、客诉，见 质量成本与KPI）、过程绩效、不合格与纠正措施、监视与测量结果（含内审结果）、供应商表现、资源是否足够
输出改进机会的决定、体系变更的需要、资源需求；每项决定要有责任人和期限
频率标准要求"策划的时间间隔"，实际多为一年一次或半年一次

管理评审的本质是：让数据说话，让资源到位。它不是年底开个会写份纪要，而是看 KPI 趋势后做出决策（比如"批准买一台 SPI""增加两名品质工程师"）。

外审与认证准备 ​

外审是外部机构来审：客户审核（第二方审核）和认证机构审核（第三方审核）。以 ISO 9001 认证为例，常见节奏（模型知识，待核对）：初次认证审核（通常分两个阶段：文件与准备情况审查、现场审核）→ 发证 → 每年一次监督审核 → 三年一次再认证审核。

准备事项要点
文件齐全受控手册、程序、SOP、表单都有编号、版本、批准；有效文件清单随时能导出
现场与文件一致现场 SOP 版本是否最新；操作员能否说出自己岗位的要求
记录可调取审核员会随机要"上周某个批次的检验记录""某台量具的校准证书"，几分钟内要拿出来
内审和管理评审已做有计划、有报告、不符合项有关闭证据；外审员常以此判断体系是否真在运行
培训记录新版文件发布后，相关人员培训并签收
上次审核的不符合项已整改关闭，并能说明有效性
追溯演练随机抽一块板，几分钟内能查出用了什么料、哪条线、测试结果，见 产品追溯

系统的价值在这里体现得最明显：能一键导出有效文件清单和修订履历、能按文件查谁培训签收了、能按板码调出全部记录，审核时就从容得多。

技术视角：文件控制的表设计 ​

表结构 ​

把"文件"和"版本"分开：一个文件号对应多个版本。

表作用关键列
ControlledDoc文件主表，一个文件号一行DocNo（唯一）、Title（nvarchar）、DocLevel（1~4 级）、OwnerDept
DocVersion版本表，一个版本一行DocId、Version、Status、ChangeNote、EffectiveDate、ObsoleteDate；(DocId, Version) 唯一
DocLog状态变更日志，只追加DocVersionId、FromStatus、ToStatus、Operator
DocIssue（设计建议，实验里没做）分发与回收：哪个版本发给了哪个部门几份，何时回收、谁签收DocVersionId、Dept、Copies、IssuedAt、ReturnedAt

核心约束：同一文件号最多一个有效版。 这条约束只靠程序控制不够——程序可能有 bug、可能两个人同时点"发布"、可能有人直接改数据库。最稳妥的办法是在数据库里加一个过滤唯一索引（Filtered Unique Index）：

sql
CREATE UNIQUE INDEX UX_DocVersion_OneEffective ON DocVersion(DocId) WHERE Status = 'Effective';

它的意思是：只对 Status = 'Effective' 的行建唯一索引，同一个 DocId 里这种行最多一行。想同时让两个版本有效，数据库直接报错 2601。这样，无论程序怎么写、怎么并发，"同一文件只有一个有效版"这条业务规则由数据库兜底。

发布作废：一个事务里完成 ​

发布新版 = 先把旧有效版置为 Obsolete，再把新版置为 Effective，两步必须在同一个事务里完成，否则会出现"旧版已作废、新版还没生效"的空窗，或程序在两步之间崩溃造成数据不一致。

另外要注意：

  • 顺序：先作废旧版，再生效新版。如果反过来，第二步会撞上唯一索引（此时旧版还在 Effective）。
  • 并发：读当前状态时用 WITH (UPDLOCK, HOLDLOCK) 加锁，防止两个人同时对同一个版本做状态变更。
  • 出错回滚：存储过程里用 TRY/CATCH，出错先 ROLLBACK 再 THROW。如果开着 SET XACT_ABORT ON 又不回滚就直接抛错，调用方会遇到"Uncommittable transaction"（3998 号错误）。这是我在做实验时踩到的坑，已经改好。
  • 状态流转表：合法的流转（Draft→InReview 等）可以写在代码里，也可以做成一张配置表。实验里用 VALUES 内联。

实验里的日期（EffectiveDate、ObsoleteDate）写成了固定的 '2026-10-21'，是为了让每次运行结果一致；真实系统用 SYSDATETIME() 或由用户指定生效日期。

逐步例子：QP-07-001 从 A0 到 A1 ​

场景：QP-07-001 不合格品控制程序 现行 A0 版。品质部发现"不良品拦截"一节不够清楚，修订成 A1。

步骤动作A0 的状态A1 的状态
1文控创建 A1 草稿EffectiveDraft
2起草人提交审核EffectiveInReview
3品质经理批准（生效日未到）EffectiveApproved
4到生效日，文控发布Obsolete（自动）Effective
5培训、签收；回收现场旧版保留在系统里，不再可见于现场Effective

关键是第 4 步：A0 变 Obsolete 和 A1 变 Effective 在同一个事务里。如果第 4 步之前有人想直接把 A2 草稿改成 Effective，会同时撞上"不能从 Draft 直接生效"和"已有一个有效版"两道关。

第 2 步：状态流转存储过程 ​

sql
-- 状态流转：只允许合法的下一步
CREATE PROCEDURE usp_DocChangeStatus @VersionId INT, @To VARCHAR(10), @Operator NVARCHAR(30)
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    BEGIN TRY
        BEGIN TRAN;
        DECLARE @From VARCHAR(10), @DocId INT;
        SELECT @From = Status, @DocId = DocId FROM DocVersion WITH (UPDLOCK, HOLDLOCK) WHERE Id = @VersionId;
        IF @From IS NULL THROW 50001, 'version not found', 1;
        IF NOT EXISTS (SELECT 1 FROM (VALUES ('Draft','InReview'),('InReview','Draft'),('InReview','Approved'),
                                             ('Approved','Effective'),('Effective','Obsolete')) t(f, t)
                       WHERE f = @From AND t = @To)
            THROW 50002, 'illegal transition', 1;
        IF @To = 'Effective'
            -- 先作废旧有效版，再生效新版：同一事务内完成，任何时刻对外只有一个有效版
            UPDATE DocVersion SET Status = 'Obsolete', ObsoleteDate = '2026-10-21' WHERE DocId = @DocId AND Status = 'Effective';
        UPDATE DocVersion SET Status = @To,
               EffectiveDate = CASE WHEN @To = 'Effective' THEN '2026-10-21' ELSE EffectiveDate END,
               ObsoleteDate  = CASE WHEN @To = 'Obsolete'  THEN '2026-10-21' ELSE ObsoleteDate END
        WHERE Id = @VersionId;
        INSERT INTO DocLog (DocVersionId, FromStatus, ToStatus, Operator) VALUES (@VersionId, @From, @To, @Operator);
        COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;   -- 出错先回滚，再把错误原样抛给调用方
        THROW;
    END CATCH
END
GO

第 4 步：故意违规，看数据库怎么挡 ​

BEGIN CATCH SELECT 'DirectUpdate' AS Step, ERROR_NUMBER() AS ErrNo; END CATCH

Step|ErrNo|Msg

IllegalJump|50002|illegal transition

Step|ErrNo
----|-----
DirectUpdate|2601

第一条被存储过程的状态机挡住（50002），第二条绕过了存储过程直接改表，仍然被过滤唯一索引挡住（2601）。这就是"双保险"：业务规则写在过程里，底线规则由索引兜底。

常见坑与排查 ​

现象 / 误区原因与办法
系统里同一文件两个版本都是"有效"只靠程序控制。用过滤唯一索引兜底；发布放在一个事务里
新版生效了，现场还在用旧版只改了系统状态，没有分发 / 回收动作。设"回收确认"环节，或让现场只从系统取有效版
删除旧版本追溯时说不清"当时用的哪版"。只作废，不删除
直接修改已生效的文件内容违反受控。要改就新建版本走流程
把记录当文件一样随便改记录不能改，更正要另行追加并签名，保留原值
审批人 = 起草人失去审核意义。系统里设置"批准人 ≠ 起草人"的检查
内审只看文件、不看现场内审是查"写的和做的是否一致"，必须到现场看、问人、查记录
内审发现只写"不符合"三个字要写依据、事实、证据，缺一不可
整改只"纠正"（改掉错误），不找原因同样的问题会再发生。严重项走 8D与CAPA
管理评审变成走过场要有数据输入（KPI、审核结果、客诉）和有人负责的输出决定
CREATE INDEX 报 1934：QUOTED_IDENTIFIER用 sqlcmd 时要加 -I；SSMS 默认已开启

练习题与答案 ​

  1. 四级文件分别是什么？《回流焊炉温测试记录表》属于哪一级？ 答：一级质量手册、二级程序文件、三级作业指导书（SOP/WI）、四级记录和表单。空白的记录表是四级；填好的就是"记录"，是证据，不能再改。
  2. 文件和记录最大的区别是什么？ 答：文件规定"该怎么做"，会改版本；记录证明"已经做了"，写下后不能改（更正要追加并留痕）。
  3. 为什么发布新版要在一个事务里同时"作废旧版"和"生效新版"？ 答：分开做可能出现空窗（旧版已作废、新版未生效，现场无有效版）或崩溃造成不一致（两个都有效或都无效）；放在一个事务里要么都成功要么都失败。
  4. 如果先执行"新版 → Effective"再执行"旧版 → Obsolete"，在本实验的表上会发生什么？ 答：第一步就会违反过滤唯一索引（此时旧版仍是 Effective），报 2601。所以顺序必须是先作废旧版。
  5. 一个审核发现："现场某岗位使用的校准标签已过期，但该量具仍在使用"。写一条符合"要求—事实—证据"格式的不符合项草稿。 答：依据：量具管理程序规定超过校准有效期的量具不得使用。事实：IPQC 工位的外径千分尺 MIC-002 校准到期日为 2026-10-10，2026-10-21 仍在使用。证据：量具标签、量具台账、现场照片。（相关设计见 校准与量具管理。）
  6. 内审员能不能去审自己部门的工作？为什么？ 答：一般不能。自己审自己缺乏独立性，容易视而不见。
  7. 管理评审的输入里至少应该有哪几类？ 答：KPI 与质量目标达成情况（直通率、PPM、客诉等）、内审和外审结果、不合格与纠正措施情况、客户反馈、资源是否足够、上次评审决定的跟踪。

小结 ​

  • 体系文件四级：质量手册 / 程序文件 / 作业指导书 / 记录表单；文件会改版本，记录写下就不改。
  • 文件控制的底线：现场用的永远是有效的最新版。版本状态机：Draft → InReview → Approved → Effective → Obsolete，新版生效时旧版自动作废，旧版保留不删。
  • 技术上：文件主表 + 版本表 + 日志；(DocId) WHERE Status='Effective' 的过滤唯一索引兜底；发布放事务，先作废旧版再生效新版；出错先回滚再抛。
  • 内审：计划 → 检查表 → 现场取证 → 报告 → 不符合项整改与验证。不符合项要写依据、事实、证据。
  • 管理评审用数据做决策；外审准备就是平时把文件、记录、内审、管理评审做扎实。
