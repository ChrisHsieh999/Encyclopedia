不合格品控制NCR

AI 生成 · 待核对制造业务QMS更新于 2026-10-21

⚠ 待核对：ISO 9001 第 8.7 条（不合格输出的控制）的要点来自二手资料（上面第一个链接的页面描述的是 2026 版文本，页面自己说明与 2015 版要求相近），没有核对 ISO 官方原文，写正式程序文件前请以你们持有的标准正文为准。NCR 的状态名、处置方式、MRB 组成都是行业通用做法，你们自研的 QMS 一定有自己的叫法和流程，请对照核实。SQL 和 C# 代码都在本机 SQL Server LocalDB 的临时库 Lab_qms2 上实际运行过，输出是真实结果。

本篇是 QMS 系列的一篇。读完你应该能：说清"不合格品"从发现到关闭要经过哪几步；分清返工、返修、报废、让步接收、退货、挑选六种处置；设计 NCR 表和状态机；理解 NCR 如何联动 MES 的在制品锁定和 WMS 的库存冻结；亲手跑出"开单隔离 - 评审 - 处置 - 执行 - 关闭"的完整过程。

一句话定义 ​

NCR（Nonconformance Report，不合格品报告单）是一张"这批（或这块）东西不符合要求，已经被隔离，等待评审决定怎么办"的单据，围绕它形成的"识别、标识、隔离、评审、处置、记录"这套做法，就叫不合格品控制。

先修知识 ​

  • 质量管理基础：知道"符合要求"是质量的底线。
  • IQC来料检验、IPQC过程检验、FQC与OQC：不合格品大多是这些检验环节发现的。
  • 缺陷代码与不良分类：NCR 上要填不良代码，统计时才能按类型汇总。
  • 会写基本的 SQL（UPDATE ... WHERE），见 工单管理 里"把条件写进 WHERE"的技巧。

它解决什么问题 ​

先看一个车间里真实会发生的故事。

周二上午，IQC 抽检一批 10,000 颗 0805 贴片电容，发现外径超差。检验员在系统里点了"判退"，然后……什么也没有发生。电容还躺在来料暂存区，仓管看到系统里这批料状态是"已入库"，下午就把它发给了 2 号线。晚上 SMT 贴了 3 小时，才有人发现这批料"好像被判退了"。

没有不合格品控制，会出这几类事故：

  • 混用：不合格品和合格品混在一起，被当成良品继续使用或出货；
  • 没人决定：不良品堆在角落，谁也不知道该修、该扔还是该退，占用现场和资金；
  • 各管各的：品质说报废，生产说还能用，采购说让供应商换，没有统一的评审和记录；
  • 没有证据：客户或审核员问"这批问题料你们怎么处理的"，答不出来。

不合格品控制就是要保证：发现了就马上拦住（隔离），拦住了就有人按规则决定怎么办（评审、处置），决定了就真的做到（执行），做到了有记录（关闭）。

ISO 9001 在"不合格输出的控制"一条里要求：对不符合要求的输出要加以识别和控制，防止非预期的使用或交付，并根据不合格的性质及其影响采取适当措施；措施可以包括纠正、隔离/遏制/退回/暂停、告知顾客、获得让步接收的授权；还要保留记录（不合格的描述、采取的措施、获得的让步、决定处置的授权人）。下面的设计就是把这些要求落成表和流程。

核心概念 ​

不合格、不良、缺陷 ​

说法意思例子
不合格（Nonconformity）没有满足某个要求，是最广的说法来料证书缺失、尺寸超差、过了有效期
缺陷（Defect）不满足预期使用要求的不合格，更偏产品本身虚焊、连锡、划伤
不良品现场口语，指有缺陷的产品AOI 报警的那块板

现场三个词常混用。系统里统一叫 NCR，用不良代码说明具体是什么问题。

不合格品控制的五步 ​

  1. 识别：检验或操作员发现问题（IQC 判退、AOI 报警、FQC 抽到不良、客户投诉）。
  2. 标识与隔离：贴红色"不合格"标签，放进隔离区；系统里同步冻结库存或锁定在制品。这一步要立刻做，不能等评审。
  3. 评审：由 MRB（Material Review Board，物料评审委员会，通常是品质、工程、生产，必要时采购和客户代表）判断问题范围、影响和处置方式。
  4. 处置：下结论并执行。
  5. 记录与关闭：留下谁决定、怎么处理的证据，NCR 关闭。

六种处置方式 ​

处置英文含义电子厂例子对库存或在制品的影响
返工Rework通过再加工，使其完全符合原要求受潮 IC 重新烘烤后复检；整板重新过炉复检合格后解冻或回到工序
返修Repair采取措施使其可用，但不一定完全符合原要求补焊、飞线进入返修站，修好后复测；若不再满足原规格则要走让步
报废Scrap无法使用，销毁裂板、烧毁的板库存转报废，扣账，需要财务和审批
让步接收Concession（也叫特采）不符合要求但经评审（常需客户同意）可以使用电容丝印颜色不同但功能和规格一致解冻，带"让步"标记使用，批次追溯里留痕
退货Return（RTV）退给供应商，要求换货或抵扣阻值超差的整批电阻库存转"已退货"，生成退货单
挑选Sort100% 全检，挑出不良，良品放行10,000 颗里挑出 360 颗外径超差良品解冻，不良品拆出新批次报废或退货

返工与返修的区别：返工的结果是"和新品一样合格"，返修的结果是"能用但可能和原规格有出入"。所以返修后如果与原要求不一致，需要走让步，现场不能自己决定。（这是行业通用理解，基于模型知识，各公司叫法可能不同。）

让步接收为什么最危险 ​

让步接收等于"明知不合格还要用"。必须：有评审记录和授权人；涉及客户规格时要客户书面同意；产品和批次要标记，方便日后追溯（见 产品追溯）。很多质量事故的根源是"口头让步"。

业务视角 ​

谁在什么环节做什么 ​

角色动作
检验员（IQC/IPQC/FQC/OQC）、产线操作员发现不合格，开 NCR，贴红牌，放入隔离区
仓管在 WMS 里冻结库存（或由系统自动冻结），实物搬入隔离区
品质工程师分析问题范围，组织 MRB，起草处置建议
MRB 成员评审，给出处置结论并签字
生产 / 返修人员执行返工、返修、挑选
采购执行退货、与供应商谈索赔，必要时触发 SCAR（见 供应商质量管理）

流程 ​

单据与记录 ​

  • NCR 单：编号、来源、对象（料号 + 批次，或序列号）、数量、不良代码、描述、处置结论、状态、时间；
  • 状态日志：每次流转谁在什么时候做的；
  • 红牌 / 不合格标签：实物上的标识，要和系统里的 NCR 号对应；
  • MRB 评审记录：参会人、结论、授权人签字（让步接收要有客户批准文件）。

常用 KPI ​

指标含义
NCR 平均关闭周期从开单到关闭的平均天数，太长说明评审拖沓，隔离区被占用
NCR 数量按来源 / 按不良代码IQC、产线、客诉各占多少，哪类不良最多（柏拉图，见 缺陷代码与不良分类）
让步接收比例过高说明规格定得不合理，或者评审把关不严
报废金额进入 质量成本与KPI 的内部损失成本
超期未关闭 NCR 数隔离区的"呆账"

技术视角 ​

表设计 ​

核心是三张表，加上被它联动的两张业务表：

表作用
NcrNCR 单本身（单据表）
NcrLog每次状态流转的流水（记录表），只增不改
StockLot简化的 WMS 批次库存，带状态 Available / Frozen / Scrapped / Returned / Concession
WipUnit简化的 MES 在制品，一块板一行，带状态 InProcess / Locked / Repair / Scrap

Ncr 的字段（题目要求的字段 + 少量必要扩展）：

字段含义
NcrNoNCR 编号，唯一
Source来源：IQC / IPQC / FQC / OQC / Customer / Line
ItemCode、LotNo、SerialNo对象：物料或产品料号；批次号；序列号（单板级才有）。两者至少有一个
Qty数量
DefectCode不良代码
Description现象描述（扩展）
Disposition处置：Rework / Scrap / Concession / Return / Sort，评审前为 NULL
GoodQty挑选后合格数，只在 Sort 时用（扩展）
StatusOpen / Reviewing / Dispositioned / Closed
CreatedAt、ClosedAt开单与关闭时间

为什么处置是 Disposition 列，而不是单独一个状态？ 状态回答"这张单走到哪了"，处置回答"决定怎么办"。评审时先写处置，再把状态推进到 Dispositioned；执行完才 Closed。这样"评审了但还没执行"这个中间状态是看得见的，隔离区里还有多少东西"已有结论但没动手"，一查便知。

建表（T-SQL） ​

sql
CREATE TABLE dbo.Ncr (
    Id          INT IDENTITY PRIMARY KEY,
    NcrNo       NVARCHAR(30)  NOT NULL,
    Source      NVARCHAR(10)  NOT NULL CHECK (Source IN ('IQC','IPQC','FQC','OQC','Customer','Line')),
    ItemCode    NVARCHAR(30)  NOT NULL,
    LotNo       NVARCHAR(30)  NULL,
    SerialNo    NVARCHAR(30)  NULL,
    Qty         INT           NOT NULL CHECK (Qty > 0),
    DefectCode  NVARCHAR(20)  NOT NULL,
    Description NVARCHAR(200) NULL,
    Disposition NVARCHAR(15)  NULL CHECK (Disposition IN ('Rework','Scrap','Concession','Return','Sort')),
    GoodQty     INT           NULL,
    Status      NVARCHAR(15)  NOT NULL DEFAULT 'Open' CHECK (Status IN ('Open','Reviewing','Dispositioned','Closed')),
    CreatedAt   DATETIME2(0)  NOT NULL DEFAULT SYSDATETIME(),
    ClosedAt    DATETIME2(0)  NULL,
    CONSTRAINT UQ_Ncr_NcrNo UNIQUE (NcrNo),
    CONSTRAINT CK_Ncr_Target CHECK (LotNo IS NOT NULL OR SerialNo IS NOT NULL)
);

注意 Status 列是 NVARCHAR(15) 而不是 12：Dispositioned 有 13 个字符。我第一次写的时候就写成了 12，结果字符串被截断、流转全部失败——这是个真实的小坑，见"常见坑"。

含中文的 Description 必须显式写成 nvarchar，否则 SqlSugar 自动建表会建成 varchar，中文变问号（本库的通用规则）。

状态机：沿用"把条件写进 WHERE" ​

流转的代码套路和 工单管理 完全一样：

sql
UPDATE dbo.Ncr SET Status = 'Reviewing' WHERE NcrNo = @NcrNo AND Status = 'Open';

受影响行数 1 才算成功。额外的业务规则也写进 WHERE，比如"没有处置结论不能进入 Dispositioned"：

sql
UPDATE dbo.Ncr SET Status = 'Dispositioned'
WHERE NcrNo = @NcrNo AND Status = 'Reviewing' AND Disposition IS NOT NULL;

两位评审员同时给结论时，用 AND Disposition IS NULL 保证先到先得，后到的更新 0 行，被明确拒绝，不会互相覆盖（实验 2 会演示）。

与 MES、WMS 的联动 ​

NCR 不是孤岛，它的每一步都要改动别的系统的状态：

时点对 WMS（批次库存）对 MES（在制品）
开单（Open）批次库存 Available → Frozen，冻结后不能发料、不能调拨该序列号 InProcess → Locked，过站时被拦截，参见 不良品拦截与锁定
处置：返工 / 返修返工后复检合格解冻进入返修站，参见 返修与维修管理，修好复测后回到流程
处置：报废转 Scrapped，财务扣账，参见 库存管理与批次序列号状态 Scrap，不再流转
处置：让步接收转 Concession（可发料，但带标记）解锁继续，批次追溯里记录"让步"
处置：退货转 Returned，生成退货单不适用（单块板不退货）
处置：挑选良品留在原批次并解冻，不良部分拆成新批次（如 -NG）报废不适用

设计要点：

  1. 隔离要和开单在同一个事务里。 开单成功但冻结失败，等于没拦住；冻结成功但开单失败，等于"莫名其妙被冻结"。实验的 usp_NcrOpen 用 BEGIN TRAN ... COMMIT 保证两者同成同败。
  2. 执行处置和关闭也要在同一个事务里。 否则会出现"NCR 已关闭，但库存还冻着"这类对不上账的情况。
  3. 跨系统时用"事件 + 幂等"。 MES、WMS 通常是独立系统，QMS 不能直接改它们的表，而是发"冻结批次"、"锁定序列号"这样的消息，对方按批次号 / 序列号做幂等处理（重复收到不出错）。公司各系统之间怎么传，见 MES与QMS衔接 和 MES与WMS衔接。⚠ 请对照你们的系统：本篇实验把几张表放在一个库里，只是为了演示逻辑。
  4. 隔离要覆盖"已经流下去的"。 一批料被判退时，有一部分可能已经上了线、甚至做成了成品。这要靠批次追溯（物料追溯与批次关联、产品追溯）找到全部受影响的对象，对它们分别开 NCR 或并案处理。

逐步例子 ​

场景：10 月 21 日，IQC 对 LOT-C0805-1021（0805 电容 10uF，10,000 颗）抽检，发现外径超差。

  1. 10:05 检验员 iqc01 在 QMS 开 NCR-001，来源 IQC，数量 10,000，不良代码 DIM。系统同时把 WMS 里这批库存从 Available 改成 Frozen。仓管收到"冻结"消息，把实物搬到隔离区贴红牌。
  2. 10:30 品质工程师把 NCR 提交评审，状态 Open → Reviewing。
  3. 14:00 MRB 评审：供应商发货紧张，退货换货要 2 周，产线明天要用。决定 100% 挑选。结论：Disposition = Sort。
  4. 16:30 两个人挑选 3 小时，挑出外径超差的 360 颗，合格 9,640 颗。录入 GoodQty = 9640，状态 Reviewing → Dispositioned。
  5. 16:40 关闭 NCR：系统执行处置——原批次 LOT-C0805-1021 数量改为 9,640 并解冻；拆出新批次 LOT-C0805-1021-NG，数量 10,000 - 9,640 = 360，状态 Scrapped。状态 Dispositioned → Closed。
  6. 事后：不良率 360 / 10,000 = 3.6%。这个数字喂给 供应商质量管理：供应商这批 PPM 为 36,000，品质工程师据此决定要不要向供应商发 SCAR 并索赔挑选工时。

SET NOCOUNT ON;
GO
-- ========== 1. 建表（重复运行先清理）==========
DROP PROCEDURE IF EXISTS dbo.usp_NcrOpen, dbo.usp_NcrMove, dbo.usp_NcrSetDisp, dbo.usp_NcrClose;

CREATE TABLE dbo.Ncr (
    Id          INT IDENTITY PRIMARY KEY,
    NcrNo       NVARCHAR(30)  NOT NULL,

    ItemCode    NVARCHAR(30)  NOT NULL,
    LotNo       NVARCHAR(30)  NULL,
    SerialNo    NVARCHAR(30)  NULL,
    Qty         INT           NOT NULL CHECK (Qty > 0),
    DefectCode  NVARCHAR(20)  NOT NULL,
    Description NVARCHAR(200) NULL,
    Disposition NVARCHAR(15)  NULL CHECK (Disposition IN ('Rework','Scrap','Concession','Return','Sort')),
    GoodQty     INT           NULL,            -- Sort（挑选）后确认合格的数量
    Status      NVARCHAR(15)  NOT NULL DEFAULT 'Open' CHECK (Status IN ('Open','Reviewing','Dispositioned','Closed')),
    CreatedAt   DATETIME2(0)  NOT NULL DEFAULT SYSDATETIME(),
    ClosedAt    DATETIME2(0)  NULL,
    CONSTRAINT UQ_Ncr_NcrNo UNIQUE (NcrNo),
    CONSTRAINT CK_Ncr_Target CHECK (LotNo IS NOT NULL OR SerialNo IS NOT NULL)

CREATE TABLE dbo.NcrLog (                      -- 每次状态流转留痕
    Id INT IDENTITY PRIMARY KEY, NcrNo NVARCHAR(30) NOT NULL,
    FromStatus NVARCHAR(15), ToStatus NVARCHAR(15), ByUser NVARCHAR(20), Note NVARCHAR(100),
    At DATETIME2(0) NOT NULL DEFAULT SYSDATETIME());
CREATE TABLE dbo.StockLot (                    -- 简化的 WMS 批次库存
    LotNo NVARCHAR(30) PRIMARY KEY, ItemCode NVARCHAR(30) NOT NULL, Qty INT NOT NULL,
    StockStatus NVARCHAR(15) NOT NULL CHECK (StockStatus IN ('Available','Frozen','Scrapped','Returned','Concession')));
CREATE TABLE dbo.WipUnit (                     -- 简化的 MES 在制品（一行一块板）
    SerialNo NVARCHAR(30) PRIMARY KEY, ItemCode NVARCHAR(30) NOT NULL, Station NVARCHAR(10) NOT NULL,
    WipStatus NVARCHAR(10) NOT NULL CHECK (WipStatus IN ('InProcess','Locked','Repair','Scrap')));
GO
-- ========== 2. 存储过程 ==========
-- 开单：写 NCR，同时隔离（批次库存冻结 / 在制品锁定）
CREATE PROC dbo.usp_NcrOpen @NcrNo NVARCHAR(30), @Source NVARCHAR(10), @ItemCode NVARCHAR(30),
    @LotNo NVARCHAR(30), @SerialNo NVARCHAR(30), @Qty INT, @DefectCode NVARCHAR(20), @Desc NVARCHAR(200), @By NVARCHAR(20)
AS BEGIN
    SET NOCOUNT ON; BEGIN TRAN;
    INSERT dbo.Ncr (NcrNo, Source, ItemCode, LotNo, SerialNo, Qty, DefectCode, Description)
    VALUES (@NcrNo, @Source, @ItemCode, @LotNo, @SerialNo, @Qty, @DefectCode, @Desc);
    IF @SerialNo IS NULL
        UPDATE dbo.StockLot SET StockStatus = 'Frozen' WHERE LotNo = @LotNo AND StockStatus = 'Available';
    ELSE
        UPDATE dbo.WipUnit SET WipStatus = 'Locked' WHERE SerialNo = @SerialNo AND WipStatus = 'InProcess';
    INSERT dbo.NcrLog (NcrNo, FromStatus, ToStatus, ByUser, Note) VALUES (@NcrNo, NULL, 'Open', @By, N'开单并隔离');
    COMMIT;
END;
GO
-- 通用流转：只允许 Open->Reviewing、Reviewing->Dispositioned；Closed 走 usp_NcrClose
CREATE PROC dbo.usp_NcrMove @NcrNo NVARCHAR(30), @From NVARCHAR(15), @To NVARCHAR(15), @By NVARCHAR(20), @Msg NVARCHAR(100) OUTPUT
AS BEGIN
    SET NOCOUNT ON;
    IF NOT EXISTS (SELECT 1 FROM (VALUES ('Open','Reviewing'), ('Reviewing','Dispositioned')) t(f, t2) WHERE f = @From AND t2 = @To)
        BEGIN SET @Msg = N'拒绝：不允许 ' + @From + N' -> ' + @To; RETURN; END
    UPDATE dbo.Ncr SET Status = @To
    WHERE NcrNo = @NcrNo AND Status = @From
      AND (@To <> 'Dispositioned' OR Disposition IS NOT NULL);      -- 没有处置结论不能进入 Dispositioned
    IF @@ROWCOUNT = 1
        BEGIN INSERT dbo.NcrLog (NcrNo, FromStatus, ToStatus, ByUser) VALUES (@NcrNo, @From, @To, @By); SET @Msg = N'成功'; END
    ELSE SET @Msg = N'拒绝：当前状态不是 ' + @From + N'，或还没有处置结论';
END;
GO
-- MRB 给出处置结论：只在 Reviewing 状态下允许；序列号级 NCR 不能 Return / Sort
CREATE PROC dbo.usp_NcrSetDisp @NcrNo NVARCHAR(30), @Disp NVARCHAR(15), @GoodQty INT, @By NVARCHAR(20), @Msg NVARCHAR(100) OUTPUT
AS BEGIN
    SET NOCOUNT ON;
    UPDATE dbo.Ncr SET Disposition = @Disp, GoodQty = @GoodQty
    WHERE NcrNo = @NcrNo AND Status = 'Reviewing'
      AND NOT (SerialNo IS NOT NULL AND @Disp IN ('Return','Sort'))
      AND (@Disp <> 'Sort' OR (@GoodQty BETWEEN 0 AND Qty));
    IF @@ROWCOUNT = 1
        BEGIN INSERT dbo.NcrLog (NcrNo, FromStatus, ToStatus, ByUser, Note) VALUES (@NcrNo, 'Reviewing', 'Reviewing', @By, N'MRB 结论：' + @Disp); SET @Msg = N'成功'; END
    ELSE SET @Msg = N'拒绝：不在评审中，或该处置对此对象不适用';
END;
GO
-- 关闭：执行处置对库存 / 在制品的影响，然后 Dispositioned -> Closed，同一个事务
CREATE PROC dbo.usp_NcrClose @NcrNo NVARCHAR(30), @By NVARCHAR(20), @Msg NVARCHAR(100) OUTPUT
AS BEGIN
    SET NOCOUNT ON; BEGIN TRAN;
    DECLARE @Disp NVARCHAR(15), @Lot NVARCHAR(30), @Sn NVARCHAR(30), @Qty INT, @Good INT;
    SELECT @Disp = Disposition, @Lot = LotNo, @Sn = SerialNo, @Qty = Qty, @Good = GoodQty
    FROM dbo.Ncr WITH (UPDLOCK) WHERE NcrNo = @NcrNo AND Status = 'Dispositioned';
    IF @Disp IS NULL BEGIN ROLLBACK; SET @Msg = N'拒绝：NCR 不存在或不在 Dispositioned 状态'; RETURN; END
    IF @Sn IS NULL      -- 批次库存
    BEGIN
        IF @Disp = 'Scrap'      UPDATE dbo.StockLot SET StockStatus = 'Scrapped'   WHERE LotNo = @Lot;
        IF @Disp = 'Return'     UPDATE dbo.StockLot SET StockStatus = 'Returned'   WHERE LotNo = @Lot;
        IF @Disp = 'Concession' UPDATE dbo.StockLot SET StockStatus = 'Concession' WHERE LotNo = @Lot;
        IF @Disp = 'Rework'     UPDATE dbo.StockLot SET StockStatus = 'Available'  WHERE LotNo = @Lot;   -- 如烘烤后复检合格
        IF @Disp = 'Sort'       -- 挑选：合格部分解冻，不合格部分拆成新批次报废
        BEGIN
            INSERT dbo.StockLot (LotNo, ItemCode, Qty, StockStatus)
            SELECT LotNo + '-NG', ItemCode, Qty - @Good, 'Scrapped' FROM dbo.StockLot WHERE LotNo = @Lot;
            UPDATE dbo.StockLot SET Qty = @Good, StockStatus = 'Available' WHERE LotNo = @Lot;
        END
    END
    ELSE                -- 在制品
    BEGIN
        IF @Disp = 'Rework'     UPDATE dbo.WipUnit SET WipStatus = 'Repair'    WHERE SerialNo = @Sn;
        IF @Disp = 'Scrap'      UPDATE dbo.WipUnit SET WipStatus = 'Scrap'     WHERE SerialNo = @Sn;
        IF @Disp = 'Concession' UPDATE dbo.WipUnit SET WipStatus = 'InProcess' WHERE SerialNo = @Sn;
    END
    UPDATE dbo.Ncr SET Status = 'Closed', ClosedAt = SYSDATETIME() WHERE NcrNo = @NcrNo AND Status = 'Dispositioned';
    INSERT dbo.NcrLog (NcrNo, FromStatus, ToStatus, ByUser, Note) VALUES (@NcrNo, 'Dispositioned', 'Closed', @By, N'已执行：' + @Disp);
    COMMIT; SET @Msg = N'成功';
END;
GO

第 3 步：读懂输出

  • A 段：6 张 NCR 开出后，4 批料变成 Frozen，两块板变成 Locked；没出问题的 LOT-OK-0001 和 PCB-A100-0009 不受影响。隔离是精确到对象的。
  • B 段：六次非法操作被拒绝（B4 是正常的提交评审）。B1 在 Open 状态直接关闭、B2 跳过评审、B3 还没进入评审就下结论、B5 没有处置结论就想推进、B6 单块板选"退货"、B7 挑选后的合格数比总数还多。注意 B2 和 B5 的拒绝原因不同：B2 是流转不在允许表里，B5 是条件不满足。
  • C 段：七个"成功"，意思是"处置结论已确定"。紧接着的表格说明：此刻库存依然是 Frozen。结论是纸面的，直到真正执行，库存才变。
  • D 段：关闭时执行。重复关闭、关闭后再改处置都被拒绝。
  • E 段：最终状态。LOT-C0805-1021 变成 9,640 + 拆出 360 的 -NG；LOT-R0603-1020 变 Returned；LOT-C0603-1018 是 Concession；MSD 烘烤的 LOT-IC-0919 回到 Available。PCB-A100-0007 去返修（Repair），-0008 报废。NcrLog 里 NCR-001 的五行记录就是审计证据。
  • 最后的汇总：可用 41,640（含 9,640 + 2,000 + 30,000），让步 50,000，已退货 20,000，报废 360。这就是 WMS 看到的"能发料"的量。

第 4 步，动手改：

  • 把 NCR-001 的挑选合格数改成 10000（一颗不良都没挑出来）再跑一遍，拆出的 -NG 批次数量是多少？你认为系统应该允许创建数量为 0 的批次吗？
  • 在 usp_NcrOpen 里故意在 INSERT dbo.NcrLog 之后 RAISERROR（或写一个 1/0），观察事务回滚后 NCR 和冻结都没有留下；
  • 给 Ncr 加一条规则：Source = 'IQC' 的 NCR 必须带 LotNo。想想该写成 CHECK 约束还是写进存储过程。

新建 LabNcr.cs（含上面的 Ncr 实体，只是多了一个 Run）：

csharp
using SqlSugar;

namespace QmsLab;

// 映射到 T-SQL 实验里建好的 dbo.Ncr 表（不用 CodeFirst 建表）
[SugarTable("Ncr")]
public class Ncr
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)] public int Id { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(30)")] public string NcrNo { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(10)")] public string Source { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(30)")] public string ItemCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(30)", IsNullable = true)] public string LotNo { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(30)", IsNullable = true)] public string SerialNo { get; set; }
    public int Qty { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(20)")] public string DefectCode { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(200)", IsNullable = true)] public string Description { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(15)", IsNullable = true)] public string Disposition { get; set; }
    [SugarColumn(IsNullable = true)] public int? GoodQty { get; set; }
    [SugarColumn(ColumnDataType = "nvarchar(15)")] public string Status { get; set; }
    public DateTime CreatedAt { get; set; }
    [SugarColumn(IsNullable = true)] public DateTime? ClosedAt { get; set; }
}

public static class LabNcr
{
    // 把"当前状态"写进 WHERE：返回 true 表示这一步真的发生了
    static bool Move(SqlSugarClient db, string no, string from, string to) =>
        db.Updateable<Ncr>().SetColumns(n => new Ncr { Status = to })
            .Where(n => n.NcrNo == no && n.Status == from).ExecuteCommand() == 1;

    // MRB 下结论：只有"评审中且还没结论"才能写，先到先得
    static bool Decide(SqlSugarClient db, string no, string disp) =>
        db.Updateable<Ncr>().SetColumns(n => new Ncr { Disposition = disp })
            .Where(n => n.NcrNo == no && n.Status == "Reviewing" && n.Disposition == null).ExecuteCommand() == 1;

    public static void Run(SqlSugarClient db)
    {
        db.Deleteable<Ncr>().Where(n => n.NcrNo == "NCR-101").ExecuteCommand();
        db.Insertable(new Ncr { NcrNo = "NCR-101", Source = "IQC", ItemCode = "CAP-10U-0805", LotNo = "LOT-C0805-1021",
            Qty = 10000, DefectCode = "DIM", Description = "电容外径超差", Status = "Open", CreatedAt = DateTime.Now }).ExecuteCommand();
        Console.WriteLine("1. 开单 NCR-101，状态 Open");
        Console.WriteLine($"2. Open -> Reviewing：{(Move(db, "NCR-101", "Open", "Reviewing") ? "成功" : "被拒绝")}");
        Console.WriteLine($"3. 再次 Open -> Reviewing：{(Move(db, "NCR-101", "Open", "Reviewing") ? "成功" : "被拒绝")}");
        var r = new bool[2];
        var picks = new[] { "Scrap", "Return" };
        Parallel.For(0, 2, i => r[i] = Decide(Db.Create(), "NCR-101", picks[i]));
        Console.WriteLine($"4. 两位评审员同时下结论（一个报废、一个退货）：成功 {r.Count(x => x)} 个，被拒绝 {r.Count(x => !x)} 个");
        var n = db.Queryable<Ncr>().First(x => x.NcrNo == "NCR-101");
        Console.WriteLine($"5. 当前：状态 {n.Status}，处置已确定（{(n.Disposition != null ? "只有一个结论" : "无")}）");
        db.Deleteable<Ncr>().Where(x => x.NcrNo == "NCR-101").ExecuteCommand();
    }
}

Program.cs：

csharp
using QmsLab;

switch (args.Length > 0 ? args[0] : "")
{

运行 dotnet run -- ncr，预期输出（本机实际运行得到）：

1. 开单 NCR-101，状态 Open
2. Open -> Reviewing：成功
3. 再次 Open -> Reviewing：被拒绝
4. 两位评审员同时下结论（一个报废、一个退货）：成功 1 个，被拒绝 1 个
5. 当前：状态 Reviewing，处置已确定（只有一个结论）

第 4 步最关键：两个线程用各自独立的数据库连接同时给 NCR-101 下结论，一个选报废、一个选退货。Decide 把 Status == "Reviewing" && Disposition == null 写进了 WHERE，所以总是恰好一个成功。如果评审系统是先 SELECT 看有没有结论、再 UPDATE，两人可能互相覆盖，库存最后按谁的结论执行就不确定了。

练习题与答案 ​

  1. 返工和返修有什么区别？ 答：返工是通过再加工使产品完全符合原要求；返修是使产品可用，但可能不完全符合原要求。返修后不一致的要走让步接收。
  2. 为什么要在开单时就冻结库存，而不是等评审完再处理？ 答：评审可能要几小时到几天，这期间如果不隔离，不合格品可能被发料上线或出货。隔离要快于评审。
  3. 实验里"Dispositioned"之后库存为什么仍是 Frozen？什么时候才变？ 答：处置结论只是决定，库存状态要到执行（实验里是关闭时）才改变。这样 NCR 的状态能真实反映"决定了但还没做"。
  4. 对 NCR-001，挑选后合格 9,640 颗，不良率是多少？如果挑选前 IQC 抽样 125 颗发现 4 颗不良，抽样不良率是多少？为什么两者不一样？ 答：全检不良率 360/10000 = 3.6%；抽样不良率 4/125 = 3.2%。抽样只是对整批的估计，样本有随机波动，全检才是真实值。
  5. 为什么"序列号级 NCR 不允许选退货和挑选"？ 答：退货是退给供应商的整批物料操作；挑选是对一批数量做 100% 检查再分流。单块成品板没有这样的语义，只能返工、返修、报废或让步。
  6. 两位评审员同时点"报废"和"退货"，系统应该怎么保证只有一个生效？请写出 WHERE 条件的关键部分。 答：WHERE NcrNo = @no AND Status = 'Reviewing' AND Disposition IS NULL，看受影响行数是否为 1。
  7. 如果 MES 和 WMS 是两个独立的系统，QMS 怎么让它们"冻结"？ 答：QMS 发出"冻结批次 / 锁定序列号"的事件或接口调用，对方按批次号 / 序列号幂等处理；失败要重试并告警，不能默默丢失。

小结 ​

  • 不合格品控制 = 识别、标识与隔离、评审、处置、记录。隔离要立刻，处置要有授权，执行要有记录。
  • 六种处置：返工、返修、报废、让步接收、退货、挑选，各对库存和在制品有不同影响。
  • NCR 状态机 Open → Reviewing → Dispositioned → Closed，处置结论是一列，执行发生在关闭时。
  • 技术上延续"检查条件写进 WHERE"；隔离、执行处置要和开单、关闭放进同一事务。
  • NCR 的数据是质量改进的原料：按来源和不良代码统计，喂给 8D与CAPA 和 供应商质量管理。
