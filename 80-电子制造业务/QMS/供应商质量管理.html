供应商质量管理

AI 生成 · 待核对制造业务QMS更新于 2026-10-21

⚠ 待核对：PPM 的定义和计算已对照资料；"多少 PPM 算好"各资料说法不一（有的说 25 PPM 以下是世界级，有的说 100 PPM 以下），只能当粗略参考，以客户合同和你们公司的规定为准。ISO 9001 第 8.4 条（外部提供的过程、产品和服务的控制）的要点来自二手资料，未核对标准原文。评分的权重、等级线、动作都是示例设计，不是标准；你们公司的供应商管理办法请对照核实。实验里的 IQC 判批规则（允收数 Ac）是我自己规定的简化规则，不是 ANSI Z1.4 / ISO 2859-1 的查表值；共享表 InspectionLot 等只建了实验用到的列，完整定义请看 IQC来料检验。SQL 在本机 SQL Server LocalDB 临时库 Lab_qms2 上实际运行，数字用 Python 复算过。

本篇是 QMS 系列的一篇。读完你应该能：说出供应商从准入到退出的全生命周期；会用 IQC 数据算批合格率和 PPM；设计一套四项指标的供应商评分和分级；知道什么时候该发 SCAR；用 SQL 做出供应商评分表。

一句话定义 ​

供应商质量管理（Supplier Quality Management，SQM）是对为你供货的外部企业，从选择、认证、日常监控、绩效评价到改善或淘汰的全过程质量管理——因为电子产品里一大半的质量，是你的供应商决定的。

先修知识 ​

  • IQC来料检验：供应商质量的主要数据来自来料检验的结果。
  • 抽样检验AQL：知道"抽样判批"，才明白为什么 PPM 只是估计。
  • 不合格品控制NCR：来料批退走 NCR；NCR 里的数据汇总就是供应商质量数据。
  • 8D与CAPA：SCAR 就是"要求供应商做 8D / CAPA"。
  • 采购管理：采购是供应商关系的主要负责人，要和品质配合。

它解决什么问题 ​

采购选了一家价格最低的电容供应商。第一个月没事；第二个月 IQC 退了一批；第三个月又退一批，产线因缺料停了半天线。采购说"他们答应改进了"，品质说"他们答应了三次"。年底评供应商，没有人拿得出数据——所有人都凭印象说话，最后价格最低的那家继续拿到最多订单。

没有供应商质量管理：

  • 选供应商靠价格和关系，质量能力没人评估；
  • 问题批退只在 IQC 这一道拦，没有机制要求供应商从源头改；
  • 没有量化的评价，好供应商得不到更多订单，差供应商也没有压力；
  • 同样的问题反复来，因为从来没有正式要求过供应商做根因分析（SCAR）；
  • 客户审核时问"你们怎么评价和监控供应商"，拿不出记录（ISO 9001 第 8.4 条要求确定并应用外部供方评价、选择、绩效监视和再评价的准则）。

核心概念 ​

供应商生命周期 ​

对应 Supplier.ApprovalStatus：Candidate / Approved / Conditional / Probation / Disqualified。

准入评估看什么 ​

项目内容说明
资质营业执照、ISO 9001 / IATF 16949 证书、RoHS / 环保声明证书只证明有体系，不保证产品好
现场审核体系审核 + 过程审核（来料检验、生产工艺、仓储、追溯）关键物料（IC、PCB、连接器）应当现场审核
样品与首件样品检验、可靠性试验、首件（FAI）报告新料号第一次到货做全项检验
小批试用试用期小批量、加严检验通过再转批量
供货能力产能、交期、应急、价格采购主导，品质参与

来料合格率与 PPM ​

批合格率 = 允收批数 / 总检验批数 × 100%。它回答"这家供应商的货十批里有几批能直接收"。

PPM（Parts Per Million，百万分之几）= 不良数 / 检验总数 × 1,000,000。它回答"每一百万个里有几个坏"。例：

  • 抽检 480 个，发现 8 个不良：8 / 480 × 1,000,000 ≈ 16,666 PPM（约 1.67%）；
  • 换算：1% = 10,000 PPM，0.01% = 100 PPM。

资料里常见的粗略参考：有的写小于 25 PPM 算优秀，有的写 100 PPM 以下；汽车一级供应商的客户可能要求 10–25 PPM 以内，超过 50 PPM 要求 8D，超过 100 PPM 升级管控。这些只是参考，各客户合同不同。

PPM 的两个口径问题（实务中最容易吵架的地方）：

  1. 抽样的 PPM 是估计。IQC 抽样 125 个，发现 2 个，不代表整批 20,000 个只有 2/125 的不良。小样本对稀有缺陷不灵敏；整批 100% 挑选后的 PPM 才是真值。
  2. 同一件产品多个检验项都不合格，只能算一个不良品。实验里用 COUNT(DISTINCT SampleNo) 统计，而不是把检验结果行数直接相加。

绩效评分（QCDS） ​

QCDS 是 Quality（质量）、Cost（成本）、Delivery（交付）、Service（服务）。本篇示例（总分 100）：

项目权重公式说明
批合格率4040 × 批合格率来自 IQC
PPM2020 × max(0, 1 − PPM / 20000)PPM 越低越好，达到或超过 20,000 PPM 得 0 分
交付2525 × 准时行数 / 总行数来自收货记录与采购交期
响应1515 × SCAR 按时关闭数 / SCAR 总数，没有 SCAR 得满分对质量问题的响应速度

等级：A ≥ 90，B 80–90，C 60–80，D < 60。

这套权重与阈值是示例。成本（价格）一般由采购单独评价，不放进质量评分。实际应用要和采购、供应商商定，公布给供应商，并至少每年复审。

一个设计陷阱：响应项"没有 SCAR 得满分"，会让该发 SCAR 却没发的供应商白白拿 15 分。实验的 S004 就是这样：两批连续退批，没有 SCAR，响应得 15 分。所以评分之外必须配一张"该发而没发 SCAR"的清单（实验查询 5）。

分级后的动作（示例） ​

等级含义动作
A优秀优先下单；检验可放宽（减量抽检、免检需有准入规则）；可作为标杆
B合格正常抽检；个别问题发通知改进
C待改进加严检验；发 SCAR 并要求改善计划；暂停新料号导入；限期复评
D不合格暂停新订单；现场审核；限期内无改善则淘汰，寻找替代供应商

SCAR 与审核 ​

SCAR（Supplier Corrective Action Request，供应商纠正措施要求）是发给供应商的、要求其对质量问题做根因分析和纠正的正式文件，供应商回复的往往就是一份 8D（见 8D与CAPA）。触发条件示例：批退、同一缺陷重复、严重缺陷流到产线甚至客户。关键是有回复期限（实验里 14 天），并统计供应商的按时关闭率。

审核分三类：体系审核（ISO 9001 等）、过程审核（针对关键工序）、产品审核（抽查成品）。审核频次按供应商等级和物料重要度决定，C、D 级和关键物料更频繁。

  1. 来料到货，IQC 检验判批，退批开 NCR（见 不合格品控制NCR）；

InspectionLot 上建索引 (SupplierCode, InspType, CreatedAt)，因为评分查询总是"某供应商、IQC、某个时间窗口"。

评分的 SQL 思路 ​

  1. 按窗口过滤（实验用 8–10 月）：CreatedAt >= '2026-08-01' AND CreatedAt < '2026-11-01'——半开区间，不要用 BETWEEN 与 <= '2026-10-31'（后者会漏掉 10-31 当天有时分秒的记录）。
  2. 每批的不良件数用 COUNT(DISTINCT SampleNo)，避免多检验项重复计数。
  3. 批合格率和PPM分别聚合，再 JOIN 交付、SCAR 汇总。
  4. 没有数据的指标要明确处理：没有 SCAR 得满分（需配合"该发未发"清单）；没有交付记录的供应商（INNER JOIN 会让它消失，实验里 S004 的 8 月没有记录，只算 9、10 月）。
  5. 口径放进视图或存储过程，月报、看板、接口都从同一处取数，避免两处算出不同结果。

与其他系统的关系 ​

  • ERP / 采购：交付数据和价格来自采购订单与收货（见 ERP、采购管理）；准入状态也要同步给采购（Disqualified 的供应商不能再下单）。
  • WMS：收货时校验供应商状态；来料判退触发库存冻结（见 收货与上架）。
  • MES：生产中发现的物料问题通过批次追溯回到供应商（见 物料追溯与批次关联），计入"内部失败"。
  • ⚠ 请对照你们的系统：IQC 数据是否留到每个样本；评分是 QMS 自动算还是 Excel 手工算。

  4. 响应：SCAR-26-007 按时关闭（9 月 3 日，期限 9 月 4 日），1/1，得 15；
  5. 合计 26.7 + 3.3 + 22.7 + 15 = 67.7，等级 C：要发 SCAR、加严检验。

再看 S003：批合格率只有 25%（4 批退 3 批），PPM 20,000 得 0 分，两张 SCAR 一张超期关闭、一张到现在还没关，响应 0 分，总分 30.0，D 级。

  CAST(1000000.0 * SUM(CASE WHEN MONTH(l.CreatedAt) = 8  THEN x.Ng END) / NULLIF(SUM(CASE WHEN MONTH(l.CreatedAt) = 8  THEN l.SampleQty END), 0) AS INT) AS Aug,
  CAST(1000000.0 * SUM(CASE WHEN MONTH(l.CreatedAt) = 9  THEN x.Ng END) / NULLIF(SUM(CASE WHEN MONTH(l.CreatedAt) = 9  THEN l.SampleQty END), 0) AS INT) AS Sep,
  CAST(1000000.0 * SUM(CASE WHEN MONTH(l.CreatedAt) = 10 THEN x.Ng END) / NULLIF(SUM(CASE WHEN MONTH(l.CreatedAt) = 10 THEN l.SampleQty END), 0) AS INT) AS Oct
FROM dbo.InspectionLot l
CROSS APPLY (SELECT COUNT(DISTINCT SampleNo) AS Ng FROM dbo.InspectionResult r WHERE r.LotId = l.Id AND r.Judgement = 'NG') x
GROUP BY l.SupplierCode ORDER BY l.SupplierCode;
PRINT N'--- 4. 供应商绩效评分（质量 60：批合格率 40 + PPM 20；交付 25；响应 15）---';
DECLARE @Today DATE = '2026-10-21';
WITH q AS (
    SELECT l.SupplierCode,
           1.0 * SUM(CASE WHEN l.Result = 'Accept' THEN 1 ELSE 0 END) / COUNT(*) AS PassRate,
           1000000.0 * SUM(x.Ng) / SUM(l.SampleQty) AS Ppm
    FROM dbo.InspectionLot l
    CROSS APPLY (SELECT COUNT(DISTINCT SampleNo) AS Ng FROM dbo.InspectionResult r WHERE r.LotId = l.Id AND r.Judgement = 'NG') x
    WHERE l.InspType = 'IQC' AND l.CreatedAt >= '2026-08-01' AND l.CreatedAt < '2026-11-01' GROUP BY l.SupplierCode),
d AS (SELECT SupplierCode, 1.0 * SUM(OnTimeLines) / SUM(Lines) AS OnTimeRate FROM dbo.SupplierDelivery GROUP BY SupplierCode),
s AS (SELECT SupplierCode, COUNT(*) AS Total, SUM(CASE WHEN ClosedDate <= DueDate THEN 1 ELSE 0 END) AS OnTime
      FROM dbo.Scar WHERE ClosedDate IS NOT NULL OR DueDate <= @Today GROUP BY SupplierCode),
sc AS (
    SELECT sup.SupplierCode, sup.Name,
           40 * q.PassRate AS QLot,
           20 * CASE WHEN 1 - q.Ppm / 20000 < 0 THEN 0 ELSE 1 - q.Ppm / 20000 END AS QPpm,
           25 * d.OnTimeRate AS Delivery,
           15 * CASE WHEN s.Total IS NULL THEN 1.0 ELSE 1.0 * s.OnTime / s.Total END AS Response
    FROM dbo.Supplier sup JOIN q ON q.SupplierCode = sup.SupplierCode JOIN d ON d.SupplierCode = sup.SupplierCode
    LEFT JOIN s ON s.SupplierCode = sup.SupplierCode)
SELECT SupplierCode, Name, CAST(QLot AS DECIMAL(5,1)) AS QLot, CAST(QPpm AS DECIMAL(5,1)) AS QPpm,
       CAST(Delivery AS DECIMAL(5,1)) AS Delivery, CAST(Response AS DECIMAL(5,1)) AS Response,
       CAST(QLot + QPpm + Delivery + Response AS DECIMAL(5,1)) AS Total,
       CASE WHEN QLot + QPpm + Delivery + Response >= 90 THEN 'A' WHEN QLot + QPpm + Delivery + Response >= 80 THEN 'B'
            WHEN QLot + QPpm + Delivery + Response >= 60 THEN 'C' ELSE 'D' END AS Grade
FROM sc ORDER BY Total DESC;

FROM dbo.InspectionLot l
WHERE l.Result = 'Reject'

                  AND DATEDIFF(DAY, CAST(l.CreatedAt AS DATE), s.IssuedDate) BETWEEN 0 AND 7)
ORDER BY l.SupplierCode, l.CreatedAt;

Python 独立复算（supplier_check.py，不读数据库，用同样的数据复算）：

python
# 供应商 PPM 与评分的独立复算（数据与 supplier.sql 一致，不读数据库）
AC = {80: 1, 125: 2, 200: 3}                      # 简化的允收数
lots = {                                           # 供应商: [(抽样数, 样本中不良数), ...]  8-10 月各批
    "S001": [(125, 0), (125, 1), (125, 0), (125, 0), (125, 1), (125, 0)],
    "S002": [(80, 1), (80, 3), (80, 1), (80, 2), (80, 0), (80, 1)],
    "S003": [(200, 4), (200, 6), (200, 4), (200, 2)],
    "S004": [(125, 4), (125, 3)]}
delivery = {"S001": (123, 121), "S002": (88, 80), "S003": (75, 60), "S004": (18, 13)}   # (总行数, 准时行数)
scar = {"S002": (1, 1), "S003": (0, 2)}            # (准时关闭数, 总数)；没有 SCAR 的得满分
for s, ls in lots.items():
    n = len(ls)
    accepted = sum(1 for size, ng in ls if ng <= AC[size])
    inspected, ng_total = sum(a for a, _ in ls), sum(b for _, b in ls)
    ppm = 1e6 * ng_total / inspected
    q_lot = 40 * accepted / n
    q_ppm = 20 * max(0.0, 1 - ppm / 20000)
    dlv = 25 * delivery[s][1] / delivery[s][0]
    resp = 15 if s not in scar else 15 * scar[s][0] / scar[s][1]
    total = q_lot + q_ppm + dlv + resp
    grade = "A" if total >= 90 else "B" if total >= 80 else "C" if total >= 60 else "D"
    print(f"{s}: 批数 {n} 退批 {n - accepted} 合格率 {100 * accepted / n:.1f}% 检验 {inspected} 不良 {ng_total} PPM {int(ppm)} "
          f"| 批{q_lot:.1f} PPM{q_ppm:.1f} 交付{dlv:.1f} 响应{resp:.1f} 总分 {total:.1f} 等级 {grade}")

常见坑与排查 ​

坑现象 / 事实办法
一个口径吵半年采购、品质各算一套 PPM口径写进办法，计算放在同一视图 / 存储过程
用样本数当检验总数PPM 被低估或高估明确分母：抽样检验用抽样数，全检用批量；报表标注口径
多检验项重复计数一件产品 3 项不合格被算成 3 个不良COUNT(DISTINCT SampleNo)
小批量 / 少批数评分失真只来 1 批，一次退批评分 0设最小样本要求（如至少 3 批或 1000 个）；样本不足标注"数据不足"
没发 SCAR 反而拿高分响应项"没有 SCAR 满分"增加"该发未发"清单；或没响应数据时不计该项权重
只看质量，忽略交付质量好但老是缺货评分含交付，并结合订单份额决策
评分结果不公开供应商无从改进月度反馈，季度会议
准入状态与采购系统不同步已淘汰的供应商还能下单状态变更同步 ERP；下单时校验
证书当作质量保证有 IATF 证书但产品还是退批证书只是门槛，仍要看实际数据和现场过程

练习题与答案 ​

  1. 抽检 800 个发现 16 个不良，PPM 是多少？它代表整批的真实不良水平吗？ 答：16/800 × 1,000,000 = 20,000 PPM。只是抽样估计，样本小，稀有缺陷灵敏度差；真实水平要靠更大样本或全检。
  2. 实验里 S001 的 PPM 是 2,666，按评分公式 PPM 项得多少分？ 答：20 × (1 − 2666.67/20000) = 17.3 分。
  3. 为什么统计不良件数要用 COUNT(DISTINCT SampleNo)？ 答：一个样本可能在多个检验项上不合格，产生多行结果；不良品是按"件"计，不是按"不良项"计，不去重会高估 PPM。
  4. S004 为什么 8 月 PPM 是 NULL 而不是 0？ 答：8 月没有来料，没有检验；0 表示"检验了而且没有不良"，NULL 表示"没有数据"，含义不同，混淆会让图表误导。
  5. S003 总分 30.0 为什么是 D 级？哪两项几乎拿不到分？ 答：批合格率仅 25% 得 10 分；PPM 20,000 得 0 分；响应 SCAR 超期或未关闭得 0 分。主要失分在质量和响应。
  6. 评分窗口为什么用 CreatedAt >= '2026-08-01' AND CreatedAt < '2026-11-01' 而不是 BETWEEN '2026-08-01' AND '2026-10-31'？ 答：CreatedAt 带时分秒，'2026-10-31' 被当作当天 00:00:00，10-31 当天的记录会被漏掉。用半开区间可靠。
  7. 供应商被评为 C 级，品质应当采取哪些动作？ 答：发 SCAR 要求根因分析和改善计划，设期限；对该供应商加严检验；暂停新料号导入；限期复评；改善无效则降到 D 级并找替代来源。
  8. （思考）为什么质量评分里一般不放价格？ 答：价格是商务维度，通常由采购单独评价；混进质量评分会让低价低质的供应商分数被"拉高"，削弱质量信号。

小结 ​

  • 供应商质量管理覆盖：准入评估、试用、批量、绩效评价、分级、SCAR、审核、淘汰。
  • 来料合格率用批为单位，PPM 用件为单位；PPM 抽样得到的是估计；去重统计不良件。
  • 评分示例：批合格率 40 + PPM 20 + 交付 25 + 响应 15；分 A/B/C/D 并对应动作。
  • 数据处理要点：半开日期区间、NULL 与 0 区分、最小样本量、"该发未发"清单。
  • SCAR 要求供应商做根因，不是"加强检验"；这和 8D与CAPA 完全同一套思想。
