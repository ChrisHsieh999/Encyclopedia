质量成本与KPI

AI 生成 · 待核对制造业务QMSKPI质量成本更新于 2026-10-21

⚠ 待核对：①质量成本四分法（预防 / 鉴定 / 内部损失 / 外部损失）来自 ASQ 和维基百科"Cost of poor quality"的介绍；ASQ 官网我只拿到搜索摘要，没能直接打开页面。文中提到的"COQ 约占销售额 15–20%""1-10-100 法则"只是第三方资料的经验说法，我没能在 ASQ 页面上核实，仅作参考。②FPY / RTY / PPM / DPMO 的公式是通用定义，但各公司的口径（分母怎么选、返修算不算、复测算不算）不同，我写的是常见做法，你们的自研 QMS/MES 的计算口径请对照核实。③Cpk 与 PPM 的对应表假设数据服从正态分布、过程受控、均值居中，用 Python 按公式算出，仅作理解用。④SQL 与 Python 代码和输出是我在本机 SQL Server LocalDB（临时库 Lab_qms3）上实际运行得到的，数据是虚构的。

本篇是 QMS 系列的一篇。读完你应该能：说清质量成本的四类以及它们之间"花在预防上的钱和失败损失的钱"的关系；定义并正确计算 PPM、FPY、RTY、一次合格率、客诉率、退货率；知道每个 KPI 的分母陷阱；亲手用 SQL 和 Python 算出一组数并手算核对。

一句话定义 ​

质量成本（COQ，Cost of Quality）是为了得到好质量花的钱，加上质量不好造成的损失，一共四类：预防、鉴定、内部损失、外部损失。质量 KPI 是衡量质量好坏的几个数字：PPM（百万分之不良数）、FPY（First Pass Yield，一次通过率）、RTY（Rolled Throughput Yield，滚动直通率）、客诉率、退货率等。

先修知识 ​

  • 质量管理基础：知道什么是不良、检验、质量体系。
  • 缺陷代码与不良分类：知道不良是怎么记录的，KPI 的原始数据来自那里。
  • 会读简单的 SQL（GROUP BY、CASE WHEN、SUM）。
  • 了解中学统计的"正态分布"和"概率"即可。

它解决什么问题 ​

先看一个现场场景。某厂的月度质量会议，品质经理汇报："本月直通率 97%！"生产经理不服："我们线上返修的人手紧张得很！"客户代表说："你们的货退货率这个月翻了一倍。"三个说法都"对"——因为每个人用的是不同的分母和口径：

  • 品质经理的"直通率"是最后一站通过的板数除以投入数，返修后合格的也算通过；
  • 生产经理感受到的是每一站的一次通过率，很多板第一次测都不过，靠返修救回来；
  • 客户的"退货率"是退货批数除以客户收货批数，而且是按退货发生月统计，和这个月出货的板没有关系。

三个人都在用数字，却没法对话。所以需要：

  1. 统一定义：分子是什么、分母是什么、时间窗口怎么划，白纸黑字写下来；
  2. 识别隐藏的浪费：返修救回来的板，在最终合格率里看不出来，但花了人工、物料和时间——隐藏工厂（Hidden Factory）；
  3. 算清楚质量到底花了多少钱：让管理层看到，花一点钱做预防比出了问题再救火划算。

核心概念 ​

质量成本 COQ 的四类 ​

据 ASQ 和维基百科的介绍，质量成本分为"符合性成本"（花钱让质量好）和"非符合性成本"（质量不好的损失）两部分，共四类：

类别含义电子制造的例子
预防成本（Prevention）为了不出问题花的钱员工培训、SOP 编写与修订、防错设计（上料防错）、供应商评审、工艺验证（炉温曲线验证）、SPC 系统
鉴定成本（Appraisal）为了发现问题花的钱来料检验（IQC）、过程检验（IPQC）、AOI/SPI/ICT/FCT 的设备折旧与维护、检验员工资、量具校准、内审
内部损失（Internal Failure）出厂前发现问题造成的损失返修工时与物料、报废板、停线损失、失效分析、重新检验
外部损失（External Failure）出厂后（客户手里）发现问题的损失退货处理、换货、现场服务、保修、客诉处理、赔偿、信誉损失

其中内部损失 + 外部损失合称 COPQ（Cost of Poor Quality，劣质成本）：它们是"如果一切都做对就不会发生的成本"，是改善的目标。维基百科的"Cost of poor quality"词条还提到，失败成本越晚发现越高——供应商处、制造商处、客户处，逐级放大。

一条常引用的经验规律是"1-10-100 法则"：缺陷在预防阶段处理花 1 份钱，在检验阶段处理花 10 份，到客户手里花 100 份。这是粗略的经验说法，具体倍数每家不同，我也没能找到权威出处，只拿来理解"越早越便宜"，不要当数据用。

质量成本在电子厂里最难的是统计：预防和鉴定成本散落在培训费、人工、设备折旧里，内部损失藏在返修工时和报废单里，外部损失在客诉和售后。不少工厂只能做到"内部损失 + 外部损失"这部分（报废 + 返修 + 退货），那也是有价值的起点。

PPM 与 DPMO ​

PPM（Parts Per Million，百万分之几）：每一百万个产品里有多少个不良。

PPM = 不良数 ÷ 总数 × 1,000,000

比如出货 50,000 块板，客户退回 3 块不良，出货 PPM = 3 ÷ 50,000 × 1,000,000 = 60 PPM。

DPMO（Defects Per Million Opportunities，每百万机会缺陷数）：分母不是"板数"，而是"缺陷发生的机会数"。一块板有很多焊点和元件，每个检测点都是一次"机会"。比如一块板 AOI 有 400 个检测点，1000 块板就有 400,000 个机会；发现 62 个缺陷，DPMO = 62 ÷ 400,000 × 1,000,000 = 155。它让不同复杂度的板可以公平比较（大板自然缺陷多）。

FPY 一次通过率 ​

FPY（First Pass Yield）：第一次就通过某道工序的比例，不含返修后再通过的。

某站 FPY = 该站第一次测试就通过的数量 ÷ 该站第一次测试的总数量

它反映"这道工序一次做对的能力"。返修后通过的板，在最终结果里是"合格"，但在 FPY 里算失败——因为这一次就花了额外成本。

RTY 滚动直通率 ​

RTY（Rolled Throughput Yield）：一块板要连续过好几站，每一站都一次通过的概率。把每一站的 FPY 连乘：

RTY = FPY(SPI) × FPY(AOI) × FPY(ICT) × FPY(FCT) × …

用实验里的数字：0.98 × 0.95 × 0.97 × 0.99 = 0.8940（89.40%）。

为什么要连乘？类比：一块板要连闯四关，每关通过概率 98%、95%、97%、99%，四关都一次通过的概率就是乘起来。可以看到，RTY 永远小于任何一站的 FPY，站越多越低。即使每一站都有 95% 以上，整条线的 RTY 也可能不到 90%——这就是"隐藏的浪费"：10% 的板在途中至少返修了一次，而最终合格率仍然显示 100%。

严格的 RTY 公式假设各站的失败是相互独立的。实验里，我把四站的失败板故意设为互不重叠，真正"四站全部一次通过"的有 890 块（89.00%），比 RTY 公式算出的 89.40% 略低。差别不大，但说明：RTY 是估算值，不是真正数出来的"整板一次全过"比例。要精确值，直接数"在所有工站都一次通过的板"。

其他合格率 ​

KPI定义说明
一次合格率通常指某批 / 某站一次检验合格的比例与 FPY 同义的情况很多；有时指整批抽检一次判合格的批数比。用之前先问清楚
最终合格率 / 直通率（Final Yield）最终合格数 ÷ 投入数含返修后合格。实验里可以看到它是 100%，却掩盖了 110 次返修
客诉率客诉件数（或次数）÷ 同期出货数，常折合成 PPM要分清"客诉次数"和"客诉涉及的不良件数"
退货率退货数 ÷ 同期出货数要分清按"出货月"还是"退货月"归属
报废率报废数 ÷ 投入数要明确是数量还是金额
返修率进入返修的板数 ÷ 投入数与 FPY 互补，但 FPY 是按站算的

Cpk 与 PPM 的对应关系 ​

Cpk 是衡量一个过程能力的指数，在 过程能力CPK 里有详细讲解。简单说，Cpk 越大，过程偏离规格上下限的概率越小。当过程服从正态分布、受控且均值居中时（此时 Cpk = Cp），规格限在均值 ±3×Cpk×σ 的位置，双侧超差比例可以用误差函数算出。用 Python 实际算出来：

这就是为什么汽车行业常要求关键特性的 Cpk ≥ 1.33（或 1.67）：过程能力决定了长期的 PPM 水平。反过来：如果测得一个尺寸的 Cpk 是 1.0，你就应该预期大约有 0.27% 的产品超差，别指望 PPM 很低。

这个对应关系有很多前提（正态、受控、居中、抽样足够），现实中的数据常常不满足。有些资料还会说长期过程会有 1.5σ 的漂移（六西格玛的 3.4 DPMO 就是这么来的），这属于另外的约定，本篇不展开。

各 KPI 的计算陷阱：分母怎么选 ​

KPI 最容易出错的就是分母。常见陷阱：

KPI陷阱办法
FPY分母用"投入数"还是"该站测试数"？一块板被重复测试多次，是不是算多次？写明：分母 = 该站第一次测试的不同板码数量；重复测试只算第一次
FPY自动复测（设备自己重测一遍就通过）算不算一次通过？每家规定不同，要写清楚。较严的做法是复测通过也算失败（因为这是设备的不稳定）
FPY报废板、试产板、返修板再次进线算不算分母返修再进线的板不算新投入；试产板与量产板分开统计
RTY各站分母不同（有的板不过某站）每站用各自的分母算 FPY，再连乘；不要把不同站的数量直接乘
PPM（出货）分子是退货发生的月份的退货数，分母是当月出货数时间错位：今天退回的板可能是三个月前出的货。应该按出货批次归属，或用滚动 3 / 12 个月
PPM（出货）样本很小（3 块 / 50,000 块），一块之差就跳变看长期（滚动 12 个月）趋势，而不是单月
DPMO"机会数"怎么定义？每块板 400 个还是 4000 个点先固定一种口径（如按 AOI 检测点数）并长期不变，不然趋势没意义
客诉率一次客诉涉及 100 块板，算 1 次还是 100 件分别统计"客诉次数"和"客诉件数"，口径写进指标定义
退货率分母用出货数量还是出货批数、金额与客户口径对齐，并保留原始口径
最终合格率返修后合格算合格，掩盖了返修成本与 FPY / RTY 一起看，不要单独汇报
所有 KPI不同产线、不同产品比较先看产品复杂度（焊点数）是否可比；用 DPMO 能部分抵消

另一个重要原则：KPI 的定义要写下来、有版本，改定义时要记录生效日期，历史数据要么按新定义重算，要么明确标注断层。否则，今年的 FPY 比去年高了，原来只是分母改了。

技术视角：数据从哪来 ​

KPI 的原始数据来自 MES 的过站记录和不良记录（过站与工序流转、缺陷代码与不良分类）。核心思路：

层内容说明
明细每次测试一行：板码、工位、第几次（Attempt）、结果、缺陷个数体量大，保留原始事实，不要覆盖
汇总按日 / 线 / 工位预汇总 FPY、PPM报表直接读，避免每次全表扫描
口径表（建议）记录每个 KPI 的名称、公式文字、版本、生效日期让口径可追溯

"第几次"（Attempt）很关键。如果过站表只存最后一次结果，FPY 永远算不出来——一次通过和返修后通过混在一起，被覆盖了。所以要只追加每次测试，按 Attempt 区分。

SQL 里没有"连乘"聚合，RTY 用对数技巧：EXP(SUM(LOG(x)))——乘法变加法。

逐步例子：1000 块板过四站 ​

数据（虚构）：1000 块板依次过 SPI、AOI、ICT、FCT 四个站，每块板每站都测一次。第一次不过的送去维修，维修后复测都合格。

FCT100010990990 / 1000 = 0.9900

RTY（手算）：

  1. 0.98 × 0.95 = 0.931
  2. 0.931 × 0.97 = 0.90307
  3. 0.90307 × 0.99 = 0.8940393 ≈ 0.8940

对照：最终合格率 = 4000 次站点测试里，最终都合格 = 1000 / 1000 = 100%；整板"四站全部一次通过" = 1000 − (20 + 50 + 30 + 10) = 890 块，即 89.00%。

第 3 步：RTY、整板一次全过、最终合格率 ​

sql
-- RTY：逐站 FPY 连乘。SQL 没有"连乘"聚合，用 EXP(SUM(LOG(x)))
;WITH f AS (
    SELECT StationCode, 1.0 * SUM(CASE WHEN Result = 'P' THEN 1 ELSE 0 END) / COUNT(*) AS Fpy
    FROM StationResult WHERE Attempt = 1 GROUP BY StationCode)
SELECT CAST(EXP(SUM(LOG(Fpy))) AS DECIMAL(6,4)) AS Rty FROM f;
GO
-- 对照：整板"四站全部一次通过"的比例（真正的整体一次通过率）
SELECT COUNT(*) AS Boards,
       SUM(CASE WHEN Bad = 0 THEN 1 ELSE 0 END) AS AllFirstPass,
       CAST(1.0 * SUM(CASE WHEN Bad = 0 THEN 1 ELSE 0 END) / COUNT(*) AS DECIMAL(6,4)) AS OverallFpy
FROM (SELECT Sn, SUM(CASE WHEN Result = 'F' THEN 1 ELSE 0 END) AS Bad FROM StationResult WHERE Attempt = 1 GROUP BY Sn) t;
GO
-- 陷阱：错用"最终合格率"（把复测算进去）-> 虚高 100%
SELECT CAST(1.0 * COUNT(DISTINCT CASE WHEN Result = 'P' THEN Sn + StationCode END)
            / COUNT(DISTINCT Sn + StationCode) AS DECIMAL(6,4)) AS FinalPassRate
FROM StationResult;
GO

python
"""用同一份数字复算 FPY / RTY / PPM / DPMO，并看 Cpk 与 PPM 的对应关系。"""
import math

tested = {"SPI": 1000, "AOI": 1000, "ICT": 1000, "FCT": 1000}
first_fail = {"SPI": 20, "AOI": 50, "ICT": 30, "FCT": 10}

rty = 1.0
for st in tested:
    fpy = (tested[st] - first_fail[st]) / tested[st]
    rty *= fpy
    print(f"{st} FPY = {tested[st]-first_fail[st]}/{tested[st]} = {fpy:.4f}")
print(f"RTY = 连乘 = {rty:.4f}")

# 整体一次通过：这份数据里四站的不良板互不重叠，所以 1000 - (20+50+30+10) = 890 块一次全过
all_pass = 1000 - sum(first_fail.values())
print(f"整板一次全过 = {all_pass}/1000 = {all_pass/1000:.4f}  (和 RTY 差 {rty - all_pass/1000:.4f})")

# DPMO / PPM
aoi_defects, boards, points = 62, 1000, 400
print(f"AOI DPMO = {aoi_defects}/({boards}x{points}) x 1e6 = {1e6*aoi_defects/(boards*points):.1f}")
print(f"AOI 不良板 PPM = {1e6*first_fail['AOI']/boards:.0f}")
print(f"出货 PPM = 3/50000 x 1e6 = {1e6*3/50000:.0f}")

# 中心对准的正态分布：Cpk -> 双侧超差 PPM（Cpk = Cp，规格限在 ±3·Cpk·σ 处）
def ppm(cpk):
    z = 3 * cpk
    return 1e6 * math.erfc(z / math.sqrt(2))      # 双侧：2*(1-Φ(z)) = erfc(z/√2)
for c in (0.67, 1.00, 1.33, 1.67, 2.00):
    print(f"Cpk={c:.2f}  双侧超差约 {ppm(c):.4g} PPM")

# COQ
coq = {"预防": 10000, "鉴定": 50000, "内部损失": 65000, "外部损失": 25000}
total, sales = sum(coq.values()), 2_000_000
for k, v in coq.items():
    print(f"{k} {v} 占COQ {100*v/total:.1f}% 占销售额 {100*v/sales:.2f}%")
print(f"COQ 合计 {total} = 销售额的 {100*total/sales:.2f}%")

常见坑与排查 ​

现象 / 误区原因与办法
直通率 99%，产线却天天返修汇报的是最终合格率。同时看 FPY 和 RTY
FPY 偏高复测通过被算进了一次通过。只取 Attempt = 1
同一块板在站里扫了三次，分母被放大分母按不同板码数，不是按扫描次数
RTY 直接用各站数量连乘应连乘各站比率；各站分母不同也要用各自的分母
出货 PPM 月度忽高忽低样本小，退货滞后。改看滚动 12 个月，并按出货批次归属
改了 KPI 定义，前后不可比定义要版本化，生效日期之前用旧口径，或重算历史数据
只统计报废，不统计返修成本返修工时、物料也是内部损失；只看报废会低估
质量成本里没有预防和鉴定只统计损失会让管理层误以为"质量没花钱"。逐项归类，至少把数字估出来
把 Cpk 等同于 PPM对应关系有正态、居中、受控等前提，只能作估算
在 SQL 里对 0 或 NULL 取 LOGLOG(0) 会报错；FPY 为 0 的站要特殊处理

练习题与答案 ​

  1. 某站投入 500 块，一次通过 475 块，另有 20 块经返修后通过、5 块报废。FPY 是多少？最终合格率是多少？ 答：FPY = 475 / 500 = 95.0%；最终合格 = 475 + 20 = 495，495 / 500 = 99.0%。
  2. 三站的 FPY 分别是 0.99、0.98、0.97，RTY 是多少？ 答：0.99 × 0.98 = 0.9702，× 0.97 = 0.941094 ≈ 94.1%。
  3. 出货 200,000 块，客户退回 12 块，出货 PPM 是多少？ 答：12 / 200,000 × 1,000,000 = 60 PPM。
  4. 一块板有 500 个 AOI 检测点，检 2000 块，发现 80 个缺陷，DPMO 是多少？ 答：80 / (2000 × 500) × 1,000,000 = 80 / 1,000,000 × 1,000,000 = 80。
  5. 质量成本里，哪两类合称 COPQ？为什么要重点盯它？ 答：内部损失与外部损失。它们是"一切做对就不会发生"的成本，是改善的目标；而且越晚发现越贵。
  6. 为什么 RTY 总是小于任何一站的 FPY？ 答：RTY 是各站 FPY 连乘，每个 FPY 都不超过 1，乘得越多越小。
  7. 为什么"返修后合格"不应该算入 FPY？ 答：FPY 衡量的是工序一次做对的能力，返修已经花了额外的人工和物料；算进去就掩盖了这部分浪费。

小结 ​

  • 质量成本四类：预防、鉴定、内部损失、外部损失；内部 + 外部损失 = COPQ，是改善的重点。越早发现越便宜。
  • PPM = 不良 ÷ 总数 × 10⁶；DPMO 的分母是"机会数"。FPY 只看第一次；RTY = 各站 FPY 连乘，比最终合格率更接近真实的浪费。
  • 本篇实验：FPY = 98% / 95% / 97% / 99%，RTY = 89.40%（手算、SQL、Python 一致），整板一次全过 89.0%，最终合格率 100%。
  • KPI 的难点在口径：分母怎么选、复测算不算、时间怎么归属、定义要版本化。
  • Cpk 越高，长期 PPM 越低（正态、居中时 Cpk 1.33 约 66 PPM），详见 过程能力CPK。
