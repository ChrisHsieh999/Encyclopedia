工程变更流程

AI 生成 · 待核对制造业务PLM变更更新于 2026-10-21

⚠ 待核对：ECR/ECN/ECO 三个词在不同公司含义不完全一样（有的把 ECN 和 ECO 当同一张单），变更分类、会签部门、生效点和旧料处置的规则是电子厂常见的通用做法；你们公司的变更流程、单据名称、会签部门和是否区分紧急变更，请对照你们的制度和系统核实。表设计、状态机和影响分析 SQL 都在本机 SQL Server LocalDB 上实际运行过，数字已手算核对。

本篇是 PLM 系列第 3 篇。读完你应该能：说清 ECR、ECN、ECO 的关系；对一张变更做影响分析（BOM、库存、在制品、已出货）；理解会签、生效点（日期/SN/批次）和旧物料处置；设计变更单的表和状态机；并写出"哪些工单受影响"的 SQL。

一句话定义 ​

工程变更（Engineering Change）是对已发布的产品定义（图纸、BOM、工艺等）做的、有控制的修改，变更流程保证每次修改经过评估、批准，在明确的时间点或序号起生效，并且旧版本该怎么处理有明确的结论。

先修知识 ​

  • 产品数据与文件管理：知道文件有版本和 Released 状态，已发布内容不能直接改。
  • BOM与物料清单：知道 BOM 版本、"工单绑定 BOM 版本"。
  • 工单管理：知道工单有计划开工日、已完成数量等状态。
  • 变更管理ECN-ECR：从质量管理（QMS）角度看同一件事，本篇与它互补，分工见下文。

它解决什么问题 ​

现场故事：A100 用的 MCU IC-MCU-32 厂家发了停产通知。研发在 Excel BOM 里把它改成了 IC-MCU-32B，口头通知了采购。结果：

  • 仓库里还有 1350 颗旧 MCU，没人说怎么处理；
  • 已下发的两张工单还要用旧料，计划员不知道，仍然领新料，新料根本没到货；
  • 另一款产品 A200 也用同一颗 MCU，没人想到它；
  • 已经出货的 680 块板子是旧 MCU，客户要问"哪些板子是旧版"，答不出来。

变更流程要提前把这些问题逐项回答完才允许生效：改什么、为什么改、影响谁、什么时候起生效、旧的怎么办、谁同意了。

核心概念 ​

ECR、ECN、ECO ​

缩写全称含义类比
ECREngineering Change Request变更申请：有人提出"我们该改这个，因为……"提案
ECOEngineering Change Order变更指令/执行单：批准后，列明具体改哪些文件、BOM，由谁执行施工单
ECNEngineering Change Notice变更通知：把已批准的变更通知所有相关方公告

常见的两种做法：

  1. 分两步：先提 ECR，评估通过后生成 ECO，再发 ECN 通知；
  2. 合一张单：一张变更单走完申请、评审、批准、实施，叫 ECN 或 ECO。

本篇实验用一张变更单走完整个生命周期（对应第二种），状态上自然分出"申请评审阶段"和"批准实施阶段"。

变更的分类 ​

分类维度类型说明
紧急程度紧急 / 一般紧急：正在量产线上出问题或停线，需要先行；一般：按正常节奏
来源内部改进 / 客户要求 / 供应商（停产 EOL 等）/ 质量问题来源决定谁主导评审、费用谁承担
影响重大（影响形状/装配/功能，需客户批准）/ 一般 / 文字类重大变更往往要通知客户

紧急变更的常见做法：缩短会签范围（本实验：研发、品质、生产 3 个部门先签），实施后再补其他部门的会签和记录。关键是"紧急"不能变成"跳过流程"。

影响分析：四件事 ​

收到一个变更，先回答这四个问题（实验里每个都有对应 SQL）：

问题查什么回答的是
BOM被改的物料还被哪些产品的 BOM 用？（反向查用，where-used）变更会不会影响其它产品
在制品与工单哪些未完工工单绑着旧版本？各剩多少？哪些要切换，哪些继续用旧版
库存旧料还有多少？够不够用到切换？新料要买多少？采购和计划要做什么
已出货哪些已出货的板子是旧版本？发给了谁？是否要通知客户、是否有召回风险

会签 ​

会签是需要多个部门都同意才算通过。常见部门：研发（RD）、工艺（PE）、品质（QA）、采购（PUR）、生产（PROD），还可能有 PMC（生产计划）、客户代表。两个规则：

  • 一票否决：任一部门拒绝，整张变更单驳回；
  • 各部门只签一次：签过的不能重复签，驳回后要改单重提，不能直接再签。

生效点：从什么时候起用新版本 ​

生效点类型说法适用
日期（Date）"2026-11-02 起投产的工单用新版"最常用，简单
序列号（SN）"从 SN A1000500 起用新版"能精确区分已生产的板子，追溯清晰
批次（Lot）"从物料批次 LOT-2611-01 起用新版"物料批次切换时
用完为止"旧料用完后切换"旧料很贵或量大

"日期"到底指什么日期，要在制度里写清楚：计划开工日？工单下发日？实际首次投产日？本实验约定用计划开工日。

旧版本（旧物料、旧在制品、旧成品）的处置 ​

处置含义什么时候选
用完为止（UseUp）现有的旧料、旧在制品继续用，新生产才用新版新旧兼容、旧料价值高、变更不紧急
报废（Scrap）旧料、旧在制品不再使用旧料有质量或安全问题，不能再用
返工（Rework）对已做好的半成品或成品改造，使其符合新版本改造成本低于报废，如飞线、换一颗料

必须在变更单里写明，因为这直接关系到钱和工期。

与 QMS 变更管理的分工 ​

PLM 的工程变更（本篇）QMS 的变更管理（变更管理ECN-ECR）
关注点数据版本：哪些文件、BOM 从哪个 Rev 变到哪个 Rev，什么时候生效质量风险：变更会不会影响质量，需要做什么验证
典型内容变更明细、影响分析、新版本发布、工单切换风险评估、首件或可靠性验证要求、客户通知、效果确认
产出新版本的文件和 BOM评审结论与验证记录

实际中同一张变更单两边都要用：PLM 负责"改了什么、哪一版"，QMS 负责"改得安不安全、有没有验证"。系统上最好用同一个变更单号把两边串起来，避免录两遍。

业务视角 ​

谁做什么：

  • 发起人（研发、工艺、品质或采购）：提变更，填原因、变更明细；
  • 变更协调员（常由文控或工艺担任）：检查完整性，发起会签，跟踪；
  • 各会签部门：评估本部门影响，签同意或驳回；
  • 计划、仓库、产线：按生效点和旧料处置执行；
  • 文控：发布新版本，回收旧版本。

流程：

Draft（草稿）→ Reviewing（会签中）→ Approved（已批准）→ Implemented（已实施）→ Closed（关闭）
                    ↓ 任一部门驳回
                 Rejected（已驳回）

涉及的单据与记录：变更单（头）、变更明细（改哪个 BOM/文件，哪个 Rev 到哪个 Rev）、会签记录、新版本的 BOM 和文件、旧料处置清单。

KPI：变更单平均周期（从提出到实施）；紧急变更占比；变更后返工或报废金额；因变更没有通知到位导致的生产事故数（目标 0）。

技术视角：表设计与状态机 ​

ChangeOrder    (CoId, CoNo 唯一, Title, Urgency, Status, EffType, EffValue, OldStock, CreatedBy)
ChangeItem     (ItemId, CoId, TargetType BOM/Doc, TargetCode, FromRev, ToRev, OldMaterial, NewMaterial)
ChangeApproval (CoId, Dept, Approver, Decision Pending/Approve/Reject)    主键 (CoId, Dept)
  • 一张变更单可以改多个对象，所以明细单独成表；
  • 会签表在提交时按紧急程度生成"待签"行，之后每个部门只能更新自己那一行；
  • 状态流转写在存储过程里：usp_Submit（草稿到会签中，生成待签行）、usp_SignOff（签字，自动判断是否通过或驳回）、usp_Implement（批准后实施：旧版截止、新版生效、未开工的计划工单改绑新版）；
  • 版本生效期用 ProductRev(ProductCode, Rev, EffFrom, EffTo) 表示，旧版本只设置截止日，不删除，和 BOM与物料清单 里"作废不删除"同理；
  • 用 UPDATE ... FROM ... JOIN 一次改完一批计划工单，放在同一个事务里，要么全成要么全不成。

逐步例子：A100 MCU 停产替换 ​

变更单 ECO-2610-003：A100 的 BOM 从 Rev B 到 Rev C，把 IC-MCU-32 换成 IC-MCU-32B；一般变更；2026-11-02 起生效；旧料用完为止。

现有数据：

工单状态数量 / 已完成计划开工绑定 BOM
WO-2610-001已关闭500 / 50010-05B
WO-2610-002进行中800 / 30010-19B
WO-2610-003已下发600 / 010-28B
WO-2611-001计划中1000 / 011-05B

MCU 库存：仓库 1200，线边 150，共 1350；新料库存 0。已出货：WO-2610-001 发客户甲 480；WO-2610-002 发客户甲 120、客户乙 80。A200 的 BOM 也用 IC-MCU-32。

手算影响分析：

  1. 反向查用：A100 Rev B 用 1 颗，A200 Rev A 用 1 颗 —— A200 也受影响，需另行评估；
  2. 未完工工单：WO-2610-002 剩 800−300 = 500，开工日 10-19 早于 11-02，继续旧版；WO-2610-003 剩 600，10-28 早于 11-02，继续旧版；WO-2611-001 剩 1000，11-05 不早于 11-02，切换新版；已关闭的 WO-2610-001 不在其中；
  3. 库存：旧料需求 500 + 600 = 1100，库存 1350，剩余 250（可留给 A200）；新料需求 1000，库存 0，缺口 1000，采购必须在 11-05 前备齐；
  4. 已出货：客户甲 480 + 120 = 600，客户乙 80，共 680 块是旧 MCU。

下面的实验用 SQL 把这些算一遍，结果应与手算一致。

动手实验：变更审批状态机与受影响工单查询 ​

前提：同 产品数据与文件管理，使用 LocalDB 和 sqlcmd，实验库 Lab_plm（不存在会创建）。脚本只删建本实验自己的表，可反复运行。

第 1 步：新建 eco_schema.sql（建表和三个存储过程），运行 sqlcmd -S "(localdb)\MSSQLLocalDB" -E -C -f 65001 -I -b -i eco_schema.sql：

sql

-- ===== 变更单本身 =====
CREATE TABLE ChangeOrder (
    CoId        INT IDENTITY PRIMARY KEY,
    CoNo        NVARCHAR(20)  NOT NULL UNIQUE,
    Title       NVARCHAR(100) NOT NULL,
    Urgency     NVARCHAR(10)  NOT NULL CHECK (Urgency IN ('Urgent','Normal')),
    Status      NVARCHAR(12)  NOT NULL DEFAULT 'Draft'
        CHECK (Status IN ('Draft','Reviewing','Approved','Rejected','Implemented','Closed')),
    EffType     NVARCHAR(5)   NOT NULL CHECK (EffType IN ('Date','SN','Lot')),   -- 生效点类型
    EffValue    NVARCHAR(30)  NOT NULL,                                        -- 日期 / 起始 SN / 起始批次
    OldStock    NVARCHAR(10)  NOT NULL CHECK (OldStock IN ('UseUp','Scrap','Rework')),  -- 旧料处置
    CreatedBy   NVARCHAR(30)  NOT NULL
);
CREATE TABLE ChangeItem (
    ItemId      INT IDENTITY PRIMARY KEY,
    CoId        INT NOT NULL REFERENCES ChangeOrder(CoId),
    TargetType  NVARCHAR(5)   NOT NULL CHECK (TargetType IN ('BOM','Doc')),
    TargetCode  NVARCHAR(40)  NOT NULL,             -- 产品编码 / 文件编号
    FromRev     NVARCHAR(10)  NOT NULL,
    ToRev       NVARCHAR(10)  NOT NULL,
    OldMaterial NVARCHAR(40)  NULL,                 -- 物料替换类变更：旧料 / 新料
    NewMaterial NVARCHAR(40)  NULL
);
CREATE TABLE ChangeApproval (                       -- 会签：每个部门一行
    CoId      INT NOT NULL REFERENCES ChangeOrder(CoId),
    Dept      NVARCHAR(10) NOT NULL,
    Approver  NVARCHAR(30) NULL,
    Decision  NVARCHAR(8)  NOT NULL DEFAULT 'Pending' CHECK (Decision IN ('Pending','Approve','Reject')),
    PRIMARY KEY (CoId, Dept)
);
-- ===== 受影响对象（演示用的最小业务表）=====
CREATE TABLE ProductRev (                           -- 产品 BOM 版本及其生效期
    ProductCode NVARCHAR(20) NOT NULL, Rev NVARCHAR(10) NOT NULL,
    EffFrom DATE NOT NULL, EffTo DATE NULL,         -- EffTo 为空 = 一直有效
    PRIMARY KEY (ProductCode, Rev)
);
CREATE TABLE BomLine (ProductCode NVARCHAR(20) NOT NULL, Rev NVARCHAR(10) NOT NULL, MaterialCode NVARCHAR(40) NOT NULL, QtyPer INT NOT NULL,
    PRIMARY KEY (ProductCode, Rev, MaterialCode));
CREATE TABLE WorkOrder (
    WoNo NVARCHAR(20) PRIMARY KEY, ProductCode NVARCHAR(20) NOT NULL, BomRev NVARCHAR(10) NOT NULL,
    Qty INT NOT NULL, DoneQty INT NOT NULL, Status NVARCHAR(10) NOT NULL, PlanStart DATE NOT NULL
);
CREATE TABLE StockLot (MaterialCode NVARCHAR(40) NOT NULL, Location NVARCHAR(10) NOT NULL, Qty INT NOT NULL, PRIMARY KEY (MaterialCode, Location));
CREATE TABLE ShipRecord (WoNo NVARCHAR(20) NOT NULL, Customer NVARCHAR(20) NOT NULL, Qty INT NOT NULL, PRIMARY KEY (WoNo, Customer));
GO
-- ===== 状态机 =====
CREATE OR ALTER PROCEDURE usp_Submit @CoId INT AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    DECLARE @st NVARCHAR(12), @urg NVARCHAR(10);
    SELECT @st = Status, @urg = Urgency FROM ChangeOrder WHERE CoId = @CoId;
    IF @st IS NULL THROW 50101, N'变更单不存在', 1;
    IF @st <> 'Draft' THROW 50102, N'只有草稿能提交', 1;
    IF NOT EXISTS (SELECT 1 FROM ChangeItem WHERE CoId = @CoId) THROW 50103, N'变更单没有变更明细，不能提交', 1;
    BEGIN TRAN;
    -- 会签部门：一般变更 5 个部门；紧急变更先由研发、品质、生产 3 个部门会签（其余事后补）
    INSERT ChangeApproval (CoId, Dept)
    SELECT @CoId, d FROM (VALUES ('RD'),('PE'),('QA'),('PUR'),('PROD')) v(d)
    WHERE @urg = 'Normal' OR d IN ('RD','QA','PROD');
    UPDATE ChangeOrder SET Status = 'Reviewing' WHERE CoId = @CoId;
    COMMIT;
END;
GO
CREATE OR ALTER PROCEDURE usp_SignOff @CoId INT, @Dept NVARCHAR(10), @Approver NVARCHAR(30), @Decision NVARCHAR(8) AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF (SELECT Status FROM ChangeOrder WHERE CoId = @CoId) <> 'Reviewing' THROW 50111, N'变更单不在会签中', 1;
    IF NOT EXISTS (SELECT 1 FROM ChangeApproval WHERE CoId = @CoId AND Dept = @Dept AND Decision = 'Pending')
        THROW 50112, N'该部门不需要会签，或已经签过', 1;
    BEGIN TRAN;
    UPDATE ChangeApproval SET Approver = @Approver, Decision = @Decision WHERE CoId = @CoId AND Dept = @Dept;
    UPDATE ChangeOrder SET Status = CASE
            WHEN @Decision = 'Reject' THEN 'Rejected'                                              -- 一票否决
            WHEN NOT EXISTS (SELECT 1 FROM ChangeApproval WHERE CoId = @CoId AND Decision <> 'Approve') THEN 'Approved'   -- 全部通过
            ELSE Status END
    WHERE CoId = @CoId;
    COMMIT;
END;
GO
CREATE OR ALTER PROCEDURE usp_Implement @CoId INT AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF (SELECT Status FROM ChangeOrder WHERE CoId = @CoId) <> 'Approved' THROW 50121, N'只有已批准的变更单能实施', 1;
    IF (SELECT EffType FROM ChangeOrder WHERE CoId = @CoId) <> 'Date' THROW 50122, N'本实验只实现按日期生效', 1;
    BEGIN TRAN;
    DECLARE @eff DATE = (SELECT CAST(EffValue AS DATE) FROM ChangeOrder WHERE CoId = @CoId);
    -- 旧版本到生效日截止，新版本从生效日起（旧版本不删除、不改内容，只设截止日）
    UPDATE p SET EffTo = @eff
    FROM ProductRev p JOIN ChangeItem i ON i.TargetType = 'BOM' AND i.TargetCode = p.ProductCode AND i.FromRev = p.Rev
    WHERE i.CoId = @CoId;
    INSERT ProductRev (ProductCode, Rev, EffFrom) SELECT TargetCode, ToRev, @eff FROM ChangeItem WHERE CoId = @CoId AND TargetType = 'BOM';
    -- 还没开工的计划工单、计划开工日不早于生效日的，改绑新版本
    UPDATE w SET BomRev = i.ToRev
    FROM WorkOrder w JOIN ChangeItem i ON i.TargetType = 'BOM' AND i.TargetCode = w.ProductCode AND i.FromRev = w.BomRev
    WHERE i.CoId = @CoId AND w.Status = 'Planned' AND w.PlanStart >= @eff;
    UPDATE ChangeOrder SET Status = 'Implemented' WHERE CoId = @CoId;
    COMMIT;
END;
GO

常见坑与排查 ​

坑说明与办法
只分析本产品，忘了 where-used同一颗物料可能被别的产品用。必须反向查用
生效日期含义不清计划开工日、下发日、首次投产日结果不同。制度里写死
变更批了但没通知计划和仓库系统要在实施时自动产生待办或通知；至少有"已通知"的记录
旧料处置没写实施时才发现 1350 颗旧料没人管。变更单必填处置方式
紧急变更变成绕过流程缩短流程不等于取消：保留最小会签，事后补签并留痕
已下发工单没处理下发时已经绑定旧版本，必须逐张决定是继续还是切换
变更实施后旧版本被覆盖旧版本只设截止日，不删除，追溯要用
重复提变更同一对象同时有多张未结束的变更会冲突。提交时检查
驳回后直接改状态重新批准驳回要改单重提，会签记录重新生成
PLM 与 QMS 各录一遍用同一个变更单号关联，数据只录一处

练习题与答案 ​

  1. ECR、ECO、ECN 各是什么？ 答：ECR 变更申请，ECO 变更执行指令，ECN 变更通知。很多公司把 ECO 与 ECN 合并成一张单，名称以公司制度为准。
  2. 为什么影响分析要包括"已出货"？ 答：已出货的产品已经带着旧版本，客户可能要求通知、换货或有风险需要追踪，必须知道发给了谁、有多少。
  3. 本例中旧料需求为什么是 1100 而不是 1600？ 答：只有计划开工日早于生效日的工单继续用旧版：500 + 600 = 1100；WO-2611-001 的 1000 块切换到新版，用新料。
  4. 紧急变更为什么只要 3 个部门会签？这有什么风险？ 答：为了快速止损。风险是遗漏了其他部门的意见，所以要事后补签，并保留紧急变更的原因记录。
  5. usp_Implement 为什么要在事务里？ 答：它要同时改旧版截止日、新增新版本、给工单改绑、改变更单状态。任何一步失败而其他成功，数据就会不一致，事务保证要么都做，要么都不做。
  6. 一张已批准的变更单发现写错了生效日，该怎么办？ 答：未实施前可驳回后改单重走会签；已实施后不能直接改，应发起新的变更修正。历史记录不能被覆盖。
  7. 按 SN 生效时，旧版本的 EffTo 还能用日期表示吗？ 答：不能，需要换成 SN 区间（从 SN 到 SN），或同时记录日期和 SN。MES 里过站时以板子的 SN 判断用哪个版本。

小结 ​

  • 工程变更 = 有控制地修改已发布的数据；ECR 申请、ECO 执行、ECN 通知，名称各厂不一。
  • 影响分析四件事：where-used、在制品与工单、库存与缺口、已出货。
  • 会签一票否决，每部门只签一次；紧急变更缩短但不跳过。
  • 生效点要写清（日期/SN/批次），旧物料要有明确处置（用完/报废/返工）。
  • PLM 管数据版本，QMS 管质量评审，用同一个变更单号串起来。
