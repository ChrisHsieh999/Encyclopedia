PLM

本篇是 PLM 系列的总览页。读完你应该能：说清 PLM 是什么、和 PDM 的关系；列出一款电子产品从设计到量产有哪些"工程数据"；说清 PLM、ERP、MES、QMS 各自管什么、数据谁给谁；知道"没有 PLM 系统"的工厂怎么用最低成本把数据管起来；并知道接下来该按什么顺序读本系列其余四篇。

一句话定义 ​

PLM（Product Lifecycle Management，产品生命周期管理）是管理一个产品从构思、设计、试产、量产到停产的全过程中所有"产品定义数据"的方法和系统。据维基百科，它把人、数据、流程和业务系统连起来，覆盖产品的工程设计、制造，以及后期的服务和报废。

用一句更接地气的话：PLM 回答"这个产品，到底应该长什么样？现行的是哪一版？谁批准的？"

先修知识 ​

  • BOM与物料清单：知道 BOM 是什么、为什么要有版本。本系列大量在 BOM 上做文章。
  • 电子制造信息系统全景图：知道 ERP、MES、WMS、QMS 在工厂里各是什么位置。
  • PCB制造流程、SMT与电子组装流程：知道一块板子是怎么做出来的，才明白工程资料要"交付"给谁。

它解决什么问题 ​

先看两个现场故事（情节是典型的虚构，问题是真实常见的）：

故事一：发错了版本的 Gerber。 硬件工程师改了 A100 的 PCB，把 Gerber 打包成 A100_gerber_最终版2.zip 发邮件给板厂，但邮件里附的是前一天的包。板厂照做，500 块裸板到货，贴片线贴到一半，发现一颗电容的位置和 BOM 对不上。损失：500 块板子的板费，加上一条线停了半天。

故事二：生产用了未发布的 BOM。 研发在共享文件夹里的 BOM Excel 上直接改，把一颗电阻换了型号，但还没经过评审。采购看到文件就按新型号下了单，生产领的料还是旧型号，现场板子上两种电阻混着用，出了问题谁也说不清哪块板用的哪种。

这两个故事的共同点是：没人能确定"现行有效的那一版"是哪一版。PLM 要做的就是：

  • 一个真相源：每份工程资料有唯一编号，同一时间只有一个"已发布的现行版"；
  • 有控制的修改：改动要走流程（评审、批准），有记录，旧版本不丢，见 产品数据与文件管理、工程变更流程；
  • 把数据正确地交给下游：BOM 交给 ERP、工艺资料交给 MES 和产线、Gerber 交给板厂，见 BOM在PLM与ERP间的流转、Gerber与工程资料发布；
  • 能回头查：一块三年前出货的板子，当时按哪一版图纸和 BOM 做的，能查到。

核心概念 ​

PLM 和 PDM、CAD、ERP 的关系 ​

名称全称关注点一句话
CAD / EDA计算机辅助设计 / 电子设计自动化画图工程师画原理图、PCB 的工具（如 Altium、Cadence、KiCad）
PDMProduct Data Management 产品数据管理管文件和 BOM管设计阶段的数据：文件版本、签入签出、BOM
PLMProduct Lifecycle Management管全生命周期在 PDM 之上，加上流程、变更、项目、供应链协同，一直管到停产
ERPEnterprise Resource Planning管资源和钱采购、库存、成本、订单，见 ERP

维基百科指出"变更管理是 PDM/PLM 的重要部分"，PDM 一般被看作 PLM 的基础部分。实际中大家常常混着叫：很多厂说的"PLM"其实只是 PDM 的功能。本系列不纠结叫法，只讲这些事该怎么管。

产品的生命周期：四个阶段 ​

据维基百科，生命周期可以分为构思（Conceive）、设计（Design）、实现（Realize）、服务（Service）。放到电子产品上：

阶段做什么产出的主要数据
构思定需求、定方案、评估风险需求文档、规格书草稿
设计画原理图和 PCB、选型、打样、测试原理图、PCB Layout、EBOM、样机测试报告
实现试产、量产准备、认证Gerber、MBOM、工艺文件、钢网、认证文件
服务量产、售后、改版、停产变更单、维修资料、停产通知

电子产品的 PLM 管什么 ​

一款电子产品（比如本知识库里反复用的 A100 控制板）的"产品定义数据"有这些：

数据例子谁产出交给谁
原理图（Schematic）A100_sch_revB.pdf 和源文件硬件工程师评审、PCB 设计、测试
PCB Layout板框、层叠、走线、封装硬件/Layout 工程师板厂、贴片厂
Gerber 与钻孔文件铜层、阻焊、丝印、钻孔由 Layout 导出板厂，见 Gerber与工程资料发布
坐标文件（CPL）每个元件的位号、坐标、角度由 Layout 导出SMT 编程
EBOM（工程 BOM）按设计，位号一一对应硬件工程师采购评估、工艺
MBOM（制造 BOM）加了辅料、工序归属、损耗工艺/生产工程师ERP、MES、仓库
规格书（Datasheet）与承认书元件厂商的资料；客户或内部的产品规格元件厂/研发评审、品质
测试规范ICT/FCT 的测试项和标准测试工程师产线、MES
认证文件RoHS、CE、UL、EMC 报告品质/认证工程师客户、销售
变更记录ECN/ECO，见 工程变更流程谁改谁发起全部相关部门

从 EBOM 到 MBOM：同一个产品的两种"配方" ​

EBOM（Engineering BOM，工程 BOM）是设计师眼里的产品：画了什么就是什么，每个元件有位号（R1、C5 这类），数量等于位号个数。MBOM（Manufacturing BOM，制造 BOM）是工厂眼里的产品：除了设计里的元件，还要有锡膏、标签这类设计里不画、生产要用的东西；不贴的元件（DNP）要去掉；结构要按"先贴板、再装机"的工序层级重排。

这是 PLM 和 ERP/MES 之间最重要、也最容易出错的一道转换，详见 BOM在PLM与ERP间的流转。

PLM、ERP、MES、QMS 怎么分工 ​

系统管什么对产品数据的态度
PLM产品怎么定义：文件、EBOM、变更源头，定义数据在这里诞生和修改
ERP买什么、做多少、花多少钱：MBOM、采购、库存账、成本消费并扩充：接收发布的 BOM，加上价格、供应商等商务信息，见 主数据与物料编码
MES车间怎么做、做到哪：工单、过站、追溯使用：按已发布的 BOM 和工艺路线执行，不改定义，见 ERP与MES衔接
QMS做得对不对：检验、不良、变更评审评审者：变更要经过质量评审，见 变更管理ECN-ECR

一个简单的记法：PLM 是"设计院"，ERP 是"财务加采购"，MES 是"车间主任"，QMS 是"质检科"。

PLM 的价值与现实 ​

理想中的 PLM 价值：缩短研发周期、减少因版本混乱造成的报废、变更可追溯、BOM 一次做对。现实中要清醒几点：

  1. 很多电子厂根本没有 PLM 系统。设计数据在工程师电脑和共享文件夹里，BOM 是 Excel，变更靠邮件和纸质签字。这并不罕见，规模不大的厂尤其如此。
  2. 买一套 PLM 不等于管好了。PLM 是"流程+规则+系统"，规则没定好，系统只是更贵的文件夹。
  3. 公司自研 MES/QMS 时，常常缺一个"源头"：MES 里的 BOM 是谁录的？是从 Excel 复制的吗？如果是，那么 MES 其实在兼职做 PLM 的活，容易出错。
  4. 最小可行的做法见本篇实验：先从"文件有唯一编号、版本只有一个现行、变更有单子"这三条做起，用数据库加一点规则就能落地，不一定要一上来买大系统。

业务视角 ​

谁在用：

  • 硬件工程师/Layout 工程师：创建和修改设计数据；
  • 工艺/生产工程师：把 EBOM 转成 MBOM，编制工艺文件、钢网和贴片程序；
  • 文控（DCC，Document Control Center，文件控制中心）：管文件编号、发布、回收旧版本；
  • 品质工程师：参与变更评审，管认证文件；
  • 采购、计划：根据发布的 BOM 采购、排产。

典型流程：

  1. 立项，分配产品编码和文件编号；
  2. 设计阶段：工程师在草稿状态下编辑文件，EBOM 逐步成形；
  3. 试产前：评审，EBOM 转 MBOM，发布给 ERP 和 MES，制造包（Gerber 等）发给板厂；
  4. 量产后：任何改动走变更单，评审、会签、选定生效点，新版本发布；
  5. 停产：发停产通知，数据归档，不删除。

KPI：变更单平均处理周期；BOM 发布后因 BOM 错误导致的返工次数；文件"发布一次通过率"；现场使用非现行版本文件的次数（目标是 0）。

技术视角：各系统里"产品数据"谁说了算 ​

在自研体系下，最重要的设计问题是：每类数据的"主数据源"是谁？ 下表是一个常见的取舍，需要你们对照实际：

数据建议主数据源其他系统怎么用
文件及其版本、状态PLM（没有就自建文件表）MES 只存"文件编号+版本"的引用，不存文件本体
物料编码、规格ERP 或专门的物料主数据，见 主数据与物料编码PLM 和 MES 引用编码
EBOMPLM只读引用
MBOMPLM 生成，ERP 作为"生效"的主数据源MES 接收并绑定到工单
变更单PLM（技术变更）+ QMS（质量评审）全部引用变更单号

后面几篇的表设计（Document/DocumentVersion、ChangeOrder/ChangeItem、BOM 版本表）可以放在一个独立的 PLM 库里，也可以先放在 MES 库里，逐步演化。

import re
from collections import defaultdict

files = [                                   # 假想的共享文件夹里的文件
    "DOC-A100-SCH_RevA.pdf", "DOC-A100-SCH_RevB.pdf", "DOC-A100-SCH_RevC.pdf",
    "DOC-A100-GBR_RevB.zip", "A100_BOM_最终版.xlsx", "A100_BOM_最终版2.xlsx",
    "DOC-A100-BOM_RevB.xlsx", "新建文件夹.zip", "DOC-A100-PCB_Rev1.0.pdf",
]
PATTERN = re.compile(r"^(?P<no>DOC-[A-Z0-9]+-[A-Z]{3})_Rev(?P<rev>[A-Z])\.(?P<ext>\w+)$")

versions, bad = defaultdict(list), []
for name in files:
    m = PATTERN.match(name)
    if m:
        versions[m["no"]].append(m["rev"])
    else:
        bad.append(name)

print(f"共 {len(files)} 个文件，命名合格 {sum(len(v) for v in versions.values())} 个，不合格 {len(bad)} 个")
for name in bad:
    print("  不合格：", name)
for no, revs in sorted(versions.items()):
    note = "  <- 多个版本并存，哪个是现行版？" if len(revs) > 1 else ""
    print(f"  {no}: {', '.join(sorted(revs))}{note}")

常见坑与排查 ​

坑说明与办法
以为买了 PLM 就万事大吉先定规则（编号、版本、流程、权限）再选系统；系统只是执行规则
文件放邮件和聊天工具里发出去的是"副本"，没有版本控制。发布要从唯一的库里取
EBOM 和 MBOM 混为一个设计要的和生产要的不同，混在一起会出现"位号对不上数量"或"漏辅料"
ERP、MES 各存一份 BOM 且手工同步一定会不一致。明确主数据源，用接口或定时同步
旧版本被覆盖或删除追溯就断了。只作废不删除
没有人负责文控再好的系统也会烂。要有人（哪怕兼职）负责发布与回收
公司自研系统没有"源头"MES 里的 BOM 来自 Excel，错误无人把关。至少要有一个受控的 BOM 版本表

练习题与答案 ​

  1. PLM 和 PDM 的区别是什么？ 答：PDM 偏重设计阶段的文件和 BOM 管理；PLM 在其上扩展到变更、项目、协同，覆盖从构思到停产的全过程。实际常混用。
  2. 为什么说"现行有效版本"是 PLM 的核心问题？ 答：设计、采购、生产、检验各部门若依据不同版本工作，就会出现板子贴错、物料买错、追溯对不上。PLM 保证同一时间同一份资料只有一个现行版。
  3. EBOM 与 MBOM 各举两个差异。 答：EBOM 有设计预留不贴的元件（DNP），MBOM 没有；MBOM 有锡膏、标签等辅料，EBOM 没有；EBOM 按位号平铺，MBOM 按工序分层。
  4. 以下数据，主数据源该是谁？文件版本、物料编码、工单。 答：文件版本在 PLM（或自建文件表）；物料编码在 ERP 或物料主数据；工单在 ERP 下达、MES 执行（见 工单管理）。
  5. 本篇实验里 DOC-A100-SCH 有 A、B、C 三版，如果文件夹里还有一份 DOC-A100-SCH_RevD.pdf 标注"草稿"，检查脚本能发现吗？ 答：不能。文件名无法表达状态。要靠数据库里的 Status 字段，见 产品数据与文件管理。

小结 ​

  • PLM 管产品定义数据的整个生命周期，核心是"唯一真相源 + 受控修改 + 正确交付 + 可追溯"。
  • 电子产品的定义数据包括原理图、PCB、Gerber、坐标、EBOM/MBOM、规格书、测试规范、认证文件和变更记录。
  • PLM 是源头，ERP 扩充商务信息，MES 执行，QMS 评审；要先明确每类数据的主数据源。
  • 很多厂只有文件夹加 Excel，可以先用数据库和规则落实"唯一现行版、变更有单子"。
