收货与上架

AI 生成 · 待核对制造业务WMS入库更新于 2026-10-21

⚠ 待核对：收货流程、ASN 字段、超收容差、上架策略都是行业通用做法，你们自研 WMS 的单据名、状态、检验与入库的先后顺序可能不同（比如有的厂"先检验后入库"，有的"先入待检区再检验"），请对照你们的系统。超收容差 2% 是我举的例子，不是标准。表结构与 T-SQL 在本机 LocalDB 临时库 Lab_wms1 里实际运行过。

本篇是 WMS 系列第 3 篇。读完你应该能：说清一批货从"供应商发货"到"放上货架可以被领用"要经过哪几步；理解 ASN、待检区、IQC 放行和上架之间的关系；写出"按 ASN 收货且不超收"的条件 UPDATE；用 SQL 做简单的上架库位推荐；并算出一批货该打几张标签。

一句话定义 ​

收货是把供应商送来的货与到货通知（ASN）核对、点数、记账，先放进"待检区"；上架是等检验放行后，把货搬到货架上的某个库位并更新库存。两步合起来就是"入库"。

先修知识 ​

  • 仓库基础概念：库区、库位、包装层级（卷/盘/箱）。
  • 库存管理与批次序列号：本篇用到里面的四张核心表和 usp_Receive、usp_Move。
  • IQC来料检验：知道来料检验检什么、结论有哪几种。

它解决什么问题 ​

场景一：供应商说发了 20000 个电阻，实际只来了 18000。如果仓管员"看着差不多就签收"，账上记 20000，生产领料时才发现少 2000，线上停线等料。

场景二：一批 IC 到货，还没检验，仓管员为了省事直接放上货架，生产线的人看到有货就领走贴到板子上，几天后 IQC 判这批不合格——板子已经做出去了，要追回、返工。

场景三：同样一批 20000 个电阻，仓管员随手塞进了离门最近的库位，三个月后另一个人找不到。

收货与上架的规矩就是为了这三件事：货和单对得上、没检验的货不能用、每件货的位置有据可查。

核心概念 ​

ASN 与采购订单 ​

  • 采购订单 PO（Purchase Order）：公司向供应商下的订单，在 ERP 里（见 采购管理）。
  • 到货通知 ASN（Advance Shipping Notice）：供应商发货前（或同时）告知"我发了什么、多少、哪个批次、几箱"。有的是供应商系统发来的，有的是采购/仓库根据送货单手工录入的。它是收货时核对的依据。

ASN 里最少有：ASN 号、供应商、对应的 PO 号、行（物料、计划数量），更详细的还有批次号、日期码、箱数、每箱数量。

没有 ASN 的货（急料、样品、退货换货）通常走"无 ASN 收货"，要求更高权限或事后补单。

收货的几步 ​

  1. 核对：送货单 / ASN 对实物：料号、数量、批次、日期码、包装有没有破损、湿敏元件的防潮包装是否完好。
  2. 点数：整箱/整卷核对数量，必要时抽点。电子料很多是以"卷（reel）"为单位，常用点料机（X-ray 点料机）数；小数量用称重估算再确认。
  3. 收货入库：生成收货记录，库存以 QC 状态进入收货待检区（本系列中是库位 RM-RCV-01），写 Receive 流水。
  4. 贴标签：给每个最小包装（每卷/每盘/每箱）打印内部标签，见下文和 物料标签与条码。
  5. 通知检验：向 IQC 推送检验任务。检验结论出来后：合格 → 上架；不合格 → 转不良区，交 不合格品控制NCR 处理。

超收、短收与容差 ​

收货数量和 ASN 计划量几乎总会有出入。常见规则：

  • 短收：来的比计划少，可以收，但 ASN 行保持未完成，等补货或人工关闭；
  • 超收：来的比计划多，在容差范围内（比如计划量的 ±2%，或某些料不允许超收）可以收，超过就拒收或走审批；
  • 容差应该是可配置的规则，而且常按物料或供应商分别设定。

技术上，"累计收货量不超过计划量×(1+容差)"也用条件 UPDATE 实现（和 工单管理 里的防超报一模一样），防止两个仓管员同时扫同一张 ASN 把数量收超了。

待检区 ​

待检区是物理上隔离的区域（或货架），加上库存状态 QC 的"双保险"：

  • 物理上：待检的货放在专门位置，贴"待检"标识，不和合格品混放；
  • 系统上：状态是 QC，拣货算法不会选它（见 拣货与发料）。

有些厂对关键物料设"免检"或"绿色通道"（信得过供应商、已有 COC 合格证的免检），这些货可以直接收为 Available。这是流程设计的选择，不是技术问题。

与 IQC 的衔接 ​

检验放行是整个流程的关卡。WMS 与 QMS 之间的最小约定是：

方向内容
WMS → IQC检验任务：物料、批次、数量、收货单号、存放位置
IQC → WMS检验结论：合格 / 不合格 / 让步接收，附检验单号

收到"合格"后，WMS 才执行上架（QC → Available）；收到"不合格"后，转成 Defect 状态移到不良区。接口细节见 WMS与MES交互 和 MES与QMS衔接。

上架策略 ​

上架（Putaway）：决定"这批货放哪个库位"，常见策略：

策略做法好处 / 代价
固定库位每种物料有指定库位好找；库位可能空着浪费
随机库位哪里有空放哪里空间利用率高；靠系统记位置，人记不住
就近 / 同料号合并优先放有同料号的库位拣货集中，少跑腿
按周转分区（ABC）快周转放近处、低层，慢周转放远处、高处（见 仓库基础概念）拣货效率高
约束过滤库位未锁定、容量够、湿敏料放干燥柜、防静电要求必须满足，是策略的前提

先用"约束"过滤掉不能用的库位（锁定的、满的、类型不对的），再用"偏好"排序（同料号优先、剩余空间最小优先……），取第一个。

标签打印 ​

收货后每个最小包装要有内部标签，至少包含：物料编码、批次、日期码、数量、条码（二维码或一维码），电子料还要有湿敏等级、收货日期。关键原则：

  • 一包装一张标签，标签上的数量是这个包装的数量；
  • 一次收货的数量按标准包装量 SPQ（Standard Package Quantity）拆成若干包装：比如 12000 个、SPQ 10000，是 2 张标签，数量分别是 10000 和 2000（最后一张是余数）；
  • 标签上的条码，上架、拣货时扫描校验，防止拿错。

业务视角 ​

角色：仓管员（收货、贴标、上架）、采购（维护 PO、处理差异）、IQC（检验）、品质（处理不合格）。

单据：PO → ASN → 收货单 → 检验单 → 上架单 → （不合格）NCR。

规则：

  • 无 ASN / 无 PO 不收货（特批除外）；
  • 超收超过容差必须审批；
  • 湿敏元件必须核对防潮包装，开包时间要记录；
  • 待检品不能被领用；
  • 收货当天完成点数和入账，避免"货到了账上没有"。

KPI：收货及时率（到货到入账的时间）、收货准确率、IQC 放行周期（到货到可用的小时数）、上架准确率。

技术视角 ​

表设计 ​

在 库存管理与批次序列号 的四张核心表之外，收货需要 ASN 的表头和行：

sql
CREATE TABLE AsnHeader (
    AsnNo        nvarchar(30) NOT NULL PRIMARY KEY,
    SupplierCode nvarchar(20) NOT NULL,
    PoNo         nvarchar(30) NOT NULL,
    Status       nvarchar(20) NOT NULL DEFAULT N'Open'      -- Open / Receiving / Closed
);
CREATE TABLE AsnLine (
    AsnNo        nvarchar(30)  NOT NULL REFERENCES AsnHeader(AsnNo),
    LineNum      int           NOT NULL,
    MaterialCode nvarchar(30)  NOT NULL REFERENCES Material(MaterialCode),
    PlanQty      decimal(18,3) NOT NULL,
    ReceivedQty  decimal(18,3) NOT NULL DEFAULT 0,
    PRIMARY KEY (AsnNo, LineNum)
);

注意：LINENO 是 T-SQL 的保留字，所以行号列叫 LineNum。

关键 SQL：按 ASN 收货 ​

sql
UPDATE AsnLine SET ReceivedQty = ReceivedQty + @Qty, @mat = MaterialCode
 WHERE AsnNo = @AsnNo AND LineNum = @LineNum
   AND ReceivedQty + @Qty <= PlanQty * (1 + @Tol);
IF @@ROWCOUNT = 0 THROW 50040, N'超过 ASN 计划数量（含容差）...', 1;

一条语句同时完成"累计不超过上限"的检查和累加，并把物料号顺手取出来（@mat = MaterialCode）。后面再把库存加进待检位、写 Receive 流水，整段放在一个事务里。

上架库位推荐 ​

用"约束过滤 + 偏好排序"写成一个查询：

sql
SELECT l.LocationCode, l.Capacity - ISNULL(u.Used, 0) AS Free,
       CASE WHEN ISNULL(s.SameMat, 0) > 0 THEN N'同料号' ELSE N'-' END AS SameMaterial
FROM Location l
LEFT JOIN (SELECT LocationCode, SUM(Qty) AS Used    FROM Inventory GROUP BY LocationCode) u ON u.LocationCode = l.LocationCode
LEFT JOIN (SELECT LocationCode, SUM(Qty) AS SameMat FROM Inventory WHERE MaterialCode = @m GROUP BY LocationCode) s ON s.LocationCode = l.LocationCode
WHERE l.Zone = N'STORE' AND l.Status = N'Active' AND l.Capacity - ISNULL(u.Used, 0) >= @need
ORDER BY CASE WHEN ISNULL(s.SameMat, 0) > 0 THEN 0 ELSE 1 END, l.Capacity - ISNULL(u.Used, 0);

WHERE 是约束（存储区、未锁定、容量够），ORDER BY 是偏好（先同料号，再剩余空间小的优先）。真实系统的容量要考虑体积、重量、库位类型，这里为了好懂只用数量。

与 IQC 的接口要点 ​

  • 检验结论回写要幂等：IQC 重复推送"合格"不能重复上架（usp_Move 的条件 UPDATE 会拒绝第二次，因为 QC 行已经没了）；
  • 检验期间如果有人要紧急领用（特采），要走特批流程，由品质改状态，而不是仓管员自己改；
  • 检验结论变更（合格后又发现问题）走冻结流程，见 库存管理与批次序列号。

逐步例子 ​

供应商 SUP-001 发来 ASN-100，对应 PO-5001，第 1 行：R-10K-0402，计划 20000，容差 2%（上限 20400）。仓里原有一个被锁定的库位 RM-A-03-01，RM-A-01-01 放着 40000 个别的批次的同料号电阻。

  1. 第一车到 12000：累计 12000 ≤ 20400，收货成功；
  2. 又来 9000：累计 21000 > 20400，被拒绝（要么只收 8400 以内，要么找采购走超收审批）；
  3. 实际决定先收 8000：累计 20000，成功；
  4. 再想多收 500：累计 20500 > 20400，被拒绝；
  5. 第一车 12000 按 SPQ=10000 打 2 张标签：10000 和 2000；
  6. IQC 合格，推荐库位：RM-A-01-01 剩余 20000 且有同料号，排第一；
  7. 上架到 RM-A-01-01；
  8. 另一批 L2613E 5000 个检验不合格，转到 QH-NG-01（Defect）；评审结论：3000 让步接收（转回 Available），2000 报废。

-- 到货通知 ASN：表头 + 行
CREATE TABLE AsnHeader (
    AsnNo        nvarchar(30) NOT NULL PRIMARY KEY,
    SupplierCode nvarchar(20) NOT NULL,
    PoNo         nvarchar(30) NOT NULL,
    Status       nvarchar(20) NOT NULL DEFAULT N'Open'      -- Open / Receiving / Closed
);
CREATE TABLE AsnLine (
    AsnNo        nvarchar(30)  NOT NULL REFERENCES AsnHeader(AsnNo),
    LineNum      int           NOT NULL,
    MaterialCode nvarchar(30)  NOT NULL REFERENCES Material(MaterialCode),
    PlanQty      decimal(18,3) NOT NULL,
    ReceivedQty  decimal(18,3) NOT NULL DEFAULT 0,
    PRIMARY KEY (AsnNo, LineNum)
);
GO
-- 按 ASN 收货：条件 UPDATE 同时检查"累计收货不超过计划数量 x (1 + 容差)"，通过后收进待检区
CREATE PROCEDURE usp_ReceiveAsn
    @AsnNo nvarchar(30), @LineNum int, @Lot nvarchar(30), @DateCode nvarchar(10),
    @Qty decimal(18,3), @DocNo nvarchar(30), @Tol decimal(5,4) = 0.02
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    BEGIN TRY
    BEGIN TRAN;
    DECLARE @mat nvarchar(30);
    UPDATE AsnLine SET ReceivedQty = ReceivedQty + @Qty, @mat = MaterialCode
     WHERE AsnNo = @AsnNo AND LineNum = @LineNum AND ReceivedQty + @Qty <= PlanQty * (1 + @Tol);
    IF @@ROWCOUNT = 0 THROW 50040, N'超过 ASN 计划数量（含容差）或 ASN 行不存在，收货被拒绝', 1;
    UPDATE Inventory SET Qty = Qty + @Qty
     WHERE MaterialCode = @mat AND LotNo = @Lot AND LocationCode = N'RM-RCV-01' AND Status = N'QC';
    IF @@ROWCOUNT = 0
        INSERT Inventory (MaterialCode, LotNo, DateCode, LocationCode, Qty, Status, ReceivedAt)
        VALUES (@mat, @Lot, @DateCode, N'RM-RCV-01', @Qty, N'QC', SYSDATETIME());
    INSERT InvTxn (TxnType, MaterialCode, LotNo, FromLoc, ToLoc, Qty, DocNo)
    VALUES (N'Receive', @mat, @Lot, NULL, N'RM-RCV-01', @Qty, @DocNo);
    UPDATE AsnHeader SET Status = N'Receiving' WHERE AsnNo = @AsnNo AND Status = N'Open';
    COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;
    END CATCH
END
GO
SET NOCOUNT ON;
-- 准备：一个被锁定的库位；两个库位里已有期初库存（用 Adjust 建账）
INSERT Location (LocationCode, WhCode, Zone, Capacity, Status) VALUES (N'RM-A-03-01', N'RM', N'STORE', 60000, N'Locked');

EXEC usp_Receive N'Adjust', N'C-100N-0402', N'L2601Y', N'2631', N'RM-A-01-02', N'Available', 25000, N'OPEN-001', '2026-09-02 09:00:00';

SELECT AsnNo, LineNum, PlanQty, ReceivedQty FROM AsnLine;
SELECT LotNo, LocationCode, Qty, Status FROM Inventory WHERE Status = N'QC';

PRINT N'== 2. 标签：第一次收的 12000，SPQ=10000，应打几张';
DECLARE @spq decimal(18,3) = (SELECT Spq FROM Material WHERE MaterialCode = N'R-10K-0402'), @q decimal(18,3) = 12000;
WITH n AS (SELECT 1 AS seq UNION ALL SELECT seq + 1 FROM n WHERE seq < CEILING(@q / @spq))
SELECT N'L2612D-' + RIGHT(N'00' + CAST(seq AS nvarchar(3)), 3) AS ReelNo,
       CASE WHEN seq * @spq <= @q THEN @spq ELSE @q - (seq - 1) * @spq END AS Qty
FROM n;

PRINT N'== 3. IQC 合格后，L2612D 共 20000 要上架：推荐库位';
DECLARE @m nvarchar(30) = N'R-10K-0402', @need decimal(18,3) = 20000;
SELECT l.LocationCode,
       l.Capacity - ISNULL(u.Used, 0) AS Free,
       CASE WHEN ISNULL(s.SameMat, 0) > 0 THEN N'同料号' ELSE N'-' END AS SameMaterial
FROM Location l
LEFT JOIN (SELECT LocationCode, SUM(Qty) AS Used    FROM Inventory GROUP BY LocationCode) u ON u.LocationCode = l.LocationCode
LEFT JOIN (SELECT LocationCode, SUM(Qty) AS SameMat FROM Inventory WHERE MaterialCode = @m GROUP BY LocationCode) s ON s.LocationCode = l.LocationCode
WHERE l.Zone = N'STORE' AND l.Status = N'Active' AND l.Capacity - ISNULL(u.Used, 0) >= @need
ORDER BY CASE WHEN ISNULL(s.SameMat, 0) > 0 THEN 0 ELSE 1 END, l.Capacity - ISNULL(u.Used, 0);

常见坑与排查 ​

误区 / 坑事实与办法
待检品直接收成可用没检验的料被领用，出问题要追回。统一收成 QC，放行才变 Available
收货靠"先查累计再加"并发会超收。累计检查写进 UPDATE 的 WHERE
不管 SPQ，一次只打一张大标签拆包后各包装没有独立标签，拣货、盘点都扫不了。按 SPQ 拆分打标签
上架不检查库位状态货放进了正在盘点的锁定库位。过滤掉 Locked 的库位
IQC 重复推送放行接口要幂等，条件 UPDATE 自然拒绝第二次
湿敏元件到货不核对防潮包装受潮的料上线会"爆米花"。收货时检查真空包装和湿度卡，见 MSD湿敏元件管理
让步接收没有留痕必须有评审单号、签批人，库存状态转换也要有流水
货到了账没记系统库存比实物少，计划误以为缺料。当天收当天记

练习题与答案 ​

  1. 为什么收货时库存先进 QC 而不是直接 Available？ 答：因为还没检验，不知道合不合格。QC 状态加待检区物理隔离，保证没检验的货不会被发料。
  2. ASN 计划 5000，容差 2%，已收 4900，再来 200 能收吗？ 答：能。上限 5000 × 1.02 = 5100，4900 + 200 = 5100，条件是"≤"，刚好可以；再来 201 就不行。（边界要小心：数量和容差都用 decimal，别用浮点数。）
  3. 收货 25000 个，SPQ=10000，打几张标签、每张多少？ 答：3 张：10000、10000、5000。
  4. 为什么上架推荐要先"约束过滤"再"偏好排序"？ 答：约束是必须满足的条件（库位没锁、容量够、类型对），不满足就不能放；偏好只是优化，多个都满足时才有意义。
  5. 同一批货分两次到，批次号一样，库存会不会有两行？ 答：在同一库位、同一状态、同一批次下只有一行，两次收货数量累加；如果放在不同库位，就是不同的行。
  6. IQC 判不合格，库存该怎么处理？ 答：把 QC 的库存用 Transfer 转到不良区、状态改成 Defect，再按评审结论：退供应商、让步接收（转回 Available）或报废（Scrap）。

小结 ​

  • 收货核对 ASN、点数、记账，先进待检区（QC）；IQC 合格后上架变 Available。
  • 超收用"累计 ≤ 计划 × (1 + 容差)"的条件 UPDATE 防并发。
  • 上架 = 约束过滤 + 偏好排序，库位状态、容量、料特性是约束。
  • 标签按 SPQ 拆分，每个最小包装一张。
  • 不合格品转 Defect，评审后让步接收或报废，每一步都留流水。
