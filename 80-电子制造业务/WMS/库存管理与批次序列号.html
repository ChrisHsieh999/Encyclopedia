库存管理与批次序列号

AI 生成 · 待核对制造业务WMS库存更新于 2026-10-21

⚠ 待核对：库存状态的叫法（Available、QC、Hold、Defect）、流水类型（Receive、PutAway、Issue……）是本系列为了教学约定的通用做法，你们自研 WMS 一定有自己的状态和单据命名，请对照你们的系统。本篇的表结构、存储过程、C# 代码都是我在本机 SQL Server LocalDB 的临时库 Lab_wms1 里实际运行过的，输出照抄实际结果；这个库用完已删除。

本篇是 WMS 系列的第 6 篇，也是整个系列的"地基"：后面所有篇（收货、拣货、盘点、FIFO、账实一致……）都建立在这里定义的四张核心表上。读完你应该能：说清库存为什么要用"物料 + 批次 + 库位 + 状态"四个维度来记；建出 Warehouse、Location、Inventory、InvTxn 四张表；理解"流水账只追加"和"库存 = 流水之和"；用条件 UPDATE 写出不会超扣的扣减；并亲眼看到并发下"先读后写"的写法如何把库存算错。

一句话定义 ​

库存（Inventory）是仓库里"此刻有什么、有多少、放哪里、能不能用"的账；库存流水（InvTxn，inventory transaction）是这本账上每一次变化的只追加记录。库存表回答"现在有多少"，流水表回答"为什么是这么多"。

先修知识 ​

  • 仓库基础概念：知道仓库、库区、库位、物料、批次这些词。
  • 事务与ACID：知道"事务"是一组要么全成功、要么全失败的操作。
  • 会写基本的 INSERT、UPDATE、SELECT ... GROUP BY（见 SQL增删改、SQL聚合与分组）。

它解决什么问题 ​

先看一个车间里真实会发生的故事。

仓库里有一卷 10K 电阻，批次 L2610A，共 20000 个。品质判定其中 500 个有疑问，要冻结；产线正好来领料 5000 个；同一时间另一个人在盘点，数出来比账面少 10 个。如果库存只有一个数字"R-10K-0402 = 20000"：

  • 冻结的 500 个算不算可用？产线领料时能不能领到？
  • 领走 5000 后剩多少？是谁、为哪张工单领的？
  • 盘点少了 10 个，是谁多拿了，还是之前记错了？
  • 半年后客户投诉某批板子电阻有问题，要查"这一批电阻用在哪些工单上"——只有总数根本答不了。

库存管理要解决的就是这几个问题：同一种物料要按批次、库位、状态拆开记，每次变化都留下不可篡改的流水，这样才能做到可控（冻结的不被领走）、可查（谁在什么时候动了什么）、可追溯（批次用到了哪里）、可对账（库存和流水互相核对）。

核心概念 ​

库存的四个维度 ​

一行库存回答的是：哪种物料、哪一批、放在哪个库位、处于什么状态，有多少个。所以库存表的"身份"是四个字段的组合：

维度字段例子为什么要
物料MaterialCodeR-10K-0402（电阻 10K 0402）是什么东西
批次LotNo（附 DateCode）L2610A（日期码 2641）来源和追溯；先进先出按它排；一批出问题只冻结这一批
库位LocationCodeRM-A-01-02东西在哪，拣货去哪找
状态StatusAvailable / QC / Hold / Defect能不能用

在数据库里，这四个字段组合起来做唯一键（UNIQUE (MaterialCode, LotNo, LocationCode, Status)）：同一个物料同一批次在同一库位同一状态，只能有一行，数量累加在这一行里。同一批电阻 19500 个可用、500 个冻结，是同一库位里的两行：

R-10K-0402  L2610A  RM-A-01-02  19500  Available
R-10K-0402  L2610A  RM-A-01-02    500  Hold

日期码 DateCode：元件厂商印在包装上的生产日期代码，常见格式是 4 位的 YYWW（年 + 第几周），例如 2641 表示 2026 年第 41 周。它不等于批次号：批次号是你们（或供应商）管理用的编号，日期码是生产日期。同一批次通常日期码相同，但供应商可能把不同日期码的货混成一个批次，所以日期码要单独存。

库存状态 ​

状态决定这批货能不能被拣出去用。本系列约定四种：

状态含义能否发料
Available可用，质量合格、没有锁定可以
QC待检，刚到货在等 IQC（来料检验，见 IQC来料检验）不可以
Hold冻结，怀疑有问题或被锁定，等待处理不可以
Defect不良，已判定不合格不可以

状态之间怎么转换，规定得越清楚越好：

批次与序列号 ​

电子厂里两个容易混的概念：

批次（Lot）序列号（SN，Serial Number）
粒度一批东西共用一个号每一件单独一个号
典型对象电阻、电容、IC、锡膏、PCB 裸板整机、PCBA 成品板、贵重模块
数量一个批次下有很多数量一个 SN 对应 1 件
在 WMS 里库存按 LotNo 分行，数量累加一般不拆成每个 SN 一行库存，而是另有 SN 明细表（归属哪个托盘/箱/订单）

原材料（电阻、电容）几万个一卷，按批次管就够了：知道"这卷是 L2610A"，追溯时再配合 MES 记录的"这块板用了哪一卷"（见 物料标签与条码）。成品板和整机的 SN 由 MES 在生产时赋予（见 WMS与MES交互），成品入库时 WMS 多半只记"这个箱子/托盘里有哪些 SN"。贵重或需要严格追溯的物料（某些芯片），也会做到"每盘一个唯一码"，那时一盘就是一个管理单位。

库存流水账：只追加 ​

库存流水（本系列叫 InvTxn）是每次库存变化的一条记录：什么时间、什么类型、哪个物料哪个批次、从哪里到哪里、多少、依据哪张单据。它有一个最重要的原则：只追加（append-only）——只能新增，不能修改、不能删除。出错了怎么办？再追加一条反向的流水冲正，错的那条留着，这样每一步都有据可查，就像会计的账本。

流水类型约定 7 种，数量永远写正数，方向由 FromLoc（从哪个库位出）和 ToLoc（进哪个库位）决定：

TxnType含义FromLocToLoc典型单据 DocNo
Receive收货入库空收货待检位收货单、ASN 号
PutAway上架收货待检位存储库位上架单
Issue发料出库（离开仓库，交给工单）存储库位空工单号
Return退料回库空存储库位退料单
Transfer调拨 / 改状态起点终点（可以和起点相同，仅改状态）调拨单、冻结单
Adjust盘点调整、期初建账盘亏时有值盘盈时有值盘点单
Scrap报废不良库位空报废单

规则就一条：库位的应有数量 = 流入它的流水之和 − 流出它的流水之和。把同一个（物料, 批次, 库位）所有状态的库存行加起来，就应该等于这个公式的结果，这就是对账公式：

库存表 Inventory 按（物料, 批次, 库位）汇总  ==  Σ流水(ToLoc=该库位)  −  Σ流水(FromLoc=该库位)

为什么对账公式里没有"状态"？因为 InvTxn 没有状态列。状态的变化（比如冻结）记成 FromLoc 和 ToLoc 相同的 Transfer，对库位来说净变化是零，状态明细则体现在 Inventory 的行上。这是教学版为了简单做的取舍；如果要从流水还原每个状态的数量，真实系统会在流水里加 FromStatus、ToStatus 两列。

库存与 ERP 库存的分工 ​

电子厂里常有两本库存账：ERP 一本，WMS 一本。简单说：ERP 管"值多少钱、属于哪个库存组织"（财务视角，粒度粗，通常到物料 + 仓库），WMS 管"具体在哪个库位、哪个批次、什么状态"（实物视角，粒度细）。两者通过接口对账（见 库存账与账实一致、库存与成本）。WMS 的库存汇总到"物料 + 仓库"这一级，应该等于 ERP 的账。

业务视角 ​

谁在用：仓管员（收货、上架、发料、盘点）、IQC 检验员（改变待检状态的结论）、计划员（看可用库存做齐套）、生产线（领料、退料）、品质（冻结、放行）、财务（对账、成本）。

关键规则：

  1. 只有 Available 的库存能发料；QC、Hold、Defect 一律不能。
  2. 任何库存数字的变化，必须由一张单据触发，并写一条流水；不允许"直接改库存数字"。
  3. 状态变化也要有人、有单、有流水：谁把它冻结的、为什么、什么时候解冻的。
  4. 同一批次不要拆在太多库位里；拆了就要保证每个库位那一行的数量对得上。
  5. 追溯：从批次 LotNo 往后查到发给了哪些工单（流水的 DocNo），再往下由 MES 查到哪些板子用了它。

KPI：库存准确率（账实相符的比例）、库存周转率、呆滞料金额、盘点差异率。

技术视角 ​

表设计：四张核心表 ​

下面是这四张表的完整建表语句（另加一张简化的 Material 物料表给外键用——真实的物料主数据在 ERP 或 MES 里，见 主数据与物料编码）。这是本系列所有实验的"底座"，其他篇里的 usp_* 存储过程、视图都建在它上面。

设计要点：

  • Inventory.Qty 带 CHECK (Qty >= 0)：数据库层面禁止负库存，这是最后一道防线。
  • Inventory.Status 带 CHECK：状态只能是四种之一，拼错了直接报错（回想 工单管理 里"状态手写字符串"的坑）。
  • InvTxn 的触发器：任何 UPDATE、DELETE 都被拒绝，把"只追加"落实到数据库里，而不只是靠程序自觉。
  • 数量用 decimal(18,3)：有些物料（锡膏按克、线材按米）有小数。
  • 中文名列一律 nvarchar。

建表脚本 00_schema.sql（会先删除再重建练习库 Lab_wms1，只动这个库）：

sql

GO

BEGIN
    ALTER DATABASE Lab_wms1 SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
    DROP DATABASE Lab_wms1;

GO
CREATE DATABASE Lab_wms1;
GO
USE Lab_wms1;
GO
-- 物料主数据（简化版，真实的物料主数据在 ERP / MES 里）
CREATE TABLE Material (
    MaterialCode  nvarchar(30)  NOT NULL PRIMARY KEY,
    MaterialName  nvarchar(100) NOT NULL,
    Unit          nvarchar(10)  NOT NULL,
    Spq           decimal(18,3) NOT NULL,       -- 标准包装量：一卷/一盘/一箱多少个
    ShelfLifeDays int           NULL,           -- 保质期（天），NULL 表示不限
    MsdLevel      nvarchar(10)  NULL            -- 湿敏等级，NULL 表示不敏感
);
-- 仓库
CREATE TABLE Warehouse (
    WhCode nvarchar(20) NOT NULL PRIMARY KEY,
    WhName nvarchar(50) NOT NULL,
    WhType nvarchar(20) NOT NULL    -- RawMaterial / SemiFinished / Finished / LineSide / Quarantine
);
-- 库位
CREATE TABLE Location (
    LocationCode nvarchar(30)  NOT NULL PRIMARY KEY,
    WhCode       nvarchar(20)  NOT NULL REFERENCES Warehouse(WhCode),
    Zone         nvarchar(20)  NOT NULL,   -- 库区：RCV 收货待检 / STORE 存储 / HOLD 冻结 / NG 不良 / LINE 线边
    Capacity     decimal(18,3) NOT NULL DEFAULT 0,   -- 最大容量，0 表示不限
    Status       nvarchar(20)  NOT NULL DEFAULT N'Active'   -- Active / Locked
);
-- 库存：物料 + 批次 + 库位 + 状态 四个维度，各占一行
CREATE TABLE Inventory (
    Id           bigint        IDENTITY(1,1) PRIMARY KEY,
    MaterialCode nvarchar(30)  NOT NULL REFERENCES Material(MaterialCode),
    LotNo        nvarchar(30)  NOT NULL,
    DateCode     nvarchar(10)  NULL,

存储过程：库存变化的唯一入口 ​

库存变化的操作只有三类，对应三个存储过程。所有改库存的代码都必须通过它们，这样规则（不超扣、状态检查、写流水）只在一个地方实现。

  • usp_Receive：库存加（收货 Receive、退料 Return、盘盈 Adjust），流水只写 ToLoc；
  • usp_Issue：库存减（发料 Issue、报废 Scrap、盘亏 Adjust），流水只写 FromLoc；
  • usp_Move：从一个库存行挪到另一个（上架 PutAway、调拨 Transfer、改状态），流水两头都写；批次、日期码、入库时间 ReceivedAt 原样带过去（FIFO 要靠它，见 先进先出与先到先用）。

核心写法有三点，每个过程里都有：

  1. 条件 UPDATE：UPDATE Inventory SET Qty = Qty - @Qty WHERE ... AND Qty >= @Qty，用 @@ROWCOUNT 判断是否扣成功（0 行就是库存不足）。检查和扣减在一条语句里，不可分割。
  2. 同一个事务：改库存和写流水放在 BEGIN TRAN ... COMMIT 里，要么都成功，要么都回滚（见 事务与ACID）。过程里用 TRY...CATCH，出错就 ROLLBACK 再 THROW。
  3. 清理零行：库存减到 0 的那一行删掉，免得库存表里堆满数量为 0 的垃圾行。

sql
USE Lab_wms1;
GO
-- 入库类：Receive 收货 / Return 退料回库 / Adjust 盘盈。库存加，流水只写 ToLoc
CREATE PROCEDURE usp_Receive
    @TxnType nvarchar(20), @Mat nvarchar(30), @Lot nvarchar(30), @DateCode nvarchar(10),
    @ToLoc nvarchar(30), @Status nvarchar(20), @Qty decimal(18,3), @DocNo nvarchar(30), @ReceivedAt datetime2(0)
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF @TxnType NOT IN (N'Receive', N'Return', N'Adjust') THROW 50010, N'usp_Receive 只处理 Receive/Return/Adjust', 1;
    IF @Qty <= 0 THROW 50011, N'数量必须大于 0', 1;
    IF @TxnType <> N'Adjust' AND EXISTS (SELECT 1 FROM Location WHERE LocationCode = @ToLoc AND Status = N'Locked')
        THROW 50012, N'库位已锁定（盘点中），不能入库', 1;
    BEGIN TRY
    BEGIN TRAN;
    UPDATE Inventory SET Qty = Qty + @Qty
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @ToLoc AND Status = @Status;
    IF @@ROWCOUNT = 0
        INSERT Inventory (MaterialCode, LotNo, DateCode, LocationCode, Qty, Status, ReceivedAt)
        VALUES (@Mat, @Lot, @DateCode, @ToLoc, @Qty, @Status, @ReceivedAt);
    INSERT InvTxn (TxnType, MaterialCode, LotNo, FromLoc, ToLoc, Qty, DocNo)
    VALUES (@TxnType, @Mat, @Lot, NULL, @ToLoc, @Qty, @DocNo);
    COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;
    END CATCH
END
GO
-- 出库类：Issue 发料 / Scrap 报废 / Adjust 盘亏。库存减，流水只写 FromLoc。条件 UPDATE 防超扣
CREATE PROCEDURE usp_Issue
    @TxnType nvarchar(20), @Mat nvarchar(30), @Lot nvarchar(30),
    @FromLoc nvarchar(30), @Status nvarchar(20), @Qty decimal(18,3), @DocNo nvarchar(30)
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF @TxnType NOT IN (N'Issue', N'Scrap', N'Adjust') THROW 50020, N'usp_Issue 只处理 Issue/Scrap/Adjust', 1;
    IF @TxnType = N'Issue' AND @Status <> N'Available' THROW 50021, N'只有 Available 状态的库存可以发料', 1;
    IF @Qty <= 0 THROW 50022, N'数量必须大于 0', 1;
    IF @TxnType <> N'Adjust' AND EXISTS (SELECT 1 FROM Location WHERE LocationCode = @FromLoc AND Status = N'Locked')
        THROW 50024, N'库位已锁定（盘点中），不能出库', 1;
    BEGIN TRY
    BEGIN TRAN;
    UPDATE Inventory SET Qty = Qty - @Qty
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @FromLoc AND Status = @Status AND Qty >= @Qty;
    IF @@ROWCOUNT = 0 THROW 50023, N'库存不足或库存行不存在，扣减被拒绝', 1;
    DELETE Inventory
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @FromLoc AND Status = @Status AND Qty = 0;
    INSERT InvTxn (TxnType, MaterialCode, LotNo, FromLoc, ToLoc, Qty, DocNo)
    VALUES (@TxnType, @Mat, @Lot, @FromLoc, NULL, @Qty, @DocNo);
    COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;
    END CATCH
END
GO
-- 移动类：PutAway 上架 / Transfer 调拨（含改状态）。源库存行减、目标库存行加，批次、日期码、入库时间原样带过去
CREATE PROCEDURE usp_Move
    @TxnType nvarchar(20), @Mat nvarchar(30), @Lot nvarchar(30),
    @FromLoc nvarchar(30), @FromStatus nvarchar(20),
    @ToLoc nvarchar(30), @ToStatus nvarchar(20),
    @Qty decimal(18,3), @DocNo nvarchar(30)
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF @TxnType NOT IN (N'PutAway', N'Transfer') THROW 50030, N'usp_Move 只处理 PutAway/Transfer', 1;
    IF @FromLoc = @ToLoc AND @FromStatus = @ToStatus THROW 50031, N'起点和终点完全相同', 1;
    IF @Qty <= 0 THROW 50032, N'数量必须大于 0', 1;
    IF EXISTS (SELECT 1 FROM Location WHERE LocationCode IN (@FromLoc, @ToLoc) AND Status = N'Locked')
        THROW 50034, N'起点或终点库位已锁定（盘点中），不能移动', 1;
    BEGIN TRY
    BEGIN TRAN;
    DECLARE @dc nvarchar(10), @rcv datetime2(0);
    SELECT @dc = DateCode, @rcv = ReceivedAt FROM Inventory
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @FromLoc AND Status = @FromStatus;
    UPDATE Inventory SET Qty = Qty - @Qty
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @FromLoc AND Status = @FromStatus AND Qty >= @Qty;
    IF @@ROWCOUNT = 0 THROW 50033, N'库存不足或库存行不存在，移动被拒绝', 1;
    UPDATE Inventory SET Qty = Qty + @Qty
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @ToLoc AND Status = @ToStatus;
    IF @@ROWCOUNT = 0
        INSERT Inventory (MaterialCode, LotNo, DateCode, LocationCode, Qty, Status, ReceivedAt)
        VALUES (@Mat, @Lot, @dc, @ToLoc, @Qty, @ToStatus, @rcv);
    DELETE Inventory
     WHERE MaterialCode = @Mat AND LotNo = @Lot AND LocationCode = @FromLoc AND Status = @FromStatus AND Qty = 0;
    INSERT InvTxn (TxnType, MaterialCode, LotNo, FromLoc, ToLoc, Qty, DocNo)
    VALUES (@TxnType, @Mat, @Lot, @FromLoc, @ToLoc, @Qty, @DocNo);
    COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;
    END CATCH
END
GO
-- 流水汇总视图：每个（物料, 批次, 库位）按流水算出来应有多少
CREATE VIEW vTxnBalance AS
SELECT MaterialCode, LotNo, LocationCode, SUM(Qty) AS Qty
FROM (
    SELECT MaterialCode, LotNo, ToLoc   AS LocationCode,  Qty FROM InvTxn WHERE ToLoc   IS NOT NULL
    UNION ALL
    SELECT MaterialCode, LotNo, FromLoc AS LocationCode, -Qty FROM InvTxn WHERE FromLoc IS NOT NULL
) x
GROUP BY MaterialCode, LotNo, LocationCode;
GO
-- 对账：库存表与流水汇总不一致的行（正常应为 0 行）
CREATE VIEW vInvDiff AS
SELECT COALESCE(a.MaterialCode, b.MaterialCode) AS MaterialCode,
       COALESCE(a.LotNo, b.LotNo)               AS LotNo,
       COALESCE(a.LocationCode, b.LocationCode) AS LocationCode,
       ISNULL(a.Qty, 0) AS InvQty, ISNULL(b.Qty, 0) AS TxnQty
FROM (SELECT MaterialCode, LotNo, LocationCode, SUM(Qty) AS Qty FROM Inventory GROUP BY MaterialCode, LotNo, LocationCode) a
FULL OUTER JOIN vTxnBalance b
  ON a.MaterialCode = b.MaterialCode AND a.LotNo = b.LotNo AND a.LocationCode = b.LocationCode
WHERE ISNULL(a.Qty, 0) <> ISNULL(b.Qty, 0);
GO

为什么用存储过程，而不是都写在 C# 里？这是一个取舍。放在数据库里：任何入口（WMS 程序、MES 接口、运维脚本）都遵守同一套规则，绕不过去。放在 C# 里：更好测试和版本管理。两种做法都对，关键是规则只有一份。自研系统里很多厂是 C# 服务层统一封装，并把"条件 UPDATE + 流水"这个核心保留在事务里。更多内容见 视图存储过程与触发器。

对账视图 ​

vTxnBalance 按公式从流水算出每个（物料, 批次, 库位）应有的数量，vInvDiff 把它和库存表对比，只列出不一致的行。正常情况下 vInvDiff 永远是 0 行，哪天不是 0 行，就说明有人绕开了存储过程直接改了数据。

第 4 步：新建 LabRace.cs，对比"先读后写"和"条件 UPDATE"：

csharp
using SqlSugar;

namespace WmsLab;

// 实验 B：并发扣减。同一行库存 10000，N 个终端同时各发 X
// 错误写法：先读后判断再写绝对值（读和写之间有空档）；正确写法：条件 UPDATE + 同一事务写流水
public static class LabRace
{
    const string Mat = "R-10K-0402", Lot = "L-RACE", Loc = "RM-A-01-01";

    static void Seed(SqlSugarClient db)
    {
        LabFlow.Reset(db);
        db.Ado.ExecuteCommand("EXEC usp_Receive @t, @m, @lot, @dc, @loc, @st, @q, @doc, @at",
            new { t = "Adjust", m = Mat, lot = Lot, dc = "2641", loc = Loc, st = "Available", q = 10000m, doc = "OPEN-001", at = new DateTime(2026, 10, 1, 9, 0, 0) });
    }

    static void Log(SqlSugarClient db, decimal qty, string doc) =>
        db.Insertable(new InvTxn { TxnType = "Issue", MaterialCode = Mat, LotNo = Lot, FromLoc = Loc, Qty = qty, DocNo = doc, CreatedAt = DateTime.Now }).ExecuteCommand();

    // 错误：先查，够了就把"剩余数"直接写回去
    static bool Naive(SqlSugarClient db, decimal qty, string doc)
    {
        var row = db.Queryable<Inventory>().First(i => i.MaterialCode == Mat && i.LotNo == Lot && i.LocationCode == Loc && i.Status == "Available");
        if (row.Qty < qty) return false;
        Thread.Sleep(200);                                   // 模拟网络、业务处理耗时，把"空档"放大
        var left = row.Qty - qty;
        db.Updateable<Inventory>().SetColumns(i => i.Qty == left).Where(i => i.Id == row.Id).ExecuteCommand();
        Log(db, qty, doc);
        return true;
    }

    // 正确：条件写在 UPDATE 的 WHERE 里，受影响行数 1 才算成功；扣库存和写流水在同一事务
    static bool Safe(SqlSugarClient db, decimal qty, string doc)
    {
        db.Ado.BeginTran();
        try
        {
            var n = db.Updateable<Inventory>().SetColumns(i => i.Qty == i.Qty - qty)
                .Where(i => i.MaterialCode == Mat && i.LotNo == Lot && i.LocationCode == Loc && i.Status == "Available" && i.Qty >= qty)
                .ExecuteCommand();
            if (n == 0) { db.Ado.RollbackTran(); return false; }
            Log(db, qty, doc);
            db.Ado.CommitTran();
            return true;
        }
        catch { db.Ado.RollbackTran(); throw; }
    }

    static void Round(string title, Func<SqlSugarClient, decimal, string, bool> issue, int threads, decimal qty)
    {
        var db = Db.Create();
        Seed(db);
        var ok = new bool[threads];
        Parallel.For(0, threads, new ParallelOptions { MaxDegreeOfParallelism = threads }, i => ok[i] = issue(Db.Create(), qty, $"WO-{i:00}"));
        var left = db.Queryable<Inventory>().Sum(i => i.Qty);
        var issued = db.Queryable<InvTxn>().Where(t => t.TxnType == "Issue").Sum(t => t.Qty);
        Console.WriteLine($"{title}：{threads} 个终端各发 {qty:0} -> 成功 {ok.Count(x => x)} 个，库存剩 {left:0}，流水记录发出 {issued:0}，对账不一致行数 {db.Ado.GetInt("SELECT COUNT(*) FROM vInvDiff")}");
    }

    public static void Run()
    {
        Round("错误写法（先读后写绝对值）", Naive, 4, 6000);
        Round("正确写法（条件 UPDATE）    ", Safe, 4, 6000);
        Round("正确写法（条件 UPDATE）    ", Safe, 20, 1000);
        Round("正确写法（条件 UPDATE）    ", Safe, 12, 1000);
    }
}

常见坑与排查 ​

误区 / 坑事实与办法
库存只存一个总数，不分批次/状态冻结、追溯、先进先出都做不了。四个维度从第一天就要有
直接 UPDATE Inventory SET Qty = ...绕过了规则和流水，账和流水对不上。所有变化走存储过程（或统一的服务方法）
先查够不够、再更新（先读后写）并发下会丢失更新或超扣；用条件 UPDATE 把检查和修改合成一条语句（实验二）
流水账允许修改、删除出错就没法审计；用触发器（或权限）保证只追加，错了就追加冲正流水
状态改了不写流水谁冻结的、什么时候解冻的追不到；改状态也要有单、有流水
上架/调拨时丢了入库时间FIFO 会乱。移动库存时，要把原来的 ReceivedAt 和日期码带到新行
日期码当批次号用同批次可能混多个日期码，日期码要单独存
库存减到 0 留着 0 行表越来越大，还可能影响"有库存的库位"判断；减到 0 就删
对账不是 0 行却不管不一致就是 Bug 的信号，要查到原因，见 库存账与账实一致

练习题与答案 ​

  1. 为什么库存的唯一键要包含 Status？ 答：同一批货在同一库位可以同时有可用的和冻结的两部分，它们能不能被发料不同，必须分开记成两行。把状态放进唯一键，既保证同状态只有一行，又允许不同状态各有一行。
  2. 冻结 L2610A 在库位 RM-A-01-02 里的 500 个，流水该怎么写？ 答：一条 Transfer，FromLoc 和 ToLoc 都是 RM-A-01-02，Qty 是 500，DocNo 写冻结单号。库存表里 Available 行减 500，Hold 行加 500。
  3. 实验二的"错误写法"里，库存最终为什么是 4000，而不是 -14000？ 答：每个终端写回去的是"自己读到的 10000 减 6000 = 4000"这个绝对值，后写的覆盖先写的，所以最终是 4000；而流水却记了 4 笔 6000 的出库。
  4. 为什么 Qty >= @Qty 要写在 UPDATE 的 WHERE 里，而不是先 SELECT 判断？ 答：SELECT 和 UPDATE 之间有时间差，别人可能已经改了库存；写在同一条 UPDATE 里，数据库保证检查和修改不可分割。
  5. 发现 vInvDiff 有一行不一致，应该怎么查？ 答：先看这行（物料、批次、库位）涉及的所有流水，看有没有缺漏或重复；再查有没有人绕过存储过程直接改了库存表（数据库审计日志或应用日志）；确认原因后，用一条 Adjust 流水加单据（经审批）纠正，并堵住绕过的入口。不要直接改库存表或删流水来"抹平"。
  6. 成品板的序列号（SN）适合像批次一样存在 Inventory 里吗？ 答：一般不适合。SN 是每件一个，如果每个 SN 一行库存表会非常大，而且它的数量永远是 1。通常用单独的 SN 明细表记录每个 SN 在哪个箱/托盘/订单，库存表只记到"物料 + 批次/订单 + 库位 + 状态"的数量级别。

小结 ​

  • 库存用 物料 + 批次 + 库位 + 状态 四个维度记，状态决定能不能发料。
  • 每次变化写一条只追加的流水 InvTxn，错了就冲正，不改不删。
  • 库存 = 流水之和，用对账视图随时检查，不一致就是 Bug 信号。
  • 扣减要用条件 UPDATE，检查和修改在一条语句里；改库存和写流水放在同一个事务。
  • 库存变化只有一个入口（存储过程或统一服务），规则只有一份。
