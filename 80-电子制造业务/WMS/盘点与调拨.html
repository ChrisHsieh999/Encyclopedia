盘点与调拨

AI 生成 · 待核对制造业务WMS盘点更新于 2026-10-21

⚠ 待核对：循环盘点的频率、差异审批的金额/比例阈值（本篇示例用 0.5%）、盲盘/复盘的要求，都是通用做法或我举的示例，各厂差别很大，请对照你们的系统和财务制度。表结构与 T-SQL 在本机 LocalDB 临时库 Lab_wms1 里实际运行过。

本篇是 WMS 系列第 5 篇。读完你应该能：说清循环盘点和全盘的区别；按"锁库位 → 快照 → 实盘 → 差异 → 审批 → 过账"的流程做一次盘点；理解为什么盘点调整必须走审批和流水；区分库位调拨和仓间调拨。

一句话定义 ​

盘点（Stocktaking）是把仓库里的实物数一遍，和系统账面数核对，找出差异并调整；调拨（Transfer）是把库存从一个库位（或仓库）搬到另一个，库存账同步变动。

先修知识 ​

  • 库存管理与批次序列号：库存四维度、Adjust 与 Transfer 流水、条件 UPDATE。
  • 仓库基础概念：库位、库区、ABC 分类。

它解决什么问题 ​

账是人记的，货是人拿的，两边迟早出现差异：

  • 拣货时手滑多拿了 100 个，没有记；
  • 报废的料直接扔了，没做报废单；
  • 一卷料被产线拿走用了，却没有退料也没有发料记录；
  • 点数错误、标签贴错、串料……

差异不处理，会一直累积：账面有库存而实物没有，计划以为有料，实际一开工就缺；财务账上有一堆不存在的资产。盘点就是定期把账拉回现实，而且每次调整都要有人批准、有记录——否则盘点就成了"谁数得顺眼就改成多少"的漏洞。

核心概念 ​

循环盘点与全盘 ​

全盘（Full Count）循环盘点（Cycle Count）
做法在某个时间点把整个仓库全数一遍每天/每周数一部分，一年轮完全部
是否停业通常要停止收发料不用，只锁正在数的那几个库位
适用年度盘点、财务审计要求日常
代价停线、人力集中日常工作量小，但要有计划

据维基百科对循环盘点（cycle counting）的介绍，它是一种库存审计方法：在一个周期内按计划盘点一部分库存，而不是一次盘点全部。常见做法是结合 ABC 分类（见 仓库基础概念）：A 类（价值高）物料盘得最勤（比如每月一次），B 类每季度，C 类每年。有些厂还有事件触发盘点：库存减到零、账面出现负数、拣货发现货架上没有时，立刻盘那个库位。

盘点的几个关键做法 ​

  • 冻结 / 锁库位：盘点期间被盘的库位不允许出入库，否则数完就变。系统上把库位 Status 设成 Locked，收货、发料、调拨一律拒绝（盘点自己的调整例外）。
  • 账面数快照：开盘点单时把当前账面数拍下来存进盘点行（BookQty），差异 = 实盘数 − 账面数。这样即使事后还有别的单据，也不影响本次差异的计算。
  • 盲盘：盘点人看不到账面数，只录实盘数，防止"照着账面数填"。差异由系统算。
  • 初盘与复盘：两个人（或两次）独立数；两次不一致就复盘。
  • 差异分级审批：小差异自动通过，大差异（超阈值，或者对高价值物料）需要主管/财务审批。

差异与调整 ​

差异 = 实盘数 − 账面数：

  • 差异 > 0：盘盈，实物比账多，调整时库存加；
  • 差异 < 0：盘亏，实物比账少，调整时库存减。

过账时生成 Adjust 流水，盘盈写 ToLoc，盘亏写 FromLoc，DocNo 是盘点单号。盘点单过账后库存才变，流水留下"谁在哪个盘点单里调整了多少"。

调拨 ​

调拨把库存从 A 搬到 B。两种常见情况：

类型例子账上变化
库位调拨整理货架，把 RM-A-01-01 的料搬到 RM-A-02-01同一仓库内，库位变，仓库账总量不变
仓间调拨原材料仓 RM 发到 SMT 线边仓 LINE两个仓库的账此消彼长，ERP 里要做库存转移

调拨流水用 Transfer，FromLoc 和 ToLoc 都有值。要注意：

  • 搬过去的库存要保留原来的批次、日期码和入库时间，否则先进先出会乱（usp_Move 已经做到了）；
  • 仓间调拨路上要时间（尤其是跨厂区），可分两步：先调出到"在途"虚拟库位，对方签收后才到目标库位。在途库存既不算原仓库的，也不算目标仓库的，避免重复计算；
  • 调拨目标库位被锁定（盘点中）时要拒绝。

业务视角 ​

角色：仓管员（盘点、调拨）、盘点员/复核员、仓库主管（审批差异）、财务（审批大额差异、做账）。

盘点流程：

  1. 制定计划（全盘或循环盘点的范围、时间）；
  2. 开盘点单：锁库位、系统取账面数快照；
  3. 初盘（可盲盘）→ 复盘（如需要）；
  4. 系统计算差异，按阈值分类：无差异 / 自动通过 / 需审批；
  5. 审批人查看差异原因，批准或要求重盘；
  6. 过账：生成 Adjust 流水，更新库存，解锁库位；
  7. 分析差异原因，改进（流程缺陷、标签问题、人员培训）。

单据：盘点计划、盘点单（头+行）、差异审批单、调整流水。调拨有调拨单（调出、调入）。

KPI：库存准确率（账实一致的行数 / 总盘点行数）、盘点差异金额、盘点覆盖率（计划内按时完成的比例）、差异原因分布。

技术视角 ​

表设计 ​

sql
CREATE TABLE CountDoc (
    CountNo   nvarchar(30) NOT NULL PRIMARY KEY,
    CountType nvarchar(10) NOT NULL,                 -- Cycle 循环盘点 / Full 全盘
    Status    nvarchar(20) NOT NULL DEFAULT N'Counting'   -- Counting / Posted
);
CREATE TABLE CountLine (
    CountNo      nvarchar(30)  NOT NULL REFERENCES CountDoc(CountNo),
    LineNum      int           NOT NULL,
    MaterialCode nvarchar(30)  NOT NULL,
    LotNo        nvarchar(30)  NOT NULL,
    LocationCode nvarchar(30)  NOT NULL,
    BookQty      decimal(18,3) NOT NULL,        -- 账面数（快照）
    CountedQty   decimal(18,3) NULL,            -- 实盘数
    ApprovedBy   nvarchar(30)  NULL,            -- 需审批的差异由谁批准
    PRIMARY KEY (CountNo, LineNum)
);

状态与规则 ​

盘点单状态：Counting（盘点中）→ Posted（已过账）。过账过程的规则：

  1. 所有行必须录入实盘数；
  2. 超出阈值的行（ABS(CountedQty - BookQty) > BookQty * 0.005）必须有 ApprovedBy；
  3. 对差异 ≠ 0 的行逐行生成 Adjust：盘盈调 usp_Receive（Adjust），盘亏调 usp_Issue（Adjust）；
  4. 单据置 Posted，库位解锁。

阈值要做成可配置的规则（可能还要按物料价值分级），不要写死在代码里；这里为了演示写成了 0.5%。

库位锁定 ​

usp_Receive、usp_Issue、usp_Move 都检查库位的 Status：被锁定（Locked）的库位拒绝一切出入库和移动，唯独 Adjust 类型例外（否则盘点过账自己也被挡住）。

关键点 ​

  • 过账要整体成功：几行差异，要么都调整，要么都不调整。真实系统会把过账放进一个事务；实验里为简洁用游标逐行调用存储过程，每行是独立事务，重要场景请包成整体事务。
  • 盘点调整不是改库存数字：必须通过 Adjust 流水，保证"库存 = 流水之和"仍然成立；对账视图随时可以验证。
  • 别让盘点员看见账面数（盲盘）：这是界面/接口层面的权限设计，不是数据库的事。

逐步例子 ​

仓里有三行库存要盘：

行批次库位账面实盘差异差异率
1L2609C（电阻）RM-A-01-0121242150+261.224%
2L3001（电容）RM-A-01-021000−100100%
3L2610A（电阻）RM-A-01-021950019490−100.051%

规则：差异率 ≤ 0.5% 自动通过，其余需主管审批。

  1. 开盘点单 CNT-001，先锁定 RM-A-01-01 和 RM-A-01-02，再拍账面数快照；
  2. 盘点期间有人想发料：被拒绝（库位已锁定）；
  3. 录入实盘数，系统算差异：行 3 差异率只有 0.051%，自动通过；行 1、2 需审批；
  4. 没审批就过账：被拒绝；
  5. 主管批准行 1、2 后过账：行 1 盘盈 26，生成 Adjust 入；行 2 盘亏 100（这 100 个电容在 拣货与发料 的例子里就是"账上有、货架上找不到"的那部分）；行 3 盘亏 10；
  6. 过账后库位自动解锁，对账 0 行不一致；
  7. 随后做两次调拨：L2609C 整个 2150 从 RM-A-01-01 搬到 RM-A-02-01；L2610A 的 3000 从原材料仓搬到 SMT 线边仓 LINE-SMT1。

PRINT N'== 3. 差异与审批规则（|差异| / 账面 <= 0.5% 自动通过，否则需要主管审批）';
SELECT LineNum, LotNo, LocationCode, BookQty, CountedQty, CountedQty - BookQty AS Diff,
       CAST(ABS(CountedQty - BookQty) * 100.0 / BookQty AS decimal(9,3)) AS DiffPct,
       CASE WHEN CountedQty = BookQty THEN N'无差异'
            WHEN ABS(CountedQty - BookQty) <= BookQty * 0.005 THEN N'自动通过'
            ELSE N'需审批' END AS Decision
FROM CountLine WHERE CountNo = N'CNT-001' ORDER BY LineNum;

PRINT N'== 4. 过账：先试"未审批就过账"，再主管批准后过账';
GO
-- 过账存储过程：需审批的行没有 ApprovedBy 就拒绝；差异 > 0 用 Adjust 入，< 0 用 Adjust 出
CREATE PROCEDURE usp_PostCount @CountNo nvarchar(30)
AS
BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;
    IF EXISTS (SELECT 1 FROM CountLine WHERE CountNo = @CountNo AND CountedQty IS NULL)
        THROW 50060, N'还有行没录入实盘数', 1;
    IF EXISTS (SELECT 1 FROM CountLine WHERE CountNo = @CountNo AND ABS(CountedQty - BookQty) > BookQty * 0.005 AND ApprovedBy IS NULL)
        THROW 50061, N'有超出阈值的差异还没有审批', 1;
    DECLARE @line int, @mat nvarchar(30), @lot nvarchar(30), @loc nvarchar(30), @diff decimal(18,3);
    DECLARE c CURSOR LOCAL FAST_FORWARD FOR
        SELECT LineNum, MaterialCode, LotNo, LocationCode, CountedQty - BookQty FROM CountLine WHERE CountNo = @CountNo AND CountedQty <> BookQty;
    OPEN c; FETCH NEXT FROM c INTO @line, @mat, @lot, @loc, @diff;
    WHILE @@FETCH_STATUS = 0
    BEGIN
        IF @diff > 0
            EXEC usp_Receive N'Adjust', @mat, @lot, NULL, @loc, N'Available', @diff, @CountNo, '2026-10-21 10:00:00';
        ELSE
        BEGIN
            SET @diff = -@diff;
            EXEC usp_Issue N'Adjust', @mat, @lot, @loc, N'Available', @diff, @CountNo;
        END
        FETCH NEXT FROM c INTO @line, @mat, @lot, @loc, @diff;
    END
    CLOSE c; DEALLOCATE c;
    UPDATE CountDoc SET Status = N'Posted' WHERE CountNo = @CountNo;
    UPDATE Location SET Status = N'Active' WHERE LocationCode IN (SELECT LocationCode FROM CountLine WHERE CountNo = @CountNo);
END
GO
BEGIN TRY EXEC usp_PostCount N'CNT-001'; PRINT N'过账：成功'; END TRY
BEGIN CATCH PRINT N'过账：被拒绝 - ' + ERROR_MESSAGE(); END CATCH
UPDATE CountLine SET ApprovedBy = N'主管-Wang' WHERE CountNo = N'CNT-001' AND ABS(CountedQty - BookQty) > BookQty * 0.005;
BEGIN TRY EXEC usp_PostCount N'CNT-001'; PRINT N'审批后过账：成功'; END TRY
BEGIN CATCH PRINT N'审批后过账：被拒绝 - ' + ERROR_MESSAGE(); END CATCH

PRINT N'== 5. 过账后库存、盘点流水与对账';
SELECT MaterialCode, LotNo, LocationCode, Qty, Status FROM Inventory ORDER BY LocationCode, LotNo;
SELECT TxnType, LotNo, FromLoc, ToLoc, Qty, DocNo FROM InvTxn WHERE DocNo = N'CNT-001' ORDER BY Id;
SELECT LocationCode, Status FROM Location WHERE LocationCode IN (N'RM-A-01-01', N'RM-A-01-02') ORDER BY LocationCode;
SELECT COUNT(*) AS DiffRows FROM vInvDiff;

PRINT N'== 6. 调拨：库位调拨（整理库位）与仓间调拨（原材料仓 -> SMT 线边仓）';
EXEC usp_Move N'Transfer', N'R-10K-0402', N'L2609C', N'RM-A-01-01', N'Available', N'RM-A-02-01', N'Available', 2150, N'TR-001';
EXEC usp_Move N'Transfer', N'R-10K-0402', N'L2610A', N'RM-A-01-02', N'Available', N'LINE-SMT1',  N'Available', 3000, N'TR-002';
SELECT i.LotNo, i.LocationCode, l.WhCode, i.Qty, i.ReceivedAt FROM Inventory i JOIN Location l ON l.LocationCode = i.LocationCode
WHERE i.MaterialCode = N'R-10K-0402' ORDER BY i.ReceivedAt, i.LocationCode;

常见坑与排查 ​

误区 / 坑事实与办法
盘点时不锁库位数的过程中有出入库，差异不准。开单时锁库位 + 快照账面数
盘点员能看到账面数容易照账面数填。做盲盘，系统算差异
直接改库存数字"调平"绕过流水，对账立刻报错。一律走 Adjust + 审批
小差异也要找人审批效率太低；设阈值，小差异自动通过，大差异、高价值物料审批
盘点调整不分原因同类差异反复出现却不知道为什么。过账时要求填原因代码
调拨丢了批次和入库时间FIFO 会错乱，追溯断掉。移动时必须带上原批次、日期码、ReceivedAt
仓间调拨一步到位路上的货凭空消失（两头都不算）。需要时用"在途"库位分两步
过账只调整一半数据不一致。过账整体放事务，失败全部回滚
只盘不分析同样的错误下次还犯。看差异率、集中在哪些库位、哪些人

练习题与答案 ​

  1. 为什么要把账面数快照存在盘点行里，而不是过账时再去查？ 答：盘点和过账之间可能有时间差，即使库位被锁，快照也保证差异的计算基准固定，审批人看到的差异和过账时一致。
  2. 账面 2124，实盘 2150，差异率是多少？是盘盈还是盘亏？ 答：差异 +26，差异率 26 / 2124 = 1.224%，盘盈。
  3. 盘盈和盘亏在流水里怎么区别？ 答：都是 Adjust 类型。盘盈只写 ToLoc（库存加）；盘亏只写 FromLoc（库存减）。
  4. 库位被锁定时，盘点过账的调整为什么还能执行？ 答：Adjust 类型被设计成不受库位锁定限制，否则盘点过账自己也会被拒绝。其他类型（发料、收货、调拨）都被挡住。
  5. 盘点过账循环处理三行，第二行调用失败了，第一行已经调整，怎么办？ 答：这是没有包整体事务的后果。应该把整个过账放在一个事务里，失败整体回滚；或者设计为幂等、可重试，过账时先检查哪些行已过账。
  6. 为什么调拨后要保留原来的 ReceivedAt？ 答：先进先出按入库时间排序；调拨改的只是位置，不是货到仓库的时间。如果改成调拨时间，这批旧货会被误当成新货，永远排在后面。

小结 ​

  • 盘点是把账拉回现实：锁库位 → 快照 → 实盘 → 差异 → 审批 → 过账。
  • 循环盘点按 ABC 分类分频，不停业；全盘用于年度审计。
  • 盘点调整只能通过 Adjust 流水，盘盈写 ToLoc、盘亏写 FromLoc，大差异必须审批。
  • 调拨用 Transfer，保留批次、日期码和入库时间；仓间调拨可用"在途"过渡。
  • 盘点的价值不只是调平，更是通过差异原因改进流程。
