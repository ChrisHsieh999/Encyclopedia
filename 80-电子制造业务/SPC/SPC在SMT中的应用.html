SPC在SMT中的应用

AI 生成 · 待核对制造业务SPCSMT质量更新于 2026-10-21

⚠ 待核对：SMT 各工位该监控哪些特性、子组大小、取样频率、规则启用、OCAP 与锁线流程，都是通用做法，不是你们公司的规定，请对照你们的工艺文件、客户要求和自研 MES/QMS 核实。SPI、贴片机、AOI 导出数据的文件格式和接口随设备品牌与型号而异，本篇不假设具体厂家。控制图公式与常数见 控制图（常数表已待核对）。表设计、T-SQL 和 Python 都在本机 SQL Server LocalDB 临时库 Lab_spc 上实际运行（实验后已删除）；SPI 数据是程序模拟的，不是真实设备数据。

本篇是 SPC 系列第 5 篇，也是落地篇。读完你应该能：说出 SMT 里哪些特性适合上 SPC、各选什么图；设计取样与数据采集方案；设计 SpcPoint / SpcSample / SpcAlarm 三张表；写出算控制限和检出失控点的 T-SQL；说清失控后怎么处置、怎么和 MES 联动锁线。

一句话定义 ​

SPC 在 SMT 中的应用，是把 控制图、过程能力CPK、判异规则 用在锡膏印刷、贴装、回流焊和 AOI 这些工位上：自动采集测量数据，在系统里算控制限、检出失控，并把报警送到 MES 和责任人，使问题在出不良之前被处理。

先修知识 ​

  • SPC、控制图、判异规则：知道子组、UCL/LCL、规则 1 和"8 点同侧"。
  • SMT与电子组装流程：知道印刷、SPI、贴片、回流焊、AOI 的顺序。
  • 工艺参数与炉温曲线管理：知道炉温曲线的峰值、斜率、TAL。
  • IPQC过程检验：知道过程检验在做什么。
  • 会一点 T-SQL（GROUP BY、窗口函数）。

它解决什么问题 ​

一条 SMT 线每天印几千块板。锡膏印刷环节占 SMT 缺陷的大头，常被认为是重点工位（很多资料称印刷相关缺陷是焊接缺陷的主要来源，具体比例各家不同，本篇不引用具体数字）。如果钢网开孔慢慢堵、刮刀压力慢慢变，锡膏高度会一点点漂。SPI 每块板都在测，但如果只判"在不在规格内"，就要等到第一块超限才知道；那时前面几十块"勉强合格"的板，焊点已经是薄弱的了。

SPC 的价值是：用 SPI/AOI 本来就在测的数据，在不良出现之前发现趋势。

核心概念 ​

哪些特性适合上 SPC ​

怎么把 SPI 数据变成子组 ​

SPI 对每块板的几千个焊盘各测高度、体积、面积。这些数据不应该直接当成一个子组的样本，因为：同一块板上的焊盘高度相关（共用一次印刷），数据量也太大。常见做法有几种（取舍由工艺决定，请和你们工艺确认）：

  • 按板汇总：每块板取某类焊盘（如所有 0402 焊盘）的平均体积，作为一个"测量值"；连续 5 块板的 5 个汇总值构成一个子组；
  • 按焊盘类型分图：BGA、0201、QFP 等不同焊盘类型各画一张图，不要混在一起（与 控制图 的"理性子组"同理）；
  • 关键位置抽样：只取指定的几个关键焊盘的值。

本篇实验直接用"每板一个高度汇总值"，连续 5 块板为一个子组。

采样策略：子组多大、多久取一次 ​

问题通用考虑
子组大小 n一般 3~6（Xbar-R 常用 5）；同一子组应来自连续生产的板，保证组内只有自然波动
取样频率看过程变化有多快：每小时一次、每个钢网擦拭周期一次、每班开始/结束各一次；开线、换线、换钢网后的首板（见 首件检验与换线）要额外测
数据量建限至少 20~25 个子组；频率太低要很久才能建限，太高又浪费
分层不同产线、钢网、锡膏批次、班次各自独立建图，别混
全检数据SPI 其实是全检，系统可以每块板都存，再从中按规则抽出子组画控制图，两者不矛盾

数据采集：数据从哪来 ​

来源做法注意
SPI / AOI 机台文件设备每块板导出一个文件（CSV/XML/文本），程序监控目录读取入库文件格式因厂家而异；要处理重复文件、写入中途被读取
设备数据库直接读设备自带的数据库版权与稳定性要和厂家确认；只读访问，别写
设备接口通过设备联网接口上报，见 设备数据采集、SMT设备接口最实时，但需要设备支持
炉温测试仪测试软件导出曲线，程序提取峰值、TAL 后写入一次测量只有一个值
人工录入推拉力、尺寸等离线测量要防错：录入时校验范围，保留测量设备编号，见 校准与量具管理

无论哪种来源，入库时至少要有：特性编码（SpcPoint）、测量值、板码 SN、产线、测量时间。有了 SN，失控后才能追到板，见 产品追溯。

报警与处置：OCAP ​

OCAP（Out of Control Action Plan，失控处置计划）是预先写好的"点失控后，谁、先做什么、查什么、怎么放行"的流程。没有 OCAP 的 SPC，报警只是屏幕上的红灯，没人知道怎么办。一份 OCAP 通常包含：

步骤内容
1 触发哪条规则触发，是哪个特性、哪条线
2 遏制视严重程度：暂停该线、锁定可疑批次（见 不良品拦截与锁定）
3 排查一张"检查表"：先排除测量系统问题（SPI 校准、测试板），再查 5M1E（人、机、料、法、环、测）：钢网堵孔？刮刀压力？锡膏批次？回温时间？温湿度？
4 处置清洗钢网、调刮刀、更换锡膏、重新校准等；记录做了什么
5 验证处置后重新取一个子组，确认回到控制限内
6 放行工艺或质量确认后关闭报警，解除锁定；对已生产的可疑板评估（隔离、复判、返修）
7 升级重复发生或处理不了，升级到 8D与CAPA

不同规则对应不同严重度。例：规则 1（单点超限）→ 立即暂停并遏制；"8 点同侧"（趋势/偏移）→ 通知工艺在本班内排查，不一定停线。严重度分级要工艺和质量一起定。

与 MES 过站联动：失控锁线/锁批 ​

SPC 软件如果只在自己的界面上亮红灯，现场很容易忽略。真正有效的做法是把报警接进生产控制：

  • 在 SPC 检出严重失控时，由 SPC 向 MES 写一条锁定记录（Hold），把该线（或该锁定范围内的工单/批次）标为锁定；
  • MES 在过站（见 过站与工序流转）时检查锁定状态：被锁的线，板子扫码过站会被拒绝，并提示"SPC 报警未关闭：xxx"；
  • 解除锁定必须走流程：工艺/质量在 SPC 里填写处置说明、关闭报警，MES 才放开；
  • 同时，从上一个正常子组到报警子组之间生产的板，可以通过 SpcSample.Sn 追出来，评估是否要隔离。

两个系统怎么接（直接读库、API、消息）取决于你们的架构，见 MES与QMS衔接。锁线对生产影响很大，什么级别的报警锁线，务必有书面规定，避免误报频繁停线。

技术视角：表设计 ​

三张核心表加一张常数表：

表作用
SpcPoint控制点：一个被监控的特性（如"1号线 SPI 锡膏高度"），带规格限、控制图类型、子组大小，以及冻结后的控制限和版本
SpcSample样本：每个测量值一行，带子组号、序号、SN、产线、测量时间
SpcAlarm报警：哪个点、哪个子组、触发哪条规则、状态（OPEN/CLOSED）、处置人和说明
SpcChartConst控制图常数（A2、D3、D4、d2），放表里，不写死在 SQL 里

设计要点：

  • 控制限冻结后写回 SpcPoint，并带 LimitVersion：以后重新建限，版本加一，旧报警仍能说清用的是哪一版；更严谨的做法是把控制限独立成一张 SpcLimit 历史表，本篇为了简短放在 SpcPoint；
  • 报警对 (PointId, SubgroupNo, RuleCode) 加唯一约束，重复运行检测不会产生重复报警；
  • 样本、报警只追加不修改（报警状态除外，且要记录谁、什么时候、做了什么），与 数据完整性 的要求一致；
  • 样本带 Sn，出现失控后可以追到板。

逐步例子 ​

例 1：AOI 批不良率，p 图 ​

AOI 每批检查若干板，统计检出不良板数。批量不同，所以用 p 图，每批有自己的控制限。前 10 批用来建限，之后 3 批监控：

批检查板数 n不良板 dp = d/n
1~10500, 480, 520, 500, 450, 510, 500, 490, 530, 5009, 11, 8, 12, 10, 7, 13, 9, 10, 11约 1.4%~2.6%
11500122.40%
12480245.00%
13510101.96%
  1. p-bar = 100 / 4980 = 0.02008（总不良数除以总检查数）；
  2. 第 12 批 n = 480：标准差 = √(0.02008 × 0.97992 / 480) = 0.00640；
  3. UCL = 0.02008 + 3 × 0.00640 = 0.0393，LCL = 0.02008 − 0.0192 = 0.0009；
  4. 第 12 批 p = 0.0500 > 0.0393，失控；第 13 批回到 0.0196。

用 Python 复算（脚本 pchart.py）：

python
from math import sqrt
# AOI 每批：(检查板数 n, 检出不良板数 d)，前 10 批用来建限
lots = [(500, 9), (480, 11), (520, 8), (500, 12), (450, 10), (510, 7), (500, 13), (490, 9), (530, 10), (500, 11)]
new = [(500, 12), (480, 24), (510, 10)]          # 第 11~13 批
pbar = sum(d for _, d in lots) / sum(n for n, _ in lots)
print(f"p-bar = {sum(d for _, d in lots)}/{sum(n for n, _ in lots)} = {pbar:.5f}")
for i, (n, d) in enumerate(lots + new, 1):
    sd = sqrt(pbar * (1 - pbar) / n)
    ucl, lcl = pbar + 3 * sd, max(0.0, pbar - 3 * sd)
    p = d / n
    flag = "  <-- 失控" if p > ucl or p < lcl else ""
    print(f"批{i:2d} n={n} d={d:2d} p={p:.4f} LCL={lcl:.4f} UCL={ucl:.4f}{flag}")

from cc import xbar_r

第 3 步：用前 20 组算控制限并冻结。保存为 limits.sql：

sql
USE Lab_spc;
SET NOCOUNT ON;
-- 第一阶段：用前 20 个子组算控制限并冻结
;WITH sg AS (
    SELECT SubgroupNo, AVG(Value) AS m, MAX(Value) - MIN(Value) AS r
    FROM SpcSample WHERE PointId = 1 AND SubgroupNo <= 20 GROUP BY SubgroupNo),
agg AS (SELECT AVG(m) AS xbb, AVG(r) AS rbar FROM sg)
UPDATE p SET
    Cl = a.xbb, Ucl = a.xbb + c.A2 * a.rbar, Lcl = a.xbb - c.A2 * a.rbar,
    RCl = a.rbar, RUcl = c.D4 * a.rbar, RLcl = c.D3 * a.rbar,
    LimitVersion = 1, LimitFrozenAt = SYSUTCDATETIME()
FROM SpcPoint p CROSS JOIN agg a JOIN SpcChartConst c ON c.SubgroupSize = p.SubgroupSize
WHERE p.PointId = 1;
SELECT PointCode, CAST(Cl AS DECIMAL(9,4)) AS Cl, CAST(Ucl AS DECIMAL(9,4)) AS Ucl, CAST(Lcl AS DECIMAL(9,4)) AS Lcl,
       CAST(RCl AS DECIMAL(9,4)) AS RCl, CAST(RUcl AS DECIMAL(9,4)) AS RUcl, LimitVersion FROM SpcPoint;

第 4 步：检出失控点。保存为 detect.sql：

sql
USE Lab_spc;
SET NOCOUNT ON;
-- 第二阶段：对第 21 组以后检出失控点
;WITH sg AS (
    SELECT s.PointId, s.SubgroupNo, AVG(s.Value) AS m, MAX(s.Value) - MIN(s.Value) AS r
    FROM SpcSample s GROUP BY s.PointId, s.SubgroupNo),
j AS (
    SELECT sg.*, p.Cl, p.Ucl, p.Lcl, p.RUcl,
           CASE WHEN sg.m > p.Cl THEN 1 ELSE -1 END AS side
    FROM sg JOIN SpcPoint p ON p.PointId = sg.PointId),
w AS (
    SELECT j.*,
           SUM(side)  OVER (PARTITION BY PointId ORDER BY SubgroupNo ROWS BETWEEN 7 PRECEDING AND CURRENT ROW) AS sideSum,
           COUNT(*)   OVER (PARTITION BY PointId ORDER BY SubgroupNo ROWS BETWEEN 7 PRECEDING AND CURRENT ROW) AS cnt
    FROM j),
hits AS (
    SELECT PointId, SubgroupNo, 'XBAR_BEYOND_3SIGMA' AS RuleCode, m AS Statistic FROM w WHERE m > Ucl OR m < Lcl
    UNION ALL
    SELECT PointId, SubgroupNo, 'R_ABOVE_UCL', r FROM w WHERE r > RUcl
    UNION ALL
    SELECT PointId, SubgroupNo, 'WE4_8_SAME_SIDE', m FROM w WHERE cnt = 8 AND ABS(sideSum) = 8)
INSERT INTO SpcAlarm(PointId, SubgroupNo, RuleCode, Statistic)
SELECT h.PointId, h.SubgroupNo, h.RuleCode, h.Statistic FROM hits h
WHERE h.SubgroupNo > 20
  AND NOT EXISTS (SELECT 1 FROM SpcAlarm a WHERE a.PointId = h.PointId AND a.SubgroupNo = h.SubgroupNo AND a.RuleCode = h.RuleCode);

SELECT SubgroupNo, RuleCode, CAST(Statistic AS DECIMAL(9,3)) AS Statistic, Status FROM SpcAlarm ORDER BY SubgroupNo, RuleCode;

SELECT a.SubgroupNo, s.Sn, s.Value FROM SpcAlarm a JOIN SpcSample s ON s.PointId = a.PointId AND s.SubgroupNo = a.SubgroupNo

sql
USE Lab_spc;
SET NOCOUNT ON;
SELECT p.PointCode,
       CAST(p.RCl / c.D2 AS DECIMAL(9,4)) AS SigmaWithin,
       CAST((p.Usl - p.Lsl) / (6 * (p.RCl / c.D2)) AS DECIMAL(9,3)) AS Cp,
       CAST(CASE WHEN p.Usl - p.Cl < p.Cl - p.Lsl THEN p.Usl - p.Cl ELSE p.Cl - p.Lsl END / (3 * (p.RCl / c.D2)) AS DECIMAL(9,3)) AS Cpk

预期输出：

---------------------------------------- ----------- ----------- -----------
SMT-L1.SPI.HEIGHT                             1.8852       3.536       3.483

手算：σ = 4.385 / 2.326 = 1.8852；Cp = 40 / (6 × 1.8852) = 3.536；Cpl = (119.7 − 100) / (3 × 1.8852) = 3.483（比 Cpu 小，取它）。Python (119.7-100)/(3*4.385/2.326) 得 3.483，一致。规格宽、过程窄，所以 Cpk 很高；注意第 28 组之后过程已经不稳定，这个 Cpk 只对"前 20 组、稳定"这个阶段有意义。

业务视角 ​

角色在 SPC 里做什么
工艺工程师决定哪些特性上 SPC、规格限、子组与频率、规则启用、OCAP 内容；建限与重新建限；分析失控原因
质量工程师（QE）审核 OCAP、跟踪报警关闭率、过程能力报告（Cpk 趋势）、必要时发起 8D
产线 / 技术员收到报警后按 OCAP 检查、处置、填写记录
设备工程师校准 SPI/AOI；排查设备原因（刮刀、吸嘴、热电偶）
IT / 系统数据采集稳定、与 MES 联动、报警通知（看板、短信、企业微信等）

常用 KPI：报警数与关闭及时率、关键特性 Cpk 达标率、同一原因的重复报警数、误报率（报警后查不到原因的比例）。

常见坑与排查 ​

坑事实与办法
一开始就给所有参数上 SPC没人看得过来。先选关键特性，逐步扩展
控制限用了规格限或随手拍控制限必须由稳定阶段的数据算出，见 控制图
建限数据里已经有异常先剔除异常再建限；系统里要有"建限时排除某些子组"的功能
数据混了不同钢网、锡膏批次、产线分图。否则规则 8 之类会常触发，或者图毫无反应
只有报警，没有 OCAP报警变成噪音。每种报警必须有对应处置，处置结果要回填
SPI 的测量系统本身没校准控制图在监控测量误差。每天用标准块或首件验证 SPI，见 校准与量具管理
误报多，现场不再相信少开规则，用误报率数据调整，见 判异规则
失控就停线，影响产能严重度分级：只有严重失控才锁线，其余通知处理
解除锁定没有记录关闭人、时间、处置说明必须写入 SpcAlarm，用于审核与追溯
样本被修改SpcSample 只追加，不允许改；错误录入用作废标记，不是删除
时区混乱统一用一个时区存储时间，否则跨班次统计错位

练习题与答案 ​

  1. 为什么炉温峰值用 I-MR 图，而 SPI 锡膏高度用 Xbar-R 图？ 答：炉温测试一次只得到一个峰值，没法分子组，用 I-MR；SPI 连续生产，可以每次取连续 5 块板成一个子组，用 Xbar-R。
  2. 在 p 图例子里，第 12 批 n=480、p-bar=0.02008，UCL 是多少？ 答：标准差 √(0.02008×0.97992/480) = 0.00640，UCL = 0.02008 + 3×0.0064 = 0.0393。
  3. SpcAlarm 为什么要给 (PointId, SubgroupNo, RuleCode) 加唯一约束？ 答：检测任务可能重复运行（定时任务、补跑）。唯一约束保证同一个点同一个子组同一条规则只会有一条报警。
  4. 控制限冻结后写回 SpcPoint 并带版本号，好处是什么？ 答：以后重新建限时能区分每条报警是按哪一版控制限判的，历史结论说得清楚，也不会因为"天天重算"而掩盖漂移。
  5. 失控报警触发后，为什么先要"排查测量系统"？ 答：控制图数据来自 SPI。如果 SPI 本身漂移，会出现假的失控信号，把整条线停下来查工艺是白费功夫。先排除测量问题，再查人机料法环。
  6. 实验里子组 28 的 5 块板，如何知道是哪些板？ 答：SpcSample 带 Sn，用 PointId 和 SubgroupNo 关联即可（第 4 步最后一个查询）。再结合 产品追溯 查它们的下游、返修情况。

小结 ​

  • SMT 里优先监控关键特性：锡膏高度/体积/偏移（Xbar-R）、贴装偏移（Xbar-R）、炉温关键点（I-MR）、AOI 不良率（p 图）。
  • 子组要"理性"：连续生产、同线同钢网；建限 20~25 个子组，冻结后再监控。
  • 表设计：SpcPoint（点+规格+冻结的控制限）、SpcSample（带 SN 的样本）、SpcAlarm（唯一约束、状态、处置记录）、SpcChartConst（常数）。
  • 报警必须有 OCAP；严重失控通过 MES 过站闸门锁线/锁批，解除要有记录。
  • 本篇所有 SQL 和 Python 在本机跑过，SQL 结果与 Python 逐条一致。
