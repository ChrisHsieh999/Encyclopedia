电子制造信息系统全景图

AI 生成 · 待核对制造业务地图系统更新于 2026-10-21

⚠ 待核对：每个系统的一句话定义已对照维基百科；但"各系统之间传什么数据、谁是主数据的拥有者、QMS 和设备自动化的职责"这些内容是行业通用做法，来自模型知识，没有逐条联网核实。不同公司、不同厂商的系统边界差别很大，请以你们公司实际的系统为准，并把不一致的地方告诉我，我来修正。

本篇是"电子制造业务"的总地图。读完你应该能：说出 ERP、PLM、APS、MES、WMS、QMS、LIMS、SPC 和设备自动化各管什么；看懂一张系统关系图；知道一个业务事件（发料、报工、来料检验）在系统之间怎么流动；明白为什么"主数据"最容易出问题。

一句话定义 ​

电子制造的信息系统，就是由 ERP（管订单和钱）、PLM（管产品资料）、APS（管排产）、MES（管车间执行）、WMS（管仓库）、QMS 和 LIMS（管质量和检测）、SPC（管过程统计）和设备（真正干活）组成的一个分层协作的系统群，本篇用一张图把它们的关系讲清楚。

先修知识 ​

  • ISA-95：知道五个层级，这张全景图就是按它来组织的。
  • SMT与电子组装流程、PCB制造流程：知道电子厂里实际发生的物理过程，才明白这些系统在管什么。

它解决什么问题 ​

刚接触制造业信息化的人最常见的困惑是：这些系统缩写一大堆，到底谁是谁？为什么同一个数据（比如物料编码、BOM）在好几个系统里都有？订单、工单、批次、板码，它们是怎么串起来的？

这张地图先建立整体印象：每个系统一句话定位，再看数据在它们之间怎么流。以后学任何一个具体系统（MES、WMS、QMS、LIMS……），你都知道它在整张图的什么位置、和谁说话。

一张图看懂 ​

怎么读这张图：

  • 上面一层是计划：ERP 接订单和管财务，PLM 管产品资料，APS 排产。
  • 中间一层是执行，MES 在中心，WMS、QMS、LIMS、SPC 围绕着它。
  • 下面一层是设备，真正干活的机器和控制器。
  • 上下之间的箭头是主干：工单、BOM、排产计划往下，报工、完工、质量结果往上。
  • 为简洁，图里省略了一些次要连线：比如 WMS 和 QMS 之间的来料检验、SPC 和 QMS 之间的统计报警，见下面的数据流表。

每个系统一句话 ​

系统管什么在电子厂里的典型例子ISA-95 层
ERP企业主要业务流程的集成管理：订单、采购、库存财务、供应链等；常以一整套集成的应用软件的形式出现接客户订单、下生产订单、采购元器件、核算成本Level 4
PLM产品从诞生到退役整个生命周期的管理，包括 BOM、图纸、工程变更、文档管理产品的 BOM 和设计文件，发起工程变更（ECN）Level 4
APS高级计划与排程：同时考虑物料、人员、产能的限制，计划并排出生产顺序决定哪条线先做哪个工单、什么时候开工Level 4
MES跟踪和记录原料变成成品的整个过程的计算机系统下发工单、过站记录、上料防错、过程参数、追溯Level 3
WMS组织仓库工作的策略和流程，核心是记录库存的进出和位置来料收货、上架、发料、锡膏冷藏管理、湿敏元件管理Level 3
QMS质量管理体系的信息化：检验、不良处理、质量分析、纠正预防来料检验 IQC、制程检验 IPQC、不良处理、8DLevel 3
LIMS实验室运营的软件：样品登记与追踪、检测任务、仪器、结果和报告来料理化分析、可靠性试验、失效分析的样品与报告Level 3
SPC用统计方法监控和控制过程质量，用控制图判断过程是否稳定对印刷体积、炉温、尺寸等关键指标画控制图，超出控制限就报警Level 3
设备自动化（EAP）设备与上位系统的数据交换和控制：采集设备数据、下发配方、远程控制通过 IPC-CFX、OPC UA、Modbus 等协议与设备对话Level 2 的上方、Level 3 的接口

注：SPC、QMS 的界线、WMS 与 MES 的界线，在不同厂商的产品里差别很大，有的把几个合在一个产品里。

数据在系统之间怎么流动 ​

下面是一些常见的业务事件和数据流向（通用做法，具体以你们公司为准）：

业务事件从 → 到传什么备注
客户下单ERP订单、交期起点
产品资料发布 / 变更PLM → ERP、MES物料清单（BOM）、工艺信息、工程变更版本要对齐
排产ERP → APS → MES待生产的工单、排好的计划有的公司由 MES 自带排产
工单下达ERP（或 APS）→ MES产品型号、数量、BOM、计划时间
备料、发料MES → WMS；WMS → MES物料需求；实际发出的物料批次发料批次决定追溯基础
工单开工、过站MES ↔ 设备配方、程序下发；过站、设备状态、参数上传常通过 IPC-CFX、OPC UA 等
报工 / 完工MES → ERP完工数量、不良数量、工时用于入库和成本
成品入库MES → WMS → ERP入库数量、批次、库位
来料检验WMS → QMS（LIMS）→ WMS到货批次待检；检验结论（合格才能上架或放行）需要理化分析时进 LIMS
过程检验与不良MES ↔ QMS检验结果、不良代码；质量判定（放行、拦截）
过程统计MES、设备 → SPC → QMS / MES关键指标数据；超限报警、拦截
失效分析QMS → LIMS → QMS样品委托；分析报告结论回到 8D / 纠正预防

一个订单的一生（总览） ​

用一条主线把上面的系统串起来（只讲大概，详细的完整场景会在后面的"场景"类词条里展开）：

  1. 客户下单，订单进入 ERP；
  2. 产品的 BOM 和工艺由 PLM 发布，同步到 ERP 和 MES；
  3. APS 根据订单、物料和产能排出计划；
  4. ERP/APS 下达工单给 MES；
  5. MES 向 WMS 提出备料需求，WMS 发料到线边，并把发出的批次告诉 MES；来料如需检验，先经 QMS（和 LIMS）放行；
  6. 板子上线，MES 控制过站、防错，设备自动上传参数，SPC 监控关键指标，QMS 记录检验和不良；
  7. 完工后，MES 把完工数量报给 ERP，成品由 WMS 入库；
  8. 客户收货，若有质量问题，沿着板码从 MES、WMS、QMS 一路追溯。

主数据：最容易出问题的地方 ​

主数据是被多个系统共同使用、相对稳定的基础数据：物料编码、BOM、工艺路线、供应商、客户、设备。

在系统群里，同一份主数据往往在好几个系统里都有一份拷贝。常见的约定是，每类主数据有一个"拥有者"系统（比如 BOM 的源头常在 PLM 或 ERP），其他系统从它那里同步。一旦同步出问题，就会出现：

  • ERP 里 BOM 已经改版，MES 还在用旧版 → 车间按旧的 BOM 生产；
  • 同一种物料在两个系统里编码不一致 → 对不上账；
  • 设备编号、工序名称不统一 → 报表对不上。

所以做集成时，最先要问的问题不是"接口怎么写"，而是"这份数据的拥有者是谁，变更怎么同步，版本怎么对齐"。

系统之间怎么连：集成方式 ​

方式通俗解释优点缺点
数据库对接一方把数据写进共用的表，另一方来读简单直接耦合高，表结构一改就出问题
接口调用（API / Web Service）一方调用另一方提供的接口清晰、可控双方都要开发和维护
消息队列一方把消息放进队列，另一方异步取走解耦、可缓冲、可重试需要额外的基础设施
文件交换定时生成文件交给对方最容易起步不实时，容易出错

据维基百科对 ERP 与车间设备连接方式的描述，常见方式包括：直接集成、数据库集成（车间系统把信息写入数据库，ERP 从暂存表里读取）、专用的接口设备，以及系统集成商的定制开发。

动手实验：追踪一块板 ​

目标：体会"数据在系统间的足迹"。需要纸笔，可以结合你们公司实际的系统。

  1. 选一块（或一批）已经出货的板子，找到它的板码或批次号。
  2. 回答：这块板的订单是哪张？在哪个系统里查？
  3. 它用的BOM 是哪个版本？这个版本从哪来？
  4. 它的工单是什么时候下达的？上面的物料批次是从哪个仓库发出的？
  5. 它在 SMT 线上过了哪些工站？每个工站的数据存在哪个系统里？
  6. 它有没有被检验、被判过不良、被维修过？记录在哪里？
  7. 画一张表：每一步的数据是什么、存在哪个系统、怎么传到下一个系统。如果有哪一步你答不出来，把问题记下来问同事，那就是你要补的功课。

常见坑与误区 ​

误区事实
"MES 就是生产管理软件，什么都能管"MES 管车间执行与追溯；订单、财务归 ERP，仓库归 WMS，质量体系归 QMS，边界因厂商而异
"买了 ERP 就不需要 MES"ERP 通常不管工序级的实时执行和追溯，电子厂对追溯要求高，MES 不可替代
"各系统各管各的，数据不用统一"主数据不统一是集成故障最大的来源
"接口通了就没问题了"还要考虑失败重试、重复数据、时间戳、版本不一致等
"系统越多越先进"重要的是边界清晰、数据一致，不是系统数量

练习题与答案 ​

  1. 来料检验合格后才能上架，涉及哪几个系统？ 答：WMS（收货、待检、上架）、QMS（检验与判定），必要时 LIMS（理化分析）。检验结论回到 WMS 才能放行。
  2. 工单完工数量，最终由哪个系统确认入账？ 答：ERP。MES 报工把完工数量交给 ERP，由 ERP 用于入库和成本核算。
  3. 谁负责决定"哪条线先做哪个工单"？ 答：APS（或 MES 里的排产功能）。ERP 只管订单和交期。
  4. 产品 BOM 变更（ECN）通常从哪个系统发起？变更后要通知哪些系统？ 答：通常从 PLM（或 ERP）发起，需要同步到 ERP 和 MES，并保证各系统版本一致。
  5. SPC 控制图报了警，后续动作可能涉及哪些系统？ 答：通知 MES 拦截或暂停该批次，QMS 记录并发起不良处理。
  6. 为什么说"主数据是集成中最容易出问题的地方"？ 答：同一份数据（BOM、物料编码）常有多份拷贝，同步不及时或版本不一致，就会导致车间按旧数据生产、账对不上、报表错误。

小结 ​

  • 电子厂的信息系统是分层的系统群：计划层（ERP、PLM、APS）、执行层（MES、WMS、QMS、LIMS、SPC）、设备层。
  • MES 居中，向上对接计划，向下对接设备，向两侧对接仓库和质量。
  • 工单、BOM、排产往下流；报工、完工、质量结果往上流。
  • 主数据要有明确的拥有者，同步和版本对齐是集成成败的关键。
  • 不同公司的系统边界不同，学任何一个系统都要先弄清它在整张图的位置。
