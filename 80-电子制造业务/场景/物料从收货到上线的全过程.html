物料从收货到上线的全过程

AI 生成 · 待核对制造业务场景WMSQMSMES物料湿敏更新于 2026-10-21

⚠ 待核对：故事里的供应商、料号、批次、盘号、数量都是虚构的演示数据；收货容差（2%）、IQC 抽样方案（AQL 0.65）、拣货整盘发料、湿敏寿命 168 小时（MSL 3）、先到先用的拦截方式，是行业通用做法，你们的自研 WMS、MES 一定有自己的规则（比如是否拆盘发料、先到先用是拦截还是提醒），请对照你们的系统核实。所有 SQL 和输出都是我在本机 SQL Server LocalDB 的临时库 Lab_scene 里实际运行得到的。

本篇是"场景"系列第 3 篇。读完你应该能：说清一盘芯片从采购订单、到货、收货、检验、上架、拣货、发料、开封、上料、消耗、退料，每一步谁在哪个系统做了什么、产生什么记录、系统检查什么；理解"待检 / 合格"状态、"先到先用"、"湿敏寿命"这三个规则怎样在流程里生效；会写一条 SQL 把采购订单一路连到某块板；知道每一步出错时现场会是什么样、怎么查。

一句话定义 ​

物料全过程是：一盘料从 ERP 的采购订单出发，经仓库收货、来料检验放行、上架存放、按先到先用拣货发到线边，在贴片机上料时被防错规则校验、被湿敏寿命计时、被记录到每一块用到它的板上，最后用不完的部分退回仓库——在每一个交接点，数量、状态和批次都不能丢。

先修知识 ​

  • WMS、收货与上架：ASN、待检区、QC 状态。
  • 库存管理与批次序列号：Inventory、InvTxn。
  • 物料标签与条码：一盘一个标签（ReelId）。
  • IQC来料检验、抽样检验AQL：检验批、Ac/Re。
  • SMT上料防错与站位表：站位表、SlotLoad。
  • MSD湿敏元件管理：MSL 等级、车间寿命、计时。
  • 读过 工单从下达到入库的全过程 更好：那里发料和上料各一笔带过，这里展开。

它解决什么问题 ​

一个现场故事。一批 IC 到货，仓管看单子数量对就放上了货架。三天后产线领走贴了 400 块板，IQC 才报告"这批抽检 200 颗发现 5 颗引脚弯曲，拒收"。400 块板已经做出去了，要追回、返工、赔料。

另一个故事：这盘 IC 是湿敏元件（MSL 3，开封后 168 小时必须焊完）。操作员周一开封，用了一半，周五又拿出来接着用，早就超期。过炉后封装内部水汽膨胀，塑封"爆米花"开裂，ICT 测不出来，半年后客户那边才出问题。

物料的全过程管的就是这几件事：对得上（货和单）、可追溯（每颗料用到哪块板）、别用错（没检验的、过期的、错料号的、该先用却没先用的）。

核心概念：三个"门" ​

门位置规则违反的后果
状态门拣货、上线之前只有状态 Available（IQC 合格）的料才能拣、才能上线；QC、Hold、Defect 都不行把未检验的料做进产品
顺序门拣货与上料先到先用：同一种料，早入库的批次先用老料积压成呆滞料，还可能超保质期
寿命门上料湿敏元件开封后累计暴露时间不得超过车间寿命封装开裂、可靠性隐患

另外，所有"门"都是条件检查：条件不满足，操作被拒绝，而不是提示后放行。

批次、盘、标签的关系：供应商给的是批次号；仓库把每个最小包装（一盘）贴一个内部标签 ReelId；库存账按"物料 + 批次 + 库位 + 状态"记（Inventory），实物按盘管理（MatLabel）。两本账的合计必须相等（见实验第 3 节）。

逐步展开 ​

第 1 步 · 采购订单（10-12，ERP） ​

  • 谁/系统：采购员林峰在 ERP 的采购模块下单，见 采购管理。
  • 产生：PoLine：PO-20261012-05，供应商 SUP-0021，料号 IC-MCU-32，数量 5000。
  • 检查：供应商是否合格（见 供应商质量管理）、物料编码是否在主数据里（见 主数据与物料编码）。
  • 可能出什么问题：料号建错（同一颗料两个编码）、采购量没按 MOQ 取整。

第 2 步 · 到货核对（10-19 14:20，WMS） ​

  • 谁/系统：供应商送货到仓库，王芳核对送货单和 ASN，见 收货与上架。
  • 产生：AsnLine：ASN-20261019-03，计划 5000，容差 2%（上限 5000 x 1.02 = 5100）。
  • 检查：ASN 对应的 PO 存在、料号一致；湿敏防潮包装是否完好（真空袋、湿度指示卡），不完好直接拒收。
  • 可能出什么问题：无 ASN 的货（急料）要走特批；送货批次号和单据不一致。

第 3 步 · 扫码收货入待检区（14:21-14:30，WMS） ​

  • 谁/系统：王芳逐盘扫码，每盘打一个内部标签，见 物料标签与条码。
  • 产生：MatLabel 5 行：R-U901-01 到 R-U901-05，每盘 1000，日期码 2640，批次 LOT-U-901，状态 QC，库位 RM-RCV-01；14:30 Inventory 增加 5000（状态 QC），InvTxn 写一条 Receive，单据号是 ASN 号。
  • 检查：每扫一盘就执行一条条件 UPDATE：ReceivedQty + 1000 <= PlanQty x (1 + 容差)。前 5 盘累计到 5000，第 6 盘（累计 6000 > 上限 5100）被拒绝，这就是实验开头那行"第 6 盘扫码：被拒绝"。
  • 可能出什么问题：供应商多送了；仓管把同一盘扫了两次（重复扫描）。条件 UPDATE 同时防住了这两件事。

第 4 步 · IQC 开检验批（10-19 14:40，QMS） ​

  • 谁/系统：收货完成后自动通知 IQC，刘洋开检验批，见 IQC来料检验。
  • 产生：InspectionLot：IQC-20261019-002，批量 5000，抽样 200，Ac/Re = 3/4。方案怎么来的：批量 5000 落在 3201～10000，水平 II 的代码字母是 L；AQL 0.65 在 L 行抽 200、Ac = 3、Re = 4（见 抽样检验AQL）。
  • 检查：待检期间，这批料对拣货不可见。实验里在 15:00 查一次"可拣货的 MCU 盘"，结果是 1 盘、300 颗——只有老批次 LOT-U-777；刚到的 5000 颗一颗都看不到。
  • 可能出什么问题：IQC 积压，产线等料；仓管为了赶工把待检料偷偷领出去（状态门就是为此设的）。

第 5 步 · 抽检判定（10-20 09:30，QMS） ​

  • 谁/系统：刘洋检验外观、尺寸、引脚，抽 200，发现 1 个引脚弯曲。
  • 产生：检验批 DefectFound = 1，Result = Accept（1 ≤ Ac 3），JudgedAt = 09:30。
  • 检查：判定是规则算出来的：不良数 ≤ Ac 接收，≥ Re 拒收。
  • 可能出什么问题：不良数落在 Ac 和 Re 之间（这里 3 和 4 之间没有空隙，但有些方案有）；拒收后要走 不合格品控制NCR 退货。

第 6 步 · 放行并上架（10-20 09:40，WMS） ​

  • 谁/系统：王芳收到 IQC 放行，上架到 RM-A-02-04。
  • 产生：标签状态 QC → Available，库位 RM-RCV-01 → RM-A-02-04；库存的 QC 行换成 Available 行；InvTxn 一条 PutAway（5000，单据 PA-20261020-01）。
  • 检查：放行的 UPDATE 里带 EXISTS (检验批 Accept)——没有合格的检验批，状态改不了。
  • 可能出什么问题：放行靠人手工改状态，绕过 IQC。

第 7 步 · 拣货（10-26 07:10，WMS） ​

  • 谁/系统：工单 WO20261023003 下发后，WMS 按 BOM 生成拣货需求，王芳处理，见 拣货与发料、先进先出与先到先用。
  • 产生：PickLine 2 行：R-U777-07（LOT-U-777，300）和 R-U901-01（LOT-U-901，1000）。分配算法：把可拣的盘按入库时间排序，累计数量，取"累计到上一盘还不够 400"的那些整盘。第一盘（300）累计前为 0 < 400 取；第二盘累计前为 300 < 400 取；第三盘累计前为 1300 ≥ 400 不取。LOT-U-905 因为是待检（QC）根本不在候选里，R-U901-02 ~ -05 因为累计够了不取。
  • 检查：只拣 Available；按 ReceivedAt（先到先用）排序。整盘发料：400 颗需求发了 1300 颗，富余的 900 颗用完后退回。

第 8 步 · 发料到线边（10-26 07:21-07:22，WMS） ​

  • 谁/系统：王芳扫码确认，料转到线边仓 LINE-SMT1，见 WMS与MES交互。
  • 产生：InvTxn 2 条 Issue（LOT-U-777 300，LOT-U-901 1000）；标签的库位变成 LINE-SMT1；库存仓库侧扣、线边侧加。
  • 检查：Inventory.Qty 有 CHECK (Qty >= 0)，扣成负数会被拒绝。
  • 可能出什么问题：只发了料没转账，线边有料而系统里没有。

第 9 步 · 开封与湿敏计时（08:20、09:40，MES/WMS） ​

  • 谁/系统：张伟拆开真空包装，扫码登记开封，湿敏计时开始，见 MSD湿敏元件管理。
  • 产生：MsdEvent：R-U777-07 在 08:20 Open；R-U901-01 在 09:40 Open。MsdSpec 里 IC-MCU-32 是 MSL 3，车间寿命 168 小时 = 10080 分钟。
  • 检查：每次上料时，函数 MsdUsedMin 会算出这一盘已经用了多少分钟：从 Open/TakeOut 开始，到下一个 Cabinet/Reseal/Bake 结束；没结束就算到"现在"。已用 ≥ 10080 分钟就拒绝。
  • 可能出什么问题：不登记开封时间，寿命就无从算起。

第 10 步 · 上料防错（08:25-09:44，MES） ​

  • 谁/系统：张伟用扫码枪逐盘扫，MES 做 5 项检查，见 SMT上料防错与站位表。

    • 08:26 他又拿了一盘电阻（R-R002-11）想装 M1-03：被站位表拦下（站位要 IC-MCU-32，这盘是 R-10K-0402）；
    • 08:26 再拿 R-U905-01（待检批次，没发到线边）：被"未发到线边"拦下；
    • 08:27 装 R-U777-07：成功。

  • 检查：唯一索引防止同一板同一站位重复记；记快照和出站在同一个事务里。
  • 可能出什么问题：快照没记（追溯断链）；换料时间和板的出站时间对不上，归属错盘。

第 12 步 · 下料、归柜、退料（10:15-10:30，MES/WMS） ​

技术视角 ​

表怎么串成一条链 ​

PoLine(PoNo) ← AsnLine(PoNo) → MatLabel(ReelId, LotNo) ─┬─ Inventory(MaterialCode, LotNo, LocationCode, Status)
                                                        ├─ InvTxn(DocNo = ASN / 拣货单 / 退料单)
                                                        ├─ MsdEvent(ReelId)
                                                        ├─ InspectionLot(ItemLotNo = LotNo)
                                                        ├─ PickLine(ReelId)
                                                        └─ SlotLoad(ReelId) → UnitMaterial(LotNo, SerialNo)

关键技巧 ​

  1. 收货容差：条件 UPDATE ReceivedQty + @q <= PlanQty * (1 + 容差)，和 工单管理 的防超报同一个思路。
  2. 先到先用：用窗口函数 SUM(Qty) OVER (ORDER BY ReceivedAt, ReelId ROWS UNBOUNDED PRECEDING) - Qty 算出"这盘之前累计了多少"，小于需求量的整盘都取。
  3. 湿敏计时：一个标量函数，从事件流水里算出累计暴露分钟；事件表只追加，不改。
  4. 上料检查：一个存储过程 usp_LoadReel，五项检查按顺序，输出拒绝原因，成功才写 SlotLoad。真实系统里应该是一个事务，把"写上料记录、改标签位置、写湿敏 Load 事件"一起提交。
  5. 两本账对账：库存合计与标签合计 JOIN 对比。不一致就是有人动了其中一本。

-- 湿敏已用分钟数：每次 Open/TakeOut 开始计时，到下一次 Cabinet/Reseal/Bake 结束；还没结束就算到 @now
CREATE FUNCTION dbo.MsdUsedMin (@reel nvarchar(30), @now datetime2(0)) RETURNS int AS
BEGIN
    DECLARE @u int;
    SELECT @u = ISNULL(SUM(DATEDIFF(MINUTE, s.At, ISNULL(x.EndAt, @now))), 0)
    FROM MsdEvent s
    OUTER APPLY (SELECT MIN(e.At) AS EndAt FROM MsdEvent e WHERE e.ReelId = s.ReelId AND e.EventType IN (N'Cabinet', N'Reseal', N'Bake') AND e.At > s.At AND e.At <= @now) x
    WHERE s.ReelId = @reel AND s.EventType IN (N'Open', N'TakeOut') AND s.At <= @now;
    RETURN @u;
END
GO
-- 上料检查（精简版）：站位表 -> 先到先用 -> 是否发到线边 -> 湿敏寿命 -> 站位是否空闲，全部通过才记 SlotLoad
CREATE PROCEDURE dbo.usp_LoadReel @slot nvarchar(10), @reel nvarchar(30), @at datetime2(0), @op nvarchar(30), @msg nvarchar(200) OUTPUT AS
BEGIN
    DECLARE @mat nvarchar(30), @lot nvarchar(30), @recv datetime2(0), @need nvarchar(30), @loc nvarchar(30), @used int, @life int;
    SELECT @mat = MaterialCode, @lot = LotNo, @recv = ReceivedAt, @loc = Location FROM MatLabel WHERE ReelId = @reel;
    SELECT @need = MaterialCode FROM FeederMap WHERE ProductCode = N'PCBA-A100' AND LineCode = N'SMT-01' AND SlotNo = @slot;
    IF @mat IS NULL BEGIN SET @msg = N'拒绝：查不到这盘料'; RETURN; END
    IF @mat <> @need BEGIN SET @msg = N'拒绝：站位 ' + @slot + N' 要 ' + @need + N'，这盘是 ' + @mat; RETURN; END
    IF @loc <> N'LINE-SMT1' BEGIN SET @msg = N'拒绝：这盘料没有发到线边（现在在 ' + @loc + N'）'; RETURN; END
    IF EXISTS (SELECT 1 FROM MatLabel o WHERE o.MaterialCode = @mat AND o.Location = N'LINE-SMT1' AND o.ReceivedAt < @recv AND o.Qty > 0)
    BEGIN SET @msg = N'拒绝：更早入库的批次还在线边，请先用旧的（先到先用）'; RETURN; END
    SELECT @life = FloorLifeHours * 60 FROM MsdSpec WHERE MaterialCode = @mat;
    SET @used = dbo.MsdUsedMin(@reel, @at);
    IF @life IS NOT NULL AND @used >= @life BEGIN SET @msg = N'拒绝：湿敏寿命用尽'; RETURN; END
    IF EXISTS (SELECT 1 FROM SlotLoad WHERE LineCode = N'SMT-01' AND SlotNo = @slot AND UnloadedAt IS NULL) BEGIN SET @msg = N'拒绝：站位上还有一盘料没下'; RETURN; END
    INSERT SlotLoad (LineCode, SlotNo, ReelId, MaterialCode, LotNo, LoadedAt, Operator) VALUES (N'SMT-01', @slot, @reel, @mat, @lot, @at, @op);
    UPDATE MatLabel SET Location = N'SLOT' WHERE ReelId = @reel;
    INSERT MsdEvent VALUES (@reel, N'Load', @at, @op);
    SET @msg = N'成功';
END
GO

如果某一步出错会怎样（5 个故障场景与排查） ​

场景 1：超收、短收、错收（第 2、3 步） ​

  • 现象：账上收了 6000，供应商只送了 5000；或者库里多出一批不属于任何 ASN 的料。
  • 原因：没有按 ASN 做累计上限检查；或者同一盘被重复扫描；或者无 ASN 的急料入了库。
  • 排查思路：对比 AsnLine.ReceivedQty、MatLabel 里该 ASN 批次的标签数量总和、InvTxn 里 Receive 的合计；找出哪两个数字不同。
  • 处理：多收的退供应商；重复扫描的标签作废。预防靠第 3 步的条件 UPDATE。

场景 2：待检料被领走（第 4-7 步） ​

  • 现象：IQC 判拒收时，这批料已经有一部分在产线上或已经贴到板上。
  • 原因：拣货没限制 Status = Available，或有人手工把状态改成了 Available。
  • 排查思路：看 InvTxn 里该批次 Issue 的时间是否早于 InspectionLot.JudgedAt；Inventory 里该批次的状态变更有没有对应的 Accept 检验批；用 UnitMaterial 反查已经用到哪些板，立刻锁定，见 不良品拦截与锁定。
  • 处理：已用的板按批次锁定；该批库存冻结，走 NCR 退货。

场景 3：先到先用被破坏（第 7、10 步） ​

  • 现象：老批次 LOT-U-777 一直剩着，几个月后变成呆滞料，甚至超保质期；新批次却用掉了很多。
  • 原因：拣货按库位远近而不按入库时间，或线边有多批同种料时操作员随手拿。
  • 排查思路：按料号列出所有批次的 ReceivedAt 和余量，看最老的批次是否长期没动；看 SlotLoad 里同一种料装上的批次顺序是不是和入库顺序相反。
  • 处理：拣货按 ReceivedAt 排序；上料时加"先到先用"拦截（第 10 步），见 退料与呆滞料。

场景 4：湿敏料超期上线（第 9、10、12 步） ​

  • 现象：ICT、FCT 全过，几个月后同一批次的板陆续出现封装开裂、功能间歇失效。
  • 原因：开封后没登记时间；剩料没放回干燥柜，暴露时间一直在累计；或烘烤后没登记 Bake。
  • 排查思路：对该批次所有盘，调用 MsdUsedMin 算累计暴露，找出已用 ≥ 10080 分钟的；看 MsdEvent 里 Open 与 Cabinet 是否成对。
  • 处理：圈出用过这些盘的板（第 11 步的快照），按批次追溯锁定；之后必须有上料时的寿命拦截。

场景 5：库存账与标签对不上，或追溯断链（第 11、12 步） ​

  • 现象：盘点时库存合计 5000，标签合计 4900；或客诉追溯某块板时，查不到它用了哪批 MCU。
  • 原因：退料只改了其中一本账；线边消耗没回写；UnitMaterial 没记（出站和快照不在同一个事务里）。
  • 排查思路：实验第 3 节的对账查询，按批次对比库存合计与标签合计；追溯完整性：找"有贴片记录的板但没有 UnitMaterial"，见 产品追溯；再看 库存账与账实一致 的对账流程。
  • 处理：按冲销方式补账（新增一笔差异调整，写明原因），不要直接改流水。

练习题与答案 ​

  1. ASN 计划 5000，容差 2%，累计最多能收多少？第 6 盘（1000）为什么被拒？ 答：5000 x 1.02 = 5100；前 5 盘累计 5000，加第 6 盘到 6000 > 5100，被拒。
  2. 批量 5000、水平 II、AQL 0.65，IQC 抽多少、Ac/Re 是多少？抽到 3 个不良怎么判？ 答：批量落在 3201～10000，代码字母 L，AQL 0.65 抽 200，Ac/Re = 3/4。3 个不良 ≤ Ac，接收。
  3. 需求 400 颗，可拣盘依次是 300、1000、1000、1000、1000。按"累计前 < 需求"取，取哪几盘？ 答：累计前依次 0、300、1300……；0 < 400 取，300 < 400 取，1300 ≥ 400 不取，所以取前两盘，共发 1300 颗。
  4. 一盘 MSL 3 的料，08:20 开封，一直放在线边，到次日 08:20 暴露多少分钟？还剩多少？ 答：24 小时 = 1440 分钟；10080 − 1440 = 8640 分钟（144 小时）。
  5. 为什么上料检查里"已发到线边"要放在"先到先用"之前？ 答：先确认这盘料能不能用（在线边、状态可用），再比较顺序；否则对一盘没发到线边的料谈"先到先用"没有意义，错误信息也会误导操作员。
  6. 为什么 R-U901-01 退回 900 颗之前，线边库存要先扣 100？ 答：100 颗已被贴到板上（第 301～400 块），不再属于库存；先扣掉实际消耗，线边余额才等于实物，然后退回的 900 才不会让线边变成负数、仓库多出 100。

小结 ​

  • 物料全过程是 12 步：采购订单、到货核对、扫码收货、IQC 开批、判定、放行上架、拣货、发料、开封、上料防错、物料快照、下料退料。
  • 三个门：状态门（只有 Available）、顺序门（先到先用）、寿命门（湿敏）；全部做成拒绝，而不是提示。
  • 批次、盘、标签、库存是多层的账，必须有对账查询；UnitMaterial 把每颗料和每块板连起来。
  • 数字：收货上限 5100；IQC 抽 200、Ac/Re 3/4；整盘发 1300 用 400、退 900；湿敏用掉 40 分钟、剩 10040。
  • 出错先看交接处：到货 → 仓库、仓库 → 线边、线边 → 板，每个交接点都有数量和批次要对。
