工单从下达到入库的全过程

AI 生成 · 待核对制造业务场景MESWMSQMSERP更新于 2026-10-21

⚠ 待核对：本篇是把前面各系统串起来的故事。故事里的人物、工单号、板码、数量都是虚构的演示数据；各系统的状态名、表名、字段沿用本知识库里已有词条的"通用做法"，并做了精简（文中标"精简版"）。你们自研的 MES、WMS、QMS、ERP 一定有自己的叫法和规则，请对照你们的系统逐步核实，特别是：下发时检查哪些东西、首件制度、FQC 抽样方案、工单"关闭"的条件、ERP 与 MES 的数量口径。所有 SQL 和输出都是我在本机 SQL Server LocalDB 的临时库 Lab_scene 里实际运行得到的。

本篇是"场景"系列第 1 篇。读完你应该能：说出一张工单从 ERP 里的销售订单一直走到成品入库、再到关闭，每一步谁在哪个系统里做了什么、产生了哪张单据或记录、系统做了哪些检查；说清楚几个系统之间靠哪些"号"（订单号、工单号、板码、批次号、单据号）串在一起；会写一条跨表的 SQL 把整条线查出来；知道每一步出错时现场会看到什么、该从哪里查。

一句话定义 ​

工单全过程就是：客户订单 → 生产订单 → MES 工单 → 备料发料 → 开线首件 → 逐板过站 → 不良返修 → 完工报工 → 成品检验 → 入库 → 退料对账 → 关闭，这条主线上每个环节的人、系统、单据和检查点连成的一条完整链子。

先修知识 ​

这是一篇"串联"的文章，不需要精通每个系统，但下面几篇至少要大致看过，遇到不懂的地方再回头：

  • 电子制造信息系统全景图：ERP、MES、WMS、QMS 各管什么、数据怎么流。
  • 工单管理：工单状态机，以及"把检查条件写进 UPDATE 的 WHERE 里"。
  • 过站与工序流转：Unit、TrackRecord 两张表，进站检查和出站。
  • SMT与电子组装流程：印刷、SPI、贴片、回流、AOI 的顺序。
  • 会读基本的 SQL（SELECT、JOIN、UNION ALL）。

它解决什么问题 ​

先看一个"各系统都没错，但整件事还是乱了"的现场故事。

月底对账，财务问："ACME 那张 480 块 A100 的订单，生产订单上写投入 500，仓库发了 6120 个电阻，成品入库 497，到底成本怎么算？" 计划员说"我下的是 500"，仓管说"我按单耗加损耗发的"，产线说"我们做了 500 块，报废 3 块"，品质说"FQC 抽了 80 块没问题"。每个人说的都对，但没有人能在十分钟内把这几个数字串成一条线：500 投入 = 497 良品 + 3 报废；6120 发料 = 6000 理论 + 80 抛料 + 40 退料；497 入库 ≥ 480 订单。

单个系统的词条讲的是"一个零件怎么造"，这一篇讲的是"整台机器怎么转"。把全过程走一遍，你能看清：

  • 数字是怎么在系统之间换算的（良品数 480 变成投入数 500）；
  • 哪些检查是关口，一旦失败整条线就停（下发、首件、FQC、关闭）；
  • 出了差错，应该顺着哪条线去查（订单号 → 工单号 → 板码 → 批次）。

逐步展开 ​

下面每一步按同一个格式讲：谁在什么系统做了什么 → 产生什么 → 系统检查什么 → 可能出什么问题。数字都来自本篇末尾的实验脚本。

第 1 步 · 接单评审（10-08，ERP） ​

  • 谁/系统：销售郑丽在 ERP 的销售订单里录入客户 ACME 的订单，见 销售订单。
  • 产生：SoLine：SO-20261008-03，产品 PCBA-A100，数量 480，承诺交期 2026-11-06。
  • 检查：评审技术（有没有 BOM 和路线）、物料（单片机够不够）、产能（SMT-01 线几号空）。
  • 可能出什么问题：口头答应交期不评审；承诺日和客户要求日混成一个字段（见 销售订单 的"三个日期"）。

第 2 步 · 生成生产订单（10-21 08:30，ERP/APS） ​

  • 谁/系统：计划员陈敏用 MRP（见 生产计划MRP）和 APS（见 排程基础）把订单变成生产订单。
  • 产生：ProdOrder：WO20261021001，PlanQty = 480（良品），StartQty = 500。500 是怎么来的：良率按 96% 算，480 ÷ 0.96 = 500，刚好整除。
  • 检查：MRP 展开 BOM 看各物料的毛需求；APS 把它排到 SMT-01 线 10-22 08:00 开始。
  • 可能出什么问题：良率估高了，投入不够，良品交不够订单；估低了，多投料占库存。

第 3 步 · 工单送进 MES（10-21 08:45，接口） ​

  • 谁/系统：ERP 与 MES 之间的接口（见 ERP与MES衔接、MES与ERP及设备的接口设计）。
  • 产生：MES 的 WorkOrder：WoNo = WO20261021001，PlanQty = 500（取的是 ERP 的 StartQty），状态 Created；WoLog 记一条"（新建）→ Created，interface"。
  • 检查：工单号是主键，接口重试时同一张工单只会存在一张（幂等）。
  • 可能出什么问题：把 480 当成 MES 的计划数，结果只投 480，良品永远凑不到；接口丢消息，MES 里没有工单，车间无单可做。

第 4 步 · 下发（10-21 09:10，MES） ​

  • 谁/系统：主管周杰在 MES 点"下发"。
  • 产生：状态 Created → Released；BomId = 1（BOM v1.0）、RouteId = 1（路线 v1.0）被绑定到这张工单上；WoLog 记 sup.zhou。
  • 检查：一条条件 UPDATE 同时检查"当前必须是 Created"和"该产品有生效的 BOM 与路线"。实验里下发返回受影响 1 行；再点一次返回 0 行，被安全拒绝。
  • 可能出什么问题：没有生效的 BOM（刚改版还没发布）→ 下发 0 行；下发后 BOM 改版，工单仍按绑定版本（见故障场景 2）。详见 工单管理。

第 5 步 · 备料（10-21 14:10，WMS） ​

  • 谁/系统：仓管王芳在 WMS 里按工单生成拣货单，见 拣货与发料。
  • 产生：PickLine 4 行（拣货单 PK-20261021-01）。数量的算法是 ⌈投入 x 单耗 x (1+损耗率)⌉：
    • PCB-A100：500 x 1 x 1.00 = 500；
    • R-10K-0402：500 x 12 x 1.02 = 6120；

谁关心什么：

角色最关心的数字对应 KPI
销售能不能 11-06 前交 480 块准时交付率 OTD
计划员投入 500 是否合理计划达成率、良率假设

本故事的核心数字：直通率 486 ÷ 500 = 97.2%；最终良率 497 ÷ 500 = 99.4%（返修救回了 11 块）；对订单的满足 497 ÷ 480 = 103.5%。

业务规则的"关口"：下发（有 BOM/路线）→ 开工（首件 Pass）→ 完工（数量闭合）→ 入库（FQC Accept）→ 关闭（账平）。每个关口都是"条件不满足就拒绝"，而不是"提醒一下"。

技术视角 ​

表怎么串成一条链 ​

SoLine(SoNo) ← ProdOrder(SoNo, WoNo) ── WorkOrder(WoNo)
                                          ├─ Unit(WoId) ── TrackRecord(SerialNo) / DefectRecord(SerialNo)
                                          ├─ PickLine(WoNo) ── InvTxn(DocNo = 拣货单号)
                                          ├─ FirstArticle(WoNo)
                                          └─ LineConsume(WoNo)
InspectionLot(ItemCode, 批量) ── 入库 InvTxn(LotNo = 工单号) ── ProdOrder.ReceivedQty

对应的表在 MES核心数据模型、库存管理与批次序列号、不合格品控制NCR 等词条里各有详细设计，本篇的建表语句是精简版（只保留故事用到的列）。

关键技巧一：状态流转全部是"条件 UPDATE" ​

每个关口都是一条 UPDATE ... WHERE 当前状态 = ... AND 条件，成功与否看受影响行数，和 工单管理 一致。例如下发：

sql
UPDATE w SET Status = N'Released', BomId = b.BomId, RouteId = r.RouteId
FROM WorkOrder w
JOIN Bom b ON b.ProductCode = w.ProductCode AND b.Status = N'Active'
JOIN Route r ON r.ProductCode = w.ProductCode AND r.Status = N'Active'
WHERE w.WoNo = N'WO20261021001' AND w.Status = N'Created';

关键技巧二：跨表查询，把整条线串起来 ​

最后一节的第 4 条查询用 JOIN 沿着"订单号 → 生产订单 → 工单 → 检验批"走一遍；第 1 条用 UNION ALL 把各系统的事件统一成"时间、系统、事件"三列，按时间排序，就是全过程的时间线（和 产品追溯 的做法一样）。第 5 条从一块板出发，展示它在 6 个工序上的履历，包括 AOI 失败、修复、复测。

关键技巧三：账要能"闭合" ​

整个故事有三组必须闭合的等式，每一组都对应一条核对 SQL：

  1. 数量：完工 + 报废 = 投入（500 = 497 + 3）；
  2. 物料：发出 = 理论消耗 + 抛料 + 退料；
  3. 四方数量：Unit 完工数 = 工单完工数 = WMS 入库数 = ERP 收到数（都是 497，实验第 6 节有核对查询）。

  1. 把第 12 步完工里 @f + @s = PlanQty 去掉，再把一块板的状态改成 InProcess，看工单会不会被错误地推进到 Completed；
  2. 在第 13 步 FQC 判定里把 DefectFound = 0 和 CASE WHEN 0 <= Ac 里的 0 都改成 2（≥ Re），看判定变成什么；入库那一段 @ok 是几、最后工单能不能关闭；
  3. 把第 6 步的某一行发料数量改成比库存大，看 CHECK (Qty >= 0) 和 Qty >= @q 条件谁先拦下。

如果某一步出错会怎样（5 个故障场景与排查） ​

场景 1：ERP 把同一张工单发了两次（第 3 步） ​

  • 现象：接口日志里有两条一样的工单号；或者 MES 里出现两张只差一位的工单，各自下发、各自领料。
  • 原因：接口超时后重试，而 MES 端没有做幂等（用工单号做主键的写法是"存在则更新或忽略"）。
  • 排查思路：查 WorkOrder 里同一订单对应几张工单（ProdOrder.SoNo 相同的行数）；对比 ERP 的生产订单号；看接口收件箱表里的消息序号有没有重复。
  • 处理：保留正确的一张，另一张状态是 Created 的直接取消；已下发的要先退料。根治办法是主键 + 幂等，见 ERP与MES衔接。

场景 2：下发后 BOM 改版（第 4、5 步之间） ​

  • 现象：工程发布了 BOM v1.1（换了电容），但车间做出来的板仍然是 v1.0 的物料清单。
  • 原因：下发时绑定了 BomId，之后主数据改版不影响已下发的工单——这是设计如此，保证同一张工单前后一致。
  • 排查思路：核对"工单绑定 BOM"和"当前生效 BOM"是否一致（实验第 6 节有这条查询，当前两者都是 1）；看变更通知 ECN 的生效点是"哪张工单起"，见 变更管理ECN-ECR。
  • 处理：需要切换新版就在 ECN 里规定从哪张工单、哪个板码起切，已下发的工单要么取消重下，要么按 ECN 规定处理在制品。

场景 3：少发了料，开工后线边断料（第 5、6 步） ​

  • 现象：生产到一半，M1-01 站位报"缺料"，线体停机等料。
  • 原因：拣货单数量漏了损耗，比如电阻只发了 6000（500 x 12），没加 2% 的损耗 120 个，抛料几十个后就不够。
  • 排查思路：对 PickLine.PlanQty 与 ⌈PlanQty x QtyPer x (1+LossRate)⌉ 逐行核对；看 InvTxn 里 Issue 的实际数量；看线边 Inventory 余量。
  • 处理：补发；根治是拣货单由系统按 BOM 自动算，不要手填，见 拣货与发料。

场景 4：首件被口头放行，量产后批量错误（第 8、9 步） ​

  • 现象：开工后 AOI 连续报同一个位号出错；统计一看，从第一块板起就错。
  • 原因：首件没做或没过，却被人"先开起来"；或系统没有门禁。
  • 排查思路：查线体最新一张 FirstArticle 是什么状态、时间；查 WoLog 里开工的时间是否晚于首件 Pass 的时间；对出错板找共同点（程序、料、钢网），见 首件检验与换线。
  • 处理：立刻停线，圈出开工以来所有板锁定（见 不良品拦截与锁定）；补首件；把"开工条件含首件 Pass"写进 SQL，不靠人。

场景 5：完工数、入库数、ERP 数对不上（第 12-15 步） ​

  • 现象：财务发现 ERP 里这张生产订单收货 500，WMS 入库 497；或者工单关不掉。
  • 原因：常见三种：返修板在 FQC 之后才修好又补入库一次；报废 3 块没在 ERP 里做报废；入库时用了计划数而不是实际完工数。
  • 排查思路：先跑四方核对（实验第 6 节）：Unit 的 Completed 数、工单 FinishedQty、InvTxn 里 Receive 的合计、ProdOrder.ReceivedQty，哪一个与别的不同，问题就在哪两个系统的交接处；再查发料账（实验第 3 节）。
  • 处理：差异用"冲销 + 重新登记"处理，不要直接改流水；根因进 库存账与账实一致 的对账流程。

常见误区 ​

误区事实
MES 的计划数就是订单量是投入数（含良率损耗），本例 500 对 480
报废的板不用管要登记，完工 + 报废 = 投入才能闭合
关闭工单只是改个状态关闭是"账平"的证明，条件不满足要拒绝
入库后 FQC 补做也行顺序错了，入库必须以 FQC Accept 为前提
系统之间用人工对数要用号 + SQL 核对，把对数变成可重复的检查

练习题与答案 ​

  1. ERP 订单量 480，良率估 96%，投入数是多少？如果良率估 95% 呢？ 答：480 ÷ 0.96 = 500；480 ÷ 0.95 = 505.26，向上取整是 506。取整一律向上，宁多勿少。
  2. 电阻单耗 12、损耗率 2%、投入 500，拣货单应是多少？ 答：500 x 12 x 1.02 = 6120，刚好整数；若不整除要向上取整。
  3. 500 块板中 9 块 AOI 不良、5 块 FCT 不良，其中 3 块报废，直通率与最终良率各是多少？ 答：直通率 = (500 − 14) ÷ 500 = 97.2%；最终良率 = 497 ÷ 500 = 99.4%。
  4. 为什么开工的条件要写成 WHERE Status = 'Released' AND 首件Pass，而不是先查再改？ 答：先查再改有时间差，期间别人可能改了状态或首件结果；写进同一条 UPDATE，由数据库保证"检查 + 修改"不可分割，受影响行数 0 即被拒绝，见 工单管理。
  5. 批量 497，AQL 0.65，水平 II，FQC 抽多少块？抽到 2 块不良怎么判？ 答：H 行遇箭头换 J 行，抽 80，Ac = 1、Re = 2；2 ≥ Re，拒收。
  6. 本例入库 497，订单只要 480，多出的 17 块怎么办？为什么不能直接丢掉？ 答：它们是合格品，按公司规则作为备货或下次发货；不能丢，因为已经入账，丢了会造成账实不一致。

小结 ​

  • 一张工单的全过程是 15 步：接单评审、生产订单、进 MES、下发、备料发料、上料、首件、开工、过站、返修、完工、FQC、入库、退料对账、关闭。
  • 系统之间靠号对接（订单号、工单号、拣货单号、批次号、板码、检验批号），数量要注意口径（订单量 480 对投入数 500）。
  • 每个关口都是"条件不满足就拒绝"的条件 UPDATE：下发、开工、完工、入库、关闭。
  • 三组等式要能闭合：完工 + 报废 = 投入；发出 = 理论 + 抛料 + 退料；Unit、工单、WMS、ERP 四方数量一致。
  • 出错时先看交接处：两个系统各说各的数字，问题就在它们之间。
