换线全过程

AI 生成 · 待核对制造业务场景MESSMT换线首件防错更新于 2026-10-21

⚠ 待核对：故事里的产品 PCBA-B200、料号、盘号、钢网寿命（100000 次）、锡膏回温（240 分钟）、各项换线任务的耗时、APS 换线矩阵里的 60 分钟，都是虚构的演示数据。换线包含哪些动作、哪些算外部作业、停线时间怎么起算（从旧工单末件离开线头，还是从整线清空）、首件由谁检验，每家公司差别很大，你们的自研 MES 一定有自己的规则，请对照你们的系统和现场核实。所有 SQL 和输出都是我在本机 SQL Server LocalDB 的临时库 Lab_scene 里实际运行得到的。

本篇是"场景"系列第 5 篇（最后一篇）。读完你应该能：把一次 SMT 换线拆成"外部作业"（线还在跑时就能做）和"内部作业"（必须停线做）；说清每一步谁在哪个系统做了什么、系统检查什么；理解为什么"首件没过不能开工"要做成数据库里的门禁；会算换线时间（并行任务的关键路径 vs 任务时间相加）和"计划对实际"；知道每一步出错时现场会发生什么、怎么查。

一句话定义 ​

换线全过程是：产线从做 A 产品切换到做 B 产品，需要备料、预装飞达、检查钢网和锡膏（这些在线还在跑时就能做，叫外部作业），然后停线、清线、换钢网、换程序、换飞达车、切换炉温、做首件（这些必须停线，叫内部作业），首件 Pass 之后，新工单才能开工。从旧工单末件离开线头，到新工单首件 Pass，这段停线时间就是换线时间。

先修知识 ​

  • 首件检验与换线：FirstArticle、首件门禁、换线清单。
  • 换线与产能：换线矩阵、SMED（外部作业转内部作业的思路）。
  • SMT上料防错与站位表：FeederMap、SlotLoad。
  • 治具与钢网管理：钢网寿命与领用。
  • 设备管理与设备状态：Setup 状态必须有原因码。
  • 工艺参数与炉温曲线管理：炉温程序。
  • 读过 工单从下达到入库的全过程 更好：这个故事接在它后面。

它解决什么问题 ​

一个现场故事。早班做完 A100，要换成 B200。线长觉得"都是熟手，换线赶快做"，一边换钢网一边装料一边调程序。结果：飞达车上一盘二极管装反了方向，没人发现；因为赶时间，首件只看了外观就签字；开工后 AOI 连续报二极管极性反，已经做了 120 块。120 块返修的人工、占线、延误的交期，远超换线本身节约的 10 分钟。

换线不只是"换东西"，而是一次让产线重新证明自己能做对的过程。管好它需要三件事：①时间：停线多久、哪些能提前做；②防错：每一样换对了没有；③证明：首件检验是门禁。

核心概念：外部作业与内部作业 ​

类型定义本例的任务
外部作业（External）线还在生产时就能做，不占停线时间备料、离线预装飞达车、领用并检查钢网、锡膏回温、确认程序版本
内部作业（Internal）必须停线才能做清线、换钢网、换贴片/印刷程序、调轨宽、切炉温并等稳定、换飞达车并校验、首件

SMED 的核心思路就是：尽量把内部作业变成外部作业。最典型的是"离线预装飞达"：飞达车在线外按站位表装好，换线时整车推上去，只需要扫码校验。

关键路径：内部作业不是一件接一件做的，有些可以同时做（工艺员调程序、操作员装飞达）。真正决定停线时间的是最长的那条链，不是所有任务时间相加。

首件门禁：新产品的第一块板做出来，经检验 Pass 之前，线体不允许开工。这个"允许"不靠自觉，写在条件 UPDATE 里：线体最新一张首件单是 Pass，才能把工单从 Released 推进到 Running。

逐步展开 ​

外部作业 E1 到 E5（08:15 到 12:30，线还在跑） ​

  • 谁/系统：王芳备料，张伟在线外装飞达，李娜检查钢网和锡膏，钱峰确认程序版本。
  • 产生：5 条 ChangeoverTask，类型 External。耗时 20、60、10、240、10 分钟，合计 340 分钟（锡膏回温 240 分钟是在冰箱外等待，不占人力）。这些都不占停线时间。
  • 检查：
    • 钢网寿命：ST-B200-T1 已用 87000，上限 100000，剩余 13000，本单只需 300（精简版把一块板算一次印刷；真实系统按拼板和使用口径折算），够用。
    • 锡膏回温：SP-1022 08:15 从冰箱取出，13:08 开始印刷时已回温 293 分钟 ≥ 要求的 240 分钟，可用。
  • 可能出什么问题：钢网寿命不够（要换新）；锡膏回温时间不到就用（印刷质量差）；程序版本没确认，上线才发现是旧版。
  • SMED 视角：E2 的 60 分钟预装如果放到线上做，I4 会从 22 分钟变成约 82 分钟，成为关键路径，整个换线从 75 分钟延长到约 129 分钟（粗略估算，不是实验输出）。能提前的一定要提前。

第 4 步 · 末件离开线头，设备进入 Setup（12:50） ​

  • 谁/系统：旧工单最后一块板（A10026102200500）12:49:30 离开线头，MES 把贴片机 SMT-01-MNT 状态由 Run 改为 Setup。
  • 产生：EquipStatusLog：Run → Setup，原因码 CHANGEOVER，12:50。见 设备管理与设备状态。
  • 检查：设备管理与设备状态 里的表设计带一条 CHECK：进入 Setup、Down 等状态必须带原因码，否则写不进去（本篇的精简版没有加这条约束，原因码由脚本直接给出）。
  • 可能出什么问题：不记 Setup，这段时间在 OEE 里就变成"未知停机"。

第 I1 步 · 清线（12:50-12:58，8 分钟） ​

  • 谁/系统：张伟把线上残留的 A100 板、锡膏清走，三盘 A100 料下线退料。
  • 产生：SlotLoad 里三行 A100 的料写入 UnloadedAt（12:56）；ChangeoverTask I1。
  • 检查：站位空闲才能上新料。
  • 可能出什么问题：旧产品的板混在新批次里（经典的混料事故）。

第 I2 步 · 换钢网（12:58-13:08，10 分钟） ​

  • 谁/系统：李娜换钢网和刮刀，见 治具与钢网管理。
  • 产生：ToolingUsage 两条：12:59 ST-A100-T1 Return（累计 26990）；13:04 ST-B200-T1 Issue（累计 87000）；Tooling 里 A100 钢网回到 InStock，B200 钢网变 InUse。
  • 检查：领用用条件 UPDATE，Status = 'InStock' 才能领；真实系统还会检查钢网的 ProductCode 与工单产品一致、寿命够不够。
  • 可能出什么问题：领错钢网；归还不记数，寿命统计失真。

第 I3、I5 步 · 换程序、调轨宽（13:08-13:16，8 分钟） ​

  • 谁/系统：钱峰在印刷机和贴片机上选 B200 程序，调导轨宽度。
  • 产生：ChangeoverTask I3（5 分钟）、I5（3 分钟）。
  • 检查：程序版本要和工艺路线绑定的版本一致。
  • 可能出什么问题：程序还是 A100 的；轨宽没调整，板卡在轨道里。

第 I6 步 · 回流炉切换并稳定（13:16-13:36，20 分钟） ​

  • 谁/系统：钱峰把炉子切到 PROF-B200，各温区需要时间到达设定值并稳定。
  • 产生：ChangeoverTask I6。这是整条关键路径里最长的单项，见下面的计算。
  • 检查：炉温稳定之前不能放板；开线后第一块板的实测曲线要记录，见 工艺参数与炉温曲线管理。
  • 可能出什么问题：没等稳定就过板，首件会因焊接不良而失败。

第 I4 步 · 换飞达车并扫码校验（13:08-13:30，22 分钟） ​

  • 谁/系统：张伟把预装好的飞达车推上贴片机，逐个站位扫料盘码，MES 对照 B200 的站位表。
  • 产生：SlotLoad 5 行：M1-01（13:12）、M1-02（13:14）、M1-03（13:22，二极管）、M1-04（13:25）、M1-05（13:30）。13:20 有一次拦截：张伟把 LED 的盘（R-LED-07）扫到了 M1-03，系统回"站位 M1-03 要 D-SS14，这盘是 LED-0603-G"，拒绝；他换成二极管盘 R-DSS14-01 后成功。

  • 可能出什么问题：这次是预装时就装错了位置，线上扫码补了一道防线。若没有扫码，错料会在线上量产。

第 I7 步 · 首件试做，Fail（13:36-13:45，9 分钟） ​

  • 谁/系统：新程序试做一块，刘洋检验，见 首件检验与换线。
  • 产生：FirstArticle #1：触发类型 Changeover，13:36 Pending，13:45 Fail，备注"D3 极性反（二极管飞达方向装反）"。
  • 检查：极性、方向这类错误，料号扫码是发现不了的：料号对了，只是装进飞达的方向反了。必须靠首件的外观和 AOI 比对。
  • 可能出什么问题：首件被跳过，批量极性反。

第 13:50 · 开工被拒绝 ​

  • 谁/系统：这时有人想让新工单先开工，MES 执行条件 UPDATE：Status = 'Released' 且线体最新首件单是 Pass。
  • 产生：受影响 0 行，工单仍是 Released。实验输出里这一行写得很清楚：13:50 开工 WO20261022004：受影响 0 行（最新首件单不是 Pass）。
  • 检查：门禁不看"有没有首件单"，而看"最新的那张是不是 Pass"。13:36 到 13:45 之间，最新那张是 Pending，也不是 Pass。

第 I8、I9 步 · 返调与复检（13:45-14:05，20 分钟） ​

  • 谁/系统：张伟重装二极管飞达方向（13 分钟）；13:58 开第二张首件单（触发类型 Retry）；14:05 刘洋判 Pass。

  • 检查：现在线体最新的首件单是 Pass，条件 UPDATE 受影响 1 行。
  • 可能出什么问题：多次 Fail 就一直重复（实际上多次 Fail 要上报工程师）。

项数值

结论：这次超时的原因不在于动作慢，而在于一次本可避免的错误——二极管飞达方向装反。如果预装时按"方向检查清单"核对，就能省下 20 分钟。

按一个班 540 分钟算，这次换线占 75 ÷ 540 = 13.9% 的时间。如果每天换 3 次，就是约 42% 的时间在换线，这就是为什么 APS 的排程要考虑"按产品族排序减少换线"。

KPI：换线时间、计划对实际、首件一次通过率（本例 0/1）、换线中被拦截的次数（本例 1 次）、外部作业占比。

技术视角 ​

表怎么串成一条线 ​

WorkOrder(WoNo, ProductCode, LineCode) ─┬─ FirstArticle(WoNo, LineCode) ── 门禁：最新一张 Pass
                                        ├─ FeederMap(ProductCode, LineCode, SlotNo) ── 比对 ──> SlotLoad(LineCode, SlotNo, UnloadedAt IS NULL)
                                        ├─ Tooling(ProductCode) ── ToolingUsage(ToolCode)
                                        └─ SetupMatrix(FromProduct, ToProduct) ── 对比 ──> ChangeoverTask
EquipStatusLog(EquipCode, ToStatus='Setup', ReasonCode) ── 换线时间的第二个来源

关键技巧 ​

  1. 开工门禁：条件 UPDATE，WHERE Status = 'Released' AND EXISTS (线体最新首件单 = Pass)。"最新"用 Id = (SELECT MAX(Id) ...)。
  2. 站位唯一索引：CREATE UNIQUE INDEX ... ON SlotLoad(LineCode, SlotNo) WHERE UnloadedAt IS NULL，同一站位同一时刻只能有一盘料。
  3. 停线时间两种算法：一是 MIN(StartAt) 到 MAX(EndAt) 的实际跨度（75 分钟）；二是从设备状态流水里累加 Setup 时长（也是 75 分钟）。两者应该相等，不相等说明有记录缺失。
  4. 时间点查询：用 OUTER APPLY (SELECT TOP 1 ...) 回答"某个时刻线体能不能生产"，注意首件单在那个时刻已经出结果才算，没出结果的算 Pending。
  5. 逐站位核对：FeederMap LEFT JOIN SlotLoad，一行一个站位，"一致"或"不符"。

-- 上料检查（精简版）：站位表要什么料、站位是否空闲
CREATE PROCEDURE dbo.usp_LoadReel @product nvarchar(30), @slot nvarchar(10), @reel nvarchar(30), @at datetime2(0), @op nvarchar(30), @msg nvarchar(200) OUTPUT AS
BEGIN
    DECLARE @mat nvarchar(30), @need nvarchar(30);
    SELECT @mat = MaterialCode FROM Reel WHERE ReelId = @reel;
    SELECT @need = MaterialCode FROM FeederMap WHERE ProductCode = @product AND LineCode = N'SMT-01' AND SlotNo = @slot;
    IF @need IS NULL BEGIN SET @msg = N'拒绝：站位表里没有 ' + @slot; RETURN; END
    IF @mat <> @need BEGIN SET @msg = N'拒绝：站位 ' + @slot + N' 要 ' + @need + N'，这盘是 ' + @mat; RETURN; END
    IF EXISTS (SELECT 1 FROM SlotLoad WHERE LineCode = N'SMT-01' AND SlotNo = @slot AND UnloadedAt IS NULL) BEGIN SET @msg = N'拒绝：站位上还有一盘料没下'; RETURN; END
    INSERT SlotLoad (LineCode, SlotNo, ReelId, MaterialCode, LoadedAt, Operator) VALUES (N'SMT-01', @slot, @reel, @mat, @at, @op);
    SET @msg = N'成功';
END

如果某一步出错会怎样（5 个故障场景与排查） ​

场景 1：预装飞达车时装错了站位，线上没有扫码（E2、I4） ​

  • 现象：开工后 AOI 在好几个位号上报"错件"，且板与板之间的错误完全一样。
  • 原因：飞达车预装时二极管盘与 LED 盘位置互换；到了线上没有逐盘扫码校验，或者扫码规则不拦截。
  • 排查思路：实验第 5 节的逐站位核对：FeederMap 对 SlotLoad，找"不符"；SlotLoad 的 LoadedAt 有没有早于换线开始。
  • 处理：停线，圈出开工以来的所有板锁定，见 不良品拦截与锁定；规则上把"换线必须扫码"做成拦截。

场景 2：极性、方向类错误，首件被跳过（I7） ​

  • 现象：开工半小时后，AOI 连续报二极管 D3 极性反，每块都一样。
  • 原因：料号对，方向装反，料号扫码发现不了；首件没做或没认真比对。
  • 排查思路：看 FirstArticle 里该线最新一张的状态和时间，门禁是否生效；WoLog 里开工时间是否早于首件 Pass 的时间；对错误板找共同点。
  • 处理：返修、锁板；首件检验清单里加"极性与方向"必查项；开工门禁必须写进数据库，见 首件检验与换线。

场景 3：钢网寿命或锡膏状态没检查（E3、E4） ​

  • 现象：印刷质量逐渐变差，SPI 报锡量异常；或开工后一小时锡膏塌陷、连锡。
  • 原因：钢网使用次数已接近上限，没人提示；锡膏回温不到 4 小时就用，或已超过开封后的使用期限。
  • 排查思路：Tooling.UseCount 与 MaxUseCount 的差；PasteLot 的取出时间到开始印刷的分钟数；对比实验第 1、2 个查询。
  • 处理：钢网到寿命就报废；锡膏回温时间做成上线前的硬性检查，见 治具与钢网管理。

场景 4：炉温程序没切换，或没等稳定就过板（I6） ​

  • 现象：首件外观没问题，但 X-ray 或功能测试发现焊接不良；炉温曲线记录显示这块板用的是 A100 的曲线。
  • 原因：炉子还在用旧程序，或新程序设了但各温区还没到位。
  • 排查思路：查首件板的 ReflowRecord，对照工艺路线绑定的炉温配方和实测峰值，见 工艺参数与炉温曲线管理；看 ChangeoverTask I6 的耗时是否被压缩。
  • 处理：返调后重做首件；换线清单里"炉温稳定"作为检查项，MES 在炉温实测未达标前不允许首件板进炉。

场景 5：换线总是超时，APS 排程失真（所有内部作业） ​

  • 现象：计划员按矩阵排了每次 60 分钟，实际每次 75 到 90，一天下来延误几个工单。
  • 原因：矩阵数字是经验值；没有把实际数据反馈回去；任务串行做，没有并行；外部作业没有提前做。
  • 排查思路：实验第 3 节的"计划对实际"；把 ChangeoverTask 按任务类型统计，看哪一项耗时最长；看关键路径是哪几项。
  • 处理：用真实换线时间更新矩阵，见 换线与产能；对关键路径上的任务做 SMED 改善（炉温切换和首件最值得优化）。

预装飞达是浪费人力把内部作业转成外部作业，节省的是停线时间
料号扫对就不会错极性、方向、位置这类错只能靠首件和 AOI
首件是走个形式首件是门禁，没过不能开工，要写进条件 UPDATE

练习题与答案 ​

  1. 内部任务时间合计 97 分钟，为什么实际停线只有 75 分钟？ 答：任务有并行。I4（22 分钟）与 I3、I5、I6 同时做，真正决定停线的是关键路径 I1 → I2 → I3 → I5 → I6 → I7 → I8 → I9，共 75 分钟。
  2. 如果 13:45 首件一次通过，换线时间是多少，相比计划如何？ 答：从 12:50 到 13:45 是 55 分钟，比计划 60 分钟少 5 分钟。
  3. 为什么门禁看"最新一张首件单是不是 Pass"，而不是"有没有 Pass 的首件单"？ 答：同一条线可能有历史上的 Pass 单；新的 Fail 出现后，最新状态才反映当前线体能不能生产。如果只看"有没有"，上一次的 Pass 会让 Fail 之后的线体仍被放行。
  4. 13:20 扫码拦截了什么错误，没拦截的是哪类错误？为什么？ 答：拦截了"料号与站位不符"（LED 盘装到二极管站位）；没拦截"极性反"，因为料号是对的，扫码只能比对料号，方向要靠首件和 AOI。
  5. 钢网剩余寿命 13000，本单 300 块，钢网够用。如果剩余只有 200 呢？ 答：不够。要么换新钢网，要么先用旧钢网做完 200 块，再中途换，后者需要再做一次换钢网和首件，一般不选。
  6. 为什么 Setup 状态必须填原因码？ 答：为了统计停机原因（换线、保养、故障分别占多少），没有原因码，OEE 里的"计划停机"和"故障停机"无法分开。本例 CHANGEOVER 合计 75 分钟。

小结 ​

  • 换线分外部作业（线在跑时做：备料、预装飞达、钢网锡膏检查、程序确认）和内部作业（停线做：清线、换钢网、换程序、调轨宽、切炉温、换飞达车、首件）；SMED 就是把内部转外部。
  • 停线时间看关键路径，不是任务时间相加：本例任务合计 97，关键路径 75。
  • 每样东西换对了没有，靠站位表扫码；方向、极性这类错，靠首件；首件 Pass 才允许开工，这是写在 SQL 里的门禁。
  • 本例 75 分钟对计划 60 分钟，超出 15 分钟，其中首件失败占 20 分钟；真实停线数据应反馈回 APS 的换线矩阵。
  • 设备 Setup 状态必须带原因码，换线时间才能从设备状态流水里准确统计。
