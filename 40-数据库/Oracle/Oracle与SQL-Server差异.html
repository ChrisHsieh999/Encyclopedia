Oracle与SQL-Server差异

AI 生成 · 待核对数据库OracleSQL-Server更新于 2026-10-21

⚠ 未在本机运行验证（Oracle 一侧）：本机没有 Oracle 数据库。表里"Oracle"一列的行为依据官方文档（已联网核对的条目在正文标了出处）或一般资料；没有实际运行，预期输出是推演。

本机已实际验证的部分：① 所有"SQL Server"一列的输出（SQL Server 2025 LocalDB，临时库 Lab_oradiff，用完已删除）；② 同样的 SQL 在 PostgreSQL 16.2 上的输出（作第三方参照）；③ SqlSugarCore 5.1.4.221 生成的 Oracle SQL 文本（只生成、不连库）。

⚠ 待核对（需要 Oracle 环境确认）：未带出处的 Oracle 行为条目，如 NULL 排序位置、标识符长度上限、ODP.NET 自动提交行为、ROWNUM 细节、SqlSugar 对 Oracle 的 CodeFirst 类型映射。已登记到待核对清单。

本篇是 Oracle 入门路径的第 3 篇（最后一篇）。读完你应该能：把 T-SQL 查询翻译成 Oracle SQL；避开空字符串、ROWNUM、自动提交这几个最大的坑；理解两边读写并发的根本差别；在 C# + SqlSugar 里连接 Oracle。

一句话定义 ​

这是一份从 SQL Server 迁到 Oracle 的对照手册：数据类型、分页、自增、空值、拼接、日期、事务、锁各是什么，以及 C#/SqlSugar 怎么连。

先修知识 ​

  • SQL-Server、T-SQL编程：对照的左边。
  • Oracle、PL-SQL：对照的右边。
  • 事务与ACID、隔离级别与锁：事务和锁的背景。
  • SqlSugar：C# 一侧的 ORM。

它解决什么问题 ​

团队用 SQL Server + C#，但要对接 ERP 的 Oracle 库，或客户要求 Oracle。直接把 T-SQL 拿去执行会遇到：TOP 不认识、ISNULL 不认识、+ 连接字符串变成数学运算、插入空字符串变成 NULL、查询卡住/不卡住的行为不同……这一篇把"最先踩到"的差异成体系地列出来。

核心概念：差异总表 ​

字节与字符：Oracle 的 VARCHAR2(10) 默认以字节计长（由参数 NLS_LENGTH_SEMANTICS 决定，默认 BYTE，⚠ 待核对）。库字符集是 UTF-8 时一个汉字占 3 字节，VARCHAR2(10) 只能放 3 个汉字。解决：显式写 VARCHAR2(10 CHAR)。SQL Server 的 NVARCHAR(10) 是 10 个字符，没有这个问题。

2. 空字符串 = NULL（最大的坑） ​

官方文档原话（Nulls 页）："The database treats a character value with a length of zero as null."，并警告以后版本可能改变，建议不要把空字符串当 NULL 用。来源：https://docs.oracle.com/en/database/oracle/oracle-database/23/sqlrf/Nulls.html 。

对比（SQL Server 一侧是本机实测，PostgreSQL 一侧也是实测，Oracle 一侧依据官方文档）：

操作SQL Server（实测）PostgreSQL（实测）Oracle（官方文档）
'' IS NULL假（LEN(N'') = 0，IS NULL 为假）假真（空串就是 NULL）
插入 '' 后查 WHERE col IS NULL不命中不命中命中
插入 '' 后查 WHERE col = ''命中命中永远不命中（= NULL 是 UNKNOWN）
'a' + NULL / `'a'NULL`NULL（+）
CONCAT('a', NULL, 'b')abab见 Oracle 版本说明（待核对）
LENGTH('')LEN(N'') = 0length('') = 0NULL

SQL Server 实测数据（表 work_order：WO001 备注为空串、WO002 备注为 NULL、WO003 备注为 rush）：

wo_no remark kind
----- ------ ----
WO001  empty            -- 空串被原样保存
WO002 NULL NULL
WO003 rush text
cnt_null = 1            -- 只有 WO002 是 NULL

同样的数据在 Oracle 中，WO001 和 WO002 的备注都是 NULL，COUNT(*) ... WHERE remark IS NULL 的预期是 2（推演，未运行）。

迁移后果：① 把"空字符串"和"未填"区分开的业务逻辑会失效；② WHERE remark = '' 要改成 WHERE remark IS NULL；③ NOT NULL 列不能插入空串（会报 ORA-01400: cannot insert NULL）；④ 从 Oracle 读到的 NULL 在 C# 里是 DBNull，不要当 string.Empty。

3. 字符串拼接 ​

  • SQL Server：+，遇 NULL 结果为 NULL（实测）；CONCAT() 把 NULL 当空串。
  • Oracle：用 ||。官方 Concatenation Operator 页：把长度为 0 的字符串（也就是 NULL）和另一个操作数拼接，结果总是另一个操作数；只有两个都是 NULL 才得 NULL。所以 'a' || NULL 得 'a'。官方也提醒这可能在未来版本改变，需要明确时用 NVL 把表达式转成空串。来源：https://docs.oracle.com/en/database/oracle/oracle-database/23/sqlrf/Concatenation-Operator.html 。
  • Oracle 的 + 是纯算术，'a' + 'b' 会报错（数值转换错误）。
  • 数字与字符串用 || 拼接时 Oracle 会隐式转换，但格式不可控，推荐 TO_CHAR(num)。

4. 分页与取前 N 行 ​

写法SQL ServerOracle
取前 N 行SELECT TOP 10 ...SELECT ... FETCH FIRST 10 ROWS ONLY（12c 起）
分页ORDER BY id OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY完全相同的写法（12c 起，第三方资料见 https://oracle-base.com/articles/12c/row-limiting-clause-for-top-n-queries-12cr1）
老写法（11g 及以前、很多老系统仍在用）—ROWNUM 嵌套子查询

SQL Server 实测输出（TOP 2 与 OFFSET 1 ROWS FETCH NEXT 2 ROWS ONLY）：

TOP 2 -> WO001, WO002
OFFSET 1 ROWS FETCH NEXT 2 ROWS ONLY -> WO002, WO003

Oracle 的预期：同样的 OFFSET ... FETCH 语句得到 WO002、WO003（推演，未运行）。

ROWNUM 老式分页（读懂老系统必备）：ROWNUM 是查询结果的"行号"伪列，在排序之前分配。取第 11～20 行，必须三层嵌套：

sql
SELECT *
FROM (
  SELECT t.*, ROWNUM rn
  FROM (SELECT * FROM work_order ORDER BY id) t
  WHERE ROWNUM <= 20
)
WHERE rn > 10;

经典陷阱：

  • SELECT * FROM t WHERE ROWNUM <= 3 ORDER BY x 是"先随便取 3 行，再把这 3 行排序"，不是前三名。必须先在子查询里排序，外层再 ROWNUM <= 3。
  • WHERE ROWNUM > 1、WHERE ROWNUM = 2 永远没有结果（行号从 1 开始分配，第一行不满足就不会继续往下编号）。

SqlSugar 为 Oracle 生成的分页 SQL（本机实测，只生成文本不连库）用的是 ROW_NUMBER() 窗口函数，见下面 C# 部分。

5. 自增与序列 ​

事项SQL ServerOracle
自增列IDENTITY(1,1)12c 起 GENERATED ALWAYS AS IDENTITY（或 BY DEFAULT）；老版本用序列 + 触发器
独立序列CREATE SEQUENCE 也有（2012+）CREATE SEQUENCE，是 Oracle 的传统做法
取新值插入后 SCOPE_IDENTITY() 或 OUTPUT inserted.idseq.NEXTVAL；插入后用 RETURNING id INTO :id
看当前值—seq.CURRVAL（本会话必须先调用过 NEXTVAL）

Oracle 序列写法（依据官方 CREATE SEQUENCE 页）：

sql
CREATE SEQUENCE seq_work_order START WITH 1000 INCREMENT BY 1 NOCACHE;
INSERT INTO work_order (id, wo_no) VALUES (seq_work_order.NEXTVAL, 'WO001');
SELECT seq_work_order.CURRVAL FROM dual;

官方说明要点：NEXTVAL 自增并返回新值；若不写 CACHE/NOCACHE，默认缓存 20 个值；不管事务提交还是回滚，序列值都会推进，所以回滚会留下空洞；并发时空洞也会出现；系统故障时缓存里没用的值会丢。因此序列适合做唯一键，不适合做必须连续的单据号（这点 SQL Server 的 IDENTITY 同样如此，见 工单管理 单号设计）。来源：https://docs.oracle.com/en/database/oracle/oracle-database/23/sqlrf/CREATE-SEQUENCE.html 。

SQL Server 一侧实测：INSERT 一行 WO004 后 SCOPE_IDENTITY() 得 4（表中已有 3 行）。

7. 日期运算 ​

SQL Server 用函数，Oracle 把日期当"数字"直接加减，单位是天：

需求SQL ServerOracle
加 N 天DATEADD(DAY, N, d)d + N
加 2 小时DATEADD(HOUR, 2, d)d + 2/24，或 d + INTERVAL '2' HOUR
加 N 个月DATEADD(MONTH, N, d)ADD_MONTHS(d, N)
两日期相差天数DATEDIFF(DAY, a, b)b - a（结果是数字，可能带小数）
相差小时DATEDIFF(HOUR, a, b)(b - a) * 24
取日期部分CAST(d AS DATE)TRUNC(d)（时间归零）
月末EOMONTH(d)LAST_DAY(d)
日期字面量'2026-10-21'DATE '2026-10-21' 或 TO_DATE(...)；不要依赖隐式转换（取决于会话的 NLS_DATE_FORMAT）

SQL Server 实测：DATEDIFF(DAY,'2026-10-01','2026-10-21') = 20；DATEADD(HOUR,2,'2026-10-21 08:30:00') = 2026-10-21 10:30:00。PostgreSQL 实测：两日期相减 DATE '2026-10-21' - DATE '2026-10-01' = 20（与 Oracle 的"日期相减得天数"同一思路）。Oracle 预期：DATE '2026-10-21' - DATE '2026-10-01' = 20（推演）。

格式掩码里的坑：MI 是分钟（不是 MM，MM 是月）；24 小时制用 HH24。

8. 事务 ​

事项SQL ServerOracle
默认提交方式自动提交，每条语句自成事务；要事务需 BEGIN TRAN没有 BEGIN：第一条 DML 隐式开启事务，必须自己 COMMIT/ROLLBACK（SQL*Plus 与 SQL Developer 都如此）
DDL 能否回滚能（实测：BEGIN TRAN; CREATE TABLE ...; ROLLBACK; 后表不存在，OBJECT_ID 为 NULL）不能：每条 DDL 前后都会隐式提交（待核对：以官方"事务控制"章节为准）

自治事务没有PL/SQL PRAGMA AUTONOMOUS_TRANSACTION：子程序在独立事务里提交，不受主事务回滚影响（官方：https://docs.oracle.com/en/database/oracle/oracle-database/26/lnpls/AUTONOMOUS_TRANSACTION-pragma.html）
驱动里默认ADO.NET 无显式事务 = 自动提交ODP.NET 无显式 OracleTransaction 时通常也自动提交（待核对）；在 SQL*Plus 手工操作则不然

自治事务的用途与示例见 PL-SQL 例 9；SQL Server 里要做"回滚了也保留日志"，常见变通是用表变量（表变量不受事务回滚影响）、另开连接写日志，或写到外部日志系统。

迁移提示：在 SQL*Plus 里测试 INSERT 后别的窗口看不到，不是 bug，是你忘了 COMMIT；反过来，C# 里的代码若混用显式事务与自动提交，要和 DBA 确认约定。

9. 锁与并发：根本差别 ​

两边默认隔离级别都叫"读已提交"，但实现不同，行为也不同：

  • SQL Server（默认）：读操作要申请共享锁，会被未提交的写操作阻塞；可以通过开启 READ_COMMITTED_SNAPSHOT（RCSI）改成行版本控制。
  • Oracle：始终基于 undo（回滚段）里的旧版本做"读一致性"：读不会阻塞写，写也不会阻塞读，读到的是该语句开始时已提交的数据。行锁记录在数据块里，没有锁升级（SQL Server 在行锁过多时会升级成页锁/表锁）。

SQL Server 一侧的真实实验（会话 A 开启事务把 done_qty 从 120 改成 220 并保持 8 秒不提交；会话 B 查询，LOCK_TIMEOUT 设为 2 秒）：

B 的查询方式结果（实测）
默认 READ COMMITTED等待 2 秒后报错：Msg 1222 ... Lock request time out period exceeded.（被 A 的写锁阻塞）
WITH (NOLOCK)立刻返回 220（读到 A 尚未提交、之后会回滚的脏数据）
开启 RCSI 后，默认立刻返回 120（读到最后已提交版本，不阻塞）——这就是 Oracle 的默认行为

Oracle 的预期（依据读一致性原理，⚠ 未运行）：B 的普通 SELECT 立刻返回 120；Oracle 没有"读未提交"级别，不需要也没有 NOLOCK。把 SQL Server 代码里的 WITH (NOLOCK) 搬过来会直接语法错误，而且也没必要。

锁相关写法对照：

拿不到锁立刻报错SET LOCK_TIMEOUT 0FOR UPDATE NOWAIT（报 ORA-00054）

Oracle 的另一个特有错误：长事务期间 undo 被覆盖，查询可能报 ORA-01555: snapshot too old（一般资料，待核对）。

逐步例子 ​

例 1：同一个需求，两种 SQL ​

需求：查 work_order 中备注不为空的工单，按 id 排序，取第 2 页（每页 2 条），并显示从 2026-10-01 到今天的天数。

SQL Server（本机跑过同类语句）：

sql
SELECT wo_no,
       ISNULL(remark, N'-') AS remark,
       DATEDIFF(DAY, '2026-10-01', GETDATE()) AS days
FROM work_order
WHERE remark IS NOT NULL AND remark <> N''
ORDER BY id
OFFSET 2 ROWS FETCH NEXT 2 ROWS ONLY;

Oracle 译文（⚠ 未运行）：

sql
SELECT wo_no,
       NVL(remark, '-') AS remark,
       TRUNC(SYSDATE) - DATE '2026-10-01' AS days
FROM work_order
WHERE remark IS NOT NULL
ORDER BY id
OFFSET 2 ROWS FETCH NEXT 2 ROWS ONLY;

逐处改动：ISNULL → NVL；DATEDIFF(DAY, ...) → 日期相减（用 TRUNC(SYSDATE) 去掉时间，否则结果带小数）；remark <> N'' 删掉——在 Oracle 里空串就是 NULL，IS NOT NULL 已经排除了；N'' 前缀在 Oracle 里表示国家字符集字符串，不要乱带。分页写法不用变。

例 2：迁移 SQL Server 的"防重复插入" ​

SQL Server 常见写法：

sql
IF NOT EXISTS (SELECT 1 FROM work_order WHERE wo_no = @wo)
    INSERT INTO work_order (wo_no, plan_qty) VALUES (@wo, @qty);

Oracle 里没有 IF 这种顶层语句（那是 T-SQL 的批处理控制流，Oracle 里要在 PL/SQL 块中）。更地道的写法是 MERGE（⚠ 未运行）：

sql
MERGE INTO work_order t
USING (SELECT :wo AS wo_no, :qty AS plan_qty FROM dual) s
ON (t.wo_no = s.wo_no)
WHEN NOT MATCHED THEN
  INSERT (wo_no, plan_qty) VALUES (s.wo_no, s.plan_qty);

或者直接插入，捕获唯一约束冲突 ORA-00001（PL/SQL 里的 DUP_VAL_ON_INDEX 异常）。

例 3：自增的两种做法 ​

Oracle 12c 之前（读老系统会见到）：

sql
CREATE SEQUENCE seq_work_order START WITH 1 INCREMENT BY 1 NOCACHE;
CREATE OR REPLACE TRIGGER trg_work_order_bi
BEFORE INSERT ON work_order
FOR EACH ROW
WHEN (NEW.id IS NULL)
BEGIN
  :NEW.id := seq_work_order.NEXTVAL;
END;
/

12c 之后直接用 id NUMBER GENERATED ALWAYS AS IDENTITY（见 Oracle 例 3）。

C# / SqlSugar 连接 Oracle：怎么写 ​

⚠ 连接和执行部分未在本机运行（无 Oracle），生成的 SQL 文本与 API 可用性已验证。

  1. NuGet 包：SqlSugarCore 已经依赖了 Oracle 官方托管驱动 Oracle.ManagedDataAccess.Core（本机还原结果为 23.8.0），不需要额外装驱动，也不需要装 Oracle Client。
  2. 连接串（Easy Connect 写法）：Data Source=主机:1521/服务名;User Id=用户;Password=密码;，Free 版的服务名用 FREEPDB1。密码里有特殊字符时注意引号转义。
  3. 配置：
csharp
var db = new SqlSugarClient(new ConnectionConfig {
    ConnectionString = "Data Source=localhost:1521/FREEPDB1;User Id=mes;Password=你的密码;",
    DbType = DbType.Oracle,
    IsAutoCloseConnection = true });
var list = db.Queryable<WorkOrder>().Where(w => w.Qty > 100).OrderBy(w => w.Id).ToList();
  1. 命名：SqlSugar 对 Oracle 默认把表名列名生成为大写；如果库里是 WO_NO 这样的下划线名，用 [SugarColumn(ColumnName = "WO_NO")]、[SugarTable("WORK_ORDER")] 对应。
  2. 主键自增：Oracle 老方式需要序列，用 OracleSequenceName 指定（实测会生成 序列名.nextval）；12c+ 的 GENERATED AS IDENTITY 列，插入时不要给 ID，是否能用 ExecuteReturnIdentity 取回值，⚠ 待核对。

  6. 和 SQL Server 同时使用：SqlSugar 支持配置多个连接（ConfigId），一个连 SQL Server 一个连 Oracle；两边的 SQL 方言差异（本篇所列）要由你自己处理，ORM 的 Lambda 查询能抹平一部分（如分页、参数前缀），原生 SQL 抹不平。

业务视角与技术视角 ​

业务视角：两种库在企业里常常"各管一摊"：Oracle 管 ERP 主数据与财务，SQL Server 管车间系统。集成时的几类典型事故其实都出在本篇列出的差异上：空串与 NULL 的口径不一致造成"未填"和"空"混淆；DATE 带不带时间造成日报少算一天；Oracle 数据被未提交事务卡住读不到最新值；序列号不连续被误判为"丢单"。设计接口时要把这些写进"接口约定"（见 接口技术选型、MES与ERP及设备的接口设计）：时间字段统一时区与精度、空值约定、主键类型、是否允许删除。

技术视角：能用标准 SQL 就用标准 SQL（COALESCE、CASE、OFFSET ... FETCH、LEFT JOIN、CAST），迁移成本最低；确需方言的地方（日期运算、序列、字符串聚合）集中放在数据访问层，不要散落在业务代码里。

练习题与答案 ​

练习 1：把 SELECT TOP 5 wo_no, ISNULL(remark,'-') + '!' FROM dbo.work_order ORDER BY id DESC 改写成 Oracle。 答案：SELECT wo_no, NVL(remark,'-') || '!' FROM work_order ORDER BY id DESC FETCH FIRST 5 ROWS ONLY;（去掉 dbo.、TOP；ISNULL → NVL；+ → ||；取前 N 行放在最后）。

练习 2：表里有一行 remark = ''（SQL Server）。迁到 Oracle 后，SELECT COUNT(*) FROM t WHERE remark IS NULL 与 SQL Server 相比有什么变化？ 答案：SQL Server 中该行不算 NULL（空串不是 NULL）；在 Oracle 中空串就是 NULL，该行被计入。所以 Oracle 的结果会更大（空串行都会被计入）。

练习 3：写出 Oracle 里"取 work_order 第 21～30 条（按 id）"的两种写法。 答案：

sql
-- 12c+
SELECT * FROM work_order ORDER BY id OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
-- ROWNUM 三层嵌套
SELECT * FROM (SELECT t.*, ROWNUM rn FROM (SELECT * FROM work_order ORDER BY id) t WHERE ROWNUM <= 30) WHERE rn > 20;

练习 4：会话 A 更新一行未提交，会话 B 查询同一行，SQL Server 默认与 Oracle 默认各会发生什么？ 答案：SQL Server 默认（不开 RCSI）B 被阻塞等待，直到 A 提交/回滚（本机实测超时报 1222）；Oracle 的 B 不被阻塞，读到 A 修改前已提交的值（读一致性，预期，未在本机验证）。

练习 5：计算 DATE '2026-10-21' - DATE '2026-10-01' 在 Oracle 里的值，单位是什么？ 答案：20，单位是天（Oracle 日期相减得到天数，可含小数；推演，PostgreSQL 实测同一表达式也得 20）。

练习 6：为什么在 SQL*Plus 里 CREATE TABLE 之后不能 ROLLBACK 撤销？ 答案：Oracle 的 DDL 会隐式提交（待核对官方事务章节）；SQL Server 中 DDL 可在事务内回滚（本机实测）。

小结 ​

  • Oracle 的 VARCHAR2 / NUMBER / DATE（含时间）是三大基础类型；VARCHAR2(n) 默认按字节计，中文加 CHAR。
  • 空字符串 = NULL（官方文档），拼接用 ||，'a' || NULL 得 'a'。
  • 分页 12c 起可用与 SQL Server 相同的 OFFSET ... FETCH；老系统用 ROWNUM 三层嵌套，注意排序前分配的陷阱。
  • 自增用序列或 12c+ 的 IDENTITY；序列回滚不退回、可能有空洞。
  • 日期直接加减（单位天），TO_CHAR/TO_DATE 带格式掩码，MI 是分钟。
  • 事务：手动 COMMIT，DDL 隐式提交，自治事务可独立提交；锁：读不阻塞写，没有 NOLOCK，没有锁升级。
  • SqlSugar 连 Oracle：同一个 SqlSugarCore 包，DbType.Oracle，Easy Connect 连接串；生成的 SQL 名称大写、参数用 :，分页用 ROW_NUMBER，序列用 OracleSequenceName。
