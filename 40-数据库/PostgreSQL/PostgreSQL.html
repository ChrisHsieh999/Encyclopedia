PostgreSQL

AI 生成 · 待核对数据库关系数据库PostgreSQL更新于 2026-10-21

验证说明：本篇和 PostgreSQL特色功能 里的 SQL、psql 命令，都在本机通过 pip 包 pgserver 启动的**真实 PostgreSQL 16.2（Windows 版）**上实际执行过，输出是真实输出；C# 部分（Npgsql 10.0.3、SqlSugarCore 5.1.4.221）也连接这个实例实测通过。

⚠ 未在本机运行验证的部分：Docker 安装命令、Windows 安装向导的界面细节、Linux 包管理器命令、以及 PostgreSQL 17/18 的新特性（本机只有 16.2）。这些以官方文档为准：https://www.postgresql.org/download/ 。

本目录入门路径：先读本篇（装好、会用 psql、知道和 SQL Server 的差别），再读 PostgreSQL特色功能（JSONB、数组、UPSERT、扩展等 PostgreSQL 最有特色的功能）。

一句话定义 ​

PostgreSQL（常简称 Postgres 或 PG）是一个开源的、功能很全的关系数据库：遵循 SQL 标准，事务和并发控制（MVCC）成熟，并且能通过"扩展"不断加功能（如向量检索、地理信息）。

先修知识 ​

  • 关系模型、SQL基础查询：知道表、行、SELECT。
  • SQL-Server：你已有的底子。本篇处处拿它对照。
  • 事务与ACID：知道事务是什么。

它解决什么问题 ​

对你（做工厂信息化、主用 SQL Server）来说，学 PostgreSQL 有三个现实理由：

  1. 很多开源软件和云服务默认用它（各类数据平台、AI 应用的向量库、时序扩展 TimescaleDB 等）。
  2. 免费且功能强：JSON、数组、窗口函数、全文检索都内置；没有按核数收费的授权问题。
  3. 换库时少踩坑：公司以后做新项目、或客户指定 PostgreSQL 时能直接上手。

它不是要取代你现在的 SQL Server——工厂里 SQL Server + C# 的组合依然是主力；PostgreSQL 是"第二把武器"。

核心概念 ​

1. 特点（简表） ​

特点说明
开源免费采用 PostgreSQL 许可证（类似 BSD/MIT 的宽松许可）
MVCC多版本并发控制：读不阻塞写、写不阻塞读（原理见 隔离级别与锁）
类型丰富jsonb、数组、uuid、范围类型、枚举、网络地址类型……
扩展机制CREATE EXTENSION 一行装新功能，如 vector（向量）
事务性 DDL建表、改表也能放进事务里回滚（本机实测过）
版本节奏每年一个大版本，每个大版本官方支持 5 年。截至 2026 年 10 月官网列出的在用版本是 14～18（18 最新，18.6）；14 将在 2026-11-12 结束支持。来源：https://www.postgresql.org/support/versioning/

2. 实例、数据库、Schema、表 ​

从大到小：

  • 集群（cluster）/ 实例：一个运行中的 PostgreSQL 服务，监听一个端口（默认 5432）。
  • 数据库（database）：实例里可以有多个，连接时必须指定连哪一个，不能像 SQL Server 那样在一个连接里 USE 切换（psql 里用 \c 实际是重新连接）。
  • Schema（模式）：数据库里的"文件夹"，默认叫 public。
  • 表（table）：在某个 schema 里。完整名字是 schema.table，如 public.board。

3. 角色（Role） ​

PostgreSQL 里"用户"和"组"统一叫角色（role）。安装时会创建超级用户 postgres。

4. 常用数据类型 ​

用途PostgreSQL 类型SQL Server 里最接近的
整数smallint / integer / bigintsmallint / int / bigint
精确小数numeric(p,s)decimal(p,s)
文本text（不限长）、varchar(n)nvarchar(max) / nvarchar(n)
布尔boolean（true/false，显示为 t/f）bit
日期时间date、timestamp、timestamptz（带时区）date、datetime2、datetimeoffset
唯一标识uuiduniqueidentifier
JSONjsonb（二进制，可建索引）nvarchar(max) + JSON 函数
数组integer[]、text[] 等没有（要拆表）

两点说明：PostgreSQL 数据库一般用 UTF-8 编码建库，text 直接存中文，不需要 SQL Server 那样专门用 nvarchar（本机实测：length('中文') = 2 个字符，octet_length = 6 字节）。text 与 varchar 性能没有差别，只是后者多一个长度检查。

5. psql：命令行客户端 ​

psql 是 PostgreSQL 自带的命令行工具，类似 SQL Server 的 sqlcmd。除了执行 SQL，还有以反斜杠开头的"元命令"（只在 psql 里有效，不是 SQL）：

命令作用
\l列出所有数据库
\c 库名连接到另一个数据库
\conninfo显示当前连接信息
\dt列出当前 schema 的表
\d 表名查看表结构、索引
\dn列出 schema
\du列出角色
\dx列出已安装扩展
\df列出函数
\x开关"竖排显示"（列很多时好读）
\timing on显示每条语句耗时
\i 文件.sql执行脚本文件
\copy客户端导入/导出 CSV
\q退出

（以上命令来自官方文档 https://www.postgresql.org/docs/current/app-psql.html ；其中 \conninfo、\x、\timing、\dt、\d、\dn、\du、\dx、\l 在本机实测过，\i、\copy、\df 未实测。）

例 2：建表、插入、查询 ​

sql
CREATE TABLE board (
    id        integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sn        varchar(20) NOT NULL UNIQUE,
    result    text,
    cycle_sec numeric(6,2),
    made_at   timestamptz DEFAULT now(),
    is_rework boolean DEFAULT false
);
INSERT INTO board (sn, result, cycle_sec)
VALUES ('SN0001','PASS',12.50), ('SN0002','FAIL',13.25), ('SN0003','PASS',11.80);
SELECT id, sn, result, cycle_sec, is_rework FROM board ORDER BY id;

实际输出：

INSERT 0 3
 id |   sn   | result | cycle_sec | is_rework
----+--------+--------+-----------+-----------
  1 | SN0001 | PASS   |     12.50 | f
  2 | SN0002 | FAIL   |     13.25 | f
  3 | SN0003 | PASS   |     11.80 | f
(3 rows)

读法：GENERATED ALWAYS AS IDENTITY 就是自增列（相当于 SQL Server 的 IDENTITY），所以不用给 id；INSERT 0 3 里的 3 是插入的行数（0 是历史遗留的占位）。布尔值显示成 f / t。

用 \d board 看表结构：

Indexes:

例 4：与 SQL Server 行为不同的几个点（全部实测） ​

sql
SELECT '' IS NULL AS empty_is_null, ''::text = '' AS same;     -- f, t
SELECT 7/2 AS int_div, 7/2.0 AS num_div;                       -- 3, 3.5000000000000000
SELECT 'abc' = 'ABC' AS case_sensitive;                        -- f
SELECT 'a' || NULL AS concat_null;                             -- NULL
SELECT concat('a', NULL, 'b') AS concat_fn;                    -- ab
SELECT 1 WHERE NULL = NULL;                                    -- 0 行
SELECT NULL IS NOT DISTINCT FROM NULL AS same_null;            -- t
SELECT 'Wang' ILIKE 'wang' AS ilike_match;                     -- t
SELECT 10 || 20;                                               -- 报错

最后一条的真实报错：ERROR: operator does not exist: integer || integer。含义：

  • 字符串比较默认区分大小写（SQL Server 默认排序规则通常不区分）。不区分大小写要用 ILIKE 或 lower()。
  • 字符串用 || 连接，遇到 NULL 结果是 NULL；想忽略 NULL 用 concat() 函数。
  • 数字不能直接 ||，要先转成文本。
  • 7/2 整数除法得 3（和 SQL Server 一致），想要小数写 7/2.0。

例 5：未加引号的名字会变小写（实测） ​

sql
CREATE TABLE MyTable (Id int, Name text);
\dt                          -- 列出的名字是 mytable
SELECT * FROM MyTable;       -- 可以：未加引号的 MyTable 也被折成 mytable
CREATE TABLE "CamelCase" (id int);
SELECT * FROM CamelCase;     -- 报错：relation "camelcase" does not exist
SELECT * FROM "CamelCase";   -- 可以

规则：不加双引号的标识符一律折成小写；加了双引号就区分大小写，之后每次都必须带引号。建议：库里的表名列名全部用小写加下划线（work_order），永远不要加引号。这也是 SqlSugar 等 ORM 对接 PostgreSQL 时要注意的点（见下）。

例 6：DDL 可以回滚（实测） ​

sql
BEGIN;
CREATE TABLE ddl_in_tx (x int);
ROLLBACK;
SELECT to_regclass('ddl_in_tx') AS exists_after_rollback;     -- 空（NULL），说明表没建成

dotnet new console -o PgLab && cd PgLab

连接串（本机端口 61280 是随机的，按自己的改）：Host=127.0.0.1;Port=61280;Username=postgres;Database=lab_pg。

csharp
using SqlSugar;
using Npgsql;

var cs = args[0];

// 1) 原生 Npgsql：参数用 @name
await using (var conn = new NpgsqlConnection(cs))
{
    await conn.OpenAsync();
    await using var cmd = new NpgsqlCommand("SELECT sn, result FROM board WHERE result = @r ORDER BY id", conn);
    cmd.Parameters.AddWithValue("r", "PASS");
    await using var rd = await cmd.ExecuteReaderAsync();
    while (await rd.ReadAsync()) Console.WriteLine($"Npgsql: {rd.GetString(0)} {rd.GetString(1)}");
}

// 2) SqlSugar + PostgreSQL
var db = new SqlSugarClient(new ConnectionConfig {
    ConnectionString = cs, DbType = DbType.PostgreSQL, IsAutoCloseConnection = true });
db.CodeFirst.InitTables<Device>();
db.Insertable(new List<Device> {
    new Device { Code = "SMT01", Name = "贴片机1号" },
    new Device { Code = "AOI01", Name = "光学检测1号" } }).ExecuteCommand();
foreach (var d in db.Queryable<Device>().OrderBy(d => d.Id).ToList())
    Console.WriteLine($"SqlSugar-PG: {d.Id} {d.Code} {d.Name}");
Console.WriteLine("PG SQL: " + db.Queryable<Device>().Where(d => d.Code == "SMT01").Skip(0).Take(5).ToSql().Key);

public class Device {
    [SugarColumn(IsPrimaryKey = true, IsIdentity = true)] public int Id { get; set; }
    [SugarColumn(Length = 30)] public string Code { get; set; } = "";
    [SugarColumn(Length = 100)] public string Name { get; set; } = "";
}

实际输出：

Npgsql: SN0001 PASS
Npgsql: SN0003 PASS
SqlSugar-PG: 1 SMT01 贴片机1号
SqlSugar-PG: 2 AOI01 光学检测1号
PG SQL: SELECT "id","code","name" FROM "device"   WHERE ( "code" = @Code0 )   LIMIT 5 offset 0

观察三点：① 中文没有变成问号——PostgreSQL 的 varchar 本来就是 UTF-8，不需要像 SQL Server 那样为中文列专门指定 nvarchar；② SqlSugar 生成的 SQL 把表名列名都小写并加了双引号（与上面"标识符折成小写"规则一致）；③ 分页变成 LIMIT 5 offset 0。SqlSugarCore 与 SqlSugar 里 SQL Server 的用法几乎一样，只改 DbType。

常见坑与排查 ​

现象原因处理

业务视角与技术视角 ​

业务视角：工厂系统一般不在 PostgreSQL 和 SQL Server 之间"选边站"，而是由已有系统和团队技能决定。典型出现 PostgreSQL 的位置：开源的数据平台、设备数据采集网关自带存储、AI/向量检索（见 Embedding与向量检索）、时序数据（TimescaleDB 扩展）。选型对比见 数据库选型对比。

技术视角：C# 里用 Npgsql 驱动（ADO.NET 风格），ORM 可用 SqlSugar 或 EF Core（见 EF-Core）；T-SQL 脚本需要手工翻译成 PostgreSQL 方言，重点是 TOP、IDENTITY、ISNULL、+ 拼接、变量与流程控制几处。

练习题与答案 ​

练习 1：把 SQL Server 语句 SELECT TOP 5 sn, ISNULL(result,'N/A') FROM dbo.board ORDER BY id DESC 改写成 PostgreSQL。 答案：SELECT sn, coalesce(result,'N/A') FROM board ORDER BY id DESC LIMIT 5;（去掉 dbo.；TOP 换成 LIMIT，放最后）。

练习 2：下面哪些会报错？(a) SELECT 'a' || 1; (b) SELECT 1 || 2; (c) SELECT concat(1, 2);答案：(b) 报错（两边都是整数，没有 || 运算符，已实测同类报错 integer || integer）。(a) 不报错，返回 a1：一边是字符串时另一边会自动转成文本（已实测）。(c) 返回 12（已实测）。

练习 3：CREATE TABLE "Board" (id int); 之后，SELECT * FROM board; 能查到吗？ 答案：不能。"Board" 带引号保留大写，而 board 不带引号被折成小写 board，是两个不同的名字，会报 relation "board" does not exist。

练习 4：为什么说 PostgreSQL 的 DDL 可回滚是个优点？举一个场景。 答案：升级脚本里同时建表、改列、插入初始数据，中途失败时整体回滚，不会留下半成品结构。

小结 ​

  • PostgreSQL 是开源、功能全的关系库，MVCC、扩展机制是亮点；每年一个大版本，官方支持 5 年。
  • 用 psql 的 \l \c \dt \d \x \timing 就能完成日常操作。
  • 与 SQL Server 的主要差别：LIMIT、||、coalesce、小写折叠、字符串区分大小写、没有 T-SQL 变量。
  • 中文不需要 nvarchar；C# 用 Npgsql，SqlSugar 只要改 DbType。
  • 想快速练手，pip install pgserver 即可（仅学习用）。
