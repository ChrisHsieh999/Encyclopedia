SQL基础查询

AI 生成 · 待核对数据库SQLT-SQL更新于 2026-10-21

本篇是 数据库 入门路径的第 2 篇，也是整个 SQL 系列的练习库定义篇：后面所有 SQL 词条都使用这里的 Lab_Basic 库和三张表。读完你应该能：用 SELECT 从表里取出想要的列和行；用 WHERE 过滤、ORDER BY 排序、TOP 取前几条；知道 NULL 为什么会让查询"丢数据"；并拥有一个可随时重建的练习环境。

一句话定义 ​

SELECT 是 SQL 里的"查询"语句：告诉数据库"从哪张表（FROM）、取哪些列（SELECT）、满足什么条件的行（WHERE）、按什么顺序（ORDER BY）"，数据库返回一张结果表。SQL（Structured Query Language）是和关系型数据库对话的标准语言；本系列使用 SQL Server 的方言 T-SQL。

先修知识 ​

  • 关系模型：知道表、行、列、主键、外键。
  • 本机装有 SQL Server LocalDB（随 Visual Studio 或 SQL Server Express 安装），能用 sqlcmd 或 SSMS 连接。

它解决什么问题 ​

数据放进库里是为了拿出来用：车间主任问"现在在产的工单有哪些""单价最高的 3 种物料是什么""昨天 AOI 站有多少块板不良"。每个问题都是一条 SELECT。没有它，数据库就是一个打不开的保险箱。

核心概念 ​

SELECT 语句的五个基本部分 ​

sql
SELECT   要的列
FROM     哪张表
WHERE    行要满足的条件
ORDER BY 排序依据

书写顺序如上，但数据库执行的逻辑顺序是：先 FROM（找表）→ WHERE（筛行）→ SELECT（取列、算表达式）→ ORDER BY（排序）。这解释了一个常见现象：在 WHERE 里不能使用 SELECT 里起的别名（别名还没产生），但 ORDER BY 里可以。

SQL 关键字不区分大小写（select 和 SELECT 一样），习惯写大写；语句可以换行；T-SQL 里分号结尾可写可不写，建议写。

先建练习库 ​

整个 SQL 系列共用下面这套脚本。它会建库 Lab_Basic（已存在就先删了重建，所以可以反复运行恢复现场），建 3 张表，造 11 种物料、5 张工单、25 条测试记录。

三张表（名字固定，其他词条依赖它们）：

表含义列
Material物料主数据（含成品）MaterialCode 编码（主键）、MaterialName 名称、Category 类别、UnitPrice 单价（可空）
WorkOrder工单WoNo 工单号（主键）、ProductCode 产品编码（外键→Material）、PlanQty 计划数、DoneQty 完工数、Status 状态、CreatedAt 创建时间
TestRecord测试记录Id 自增主键、SerialNo 板序列号、WoNo 工单号（外键→WorkOrder）、Station 测试站、Result 结果、TestedAt 测试时间

重要约定：含中文的列一律用 nvarchar，中文字符串常量前加 N（如 N'电阻'）。原因见下文"常见坑"。

sql
SET NOCOUNT ON;
IF DB_ID(N'Lab_Basic') IS NOT NULL
BEGIN
    ALTER DATABASE Lab_Basic SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
    DROP DATABASE Lab_Basic;
END
GO
CREATE DATABASE Lab_Basic;
GO
USE Lab_Basic;
GO
-- 物料主数据：含中文的列一律 nvarchar
CREATE TABLE Material (
    MaterialCode varchar(20)   NOT NULL PRIMARY KEY,
    MaterialName nvarchar(50)  NOT NULL,
    Category     nvarchar(20)  NOT NULL,
    UnitPrice    decimal(10,2) NULL          -- 允许空：治具之类不定价
);
-- 工单
CREATE TABLE WorkOrder (
    WoNo        varchar(20) NOT NULL PRIMARY KEY,
    ProductCode varchar(20) NOT NULL REFERENCES Material(MaterialCode),
    PlanQty     int         NOT NULL,
    DoneQty     int         NOT NULL DEFAULT 0,
    Status      varchar(20) NOT NULL,        -- Created / Running / Done / Cancelled
    CreatedAt   datetime2(0) NOT NULL
);
-- 测试记录（每次过测试站产生一行，同一块板可有多行）
CREATE TABLE TestRecord (
    Id       int IDENTITY(1,1) NOT NULL PRIMARY KEY,
    SerialNo varchar(30)  NOT NULL,
    WoNo     varchar(20)  NOT NULL REFERENCES WorkOrder(WoNo),
    Station  varchar(20)  NOT NULL,          -- SPI / AOI / ICT / FCT
    Result   varchar(10)  NOT NULL,          -- PASS / FAIL
    TestedAt datetime2(0) NOT NULL
);
GO

怎么运行：把上面脚本存成 Lab_Basic.sql（用 UTF-8 保存），在命令行执行：

sqlcmd -S "(localdb)\MSSQLLocalDB" -E -C -f 65001 -i Lab_Basic.sql

参数含义：-S 服务器（LocalDB 的默认实例名是 (localdb)\MSSQLLocalDB）；-E 用当前 Windows 账号登录；-C 信任服务器证书（新版 sqlcmd 默认要求加密连接，LocalDB 的证书不被信任，可能连接失败；我本机的 sqlcmd 15.0 版不加 -C 也能连，加了无害）；-f 65001 按 UTF-8 读写文件，中文才不乱码；-i 指定要执行的脚本。成功后输出：

tbl|n
---|-
Material|11
WorkOrder|5
TestRecord|25

（我在命令里还加了 -W -s "|"，让输出紧凑、列用竖线分隔，本系列所有"预期输出"都是这种样式；你不加这两个参数，只是列之间用空格对齐，内容相同。）

本机有两个 SQL Server：LocalDB（练习用）和可能存在的默认实例 MSSQLSERVER（别的软件在用的）。本系列只连 (localdb)\MSSQLLocalDB，脚本里的 DROP DATABASE 只作用在连接到的那个实例上，千万别把 -S 改成别的。也可以用 SSMS / VS Code 的 SQL 扩展连接同一个地址，把脚本粘进去执行。

练习完要清理：DROP DATABASE Lab_Basic;（需先 USE master;）。

逐步例子 ​

以下输出均来自在 SQL Server 2025 Express（LocalDB）上的实际运行。

1. 取全部列、取指定列、起别名 ​

sql
SELECT * FROM Material;

* 表示所有列，学习时随便用，正式程序里尽量写明列名（表结构改了，* 的结果就悄悄变了，还多传无用的数据）。结果 11 行（节选）：

MaterialCode|MaterialName|Category|UnitPrice
------------|------------|--------|---------
C-100N|贴片电容100nF|电容|.05
C-10U|贴片电容10uF|电容|.30
CN-USB01|USB接口|连接器|1.20
FIXTURE-01|测试治具01|治具|NULL
……

两点说明：

  • 单价显示成 .05 而不是 0.05，这是 sqlcmd 的显示习惯，值本身没问题。
  • 没写 ORDER BY 时，行顺序没有保证。这次碰巧按主键排，不要依赖它。

只取需要的列并改个显示名（AS，列别名）：

sql
SELECT MaterialCode AS 物料编码, MaterialName AS 名称, UnitPrice AS 单价 FROM Material;

2. WHERE 过滤行 ​

sql
SELECT WoNo, ProductCode, PlanQty, DoneQty FROM WorkOrder WHERE Status = 'Running';
WoNo|ProductCode|PlanQty|DoneQty
----|-----------|-------|-------
WO-1002|PCBA-A100|300|120
WO-1004|PCBA-B200|1000|640

字符串常量用单引号。比较运算符：=、<>（不等于，也可写 !=）、<、>、<=、>=。

3. 多个条件：AND、OR、IN、BETWEEN ​

sql
SELECT WoNo, PlanQty, DoneQty FROM WorkOrder WHERE Status = 'Running' AND PlanQty >= 500;

结果只有 WO-1004|1000|640。

"状态是 Done 或 Cancelled"有两种写法，结果一样（WO-1001、WO-1005）：

sql
WHERE Status = 'Done' OR Status = 'Cancelled'
WHERE Status IN ('Done', 'Cancelled')      -- 候选值多时，IN 更清楚

区间用 BETWEEN，两端都包含：

sql
SELECT MaterialCode, UnitPrice FROM Material WHERE UnitPrice BETWEEN 1 AND 20;
MaterialCode|UnitPrice
------------|---------
CN-USB01|1.20
IC-MCU01|12.80
IC-PWR01|3.60

AND 比 OR 优先，混用一定加括号。实验（取 WO-1002 的 AOI 记录，或任何 FAIL 记录）：

sql
-- 写法 A：没加括号，等价于 (WoNo='WO-1002' AND Station='AOI') OR Result='FAIL'
SELECT Id, Station, Result FROM TestRecord WHERE WoNo = 'WO-1002' AND Station = 'AOI' OR Result = 'FAIL';
-- 写法 B：加了括号，意思是 WO-1002 里，站是 AOI 或者结果 FAIL
SELECT Id, Station, Result FROM TestRecord WHERE WoNo = 'WO-1002' AND (Station = 'AOI' OR Result = 'FAIL');

写法 A 返回 9 行（把其他工单的 FAIL 都带出来了），写法 B 只返回 4 行（Id 为 11、14、15、16）。想要哪个意思，用括号写清楚。

4. 模糊匹配 LIKE ​

sql
SELECT MaterialCode, MaterialName FROM Material WHERE MaterialName LIKE N'贴片%';

通配符：% 代表任意多个字符（包括 0 个），_ 代表恰好一个字符，[CR] 代表方括号里任选一个字符。

写法含义结果
LIKE N'贴片%'以"贴片"开头4 行（两个电容、两个电阻）
LIKE N'%电阻%'包含"电阻"R-10K、R-1K
LIKE 'C-%N'C- 开头、N 结尾只有 C-100N
LIKE 'R-1_'R-1 后面恰好一个字符只有 R-1K（R-10K 多一个字符，不匹配）
LIKE '[CR]-%'以 C- 或 R- 开头C-100N、C-10U、R-10K、R-1K

性能提示：LIKE 'abc%'（前缀匹配）可以用上索引，LIKE '%abc'（后缀/包含）基本只能逐行扫描，大表上要小心，见 数据库索引。

5. NULL：最容易丢数据的地方 ​

FIXTURE-01（治具）的单价是 NULL（不定价）。先来个"想当然"的写法：

sql
SELECT MaterialCode FROM Material WHERE UnitPrice = NULL;     -- 返回 0 行！
SELECT MaterialCode FROM Material WHERE UnitPrice IS NULL;    -- 正确：FIXTURE-01

原因：NULL 表示"未知"，未知 = 未知 的结果还是"未知"，而 WHERE 只放行结果为"真"的行。所以判断空要用 IS NULL / IS NOT NULL。

更隐蔽的是 <>：

sql
SELECT COUNT(*) FROM Material WHERE UnitPrice <> 85.00;                       -- 9
SELECT COUNT(*) FROM Material WHERE UnitPrice <> 85.00 OR UnitPrice IS NULL;  -- 10

11 种物料里只有一个单价是 85.00，按直觉"不等于 85"应该是 10 行，但 NULL 那行被悄悄丢掉了，只得到 9。凡是比较的列允许为 NULL，都要想一想 NULL 那行该不该算。

ISNULL(列, 默认值) 可以把 NULL 换成默认值：

sql
SELECT MaterialCode, UnitPrice, ISNULL(UnitPrice, 0) AS 单价或零 FROM Material WHERE Category IN (N'辅料', N'治具');
MaterialCode|UnitPrice|单价或零
------------|---------|----
FIXTURE-01|NULL|.00
SOLDER-T3|380.00|380.00

6. ORDER BY 排序 ​

sql
SELECT MaterialCode, UnitPrice FROM Material ORDER BY UnitPrice DESC;

ASC 升序（默认），DESC 降序。结果从 SOLDER-T3|380.00 开始，依次递减，NULL 排在最后（降序时）——在 SQL Server 里 NULL 被当作最小值，升序时排最前。

多个排序键用逗号分隔，先按第一个，相同再按第二个：

sql
SELECT WoNo, Status, PlanQty FROM WorkOrder ORDER BY Status ASC, PlanQty DESC;
WoNo|Status|PlanQty
----|------|-------
WO-1005|Cancelled|50
WO-1003|Created|200
WO-1001|Done|500
WO-1004|Running|1000
WO-1002|Running|300

Running 两行再按计划数降序：1000 在 300 前面。

7. TOP 与分页 ​

取单价最高的 3 种：

sql
SELECT TOP 3 MaterialCode, UnitPrice FROM Material ORDER BY UnitPrice DESC;
MaterialCode|UnitPrice
------------|---------
SOLDER-T3|380.00
PCBA-B200|120.50
PCBA-A100|85.00

TOP 必须配 ORDER BY，否则"前 3 条"是哪 3 条没有保证。要翻页（跳过前 3 条，再取 3 条）用 OFFSET … FETCH（SQL Server 2012 起）：

sql
SELECT MaterialCode, UnitPrice FROM Material
ORDER BY UnitPrice DESC, MaterialCode
OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;
MaterialCode|UnitPrice
------------|---------
IC-MCU01|12.80
IC-PWR01|3.60
CN-USB01|1.20

OFFSET 必须搭配 ORDER BY；排序键里加上主键 MaterialCode，保证并列时顺序稳定，翻页才不会重复或漏行。

8. DISTINCT 去重 ​

sql
SELECT DISTINCT Station FROM TestRecord;

25 条测试记录，去重后只剩 4 个测试站：AOI、FCT、ICT、SPI。多列一起去重时，是看"整组值"是否重复：SELECT DISTINCT Station, Result FROM TestRecord 返回 8 行（4 站 × PASS/FAIL）。

9. 计算列、CASE 与类型转换 ​

sql
SELECT WoNo, PlanQty, DoneQty, PlanQty - DoneQty AS 未完成数 FROM WorkOrder;

WO-1002 的未完成数是 180，WO-1004 是 360。

计算完成率时要小心整数除法：

sql
SELECT 640 / 1000 AS int_div, 640 * 1.0 / 1000 AS dec_div;
int_div|dec_div
-------|-------
0|.640000

两个整数相除，结果被截成整数 0。把其中一个乘以 1.0 变成小数，或者用 CAST：

sql
SELECT WoNo, CAST(DoneQty * 100.0 / PlanQty AS decimal(5,1)) AS 完成率百分比 FROM WorkOrder;

结果：WO-1001 为 100.0，WO-1002 为 40.0，WO-1004 为 64.0，没开工的是 0。

CASE 是 SQL 里的"如果……就……"：

sql
SELECT WoNo, Status,
       CASE Status WHEN 'Created' THEN N'已创建' WHEN 'Running' THEN N'生产中'
                   WHEN 'Done' THEN N'已完工' ELSE N'已取消' END AS 状态中文
FROM WorkOrder;

WO-1002 → 生产中、WO-1001 → 已完工……报表里把状态码翻译成中文很常用。

10. 时间范围过滤 ​

查 2026-10-19 这一天的 FAIL 记录。日期范围推荐写成"大于等于当天零点 且 小于次日零点"：

sql
SELECT Id, SerialNo, TestedAt FROM TestRecord
WHERE TestedAt >= '2026-10-19' AND TestedAt < '2026-10-20' AND Result = 'FAIL';
Id|SerialNo|TestedAt
--|--------|--------
21|SN1004-002|2026-10-19 13:22:00
22|SN1004-003|2026-10-19 13:05:00
25|SN1004-004|2026-10-19 14:05:00

不要写 BETWEEN '2026-10-19' AND '2026-10-19 23:59:59'：边界容易漏掉最后那一秒内的毫秒数据，而且换成 datetime 类型时精度问题更麻烦。

动手实验 ​

  1. 按上面的方法运行建库脚本，确认输出 11 / 5 / 25。
  2. 写查询并对照结果（括号里是我实际运行得到的结果）：
    • 所有"电容"类物料的编码和名称（C-100N、C-10U 共 2 行）；
    • 计划数量大于 250、且状态不是 Cancelled 的工单，按计划数量从大到小排（WO-1004、WO-1001、WO-1002）；
    • 2026-10-16 当天 Result = 'FAIL' 的测试记录（Id 15、16 共 2 行）；
    • 单价最低的 2 种物料（提示：NULL 排在升序最前面，怎么避开？答案：加 WHERE UnitPrice IS NOT NULL，得到 R-10K、R-1K，单价都是 0.02）。
  3. 把 WHERE UnitPrice = NULL 和 IS NULL 各跑一次，亲眼看差别。
  4. 想恢复现场：重新运行建库脚本即可。

常见坑与排查 ​

  • 中文变成问号：
    • 列用了 varchar：中文存进去就是 ?，且不可恢复。含中文的列必须 nvarchar。
    • 查询里的中文常量漏写 N：我实测 SELECT '中' 显示成 ?，WHERE MaterialName = '贴片电阻10K' 返回 0 行，加上 N 的版本才返回 1 行。
    • 终端显示乱码：用 sqlcmd -f 65001 或在 PowerShell/CMD 里先 chcp 65001；脚本文件要保存成 UTF-8。注意这只影响"显示/读文件"，数据库里存的是对的。
  • Invalid column name 'xxx'（Msg 207）：列名拼错（我故意把 MaterialCode 拼成 MaterialCod 就是这个错）。Invalid object name（Msg 208）：表名拼错，或者当前库不对——先看是不是忘了 USE Lab_Basic;。
  • Divide by zero error encountered（Msg 8134）：除数为 0。分母可能为 0 时用 NULLIF(分母, 0) 把 0 变成 NULL（除以 NULL 得 NULL，不报错）。
  • 字符串拼接遇 NULL：'WO-' + NULL 的结果是 NULL；CONCAT('WO-', 1002, '-', NULL) 会把 NULL 当空串，得到 WO-1002-。（均已实测）
  • 大小写：我的 Lab_Basic 使用默认排序规则 SQL_Latin1_General_CP1_CI_AS，其中 CI 表示不区分大小写，所以 MaterialCode = 'r-10k' 也能匹配到 R-10K。如果你的库排序规则是区分大小写的（CS），结果会不同。
  • TOP / 分页没有 ORDER BY：结果不稳定，今天对明天可能错。

练习题与答案 ​

1. 为什么下面的查询返回 0 行？怎么改？ SELECT * FROM Material WHERE MaterialName = '贴片电阻10K'

答： 中文常量没写 N 前缀，被转成 ?，对不上任何名称。改成 N'贴片电阻10K'。

2. 写出：状态为 Running 的工单中，计划数量最大的那一张的工单号。

答：

sql
SELECT TOP 1 WoNo FROM WorkOrder WHERE Status = 'Running' ORDER BY PlanQty DESC;

结果 WO-1004（计划 1000）。

3. 下面两条 SQL 的结果行数各是多少？为什么不同？ SELECT COUNT(*) FROM Material WHERE UnitPrice <> 85.00SELECT COUNT(*) FROM Material WHERE UnitPrice <> 85.00 OR UnitPrice IS NULL

答： 9 和 10。治具单价是 NULL，NULL <> 85.00 的结果是"未知"，第一条丢掉了它；第二条用 OR UnitPrice IS NULL 把它补回来。

4. 取 2026-10-02 当天所有 AOI 站测试记录，要求写成"零点到次日零点"的形式。

答：

sql
SELECT * FROM TestRecord
WHERE Station = 'AOI' AND TestedAt >= '2026-10-02' AND TestedAt < '2026-10-03';

（共 4 条：Id 1、3、6、7。）

5. 如何分页，每页 3 条，取第 2 页，按物料编码排序？

答： ORDER BY MaterialCode OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;（第 n 页就是 OFFSET (n-1)*页大小）。

小结 ​

  • SELECT 取列、FROM 指表、WHERE 筛行、ORDER BY 排序；TOP / OFFSET FETCH 取前几条或分页。
  • AND 比 OR 优先，混用加括号；判断空值只能用 IS NULL，NULL 会让 =、<> 比较丢行。
  • 整数除法会截断；中文列用 nvarchar、常量加 N。
