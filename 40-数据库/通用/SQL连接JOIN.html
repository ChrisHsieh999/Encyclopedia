SQL连接JOIN

AI 生成 · 待核对数据库SQLT-SQL更新于 2026-10-21

本篇是 数据库 入门路径的第 4 篇。读完你应该能：说清 INNER / LEFT / RIGHT / FULL / CROSS JOIN 各返回什么；用 LEFT JOIN 找出"没有记录"的行；避开 ON 与 WHERE 位置写错、一对多放大、忘写连接条件这几个经典坑；会写自连接和三表连接。

一句话定义 ​

JOIN（连接） 把两张（或多张）表的行，按"连接条件"（通常是 外键 = 主键）拼成一行，让你在一条查询里同时看到分散在不同表里的信息。

先修知识 ​

  • 关系模型：为什么数据要拆成多张表，外键是什么。
  • SQL基础查询：SELECT、WHERE，并已运行建库脚本得到 Lab_Basic。
  • 表别名：FROM WorkOrder AS w 给表起个短名字 w，后面用 w.WoNo 引用。多表查询里几乎必用。

它解决什么问题 ​

拆表之后，信息分散了：工单表里只有 ProductCode = 'PCBA-A100'，产品叫什么名字要去物料表查；测试记录里只有工单号，这张工单是什么产品、什么状态要去工单表查。每次手工对照太累。JOIN 让数据库替你对照。

核心概念 ​

连接的原理：配对 ​

想象把两张表的行摆在一起，对于左表的每一行，去右表找满足 ON 条件的行，找到几行就配成几对。例如：

左表 WorkOrder 的 WO-1001（ProductCode = PCBA-A100）→ 去物料表找 MaterialCode = 'PCBA-A100' 的行 → 配成一行：WO-1001 | PCBA-A100 | 控制板A100。

各种 JOIN 的区别，只在于**"没有配上的行怎么处理"**：

类型没配上的行常见用途
INNER JOIN两边都丢掉只要有关联的数据（最常用，INNER 可省略写成 JOIN）
LEFT JOIN保留左表的，右表列填 NULL"以左表为主"：列出所有工单，没有测试记录的也要显示
RIGHT JOIN保留右表的，左表列填 NULL与 LEFT 对称，实际很少用（交换两表顺序就是 LEFT）
FULL JOIN两边没配上的都保留，对方填 NULL对账：找出"一边有、另一边没有"的差异
CROSS JOIN没有 ON，左边每行配右边每行（笛卡尔积）生成组合，如"每张工单 × 每个测试站"

基本写法 ​

sql
SELECT 列...
FROM   表A AS a
JOIN   表B AS b ON b.外键 = a.主键
WHERE  过滤条件;

ON 写连接条件，WHERE 写过滤条件，各司其职（对 INNER JOIN 两者可互换，对 LEFT JOIN 却天差地别，见下文）。

逐步例子 ​

以下全部在 Lab_Basic（SQL Server 2025 Express LocalDB）上实际运行。

1. INNER JOIN：工单加上产品名称 ​

sql
SELECT w.WoNo, w.ProductCode, m.MaterialName, w.PlanQty
FROM WorkOrder AS w
INNER JOIN Material AS m ON m.MaterialCode = w.ProductCode
ORDER BY w.WoNo;
WoNo|ProductCode|MaterialName|PlanQty
----|-----------|------------|-------
WO-1001|PCBA-A100|控制板A100|500
WO-1002|PCBA-A100|控制板A100|300
WO-1003|PCBA-B200|控制板B200|200
WO-1004|PCBA-B200|控制板B200|1000
WO-1005|PCBA-A100|控制板A100|50

5 张工单，每张配上 1 个物料，共 5 行。物料表里的另外 9 种物料（电阻、电容……）没有工单引用它们，在 INNER JOIN 里被丢掉了。

2. 忘了写 ON：笛卡尔积 ​

sql
SELECT COUNT(*) AS n FROM WorkOrder, Material;      -- 老式逗号写法，忘了 WHERE 连接条件

结果 55（5 × 11）：每张工单和每种物料两两配对。表一大就是灾难（10 万 × 10 万 = 100 亿行）。现代写法 JOIN … ON 把连接条件强制写在 ON 里，更不容易忘。

3. 统计时：INNER JOIN 会"吃掉"没有记录的工单 ​

sql
SELECT w.WoNo, COUNT(*) AS test_cnt
FROM WorkOrder w JOIN TestRecord t ON t.WoNo = w.WoNo
GROUP BY w.WoNo ORDER BY w.WoNo;
WoNo|test_cnt
----|--------
WO-1001|10
WO-1002|6
WO-1004|9

WO-1003 和 WO-1005 没有测试记录，根本没出现在结果里。做报表时，"没有数据"的那几行往往正是老板要看的。

4. LEFT JOIN：保留所有工单 ​

sql
SELECT w.WoNo, w.Status, COUNT(t.Id) AS test_cnt
FROM WorkOrder w LEFT JOIN TestRecord t ON t.WoNo = w.WoNo
GROUP BY w.WoNo, w.Status ORDER BY w.WoNo;
WoNo|Status|test_cnt
----|------|--------
WO-1001|Done|10
WO-1002|Running|6
WO-1003|Created|0
WO-1004|Running|9
WO-1005|Cancelled|0

注意两点：这次 5 张工单都在；计数写的是 COUNT(t.Id) 而不是 COUNT(*)——COUNT(列) 不数 NULL，没配上的工单右表列全是 NULL，所以正确得到 0；如果写成 COUNT(*)，WO-1003 会变成 1（那一行"空配对"也算一行）。

看一眼没分组的原始配对，更容易理解（WO-1003 只有一行，右边全是 NULL）：

WoNo|Id|Station
----|--|-------
WO-1002|11|AOI
WO-1002|12|ICT
……（WO-1002 共 6 行）
WO-1003|NULL|NULL

5. LEFT JOIN + IS NULL：找出"没有"的（反连接） ​

问题："哪些工单从来没有测试记录？"

sql
SELECT w.WoNo, w.Status
FROM WorkOrder w LEFT JOIN TestRecord t ON t.WoNo = w.WoNo
WHERE t.Id IS NULL;
WoNo|Status
----|------
WO-1003|Created
WO-1005|Cancelled

逻辑：先 LEFT JOIN，没配上的行右表主键必为 NULL，再用 WHERE 筛出这些行。这是工厂里极常见的问题类型："哪些订单没发货""哪些物料没领用""哪些设备没点检"。（用子查询 NOT EXISTS 也能做，见 SQL子查询与CTE。）

6. 以物料为主：哪些物料从没被生产过 ​

sql
SELECT m.MaterialCode, m.MaterialName, w.WoNo
FROM Material m LEFT JOIN WorkOrder w ON w.ProductCode = m.MaterialCode
WHERE m.Category IN (N'成品', N'电阻') ORDER BY m.MaterialCode, w.WoNo;
MaterialCode|MaterialName|WoNo
------------|------------|----
PCBA-A100|控制板A100|WO-1001
PCBA-A100|控制板A100|WO-1002
PCBA-A100|控制板A100|WO-1005
PCBA-B200|控制板B200|WO-1003
PCBA-B200|控制板B200|WO-1004
R-10K|贴片电阻10K|NULL
R-1K|贴片电阻1K|NULL

一个物料对应多张工单时，会出现多行（A100 有 3 张工单就是 3 行）。这叫一对多"展开"，下面第 11 步会看到它的副作用。

7. RIGHT JOIN：换个方向写的 LEFT JOIN ​

sql
SELECT m.MaterialCode, w.WoNo
FROM WorkOrder w RIGHT JOIN Material m ON w.ProductCode = m.MaterialCode
WHERE m.Category IN (N'成品', N'电阻') ORDER BY m.MaterialCode, w.WoNo;

结果与第 6 步完全相同（7 行）。右连接只是把"主表"写在了 JOIN 右边；建议统一用 LEFT JOIN，主表放左边，读起来顺。

8. FULL JOIN：对账——应测 vs 实测 ​

场景：规定每张工单要测 4 个站（SPI、AOI、ICT、FCT），WO-1002 实际测了哪些？用 FULL JOIN 把"应测清单"和"实测"对比：

sql
SELECT e.Station AS 应测, a.Station AS 实测
FROM (VALUES ('SPI'),('AOI'),('ICT'),('FCT')) AS e(Station)
FULL OUTER JOIN (SELECT DISTINCT Station FROM TestRecord WHERE WoNo = 'WO-1002') AS a ON a.Station = e.Station
ORDER BY e.Station;
应测|实测
--|--
AOI|AOI
FCT|FCT
ICT|ICT
SPI|NULL

SPI 站"应测"但"实测"为 NULL，说明 WO-1002 漏了 SPI（SMT 的锡膏印刷检查）这一站。如果实测里有应测清单之外的站，会出现"应测为 NULL"的行——FULL JOIN 同时能发现缺的和多的。(VALUES …) AS e(Station) 是临时造一张小表的写法，这里不展开。

9. CROSS JOIN：生成组合 ​

问：在产（Running）的每张工单，要检查 4 个站，列出完整检查清单：

sql
SELECT w.WoNo, s.Station
FROM WorkOrder w
CROSS JOIN (VALUES ('SPI'),('AOI'),('ICT'),('FCT')) AS s(Station)
WHERE w.Status = 'Running' ORDER BY w.WoNo, s.Station;

2 张在产工单 × 4 个站 = 8 行（WO-1002 与 WO-1004 各 4 行）。CROSS JOIN 少见，但生成"日期 × 产线""工单 × 工序"这类骨架再 LEFT JOIN 实际数据，是做完整报表的好办法。

10. 自连接：同一张表连自己——找"先失败后复测通过"的板 ​

同一块板在同一站先 FAIL、后 PASS，说明复测过。把 TestRecord 当两张表用（别名 a 是首次，b 是后来）：

sql
SELECT a.SerialNo, a.Station, a.TestedAt AS first_fail, b.TestedAt AS retest_pass
FROM TestRecord a
JOIN TestRecord b ON b.SerialNo = a.SerialNo AND b.Station = a.Station AND b.TestedAt > a.TestedAt
WHERE a.Result = 'FAIL' AND b.Result = 'PASS'
ORDER BY a.SerialNo;
SerialNo|Station|first_fail|retest_pass
--------|-------|----------|-----------
SN1001-002|FCT|2026-10-02 08:45:00|2026-10-02 10:05:00
SN1001-003|AOI|2026-10-02 08:15:00|2026-10-02 09:30:00

自连接必须起别名，否则分不清左右。连接条件可以有多个，用 AND 连起来。

11. 三表连接：哪个产品的哪块板在哪一站失败 ​

sql
SELECT t.SerialNo, t.Station, t.Result, w.WoNo, m.MaterialName
FROM TestRecord t
JOIN WorkOrder w ON w.WoNo = t.WoNo
JOIN Material  m ON m.MaterialCode = w.ProductCode
WHERE t.Result = 'FAIL' ORDER BY t.Id;

返回 7 行，例如 SN1001-002 | FCT | FAIL | WO-1001 | 控制板A100、SN1004-004 | FCT | FAIL | WO-1004 | 控制板B200。多表连接就是一个接一个 JOIN，每个 ON 说明"新加的表怎么和已有的接上"。顺序写成"沿着外键链走"最好读。

12. 经典大坑：LEFT JOIN 里 ON 与 WHERE 不一样 ​

目标：列出 WO-1002、WO-1003、WO-1004 三张工单，以及它们的 FAIL 测试记录（没有 FAIL 的工单也要显示）。

写法 A（FAIL 条件放在 ON）：

sql
SELECT w.WoNo, t.Id, t.Result
FROM WorkOrder w LEFT JOIN TestRecord t ON t.WoNo = w.WoNo AND t.Result = 'FAIL'
WHERE w.WoNo IN ('WO-1002','WO-1003','WO-1004') ORDER BY w.WoNo, t.Id;
WoNo|Id|Result
----|--|------
WO-1002|15|FAIL
WO-1002|16|FAIL
WO-1003|NULL|NULL
WO-1004|21|FAIL
WO-1004|22|FAIL
WO-1004|25|FAIL

写法 B（FAIL 条件放在 WHERE）：

sql
SELECT w.WoNo, t.Id, t.Result
FROM WorkOrder w LEFT JOIN TestRecord t ON t.WoNo = w.WoNo
WHERE t.Result = 'FAIL' AND w.WoNo IN ('WO-1002','WO-1003','WO-1004') ORDER BY w.WoNo, t.Id;

结果少了 WO-1003 那一行（只剩 5 行）。

原因：WHERE 在连接之后执行。WO-1003 配出来的行 Result 是 NULL，NULL = 'FAIL' 不成立，被 WHERE 筛掉了——LEFT JOIN 被悄悄变成了 INNER JOIN。规则：想保留左表所有行时，针对右表的过滤条件要写在 ON 里；针对左表的过滤条件放 WHERE。

13. 一对多放大：合计被重复计算 ​

问："所有工单的计划数量合计？"正确答案是 SELECT SUM(PlanQty) FROM WorkOrder：

right_sum
---------
2050

如果先连测试记录再求和：

sql
SELECT SUM(w.PlanQty) AS wrong_sum
FROM WorkOrder w JOIN TestRecord t ON t.WoNo = w.WoNo;
wrong_sum
---------
15800

15800 = 500×10 + 300×6 + 1000×9：WO-1001 有 10 条测试记录，它的 500 被加了 10 遍。连接了"多"的一方之后，"一"的一方的数值列会按多方的行数重复。 要对工单求和，就不要连测试记录；或者先在子查询里分别汇总再连（见 SQL聚合与分组 和 SQL子查询与CTE）。这是报表数据对不上的头号原因。

14. 用 JOIN 来更新 ​

T-SQL 允许 UPDATE … FROM … JOIN：根据另一张表的信息来改本表。例如，对"有在产工单的成品"降价 10%（放进事务里演示，随后回滚）：

sql
BEGIN TRAN;
UPDATE m SET m.UnitPrice = m.UnitPrice * 0.9
FROM Material m JOIN WorkOrder w ON w.ProductCode = m.MaterialCode
WHERE w.Status = 'Running';
SELECT MaterialCode, UnitPrice FROM Material WHERE Category = N'成品' ORDER BY MaterialCode;
ROLLBACK;
MaterialCode|UnitPrice
------------|---------
PCBA-A100|76.50
PCBA-B200|108.45

85.00 × 0.9 = 76.50，120.50 × 0.9 = 108.45。回滚后又恢复为 85.00 和 120.50。注意：如果一个物料匹配到多张在产工单，被更新的仍然只有那一行物料，但用的是哪一张工单的值是不确定的——一对多时要小心。

  1. 运行 SQL基础查询 里的建库脚本。
  2. 依次执行例子 1、4、5、12A、12B，对比 12A / 12B 的行数。
  3. 自己写：

    • 找出"在产但还没有任何 FAIL 记录"的工单（提示：LEFT JOIN + IS NULL，FAIL 条件放 ON；当前数据返回 0 行，因为两张在产工单都有 FAIL，可以先把 Running 改成 Created 看看有结果的情形）；

常见坑与排查 ​

  • Ambiguous column name 'WoNo'（Msg 209）：两张表都有同名列时，必须写 表别名.列名（w.WoNo）。我实测 SELECT WoNo FROM WorkOrder w JOIN TestRecord t … 就会这样报错。好习惯：多表查询里所有列都带别名前缀。
  • LEFT JOIN 后行数变少：多半是针对右表的条件写进了 WHERE（例子 12）。
  • 结果行数比预想的多：连了一对多的表，或者连接条件不是唯一匹配（例如用名称而不是编码连接，而名称有重复）。用 SELECT COUNT(*) 对比连接前后的行数能快速发现。
  • 合计翻倍：例子 13。
  • 忘写 ON（笛卡尔积）：行数突然爆炸。
  • 连接列类型/排序规则不同：比如一张表用 varchar，另一张用 nvarchar，连接时会发生隐式转换，可能导致索引失效、变慢（见 执行计划与SQL优化）。外键两端的类型应当一致。
  • NULL 连不上：NULL = NULL 不成立，所以两边都是 NULL 的行不会被配对。需要时用 ON a.col = b.col OR (a.col IS NULL AND b.col IS NULL)。
  • 连接列没有索引：大表上 JOIN 慢，首先检查连接列（尤其外键列）有没有索引，见 数据库索引。SQL Server 不会自动给外键列建索引（主键才会）。

换个数据库怎么写 ​

JOIN 的核心语法是 SQL 标准，各库基本一致。已知差异：

  • SQLite 3.49.1 我在本机验证了 LEFT JOIN … GROUP BY、FULL OUTER JOIN 都能运行，结果与 SQL Server 一致（FULL OUTER JOIN 需要 SQLite 3.39 以上）。
  • ⚠ 未在本机运行验证：MySQL 不支持 FULL OUTER JOIN，需要用 LEFT JOIN … UNION … RIGHT JOIN 模拟。
  • ⚠ 未在本机运行验证：多表更新写法不同——PostgreSQL 用 UPDATE a SET … FROM b WHERE a.x = b.x；MySQL 用 UPDATE a JOIN b ON … SET a.col = …；Oracle 没有 UPDATE … FROM，要用 MERGE 或相关子查询。
  • ⚠ 未在本机运行验证：Oracle 早期有 (+) 的旧式外连接写法，新代码一律用标准的 LEFT JOIN。

练习题与答案 ​

1. 下面两条 SQL 结果行数分别是多少？ SELECT * FROM WorkOrder w JOIN TestRecord t ON t.WoNo = w.WoNoSELECT * FROM WorkOrder w LEFT JOIN TestRecord t ON t.WoNo = w.WoNo

答： 25 和 27。每条测试记录都有对应工单，INNER JOIN 得 25；LEFT JOIN 再加上两张没有测试记录的工单（WO-1003、WO-1005）各一行空配对，得 27。

2. "列出所有测试站及其 FAIL 次数，没有 FAIL 的也要显示 0"，应该怎么写？

答：

sql
SELECT s.Station, COUNT(t.Id) AS fail_cnt
FROM (VALUES ('SPI'),('AOI'),('ICT'),('FCT')) AS s(Station)
LEFT JOIN TestRecord t ON t.Station = s.Station AND t.Result = 'FAIL'
GROUP BY s.Station ORDER BY s.Station;

关键两点：以站清单为主表，FAIL 条件写在 ON。当前数据四个站都有 FAIL（AOI 3、FCT 2、ICT 1、SPI 1），所以没有 0 的行；若某站没有 FAIL 才会显示 0。

3. 为什么 SELECT SUM(w.PlanQty) FROM WorkOrder w JOIN TestRecord t ON t.WoNo = w.WoNo 的结果不是 2050？

答： 连接测试记录后，每张工单按它的测试记录条数重复了多次；WO-1003、WO-1005 因没有测试记录还被 INNER JOIN 丢掉。得到的 15800 没有业务意义。

4. 想找出"物料表里从未出现在任何工单中的物料"，用 JOIN 怎么写？

答： 以物料为主表 LEFT JOIN 工单，筛选工单列为 NULL：

sql
SELECT m.MaterialCode FROM Material m
LEFT JOIN WorkOrder w ON w.ProductCode = m.MaterialCode
WHERE w.WoNo IS NULL;

当前会返回 9 种（电阻电容芯片等原料、辅料、治具，因为工单只引用了 2 种成品）。

小结 ​

  • JOIN 按条件把行配对；各种 JOIN 的区别只在"没配上的行"怎么处理。
  • 常用 INNER JOIN（只要匹配）和 LEFT JOIN（保左表）；LEFT JOIN + IS NULL 找"没有"的。
  • LEFT JOIN 时右表的过滤条件放 ON，放 WHERE 会变回 INNER JOIN。
  • 连接一对多的表后，一方的数值会重复，汇总时要小心；多表查询所有列加别名前缀。
