C结构体与文件

AI 生成 · 待核对编程语言C语言更新于 2026-10-21

本篇是 C语言 入门路径的第 3 篇（最后一篇）。读完你应该能：用 struct 把相关数据打包；用 typedef、enum、union 让代码更清晰；读写文本和二进制文件；用位运算和位域解析一个 Modbus 状态寄存器，并把两个 16 位寄存器拼成 32 位浮点数。

一句话定义 ​

struct（结构体）把几个不同类型的变量打包成一个新类型，相当于 C 里"没有方法的类"；文件读写则是用 FILE * 这个指针去操作磁盘上的文件。

先修知识 ​

  • C语言：类型、数组、函数。
  • C指针与内存：指针、->、malloc，本篇大量传结构体指针。
  • 位运算与大小端：&、|、^、<<、>> 和字节序。
  • 十六进制。

它解决什么问题 ​

一块 PCB 有板码、层数、厚度。如果只能用独立变量，三块板就要 9 个变量，传给函数要带 3 个参数。用 struct，一个 Board 类型就能装下，数组可以装一批，函数只传一个指针。

文件读写解决"程序结束后数据还在"：把炉温读数存成 CSV，下次再读；或者直接把整个结构体按字节写进二进制文件。

位域与位运算则解决设备通信里一个 16 位寄存器要塞很多开关状态的问题：运行、故障、门打开……各占 1 位，工业协议里到处是这种设计。

核心概念 ​

1. struct 与 typedef ​

c
typedef struct {
    char   sn[16];
    int    layers;
    double thickness;
} Board;

typedef 给类型起别名，之后写 Board 就行，不用每次写 struct ...。访问成员：变量用 .，指针用 ->（b->layers 就是 (*b).layers）。结构体赋值是整块复制，包括里面的数组。

2. 内存对齐（padding） ​

CPU 读取数据时，喜欢地址是自身大小的整数倍。所以编译器会在成员之间悄悄填充空字节。成员的排列顺序会影响总大小：

  • {char a; int b; char c;}：1 + 3（填充）+ 4 + 1 + 3（末尾填充）= 12 字节；
  • {int b; char a; char c;}：4 + 1 + 1 + 2（末尾填充）= 8 字节。

这件事在你把结构体直接写入文件、或和别的语言（比如 C#）共享内存时尤其重要——两边的布局必须一致。

3. enum 枚举 ​

给一组整数起名字，代码比 0/1/5 好读：

c
typedef enum { ST_IDLE, ST_RUN, ST_FAULT = 5, ST_MAINT } State;

没指定值的从前一个加 1：ST_IDLE=0，ST_RUN=1，ST_FAULT=5，ST_MAINT=6。

4. union 联合体 ​

所有成员共用同一块内存，大小等于最大的成员。同一份 4 字节，既可以当 float 看，也可以当 uint32_t 看，或者两个 uint16_t。常用于解析协议里的"同一段字节、多种解释"。

5. 文件读写 ​

流程固定：fopen 打开 → 读写 → fclose 关闭。

函数作用
fopen(路径, 模式)打开文件。模式 "r" 读、"w" 写（会清空）、"a" 追加；加 b 表示二进制，如 "rb"、"wb"。失败返回 NULL，必须检查
fprintf / fgets / sscanf文本方式写 / 读一行 / 从字符串解析
fwrite / fread二进制方式整块写入/读取
fseek / ftell移动位置 / 查当前位置（可用来求文件大小）
fclose关闭，数据才保证真正写出

6. 位运算与位域 ​

16 位寄存器的每一位是一个开关。操作它们的"四件套"（reg 是寄存器值，BIT 是只有目标位为 1 的掩码）：

目的写法
读某一位(reg & BIT) != 0
置 1reg |= BIT
清 0reg &= ~BIT
翻转reg ^= BIT

多位字段要用"移位 + 掩码"：取 bit4~7 的 4 位模式值：(reg & (0xF << 4)) >> 4。

位域是 C 提供的另一种写法：在 struct 里用 类型 成员 : 位数 声明。优点是读起来像普通成员，缺点是位在字节里的排列顺序、跨边界怎么处理，都由编译器决定（标准没有规定），所以拿它去对应硬件/协议格式时要先确认编译器行为，最稳妥的做法仍是"移位 + 掩码"。

逐步例子 ​

例 1：结构体基本用法 ​

st1.c：

c
#include <stdio.h>
#include <string.h>

typedef struct {
    char   sn[16];      /* 板码 */
    int    layers;      /* 层数 */
    double thickness;   /* 板厚 mm */
} Board;

void print_board(const Board *b) {
    printf("%s: %d 层, %.1f mm\n", b->sn, b->layers, b->thickness);
}

void upgrade(Board *b) { b->layers += 2; }

int main(void) {
    Board b1 = {"PCB0001", 4, 1.6};
    print_board(&b1);
    upgrade(&b1);
    print_board(&b1);

    Board lot[3] = {{"A1", 2, 1.0}, {"A2", 4, 1.6}, {"A3", 6, 2.0}};
    double total = 0;
    for (int i = 0; i < 3; i++) total += lot[i].thickness;
    printf("3 块板总厚 %.1f mm\n", total);

    Board c = b1;                 /* 结构体赋值 = 整块复制 */
    strcpy(c.sn, "PCB0002");
    printf("原板仍是 %s, 副本是 %s\n", b1.sn, c.sn);

    struct { char a; int b; char c; } padded;
    struct { int b; char a; char c; } packed_order;
    printf("sizeof {char,int,char} = %zu\n", sizeof(padded));
    printf("sizeof {int,char,char} = %zu\n", sizeof(packed_order));
    printf("sizeof(Board) = %zu\n", sizeof(Board));
    return 0;
}

编译运行（本篇都这样编译，换文件名即可）：

python -m ziglang cc -std=c11 -Wall -Wextra st1.c -o st1.exe
./st1.exe

实际输出：

PCB0001: 4 层, 1.6 mm
PCB0001: 6 层, 1.6 mm
3 块板总厚 4.6 mm
原板仍是 PCB0001, 副本是 PCB0002
sizeof {char,int,char} = 12
sizeof {int,char,char} = 8
sizeof(Board) = 32

逐条验证：upgrade 通过指针把 layers 改成 4 + 2 = 6；总厚 1.0 + 1.6 + 2.0 = 4.6；Board 里 sn 占 16、layers 占 4、再填充 4 字节让 double 对齐到 8 的倍数、thickness 占 8，共 16 + 4 + 4 + 8 = 32。print_board 的参数用 const Board *，表示只读，不会改。

例 2：enum 与 union，从内存看 float ​

en.c：

c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

typedef enum { ST_IDLE, ST_RUN, ST_FAULT = 5, ST_MAINT } State;

const char *state_name(State s) {
    switch (s) {
        case ST_IDLE:  return "待机";
        case ST_RUN:   return "运行";
        case ST_FAULT: return "故障";
        case ST_MAINT: return "保养";
        default:       return "未知";
    }
}

typedef union {
    float    f;
    uint32_t u;
    uint16_t w[2];
} Float32;

int main(void) {
    printf("ST_RUN=%d ST_FAULT=%d ST_MAINT=%d\n", ST_RUN, ST_FAULT, ST_MAINT);
    printf("状态 5 = %s\n", state_name((State)5));

    Float32 v;
    v.f = 25.0f;
    printf("sizeof(Float32) = %zu\n", sizeof(Float32));
    printf("25.0f 的位模式 = 0x%08X\n", (unsigned)v.u);
    printf("在内存里 w[0]=0x%04X w[1]=0x%04X (小端机器)\n", v.w[0], v.w[1]);

    /* 可移植写法: memcpy */
    uint32_t bits = 0x41C80000u;
    float f;
    memcpy(&f, &bits, sizeof f);
    printf("0x41C80000 当作 float = %.1f\n", f);
    return 0;
}

输出：

ST_RUN=1 ST_FAULT=5 ST_MAINT=6
状态 5 = 故障
sizeof(Float32) = 4
25.0f 的位模式 = 0x41C80000
在内存里 w[0]=0x0000 w[1]=0x41C8 (小端机器)
0x41C80000 当作 float = 25.0

怎么手算 25.0 = 0x41C80000：25 = 11001 二进制 = 1.1001 × 2^4。符号位 0；指数 = 4 + 127 = 131 = 10000011；尾数 = 1001 后补 0。拼起来 0 10000011 10010000000000000000000 = 0100 0001 1100 1000 0000... = 0x41C80000。详细规则见 浮点数。

注意 w[0] 是 0x0000 而 w[1] 是 0x41C8：x86 是小端（低字节在低地址），所以低 16 位在数组前面。这提醒你：联合体看到的内容依赖机器字节序，可移植的转换用 memcpy（memcpy 把字节从一处复制到另一处，不受类型别名规则影响）。

例 3：文本文件读写（CSV） ​

file1.c：

c
#include <stdio.h>
#include <string.h>

int main(void) {
    FILE *fp = fopen("temp.csv", "w");
    if (fp == NULL) { perror("fopen"); return 1; }
    fprintf(fp, "time,temp\n");
    fprintf(fp, "08:00,245.5\n");
    fprintf(fp, "08:10,248.0\n");
    fprintf(fp, "08:20,251.5\n");
    fclose(fp);

    fp = fopen("temp.csv", "r");
    if (fp == NULL) { perror("fopen"); return 1; }
    char line[64];
    double sum = 0; int n = 0;
    fgets(line, sizeof line, fp);                    /* 跳过表头 */
    while (fgets(line, sizeof line, fp) != NULL) {
        char t[16]; double v;
        if (sscanf(line, "%15[^,],%lf", t, &v) == 2) {
            printf("读到 %s -> %.1f\n", t, v);
            sum += v; n++;
        }
    }
    fclose(fp);
    printf("共 %d 行, 平均 %.2f\n", n, sum / n);

    FILE *none = fopen("不存在的文件.txt", "r");
    if (none == NULL) puts("打开失败: 返回 NULL, 必须检查");
    return 0;
}

输出：

读到 08:00 -> 245.5
读到 08:10 -> 248.0
读到 08:20 -> 251.5
共 3 行, 平均 248.33
打开失败: 返回 NULL, 必须检查

并且当前目录下生成了 temp.csv，用记事本打开能看到三行数据加表头。(245.5 + 248.0 + 251.5) / 3 = 745 / 3 = 248.33。

解释：sscanf(line, "%15[^,],%lf", ...) 的 %15[^,] 意思是"最多读 15 个字符，直到遇到逗号为止"（15 是为了给结尾 '\0' 留位置，防止越界），%lf 读一个 double；返回值是成功读到的字段数，等于 2 才算成功。

例 4：二进制文件读写 ​

file2.c：

c
#include <stdio.h>
#include <string.h>

typedef struct { char sn[16]; int layers; double thickness; } Board;

int main(void) {
    Board out[2] = {{"A1", 2, 1.0}, {"A2", 4, 1.6}};
    FILE *fp = fopen("boards.bin", "wb");
    if (!fp) return 1;
    size_t w = fwrite(out, sizeof(Board), 2, fp);
    fclose(fp);
    printf("写入 %zu 条, 每条 %zu 字节\n", w, sizeof(Board));

    Board in[2];
    fp = fopen("boards.bin", "rb");
    if (!fp) return 1;
    size_t r = fread(in, sizeof(Board), 2, fp);
    fseek(fp, 0, SEEK_END);
    long size = ftell(fp);
    fclose(fp);
    printf("读回 %zu 条, 文件大小 %ld 字节\n", r, size);
    printf("第 2 条: %s %d 层 %.1f mm\n", in[1].sn, in[1].layers, in[1].thickness);
    return 0;
}

输出：

写入 2 条, 每条 32 字节
读回 2 条, 文件大小 64 字节
第 2 条: A2 4 层 1.6 mm

文件大小 = 2 × 32 = 64，正好是 sizeof(Board) 的倍数，包含了填充字节。这种"把结构体原样倒进文件"写法简单，但有三个限制：换了编译器/平台/字节序，文件就读不了；结构体里不能有指针（地址在下次运行时没有意义）；填充字节里的内容不确定。要跨系统交换数据，用文本格式（CSV/JSON）或明确规定字节序的协议，不要直接存结构体。

例 5：位运算解析 Modbus 状态寄存器 ​

假设一台设备的状态寄存器（一个 16 位保持寄存器，地址与读取方式见 Modbus数据模型与地址）定义为：

位含义
bit0运行
bit1故障
bit2门打开
bit3保留
bit4~7工作模式（0~15）
bit8~15报警码（0~255）

这是为了教学自拟的映射，真实设备以厂商手册为准。从 Modbus 读回的原始值是 0x0B35。bits.c：

c
#include <stdio.h>
#include <stdint.h>
#include <string.h>

/* 设备状态寄存器 (假设的 Modbus 保持寄存器, 16 位):
   bit0 运行  bit1 故障  bit2 门打开  bit3 保留  bit4-7 工作模式  bit8-15 报警码 */
#define BIT_RUN    (1u << 0)
#define BIT_FAULT  (1u << 1)
#define BIT_DOOR   (1u << 2)
#define MODE_SHIFT 4
#define MODE_MASK  (0xFu << MODE_SHIFT)
#define ALARM_SHIFT 8

typedef struct {                 /* 位域: 布局由编译器决定, 只在确认编译器后使用 */
    uint16_t run   : 1;
    uint16_t fault : 1;
    uint16_t door  : 1;
    uint16_t       : 1;
    uint16_t mode  : 4;
    uint16_t alarm : 8;
} StatusBits;

int main(void) {
    uint16_t reg = 0x0B35;       /* 从 Modbus 读回的原始值 */
    printf("原始值 0x%04X = 二进制 ", reg);
    for (int i = 15; i >= 0; i--) putchar((reg >> i) & 1 ? '1' : '0');
    putchar('\n');

    printf("运行=%d 故障=%d 门=%d 模式=%u 报警码=%u\n",
           (reg & BIT_RUN) != 0, (reg & BIT_FAULT) != 0, (reg & BIT_DOOR) != 0,
           (unsigned)((reg & MODE_MASK) >> MODE_SHIFT), (unsigned)(reg >> ALARM_SHIFT));

    StatusBits sb;
    memcpy(&sb, &reg, sizeof sb);
    printf("位域: 运行=%d 故障=%d 门=%d 模式=%d 报警码=%d (sizeof=%zu)\n",
           sb.run, sb.fault, sb.door, sb.mode, sb.alarm, sizeof(StatusBits));

    uint16_t cmd = 0;
    cmd |= BIT_RUN;
    cmd |= (uint16_t)(2u << MODE_SHIFT);
    printf("下发命令字 = 0x%04X\n", cmd);
    cmd &= (uint16_t)~BIT_RUN;
    printf("清运行位后 = 0x%04X\n", cmd);
    cmd ^= BIT_DOOR;
    printf("翻转门位后 = 0x%04X\n", cmd);

    /* 两个 16 位寄存器拼成 32 位浮点 (大端字序: 高字在前) */
    uint16_t hi = 0x41C8, lo = 0x0000;
    uint32_t u = ((uint32_t)hi << 16) | lo;
    float f;
    memcpy(&f, &u, sizeof f);
    printf("寄存器 %04X %04X -> float %.1f\n", hi, lo, f);
    return 0;
}

输出：

原始值 0x0B35 = 二进制 0000101100110101
运行=1 故障=0 门=1 模式=3 报警码=11
位域: 运行=1 故障=0 门=1 模式=3 报警码=11 (sizeof=2)
下发命令字 = 0x0021
清运行位后 = 0x0020
翻转门位后 = 0x0024
寄存器 41C8 0000 -> float 25.0

手工验证（读者应该自己推一遍）：0x0B35 的高字节 0x0B = 0000 1011，低字节 0x35 = 0011 0101。

  • bit0 = 1（运行）、bit1 = 0（无故障）、bit2 = 1（门打开）、bit3 = 0；
  • bit4~7 = 0011 = 3（模式 3）；
  • bit8~15 = 0x0B = 11（报警码 11）。

下发命令：运行位 0x0001，模式 2 左移 4 位得 0x0020，合起来 0x0021；清掉运行位得 0x0020；翻转 bit2（0x0004）得 0x0024。

位域那行和手动掩码结果一致，在 zig cc（clang）/x86 上如此；换成别的编译器或大端 CPU 位的排列可能不同，所以上面用位运算作为"主写法"，位域只做对照。⚠ 其它编译器上位域的结果未在本机验证。

最后一段是协议里常见的另一个问题：32 位浮点数占两个连续的 16 位寄存器。25.0 的位模式是 0x41C80000，高 16 位 0x41C8，低 16 位 0x0000。是"高字在前"（大端字序，Modbus 常见）还是"低字在前"，不同厂商不同，必须看设备手册；弄反了读到的就是离谱的数，这是 Modbus 联调的经典坑（对应 Modbus数据模型与地址）。如果设备是低字在前，把 hi、lo 换一下位置即可。

动手实验 ​

  1. 编译运行例 1~5，输出与文中比对。
  2. 改结构体顺序：在 st1.c 里把 Board 的成员顺序改为 double thickness; int layers; char sn[16];，看 sizeof(Board) 还是 32 吗？（double 8 + int 4 + char[16] 16 = 28，补到 8 的倍数 = 32，所以不变，但道理要想清楚。）
  3. 解析另一个寄存器值：把 bits.c 里 reg 改成 0x2152，手算后再跑，核对：运行=0、故障=1、门=0、模式=5、报警码=33。（0x52 = 0101 0010：bit1=1、bit4~7=0101=5；0x21=33。）
  4. 写一个"设备状态"小程序：定义 typedef struct { char name[16]; State st; double temp; } Device;，创建 3 台设备，用 fprintf 写进 devices.csv，再读回来打印每台设备的名字、状态名（用 state_name）和温度。
  5. 字序练习：假设设备把 50.0 以"低字在前"发来：寄存器依次是 0x0000、0x4248。用 uint32_t v = ((uint32_t)r[1] << 16) | r[0]; 拼接再用 memcpy 转 float，结果应是 50.0。

常见坑与排查 ​

现象原因与办法
fopen 返回 NULL路径不对、没有权限、文件被别的程序占用。相对路径是相对"运行时的当前目录"，不是源文件目录；用 perror 打印原因
文件内容没写进去忘了 fclose（或 fflush），缓冲区没刷出
文本文件 Windows 与 Linux 换行不同（\r\n 与 \n）文本模式会自动转换；二进制模式不转换，读取时要自己处理 \r
二进制文件换电脑读不出来结构体填充、字节序、long 大小不同；用定宽类型并逐字段读写或改文本格式
结构体写入文件有"垃圾字节"填充字节内容不确定；先 memset(&b, 0, sizeof b) 清零再赋值
scanf/sscanf 读字符串越界一定要像 %15[^,] 这样限制宽度
位域值和手册对不上位域排列由编译器决定；对接协议用位运算
读 32 位浮点结果离谱字序（高字低字）弄反；或者误当成两个独立的整数
结构体里有 char * 指针，整体写入文件写入的是地址，下次运行无意义，应写指向的内容

练习题与答案 ​

  1. struct { char a; double b; } 在本机多大？struct { int a; char b; } 呢？ 答：16 和 8。前者 a 后填充 7 字节再放 8 字节 double；后者 4 + 1 + 3 填充。已运行验证。
  2. 要把寄存器 reg 的 bit4~7（模式）设置为 5，并保持其它位不变，怎么写？ 答：先清后设：reg = (reg & ~(0xFu << 4)) | (5u << 4);。例如 reg = 0x0B35 时，清掉模式位后得 0x0B05（已验证），再 | 0x50 得 0x0B55。
  3. 5u << 4 是多少（十六进制）？ 答：0x50（已验证）。
  4. 两个寄存器 0x4248（高字）、0x0000（低字）拼成的浮点是多少？ 答：50.0（已运行验证）。手算：0x42480000 符号 0，指数 0x84 = 132 → 132 − 127 = 5，尾数 0x480000 对应 1.5625，1.5625 × 2^5 = 50。
  5. 为什么二进制文件读写适合"同一台机器、同一程序存取的缓存"，不适合"发给别人"？ 答：结构体布局（填充）、字节序、类型大小因编译器和平台而异，文件里的格式没有标准定义。
  6. fopen("a.txt", "w") 和 "a" 的区别？ 答："w" 打开时清空原内容，"a" 在末尾追加。写日志要用 "a"。

小结 ​

  • struct 打包相关数据，. 访问成员，指针用 ->；赋值是整块复制；成员顺序影响因对齐产生的填充。
  • typedef 起别名，enum 给整数起名，union 让同一块内存有多种解释（可移植的解释用 memcpy）。
  • 文件：fopen 必须检查返回值，用完 fclose；文本格式通用，二进制结构体直写不可移植。
  • 寄存器的开关用位运算（读、置位、清位、翻转），多位字段用"移位+掩码"；位域布局由编译器决定。
  • 32 位浮点占两个寄存器，字序以设备手册为准。
