大语言模型

AI 生成 · 待核对AI大语言模型更新于 2026-10-21

本篇是 AI 入门路径里"开始用大模型"的第一篇。读完你应该能：说清大语言模型本质上在做什么（预测下一个 token）；看懂 token、上下文窗口、温度这几个参数的含义并会估算；知道一个模型是怎么从"只会接龙"变成"会听指令的助手"的；用 60 行 Python 亲手做一个迷你"语言模型"，亲眼看到"预测下一个字"和"温度"；清楚它擅长什么、不擅长什么。

关于版本：模型的名称、版本号、价格、上下文长度更新非常快。本篇不写任何具体型号，只讲不会过期的原理。术语定义对照了 Anthropic 官方术语表（查询日期 2026-10-21，见文末延伸阅读）。

一句话定义 ​

大语言模型（LLM，Large Language Model）是一个用海量文本训练出来的巨大数学函数：输入一段文字，输出"下一个词（token）最可能是什么"的概率分布；把这个过程一遍遍重复，就"写"出了整段文字。

先修知识 ​

  • 神经网络、Transformer：知道模型是由大量可调数字（参数）组成的，训练就是调这些数字。看不懂也没关系，本篇把它当黑盒，只看输入和输出。
  • Python容器类型：实验里用到字典（dict）和计数器（Counter）。
  • 一点点概率常识：概率是 0 到 1 之间的数，所有可能结果的概率加起来等于 1。

它解决什么问题 ​

传统软件靠程序员把规则一条条写死：if 不良描述包含"少锡" then 缺陷代码 = D01。规则写不全，操作员换个说法（"锡不够""焊盘露铜"）程序就懵了。

大语言模型换了一条路：不写规则，让模型从海量文字里学会语言的规律，于是它可以：

  • 读懂五花八门的自然语言（操作员随手写的不良描述、客户邮件、SOP 文档）；
  • 生成文字（总结、改写、翻译、写代码草稿）；
  • 把非结构化的文字变成结构化的数据（提取字段、归一化编码）。

代价是：它给的是"很可能对"的答案，而不是"保证对"的答案。后面的 AI的局限与幻觉 专门讲这一点。

核心概念 ​

1. token：模型眼里的"字" ​

模型不直接读汉字或英文单词，而是先把文字切成一个个小块，叫 token（词元）。Anthropic 术语表的说法：token 可以对应词、子词、字符，甚至字节（Unicode 的情况下）。

  • 英文常常"一个常见单词 = 1 个 token"，生僻词会被拆成几块（具体怎么拆因模型而异）。
  • 中文常常"一个字或一个常用词 = 1 个 token"，具体取决于模型的切分表。
  • 不同模型切法不同，同一段话在不同模型里的 token 数不一样。 官方术语表里就提到，较新的一代模型换了新的切分器，同样的文字会多出约 30% 的 token。要准确数，请用官方提供的 token 计数功能，不要靠猜。

为什么要关心 token？因为计费、速度、长度限制全按 token 算，而不是按字数。

2. 上下文窗口：模型的"工作台" ​

上下文窗口（context window）是模型一次请求里能"看到"的文字总量上限，单位是 token。它像一张工作台：你的提示词、之前的聊天记录、检索来的资料、以及模型自己要写的回答，全都得摆在这张台子上。台子放不下，就得删东西。

模型没有"记忆"：每次请求它都只看到台子上的内容。聊天软件里"它记得我上一句"，其实是软件把历史对话重新塞进了台子。

估算例子（数字是假设的，用来练算术）：假设窗口为 32,000 token。

内容token
系统提示词（规则、角色）500
历史对话6,000
检索来的 5 段资料，每段 8004,000
预留给模型的回答2,000
合计12,500

剩余 32,000 − 12,500 = 19,500 token 还能塞。窗口再大，塞得越满越贵越慢，而且资料太多反而会干扰模型（这叫"大海捞针"问题），所以 RAG 的思路是"只塞最相关的几段"。

3. 预测下一个 token：本质只有这一件事 ​

给模型一句话"工单下达后产线开始"，它输出的不是一个答案，而是一张概率表：

候选 token概率
上0.40
贴0.40
量0.20

然后从表里挑一个（挑法见下一节），接到后面，再预测下一个，直到模型输出"结束"标记。整段回答就是这样一个字一个字"接龙"出来的。

这个视角能解释很多现象：为什么它写得流畅（接龙练得多）、为什么它会一本正经地胡说（接龙只管"像不像"，不管"对不对"）、为什么同一个问题两次回答不一样（挑的时候有随机性）。

4. 采样参数：温度、top-p ​

怎么从概率表里挑？

  • 贪心（greedy）：永远挑概率最大的。稳定，但死板、容易重复。
  • 随机采样：按概率抽签。概率 0.4 的字被抽中的机会就是 40%。
  • 温度（temperature）：调节"抽签前先把概率表拉平还是拉尖"。官方术语表的说法：高温度输出更有创造性、更多样；低温度更保守、更确定。
    • 温度低（如 0.2）：大概率的字更占优，输出稳定；
    • 温度高（如 1.5）：各候选概率接近，输出发散，也更容易出错；
    • 温度趋近 0：基本等于贪心。
  • top-p（核采样）：只在"概率累加到 p 的那几个最可能的字"里抽签，把离谱的长尾直接丢掉。
  • 注意：官方术语表特别提醒，即使温度设为 0，API 返回也不保证每次完全相同。所以不要把"结果可复现"当作模型的性质，需要稳定时要靠校验和人工复核。

数学上，温度怎么起作用？模型先给每个候选一个分数（logit），概率 = softmax(分数 / T)。温度 T 越小，分数差被放大，大的更大。下面实验里用等价的简化版：把"出现次数 n"的 1/T 次方当权重。

手算验证：候选 上、贴、量 的次数是 2、2、1。T = 0.5 时权重为 2²=4、4、1²=1，总和 9，概率 0.444、0.444、0.111；T = 2 时权重为 √2≈1.414、1.414、1，总和 3.828，概率 0.369、0.369、0.261。后面实验的输出与此完全一致。

5. 三阶段训练：从"接龙机"到"助手" ​

  1. 预训练（pretraining）：在海量文本上学"预测下一个 token"。学完得到的模型什么都懂一点，但不会听指令——你问"首件检验是什么？"它可能接着写"……的流程包括哪几步？"（把你的问题当成文章开头继续写）。术语表也说，预训练模型本身不擅长回答问题或遵循指令。
  2. 指令微调（instruction tuning，属于 fine-tuning 微调）：用人工编写的"问题-好回答"对照数据继续训练，模型学会"看到问题就给回答"。
  3. RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）：让模型对同一个问题写出几个回答，人类给它们排序，再用强化学习让模型更倾向于高排名的那类回答，使它更有用、更安全。人类反馈的形式就是对两个或多个样本文本排序。论文见延伸阅读。

类比：预训练是"读完整座图书馆"，指令微调是"岗前培训，学会按工单格式回答"，RLHF 是"主管打分反馈，越来越懂规矩"。

之后工厂想让模型更懂自己的领域，常见两条路：往提示词里塞资料（RAG），或做针对性训练（微调与量化）。

6. 能力边界 ​

擅长：

  • 语言类任务：总结、改写、翻译、分类、抽取字段；
  • 写代码草稿、解释报错、写测试；
  • 按提供的资料回答问题（配合 RAG）。

不擅长或危险：

  • 精确计算与精确记忆：大数乘法、"某标准第几条原文"，它可能给出看起来对的错误答案；
  • 不知道训练之后发生的事，也不知道你们公司内部的事（除非你把资料放进上下文）；
  • 会编造（AI的局限与幻觉）；
  • 不保证每次一样。

经验法则：让它做"理解和起草"，让程序和人做"计算和拍板"。

逐步例子：手工推一遍"预测下一个字" ​

我们用 7 句工厂语料训练一个只看"前 2 个字"的迷你模型。数一数 开始 后面接什么字：

语料句子开始 后面的字
工单下达后产线开始上料上
产线开始上料后设备开始贴片上、贴（一句里出现两次）
设备开始贴片后需要首件检验贴
首件检验合格后开始量产量

数完得到：上 2 次、贴 2 次、量 1 次，共 5 次，所以 P(上)=2/5=0.4，P(贴)=0.4，P(量)=0.2。这就是上一节那张概率表。真正的 LLM 做的事情完全一样，只是"前 2 个字"换成"前几万个 token"，"数一数"换成"一个有几百亿参数的神经网络来估计"。

动手实验：60 行代码的迷你语言模型 ​

环境：Python 3.12，标准库即可。保存为 mini_lm.py，运行 python -I -X utf8 mini_lm.py。

python
import random, math
from collections import Counter, defaultdict

corpus = [
    "工单下达后产线开始上料",
    "工单下达后系统生成条码",
    "产线开始上料后设备开始贴片",
    "设备开始贴片后需要首件检验",
    "首件检验合格后开始量产",
    "首件检验不合格需要调机",
    "量产完成后工单报工入库",
]

N = 2  # 看前 2 个字，预测下一个字
table = defaultdict(Counter)
for sent in corpus:  # 句首补 ^^ 当开头占位，句末补换行符当结束符
    padded = "^" * N + sent + "\n"
    for i in range(N, len(padded)):
        table[padded[i-N:i]][padded[i]] += 1

def show(ctx):
    c = table[ctx]; tot = sum(c.values())
    print(repr(ctx), "->", {k.replace("\n", "\\n"): f"{v}/{tot}" for k, v in c.most_common()})

show("首件"); show("开始"); show("^^")

def probs(ctx, T):
    c = table[ctx]
    w = {ch: math.exp(math.log(n) / T) for ch, n in c.items()}   # n 的 1/T 次方
    s = sum(w.values())
    return {ch: v / s for ch, v in w.items()}

print("--- 温度对 '开始' 之后概率分布的影响 ---")
for T in (0.5, 1.0, 2.0):
    p = probs("开始", T)
    print(T, {k: round(v, 3) for k, v in p.items()})

def generate(T, seed, greedy=False, maxlen=30):
    rnd = random.Random(seed)
    ctx, out = "^" * N, ""
    while len(out) < maxlen:
        c = table[ctx]
        if greedy:
            ch = c.most_common(1)[0][0]
        else:
            p = probs(ctx, T)
            ch = rnd.choices(list(p), weights=list(p.values()))[0]
        if ch == "\n":
            break
        out += ch
        ctx = ctx[1:] + ch
    return out

print("--- 贪心（总选概率最大） ---")
print(generate(1, 0, greedy=True))
for T in (0.3, 1.0, 3.0):
    print(f"--- T={T} ---")
    for s in range(5):
        print(generate(T, s))

实际运行输出（Python 3.12）：

'首件' -> {'检': '3/3'}
'开始' -> {'上': '2/5', '贴': '2/5', '量': '1/5'}
'^^' -> {'工': '2/7', '首': '2/7', '产': '1/7', '设': '1/7', '量': '1/7'}

你能从输出里读到什么：

  1. '^^' 那行：句子开头，模型有 5 种选择，工、首各 2/7。这就是"开头怎么起"的概率表。
  2. 温度的作用：T 小，概率向大的靠（0.5 时 量 被压到 0.111）；T 大，各选项更接近（2.0 时 量 升到 0.261）。
  3. "流畅但不对"：首件检验合格需要首件检验 语法顺口，内容却是车轱辘话；首件检验不合格后开始贴片 更危险，语料里从没有这句话，是模型"拼"出来的，而且它违反了业务逻辑（不合格应该调机）。这就是幻觉的最小模型：它只学了"哪个字常跟在哪两个字后面"，没有"知道"首件检验的含义。真正的大模型看的上下文长得多、学得精细得多，幻觉少得多，但原理上没有消失。
  4. 同一个种子保证可复现：这是我们用 random.Random(seed) 固定的；真实的模型服务通常不给你固定到位（见上面温度的说明）。

想一想：怎么让它更"聪明"？ ​

把 N = 2 改成 N = 3 再跑（T=1.0），5 次生成全是语料里的原句：首件检验合格后开始量产、工单下达后产线开始上料、量产完成后工单报工入库……看得越长，越像"背书"。改成 N = 1，就出现 工入库、工单下达后设备开始上料 这种语料里没有的拼凑句：看得越短，越会胡拼。大模型本质上也在"泛化能力"和"死记硬背"之间取平衡。

常见坑与排查 ​

现象原因对策
回答被截断输出 + 输入超过了上下文窗口，或超过了"最大输出 token"设置缩短输入；调大输出上限；分段处理
同一问题两次答案不同采样有随机性，且服务端实现也未必逐字稳定要稳定就降温度 + 校验输出格式，不依赖"逐字一致"
中文比预期更费 token切分器对中文的效率因模型而异用官方 token 计数先量一量，再估成本
它不知道最新的事或公司内部的事训练数据有截止时间，且不含你的私有数据用 RAG 把资料放进上下文
越往后越"忘"上下文太长，早期内容被挤掉或被淡化精简历史，把关键信息放在提示词的开头或结尾
把模型当计算器它是接龙，不是算术单元计算交给代码，让模型只负责生成调用代码或理解需求
看到"某某模型最新最强"就换型号、价格、能力变化极快，榜单也不等于你的场景用自己的 20～50 条真实样本做评测后再选（见 RAG 里的评估）

练习题与答案 ​

1. 语料里 首件 后面只出现过 检。T 取任意值时，probs("首件", T) 的结果是什么？

答案：{'检': 1.0}。只有一个候选，概率必为 1，温度改变不了。这说明温度只在"有多个合理候选"时起作用。

2. 候选字的次数是 3、1，温度 T=1 时概率是多少？T=0.5 时呢？

答案：T=1：3/4=0.75、0.25。T=0.5：权重 3²=9、1²=1，总和 10，概率 0.9、0.1。温度调低，大概率的更占优。

3. 窗口 8,000 token，系统提示 300，要求预留回答 1,000，检索来的每段资料 600 token，最多能放几段？

答案：8000 − 300 − 1000 = 6700，6700 ÷ 600 = 11.17，最多 11 段（还没算历史对话）。

4. 为什么不能把"模型说它不确定"当成可靠的置信度？

答案：模型是在"预测像不像人话"，它输出"我不确定"也只是接龙的一种结果；它说"我很确定"时也可能错。可靠的做法是外部校验（对照资料、跑程序、人工复核）。

5.（动手） 在实验里加一句语料 首件检验不合格后重新首件检验，重新运行，看 首件检验不合格 之后的生成有什么变化，并解释。

答案（已实际运行）：首件 之后仍是 检（5/5）；句首概率变为 首 3/8、工 2/8、产 1/8、设 1/8、量 1/8，也就是 首件检验…… 开头的句子更多了；合格 之后 后 2/3、需 1/3；格后 之后 开 1/2、重 1/2，所以生成里会出现"……不合格后重新首件检验"这种新组合。多喂一句话，整张概率表都被改写，这就是"训练数据决定模型行为"的最小例子。

小结 ​

  • LLM 的本质：根据已有 token 预测下一个 token，循环往复。
  • token 是计费和长度的单位；上下文窗口是一次请求的工作台，输入输出共用。
  • 温度越高越随机；设 0 也不保证每次一样。
  • 预训练 → 指令微调 → RLHF，才有了"会听话的助手"。
  • 擅长语言理解和起草，不擅长精确计算、不知道私有信息，并且会编造。
