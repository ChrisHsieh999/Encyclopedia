工业以太网

AI 生成 · 待核对工业通信网络更新于 2026-10-21

⚠ 待核对：下面对比表里各协议的"周期/抖动"数字来自维基百科，且 EtherCAT 页面自身标注"需要更多引用"；环网冗余的恢复时间（RSTP、MRP、DLR、PRP/HSR）我只写数量级，来自模型知识，未联网核实；没有工业交换机或实时以太网设备可在本机验证。本机实际运行的只有两个小脚本：回环 UDP 往返抖动测量和环网断链模拟。

本篇属于 工业通信 系列。读完你应该能：解释为什么普通以太网不能直接当实时总线；说出 Profinet、EtherNet/IP、EtherCAT、Modbus TCP、POWERLINK 各自的实时思路；理解环网为什么能容错；画出工厂网络的分区。

一句话定义 ​

工业以太网是指用于工业现场的以太网技术及其协议族：物理上基本沿用 IEEE 802.3 以太网，但在可靠性（宽温、抗振、冗余）和**确定性（实时性）**上做了增强，让控制数据可以在固定的时间内送达。

先修知识 ​

  • 以太网与交换机：MAC 地址、交换机转发、全双工、VLAN。必读。
  • TCP-IP、TCP与UDP：理解 TCP 的重传为什么影响实时性。
  • 对前面的协议有印象：Modbus-TCP、Profinet、EtherNet-IP。

它解决什么问题 ​

办公室里以太网丢一两个包、慢 50 ms，没人在乎。但控制一台伺服电机，每 1 ms 要更新一次位置，如果某一次数据晚了 20 ms，机械可能撞坏。普通以太网的问题：

  1. 不确定：经过交换机时可能排队，TCP 可能重传，操作系统调度会产生抖动。我在本机做的测量很直观（见下）。
  2. 帧太大太浪费：以太网最小帧 64 字节，而工业数据常常只有几个字节（维基百科也提到这点）。
  3. 环境恶劣：车间的温度、振动、电磁干扰、灰尘，办公室的交换机撑不住。
  4. 可靠性要求高：一根线断了不能让整条产线停。

核心概念 ​

先看一眼"不确定"有多大 ​

在同一台电脑上，用 UDP 对 127.0.0.1 的回显服务器做 2000 次往返，每次间隔 1 ms，测往返时间。这是没有任何网络设备的最理想情形，结果如下（两次运行，数值有出入）：

2000 次回环往返(微秒): 中位数 90  99% 分位 334  最大 404
最大值 / 中位数 = 4.5 倍
2000 次回环往返(微秒): 中位数 92  99% 分位 332  最大 500
最大值 / 中位数 = 5.4 倍

中位数 90 µs，但最慢的几次是它的 4~5 倍。这仅仅来自 Windows 的调度，没有交换机、没有拥塞。真实网络加上排队，抖动更大。实时控制关心的不是"平均多快"，而是"最坏多慢"。

脚本 udp_jitter.py（本机实际运行）：

python
import socket, statistics, threading, time

srv = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
srv.bind(("127.0.0.1", 0)); port = srv.getsockname()[1]
stop = False

def echo():
    srv.settimeout(0.2)
    while not stop:
        try:
            d, a = srv.recvfrom(64); srv.sendto(d, a)
        except socket.timeout:
            pass

threading.Thread(target=echo, daemon=True).start()
cli = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
cli.connect(("127.0.0.1", port)); cli.settimeout(1)
rtt = []
for i in range(2000):
    t0 = time.perf_counter()
    cli.send(b"x" * 32); cli.recv(64)
    rtt.append((time.perf_counter() - t0) * 1e6)
    time.sleep(0.001)
stop = True
rtt.sort()
print(f"2000 次回环往返(微秒): 中位数 {statistics.median(rtt):.0f}  99% 分位 {rtt[int(len(rtt)*0.99)]:.0f}  最大 {rtt[-1]:.0f}")
print("最大值 / 中位数 =", round(rtt[-1] / statistics.median(rtt), 1), "倍")

实时以太网家族对比 ​

各家的做法不同，大体分三派：

  1. 走标准 TCP/IP，靠优先级和高速度（EtherNet/IP、Modbus TCP）：兼容性最好，实时性一般；
  2. 绕开 TCP/IP，直接用二层帧 + 优先级/时间窗口（Profinet RT/IRT）；
  3. 改变通信机制（EtherCAT 的"飞速处理"、POWERLINK 的"轮询调度"）：实时性最强，需要专用硬件或特殊拓扑。
协议维护/代表实时思路典型周期（据维基百科）传输层备注
ProfinetPI，西门子RT：VLAN 优先级；IRT：时间同步+带宽预留RT 约 1~10 ms；IRT 可到 31.25 µs实时帧直接放在以太网二层（EtherType 0x8892），不含 IP设备按名称识别；见 Profinet
EtherNet/IPODVA，罗克韦尔标准 TCP/UDP，隐式 I/O 用 UDP 组播；周期由 RPI 约定常见几毫秒到几十毫秒（⚠ 模型知识）TCP 44818 / UDP 2222名字的 IP 是 Industrial Protocol；见 EtherNet-IP
EtherCATETG，倍福（Beckhoff）主站发一帧，帧在经过每个从站时被即时读写（"processing on the fly"），不需要每站接收再转发目标 100 µs 或更短，抖动 1 µs 以内；常见 1~30 kHzEtherType 0x88A4，直接放在以太网帧拓扑灵活（线、树、环、星），单段最多 65535 个节点；收发走硬件
Modbus TCPModbus 组织无实时机制，TCP 请求/响应取决于网络，没有保证TCP 502简单、通用；见 Modbus-TCP
POWERLINKB&R 发起，现由 B&R 维护开放协议时隙轮询：管理节点（MN）依次叫受控节点（CN）发数据，同一时刻只有一个节点发，避免冲突可低于 200 µs，抖动小于 1 µs实时域建议用集线器而非交换机原 EPSG 组织已于 2023 年解散（据维基百科）

读表要点：

  • 选型的第一约束往往是生态：用西门子 PLC 就用 Profinet，用罗克韦尔就用 EtherNet/IP，用倍福或大量伺服轴就用 EtherCAT。
  • 同一个车间可能有多种协议，它们之间不能直接通，靠 PLC 作为网关，或者用 OPC-UA 在上层统一。
  • Modbus TCP 不是严格意义的实时以太网，但工业里应用极广，因为够简单。

交换机：工业级与办公级 ​

项目办公交换机工业交换机
温度0~40 ℃常见 -40~75 ℃（⚠ 型号差异大，以手册为准）
供电交流24 V 直流，冗余双电源
安装机架/桌面DIN 导轨
功能通常较少网管（VLAN、端口镜像、IGMP Snooping、QoS）、环网冗余、报警继电器

非管理型交换机即插即用但不能配置；管理型可以划 VLAN、限速、镜像抓包、开启环网协议。产线核心网络强烈建议用管理型。

IGMP Snooping：组播流量（EtherNet/IP 隐式 I/O、PROFINET 部分功能）默认会被交换机当广播发到所有口；开启后交换机只发给订阅了的端口。

环网与冗余 ​

线型网络中，任何一处断开，下游全部失联。环形把末端接回起点，断一处时数据可以从另一边绕过去。但以太网不允许二层环路（会产生广播风暴），所以需要协议在环里"人为断开一处"作为备用链路，故障时再启用：

协议适用恢复时间（数量级，⚠ 模型知识，以手册为准）
RSTP（快速生成树，IEEE 802.1w）通用，各厂交换机基本都支持毫秒到秒级，拓扑越大越慢
MRP（Media Redundancy Protocol）Profinet 环网（EtherType 0x88E3，据 HMS 文档）百毫秒级
DLR（Device Level Ring）EtherNet/IP 设备环网几十毫秒级
PRP / HSR（IEC 62439-3，维基百科仅列为相关条目）无缝冗余：同一份数据走两条网络，收到先到者零切换时间

我用一个小脚本验证"线型断一处会失联，环型断任何一处都不会"（ring_sim.py，本机实际运行；用图的广度优先搜索判断从 PLC 能到达哪些设备）：

python
from collections import deque


def reachable(nodes, links, start):
    adj = {n: [] for n in nodes}
    for a, b in links:
        adj[a].append(b); adj[b].append(a)
    seen, q = {start}, deque([start])
    while q:
        for m in adj[q.popleft()]:
            if m not in seen:
                seen.add(m); q.append(m)
    return seen


nodes = ["PLC", "S1", "S2", "S3", "S4"]                       # 一个 PLC + 四台设备串成环
ring = [("PLC", "S1"), ("S1", "S2"), ("S2", "S3"), ("S3", "S4"), ("S4", "PLC")]
line = ring[:-1]                                              # 没有闭环，只是线型

for name, links in (("线型", line), ("环型", ring)):
    for broken in links[:]:
        left = [l for l in links if l != broken]
        lost = set(nodes) - reachable(nodes, left, "PLC")
        print(f"{name}  断开 {broken[0]}-{broken[1]} -> PLC 联系不上: {sorted(lost) or '无'}")

实际输出：

线型  断开 PLC-S1 -> PLC 联系不上: ['S1', 'S2', 'S3', 'S4']
线型  断开 S1-S2 -> PLC 联系不上: ['S2', 'S3', 'S4']
线型  断开 S2-S3 -> PLC 联系不上: ['S3', 'S4']
线型  断开 S3-S4 -> PLC 联系不上: ['S4']
环型  断开 PLC-S1 -> PLC 联系不上: 无
环型  断开 S1-S2 -> PLC 联系不上: 无
环型  断开 S2-S3 -> PLC 联系不上: 无
环型  断开 S3-S4 -> PLC 联系不上: 无
环型  断开 S4-PLC -> PLC 联系不上: 无

注意：这个模拟只证明"环有两条路径"；真实环网里，交换机还要靠上表的协议防止广播风暴并在故障时重新选路，这部分没有模拟。

工厂网络分区 ​

把整个工厂网络按功能和风险分成区（Zone），区与区之间用路由器/防火墙连接，只放行必要的流量。典型分层（与 ISA-95 层级、工业网络安全 的 Purdue 模型对应）：

办公/企业网（ERP、邮件）          ← 办公 IT
   │  防火墙
DMZ / 工厂数据区（MES、数据库、历史库）
   │  防火墙
车间控制网（SCADA、HMI、工程师站）
   │
设备/控制层网络（PLC ↔ I/O ↔ 驱动，Profinet/EtherNet-IP/EtherCAT 实时通信）

分区原则：

  • 实时控制网络单独成区，不要接办公电脑、不要接 Wi-Fi；
  • 每台设备的网口、交换机、IP 段要有登记表；
  • MES 要读 PLC 数据，由 MES 所在的区向下"单向"访问到控制区某个网关，而不是把 PLC 放到办公网。

逐步例子：为一条 SMT 线设计网络 ​

条件：8 台设备（贴片机 x3、印刷机、回流焊、AOI x2、炉后检查），每台设备有两个网口：设备网（控制）和信息网（MES）。

  1. 信息网（MES、设备数据采集）：8 台设备的信息口接到车间交换机，划 VLAN 20，网段 10.20.1.0/24（见 IP地址与子网）。MES 服务器在 DMZ，通过防火墙访问；
  2. 设备网（各设备内部的 PLC、伺服）：不接出设备，设备内部自己的小网络，不和其它设备混；
  3. 时间同步：给所有设备配同一个 NTP 服务器，保证 MES 收到的时间戳可比；
  4. 冗余：线体主交换机用 RSTP 环网连到车间核心交换机（线体断一根线不整体掉线）；
  5. 登记：写一张 IP/MAC/端口/责任人的表。

这个设计中，实时协议只在设备内部，线体级别只有"MES 采集"这类对延迟不敏感的流量，所以普通的管理型工业交换机就够。

常见坑与排查 ​

现象最可能的原因
整个网络突然慢、所有设备掉线广播风暴：线缆接成了环但没开 RSTP/MRP；或设备 IP 冲突
组播数据到处都有，网络带宽异常高没开 IGMP Snooping
换了交换机后实时通信抖动新交换机不支持优先级/QoS，或存储转发延迟更大
设备网与办公网互通后出现奇怪故障办公网的广播/扫描/病毒影响设备；应隔离
周期性断线，几十秒一次交换机 MAC 表老化时间、生成树重算；检查是否有人在接新设备
网口协商成 10M 半双工自动协商失败，强制设置速率与双工；半双工在实时网络中会有冲突
看不到设备不同 VLAN；ARP 表；IP 冲突；设备在二层协议（Profinet/EtherCAT）不能路由

业务视角与技术视角 ​

  • 业务视角：网络是"看不见的基础设施"，出问题时往往表现为"某台设备总掉线"。工厂要有网络拓扑图、IP 规划表、交换机配置备份和变更记录，否则每次故障都靠人经验。对停线成本高的产线，环网冗余和备件交换机是低成本的保险。
  • 技术视角：写 MES 采集服务时，要把"网络不稳定"当作常态：重连、超时、断线缓存、时间戳统一（见 设备数据采集、设备联网方案）。采集用 Modbus-TCP 或 OPC-UA 这些走 TCP 的协议时，不要期待毫秒级确定性。

练习题与答案 ​

  1. 为什么说"平均延迟很低"不足以说明一个网络适合实时控制？ 答：实时控制关心最坏延迟（抖动）。平均 90 µs 但偶尔 500 µs 的网络，如果周期要求 250 µs，就会超时。
  2. EtherCAT 为什么能比"先接收再转发"的协议更快？ 答：主站的一帧在经过各从站时，从站硬件就地读取属于自己的数据并插入输入数据，不用整帧接收后再处理，延迟只有硬件传输时间。
  3. 线型 5 个设备，断开第 2 与第 3 台之间的线，会有几台设备失联？改成环型呢？ 答：线型下游失联（脚本里是 S3、S4，共 2 台）；环型一台都不失联。
  4. 为什么以太网不能直接把线缆接成环？ 答：二层广播帧会在环里无限循环，形成广播风暴；需要 RSTP/MRP 等协议在环里选择一个端口阻塞。
  5. Profinet 与 EtherNet/IP 的设备能否直接连在同一交换机上互相通信？ 答：物理上可以同在一个网络里共存，但两种协议不互通，需要 PLC 网关或 OPC UA 之类中间层。

小结 ​

  • 工业以太网 = 以太网 + 确定性 + 工业级可靠性；关键指标是最坏延迟，而不是平均值。
  • 五个常见协议的实时思路：优先级与时间窗口（Profinet）、标准 TCP/UDP + 组播（EtherNet/IP）、帧飞速处理（EtherCAT）、无实时机制（Modbus TCP）、时隙轮询（POWERLINK）。
  • 管理型工业交换机 + VLAN + IGMP Snooping + 环网协议是常见配置。
  • 环网靠协议防广播风暴并提供备用路径；分区隔离是网络安全与稳定的前提。
