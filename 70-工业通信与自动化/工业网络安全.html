工业网络安全

AI 生成 · 待核对工业通信网络安全更新于 2026-10-21

⚠ 待核对：IEC 62443 各部分的编号与安全等级描述来自维基百科；"七项基础要求（FR）"的名称来自搜索摘要（PLCnext 文档等二手资料），未购买/阅读标准正文；Purdue 模型各层的叫法在不同资料里略有差异，本篇采用常见版本。IEC 62443 是付费标准，以官方文本为准。

本篇只做防御性说明：讲"为什么危险、怎么防"，不提供任何攻击步骤。实验只在本机 127.0.0.1 上运行。

本篇属于 工业通信 系列。读完你应该能：解释为什么 Modbus 等工业协议天然不安全；画出 Purdue 分层与区域划分；说出纵深防御的几道防线；知道 IEC 62443 是什么、怎么读；为 U 盘和远程运维制定可执行的管理规则。

一句话定义 ​

工业网络安全（OT 安全，Operational Technology security）是保护 PLC、SCADA、MES 采集、设备网络等生产控制系统免受误操作、恶意软件和入侵的一整套技术与管理措施。与办公室 IT 安全相比，它首要保的是生产不停、人员安全、产品质量，而不是数据保密。

先修知识 ​

  • Modbus-TCP：理解"没有认证、没有加密"的含义。
  • 以太网与交换机、IP地址与子网、TCP-IP：分区、VLAN、防火墙的基础。
  • 工业以太网：工厂网络大体长什么样。
  • 听说过 ISA-95 的层级模型会有帮助。

它解决什么问题 ​

早年的工业控制系统是封闭的孤岛：串口线、专用网络、厂商私有协议，"没人能接进来"，也就没人考虑安全。这几十年来，生产数据被拉到 MES、ERP 甚至云端，工业协议被搬上了以太网，原来的前提就失效了：

  1. 协议没有安全机制：原始 Modbus 没有认证和加密（见 Modbus-TCP），谁连上 502 端口谁就能读写。这不是 bug，是 1979 年设计时的前提——线只在柜子里。
  2. 设备寿命长、很少更新：PLC 和设备用 15~25 年；上位机装着停止维护的老 Windows，打补丁可能要停线、要厂家认证。
  3. 可用性第一：办公室电脑被入侵可以"断网重装"；产线的 PLC 被打断可能导致产品报废、设备损坏，甚至人员伤害。
  4. IT 和 OT 的边界模糊：MES 连着 ERP、办公网、供应商远程维护，攻击面成倍增加。

核心概念 ​

IT 与 OT 的优先级不同 ​

IT（办公）OT（生产）
第一优先机密性可用性与安全性（人和设备）
补丁月度自动更新需要停机窗口、厂家兼容性验证
重启可接受往往不可接受
寿命3~5 年15~25 年
典型协议HTTPS、SSHModbus、S7、EtherNet/IP，多无认证

所以不能把 IT 的方案原样搬进车间：例如在 PLC 网络上对设备做激进的端口扫描，就可能让脆弱的设备死机。在生产网络做任何安全检测前，先在测试环境验证并获得许可。

Purdue 模型：给网络分层 ​

Purdue 模型最早（20 世纪 90 年代，普渡大学）是一个制造业集成的参考架构，不是专为安全设计的；后来被 ICS 安全行业借来当分层与分区的参考。常见版本把系统分成 0~5 层，中间加一个"3.5 层 DMZ"：

要点（据 Palo Alto Networks、SentinelOne 等资料）：Level 0~3 属于 OT 一侧，Level 4~5 属于 IT 一侧，在 3 与 4 之间放防火墙，中间设 DMZ，让 IT 和 OT 两侧不直接通话——各自只和 DMZ 里的中转服务通信。DMZ 里典型放：数据代理、历史库副本、远程访问入口（跳板机）、补丁/杀毒更新服务器。

这个模型的局限：它假设层次分明、数据单向向上；而现代工厂有云、无线、IIoT 设备，层次变模糊，DMZ 也可能成为单点瓶颈（Trout 等文章的批评）。所以它是起点，不是全部。

纵深防御（Defense in Depth） ​

像城堡有护城河、城墙、城门、内城一样，不依赖任何单一防线：

层措施例子
管理制度、培训、资产清单、变更审批U 盘登记、远程维护审批
物理机柜上锁、网口封堵、门禁交换机空闲端口禁用
网络分区、VLAN、防火墙默认拒绝、单向网关办公网不能直接访问 PLC
主机最小权限账号、白名单软件、补丁、杀毒工程师站只装必要软件
应用/设备改默认密码、关闭不用的服务、固件管理关闭 PLC 上不用的 Web 服务
数据与协议加密认证（OPC UA 安全模式、MQTT over TLS）见 OPC-UA、MQTT
监控与响应日志、异常流量监测、备份与恢复演练PLC 程序备份、离线保存

IEC 62443：工业安全标准族 ​

IEC 62443（对应美国的 ANSI/ISA-62443，最早由 ISA99 委员会制定；据维基百科）是工业自动化与控制系统（IACS）安全的国际标准系列，面向三类角色：

  • 资产所有者（工厂业主）：建立安全管理体系（如 2-1 部分）；
  • 系统集成商/服务商：按要求设计、集成、维护（2-4 部分）；
  • 产品供应商（设备厂）：安全开发生命周期（4-1），组件技术要求（4-2）。

系列分成通用、策略与流程、系统、组件四大块（据维基百科还有"配置文件""评估"）。常提到的几份：

部分内容
1-1概念与模型
2-1资产所有者的安全计划要求
2-3补丁管理
2-4集成商/服务提供商要求
3-2安全风险评估与系统设计
3-3系统安全要求与安全等级
4-1产品安全开发生命周期
4-2组件技术要求

区域与管道（Zones and Conduits）：把资产按安全要求相同分成区域（Zone）；区域之间的通信路径叫管道（Conduit），在管道上放防火墙等控制措施。这就是上面 Purdue 分层的"标准化版本"。

安全等级（SL，Security Level）：

SL抵御的对象（据维基百科）
SL 1偶然或无意的误用
SL 2有意误用，手段简单、资源少、动机低
SL 3有意误用，手段复杂、资源中等、有自动化系统专业知识
SL 4有意误用，手段复杂、资源丰富、有专业知识、动机强

等级是针对每一条技术要求单独评定的，不是给整个产品贴一个标签。

七项基础要求（FR1~FR7）（据 PLCnext 文档等二手资料，标准正文未核对）：识别与鉴别控制（IAC）、使用控制（UC）、系统完整性（SI）、数据保密性（DC）、受限数据流（RDF）、对事件的及时响应（TRE）、资源可用性（RA）。

对 MES/信息化人员来说，不需要精通 62443，但要能读懂供应商的"我们符合 62443-4-1/4-2"之类声明，并在采购时把它写进要求。

常见攻击面（防守视角） ​

只列"哪里容易出问题"，对应的防守措施在后面一起给：

攻击面为什么容易出问题防守要点
扁平网络办公、MES、PLC 在同一网段，一台电脑中毒全网受影响分区、VLAN、默认拒绝
暴露在互联网的设备/端口工业协议（502、44818、102 等）无认证，出现在公网很危险禁止映射到公网，远程访问走 VPN/跳板机
远程运维通道厂家为了方便留下常开的远程入口、共享账号按需开通、审批、双因素、会话录像
U 盘与移动介质隔离网络里最常见的恶意代码入口登记、专用 U 盘、查杀站（见下）
工程师笔记本既连办公网又连设备网，成为"摆渡"专用笔记本、白名单、不上外网
默认口令/弱口令设备出厂账号长期不改改密码、账号分级、集中管理
老旧未补丁系统停止维护的 Windows、无法升级的设备网络隔离、虚拟补丁（防火墙/IPS）、限制用途
无线网络车间 Wi-Fi 与控制网共用独立 SSID/VLAN，企业级认证，不与控制网互通
供应链设备固件、第三方软件的漏洞采购时要求安全声明（62443-4-1），固件来源校验
缺少备份与监控出事不知道，也恢复不了程序/配置备份，日志集中，异常告警

U 盘与远程运维的管理（可直接落地） ​

U 盘/移动介质

  1. 车间的 U 盘分"专用、登记、编号"，不得混用个人 U 盘；
  2. 进入控制网前先在**独立的查杀终端（隔离的"摆渡"电脑）**上扫描，且该终端的病毒库定期更新；
  3. 设备主机上禁用不需要的 USB 存储（组策略/BIOS 层面），只给指定端口开放；
  4. 能不用就不用：优先用服务器的受控文件传输通道；
  5. 记录谁在何时拷贝了什么，纳入审计。

远程运维

  1. 默认关闭，有需要时申请开通，设定开始和结束时间；
  2. 走公司 VPN + 跳板机（Level 3.5 DMZ），不允许厂家直接连到 PLC；
  3. 个人账号 + 双因素认证，不共用账号；
  4. 会话录像或日志留存，操作后复核；
  5. 结束后关闭通道、改动更新记录；
  6. 需要改 PLC 程序时，先备份、再改、改后对比，变更走审批。

逐步例子：画一张"允许清单" ​

目标：某 SMT 工厂，MES 服务器在 DMZ，要读车间 PLC（OPC UA 4840），SCADA 读设备（Modbus TCP 502），员工从办公网访问 MES 网页（443）。

  1. 列出区域：办公网、DMZ、车间控制网、设备网；
  2. 只登记必须的流量，每条写明用途和负责人：
    • 办公网 -> DMZ，443，员工访问 MES 网页；
    • DMZ -> 车间控制网，4840，MES 采集服务读 OPC UA；
    • 车间控制网 -> 设备网，502，SCADA 读 PLC；
  3. 其余一律默认拒绝；
  4. 把这张表交给网络管理员落实到防火墙，每季度复核，设备改动先改表。

动手实验 ​

只在本机进行，不连接任何外部设备。脚本 sec_lab.py（本机实际运行）做两件事：①把上面的"允许清单"写成代码，验证默认拒绝；②只检查本机 127.0.0.1上哪些工业/高风险端口在监听，作为"端口自查"的最小示例。

python
import socket

# ---------- 1. 区域与管道：默认拒绝，只放行登记过的流量 ----------
# 区域对应 Purdue 层次：办公网 L4-5，DMZ L3.5，车间控制网 L2-3，设备网 L0-1
ALLOW = {                                                         # (源区, 目的区, 端口) -> 用途
    ("办公网", "DMZ", 443): "员工访问 MES 网页",
    ("DMZ", "车间控制网", 4840): "MES 采集服务读 OPC UA",
    ("车间控制网", "设备网", 502): "SCADA 读 PLC（Modbus TCP）",
}


def check(src, dst, port):
    why = ALLOW.get((src, dst, port))
    return ("放行: " + why) if why else "拒绝(默认)"


print("== 1. 区域管道检查 ==")
for flow in [("办公网", "DMZ", 443), ("办公网", "设备网", 502), ("DMZ", "车间控制网", 4840), ("办公网", "车间控制网", 4840)]:
    print(f"  {flow[0]:<6} -> {flow[1]:<6} 端口 {flow[2]:<5} {check(*flow)}")

# ---------- 2. 只检查本机 127.0.0.1：哪些工业/高风险端口正在监听 ----------
WATCH = {21: "FTP", 23: "Telnet", 102: "S7comm", 445: "SMB", 502: "Modbus TCP", 1883: "MQTT",
         3389: "远程桌面", 4840: "OPC UA", 8883: "MQTT/TLS", 44818: "EtherNet/IP"}
print("== 2. 本机监听端口自查（仅 127.0.0.1）==")
for port, name in WATCH.items():
    s = socket.socket(); s.settimeout(0.3)
    state = "监听中" if s.connect_ex(("127.0.0.1", port)) == 0 else "未监听"
    s.close()
    if state == "监听中":
        print(f"  {port:<6}{name:<12}{state}  <- 确认是否需要对外开放；能限制来源 IP 就限制")
print("  (其余端口均未监听)")

我的运行结果（当时本机正开着 MQTT 篇的实验 broker，所以 1883 在监听；23 和 445 是这台电脑自带/其它软件的服务，你的结果会不同）：

== 1. 区域管道检查 ==
  办公网    -> DMZ    端口 443   放行: 员工访问 MES 网页
  办公网    -> 设备网    端口 502   拒绝(默认)
  DMZ    -> 车间控制网  端口 4840  放行: MES 采集服务读 OPC UA
  办公网    -> 车间控制网  端口 4840  拒绝(默认)
== 2. 本机监听端口自查（仅 127.0.0.1）==
  23    Telnet      监听中  <- 确认是否需要对外开放；能限制来源 IP 就限制
  445   SMB         监听中  <- 确认是否需要对外开放；能限制来源 IP 就限制

  (其余端口均未监听)

注意：connect_ex 能连上说明端口在监听，但是否对外开放还取决于它绑定在 127.0.0.1 还是 0.0.0.0、以及防火墙规则——想确认就用系统自带命令 netstat -ano 看"本地地址"一列，或查看防火墙规则。本脚本不会也不应该对其它主机做扫描；对生产设备做端口扫描前必须取得许可并避开生产时段。

另外两个可以自己做的练习：

  1. 把你们车间的实际流量填进 ALLOW，找出"现在其实在发生、但你没登记"的流量（用交换机端口镜像抓包对照，需网络管理员配合）；
  2. 写出一份"U 盘使用登记表"和"远程运维申请单"的模板（纸面工作，但比任何脚本都有用）。

常见坑与排查 ​

现象最可能的原因
防火墙开了策略后 MES 采集中断漏登记某条合法流量（常见：响应方向、动态端口）；先在测试期用"只记录不拦截"模式
老设备打补丁后不工作没有在测试环境验证；应先咨询厂家、保留回滚
隔离网络仍然感染病毒移动介质、工程师笔记本、临时拉的网线、无线热点
厂家说"必须开放远程才能保修"谈判为"按需开通、经跳板机、全程记录"的方案
安全制度形同虚设流程太繁琐，现场绕开；简化到现场愿意执行，并配套工具（如查杀站就在车间入口）
把所有安全寄托在一台防火墙缺少纵深：主机加固、备份、监控缺一不可
误以为用了 TLS/OPC UA 加密就安全证书管理、用户权限、默认密码仍需管理；见 OPC-UA

业务视角与技术视角 ​

  • 业务视角：一次勒索病毒或误操作造成的停线损失，通常远超安全投入。客户（尤其汽车、医疗、军工）越来越多要求供应商满足 IEC 62443 或 TISAX、ISO 27001 等体系，审核时会看资产清单、分区、远程运维记录和备份。信息化部门在这里的角色是"把 IT 的经验带进 OT，同时尊重 OT 的可用性要求"，与设备部门、生产部门共同制定规则。
  • 技术视角：MES 相关的具体动作：①MES 采集服务用最小权限账号，只读就只给只读；②对外接口（WebAPI开发）要有认证（身份认证与JWT）；③MQTT 开 TLS 与用户权限（ACL）；④OPC-UA 生产环境用 Sign 或 SignAndEncrypt；⑤数据库备份与 PLC 程序备份纳入定期演练（见 备份与恢复）；⑥所有连接设备的服务器放在 DMZ 或控制区，不要双网卡跨接办公网和设备网（会绕过防火墙）。

练习题与答案 ​

  1. 为什么说"Modbus 没有认证"不是 Modbus 的 bug？ 答：它设计于 1979 年，前提是线路封闭在设备柜内的串口上。安全应由网络隔离等外部手段提供。
  2. IT 与 OT 安全的首要优先级各是什么？ 答：IT 偏重机密性；OT 偏重可用性和人身/设备安全。
  3. Purdue 模型中 Level 3.5 有什么作用？ 答：工业 DMZ，是 IT 与 OT 之间的缓冲区，放跳板机、数据中转和更新服务器，让两侧不直接通信。
  4. IEC 62443 里 SL 1~SL 4 表示什么？ 答：对不同能力和动机的攻击者的抵御程度：SL1 防偶然误用，SL2~SL4 防日益强大的有意攻击。
  5. 一个供应商要求在你们 PLC 上保留 24 小时开启的远程桌面，如何处理？ 答：不接受常开；改为按需申请、通过 VPN 加跳板机、双因素和会话记录，结束后关闭，并将 PLC 程序先备份。
  6. 为什么要在防火墙采用"默认拒绝"而不是"默认放行再逐条封堵"？ 答：默认拒绝时，你未知的流量也被挡住，只放行已登记的合法流量，遗漏的后果是"断一条业务"（容易发现、修正）；默认放行遗漏的后果是"留一个口子"（难以发现）。

小结 ​

  • 工业协议多半没有安全机制，保护靠"网络隔离 + 多层防御"。
  • OT 的首要目标是可用性与安全，改动要先测试、再上线。
  • Purdue 模型给出分层与 DMZ 的思路；IEC 62443 提供区域/管道、安全等级和针对三类角色的要求。
  • U 盘和远程运维是最常见的入口：登记、查杀、按需开通、跳板机、双因素、记录。
  • 工具只是辅助：资产清单、允许清单、备份演练和人的习惯才是核心。
